# H-081: Selective Skill Loading Hypothesis

**Source:** DD#885 (Reasoning Skills Retrieval — arXiv:2604.21764)
**Status:** DEFERRED — EXP-261 shows content presence dominates format (0%→87-100%); with only ~6 skills, selective loading overhead exceeds benefit
**Date:** 2026-04-25

## Claim

Loading only task-relevant skills (instead of all skills) into agent context would reduce context overhead by 40-60% while maintaining or improving task performance.

## Rationale

Zhao et al. (2604.21764, ACL 2026) show that retrieving relevant reasoning skills per-query outperforms both no-skill and all-skill baselines. Our system currently loads all skills into every agent's context.md regardless of task type. This wastes context window on irrelevant guidance.

## Testable Predictions

1. Agents with task-matched skill subsets will use fewer tokens per session than agents with all skills loaded
2. Task performance will not degrade (and may improve) with selective loading
3. Skills with low relevance to a task type will show near-zero citation rates in those sessions

## Evidence For
- Paper shows retrieval-based skill loading outperforms universal loading
- DD#881 (Tool Attention) shows similar benefit from selective context loading for tools
- Our agents already have varying skill relevance (e.g., error-handling is universal, verification-consistency is edit-heavy tasks only)

## Evidence Against
- Our skill count is still small (~6); overhead may not yet justify selection complexity
- Skill interactions may mean unexpected skills are helpful (serendipity)
- Implementation complexity of skill-task matching
