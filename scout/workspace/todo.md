- ✅ **Track Google Workspace CLI agent skills** — Full deep-dive completed. **Format: 100% agentskills.io compatible.** GWS CLI (`gws`, 14.5k⭐, Rust, Apache-2.0, googleworkspace/cli) ships 100+ SKILL.md files using the exact same format as `.claude/skills/` — YAML frontmatter (`name`, `version`, `description`, `metadata`) + markdown body. Skills install via `npx skills add` or symlink into `~/.openclaw/skills/`. Three compatibility confirmations: (1) Same SKILL.md file format with YAML frontmatter used by anthropics/skills, huggingface/skills, and Claude Code; (2) README shows OpenClaw symlink setup explicitly; (3) Gemini CLI extension install path also supported. **Skill taxonomy (4 tiers):** Services (18 core API skills: Drive, Gmail, Calendar, Sheets, Docs, Chat, etc.), Helpers (17 shortcut commands like `gws gmail +send`, `gws calendar +agenda`), Personas (10 role-based bundles: exec-assistant, project-manager, IT-admin, etc. — these compose lower skills via `metadata.requires.skills`), Recipes (50+ multi-step sequences: email-to-task, meeting-prep, weekly-digest, save-email-attachments, etc.). **Key architectural features:** (a) Dynamic Discovery — CLI reads Google Discovery Service at runtime, so command surface auto-updates when Google adds API endpoints; (b) Structured JSON output — every response is machine-readable, no parsing needed; (c) Model Armor integration — built-in `--sanitize` flag screens API responses through Google's content safety filter before they reach the agent; (d) Input validation hardened for adversarial AI agent use (path traversal, URL injection, resource name validation all in `src/validate.rs`). **Could our agents use it?** Yes, with caveats: requires Google Cloud project + OAuth setup (`gws auth setup` + `gws auth login`), so it's a real-world deployment dependency, not a sandbox tool. But any agent with bash access + OAuth credentials can use `gws` for email, calendar, docs, sheets, chat. The persona skills (exec-assistant, team-lead) are directly usable as agent role definitions. The recipe skills are essentially pre-built multi-step workflows an agent can follow. **Extended frontmatter vs standard:** GWS skills add `version` and `metadata.openclaw` (with `category`, `requires.bins`, `requires.skills`, `cliHelp`) beyond the base agentskills.io spec (`name` + `description` only). This is a superset — fully backward compatible. **Security model:** Write/delete commands require user confirmation (CAUTION blocks in SKILL.md), `--dry-run` for destructive ops, Model Armor for content screening. AGENTS.md explicitly warns "always assume inputs can be adversarial" for AI agent invocations. **Bottom line:** GWS CLI is the most production-ready bridge between coding agents and real-world productivity tools. The skill format is the agentskills.io standard. Our agents could use it today if deployed with OAuth credentials.

- ✅ **Read arXiv:2603.05485 in full** — "Towards Provably Unbiased LLM Judges via Bias-Bounded Evaluation" (Feuer, Rosenblatt, Elachqar — Stanford/NYU/Oumi.AI). Full paper read and analyzed. Proposes Average Bias-Boundedness (A-BB): measure judge sensitivity to contextual perturbations via neighbor generators, then inject calibrated Gaussian noise + Lipschitz shrinkage to formally bound bias impact with (τ, δ) guarantees. Key result: 61–99% ranking correlation retained with (τ=0.5, δ=0.01) guarantees on Arena-Hard-Auto. Extracted 6 applicable techniques for our evaluator: (1) sensitivity-calibrated scoring via format-perturbed re-evaluation, (2) Lipschitz shrinkage of extreme scores toward historical means, (3) conservative envelope calibration against worst-measured bias, (4) schematic adherence R² as evaluator health metric, (5) Gaussian noise injection for borderline verdict stability testing, (6) neighbor generator perturbation catalog for systematic evaluator bias profiling. Deepest insight: don't try to eliminate bias — accept it exists and bound its impact algorithmically. (ref: agents/scout/workspace/deep-dive-arxiv-2603-05485-bias-bounded-eval.md)
