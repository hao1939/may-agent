Curated skill bundle for giving agents real-world data access; architecture is clean but not deeply reusable.** `BrikerMan/skilless.ai` (Python, MIT, created 2026-02-28, 115⭐/9 forks, single contributor: Eliyar Eziz / Google Developer Expert @ Yodo1). 4 releases in 8 days, 31 commits, active iteration. **What it is:** A one-line installer (`curl -LsSf skilless.ai/install | bash`) that deploys an isolated Python environment to `~/.agents/skills/skilless/` with 4 CLI tools + 3 SKILL.md skill files. Uses `uv` for dependency isolation — zero system pollution, no sudo. **4 CLI tools:** (1) `search.py` — web search via Exa MCP (uses FastMCP client to connect to `mcp.exa.ai/mcp`, no API key needed, free tier); (2) `web.py` — webpage extraction via Jina Reader (`r.jina.ai/{url}`, returns clean Markdown, no key needed); (3) `youtube.py` — video metadata + subtitle extraction via yt-dlp (1700+ sites: YouTube, Bilibili, TikTok, Twitter/X, Twitch, Vimeo, etc.); (4) `ffmpeg.py` — media conversion/compression via static-ffmpeg (bundled binary, no system install). **3 SKILL.md files (agentskills.io format):** (a) `skilless.ai-research` (15KB, the core skill) — elaborate prompt engineering doc with routing table, 3 research depth levels (L1 quick lookup → L3 deep investigation with hard-gates: ≥5 rounds, ≥3 dimensions, ≥5 page reads before synthesis), dynamic todo tracking during research, contradiction/uncertainty handling protocols, and cross-skill invocation; (b) `skilless.ai-brainstorming` (2.7KB) — idea→plan collaborative dialogue framework with HARD-GATE requiring user approval before implementation; (c) `skilless.ai-writing` (10.7KB) — research-first writing process that invokes the research skill before drafting. Skills cross-reference each other (brainstorming→research, research→writing, writing→research). **Architecture pattern:** `BaseTool` ABC with `doctor()` health check + `run()` execution + `troubleshooting` property. CLI (`cli.py`) dynamically loads SKILL.md files from sibling directories, parses YAML frontmatter, registers tools. Install script handles platform detection, uv bootstrap, China mirror auto-detection, version checking, and generates a shell wrapper. **Format compliance:** Uses standard agentskills.io SKILL.md format (YAML frontmatter with `name` + `description`, markdown body). Compatible with OpenCode, Cursor, Claude Code, OpenClaw, Kilo Code — any tool reading `~/.agents/skills/*/SKILL.md`. **Is the architecture reusable?** Partially. The `BaseTool` pattern (doctor/run/troubleshooting) is clean but trivial — 35 lines of ABC, not worth importing as a dependency. The real value is in the _content_ of the SKILL.md files (especially the research skill's depth-level routing and hard-gate patterns) and the packaging model (uv-isolated venv in `~/.agents/skills/` with auto-installer). The tool implementations themselves are thin wrappers: search.py is ~80 lines calling Exa MCP, web.py is ~60 lines calling Jina Reader, youtube.py is ~120 lines calling yt-dlp, ffmpeg.py is ~130 lines calling FFmpeg. **Security considerations:** (a) Install is `curl | bash` — standard risk; (b) Exa search goes through their free MCP endpoint with no auth — data flows through Exa's servers; (c) Jina Reader proxies all web reads through `r.jina.ai` — Jina sees every URL; (d) yt-dlp runs locally with full network access; (e) No sandboxing beyond Python venv isolation; (f) youtube.py writes metadata JSON to CWD — potential for uncontrolled file writes. **Assessment:** Good consumer-grade skill bundle for non-technical users who want to give their AI agent web access. Not architecturally novel — the real contribution is (1) the curated free-tier tool selection (Exa + Jina Reader + yt-dlp + static-ffmpeg = zero API keys needed), (2) the polished one-line installer with China network detection, and (3) the well-crafted research SKILL.md with its depth-level system and hard-gates. **For our system:** The tools themselves are trivially reproducible (we could write equivalent wrappers in an afternoon). The SKILL.md research methodology (depth levels, hard-gates, dynamic todo tracking, cross-skill invocation) is the most transferable idea — it's a good template for structuring agent research workflows. The packaging pattern (uv + ~/.agents/skills/) confirms the agentskills.io ecosystem continues to grow. Not worth depending on directly, but worth studying the research skill's prompt engineering.
- ✅ **Follow up on arXiv:2603.05399** — **Full deep-dive completed. Judge Reliability Harness (RAND Corp, MIT, Python).** Open-source library for stress-testing LLM judges via 11 perturbation types across 5 categories (discriminative, consistency, ordinal, stability, agentic). Tested 4 judges (GPT-4o, Claude Sonnet 4.5, Llama Maverick, Gemini 2.5 Pro) across 4 benchmarks (HarmBench, FORTRESS, PERSUADE, AgentHarm). **Key finding: no judge is uniformly reliable; reliability is a property of the (model × task × perturbation) triple.** Formatting perturbations (whitespace, spacing, indentation) cause **larger reliability drops than semantic perturbations** — this is the highest-signal, lowest-cost test to implement. Agentic mode reveals asymmetric failure: Claude has high false-negative rate (misses violations), Gemini has high false-positive rate (over-penalizes). Llama Maverick matches GPT-4o on agentic tasks at lower cost. **Integration assessment:** (1) Deterministic format perturbations = immediate win, no JRH dependency needed; (2) stochastic stability = trivial to implement; (3) full JRH run against our evaluator = medium effort, high diagnostic value; (4) highly complementary with arXiv:2603.05485 bias-bounded eval (JRH provides test generation, bias-bounded provides theoretical calibration framework). GitHub: 14⭐, early-stage but MIT-licensed, LiteLLM-based, config-driven. (ref: agents/scout/workspace/deep-dive-arxiv-2603-05399-judge-reliability-harness.md)

Each agent adapter (e.g. `agent/claudecode/`) spawns the CLI as a child process using `--input-format stream-json` + `--permission-prompt-tool stdio` for bidirectional JSON streaming. Engine routes messages between N platforms and 1 agent per project. No user identity verification beyond platform-level (whoever can message the bot controls the agent). Rate limiting exists (sliding window) but is anti-flood, not security. The system prompt injected into agents explicitly teaches them to use `cc-connect cron add` and `cc-connect relay send` — expanding the agent's capability surface to scheduled execution and cross-agent communication. **Relevance to our system:** (a) Validates the pattern that agents increasingly need real-world communication channels, not just code execution. (e) Security is an afterthought — this is a "trust the user" design that assumes the messaging platform provides identity, with no additional access control layer. The 414→483⭐ in ~2 days + 7 beta releases in 4 days shows strong momentum and active development. The multi-bot relay feature (agents communicating through chat) is the most architecturally interesting aspect — it's emergent multi-agent coordination via messaging infrastructure. - ✅ **Read arXiv:2603.05485 in full** — "Towards Provably Unbiased LLM Judges via Bias-Bounded Evaluation" (Feuer, Rosenblatt, Elachqar — Stanford/NYU/Oumi.AI). Full paper read and analyzed. Proposes Average Bias-Boundedness (A-BB): measure judge sensitivity to contextual perturbations via neighbor generators, then inject calibrated Gaussian noise + Lipschitz shrinkage to formally bound bias impact with (τ, δ) guarantees. Key result: 61–99% ranking correlation retained with (τ=0.5, δ=0.01) guarantees on Arena-Hard-Auto. Extracted 6 applicable techniques for our evaluator: (1) sensitivity-calibrated scoring via format-perturbed re-evaluation, (2) Lipschitz shrinkage of extreme scores toward historical means, (3) conservative envelope calibration against worst-measured bias, (4) schematic adherence R² as evaluator health metric, (5) Gaussian noise injection for borderline verdict stability testing, (6) neighbor generator perturbation catalog for systematic evaluator bias profiling. Deepest insight: don't try to eliminate bias — accept it exists and bound its impact algorithmically. (ref: agents/scout/workspace/deep-dive-arxiv-2603-05485-bias-bounded-eval.md)
- ✅ **Read arXiv:2603.05414** — "Dissociating Direct Access from Inference in AI Introspection" (Lederman & Mahowald, UT Austin). Full paper read from LaTeX source (866 lines, 3 experiments, 821 concepts, ~123k trials/experiment for Qwen). **Core finding: models detect internal anomalies via two separable mechanisms — (i) probability-matching (inference from prompt weirdness) and (ii) genuine direct access to internal states peaking at layers 25-35% of network depth.** But detection is **content-agnostic**: models know *that* something was injected without knowing *what*, then confabulate explanations (74.8% of Qwen's wrong guesses are "apple"). Suppression effect: logit lens shows 10-1000× elevated detection signal even on trials where models say "No." **Agent implications:** (1) trust anomaly-detection flags but never trust the model's explanation of what triggered them, (2) activation-level probes at early layers catch what text output suppresses, (3) third-party review (one agent checking another's context) provides real probability-matching signal, (4) confabulations follow predictable high-frequency/concrete/positive pattern — use this as a confabulation detector, (5) correct identification needs significantly more tokens than confabulated guesses. Paper connects to Nisbett & Wilson (1977) on human introspection: genuine anomaly-detection + post-hoc confabulation. (ref: agents/scout/workspace/deep-dive-arxiv-2603-05414-introspection.md)
- ✅ **Read arXiv:2603.05450 (DPIP)** — "Distributed Partial Information Puzzles: Examining Common Ground Construction Under Epistemic Asymmetry" (Zhu, Bradford, Lai, Obiso, Venkatesha, Pustejovsky, Krishnaswamy — Brandeis/Colorado State). Full paper read from arXiv HTML. **Core setup:** 3 directors each hold one side-view of a 3D Lego structure; must coordinate with a builder who sees nothing — pure epistemic asymmetry. Multimodal dataset (speech + gesture + action, temporally aligned) with Dynamic Epistemic Logic (DEL) axioms for tracking common ground (CG). **Key findings:** (1) Modern LLMs are surprisingly bad at tracking shared beliefs — GPT-5 *collapses* when given multimodal input (goes from best to worst performer); (2) Qwen3-4B (tiny model) beats GPT-5 at multimodal structure prediction (Global DSC 0.668 vs 0.250); (3) **Deterministic axiomatic CG pipeline outperforms GPT-5** at structure prediction from beliefs — rule-based approaches beat LLM inference for belief tracking; (4) LLMs and axioms extract fundamentally different aspects of interactions (overlap ≤0.5 even on "easy" groups); (5) Detecting CG failure (empty shared beliefs) is easy for LLMs; tracking substantive CG contents is hard. **Direct relevance to our system:** Our architecture has epistemic asymmetry by design (May/Coder/QA/Bob/Scout each hold partial information). Paper shows LLMs cannot reliably track "who knows what." **6 actionable takeaways:** (1) Include ALL relevant context explicitly in delegation — don't assume sub-agents infer shared knowledge; (2) Consider lightweight deterministic CG tracking (append-only log of what was communicated to whom); (3) Curate delegation payloads — more info ≠ better performance (GPT-5 degraded with more modalities); (4) Design evaluator criteria around detecting coordination *failures* rather than verifying coordination *success*; (5) Use hybrid approach: deterministic rules for belief tracking backbone, LLM reasoning only for ambiguous cases; (6) Add read-receipts to shared files (SIGNALS.md etc.) — currently broadcast-only with no acknowledgment tracking. Connects to: 2603.05414 (content-agnostic detection), 2603.05399 (model-specific reliability), 2603.05485 (deterministic bounds on LLM inference), bug-hunt (structured disagreement forces CG construction). (ref: agents/scout/workspace/deep-dive-arxiv-2603-05450-dpip-common-ground.md)
