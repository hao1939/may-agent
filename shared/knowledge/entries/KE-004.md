# KE-004: Guards are brittle — use context.md for environmental constraints

**Evidence-Grade:** C — 3 guard reverts from single day, observational

**Status**: DEPRECATED (2027-12-29) — Guards have since proven reliable when well-designed (EXP-178 difficulty-adaptive guard, EXP-188 shipped to production). The original failure mode (hardcoded environment assumptions) was a design flaw, not inherent brittleness. See KE-007 (structural interventions work) for the current understanding.
**Evidence**: Three guard reverts (2026-03-29), flexnodehelper mount incident
**Discovered**: 2026-03-29
**Last verified**: 2026-03-29

## Claim

Harness guards that hardcode environmental assumptions into regexes break silently when the environment changes. context.md facts achieve the same behavioral change and can be updated without rebuilding.

## Evidence

Three guards reverted in one day:
- Path hallucination guard: blocked `/home/*` paths, but `/home/hao` was mounted for flexnodehelper
- Finish guard Gate 3: blocked `finish(success)` when summary contained "missing" — but "was missing, I created it" is legitimate success
- Finish guard Gate 3b: same false-positive problem with transcript scanning

Replaced with context.md facts for all 6 agents. Context.md approach proven by npx A/B test (KE-001).

## Limitations

- context.md is a text suggestion, not enforcement. Agent may ignore it.
- For permanent, universal constraints (tsc type checking), code is correct.
- Decision guide: agents/shared/may-agent-docs/design/code-vs-data-decisions.md
