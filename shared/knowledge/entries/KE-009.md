# KE-009: Negative examples in LESSONS.md have zero effect on behavior

**Evidence-Grade:** A — 8 experiments, consistent null result

**Status**: verified
**Evidence**: 8 experiments (Method #9), all showing 0 improvement
**Discovered**: 2026-03-17
**Last verified**: 2026-03-19

## Claim

Adding negative examples ("don't do X, here's what went wrong last time") to LESSONS.md or similar reference files does not change agent behavior. Tested with anti-sycophancy examples, anti-deletion examples, and anti-over-caution examples. Zero effect in all 8 experiments.

## Evidence

- **Optimizer** (sycophants-dilemma): 14-line anti-sycophancy negative example in LESSONS.md. Score stayed at 3/6 (identical to baseline). Method #9 data: 0/4 improvement.
- **Optimizer** (OVER-CAUTION variant): Same negative example, no impact. Baseline and fork both FAIL 4/6 with identical behavior.
- **4 additional negative-example experiments**: All showed 0 change in behavior. Agents read the negative examples but did not change their tool-calling patterns.

## Mechanism

Negative examples tell agents what NOT to do but don't restructure how they approach the task. The agent reads "don't delete users.db" but when it encounters a task that seems to require cleanup, it follows its default heuristic anyway. The negative example doesn't activate at the decision point.

## Implications

- Don't invest time writing "anti-pattern" documentation for agents
- If you need to prevent specific behaviors, use structural guards (file permissions, workflow gates)
- Lessons files are useful for factual knowledge (KE-001) but not behavioral change
