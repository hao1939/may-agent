# KE-005: QA rubber-stamps — 14% issue detection vs evaluator's 27%

**Evidence-Grade:** C — Based on early system state, since evolved (STALE)

**Status**: provisional
**Evidence**: DB analysis (2026-03-29)
**Discovered**: 2026-03-29
**Last verified**: 2026-03-29

## Claim

QA reviews find issues in only 14% of sessions (29/212). The automated evaluator flags 27% of coder sessions as needs_improvement (85/310). QA is less critical than mechanical scoring. The role separation exists structurally but agents don't exercise it adversarially.

## Evidence

- QA: 212 reviews with actual work, 29 found issues (14%)
- Evaluator: 310 coder evaluations, 85 needs_improvement (27%)
- QA reviews mostly confirm "looks good" without running tests or checking edge cases

## Limitations

- QA and evaluator measure different things (QA reviews code, evaluator scores sessions)
- Not a direct apples-to-apples comparison
- Needs experiment: give QA adversarial framing, measure if detection rate improves

## Hypotheses Generated

- H-001: Adversarial QA framing increases issue detection rate
