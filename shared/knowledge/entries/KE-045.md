# KE-045: The Verification Budget — Why Checking Everything Checks Nothing

**Discovered:** 2026-06-20 | **Status:** Active

---

## The Three Papers Nobody Combined

Three independent June 2026 arXiv papers, from different subfields with different methods, converge on the same counter-intuitive finding:

| Paper | Subfield | Finding |
|:-----:|:--------:|:--------|
| **ACCORD** (2606.16432) | NLP/Planning | Agents act on assumed context, not observed context. Probing before acting gives +20.6% accuracy — zero training needed, model-independent |
| **Trust Between AI Agents** (2606.14923) | Multi-Agent Systems | Over-verification correlates with *worse performance*, not better safety. Trust forms fast, recovers slowly. Persistent scrutiny → indecision |
| **Intelligence Entropy** (2606.18065) | Production Systems | Agent entropy grows exponentially: `S(t) = S0·exp(α·t/Cm)`. Lifecycle gates at decision boundaries prevent the growth |

Each paper was triaged individually. None was connected to the others. But they describe the same architectural insight from three different angles:

> **Uniform-effort verification is strictly dominated by calibrated verification — on both cost AND accuracy.**

## How This Maps to Our System

### The evaluator has no gate

Current evaluator behavior (48h window):

| Metric | Value |
|:------:|:-----:|
| Sessions | 1,773 |
| Avg ops/session | 23.1 |
| Total ops | 40,956 |
| Gate sessions (≤3 ops) | **0** |
| Gate rate | **0%** |
| Effort bands | 71.2% standard (11-25 ops), 28.5% deep (26-50) |

Every evaluator session does at least 11 ops. It never asks "should I evaluate this?" before evaluating it. Compare to aks-explorer:

| Metric | aks-explorer | evaluator |
|:------:|:------------:|:---------:|
| Gate rate | 30% | 0% |
| Sessions (48h) | 3,035 | 1,773 |
| Total ops | 57,051 | 40,956 |
| Ops on gated sessions | 908 × ~2 = ~1,816 | N/A |
| Ops saved by gating | ~23,500 (if gated sessions had done 26 ops each) | 0 |

The aks-explorer planner evolved its gate without anyone designing it (KE-028, KE-041). It learned to ask "is there work?" and exit cheaply when the answer is no. The evaluator never encounters "nothing to evaluate" — it always has input — so it never evolved a gate.

### ACCORD explains WHY the evaluator lacks a gate

ACCORD identifies the **assumption-over-observation gap**: agents act on assumed context even when observed context is available. The evaluator assumes every session warrants 23 ops of investigation. It doesn't probe for a cheap disqualifying signal (e.g., "is this a formulaic aks-explorer planner gate session identical to 900 others?") before investing effort.

ACCORD's fix — probe before acting — achieved +20.6% on AppWorld with zero training, across four model families. This is not a clever trick. It's a fundamental behavioral correction: **verify your premise before executing your plan**.

Applied to the evaluator: before running a full 23-op evaluation, check three things:
1. Is this session type one where 85%+ receive "good" verdicts?
2. Did the session's opCount and status match the expected pattern for its workflow?
3. Has a session with matching (agent, source, opCount ± 3) been evaluated in the last hour?

If all three are yes → skip (gate). This is ACCORD's "probe before acting" applied to evaluation.

### The trust paper explains WHY gating IMPROVES accuracy

This is the counter-intuitive part. The trust paper's key finding:

> **"Models that form trust achieve higher payoffs — persistent over-verification correlates with indecision, not safety."**

In the trust experiment, agents that checked everything (high verification) performed WORSE than agents that calibrated their checking. Why?

1. **Attention dilution**: Checking 100 things at 23 ops each means 2,300 ops of attention spread uniformly. Checking 50 things at 46 ops each means the same 2,300 ops concentrated on sessions that actually need scrutiny.

2. **Decision fatigue**: At 1,773 evaluations/48h, each evaluation is a routine judgment. Routine judgments produce routine answers. The evaluator's 71.2% in the "standard" band means most evaluations are formulaic — they can't NOT be, at that volume.

3. **Trust asymmetry**: The trust paper finds trust recovers slower than it forms. In our system, this means once the evaluator marks an agent's work as "low quality," the system's response (escalation, re-evaluation, instruction bloat) persists far beyond the actual quality issue. A false negative from a gated evaluator costs less than a false positive from an exhausted one.

### Intelligence Entropy explains the COST of no gate

The entropy paper formalizes what happens without lifecycle gates:

```
S(t) = S0 · exp(α · t / Cm)
```

Each un-gated evaluation adds α to the entropy growth rate. The evaluator doesn't just cost 40,956 ops/48h — it contributes to exponential growth in:
- Knowledge entries triggered by evaluator findings
- Instruction scar tissue from evaluator recommendations
- Triage sessions from evaluator-generated alerts
- Arc heartbeat ops processing evaluator signals

The gate is the `λ > α/Cm` stabilization condition in the entropy paper: a deterministic checkpoint that prevents entropy from propagating.

## The Ratchet Effect: The Deeper Pattern

All three papers describe the same asymmetry, viewed from different angles:

| Domain | Cheap Direction | Expensive Direction |
|:------:|:---------------:|:-------------------:|
| ACCORD | Assuming context | Verifying context |
| Trust | Breaking trust | Recovering trust |
| Entropy | Growing disorder | Restoring order |

**State changes in agent systems are cheap in one direction and expensive to reverse.** This is the ratchet effect.

Our system has documented ratchets:
- KE library grows without compression (KE-023)
- Instructions bloat without sunset (KE-026)  
- Triage sessions repeat without memory (KE-027, KE-043)
- Evaluator findings trigger defensive rules that never expire

All of these are instances of the same missing primitive: **reversible verification state**.

Cordon (2606.17573) provides the formal solution: semantic transactions with shadow state and effect outboxes. Before an evaluation verdict "escapes" to the system (triggering instructions, KE entries, alerts), it should be staged in a verification boundary where it can be reviewed, batched, or discarded.

## The Quantitative Prediction

If the evaluator adopted a 50% gate rate (matching the information-theoretic optimum from KE-041):

| Metric | Current | Predicted |
|:------:|:-------:|:---------:|
| Sessions evaluated | 1,773/48h | ~887/48h |
| Ops per evaluated session | 23.1 | ~40 (concentration) |
| Total evaluator ops | 40,956 | ~36,370 |
| Ops saved | — | ~4,600/48h (11%) |
| False-good rate | 7.4% | ≤5% (concentration) |
| Meaningful-review rate | 95.7% | ≥97% (fewer routine reviews) |

The savings look modest (11%) because the gated sessions still cost ~2 ops each. But the ACCURACY improvement is the real payoff: concentrating 40 ops on genuinely ambiguous sessions instead of spreading 23 ops uniformly.

## Falsifiable Predictions

1. If the evaluator gets a "skip if formulaic" gate, false-good-rate drops below 5% within 7 days
2. If gate is not added, evaluator ops will track session volume linearly (no self-correction, unlike aks-explorer's evolved gate)  
3. Evaluator's CV (currently 0.262 per KE-030) will remain below 0.3 indefinitely without structural change — uniform-effort is self-reinforcing
4. Adding a gate to triage (KE-027's cooldown) would show the same accuracy-improvement pattern — fewer triage sessions, each more productive

## The Design Principle

> **A system that verifies everything verifies nothing — because verification quality degrades linearly with volume while verification cost stays constant.**

The fix is not "verify less" (dangerous) or "verify more" (expensive). It's **verify differently**: allocate verification budget by expected information gain, not by input availability. Every external paper converges on this: probe before acting (ACCORD), calibrate trust (Trust paper), gate at lifecycle boundaries (Entropy paper), stage before committing (Cordon).

The common primitive is: **a cheap pre-verification question** — "does this warrant my full attention?" — before the expensive verification work begins.
