# KE-201: MCP Production Gaps Map to May's Existing Architecture Challenges

**Source**: DD-773 (MCP Production Gaps — Identity, Budgeting, Error Semantics)
**Date**: 2026-04-16
**Tags**: `mcp` `error-recovery` `budget-allocation` `agent-architecture`

## Core Insight

The three MCP production gaps (identity propagation, tool budgeting, structured errors) mirror problems May already faces — but May has partial solutions the MCP ecosystem lacks. The actionable gap is **structured error semantics**, where May's FM taxonomy is ahead of MCP's SERF proposal but not yet machine-readable.

## Which Gaps Apply to May?

| MCP Gap | May Equivalent | Status |
|---------|---------------|--------|
| **Identity propagation** (CABP) | Not applicable — May is single-user, no multi-tenant routing needed | N/A |
| **Adaptive tool budgeting** (ATBA) | opBudget was removed (Hao directive 2026-03-30); cost control is at model/session level | Divergent — May moved *away* from per-call budgeting |
| **Structured error semantics** (SERF) | FM taxonomy (FM-1.x through FM-3.x) classifies failure modes | Partial match — FM codes exist but aren't machine-actionable |

## Concrete Improvements Suggested

1. **Make FM codes machine-readable**: The SERF pattern (structured error types → deterministic self-correction) is exactly what May's FM taxonomy *could* become. Today FM codes are human-readable labels in post-hoc analysis. If agents could detect their own FM patterns at runtime (e.g., "I'm doing FM-1.3 right now — path guessing"), they could self-correct. The `active_recall` injection is a first step but it's pre-session, not runtime.

2. **Skip tool budgeting**: ATBA's heterogeneous-latency budget allocation is interesting academically but May deliberately removed opBudget. The paper validates May's direction — rigid per-tool budgets don't work when tool costs vary 100x. Session-level cost control is the right abstraction.

3. **Error recovery patterns are reusable**: SERF's idea of *typed* errors (transient vs permanent vs semantic) could improve May's guard system. Currently guards catch FM-3.3 (verification gaps) generically. Typed errors would let guards distinguish "needs retry" from "needs different approach."

## Connections to Existing Knowledge

- **KE-053/KE-109** (gym-production gap): MCP's protocol-to-production gap is structurally similar — what works in demos fails in deployment for the same reasons (missing identity, missing budgets, missing error handling).
- **FM taxonomy**: SERF validates the FM approach but pushes it toward runtime detection rather than post-hoc classification.
- **opBudget removal**: ATBA paper unknowingly validates Hao's decision — adaptive budgeting over heterogeneous distributions is complex; session-level caps are simpler and sufficient.

## Bottom Line

May is ahead of MCP ecosystem on error classification (FM taxonomy) but behind on making it actionable at runtime. The highest-value follow-up would be exploring runtime FM detection — agents recognizing their own failure patterns mid-session rather than only being warned pre-session via active_recall.
