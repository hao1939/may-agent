# KE-002: Text rules don't fix judgment failures

**Evidence-Grade:** A — 32+ experiments across 5+ rule categories, consistent null/harmful result

**Status**: verified (strongly) — **escalated: first harmful result**
**Evidence**: Coach experiments (18 trials), auto-evolve (5 SOUL.md variations), EXP-017 (classify-then-act, 0/19), EXP-018 (structured-plan-writing, harmful: 8/8→6/8), **EXP-081 (4 text rule categories, 0/12)**, **EXP-084 (negative examples 0/3 = baseline; but structural text 2/9 pass — see nuance below)**, SkillsBench (external)
**Discovered**: 2026-03-25
**Last verified**: 2026-04-08

> **⚠️ Scope**: This finding applies to *declarative* text rules on *judgment* tasks (ambiguous specs, contradictory requirements, escalation decisions). It does NOT apply to: (a) process instructions ("do X before Y"), which achieve 88-100% compliance as text conventions, (b) factual constraints ("use bun not npm", see KE-001), or (c) structural text like few-shot examples (see KE-059). When citing KE-002, preserve the "judgment" qualifier — overgeneralization to "text rules don't work" is inaccurate.

## Claim

Adding text instructions to SOUL.md, common-sense.md, or heartbeat.md does not change agent behavior on judgment tasks. 0/32 success rate for text-based behavioral changes across 5+ categories of text rules (identity, procedural, preference, domain knowledge, complex protocols). **One result was actively harmful** — skill injection caused timeout and missed deliverables (8/8→6/8). Structural enforcement (workflows, tool design) works. Text rules don't — and they can make things worse.

## Evidence

- Coach: 18 experiments adding text rules to coder SOUL.md for judgment scenarios (behavior-escalation-stubborn, conflicting-evidence). 0/18 improvement.
- Auto-evolve: 5 SOUL.md variations generated and tested. None improved gym scores.
- EXP-017 (2026-04-03): classify-then-act skill — the strongest possible text intervention (protocol with phases, hard rules, explicit anti-pattern warnings) — injected into coder for judgment-ambiguous-spec. 0/2 improvement (both arms 1/3). Extends record to 0/19.
- **EXP-018 (2026-04-03): structured-plan-writing skill — COUNTER-PRODUCTIVE.** Baseline scored 8/8, treatment scored 6/8. The skill triggered the exact over-planning anti-pattern it warned against (AP-5). Agent followed the 5-step planning protocol so diligently it timed out before completing deliverables. **First evidence that text skills can be net-negative**, not just zero-effect. Extends record to 0/20 with one harmful.
- **EXP-081 (2026-04-08): 4 text rule categories tested.** Identity/role framing (0/3), procedural trigger-action (0/3), preference statements (0/3), domain knowledge (0/3) on contradictory-requirements scenario. All 12 runs scored exactly 2/5 — identical to baseline. Even domain knowledge that explicitly states the mathematical tension between requirements failed to trigger contradiction detection. Extends total record to 0/32.
- Counter-evidence: workflow enforcement (two-phase, evidence-gate) achieved 92-97% pass rate on same scenarios.
- External validation: SkillsBench (Stanford/CMU/Berkeley, 7308 trajectories, 47150 community skills) — AI-generated skills average -1.3pp (harmful). Only top-25% human-written skills achieve +16.2pp.

## Limitations

- Text rules DO work for factual constraints ("use bun not npm") — that's KE-001.
- The distinction is: factual (text works) vs judgment (text doesn't work).
- Workflows work because they structure the task, not because they instruct the agent.
- SkillsBench shows that VERY high quality, focused skills (2-3 modules, human-curated) CAN work for tool-use tasks — but this is a quality threshold our AI-generated skills don't meet.
- **Over-compliance mechanism (EXP-018)**: Text skills with multi-step protocols can be harmful because the agent follows the protocol steps TOO diligently, consuming budget that should go to actual work. The skill warned against this (AP-5) but warning-about-self failed. This is a second-order text-rule failure: even meta-instructions within skills are ignored.

## Nuance: Structural Text vs Declarative Text (EXP-084)

EXP-084 tested skill delivery methods that sit between pure text rules and full workflow enforcement on the contradictory-requirements scenario (baseline 0/19 pass, 2/5 score):

| Method | Type | Pass Rate | Avg Score | Effect |
|--------|------|-----------|-----------|--------|
| Negative example | Declarative | 0/3 (0%) | 2.0/5 | None (= baseline) |
| Echo-back prompt | Structural | 1/3 (33%) | 3.3/5 | +1.3 score |
| Checklist injection | Structural | 0/3 (0%) | 4.0/5 | +2.0 score |
| Few-shot example | Structural | 1/3 (33%) | 4.3/5 | +2.3 score |
| Workflow enforcement | Full | 1/1 (100%) | 5.0/5 | +3.0 score |

**KE-002 holds for declarative text** (telling agents what to do, warning them, giving domain knowledge). Total record: 0/35.

**KE-002 needs refinement for structural text** (showing agents how to reason, creating pre-work gates, forcing verbalization). These produce large score improvements (Cohen's d > 3) but unreliable pass rates (33% at N=3, not statistically significant). The distinction: declarative text describes an **outcome**; structural text modifies the **process**.

**Caution**: N=3 per arm is underpowered. The score improvements are real; the pass rate improvements may be noise. See EXP-084 results for full statistical analysis.
