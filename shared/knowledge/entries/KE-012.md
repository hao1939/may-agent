# KE-012: Lab-fork null-patch test confirms infrastructure validity

**Evidence-Grade:** C — Single controlled experiment, single agent

**Status**: verified
**Evidence**: 1 controlled experiment with optimizer (zero-change fork)
**Discovered**: 2026-03-17
**Last verified**: 2026-03-17

## Claim

Creating a lab fork with zero code changes produces identical gym results to the baseline agent. This rules out infrastructure overhead (fork mechanism, directory copying, etc.) as a confound in A/B experiments. When patched agents regress, it's caused by the patch itself, not the fork mechanism.

## Evidence

- **Null-patch test**: Forked optimizer with ZERO changes. Both scenarios pass identically to baseline (6/6, 5/5). Lab-fork mechanism works correctly.
- **Implication**: Sprint 1 regressions (multiple -2 to -4 check regressions) were caused by the patches themselves (heartbeat restructuring, soul guards), not by lab infrastructure.

## Significance

This is a critical validation of the experimental methodology. Without this test, all negative results could be attributed to infrastructure issues. With it confirmed, we can trust that:
- Regressions are caused by the intervention
- Improvements are caused by the intervention (not by fork novelty or path changes)
