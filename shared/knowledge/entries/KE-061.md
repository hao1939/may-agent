## Core Discovery: There Is a Formal Boundary Where More Text Guidance Hurts

Six independent signals — three research papers, one XHS community consensus, one memory architecture paper, and live system data — converge on the same previously unnamed principle:

> **Text-mutable evolution (prompt edits, context growth, instruction accumulation) has a provable ceiling. Past this ceiling, every addition to guidance REDUCES system performance. The system is at this ceiling now.**

## How the Ceiling Manifests in Our System

### Manifestation 1: The Guardrail Paradox (KE-059 → MOSS connection)

The evaluator receives two persistent red alerts. The system's response was text-mutable: inject KE references and "do not investigate" instructions into the prompt.

**The problem is structural** (clock-driven heartbeat fires regardless of state change). **The fix attempted is textual** (instructions saying "don't do the thing your structural trigger tells you to do").

MOSS's theorem predicts this fails: when the routing logic (heartbeat fires on clock) contradicts the text guidance (don't investigate unchanged state), the structural trigger wins because it's architecturally load-bearing — it's WHY the session exists.

**Evidence:** Despite 10+ sessions with explicit "do not treat as new investigation" instructions, the evaluator STILL processes the alert text (reading KE references, reasoning about the metric, concluding "expected"). The text tells it to skip; the structure forces it to engage.

### Manifestation 2: The Instruction Inflation Asymmetry

| Agent | Context growth mechanism | Ops trajectory | At ceiling? |
|:-----:|:------------------------|:-------------:|:----------:|
| evaluator | Alert guardrails accumulate | 21.7 → 38.0 (+75%) | **Yes** — more text = higher cost, zero benefit |
| arc | KE context at maximum | 64.7 → 70.2 (+8%) | **Near** — flat cost, zero new insights (KE-049) |
| scout | Recently simplified | 54.1 → 48.7 (−10%) | **Below** — simplification helped |
| dev | Fixed contract, no growth | 9.3 → 6.5 (−30%) | **Far below** — model improvements flow through |

**The control case is dev.** Its fixed contract means model efficiency improvements translate directly to cost reduction (−30%). Every other agent's text growth ABSORBS model improvements and converts them into constant or rising costs.

### Manifestation 3: The Self-Optimization Trap

SkillOpt's key architectural decision: **the optimizer must be separate from the solver.** When the same model both executes tasks and proposes its own guidance edits, it cannot identify its own blind spots.

Our system's version: KE-058 identified four simultaneous stall mechanisms, all involving self-referential improvement loops. The KE library (60 entries, 10,220 lines) was written by agents analyzing themselves. Every entry that proposes a fix does so from within the same context that couldn't fix the problem — the optimizer IS the solver.

Life-Harness's finding explains why this fails: persistent agent failures are **environment-side** (tool contracts, scheduler behavior, metric computation logic) not **model-side** (reasoning capability). Text guidance helps the model reason better; it CANNOT change the environment the model operates within.

## The Taxonomy of What's Below vs. Above the Ceiling

Using Life-Harness's four-layer failure taxonomy:

| Layer | Fixable by text? | Example in our system | Evidence |
|:-----:|:----------------:|:---------------------|:---------|
| **Contract** (tool/env interface) | Partially | Tool definition clarity, output format requirements | Some KE lessons about query_db schema → effective |
| **Skill** (multi-step procedure) | Yes (below ceiling) | SQL cheatsheet in arc's prompt, finish hygiene checklist | Arc's schema errors eliminated after cheatsheet |
| **Realization** (action format) | Yes (below ceiling) | "Use explicit paths; never git add ." | Commit hygiene improved with instruction |
| **Regulation** (trajectory control) | **NO** (ABOVE ceiling) | "Don't investigate unchanged alerts" | Text says don't; structure forces engagement anyway |

**The ceiling sits between Layer 3 (Realization) and Layer 4 (Regulation).** Text guidance can teach agents WHAT to do and HOW to format it. It cannot teach agents WHEN NOT TO ACT — because the structural triggers that cause action are upstream of text processing.

## The Resolution Pattern (What Works Above the Ceiling)

Every paper that addresses above-ceiling failures uses the same primitive: **structural intervention, not textual instruction.**

| Paper | Structural Fix |
|:-----:|:--------------|
| SkillOpt | Separate optimizer model with validation gate — edits only accepted when quality improves |
| Life-Harness | Runtime harness adaptation that modifies the ENVIRONMENT interface, not the model instructions |
| MOSS | Source-level rewriting of routing/dispatch/state code |
| Self-Healing Orchestrators | Bounded recovery budgets with failure-class routing — structural, not instructional |
| Engram | Bi-temporal invalidation — facts EXPIRE, not "instructions to ignore old facts" |
| LACUNA | Type-checking at the interface — structural rejection, not instruction to self-check |

**The common element:** All solutions operate on the STRUCTURE that causes behavior, not the INSTRUCTIONS that describe desired behavior.

For our system, the above-ceiling fixes are:
1. **Don't fire heartbeat when state unchanged** (structural gate, not "don't investigate" instruction)
2. **Expire stale alerts after N unchanged checks** (structural cleanup, not "known issue" annotation)
3. **Separate the optimization loop from execution** (dedicated arc/evaluator improvement sessions that don't share the solver's context)
4. **Relevance-gate context injection** (structural: skip context loading when task doesn't match, not "ignore irrelevant context")

## The Principle (One Sentence)

> **When instruction cost exceeds instruction benefit, the system needs a structural change, not a better instruction.**

This is MOSS's Turing-completeness argument made concrete: text-mutable guidance is a proper subset of what structural code changes can express. The persistent failures in our system live in the gap between what instructions can describe and what code can enforce.
