# KE-007: Workflow enforcement (Method #15) is the only reliable behavioral intervention

**Status**: verified
**Evidence**: 56+ experiments (5 promoted, 5 discarded, rest infrastructure/ceiling issues)
**Discovered**: 2026-03-17
**Last verified**: 2026-04-02

## Claim

Two-phase workflow enforcement — structuring a task into Phase 1 (assess/diagnose) and Phase 2 (act based on assessment) — is the only method that reliably changes agent judgment behavior. It works across agents (coder, QA, bob) and failure modes (verification gaps, over-strict gating, efficiency).

## Evidence

### Promoted experiments:
1. **QA over-strict gate** (FM-2.1): Baseline QA fails qa-overstrict-gate 0/1 (gives FAIL verdict for environment failures). Two-phase workflow (diagnose → verdict) achieves 6/6. QA correctly distinguishes environment failures from patch bugs.
2. **Coder prerequisite check** (FM-3.3): Method #15 flips critical behavior — coder calls `finish(blocked)` instead of `finish(success)` when prerequisite file is missing. Correct judgment at cost of efficiency (10+ tool calls vs <10), acceptable tradeoff.
3. **Coder verification** (two experiments): Baseline fails verification checks. Workflow enforcement achieves 100% pass rate (N=2 each). Phase 1 assessment-only constraint forces disciplined state-checking.
4. **Bob convention compliance**: Patched 3/5 vs baseline 2/5 on convention-verify scenarios.
5. **Coder tool discovery** (EXP-015): Baseline coder uses `npx vitest run` 0/3 despite prompt saying "npx not available." Two-phase workflow (discover tools → execute planned command) achieves 2/2 (100%). Forced discovery phase makes environmental knowledge actionable. R≈0.90.

### Why it works:
Workflow enforcement changes task **structure**, not instructions. Instead of telling agents "remember to check X," it forces them to *do* the checking as a prerequisite step before acting. This bypasses the text-rule blindness documented in KE-002.

### Limitations found:
- **Does NOT work for materialization patterns** (exp-094): Method #15 failed for "write intermediate findings to file" behavior. Baseline 6/9, patched 5/9 (regression). Verification ≠ materialization.
- **Ceiling effects** hide improvements: Many scenarios where agents already pass at baseline, making measurement impossible.
- **Infrastructure fragility**: Several experiments lost to gym bugs (JSON parse errors, bun not found in env, branch already checked out).

## Limitations

- Only tested with Claude Sonnet 4. May differ with other models.
- Works for judgment/verification patterns, not all behavioral categories.
- Efficiency cost: adding forced assessment phases increases tool calls.
- Small N per experiment (2-3 runs). Directionally strong but not statistically powered.
