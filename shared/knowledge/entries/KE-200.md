# KE-200: Probe-Based Monitoring Could Predict FM-3.3 Verification Collapse Before It Manifests

**Status**: HYPOTHESIS — grounded in DD-770 findings, untested in our system
**Source**: DD-770 (Cognitive Companion — Parallel Monitoring for Reasoning Degradation)
**Date**: 2026-04-16
**Extends**: KE-123 (over-intervention iatrogenesis), KE-125 (task-type mismatch harm)

---

## Finding

DD-770 demonstrates two parallel monitoring approaches for reasoning degradation (looping, drift, stuck states affecting ~30% of hard tasks):

1. **LLM Companion** — separate LLM watches agent outputs, reduces loops 52-62%, costs ~11% overhead
2. **Probe-based Companion** — classifier on hidden states (layer 28) predicts degradation *before it manifests in text*. AUROC 0.840, zero inference overhead.

The probe-based approach is especially relevant: it detects degradation at the sub-token level before the agent produces bad output. This is exactly the "predict before it happens" capability our FM-3.3 guards lack.

## Connection to FM-3.3 Verification Collapse

FM-3.3 (verification skip — 20.3% rate per EXP-099) is a form of reasoning degradation where the agent skips post-edit verification and calls finish(success) prematurely. Current mitigation is a structural guard that rejects finish() without verification evidence — reactive, not predictive.

**Could probes detect FM-3.3 onset?** DD-770's probe approach monitors hidden states for degradation signatures. If verification collapse has a distinct hidden-state pattern (e.g., the agent's internal representation shifting from "task incomplete" to "task done" without passing through a verification step), a probe could flag it before the bad finish() call is generated. This would enable preemptive intervention rather than post-hoc rejection.

## Task-Type Dependency Explains FM-3.3's Selective Appearance

DD-770's key finding: monitoring helps on loop-prone/open-ended tasks but is neutral or negative on structured tasks. This maps directly to our observation that FM-3.3 doesn't hit uniformly — it concentrates on certain scenario types.

**Hypothesis**: FM-3.3 is more likely on tasks where the agent enters a "completion momentum" state — tasks with clear edit→done progression where the agent's reasoning shortcuts the verify step. Structured tasks with explicit checkpoints may naturally resist this. If true, a probe-based monitor should activate selectively based on task type, not globally.

## Alignment with KE-123: Selective Activation Over Stacking

DD-770's selective activation finding directly validates KE-123's "don't stack interventions" principle:

- KE-123 shows combined interventions cause -12pp to -15pp degradation (superadditive harm)
- DD-770 shows monitoring interventions are harmful on structured tasks where they're unnecessary
- **Implication for guard design**: The optimal architecture is a lightweight probe that activates intervention *only when degradation is predicted*, not an always-on guard that taxes every task

This resolves a tension in our system: we want FM-3.3 protection but KE-123 warns against layering guards. A probe-based approach squares this circle — the monitoring layer has zero overhead (hidden-state classifier, no extra LLM calls), and intervention fires only when the probe detects degradation onset.

## Practical Implications for May

1. **Short-term (no hidden-state access)**: We can approximate probe-based monitoring with text-level heuristics — detect "completion momentum" patterns in agent output (e.g., agent stops asking questions, stops reading files, jumps to finish). Our existing FM-3.3 guard does a crude version of this.

2. **Medium-term**: If model providers expose hidden-state access or logprobs, train a lightweight classifier on FM-3.3 cases vs. successful verification sequences. DD-770 suggests layer 28 (late middle layers) is where degradation signatures concentrate.

3. **Guard design principle**: Prefer *conditional* guards over *unconditional* ones. The cost of an always-on guard (KE-123 iatrogenesis) exceeds the cost of occasional FM-3.3 misses, especially on creative/synthesis tasks where KE-091 shows verification guards harm output quality.

## Limitations

- DD-770's probe approach requires hidden-state access — unavailable in our API-based setup
- AUROC 0.840 means ~16% false negatives — not reliable enough as sole defense
- DD-770 tested on loop/drift degradation, not specifically verification-skip behavior
- Scale boundary: no improvement on 1B-1.5B models — unclear if our model tier is above threshold
- Text-level approximation of probe monitoring may not capture the sub-token predictive advantage
