# KE-151: Extended Thinking Is Disabled System-Wide — Infrastructure Gap for Reasoning Observability

**Date:** 2026-04-12  
**Source:** EXP-146 feasibility assessment  
**Author:** Bob  
**Connections:** H-105, EXP-146, KE-146, DD-750

## Finding

Extended thinking (`thinkingLevel`) is disabled for all agents in the pi-agent system. The parameter defaults to `"off"` in pi-agent-core, and no agent configuration overrides this default. As a result, **210 of 211 stored sessions contain zero thinking-type content blocks.**

The one exception is amy-kimi (session `s_1775237923782_1`), which uses kimi-k2.5 — a model that natively returns thinking blocks regardless of configuration.

## Technical Details

**Default behavior** (`node_modules/@mariozechner/pi-agent-core/dist/agent.js`):
```javascript
thinkingLevel: initialState?.thinkingLevel ?? "off"
// converts to: reasoning: "off" ? undefined : thinkingLevel
```

When `thinkingLevel` is `"off"`, the `reasoning` parameter is `undefined`, so the LLM API receives no reasoning/thinking instruction — the model runs in standard mode.

**Configuration gap:** The `SubagentDefinition` type in `src/lib/types.ts` does not include a `thinkingLevel` field. Agent configs (`agents/*/agent.json`) specify model, description, domain, tools, compaction — but no thinking configuration.

**Infrastructure readiness:** Despite being disabled, the full pipeline for thinking traces already works:
- pi-ai supports five thinking levels: `"minimal"`, `"low"`, `"medium"`, `"high"`, `"xhigh"`
- Streaming handles `thinking_start`, `thinking_delta`, `thinking_end` events
- Storage (`appendSessionMessage`) persists full messages including thinking blocks via `JSON.stringify` — no field stripping
- Proven by kimi-k2.5: thinking blocks are captured and stored end-to-end

## What This Means

1. **All agents run without explicit reasoning traces.** Every reasoning step we observe (planning, awareness, self-correction) happens in the output layer (Layer 3 in H-105's model) — we have zero visibility into Layer 2 reasoning.

2. **We cannot test H-105's core prediction.** The Three-Layer Reasoning Model hypothesizes that thinking traces catch ~3× more failures than output monitoring. With thinking disabled, predictions P-105a through P-105e are all blocked.

3. **Enabling thinking is trivial.** The engineering effort is estimated at <1 hour:
   - Add `thinkingLevel` to `SubagentDefinition` (~5 lines in types.ts)
   - Pass through `createAgent()` (~3 lines in manager.ts)
   - Set per-agent config: e.g., `"thinkingLevel": "low"` in agent.json

4. **Cost implications are real but manageable.** Extended thinking adds 500-2000 tokens/turn depending on level. At `"low"`, this is modest. Recommendation: pilot with 1-2 agents before system-wide rollout.

## Significance

This is a fundamental observability gap. We're building a system designed to understand and improve agent reasoning, but we can't see agent reasoning — only its compressed output. The gap between "what the model considers" and "what the model produces" is exactly where H-105 predicts the most actionable failure signals live.

The irony: the infrastructure to close this gap already exists. It's a configuration change, not a capability gap.
