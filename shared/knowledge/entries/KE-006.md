# KE-006: Skills that target reasoning patterns don't change tool-calling patterns

**Evidence-Grade:** C — Single experiment (EXP-004), single scenario

**Status**: observed
**Evidence**: EXP-004 (H-004 refuted)
**Date**: 2026-04-01

## Finding

The plan-once-amend skill teaches "mark blocked and move on" (a reasoning/planning instruction), but the agent's actual failure mode is persistent tool-calling: trying `read()`, `find`, `ls` for a missing file 4+ times. The skill changed neither the number of search attempts nor the pass rate.

This extends KE-002 (text rules don't fix judgment failures). Even well-structured skills with worked examples, anti-patterns, and specific trigger conditions fail when the target behavior is a tool-calling habit rather than a reasoning/judgment pattern.

## Implication

To fix "too many attempts at a missing file," the intervention needs to operate at the tool-calling level:
1. **Framework guard**: After 2 failed reads of the same path, inject a system message ("file confirmed missing, mark blocked and proceed")
2. **Tool-level retry limit**: Framework blocks 3rd attempt to read same non-existent path
3. **Environment signal**: Error message for ENOENT could include "Tip: if this file doesn't exist, mark it as blocked and move to the next task"

Text-level skills work when the agent needs to *know* something it doesn't know. They don't work when the agent *knows* the right behavior but can't stop itself from retrying.
