# KE-020: Agent capability adoption requires explicit wiring, not just availability

**Status**: verified  
**Evidence**: EXP-028 (natural experiment), EXP-020 (observational), H-053 (decay data)  
**Discovered**: 2026-04-05  
**Last verified**: 2026-04-05

## Claim

LLM agents do not spontaneously discover or use available capabilities (workflows, tools, knowledge files). Adoption requires **explicit instructions in the agent's primary instruction source** (heartbeat). Capabilities that exist but aren't wired into the heartbeat have effectively zero usage. Even wired instructions produce a decaying adoption curve (peak → 60-80% decay over 7 days), but sustain a non-zero floor (~4-10%) that is dramatically better than zero.

## Evidence

### EXP-028: The Heartbeat Rewrite Natural Experiment

On 2026-04-01, a heartbeat rewrite removed `workflow.run()` instructions from coach's heartbeat while leaving all workflow code intact and available.

**Before removal (Mar 29-30)**: Coach used workflows 7-8 times/day, done rate ~85%  
**After removal (Apr 2-3)**: Coach used workflows 0 times/day, done rate ~34%  
**Effect size**: 51pp done-rate degradation — the largest measured in the system

Critical detail: the training-sprint cron job still included `workflow.run()` in its task description, but agents ignored embedded instructions — they only follow their heartbeat.

### EXP-020: Workflow Decay Data

Even WITH instructions present, system-wide workflow adoption decayed from 19.7% → 1.8% over 6 days (Mar 26 → Mar 31). The heartbeat rewrite then drove it from 1.8% → 0%.

### The Adoption Hierarchy

Three levels of capability wiring, with dramatically different adoption rates:

| Level | Mechanism | Adoption Rate | Persistence |
|-------|-----------|--------------|-------------|
| **Available** | File exists in workflows/ dir | ~0% | Never adopted |
| **Instructed** | Heartbeat says "use workflow X" | ~4-10% floor | Decays from peak over 7 days |
| **Automatic** | Infrastructure routes to workflow | 100% by definition | Permanent |

### System-wide workflow quality gap

During the period when workflows were used (EXP-028 data):
- Workflow sessions: **83.9% done rate, 0% error rate**
- Non-workflow sessions: **73.9% done rate, 10% error rate**

## Why It Matters

This is a **meta-level instance of KE-002** (text rules don't change behavior). Just as text skills don't change judgment, *text descriptions of available tools don't cause tool adoption*. The mechanism is the same: LLMs process instructions in priority order, and capabilities mentioned outside the primary instruction stream are functionally invisible.

The implication is stark: **every capability we build has an adoption problem**. Building the capability is half the work. The other half is wiring it into the instruction path where agents will actually encounter and use it.

## The Dual-Cause Model

The complete adoption story has two phases:

1. **Organic decay** (instructions present, usage declining): Agents gradually optimize for shorter sessions, and workflow overhead (~25% more ops) creates selection pressure against usage. This phase takes 3-7 days from peak to floor.

2. **Instruction removal** (catastrophic collapse): Removing instructions from the heartbeat causes immediate and complete extinction. This phase takes 1-2 days.

The reverse also holds: **restoring instructions should recover to the floor** (~4-10%) within 1-2 days, but will NOT recover to the initial deployment peak without additional novelty/deployment energy.

## Implications

1. **Build adoption plans alongside capabilities** — every new workflow, tool, or knowledge file needs a specific wiring plan
2. **Heartbeat is the critical path** — if it's not in the heartbeat, it doesn't exist to the agent
3. **Automatic routing > instruction-based adoption** — for critical capabilities, the infrastructure should select the workflow, not the agent
4. **Audit heartbeats for capability gaps** — any workflow not mentioned in an agent's heartbeat has 0% adoption regardless of quality
