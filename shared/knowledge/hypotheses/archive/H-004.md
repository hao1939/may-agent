# H-004: Plan-once-amend skill improves blocker handling efficiency

**Status**: refuted
**Priority**: high
**Proposed by**: bob (from research agenda analysis)

## Hypothesis

Installing the plan-once-amend skill (skills/plan-once-amend/SKILL.md) into the coder agent improves the `handles-blocker-efficiently` check pass rate on the plan-once-amend gym scenario.

## Existing Evidence

- **Baseline**: 7/8 (exp-185-baselines, 2026-03-25). Only failing check: `handles-blocker-efficiently` — agent spends >3 operations searching for the missing `health-check.ts` instead of marking it blocked and moving on.
- **KE-002**: Text rules don't fix *judgment* failures (0/18). But this isn't judgment — it's a behavioral pattern (when to give up searching). Skills with specific trigger conditions and procedures have shown promise for behavioral patterns even when text rules fail.
- **The skill directly targets the gap**: The plan-once-amend skill's Step 3 "Never Redeclare" and the scenario's blocker handling check are aligned — the skill explicitly teaches "mark blocked, move on."
- **No prior experiments on this skill**: This is the first test.

## Experiment Design

**Control**: Run plan-once-amend scenario with coder (no plan-once-amend skill)
**Treatment**: Run same scenario with coder + plan-once-amend skill installed
**Metric**: 
- Primary: `handles-blocker-efficiently` check pass (yes/no)
- Secondary: Total score (X/8), total ops
**Scenarios**: plan-once-amend
**Runs**: 3 per arm (6 total)
**Success criteria**: Treatment passes `handles-blocker-efficiently` in at least 2/3 runs AND control fails it in at least 2/3 runs
**Cost estimate**: ~$0.60 (6 runs × ~$0.10)

## Results

**Verdict: REFUTED — No effect**

| Arm | handles-blocker-efficiently | Overall |
|-----|---------------------------|---------|
| Control (no skill) | 1/3 (33%) | 1/3 pass |
| Treatment (with skill) | 1/3 (33%) | 1/3 pass |

The skill had zero measurable effect. Both arms showed identical 1/3 pass rates on the target metric.

**Root cause analysis**: The `handles-blocker-efficiently` check measures whether the agent spends ≤3 tool operations searching for a missing file. The plan-once-amend skill teaches plan tracking (don't redeclare your plan), but doesn't directly address the search-obsession behavior. The agent's tendency to keep trying `read`, `find`, `ls` for the missing `health-check.ts` is a search-persistence issue, not a planning-structure issue.

**Insight → KE-006**: The skill text teaches "mark blocked and move on" but the agent's actual behavior is to try multiple search strategies before giving up. The skill addresses the cognitive pattern (replanning) but not the motor pattern (retrying tool calls). This suggests skills need to target the specific tool-calling behavior, not just the reasoning pattern.
