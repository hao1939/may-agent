# H-0180: MCP协议 vs CLI工具调用架构选择

**状态**: ACTIVE  
**创建**: 2026-04-02  
**来源**: XHS社区讨论 + Anthropic官方立场

## 假设陈述

对于我们的Agent系统，**CLI优先的工具调用架构**可能比MCP协议更符合实际需求，因为：
1. 更直接的控制性
2. 更低的Token开销
3. 更简单的调试和维护
4. 行业趋势显示大厂正在从MCP转向CLI

## 证据

### 支持CLI优先的证据

1. **Perplexity CTO公开表态**: 内部已弃用MCP
2. **Anthropic官方**: "为什么1个Bash工具胜过..." (346赞)
3. **社区共识**: CLI vs MCP讨论帖 (158赞) 倾向于CLI更可控
4. **Token效率**: Anthropic新方法可节省50% Token，MCP被认为是浪费来源
5. **微软迁移**: 向CLI工具迁移

### MCP仍适用的场景

- 需要跨平台标准化的生态
- 多供应商互操作性要求
- 复杂工具链需要统一协议

## 关键问题

| 维度 | MCP | CLI |
|------|-----|-----|
| 复杂性 | 高(需实现协议) | 低(直接调用) |
| Token效率 | 较低 | 较高 |
| 调试难度 | 高 | 低 |
| 生态成熟度 | 早期 | 成熟 |
| 厂商支持 | Anthropic主导 | 通用 |

## 建议的实验

1. **基准测试**: 相同任务下MCP vs CLI的Token消耗对比
2. **开发效率**: 实现相同工具集的开发时间对比
3. **错误率**: 两种方式的失败率和调试难度对比

## 决策建议

**短期**: 采用CLI优先，但保持MCP兼容层
**长期**: 根据社区生态发展决定，不过早绑定单一标准

## 风险

- MCP可能成为事实标准，CLI方案需要后期迁移
- CLI工具缺乏统一规范，可能导致碎片化
