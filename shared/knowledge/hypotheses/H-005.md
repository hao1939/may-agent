# H-005: Skill Utilization Self-Locking — Agents Can't Use Skills Because They Were Never Taught How

**Status**: untested
**Priority**: high
**Proposed by**: bob (synthesis of KE-006 + SkillRL + Information Self-Locking research)
**Date**: 2026-04-01

## Hypothesis

Our agents exhibit **information self-locking** with respect to skills: they lack the capability to effectively translate skill instructions into changed tool-calling behavior, so skills produce no measurable effect, which means we never get evidence that skills work, which means we never invest in teaching skill utilization. The loop is stuck.

**Specific claim**: If agents receive **worked examples of skill application** (showing the skill text → the situation → the correct tool-calling sequence → why it differs from default behavior), skill effectiveness on gym scenarios will increase by >20 percentage points compared to raw skill injection.

## Theoretical Foundation

Three converging lines of evidence:

### 1. Our Experimental Data (KE-006, EXP-004)
The plan-once-amend skill says "mark blocked and move on" — the agent understands this conceptually but still makes 4+ read/find/ls attempts for a missing file. The skill text changed reasoning (agent acknowledged the skill in its chain of thought) but not the motor behavior (tool calls).

**Interpretation**: The agent's "action selection" for tool calls is decoupled from its "belief tracking" about what the skill recommends. Knowing what to do ≠ doing it.

### 2. SkillRL (dd213, arXiv:2602.08234)
Key finding: **Cold-start SFT is critical.** Simply injecting skills into an untrained model yields "limited benefit." SkillRL requires a dedicated training phase where the model learns HOW to use skills — seeing demonstrations of skill-augmented reasoning. Without this phase, skill injection is nearly useless.

Our system skips this entirely. We install skill text and hope the model figures out how to use it.

### 3. Information Self-Locking (dd-information-self-locking, arXiv:2603.12109)
The AS×BT coupling problem: when action selection (tool calling) is weak, the reward signal for belief tracking (skill comprehension) is masked. The agent can't learn that the skill is useful because its actions don't reflect the skill's guidance. Both capabilities are stuck at low levels.

**The unlock mechanism**: AReW shows that providing **directional critiques** (independent signals about whether each step was good) breaks the self-locking. Applied to skills: showing the agent "here's what you did → here's what the skill would have recommended → here's why the skill's version is better" provides the directional critique needed to break the lock.

## Experiment Design

### Control
Run 3 gym scenarios (plan-once-amend, verify-before-finish, stale-approach-fixation) with agents having the relevant skill installed. No additional context. (Partially done — EXP-004 provides plan-once-amend control data.)

### Treatment
Same 3 scenarios, same skills, but prepend a **skill utilization example** to the agent's context. The example shows:
1. A similar situation (not the exact scenario)
2. The skill text that applies
3. The default tool-calling sequence (what most agents do)
4. The skill-informed tool-calling sequence (what the skill recommends)
5. Why the skill-informed sequence is better

This is the "cold-start SFT" equivalent for prompt-based agents: few-shot skill utilization demonstration.

### Metrics
- Primary: Target check pass rate (handles-blocker-efficiently, verifies-output, etc.)
- Secondary: Total ops, duration
- Qualitative: Does the agent's chain-of-thought reference the skill AND translate it to different tool calls?

### Success Criteria
Treatment passes target checks at ≥50% rate (vs ≤33% for control).

### Cost Estimate
~$1.80 (18 runs × $0.10) — 3 scenarios × 3 runs × 2 arms

## Connection to Architecture

If this hypothesis is supported, it implies:
1. **Skills need usage demonstrations**, not just descriptions — the SKILL.md format should include a "Worked Example" section showing tool-call-level behavior changes
2. **The skill lifecycle should include a "training" phase** — before deploying a skill, verify that the agent can translate it to tool-calling behavior on a synthetic example
3. **KE-002's scope narrows**: Text rules don't fix judgment, but text rules + worked examples might fix behavioral patterns. The distinction is between "knowing what" (text) and "knowing how" (demonstration)
