# H-001: Adversarial QA framing increases issue detection rate

**Status**: ❌ DISCONFIRMED (2026-04-07)
**Priority**: archived
**Proposed by**: Hao/pi (from KE-005 analysis)
**Resolution**: EXP-038 showed adversarial framing provided NO detection benefit and HURT evidence discipline (skipped tests 2/3 times on hard scenarios). +19-58% slower. P(H) = 0.30. H-082 (SCRAT adversary role) merged here and also did not overcome the result. See PRIORITY-TRACKER.md.

## Hypothesis

Giving QA an adversarial framing ("try to break it, find bugs") instead of confirmatory framing ("review this code") will increase issue detection rate from 14% to >30%.

## Existing Evidence

- KE-005: QA finds issues in 14% of reviews. Evaluator flags 27%.
- KE-002: Text rules don't fix judgment. But framing (how the task is structured) is different from text rules (instructions in SOUL.md).
- Workflow enforcement works 92-97% (KE-002). Framing the QA task as a workflow with adversarial structure may help.

## Experiment Design

**Control**: 10 QA reviews with current framing ("review this implementation")
**Treatment**: 10 QA reviews with adversarial framing ("find bugs, try to break it, check edge cases, run the tests")
**Metric**: issue detection rate (% of reviews that find real issues)
**Success criteria**: treatment detection rate > 2x control rate
