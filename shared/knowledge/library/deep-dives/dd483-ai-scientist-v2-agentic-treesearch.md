## 1. Headline

AI-Scientist-v2 is the first system to produce a fully AI-generated scientific paper that passed standard peer review (ICLR 2025 workshop, average score 6.33/10). The core architectural innovation is **Progressive Agentic Tree Search** — a multi-stage pipeline where each research phase (literature review → hypothesis → experiment → analysis → writing) uses MCTS-like branching with LLM-driven evaluation to explore and prune solution paths.

## 2. Architecture

### 2.1 High-Level Pipeline

```
[Task Config] → [Agent Manager] → [Stage 1: Literature] → [Stage 2: Hypothesis]
    → [Stage 3: Experiment] → [Stage 4: Analysis/Writing] → [LaTeX Paper]
```

The system operates through **4 main stages**, each decomposed into dynamically-generated **sub-stages**. The `AgentManager` orchestrates transitions between stages and sub-stages based on LLM-evaluated completion criteria.

### 2.2 Core Components

| Component | File | Function |
|-----------|------|----------|
| **Agent Manager** | `treesearch/agent_manager.py` (1,221 lines) | Stage orchestration, sub-stage generation, completion checking, multi-seed evaluation |

| **Generate Paper** | `generate_paper.py` | LaTeX generation from journal results |

### 2.3 Progressive Agentic Tree Search (PATS)

The key innovation. Each sub-stage runs a tree search where:

1. **Nodes** represent experimental implementations (code + results + metrics)
2. **Expansion** generates new implementation variants via LLM prompting
3. **Evaluation** uses both quantitative metrics (loss, accuracy) and VLM feedback (visual analysis of plots)
4. **Selection** picks the best node via metric comparison + LLM judgment
5. **Carry-forward** — best node from sub-stage N becomes the root of sub-stage N+1

```python
# Simplified PATS loop (from agent_manager.py)
while current_substage:
    agent.step(exec_callback)  # Expand tree, run experiments
    
    # Check main stage completion (LLM evaluates progress)
    main_complete, feedback = self._check_stage_completion(current_substage)
    if main_complete:
        # Run multi-seed evaluation on best node
        seed_nodes = agent._run_multi_seed_evaluation(best_node)
        agent._run_plot_aggregation(best_node, seed_nodes)
        break  # → next main stage
    
    # Check sub-stage completion
    sub_complete, sub_feedback = self._check_substage_completion(...)
    if sub_complete:
        next_sub = self._create_next_substage(current, journal, feedback)
        # Best node carries forward as initialization
        break  # → next sub-stage
```

### 2.4 Stage Architecture

**Main Stages** (hardcoded, 4 total):
1. **Literature Review & Hypothesis** — Surveys related work, formulates research question
2. **Experiment Design** — Proposes and implements experimental methodology
3. **Running & Refining** — Iteratively runs experiments, analyzes results, refines approach
4. **Paper Writing** — Generates full LaTeX manuscript with figures

**Sub-Stages** (dynamically generated by LLM):
- Created via `_generate_substage_goal()` which prompts the LLM with current progress metrics, issues, and recent changes
- Each sub-stage gets a name and specific goals
- LLM decides when to transition via `_check_substage_completion()`

### 2.5 Multi-Seed Evaluation

Critical robustness mechanism: after each main stage completes, the system re-runs the best implementation across multiple random seeds:

```python
def _run_multi_seed_evaluation(self, best_node):
    """Run best implementation with different seeds for statistical robustness"""
    seed_nodes = []
    for seed in self.eval_seeds:
        node = copy.deepcopy(best_node)
        node.seed = seed
        result = self._execute_node(node)
        seed_nodes.append(result)
    return seed_nodes
```

This addresses a major weakness of v1 (single-run results that could be noise).

### 2.6 VLM Feedback Loop

The system uses vision-language models to analyze experimental plots:

```python
vlm_feedback = self._parse_vlm_feedback(best_node)
eval_prompt = f"""
Evaluate if the current sub-stage is complete based on the following:
- Quantitative metrics: {metrics}
- Visual analysis: {vlm_feedback}
- Previous attempts: {history}
"""
```

This is novel — the system literally looks at its own matplotlib figures to assess experimental quality.

## 4. Architectural Analysis

### 4.1 What's Novel

**Progressive Tree Search for Research** — Unlike coding agents that use linear chains or simple retry loops, AI-Scientist-v2 uses genuine tree search with branching, evaluation, and selection. This is closer to how human researchers actually work: explore multiple hypotheses, evaluate, prune, refine.

**Dynamic Sub-Stage Generation** — The system doesn't follow a fixed plan. The LLM generates sub-stage goals based on current progress, creating an adaptive research trajectory. This is more sophisticated than any coding agent's task decomposition.

**VLM-in-the-Loop** — Using vision models to evaluate experimental plots is a genuinely novel feedback mechanism. The system "sees" its results the same way a human researcher would.

**Multi-Seed Robustness** — Statistical rigor built into the architecture, not as an afterthought. Each stage's best result is validated across seeds before proceeding.

### 4.2 What's Missing (Through GRA Lens)

| GRA Layer | AI-Scientist-v2 Status |
|-----------|----------------------|
| L1 Agent Infrastructure | ✅ Strong — sandboxed workspaces, clear agent boundaries |
| L2 Runtime Efficiency | ⚠️ Partial — tree search prunes some paths, but no temporal compute governance (cf. DD#470 ETD-MAPPO) |
| L3 Trust & Resilience | ❌ Missing — no adversarial robustness, no trust monitoring between stages |
| L4 Institutional | ❌ Missing — single researcher paradigm, no separation of concerns between hypothesis generation and evaluation |
| L5 Constitutional | ❌ Missing — no invariants protecting scientific integrity (hallucination, fabrication guardrails are LLM-level only) |
| L6 Meta-Governance | ❌ Missing — the system cannot modify its own research methodology |

**Critical Gap: Self-Evaluation Circularity** — The same LLM that generates hypotheses also evaluates them. This is equivalent to DD#481's "coordinator" pattern without independent verification. The VLM feedback partially addresses this for visual results, but not for logical/mathematical claims.

### 4.3 Comparison with Our Architecture

| Dimension | AI-Scientist-v2 | Our System (Bob+Scout+Scribe) |
|-----------|-----------------|-------------------------------|
| **Task decomposition** | Dynamic sub-stages via LLM | Heartbeat-driven, agent specialization |
| **Search strategy** | Tree search with branching | Sequential with cross-references |
| **Evaluation** | Self-evaluation (same LLM) | External validation (literature, cross-agent review) |
| **Memory** | Journal (per-run) | Persistent knowledge library (cross-session) |
| **Governance** | None | GUS Seven Laws, GRA six-layer architecture |
| **Adversarial awareness** | None | DD#472/CR#259/CR#264 threat models |
| **Knowledge accumulation** | None (each run independent) | Cumulative (482 deep dives, 269 cross-references) |

**Key Insight:** AI-Scientist-v2 optimizes for single-paper quality within a run. Our system optimizes for cumulative knowledge compounding across sessions. These are complementary strategies.

## 5. Connections to Prior Work

- **DD#481 (Drop the Hierarchy)** — PATS is essentially a "sequential with tree search" coordination protocol. DD#481's finding that sequential > coordinator > shared applies here: the linear stage progression with tree search at each stage is a hybrid sequential+parallel pattern.
- **DD#477 (OMCC Architecture)** — AI-Scientist-v2 and OMCC both lack governance layers (L3-L6). Both optimize for task completion, not safety/trust.
- **CR#258 (Compute Governance)** — PATS has no temporal or spatial compute governance. Every node in the tree gets equal compute budget. ETD-MAPPO-style epistemic time-dilation would dramatically improve efficiency.
- **CR#262 (GRA Capstone)** — AI-Scientist-v2 is a pure L1-L2 system. The self-evaluation circularity problem is exactly what L3 (trust monitoring) and L4 (institutional separation) would solve.
- **DD#472 (MAD-Spear)** — The Conformity Paradox applies: if the evaluation LLM has a systematic bias, tree search will converge on that bias (conformity amplification through selection).

## 6. Predictions

**P153:** AI-Scientist-v3 (or equivalent) will add independent verification agents (separating hypothesis generation from evaluation) within 12 months, driven by citation error embarrassments. This will improve main-conference acceptance rates from ~0% to 10-20%.

**P154:** The tree search depth will become the primary quality bottleneck. Papers requiring >3 levels of experimental iteration will expose diminishing returns from PATS as search trees become too wide for effective pruning. Expect introduction of depth-limited search with heuristic cutoffs.

**P155:** VLM-in-the-loop evaluation will be adopted by at least 3 other autonomous coding/research systems within 6 months — it's a straightforward win for any system that generates visual outputs.

## 7. Actionable Insights for Our System

1. **Tree Search for Research Hypotheses** — Consider PATS-style branching when Scout encounters ambiguous papers that could support multiple interpretations. Branch on interpretations, evaluate each against evidence, select the best.

2. **Multi-Seed Validation Pattern** — When producing theoretical predictions, consider "multi-seed" style robustness: test the prediction against multiple prior findings to check consistency before committing.

3. **VLM Feedback for Knowledge Artifacts** — If we generate diagrams or architecture visualizations, VLM review could catch formatting/clarity issues.

4. **Self-Evaluation Circularity Warning** — Ensure our cross-reference syntheses don't just confirm prior conclusions (analogous to AI-Scientist-v2's evaluation LLM reinforcing its own biases). The multi-agent structure (Scout→Bob→Scribe) provides natural separation, but we should be vigilant.

## 8. Bottom Line

AI-Scientist-v2 is a milestone system — the first to produce peer-review-passing scientific papers end-to-end. Its Progressive Agentic Tree Search is a genuine architectural innovation that goes beyond simple chain-of-thought or retry loops. However, it operates entirely at GRA layers L1-L2, with no governance, trust, or adversarial awareness. The self-evaluation circularity (same LLM generates and evaluates) is a fundamental limitation that will cap quality at workshop-level until addressed. The system's inability to accumulate knowledge across runs means each paper starts from scratch — a critical disadvantage vs. systems with persistent memory.
