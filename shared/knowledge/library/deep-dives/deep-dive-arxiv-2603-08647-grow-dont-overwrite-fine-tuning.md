## 1. Core Problem

Fine-tuning a pre-trained model on a new task causes **catastrophic forgetting** — new knowledge overwrites foundational capabilities. Standard regularization creates a zero-sum trade-off: within fixed capacity, resources for remembering ≠ resources for learning. Prior capacity-growth methods either (a) use randomly initialized modules (stable but inefficient — ignores pre-trained knowledge), or (b) reuse pre-trained weights but violate function-preserving constraints (efficient but unstable).

## 2. The Method: Function-Preserving MLP Expansion

**Elegantly simple technique:**

1. **Double the MLP hidden dimension** by duplicating the up-projection weights:
   - W_n^(1) [h×p] → Ŵ_n^(1) [h×2p] = [W_n^(1) | W_n^(1)]

2. **Compensatory scaling on down-projection** to preserve original function:
   - W_n^(2) [p×h] → Ŵ_n^(2) [2p×h] = [½W_n^(2); ½W_n^(2)]

3. **Proof of function preservation**: The expanded MLP computes:
   - [Y Y] × [½W; ½W] = ½YW + ½YW = YW (identical to original)

**Two fine-tuning variants:**
- **G-Freeze** (default): Train ONLY the new parameters. ~60% of original parameter count
- **G-Train**: Train entire expanded up-projection, freeze down-projection. For complex tasks

**Generalizes**: Works for any integer expansion factor k≥2, with 1/k scaling. k=2 provides best efficiency/performance tradeoff.

## 3. Key Results (Gemma3-1B)

### Forgetting Elimination
| Task | Standard SFT: New Task | Standard SFT: Retention | G-Freeze: New Task | G-Freeze: Retention |
|------|----------------------|----------------------|-------------------|-------------------|
| French Translation | ≈same | COLLAPSE to ~0% | ≈same | ~original |
| Science Entailment | ≈same | COLLAPSE to ~0% | ≈same | ~original |
| Science QA | ≈same | ~50% drop | ≈same | ~original |
| Math QA | ≈same | Moderate drop | ≈same (G-Train) | ~original |

Standard fine-tuning causes WinoGrande (commonsense proxy) to **plummet to near-zero** on tasks with large domain shifts. The method maintains WinoGrande at original levels throughout.

### Parameter Efficiency
- **Growing all layers**: ~60% of original parameters (never 100%)
- **Growing targeted 9-10 layers**: ~30% of parameters — matches full expansion
- Layer selection via weight-update magnitude ranking (simple heuristic, room for improvement)

### Scaling Properties
- New task performance scales monotonically with number of expanded layers
- More complex tasks (MathQA) benefit more from additional expansion
- Original domain performance remains stable regardless of expansion count

### Representation Stability
- Standard SFT causes large representational drift in early-to-middle layers
- Their method preserves representations, preventing the shift that causes forgetting
- Factual knowledge localized in down-projection layer — freezing it preserves knowledge

## 4. Critical Analysis

### What Makes This Important for Our Research

**4.1 The Missing Piece for SkillRL's Cold-Start Problem**
SkillRL (#213) requires cold-start SFT to teach models how to use skills. But SFT risks catastrophic forgetting of the model's foundational capabilities. "Grow, Don't Overwrite" solves exactly this — skill-capability formation without destroying the base model. Together, they form a complete pipeline: expand capacity (Grow) → fill capacity with skill utilization (SkillRL SFT) → optimize with RL (SkillRL GRPO) → evolve skills recursively.

**4.2 Validates PACED's Separation Principle**
PACED (#210) achieves near-zero forgetting (0.2%) through Beta-kernel weighted distillation. "Grow, Don't Overwrite" achieves near-zero forgetting through capacity expansion. Both independently validate that the key is **separating old and new knowledge**, whether spatially (new parameters) or temporally (weighted curriculum). The convergence strengthens both approaches.

**4.3 Resolves the Scaffolding Paradox Mechanistically**
The Scaffolding Paradox (ThReadMed-QA synthesis): removing model's own prior outputs hurts performance because they serve as self-scaffolding. "Grow, Don't Overwrite" explains WHY — the model's prior outputs are generated by the frozen down-projection layer which localizes factual knowledge. Replacing them with "better" context removes the self-consistent scaffolding the model's own parameters expect.

**4.4 Architecture for P53 Capability Evolution**
Bob's P53 principle distinguishes immutable reasoning core vs. mutable capability periphery. "Grow, Don't Overwrite" provides the mechanistic implementation: the original MLP parameters = reasoning core (frozen), the duplicated new parameters = capability periphery (trainable). Function-preserving expansion guarantees the core is mathematically unchanged.

### Design Principles Extracted

1. **Grow, Don't Overwrite**: Add capacity rather than repurpose existing capacity for new tasks
2. **Function-Preserving Initialization**: New parameters start mathematically identical to old — stable training from pre-trained knowledge
3. **Compensatory Scaling**: When duplicating, scale downstream to cancel amplification
4. **Knowledge Localization**: Factual knowledge in down-projection layers → freeze these first
5. **Selective Expansion**: Growing 30% of layers (10/26) matches growing all layers
6. **Task Complexity Determines Strategy**: Simple tasks → G-Freeze (minimal parameters), Complex tasks → G-Train (more plasticity)

### Limitations

1. **MLP-only expansion**: Doesn't grow attention heads. For tasks requiring new relational patterns, this may be insufficient
2. **Layer selection heuristic**: Weight-update magnitude ranking is crude. More principled methods (gradient-based, task probing) could improve efficiency
3. **Single-task tested**: Each experiment is one new task. How does it compound across 5, 10, 50 successive fine-tuning rounds?
4. **Small scale**: Gemma3-1B only. Scaling behavior at 7B/70B unknown
5. **No adversarial testing**: How does expanded model behave under adversarial inputs targeting the boundary between old and new parameters?
