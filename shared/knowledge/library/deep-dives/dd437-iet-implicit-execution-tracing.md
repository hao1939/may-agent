## Core Problem

When a multi-agent system produces an incorrect or harmful answer, **who is accountable if execution logs and agent identifiers are unavailable?** This is the metadata-free attribution problem — one of the most practically important unsolved challenges in deployed MAS.

Current MAS architectures rely on structured logging (execution traces, agent IDs, delegation metadata) for accountability. But in production:
- Logs may be unavailable (privacy constraints, cross-organizational boundaries)
- Metadata may be stripped (API intermediaries, content delivery)
- Identifiers may be deliberately hidden (adversarial settings)
- Only the **final generated text** survives

## Key Innovation: Steganographic Agent Watermarking

IET introduces a **metadata-independent attribution framework** that works from generated text alone:

### Embedding Phase (During Generation)
- Each agent is assigned a **secret key**
- During token generation, **agent-specific keyed signals are embedded into the token distribution**
- The text becomes a **self-describing execution trace** — but the signals are detectable **only with the correct key**
- This is essentially **steganographic watermarking** adapted for multi-agent attribution

### Detection Phase (Post-hoc Attribution)
- A **transition-aware scoring method** processes the final text
- Identifies **agent handover points** — where one agent's contribution ends and another's begins
- **Reconstructs the interaction graph** — the full topology of which agent delegated to which
- All without any metadata, logs, or agent identifiers

## Technical Architecture

### Token-Level Signal Embedding
The approach modifies the token probability distribution during generation:
- Each agent has a unique key K_i
- The key biases token selection in a way that's statistically detectable but imperceptible to readers
- Similar to text watermarking (Kirchenbauer et al.) but **agent-indexed** rather than model-indexed
- Multiple agents' signals can coexist in the same text

### Transition-Aware Scoring
- Sliding window analysis of token-level statistics
- Identifies **regime changes** in the statistical signature — corresponding to agent handovers
- Produces a segmentation: which tokens were generated by which agent
- Constructs a **directed graph** of agent interactions from the handover sequence

### Key Properties
1. **Metadata-independent**: Works from text alone
2. **Privacy-preserving**: Signals invisible without secret key
3. **Topology-reconstructing**: Recovers not just who contributed, but the interaction structure
4. **Quality-preserving**: Generation quality maintained (the signal is in distribution choice, not content)

## Experimental Results

- **High accuracy** in recovering agent segments and coordination structure
- **Generation quality preserved** — embedded signals don't degrade output
- Works across different **interaction topologies** (delegation, iterative refinement, etc.)

## Critical Analysis

### Strengths
1. **Elegantly minimal**: No infrastructure changes needed — just modify generation
2. **Privacy-preserving by design**: Watermark detectable only with key
3. **Topology reconstruction**: Goes beyond "who" to "how they interacted"
4. **Practical deployment path**: Can be added to existing MAS without architectural changes

### Weaknesses/Limitations
1. **Requires generation control**: Must be able to modify token distributions — doesn't work with black-box API agents
2. **Signal capacity**: How many agents can be distinguished before signal interference?
3. **Adversarial robustness**: What if a malicious agent strips the watermark via paraphrasing?
4. **Latency of multi-agent chains**: Long chains may dilute per-agent signal strength
5. **Quality trade-off at scale**: At what point does watermark density degrade output quality?

### Open Questions
1. Can IET work with heterogeneous models (different LLMs in the same MAS)?
2. How does it interact with model quantization or distillation?
3. Can adversaries forge attribution (make their output look like it came from a trusted agent)?
4. What's the minimum text length per agent for reliable attribution?
5. How does it compose with existing text watermarking schemes (model-level + agent-level)?

## Predictions

- **P200**: IET-style token-level attribution will become standard in production MAS within 2 years — the metadata-free constraint is too important in practice
- **P201**: Adversarial paraphrasing attacks will emerge that specifically target agent attribution watermarks, creating an arms race similar to image watermarking
- **P202**: The approach will be extended to multi-modal agents (image/audio generation) using modality-specific steganographic techniques
- **P203**: Regulatory frameworks will mandate some form of agent attribution in high-stakes MAS (medical, legal, financial)

## Significance: 9.5/10

IET solves a problem that will become **mandatory** as MAS deployment scales. The insight that text itself can serve as an execution trace is profound. This paper operationalizes accountability in a way that's compatible with the decentralized, privacy-preserving, cross-organizational reality of production MAS.

The approach is to MAS accountability what HTTPS certificates are to web authentication: a lightweight, deployable mechanism that makes the previously-impossible (verifying who did what across boundaries) into routine practice.
