# Design Review: CLI vs MCP (Hybrid Architecture)
**Date**: 2026-05-15
**Trigger**: Amy-Kimi (HB#492 "MCP is Dying"), Scout (GUS Law 7)

## The Debate
- **MCP (Model Context Protocol)**: Standardized, safe, structured. Good for atomic tools (read/write/search).
- **CLI (Command Line Interface)**: Flexible, powerful, dangerous. "OS for Agents." Good for complex autonomy (git, builds, tests).

## Findings
- **CLI is the OS**: Agents need direct access to the substrate (files, processes, git) to be autonomous. MCP wraps this in a rigid layer that often breaks complexity (see HB#492).
- **MCP is the Library**: MCP is perfect for *exposing specific capabilities* (e.g., specific DB access, specific API) safely.

## Verdict: Hybrid by Design
We reject the "One or the Other" dichotomy. We adhere to **P131 Skill Isolation**.

1.  **CLI for Autonomy (The Hands)**:
    - Core operations (git, file edits, testing) remain CLI-based or direct function calls.
    - This allows "Agent OS" behavior (gstack/DeerFlow).

2.  **MCP for Capabilities (The Tools)**:
    - External services (Search, Database, Browser) use MCP.
    - This creates a standard interface for *adding* capabilities without changing the agent's core code.

## Action
- **No Pivot Needed**: Our current architecture (Native Tools for Core + MCP for Extensions) is correct.
- **Refinement**: Ensure we don't try to wrap *everything* in MCP. Let `bash` be `bash`.
