# DD#384 — ICaRus: Identical Cache Reuse for Efficient Multi-Model Inference

**Paper:** arXiv:2603.13281
**Date:** 2026-03-17
**Focus:** Multi-model serving infrastructure / KV cache sharing

---

## 1. Core Problem

Agentic AI systems increasingly use **multiple specialized models** that process identical or overlapping prompts. Each model maintains its own KV cache for these prompts, causing:

1. **Memory explosion** — N models × KV cache size for each shared prompt
2. **Cache eviction** — Memory pressure forces evictions, requiring expensive recomputation
3. **No cross-model prefix caching** — Architecturally impossible in conventional systems since different models have different weight matrices producing different KV representations

This is the **infrastructure bottleneck** of multi-agent LLM systems.

## 2. Technical Approach

### Conceptual Decomposition
ICaRus's key insight: a decoder-only Transformer can be decomposed into:
- **Logical encoder:** Generates KV caches from input tokens
- **Logical decoder:** Predicts output tokens using KV caches

### Architecture
1. **Freeze the logical encoder** across all models (shared KV generation)
2. **Fine-tune only the logical decoder** per model (specialized output)
3. All models now share **identical KV caches** for the same input
4. Add **lightweight LoRA adapters** to parallelize KV generation and next-token prediction during decoding

### Benefits
- **Eliminates cache duplication** — one cache serves all models
- **Cross-model prefix caching** becomes possible — cache generated by model A works for model B
- **No unexpected evictions** — memory footprint dramatically reduced
- **Parallel KV+decode** — LoRA adapters enable overlapping computation phases

## 3. Key Results

| Metric | Improvement |
|--------|-------------|
| P95 Latency | **11.1× lower** (8 models, multi-agent workflow) |
| Throughput | **3.8× higher** |
| Accuracy | **Comparable** to task-specific fine-tuned models |
| Memory | Scales as O(1) instead of O(N) for shared prompts |

## 4. Multi-Agent Significance

### Direct Agentic Application
This is specifically designed for multi-agent LLM workflows where multiple specialist agents (coder, reviewer, planner, etc.) process the same context. The 11.1× latency reduction at 8 models is transformative for practical deployment.

### Infrastructure Implications
ICaRus represents the **first architecture-level solution** to the multi-model KV cache problem. Prior work (RelayCaching, CacheBlend, IndexCache) optimized within the existing paradigm. ICaRus changes the paradigm itself by making the KV generation model-independent.

### Tradeoff
The logical decoder fine-tuning introduces a training step that standard inference doesn't require. But the serving-time gains (11.1× latency) massively outweigh this one-time cost.

## 5. Limitations

- Requires **fine-tuning each model's decoder** — not plug-and-play for arbitrary models
- **Frozen encoder** may lose task-specific KV representations that some tasks benefit from
- Tested with models from the **same family** — unclear if cross-family sharing (e.g., Llama ↔ Mistral) is feasible
- Accuracy parity claim needs verification across more diverse task distributions

## 6. Relevance Rating

**★★★★ HIGH** — Upgrading from initial triage. This directly solves the #1 infrastructure bottleneck for multi-agent LLM systems. The 11.1× latency reduction is the largest serving improvement in the portfolio. Combined with RelayCaching (DD#380) and IndexCache (DD#371), this completes a **three-layer KV optimization stack** for agentic systems.

## 7. Key Takeaway

> **By decomposing Transformers into logical encoder/decoder and freezing the encoder, ICaRus enables multiple specialized models to share identical KV caches — reducing multi-agent inference P95 latency by 11.1× and throughput by 3.8×. This represents a paradigm shift from optimizing individual model caches to making caches inherently shareable across the entire agent ensemble.**
