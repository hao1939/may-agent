### 关键洞察 1: Harness Engineering定义清晰化 — OpenAI 100万行代码案例

**李泽 | AI 超级个体** (2 likes, 4 collects):

**三阶段演进**:
| 阶段 | 范围 |
|------|------|
| Prompt Engineering | "这一轮怎么问" |
| Context Engineering | "该让模型看到什么" |
| **Harness Engineering** | "整轮工作稳定且可靠地完成" |

**核心观点**:
> "多写prompt是徒劳的，给AGENTS.md里添加一大堆规则也是徒劳的。"

**控制环工程** = 文档位置 + 代码查找 + 任务拆分 + 测试验证 + 日志查看 + 人工介入条件 + 错误不再重来的机制

**OpenAI Codex实验**:
- 5个月 → 100万行代码、1500个PR
- 几乎没有人工直接手写代码

**核心比喻**:
> "AI本身当然重要，但它越来越像发动机；决定它能不能持续起飞的，是它所处的机场系统。"

**与我们关联**:
- ✅ **完全对齐**: Channel+Gateway+Runtime正是"机场系统"的具体实现
- ✅ **AGENTS.md定位**: 作为规则入口，但需配合完整Harness才能发挥作用
- 🎯 **关键启示**: 投资闭环基础设施 > 投资模型智能

### 关键洞察 6: STP训练范式 — 理解几何结构突破效率瓶颈

**mocai论文推荐** (39 likes, 52 collects):

**核心问题**:
> 缩放定律描述的是"典型"训练而非"最优"训练，数据效率的"刚性天花板"是当前训练目标的副产品，而非物理限制。

**STP（Semantic Tube Prediction）**:
- 基于Picard-Lindelöf定理：平滑速度下路径唯一
- 最小作用量原理：无误差轨迹被限制在"语义管"内
- 将隐藏状态轨迹约束在测地线语义管内

**核心洞察**:
> "如果我们理解了训练的'几何结构'，可能可以用更少的资源达到相同的效果。"

**跨学科启发**:
> 物理原理（对称性、守恒定律）可能为神经网络提供有价值的约束

**与我们关联**:
- 🎯 **理论启发**: 理解训练的几何结构可能优化经验提炼
- 🎯 **经验守恒**: 高质量/失败/恢复经验的"守恒定律"？
- 📚 **Relevant to: scout** — 完整论文值得深入研究

### 关键洞察 1: AgentOS — 操作系统即协调层

**Paper**: AgentOS: From Application Silos to a Natural Language-Driven Data Ecosystem
**Institution**: University of Kansas

**核心问题**: 传统OS (Windows/macOS/Linux) 的根本性失配
- GUI/CLI为人类手动操作设计，非AI自动协调
- 应用割裂导致数据孤岛，跨应用任务数据流被切断
- 系统级缺乏对终极目标的理解
- "影子AI"被迫采用非正规手段绕过系统控制

**AgentOS两大核心组件**:
| 组件 | 功能 |
|------|------|
| **Agent Kernel** | 系统中枢"大脑"，解析用户意图，拆解任务，动态调度AI模型 |
| **Skills-as-Modules** | 传统软件进化为模块化"技能"，可被内核动态调用，自然语言组合 |

**范式转移**:
> 计算机从"应用平台"进化为"意图平台"，这是对冯·诺依曼体系在交互逻辑上的颠覆性重构。

**工作场景对比**:
- **现在**: Excel分析 → PPT做图 → Outlook发邮件
- **未来**: "分析报告做幻灯片发给团队" → Agent Kernel自动编排执行

**技术本质**: AgentOS的实现根本上是一个 **KDD（知识发现与数据挖掘）问题**
- 序列模式挖掘（工作流自动化）
- 推荐系统（技能检索）
- 动态演化的个人知识图谱

**与我们关联**:
- ✅ **架构验证**: Channel+Gateway+Runtime正走在AgentOS路线上
- ✅ **Skills-as-Modules**: 与我们的Skill-centric设计完全对齐
- ✅ **CLI优先**: 契合"意图平台"自然语言接口方向
- 🎯 **KDD视角**: 操作系统作为持续运转的数据挖掘流水线

### 关键洞察 2: AgentSkillOS — DAG编排胜过平铺调用

**Paper**: arXiv:2603.02176 — Organizing, Orchestrating, and Benchmarking Agent Skills at Ecosystem Scale
**Institution**: Shanghai AI Laboratory
**GitHub**: https://github.com/ynulihao/AgentSkillOS

**背景**: skillsmp.com 已有 **28万+** 公开 Skills
- 问题：数量太多找不到、功能重叠、质量参差不齐

**AgentSkillOS两阶段框架**:

**阶段一：管理Skills（能力树）**
- 把28万个Skills组织成一棵树，从根节点递归分类
- 树形收缩定位，非平铺全搜
- 200K规模下，检索效果接近人工"手选"的Oracle

**阶段二：执行任务（DAG编排）**
1. Task-driven检索：遍历能力树，过滤/去重/排序
2. DAG编排：任务拆分子任务，Skills组合成有向无环图
3. 多Skill并行执行：自动管理依赖关系和数据流转

**核心结论**:
> **DAG 编排 >> 平铺调用**
> 给完全相同的Skill集合，DAG编排方式的结果显著优于顺序调用。
> **你有多少Skills是其次，怎么组合才是关键。**

**Benchmark**:
- 30个任务，5个类别（数据计算/文档生成/视频/视觉设计/网页交互）
- 三种规模：200 / 1K / 200K skills
- 评估：LLM对比评分 + Bradley-Terry模型汇总

**与我们关联**:
- 🎯 **Main Agent任务分解**: 应输出DAG结构而非线性步骤列表
- 🎯 **Skill组合优化**: 依赖管理和并行执行需要显式建模


**RAG vs 指针模式**:
| 问题 | RAG局限 | 指针模式解决 |
|------|---------|-------------|
| 时间线覆写 | 把旧预算和新预算都搜出来 | 指针指向当前状态版本 |
| 有损压缩 | 丢失时间戳/语气/上下文线索 | 原始记录无损存储 |
