## 核心发现

### 1. 架构"非委托区"(Non-Delegation Zones)
论文识别了**无法委托给AI生成代码**的架构任务：
- **多租户隔离**(Multi-tenancy) — 需要显式设计而非自动生成
- **访问控制流**(Authentication flows) — 人类必须审计
- **数据库关系设计** — AI倾向于最小功能而非系统上下文
- **异步处理管道** — 基础设施决策不能推迟

> "Generated code often under-specified isolation rules and infrastructure constraints when these were not explicitly defined"

### 2. 工程努力的转移
| 减少的努力 | 增加的努力 |
|-----------|-----------|
| 样板代码编写 | 架构设计 |
| CRUD脚手架 | 隔离审计 |
| 基础路由 | 策略规范 |
| UI模板创建 | 验证与监控 |

**核心洞察**: "Vibe coding reduces effort for routine scaffolding... engineering work shifted toward architectural specification, constraint enforcement, validation"

### 3. 上下文提示的重要性
- **模糊的提示** → 局部正确但结构上不完整的解决方案
- **显式约束** → 生成的代码才能保留架构属性
- **策略和评估** → 必须由人类设计，AI只能搭建脚手架

### 4. 两个案例研究
**案例1: 多项目Agent学习平台**
- 项目级隔离 + 结构化记忆
- AI生成的后端代码**经常忽略架构约束**
- 早期路由缺少项目级过滤 → 跨项目数据访问风险
- 需要手动添加显式项目标识符检查

**案例2: 学术RAG系统**
- 基于角色的访问控制 + 引用追踪
- AI生成的引用**不验证答案与检索段落的对齐**
- 初始同步嵌入导致大文件上传时响应时间过长
- 需要手动引入引用对齐检查
