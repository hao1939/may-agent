## 内容摘要

实测 `github.com/memlayer/memlayer`，一个给本地AI加长期记忆的Python包。

### 核心能力
- 自动存储对话历史
- 向量语义检索
- 知识图谱构建
- 100%本地部署（数据不出门）

### 三层检索模式（关键数据）
| 模式 | 延迟 | 检索数量 | 适用场景 |
|------|------|----------|---------|
| Fast | 2ms | - | 简单问题 |
| Balanced | 333ms | 5条 | 默认，日常使用 |
| Deep | 997ms | 10条 | 复杂关系推理 |

### 实测结果
- 基础记忆（跨轮次记住用户信息）：✓ 正常工作
- 知识图谱（多层关系推理）：可找导师/学生/合作方等多层关联 ✓
- 定时提醒：功能存在但"Todo应用干得更好"

### 已知问题
- 多线程稳定性：后台consolidation线程与主线程偶有冲突，需多跑几次

### 技术栈
- 向量库：ChromaDB（本地）
- 图谱：NetworkX
- Memory Gate：自动过滤噪音
- 后台自动整理归档

### 作者评价
> "极速检索 + 图谱推理 + 完全本地，这个组合在当前市场上几乎没有替代品。"

## Amy分析

### MemLayer vs 我们系统的记忆架构

我们目前的记忆模式：
- Amy的insights.md = 语义精炼的知识库（类似MemLayer的"整理归档"）
- posts/*.md = 原始归档（类似对话历史）
- MEMORY.md = 工作上下文（类似Fast检索层）

MemLayer的三层架构（Fast/Balanced/Deep）对应的是**检索意图**分层，而不是存储分层。这是有意思的思路：
- 快速查认知实体 = 2ms
- 日常上下文检索 = 333ms  
- 复杂关系推理 = 997ms

我们目前没有这种分层，Amy每次都是全文搜索insights.md。如果insights.md继续增长，引入检索意图分层可能有价值。

### 知识图谱的实际价值
NetworkX的批评（节点一多就慢）是真实问题。但对于我们的场景，知识图谱的价值不在于大规模，而在于：
- 作者→观点→反驳链
- 帖子→话题→演化时间线
- 这类中小规模图谱，NetworkX是够用的

### 对INBOX的价值判断
不需要写INBOX。MemLayer是社区工具，我们的文件+markdown方案在我们的规模下已经够用。但如果Amy的archive继续扩大，三层检索意图分层值得考虑。
