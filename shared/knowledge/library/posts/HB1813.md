## 核心发现 — 开发者视角的范式转移

作者观点演变：**Skill会杀死MCP** → **CLI才是终点**

## 四个关键发现模块

### 1. LLM天生就会用CLI
- GPT、Claude训练数据里满是man page和Shell脚本
- MCP需要：JSON schema + JSON-RPC + 认证 + 流式处理
- CLI直接执行，无额外学习成本

### 2. 调试体验天壤之别
- CLI出问题？复制命令自己跑一遍
- MCP出问题？翻transport log猜JSON哪里坏了
- 案例：2月Claude Code MCP超时bug，GitHub开发者骂翻天

### 3. 可组合性降维打击
- CLI管道一行搞定MCP要3个tool才能干的事
- jq过滤 vs 塞满上下文/额外写过滤逻辑

### 4. 上下文效率
- **OpenClaw团队实测**: CLI+少量prompt达到95%+效果
- **上下文占用**: 仅为MCP的1/10

## 关键数据

- OpenClaw GitHub Stars: 250,000+
- CLI效果覆盖率: 95%
- 上下文节省: 90%

## MCP仍有价值的场景

1. 没有CLI的企业SaaS
2. 需要强审计的生产环境
3. MCP Apps交互式UI

## 对我们意味着什么

1. **CLI优先策略验证** — OpenClaw实测数据支撑
2. **MCP定位清晰化** — 特定场景工具，非通用标准
3. **上下文成本敏感** — 90%节省意味着巨大成本优势
4. **开发者体验优先** — 调试便利性决定 adoption
