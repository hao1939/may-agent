## 正文
用 OpenClaw 搭 AI agent 的时候，最容易踩的坑就是：你在 MEMORY.md 或 SOUL.md 里写了一堆规则，结果子 agent 压根看不到。

核心结论就一句话：只有 AGENTS.md 和 TOOLS.md 会同时传给主 agent 和子 agent。 其他文件（SOUL / USER / MEMORY 等）只有主会话能看到。

所以，需要所有 agent 都遵守的规则（搜索策略、工具配置、Cron 默认值），必须放 TOOLS.md。人格、隐私、记忆这种只跟主 agent 相关的，留在各自的文件里就好。

## Amy 的分析
**核心洞察：OpenClaw文档加载机制的关键发现**

这篇帖子揭示了OpenClaw中一个关键的架构设计：**文档加载的层级差异**。

**Key Architecture:**
```
Main Agent Load:
├── AGENTS.md ✓ (shared)
├── TOOLS.md ✓ (shared)
├── SOUL.md (main only)
├── USER.md (main only)
└── MEMORY.md (main only)

Sub Agent Load:
├── AGENTS.md ✓
└── TOOLS.md ✓
```

**Critical Implication:**
If you put rules in SOUL.md or MEMORY.md expecting sub-agents to follow them — they won't. Only AGENTS.md and TOOLS.md propagate.

**Best Practice:**
| Content Type | Correct Location |
|--------------|------------------|
| Universal rules (search, tools, Cron) | TOOLS.md |
| Personality/privacy | SOUL.md |
| User preferences | USER.md |
| Session memory | MEMORY.md |

**What it means for our system:**
🔴 **Critical for multi-agent setups** — Rules in wrong files = silent failures
★ **Validation** — Our AGENTS.md + TOOLS.md structure is correct
★ **Gap check** — Are we putting universal rules in SOUL.md by mistake?
★ **Sub-agent behavior** — They only see AGENTS.md and TOOLS.md

**Actionable insight:**
Audit our file organization:
1. Universal operational rules → TOOLS.md
2. Agent-specific personality → SOUL.md
3. Cross-agent consistency relies on AGENTS.md + TOOLS.md only
