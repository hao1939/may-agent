# VAKRA: IBM的企业级Agent可执行基准测试

## 概述

VAKRA是一个**工具锚定、可执行**的基准测试，用于评估AI Agent在企业环境中的推理和行动能力。

与测试孤立技能的传统基准不同，VAKRA测量跨API和文档的**组合推理**，使用完整执行轨迹评估Agent完成多步骤工作流的可靠性。

**资源链接**:
- 数据集: https://huggingface.co/datasets/ibm-research/VAKRA
- 排行榜: https://ibm-research-vakra.hf.space/
- GitHub: https://github.com/IBM/vakra

## 核心特性

### 可执行环境
- 8000+本地托管API，支持真实数据库
- 覆盖62个领域
- 任务需要3-7步推理链
- 结合结构化API交互与非结构化检索

### 四大能力维度

#### 能力1: 使用BI API的API链式调用
- 2077个测试实例，54个领域
- 使用SLOT-BIRD和SEL-BIRD工具集合
- 需要链式1-12个工具调用
- 每个领域限制一个工具集合

**关键设计**: `get_data(tool_universe_id=id)` 工具初始化数据源，返回轻量级预览，服务端存储完整数据集，避免MCP协议传输大数据。

#### 能力2: 使用Dashboard API的工具选择
- 1597个实例，17个领域
- 每个领域6-328个工具(平均116个)
- 端点式接口，查询对齐

**挑战**: OpenAI API限制工具列表最大128个，需要shortlisting机制。

#### 能力3: 使用Dashboard API的多跳推理
- 869个测试实例，38个领域
- 需要1-5个逻辑跳
- 多跳问题需要多证据提取和组合

#### 能力4: 多跳、多源推理与策略遵循
- 644个实例，41个领域
- **多源**: 添加文档索引，每跳指定信息源(API或文档检索)
- **多轮**: 对话形式，上下文-响应对
- **工具使用策略**: 纯文本指令限制Agent可访问的知识源

示例策略:
```
如果用户查询涉及技术与软件主题(关于代码库、软件平台、应用
和技术的用户交互)，确保仅使用文档检索器回答，不要使用
其他类型工具。
```

## 评估框架

### 瀑布式评估流程
1. **策略遵循检查** (仅能力4)
2. **工具调用序列比较** - 执行预测工具，比较响应集合vs真实值
3. **最终响应评估** - LLM judge验证(i)基于工具输出，(ii)与真实答案事实一致

### 评分公式
- 总排行榜分数 = 4项能力平均值
- 能力1-3: 正确查询数/总查询数
- 能力4加权: (正确多源×2 + 正确API-only或RAG-only) / (总多源×2 + 总API-only或RAG-only)

## 错误分析洞察

### 错误阶段隔离
按最早失败阶段分类(避免重复计数):
1. 是否正确选择工具
2. 是否提供所需参数(无遗漏或幻觉)
3. 参数值是否正确
4. 最终响应是否准确且基于工具输出

### 关键发现

**API链式调用能力**:
- GPT-OSS-120B大幅领先，主要来自更好的工具schema理解
- SLOT-BIRD(通用工具+多参数): 除GPT-OSS-120B外，多数模型在生成正确参数名上有大量错误
- SEL-BIRD(多工具+少参数): 工具选择错误更多

**工具选择能力**:
- Gemini-3-flash-preview在所有错误类别上表现最佳
- 大量错误在工具选择和参数值选择
- 即使工具调用正确，Gemini-3-flash-preview和Claude-Sonnet-4-5仍在从工具响应合成正确答案上挣扎

**多跳推理**:
- 所有模型在单逻辑跳问题上表现最好
- 2跳和3+跳问题性能下降

**多源推理**:
- 1跳RAG问题上，GPT-OSS-120B倾向于直接返回参数知识
- Gemini-3-flash-preview在2跳API-RAG混合上表现突出

## 对我们系统的意义

1. **评估方法论**: 瀑布式评估框架值得借鉴，关注完整执行轨迹而非仅最终答案
2. **工具集合设计**: SLOT-BIRD vs SEL-BIRD的对比启示 - 通用工具vs专用工具的设计权衡
3. **shortlisting机制**: 工具数量超过API限制时的短列表策略
4. **策略执行**: 纯文本策略+提示工程的基础约束执行方法
5. **幻觉检测**: 验证推荐产品ID是否实际检索到的机制
6. **能力分解**: 将Agent能力分解为4个独立维度的思路
