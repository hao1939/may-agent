# Ecom-RLVE: 可验证奖励的自适应电商对话Agent

**Source**: Hugging Face Blog (Apr 16, 2026) — Owlgebra AI团队  
**Link**: https://huggingface.co/blog/ecom-rlve  
**Status**: 开源项目，PyTorch OpenEnv Hackathon作品

---

## TL;DR

将RLVE框架从单轮推理扩展到多轮、工具增强的电商对话。EcomRLVE-GYM提供8个可验证环境，每个都有程序化问题生成、12轴难度课程和算法可验证奖励。使用DAPO在Qwen 3 8B上训练300步，展示环境扩展和自适应难度如何迁移到真实任务完成。

---

## 核心问题

大语言模型能流利对话，但作为购物助手部署时暴露持续差距：**流利 ≠ 任务完成**。用户要求"找25美元以下、两天内发货的USB-C充电器"时，Agent需要：
- 调用正确的目录搜索
- 在三个硬约束上过滤
- 避免幻觉从未检索到的产品ID
- 处理缺货时的后续问题

监督微调可以教表层工具使用，但无法扩展到真实电商所需的组合约束空间、部分信息对话和多步交易工作流。

## 架构创新

### 三层奖励信号（全部算法验证，无需LLM评判）

| 奖励类型 | 说明 | 示例 |
|---------|------|------|
| **任务奖励** | 是否真正完成目标？ | 推荐产品是否正确、购物车是否正确、追踪订单是否正确 |
| **效率奖励** | 是否无浪费回合完成？ | 用户导致的回合不计入，只有Agent错误导致的计入 |
| **幻觉惩罚** | 只推荐实际检索过的产品 | 推荐从未查找的产品ID会被惩罚 |

### 8个环境（真实购物场景全覆盖）

| 环境 | Agent任务 |
|------|----------|
| **Product Discovery** | 找到满足所有用户约束的产品 |
| **Substitution** | 缺货时找相似兼容替代品 |
| **Cart Building** | 精确添加用户要求的产品、变体、数量 |
| **Return + Replacement** | 识别正确订单行、发起退货、建议替换 |
| **Order Tracking** | 解析用户指的哪个订单并报告状态 |
| **Policy QA** | 回答关于商店政策的确定性问题 |
| **Bundle Planning** | 在预算内推荐完整购物清单 |
| **Multi-Intent Journey** | 处理链式2-5个上述任务的对话 |

### 12轴自适应难度课程

单一难度数字d同时控制12个独立维度：

| 维度 | Easy (d=0) | Medium (d=6) | Hard (d=12) |
|------|-----------|-------------|-------------|
| 用户约束数量 | 2 | 5 | 8 |
| 用户省略约束频率 | 5% | 70% | ~80% |
| 搜索结果干扰项比例 | 0% | 12% | 24% |
| 对话中缺货频率 | 0% | 30% | 50% |

其他8轴：回合预算、输入噪音（拼写错误、俚语）、上下文切换、检索深度、订单历史大小、政策复杂度、工具预算。

**自适应调度**：每个环境独立追踪Agent成功率，只有当前级别 reliably 通过后才进入更难级别。保持训练在Agent能力前沿。

## 深度案例：购物车构建 (E_CART)

Agent必须发展五个独立技能：
1. **产品发现**：用良好查询搜索目录
2. **变体选择**：识别正确颜色/尺寸/接口类型
3. **购物车管理**：精确添加指定变体和数量
4. **澄清对话**：请求模糊时提出聚焦跟进问题
5. **多商品订单**：单次对话处理多个不同产品

### 工具集
- `catalog_search` - 自然语言查询产品目录
- `catalog_get_variants` - 获取产品可用变体
- `cart_add` - 添加特定变体和数量到购物车
- `cart_view` - 读取当前购物车验证匹配请求
- `user_get_visit_history` - 获取用户最近浏览产品
- `ask_user` - 细节缺失时向客户发送澄清问题

### 难度缩放示例

**d=1（简单）**：1件商品，无变体 → 3回合完成，奖励+0.80  
**d=8（困难）**：3件商品，变体+拼写错误 → 8回合后失败，奖励-0.06

困难案例展示多步错误级联：选错变体（Bamboo而非Charcoal）、错误尺寸（XL而非XS），即使用户两次纠正仍未修复，最终幻觉声称变体不存在。

## 环境扩展假设

遵循RLVE方法论，定义嵌套环境集合：C1 ⊂ C2 ⊂ C4 ⊂ C8

| 集合 | 环境 | 训练技能 |
|-----|------|---------|
| C1 | Cart | 搜索查询构建、购物车操作 |
| C2 | + Substitution | 约束下的相似性推理 |
| C4 | + Product Discovery, Returns | 交易工作流 |
| C8 | + Status, Policy, Bundle, Journey | 知识检索、规划、组合性 |

**假设**：C8 Agent优于单环境专家，即使在专家自己的任务上。

## 早期实验结果

使用DAPO在C1（购物车构建）上训练Qwen 3 8B，300步：

- **基础模型**：Qwen 3 8B
- **算法**：DAPO (G=8 rollouts/prompt)
- **学习率**：1e-5
- **目录**：200万产品，FAISS索引
- **用户模拟**：Qwen3.5 9.7B

观察到难度达到的渐进增长，确认自适应调度产生稳定学习信号，而非静态低难度饱和或静态高难度饥饿。

## 对 OpenClaw 的意义

### ✅ 验证
- **可验证奖励**：算法验证 > LLM-as-a-judge，减少主观性
- **难度课程**：12轴自适应难度是Gym场景设计的参考
- **工具组合**：6个原子工具覆盖复杂电商工作流，验证最小工具集策略

### ⚠️ 差距
- **缺乏显式环境生成器**：我们没有程序化场景生成
- **缺乏自适应难度**：Gym场景固定难度，无动态调整
- **缺乏用户模拟器**：没有LLM驱动的用户行为模拟

### 💡 机会
- 将Gym场景重构为可验证环境（明确成功/失败标准）
- 添加难度轴（约束数量、噪音水平、干扰项比例）
- 探索DAPO训练用于Skill选择策略
