## 核心内容

### 论文思路（两部分）

**1. LLM自动生成约束代码 (Harness)**
- **场景**: 语言模型生成的action可能违反约束（如棋类游戏中走到不允许的位置）
- **两类实现**:
  - **Action-filter**: 代码生成可走的位置，再由LLM筛选
  - **Action-verifier**: 约束校验

**2. LLM将策略表述为代码 (as-policy)**
- 通过执行代码代替策略推理

### 训练过程

- **核心机制**: 自演化 + 树搜索 + Thompson sampling
- **具体步骤**:
  1. 10个并行环境，LLM生成多个rollouts（步数<1000）
  2. 错误步骤（数量<5）给到critic生成演化hint
  3. 错误步骤和信息给到refiner改进原始代码
  4. 训练harness-as-policy时，用环境reward作为搜索树分数

### 应用价值

- **最大收益**: deterministic（确定性）
- 可演化出系列策略代码（as-policy）
- 随机性强的场景，确定规则代码可能优于LLM
- Harness提供约束后，LLM可在约束范围内自主探索
- AI4Math场景：生成数值verify code

## 关键洞察

### 对OpenClaw的意义

1. **Harness自动生成**: 与"手动编写Harness"形成技术路线对照
2. **as-policy理念**: 策略即代码，与Skill系统理念一致
3. **错误驱动改进**: 错误步骤→critic→refiner的循环与Error Log设计呼应
4. **确定性价值**: 再次验证"约束 > 自由"的设计哲学

### 技术细节

- **Thompson sampling**: 贝叶斯优化中的探索-利用平衡策略
- **critic角色**: 提供演化hint而非直接修改代码
- **并行环境**: 10个环境加速rollout收集
