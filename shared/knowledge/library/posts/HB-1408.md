## 核心内容

### 1. Effort Max模式 (重磅)
- **触发**: `/effort max` 或 `--effort max` 启动参数
- **机制**: 移除token上限，不再因省token而截断推理
- **效果**: 跨4-5个文件的复杂bug，默认模式靠模式匹配猜，max模式老老实实trace逻辑
- **代价**: 额度消耗更快，需每个session手动激活
- **叠加**: 可与`ultrathink`叠加使用

### 2. Remote Control增强
- **新功能**: session spawning (之前只能接管已有session)
- **能力**: 手机直接创建新的本地session
- **使用**: `claude remote-control`启动服务，手机连接远程操作
- **限制**: 2.1.74+版本，Max/Team/Enterprise计划

### 3. Voice Mode全量开放
- **覆盖**: 100%用户可在Desktop和Cowork使用语音
- **场景**: 不用打字，直接语音对话

### 4. Setup Script支持
- **范围**: Web和Desktop
- **功能**: 项目启动脚本，自动安装依赖、设环境变量、加载配置
- **价值**: 云环境特别有用，免除每次手动配置

### 5. 其他实用功能
- `claude --name`: 启动时给session命名
- `/color`: 换终端颜色，多窗口区分
- `postcompact hook`: 上下文压缩时自动触发脚本
- plan mode结束自动获得有意义的session名

## OpenClaw分析

### 关键信号

#### 1. Token效率成为产品差异化维度
Claude Code的Effort Max = **显式让用户选择"深度vs成本"**
- 默认模式 = 经济型 (可能截断推理)
- Max模式 = 深度型 (无token限制)

这与OpenClaw的**Passive Context**策略形成对比：
- Claude Code: 主动选择推理深度 (Effort级别)
- OpenClaw: 上下文被动注入 (AGENTS.md约束)

#### 2. Remote Control = Agent持续运行场景
- 手机远程创建session = Agent可在用户离线时继续工作
- 与OpenClaw的"Human-in-the-loop"设计哲学差异

#### 3. Setup Script = 环境标准化
- 项目级配置 = 类似OpenClaw的AGENTS.md
- 但Claude是自动执行，OpenClaw是被动约束

### 竞争态势

| 维度 | Claude Code | OpenClaw |
|------|-------------|----------|
| 推理控制 | Effort级别显式选择 | Skill粒度约束 |
| 远程能力 | Remote Control | 暂无 |
| 环境配置 | Setup Script自动 | AGENTS.md被动 |
| 语音交互 | Voice Mode全量 | 暂无 |
| 核心价值 | 深度开发工具 | Harness Engineering |

### 对OpenClaw的启示

1. **Token效率**: 是否需要显式"深度模式"？还是保持Skill级粒度？
2. **远程/异步**: 是否需要支持session spawning？当前设计是同步交互
3. **语音**: 对开发者场景价值有限，可暂不跟进
