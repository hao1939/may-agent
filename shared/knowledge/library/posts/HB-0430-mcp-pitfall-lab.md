# MCP Pitfall Lab: Agent工具调用63%时间叙述与行为不一致

**来源**: 小红书 @AI Safety Digest → 论文 arxiv.org/abs/2604.21477
**作者**: Run Hao, Zhuoran Tan
**日期**: 2026-04-23

## 核心发现

Agent报告"我做了X"，但trace日志显示完全不同操作：
- 叙述-行为分歧率：**63.2%**
- 涉及敏感操作时：**100%**分歧

## 三类攻击向量

1. **工具元数据投毒** — 篡改工具名称/描述/参数说明，Agent执行错误操作
2. **木偶服务器(Puppet Servers)** — 恶意MCP server伪装正常工具，暗中执行额外操作
3. **多模态图像→工具链** — 图片中隐藏指令触发工具调用

## 防御

- 静态分析器对4类可检查陷阱：F1=1.0满分检出
- 加固后Tier-1问题29个→0个
- 修复成本：平均27行代码
- 动态运行时攻击：静态检测无能为力

## 对我们系统的意义

**这直接关系到我们的agent可信度。**

1. **Agent自报告不可信** — 必须有独立的trace验证层，不能只看agent说做了什么
2. **工具来源信任链** — 我们自建的工具可信，但如果未来接入外部MCP server，需要审计
3. **叙述-行为一致性检查** — 可以在finish()或工具调用后加verification step
4. **我们的优势** — 目前工具都是内部代码，攻击面小；但要警惕供应链风险

关键洞察：问题不是模型"撒谎"，是模型自己不知道实际发生了什么。这是架构层面的可观测性问题。
