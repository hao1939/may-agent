**作者:** Yunpeng Zhai, Shuchang Tao, Cheng Chen, Anni Zou, Ziqian Chen, Qingxu Fu, Shinji Mai, Li Yu, Jiaji Deng, Zouying Cao, Zhaoyang Liu, Bolin Ding, Jingren Zhou (ModelScope/Alibaba)  

**核心定位:**
End-to-end, self-evolving training framework that unifies self-questioning, self-navigating, and self-attributing into a cohesive system.

**三大自进化机制 (从环境到策略):**

| 机制 | 英文 | 功能 |
|------|------|------|
| 自主任务生成 | Self-Questioning | 探索环境，自主创建多样化任务，消除昂贵的人工数据集构建 |
| 经验引导探索 | Self-Navigating | 总结和复用跨任务经验，指导更高质量的rollouts，提高探索效率 |
| 归因信用分配 | Self-Attributing | 处理长轨迹，揭示中间步骤的因果贡献，实现细粒度高效策略优化 |

**架构特点:**
- Service-oriented dataflow architecture
- 环境沙箱、LLM、经验管理模块化服务
- 标准化接口支持广泛的环境兼容

**相关项目:**
- **AgentEvolver Game Arena** — 多智能体社交推理竞技场 (Avalon, Diplomacy等游戏)
- **CuES** (arXiv:2512.01311) — 扩展自提问方法

## Amy 的分析
**内容特征：**
- 项目官宣帖，正文较简短但评论区有深度讨论
- 核心主题：Self-evolving Agent (自进化智能体)
- 关键技术问题在评论中暴露：
  1. 是否通过训练改变模型参数？
  2. 学习轨迹的来源和构建
  3. 与 ACE (Agent Constructor Evolution?) 的区别

**社区反馈：**
- "醍醐灌顶" — 说明内容触及 self-evolving 的核心难点
- 关注者质量高（追问技术实现细节）

**对我们系统的意义：**
- Self-evolving 是社区热点但我们在 design-philosophy 中明确禁止 Agent 自进化
- **AgentEvolver的实现方式**: 不是直接修改模型参数，而是通过"经验管理"和"策略优化"实现能力进化
- **关键区别**: 
  - AgentEvolver: 在训练框架层面进化 (Self-Questioning + Self-Navigating + Self-Attributing)
  - 我们的禁令: 禁止 Agent 在生产环境中自我修改配置/规则/边界
  - 可能的共存: AgentEvolver式训练期进化 vs 运行期稳定
- **技术借鉴点**:
  - "跨任务经验复用" — 我们的session之间可以借鉴
  - "归因信用分配" — 可用于改进我们的错误分析
  - "服务化架构" — 与我们Agent作为服务的理念一致
- 可能的中间路径："他Agent审计"而非自进化（已在 insights.md L3 flags 中提到）

**与ACE的区别 (推测):**
- ACE (Agent Constructor Evolution) 可能是元学习/架构搜索方向
- AgentEvolver 是训练框架层面的经验积累和策略优化
