## Core Framework: Five-Stage SLEEC Operationalisation Process

### Stage 1: AI Agent Capability Specification
- **Purpose**: Define high-level functional capabilities that determine how agent perceives/affects environment
- **Two crucial aspects**:
  1. Capabilities determine which SLEEC norms are relevant
  2. Capabilities needed to satisfy SLEEC norms
- **Output**: Informally specified capabilities + use cases for non-technical stakeholders

### Stage 2: SLEEC Requirements Elicitation
- Translate abstract normative principles → actionable operational rules
- **Three-step process**:
  1. **High-level principles identification**: non-maleficence, human autonomy, privacy, etc.
  2. **Normative-principle proxies**: actionable placeholders capturing abstract values
  3. **SLEEC rules definition**: Using SLEEC DSL

**SLEEC DSL Rule Format**:
```
id
when triggerEvent [and triggerGuard]
then response [within timeframe]
[unless defeaterGuard [then defeaterResponse]]
```

### Stage 3: SLEEC Requirements Well-Formedness Checking
- **Goal**: Identify conflicts, redundancies, insufficiency, over-restrictiveness
- **Two complementary methods**:
  1. **Process-algebraic (tock-CSP)**: FDR model checker detects conflicts/redundancies
  2. **FOL* Logic-based (LEGOS)**: Global ruleset analysis with causal proofs

### Stage 4: SLEEC-Aware AI Agent Implementation
- Map capabilities → implementable abstractions (events, measures, state variables, actions)
- **Training-time**: Dataset schemas encode SLEEC-compliant/violating situations
- **Runtime**: Guardrails monitor perceptions, constrain actions, handle defeaters

### Stage 5: Verification of AI Agent Compliance
- **Novel conformance notion**: Distinguishes mission capabilities from environment-perception capabilities
- **Tool**: RoboChart modeling language with tock-CSP semantics
- **Output**: Counterexamples when rules violated OR verified compliance → code generation

## Key Insights

### 1. Normative Principle Reification Challenge
> "Translating high-level abstractions into practical SLEEC requirements... is a substantial, application-specific undertaking"

- UNESCO: "respect, protection and promotion of human rights" → concrete dressing robot requirements?
- Gap: Domain-specific regulatory frameworks remain limited

### 2. Normative Ambiguity and Value-Conflict Resolution
> "It is not possible to produce a set of rules purporting to describe what a [person] should do in every conceivable set of circumstances" — Alan Turing, 1950

**Key challenges**:
- Transparency vs Privacy
- Safety vs Personal autonomy
- When is SLEEC ruleset "sufficient"?

**Solution**: Priority-based trade-offs via systematically identified defeaters

### 3. Runtime Adaptation to Changing Normative Requirements
- Humans adapt seamlessly to varying social/cultural preferences
- AI agents need: dynamic behavior updates + runtime normative signal perception
- Challenge: Maintain formal guarantees while enabling adaptivity

### 4. Cancellation as Positive Outcome
> "Cancellation... represents a positive outcome, which not only preempts deploying an AI agent that can violate norms, but may also identify gaps requiring further regulatory and technical efforts"

Process failure = valid and necessary outcome

### Critical Gap Identified
**SLEEC-TK toolkit** (well-formedness checking) vs **OpenClaw**: We lack automated conflict/redundancy detection for AGENTS.md constraints.

### Validated Design Decisions
1. **Rule-based governance**: SLEEC DSL validates AGENTS.md constraint format
2. **Defeaters/exceptions**: Confirms conditional override necessity
3. **Human-in-the-loop**: Verification stage requires stakeholder involvement
4. **Cancellation validity**: AGENTS.md rejection of non-compliant agents aligns with framework
