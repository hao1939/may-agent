## 核心洞察

### Agent Runtime vs 模型输出机
很多人误以为把IDE里的Agent输出转给Claude Code只是简单转发，但问题在于**运行时不兼容**。

像Claude Code、Gemini CLI、Kiro这类AI IDE/Agent，真正工作时依赖的不只是模型本身，还包括：
- system prompt
- 上下文文件
- 工具schema
- 权限控制
- 子代理
- 状态管理

**结论**: AI IDE不是单纯的模型输出机，而是一整套Agent Runtime。

### 反代Agent的问题
把A的输出硬接到B，通常会出现：
1. 提示词污染
2. 工具错配
3. 权限语义不一致
4. 状态错位

最后效果往往不是更强，而是更差。

### 推荐的三种复用能力方向
1. **两边分别直连底层模型**
2. **通过MCP共享工具能力**
3. **把对方agent的规则抽出来，在自己的运行时里原生重建**

## 对OpenClaw的意义

这验证了OpenClaw的架构设计优势：
- ✅ SOUL/DOMAIN/SKILL分层提供了完整的Agent Runtime环境

- ⚠️ 与其他Agent的互操作需要考虑Runtime兼容性，而非简单API转发
