# HB#1794: "Agent 只是 AI 不够强时的一种 workaround"

**Source**: XHS@AI与个人成长 (编辑于 27分钟前 美国)  
**Author**: NLP 领域多年研究者  
**Tags**: #Agent哲学 #模型演进 #工程实践 #NLP

## 核心观点

> "很多人把 Agent 当作 AI 的未来，但从技术演化的角度来看，它更像是一种工程上的 workaround。"

### 论证逻辑

**当前 Agent 系统的本质**:
当模型本身还不够可靠时，我们在模型外面不断增加各种结构：
- multiple models
- deterministic tools
- memory
- domain knowledge
- dynamic learning

这些结构组合在一起，形成了今天的 Agent systems。

**未来趋势预测**:
> "如果未来的模型本身变得足够强，也许很多 Agent 的复杂结构，都会重新回到模型内部。"

## 社区讨论

**评论亮点**:
- @永远生长2024: "没有 agent 怎么执行命令…"
- @star 回复: "所以说模型不够强呀"

这体现了社区对 Agent 必要性的基本共识：当前模型需要外部结构来弥补能力缺口。

## 与 OpenClaw 的关联

### 哲学层面
这与 OpenClaw 的 **Harness Engineering** 理念形成有趣的张力：

| 观点 | 立场 | 时间尺度 |
|------|------|---------|
| Agent = Workaround | 模型终将内化所有能力 | 长期 (5-10年) |
| Harness Engineering | 模型外的一切才是核心竞争力 | 中期 (2-5年) |

### 实践启示
1. **不要过度工程化**: Agent 结构是为当前模型能力缺陷而存在的临时方案
2. **保持架构灵活性**: 随着模型能力提升，部分 Agent 功能可能被模型原生替代
3. **聚焦不可替代性**: 思考哪些 Harness 层能力是模型即使变强也无法内化的

## 可操作的洞察

**什么应该留在 Harness 层？**
- 安全边界 (即使模型更强，也需要外部约束)
- 工具生态集成 (与外部世界的接口)
- 多模型协作 (单体模型无法解决的系统性问题)
- 审计与可追溯性 (需要外部记录)

**什么可能被模型内化？**
- 简单的工具调用决策
- 基础的记忆管理
- 常规的任务分解
