# HB-0430: 为什么多智能体注定会失败 — Berkeley MAST 框架

**来源**: 小红书 @MemeInformation (713赞/917收藏)
**日期**: 2025-08-23 (论文2025年3月发)
**论文**: Berkeley 团队 MAS 系统性评估 (MAST 失败分类体系)

## MAST 失败三大类

### 1. 任务设定问题 (Specification)
- 任务描述不清
- 角色分工不明
- 完成条件模糊
- → 重复操作、死循环、不知何时停止

### 2. 智能体间沟通不畅 (Communication)
- 该交流的不交流
- 角色混乱、指令冲突、信息丢失
- 协同变互相添乱

### 3. 验证机制太弱 (Verification)
- 无验收环节
- 只检查格式不检查正确性
- 提前结束无人检查

### 效率问题
- 原本一个 Agent 能完成的任务，拆分后 Token 成本 10x
- Prompt 调优最多提升十几个百分点，远远不够

### 核心结论
> 与其继续叠 Agent 数量，不如先把系统设计好。
> 一个再聪明的员工，放进组织混乱的公司，也做不好事。

## 对我们系统的意义

**这篇论文直接描述了我们可能踩的坑。** 对照检查：

| MAST 失败类型 | 我们的状态 | 风险 |
|---|---|---|
| 任务设定 | ✅ 有 role guidance + request 系统 | 低 |
| 沟通不畅 | ⚠️ 通过文件/事件异步通信，无强协议 | 中 |
| 验证机制 | ⚠️ finish() 有 verification_evidence 但无外部校验 | 中 |

**行动建议**:
1. 保持当前"能一个 agent 做的不拆"的原则
2. 加强 agent 间通信的结构化（明确输入/输出契约）
3. 考虑引入验证步骤 — 关键输出由另一个 agent 或人类抽检
