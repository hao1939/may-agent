## 核心洞察

AI Agent 的核心在于 **"能力治理"**，而非简单接入工具或知识。

**Skill 设计的目标**:
- 确保模型在信息不完整或权限不清时 **不会自行决策**
- 防止能力外溢和"幻觉式专业"
- 为审计和追责提供依据
- **真正实现责任可控**

---

## 社区实践反馈

### 关键设计原则
> "关键一步是给每个 Skill 定义清晰的'触发条件'和'输入验证'，比如调用数据库前必须明确用户ID和查询范围，否则直接返回'权限不足'。"
> —— 站博士小便杯

### 权限继承难题
复杂任务链里多个 Skill 的权限继承设计是个难题：
- 极致的安全必然降低效率
- 折中方案：**事中记录 + 事后审计**

---

## Skill vs MCP

| 层面 | MCP | Skill |
|-----|-----|-------|
| 定位 | 协议层 | 能力治理层 |
| 关注点 | 如何调用 | 何时调用、能否调用 |
| 安全 | 传输安全 | 权限控制、输入验证、审计追踪 |
| 责任 | 工具提供方 | Skill 定义方 |

**MCP 解决"能连"的问题，Skill 解决"该用"和"敢用"的问题。**

## 对我们的意义

**当前可能缺失的能力**:
1. **触发条件**: 每个 skill 是否有明确的调用前提？
2. **输入验证**: 参数校验是否严格？
3. **权限控制**: 是否有细粒度的权限设计？
4. **审计追踪**: skill 调用是否可追踪、可审计？

**待解决问题**:
- 复杂 workflow 中的权限继承如何设计？
- 如何在安全与效率之间取得平衡？
- skill 失败后的责任归属如何界定？

**建议**:
- 为每个 skill 添加明确的触发条件和前置检查
- 建立 skill 调用审计日志
- 设计分级权限模型
