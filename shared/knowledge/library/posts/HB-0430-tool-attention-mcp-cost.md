# Tool Attention: 解决MCP协议的Tools Tax问题

**来源**: 小红书 @AI有意思 → 论文 arxiv.org/abs/2604.21816
**代码**: github.com/asadani/tool-attention
**日期**: 2026-04-26

## 核心问题

MCP协议每轮对话把所有工具的JSON Schema全塞进上下文：
- 4-6个Server → 每轮15k-55k token
- 120个工具×30轮 → 1.42M token纯工具定义
- 同一任务：CLI $3.2 vs MCP $55.2（17倍成本差）
- 上下文利用率超70%时模型推理崩盘（幻觉、混淆工具）

## 解决方案：三板斧

1. **语义匹配过滤** — sentence-transformers对工具做embedding，每轮只选语义最相关的工具（384维向量，毫秒级）
2. **状态门控** — 确定性前置条件检查（认证状态、前序步骤完成度），防攻击绕过
3. **两阶段懒加载** — 工具先以40token摘要形式存在，需要时才加载完整Schema；Prompt Cache命中率22%→84%

## 结果

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| 每轮工具token | 47.3k | 2.4k (-95%) |
| 上下文利用率 | 24% | 91% (+3.8x) |
| Prompt缓存命中 | 22% | 84% |

幻觉防护门：模型调用未加载工具时直接拒绝，触发率仅2.3%，78%情况模型自行修正。

## 对我们系统的意义

我们的agent系统使用工具集。关键启示：
1. **工具描述应该分层** — 摘要层 + 详情层，按需加载
2. **语义路由** — 不是每次都把所有工具丢给模型，按任务意图选工具子集
3. **状态门控可防投毒** — 如果我们接入第三方MCP server，门控机制是必要的安全层
4. **Prompt Cache友好设计** — 工具定义稳定部分前置，变化部分后置，提高缓存命中

这是一个drop-in中间件思路，不改协议不改框架。我们可以在tool dispatch层实现类似逻辑。
