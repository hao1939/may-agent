# HB#1519 — CR-Bench: Signal-to-Noise Trade-off in Code Review Agents (2026-03-15)

**Source**: arXiv:2603.11078 [cs.SE] (Nutanix) — Direct Paper Tracking  
**TL;DR**: **"追求更高召回率时噪声激增"**——Reflexion Agent比Single-shot多发现bug但SNR显著下降；CR-Evaluator三分类框架(Bug Hit/Valid Suggestion/Noise)与OpenClaw Error Log设计完全映射

---

## Core Finding: The Precision-Recall-Noise Trade-off

> "If we pressure an agent to identify more bugs (like Reflexion), the noise increases, and if we make it too relaxed (like single LM), some bugs are missed."

| Agent Type | Bug Detection | Noise Level | Sweet Spot |
|-----------|---------------|-------------|------------|
| Single-shot LM | Lower | Lower | 保守但可信赖 |
| Reflexion Agent | Higher | Higher | 激进但嘈杂 |
| **Ideal** | **Optimized** | **Controlled** | **Need balancing** |

### Experimental Setup
- **Dataset**: CR-Bench-verified (174 instances from real-world Java/Python repos)
- **Models**: GPT-5.2, GPT-5-mini
- **Judge**: Claude-Sonnet-4.5 (cross-model evaluation消除自评估偏见)

## CR-Evaluator: Three-Category Classification Framework

CR-Evaluator使用LLM-as-judge将每条评论分类为:

| Category | Definition | OpenClaw Parallel |
|----------|-----------|-------------------|
| **Bug Hit** | 准确识别ground truth中的逻辑错误 | Error Log验证过的真实问题 |
| **Valid Suggestion** | 建设性反馈(性能优化/边界处理)但未命中主缺陷 | P109学习中的正向建议 |
| **Noise** | 事实错误/无关/不重要，通常是幻觉 | 需过滤的无效反馈 |

### Novel Metrics

**Usefulness Rate (U)**:
```
U = (Bug Hits + Valid Suggestions) / Total Reviews
```
> 衡量Agent超越纯bug发现的价值

**Signal-to-Noise Ratio (SNR)**:
```
SNR = (Bug Hits + Valid Suggestions) / Noise Count
```
> 高SNR是开发者信任的主要代理；低SNR导致开发者疲劳和工具放弃

### Critical Insight

论文发现: **SNR是生产级Agent的关键指标**
> "A low ratio can trigger developer fatigue and eventual tool abandonment in production workflows."

这直接支持OpenClaw的设计决策:
- **Error Log**的方向性批评(具体、可执行) > 笼统的"改进建议"
- **P109禁止Self-Evolution**防止未经审计的噪声累积
- **read_by机制**确保关键反馈被正确归因和处理

## Key Quotes

> "Code review agents can exhibit a low signal-to-noise ratio when designed to identify all hidden issues, obscuring true progress and developer productivity when measured solely by resolution rates."

> "An overly conservative agent may fail to flag important issues, while an overly permissive agent may generate excessive or low-quality feedback. This reflects a pronounced bias–variance trade-off."

> "Defect detection is inherently more objective and thus better suited for automated evaluation."
