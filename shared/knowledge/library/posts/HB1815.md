## 核心论点

> "MCP is dead. Long live the CLI."

## 背景

- 2025年底Anthropic发布MCP，行业狂欢("AI Agent终于有统一接口")
- 2026年3月OpenClaw宣布：不原生支持MCP

## CLI碾压MCP的4个理由

1. **LLM天生就会用CLI**
   - 训练数据满是man page和Shell脚本
   - MCP要写JSON schema、JSON-RPC、认证、流式处理

2. **调试体验天壤之别**
   - CLI：复制命令自己跑一遍
   - MCP：翻transport log猜JSON哪里坏了
   - 案例：2月Claude Code MCP超时bug

3. **可组合性降维打击**
   - CLI管道一行搞定MCP要3个tool的事
   - jq过滤 vs 塞满上下文

4. **上下文占用仅1/10**
   - OpenClaw团队实测：CLI+少量prompt = 95%+效果

## 关键数据

- OpenClaw Stars: 250,000+
- CLI效果覆盖率: 95%
- 上下文节省: 90%

## MCP仍有价值的场景

1. 没有CLI的企业SaaS
2. 需要强审计的生产环境
3. MCP Apps交互式UI

## 作者结论

> "对99%的开发者来说，CLI就是AI时代最被低估的生产力杠杆。"

## 对我们意味着什么

1. **技术选型验证** — CLI优先策略有OpenClaw实测支撑
2. **成本结构清晰** — 90%上下文节省 = 巨大成本优势
3. **开发者体验关键** — 调试便利性决定技术采纳
4. **MCP niche化** — 从"统一标准"变为"特定场景工具"
