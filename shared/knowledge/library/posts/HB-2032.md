## 面试题核心

> "你觉得为什么要手搓Agent，而不是直接上框架？"
> 
> 这题表面问技术选型，实际是**候选人的分水岭题**——考你是"框架使用者"还是"系统设计者"

## 手搓的三大原因

### 1. 场景太简单，框架反而变重
- B端Agent真实形态: 一句话 → 调一次API → 给结果
- 框架带来: 多层抽象、Planner兜底逻辑、调试成本极高
- 手搓方案: 300行Agent Loop (思考→选工具→调用→总结)
- **优势**: 出问题一眼定位，性能更稳，成本更低

### 2. 业务需要"可控性"，不是炫技
**企业级Agent核心关键词**: 可控性

| 可控点 | 框架局限 | 手搓优势 |
|-------|---------|---------|
| 调用次数限制 | 难以精确控制 | 状态机100%控制 |
| 二次确认 | 内置逻辑死板 | 自定义确认流程 |
| 失败Retry | 策略固化 | 自定义Retry逻辑 |
| 推理链长度 | 难以限制 | 精确控制时延/成本 |

> 💡 "这句话在面试官耳朵里等于：**我做过线上系统**"

### 3. 深度接内部系统，框架很吃力
- RPC服务调用
- 审计、权限、风控
- 日志、链路追踪
- **手搓方案**: 直接在公司原有微服务体系里写AgentService

## 选型决策树

| 场景 | 推荐方案 |
|-----|---------|
| Demo/PoC | ✅ 框架 |
| RAG、多工具对话 | ✅ 框架 |
| 多人协作需统一抽象 | ✅ 框架 |
| 成本/稳定性要求不极致 | ✅ 框架 |
| 场景简单但要求稳定 | ✅ **手搓** |
| 强依赖权限/审计/风控 | ✅ **手搓** |
| 深度接内部系统 | ✅ **手搓** |
| Agent流程高度定制 | ✅ **手搓** |

## 一句话总结

> **框架解决的是"快"，手搓解决的是"稳和可控"**
> 
> "我不是在选工具，我是在为业务兜底。"
