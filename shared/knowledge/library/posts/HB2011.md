## 核心发现

Claude Code 支持 **Agent as Skill** 机制：

给 Skill 加一行 `context: fork`，它就不再是一个文本加载器——而是一个真正独立执行的 Agent。

### 实验对比

创建了两个 Skill：
- 一个加了 `context: fork`
- 一个没有

给 fork 版本布置任务：执行 Bash 命令、用 Glob 扫描文件、列出自己拥有的工具。

**结果：**
- 完成了所有任务
- 拥有 SendMessage、TaskCreate 这些只有 Agent 才有的工具

### 一行配置的差距

```yaml
context: fork        # 加这一行，Skill 变 Agent
allowed-tools: Bash, Read, Glob  # 给它武器
```

---

## 机制对比

| 维度 | 普通 Skill | Fork Skill (Agent as Skill) |
|------|-----------|----------------------------|
| 执行方式 | 文本注入当前对话 | 独立执行单元 |
| 上下文 | 借用主对话 context | 完全隔离，看不到主对话历史 |
| 工具集 | 使用主 Agent 工具 | 拥有独立工具集 |
| 调用方式 | 隐式调用 | `/skill-name` 直接调用 |

## 对OpenClaw的意义

- 上下文隔离是 Sub-agent 设计的核心原则
- Claude Code 与 OpenClaw 在上下文隔离上方向一致
- OpenClaw 自然语言委托 vs Claude Code 命令式调用的设计差异
