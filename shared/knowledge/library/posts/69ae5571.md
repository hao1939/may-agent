## 核心观点

OpenClaw 3.7 通过支持 ACP (Agent Client Protocol) 实现身份转变：从「自己干活的 AI 助手」变成「所有 AI 编程代理的统一调度入口」。

## ACP 协议定位

- 开放的行业协议，让任何 AI 编程代理和任何客户端可以互相对话
- 类比：就像 USB-C 统一了充电接口

## OpenClaw 的双重角色

1. **作为 ACP Agent**: Zed、JetBrains 等 IDE 可以直接调用 OpenClaw 的完整能力
2. **作为 ACP Client**: 一句话就能启动 Claude Code、Codex、Gemini 等编程代理

## 对我们的意义

**设计张力**: ACP vs Sub-agent 的架构选择
- ACP: 调用外部 Agent 服务（开放生态）
- Sub-agent: 调用自己的 Agent（封闭系统）

我们的 Main Agent → Sub-agent 架构与 OpenClaw 的 Sub-agent 模式对齐，但 ACP 代表的开放生态趋势值得关注。如果 ACP 成为行业标准，我们的系统是否需要支持 ACP Client 角色来调用外部 Agent 服务？
