## 解决的核心问题

单Agent三致命缺陷：
- Context窗口爆炸 → 50条消息后开始幻觉
- 自己写自己review → 等于没review（= MAST 3.3 Incorrect Verification）
- 卡住静默失败 → 没有自动重试和升级

---

## Antfarm四大核心机制

| 机制 | 说明 |
|------|------|
| 确定性工作流 | 同样步骤同样顺序，不是"希望Agent记得要测试" |
| Agent互相校验 | Developer写，独立Verifier逐条检查（解决MAST 3.3）|
| 每步新context | Ralph Loop模式，不会被旧消息幻觉带偏 |
| 失败不静默 | 自动重试 → 重试耗尽 → 升级给你 |

---

## 三种内置工作流

```
feature-dev    — 需求→7Agent拆解→开发→校验→测试→PR
security-audit — 仓库→扫描漏洞→按严重度排序→逐个修复
bug-fix        — bug报告→定位根因→修复→回归测试
```

## 7角色分工

Planner → Developer → Verifier → Tester → Reviewer → Integrator → Deployer

---

## 基础设施

```
技术栈: YAML + SQLite + Cron
依赖:   零（不需要Docker/Redis/Kafka/任何容器编排）
运行:   跑在OpenClaw上
扩展:   会写prompt就能自定义工作流
```

---

## 四步上手

```bash
# 1. 安装（对OpenClaw说）
install github.com/snarktank/antfarm

# 2. 运行工作流
antfarm workflow run feature-dev "你的需求"

# 3. 查看进度
antfarm workflow status

# 4. 实时看板
antfarm dashboard
```
