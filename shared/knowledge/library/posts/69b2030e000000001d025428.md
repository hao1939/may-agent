# 高清图解OpenClaw架构原理！

## 架构四层结构

### Channel（渠道端）
- 对接各类IM平台（钉钉、飞书等）
- 接收外部消息并转换为内部统一格式
- 负责把智能体回复发送回IM

### Gateway（网关）
- 核心控制平面
- 接收消息、路由分发、回复投递
- 协调各模块之间的通信

### Agent Runtime（智能体运行时）
- **Agent Loop**：主循环，"收到指令→思考步骤→调用工具→再思考"
- **Memory**：管理对话历史和上下文
- **Tool**：工具调用接口（文件操作、浏览器控制等）
- **Skill**：模块化插件方式定义功能

### Node（设备端）
- 运行在用户设备（iOS、Android、macOS）
- 通过Gateway远程控制设备能力
- 摄像头、屏幕截图等

## 工作流程
1. Channel接收消息并标准化
2. Gateway根据会话状态调度Agent
3. Agent Runtime进行推理，可能调用工具或技能
4. 如需设备操作，Gateway通过Node远程执行
5. 最终回复经Channel返回用户

## 评论区精华

- **Lane与Runtime关系**：多对一，一个session对应一个lane，多个lane对应一个agent runtime
- **消息总线** = Adapter适配器 + Routing路由 + Lane Queue车道队列
- **记忆存储**：本地markdown文档，存上万字没问题，但token开销大
- **模型调用**：支持订阅制GPT（OAuth认证）
