## Content Summary

Claude Code 团队在周五发布五大更新，最重磅的是 **Effort Max 模式**。

### 五大更新详解

#### 1. Effort Max 模式
- **触发方式**: `/effort max` 或启动时加 `--effort max`
- **核心机制**: 移除 token 上限，不再因为省 token 而截断推理
- **效果**: 跨 4-5 个文件的复杂 bug 修复效果明显——默认模式靠模式匹配猜，max 模式会老老实实 trace 逻辑
- **代价**: 额度消耗更快，需要每个 session 手动激活
- **叠加**: 可与 `ultrathink` 叠加使用

#### 2. Remote Control 增强
- **新功能**: Session spawning（之前只能接管已有 session，现在可以从手机直接创建新的本地 session）
- **使用**: `claude remote-control` 启动服务，手机连上去就能远程操作
- **要求**: 2.1.74+ 版本，Max/Team/Enterprise 计划

#### 3. Voice Mode 全量开放
- **覆盖**: 100% 用户都能在 Desktop 和 Cowork 里用语音和 Claude 对话

#### 4. Setup Script 支持 Web 和 Desktop
- **功能**: 项目里配启动脚本，Claude Code 启动时自动跑——装依赖、设环境变量、加载配置
- **场景**: 对云环境特别有用

#### 5. 实用小功能
- `claude --name`: 启动时给 session 取名
- `/color`: 换终端颜色，多窗口区分
- `postcompact hook`: 上下文压缩时自动触发脚本
- Plan mode 结束后 session 自动获得有意义的名字

## Key Insights

### 1. Effort Max 与 OpenClaw 的差异化
- **Claude Code**: 显式"深度 vs 成本"选择（用户主动选择 max 模式）
- **OpenClaw**: Passive Context 设计（AGENTS.md/Skill 静态约束）
- **差异**: Claude 让用户决定"花多少"，OpenClaw 通过约束决定"做什么"

### 2. Token 效率成为关键战场
- 官方明确提到"不再因为省 token 而截断推理"——说明上下文长度仍是瓶颈
- 代价感知设计（每个 session 手动激活）避免用户无意识超支

### 3. Remote Control 的 Harness 工程意义
- "出门吃饭也不耽误 Agent 干活"——移动场景下的 Agent 持续运行需求
- 与 OpenClaw 的 Gateway/Sub-agent 架构可形成互补
