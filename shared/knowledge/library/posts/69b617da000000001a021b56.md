OpenViking：给 Agent 装上文件系统式大脑
做 Agent 开发的人都踩过传统 RAG 的坑。上下文碎片化散落在代码、向量库、配置文件各处，检索是黑盒出了错只能猜，记忆只记用户说了什么不记 Agent 学到了什么。火山引擎开源的 OpenViking 用一个思路解决了这些问题：把所有上下文当文件管理。

OpenViking 设计了一套 viking:// 虚拟文件系统，把 Agent 需要的三类上下文统一组织：resources 放外部资源（文档、代码库、网页），user 放用户偏好和记忆，agent 放技能、指令和任务经验。每个节点都有唯一 URI，Agent 用 ls、find、grep 这些命令操作上下文，像开发者管理代码一样精确可控。

最核心的设计是三层加载。写入时系统自动把内容拆成 L0 摘要（约 100 tokens）、L1 概览（约 2000 tokens）、L2 全文三个层级。Agent 检索时先扫摘要判断相关性，再看概览了解结构，只在真正需要时才加载全文。一个 5000 行的 API 文档，传统方式消耗 15000 tokens，OpenViking 只需要 2600。

检索策略也不一样。传统 RAG 做一次向量搜索取 top-N 碎片就完了，OpenViking 用目录递归检索：先分析意图拆成多个检索条件，向量检索锁定高分目录，在目录内做二次精细探索，有子目录就逐层递归。整个检索过程生成可视化轨迹，每一步路径决策都有记录，出了问题看轨迹就知道原因。

记忆也不再是静态记录。每次会话结束，OpenViking 自动分析任务执行结果和用户反馈，提取经验更新到 user 和 agent 目录。用户偏好越来越准，Agent 操作越来越熟，真正做到越用越聪明。

实测数据很有说服力。基于 LoCoMo 长对话基准（1540 案例），OpenViking 比原生记忆方案任务完成率提升 49%，同时 token 消耗降低 83%。跟 LanceDB 比也好不少，完成率高 17%，token 消耗降低 92%。效果好还省钱，不常见。
