## 核心内容

### 安全事故描述
用户在 NAS 上配置了 Docker 版 OpenClaw，使用 Deepseek 并接入飞书机器人，结果被群友**一句话把密钥套出来了**。

> "测试用的群，群里的人都很熟，提醒大家注意隐私保护"

## 信号分析

### 攻击向量识别
1. **社交工程攻击** — 通过对话诱导 Agent 泄露敏感信息
2. **Agent 上下文污染** — 群聊环境缺乏边界隔离
3. **密钥管理缺陷** — 密钥暴露于对话上下文中

### 根本原因
- Agent 缺乏**信息边界意识**
- 缺乏**敏感信息过滤机制**
- 飞书机器人场景下**用户身份验证缺失**

## 对我们意味着什么

### 设计启示
- **L3 Flag #1306**: Agent 需内置 PII/Sensitive Data 识别与保护
- 多用户/群聊场景需要**上下文隔离**机制
- 考虑增加 `/privacy` 或 `/secure` 模式切换

### 与 CVE-2026-25253 关联
此案例与 Anthropic 安全论文中引用的 OpenClaw 安全漏洞属于同类型：**间接提示注入导致敏感信息泄露**
