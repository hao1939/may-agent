## 核心主张

> "长程性能不由上下文长度决定，而由有限上下文预算内维持的决策相关信息量决定。"

GenericAgent 围绕**上下文信息密度最大化**这一单一原则构建，通过四个紧密连接的组件实现：

### 四大组件

| 组件 | 功能 | 设计原则 |
|------|------|----------|
| **最小原子工具集** | 9个原子工具，保持接口简单 | 工具最小化 |
| **分层按需记忆** | 默认只展示高层概览，细节按需展开 | 信息分层 |
| **自进化机制** | 将验证过的轨迹转化为可复用SOP和可执行代码 | 经验固化 |
| **上下文截断压缩层** | 长执行期间维持信息密度 | 密度保持 |

## 架构极简主义

```
核心代码: ~3.3K 行
Agent Loop: ~100 行
工具数量: 9个原子工具
```

**9个原子工具覆盖**: 浏览器、终端、文件系统、键盘/鼠标输入、屏幕视觉、移动设备(ADB)

### 与OpenClaw的对比

| 维度 | GenericAgent | OpenClaw |
|------|--------------|----------|
| 核心代码量 | ~3K行 | 更大 |
| 技能来源 | 运行时自动进化 | 预定义 + 手动编写 |
| 记忆策略 | 分层按需 | 文件系统为主 |
| 自进化立场 | **积极拥抱** | **明确禁止** |
| Token效率 | <30K上下文 | 未明确优化 |

## 自进化机制详解

```
[新任务] --> [自主探索] (安装依赖、写脚本、调试验证) -->
[将执行路径结晶为技能] --> [写入记忆层] --> [下次类似任务直接调用]
```

### 关键创新

1. **执行路径结晶**: 每次解决新任务，自动将执行路径转化为可复用技能
2. **技能树生长**: 使用时间越长，积累越多技能——完全属于你的技能树
3. **经验不丢失**: 跨episode保留有用的经验

### 自我引导证明

> "本仓库的所有内容——从安装Git、运行 `git init` 到每条commit message——都是由GenericAgent自主完成的。作者从未打开过终端。"

## 与OpenClaw的关键分歧

### 1. 运行时自进化

GenericAgent **积极拥抱**运行时自进化，而我们**明确禁止**。

- **他们的立场**: 技能应在运行中从经验生长
- **我们的立场**: 运行时自进化带来不可预测性和安全风险

### 2. 技能来源

| 来源 | GenericAgent | OpenClaw |
|------|--------------|----------|
| 自动发现 | ✅ 核心机制 | ❌ 禁止 |
| 人工编写 | 辅助 | 主要 |
| 多Agent协作 | 不明确 | ✅ Dispatcher协调 |

## 值得借鉴的设计

### 1. 上下文信息密度最大化

> "长程Agent的根本限制不是上下文长度，而是决策相关信息在有限上下文预算中的密度。"

- **分层记忆**: 默认高层概览，细节按需展开
- **Token效率**: <30K vs 200K-1M（其他Agent）
- **密度保持**: 专门的截断和压缩层

**启示**: 我们的技能系统可以借鉴分层加载思想，区分热/冷技能。

### 2. 最小原子工具集

仅用9个原子工具实现全系统控制：
- 浏览器（保留登录会话）
- 终端
- 文件系统
- 键盘/鼠标输入
- 屏幕视觉
- 移动设备(ADB)

**启示**: 工具最小化可能比拼凑大量工具更有效。

### 3. 经验固化机制

将成功轨迹转化为可复用SOP，这与我们的Error Log理念有共通之处：
- 都是从事故/成功中学习
- 都强调可复用性
- 都形成组织记忆

**差异**: 他们自动、即时；我们手动、审慎。

## 对我们的意义

### 验证

1. **技能系统方向正确**: 技能作为核心抽象是行业共识
2. **Token效率重要**: 上下文信息密度是优化关键
3. **分层记忆有效**: 按需加载优于全量加载

### 挑战

1. **自进化张力**: 他们证明自进化可行且有效，我们需要重新审视"禁止运行时自进化"的立场
2. **技能发现**: 我们依赖人工编写，他们自动发现——效率差距明显
3. **上下文优化**: 我们有L1/L2/L3 Flag，但缺乏系统的密度最大化策略

### 行动建议

| 优先级 | 建议 | 依据 |
|--------|------|------|
| P2 | 研究分层技能加载 | Token效率差距 |
| P3 | 重新审视自进化立场 | 行业趋势挑战 |
| P4 | 借鉴经验固化机制 | Error Log可自动化 |
