## Core Concept: Semantic Invariance

**定义**: Agent在语义等价输入变化下保持输出一致性的能力。

> "A physics problem should yield the same solution whether phrased in formal academic language or practical business terminology"

**关键洞察**: 标准benchmark评估的是固定表述的准确性，但真实世界输入表述是多变且不可控的。

## Metamorphic Testing Framework

### 8种语义保持变换 (3大类)

| 类别 | 变换 | 描述 |
|------|------|------|
| **Structural** | Identity | 基准线（量化采样随机性） |
| | Paraphrase | 同义改写，词汇/句法变化 |
| | Reorder Facts | 独立事实顺序重排 |
| **Verbosity** | Expansion | 添加澄清性上下文（无新信息） |
| | Contraction | 删除冗余语言材料 |
| **Contextual** | Academic Context | 学术场景包装（考试题/教科书） |
| | Business Context | 商业场景包装（物流/品控） |
| **Control** | Contrastive | 显式对比替代方案（压力测试） |

### 评估指标

1. **Semantic Similarity Score**: 使用all-MiniLM-L6-v2嵌入计算余弦相似度
2. **Score Delta**: 变换前后得分变化（负值=退化，接近0=不变）
3. **Step-Level Metrics**: 多步推理的每步准确度

## Key Findings

### 1. Scale-Robustness Inversion (规模-鲁棒性反转) ⭐

| 模型 | 规模 | 不变响应率 | 语义相似度 |
|------|------|-----------|-----------|
| **Qwen3-30B-A3B** | 30B | **79.6%** | **0.91** |
| Qwen3-235B-A22B | 235B | 较低 | 较低 |
| Hermes 405B | 405B | 较低 | 较低 |
| gpt-oss-120B | 120B | 较低 | 较低 |
| DeepSeek-R1 | - | 较低 | 较低 |

**惊人发现**: 小模型Qwen3-30B稳定性最高，而更大模型表现更脆弱。

> "Model scale does not predict robustness"

### 2. Model-Family Signatures (模型家族脆弱性签名)

| 模型家族 | 脆弱性特征 |
|----------|-----------|
| **Hermes** | Contrastive fragility（对比场景易崩溃） |
| **Qwen3** | Robustness excellence（整体鲁棒性最佳） |
| **gpt-oss** | Reasoning coherence breakdown（多变换下推理连贯性崩溃） |
| **DeepSeek-R1** | Structural sensitivity（对事实重排和压缩敏感） |

### 3. Universal Contrastive Fragility (通用对比脆弱性)

- **Contrastive变换**（显式对比替代方案）**普遍 destabilize 所有模型家族**
- 得分退化高达 -0.45
- 表明注意力机制在面对干扰信息时存在根本性局限

## Experimental Setup

- **模型**: 7个foundation models，4个架构家族
- **问题**: 19个多步推理问题
- **领域**: 8个科学类别（物理/数学/化学/经济/统计/生物/微积分/优化）
- **难度**: 3个等级（Easy/Medium/Hard）

## Relevance to OpenClaw

### 设计验证

| 论文发现 | OpenClaw设计 | 一致性 |
|----------|-------------|--------|
| 输入表述敏感性是可靠性的关键维度 | L1确定性执行+固定Tool契约 | ✅ 直接验证 |
| 对比/干扰信息导致推理崩溃 | Skill原子化设计减少上下文干扰 | ✅ 架构支撑 |
| 需要超越准确性的鲁棒性评估 | Error Log多维度追踪(成本/稳定性/正确性) | ✅ 评估对齐 |

### 关键启示

1. **Agent选型**: 在可靠性优先场景，不应盲目追求最大模型
2. **Prompt工程**: 避免contrastive表述（"不要像X那样做"）
3. **评估维度**: 需要增加语义不变性测试到Skill验证流程
