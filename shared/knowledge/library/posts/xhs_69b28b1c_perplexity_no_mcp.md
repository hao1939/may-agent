## 核心新闻

Perplexity是目前最被认可的AI搜索引擎之一。它的联合创始人兼CTO **Denis Yarats** 在内部对团队说，他们正在**从MCP迁移出去，改用API和命令行工具**。

这条消息被开发者博主Morgan转发后，知名独立开发者**levelsio**（Nomad List和Remote OK创办者）当即引用：

> "感谢老天，MCP终于死了。"

---

## levelsio的逻辑

MCP和之前昙花一现的LLMs.txt一样，都是为AI专门造的抽象层，但根本没必要。**AI已经够聪明了，把API文档给它，它自己就能调，不需要再多一套协议包在外面。**

---

## MCP背景

- 2024年底Anthropic推出的标准
- 目的：让AI模型用统一方式接入外部工具和数据源
- 过去一年在开发者圈扩张很快

---

## 为什么Perplexity的信号重要

一家**真正在生产环境大规模跑AI的公司**，在内部选择退回API，说明至少对他们来说，**多这一层不划算**。

- MCP Token开销高

## 对我们意味着什么

| 发现 | 意义 |
|------|------|
| Perplexity生产环境迁移 | CLI-first路线被行业验证 |
| MCP vs API争论 | 社区共识向CLI倾斜 |
| Token成本问题 | CLI的10x效率优势被认可 |
| 模型能力演进 | 中间抽象层价值递减 |

**架构启示**:
- ✅ **技术选型完全验证**: CLI-first与行业最强声音一致
- ✅ **MCP边界清晰**: 标准化有价值，但非默认选择
- ✅ **模型能力演进**: AI可直接读API文档，中间层价值降低
- ⚠️ **产品差异化**: 需要与基模保持夹角，避免被创飞

**与我们设计的对应**:
| 社区洞察 | 我们的设计 |
|----------|------------|
| MCP→API/CLI迁移 | Channel+Gateway的CLI-first路线 |
| Skill+API组合 | Skill Registry + Tool Gateway |
| Token效率 | Channel层轻量设计 |
| 产品夹角 | 我们的价值在于编排层而非工具层 |
