## 核心内容: OpenClaw ACP实操

### ACP是什么
- **Agent Client Protocol** — 标准协议桥梁
- 把聊天工具和AI agent后端连起来
- 在Telegram topic里发消息 → ACP桥转给Codex/Claude → 回复传回
- **会话持久化**: 重连后上下文还在

### 推荐群结构 (3个topic)
| Topic | 用途 | ACP后端 |
|-------|------|---------|
| General | 正常聊天 | 不绑任何ACP |
| Codex topic | 写代码修bug做功能 | ACP直连Codex |
| Claude topic | 代码审查重构复杂逻辑 | ACP直连Claude Code |

**原则**: 三个互不干扰，聊天归聊天干活归干活

### 配置三步
1. **bindings映射**: 在配置文件里写chat id和topic id对应哪个agent
2. **启用ACPX runtime插件**: 这步最容易漏
3. **重载gateway**: 让配置生效

### 验证方法
- **直接法**: 去绑定的topic发消息看有没有回复
- **精准法**: 命令行起最小ACP探针测试
  - 如果报runtime backend未配置 → 问题在ACP runtime层不是Telegram层

### 排查四步 (发消息没反应时)
1. 查binding在不在，chat id和topic id对不对
2. 查agent活没活，状态是ABSENT说明后端没起来
3. 做ACP探针定位是哪一层的问题
4. **查acpx插件是不是enabled** — 最常见的根因

> "线插好了标签贴好了但工位没通电，就是这个情况"

### 两个坑
1. **General不要绑ACP** — 否则随便聊两句都会被当成工作输入
2. **不要用runtime spawn硬开topic ACP** — 正确做法是在bindings里写明确映射然后重启gateway
