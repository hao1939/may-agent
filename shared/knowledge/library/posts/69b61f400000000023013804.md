## Title
一个AI agent删掉了亚马逊的生产环境，630万订单没了

## Content
亚马逊内部强推AI编程工具Kiro，要求80%的工程师每周必须用。

结果：一个AI agent把生产环境删了。AWS宕机13个小时。累计丢了630万订单。

这不是段子，是上周真实发生的事。亚马逊紧急召开了工程事故复盘会。

问题出在哪？不是Kiro这个工具本身不行。是整个流程出了问题——AI生成了代码，没有足够的人在review，直接进了生产环境。

这件事指向一个正在变得越来越明显的行业问题：
AI写代码的瓶颈，已经不是写得够不够快。是没人在认真检查它写了什么。

Anthropic上周发布了multi-agent Code Review，GitHub集成，专门用AI来review AI写的代码。内部数据：用了之后，有实质性修改意见的review从38%涨到了54%。

这两件事放在一起看，pattern很清楚：code generation已经不是瓶颈了，code review才是。

我自己的体验也是这样。用Claude Code写代码很快，但最花时间的不是写，是回头看它改了什么、有没有改多、有没有引入新的问题。越是大项目，这个检查成本越高。

还有一个容易被忽略的点：context越长，AI越容易出问题。Transformer的注意力成本随token数的平方增长。你以为把整个codebase塞进去是在帮它，其实你在用信息淹死它。重要的事实被埋在噪声里。

更聪明的做法是拆——用专门的sub-agent处理不同模块，每个agent只看它需要看的部分，而不是一个模型吃掉一切。

AI写代码越来越快。但如果review跟不上，快只会让你更快地制造问题。

## Key Insights
1. **Code Generation ≠ Code Review** — 生成快但检查慢成为新瓶颈
2. **Context Length Trap** — 长上下文反而淹没关键信息
3. **Sub-agent Architecture** — 模块化Agent设计比单Agent通吃更可靠
4. **Industry Pattern** — AI-generated code needs AI-assisted review (38%→54% improvement)
