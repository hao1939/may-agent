## Core Framework: Agent Architecture Taxonomy

### Three Paradigms ↔ Classical Planning Mapping

| Agent Architecture | Planning Paradigm | Search Strategy | Horizon | Examples |
|-------------------|-------------------|-----------------|---------|----------|
| **Step-by-Step** | BFS (Breadth-First Search) | d=1 per step, immediate feedback | Short | WebArena, Mind2Web |
| **Tree Search** | Best-First Tree Search | Maintain search tree 𝒯, value function V:𝒮→[0,1] | Medium | Koh et al. 2024 |
| **Full-Plan-in-Advance** | DFS (Depth-First Search) | Complete trajectory τ=(a₁,a₂,…,aₙ) before execution | Long | **This paper's novel implementation** |

### Key Insight

> "Current LLM agents do not merely mimic classical search; they implement distinct traversal strategies over the (𝒮,𝒜) graph."

## Context Drift: The Fundamental Failure Mode

### Definition
> "An agent can, while completing a task, gradually lose sight of its original goal... Over many steps, the original goal simply falls out of memory, replaced by the most recent instructions."

### Mechanism
- **Short-horizon planning** (Step-by-Step/BFS) → susceptible to drift
- **Long-horizon constraints** (Full-Plan-in-Advance/DFS) → resist drift
- **External memory** → continuous reminder of original intent

### Mitigation Strategy (This Paper)
> "The plan itself is provided to the agent in the prompt for every single reasoning step. This continuous reminder serves as a form of external, high-level memory, helping the agent to interpret new observations, decide how to continue, and strongly resist context drift."

## Five Novel Evaluation Metrics

Beyond binary success/fail — assess **trajectory quality**:

### 1. Recovery Rate
```
Recovery Rate = Σ(# recoveries in task t / # deviation incidents in task t) / #tasks
```
Measures ability to return to human-demonstrated sequence after deviation.

### 2. Repetitiveness Rate
```
Repetitiveness Rate = 1 - Σ(# repetitive actions / # actions) / #tasks
```
Quantifies redundant actions (higher = less repetition).

### 3. Step Success Rate
```
Step Success Rate = Σ(# matched human gold steps / # human gold steps) / #tasks
```
Proportion of human-defined steps successfully completed.

### 4. Partial Success Rate
```
Partial Success Rate = Σ(# completed requirements / # requirements) / #req_tasks
```
For multi-requirement tasks (e.g., "list 5 reviews" → 4/5 = 0.8).

### 5. Element Accuracy Rate
```
Element Accuracy Rate = Σ(# matching planned vs actual / # agent steps) / #tasks
```
Gap between intended action and executed action.

## Experimental Results: Step-by-Step vs Full-Plan-in-Advance

| Metric | Step-by-Step (BFS) | Full-Plan-in-Advance (DFS) | Interpretation |
|--------|-------------------|---------------------------|----------------|
| **Overall Success** | 38.41% | Lower | Human-like trajectory alignment |
| **Element Accuracy** | Lower | **89%** | Technical execution precision |
| **Context Drift Resistance** | Lower | **Higher** | Plan-as-memory effect |

### Key Finding
> "While the Step-by-Step agent aligns more closely with human gold trajectories, the Full-Plan-in-Advance agent excels in technical measures... demonstrating the necessity of our proposed metrics for selecting appropriate agent architectures based on specific application constraints."

## OpenClaw Mapping

### Architecture Alignment

| This Paper | OpenClaw | Notes |
|------------|----------|-------|
| Full-Plan-in-Advance (DFS) | **AGENTS.md + Task decomposition** | Pre-computed plan as persistent context |
| External, high-level memory | **AGENTS.md + read_by** | Continuous reminder of role/intent |
| Context Drift resistance | **L1 Flag #1 (Identity)** | SOUL/DOMAIN as invariant anchor |
| Recovery Rate | **Error Log + L3 retry** | Deviation detection and recovery |
| Step Success Rate | **L2/L3 Validation gates** | Step-by-step verification |

### Design Philosophy Validation

This paper **formally validates** OpenClaw's core design decisions:

1. **AGENTS.md as persistent plan** → equivalent to Full-Plan-in-Advance's continuous plan injection
2. **L1 Identity as drift anchor** → SOUL.md/DOMAIN.md resist context drift through architectural invariants
3. **Error Log as recovery mechanism** → deviation detection + recovery trajectory
4. **L3 handoff as replanning** → when execution diverges from plan, handoff triggers replanning

### Critical Distinction

This paper's Full-Plan-in-Advance requires **replanning** when state diverges from expected intermediate state. OpenClaw's handoff mechanism is the **structural equivalent** — explicit replanning via delegation rather than implicit regeneration.

## Strategic Implications

### For Architecture Design
1. **BFS vs DFS is not a binary choice** — hybrid architectures (like OpenClaw) combine both
2. **Context drift is a first-class concern** — requires explicit mitigation (external memory)
3. **Evaluation must be multi-dimensional** — single success rate is insufficient

### For OpenClaw
1. **Formal validation of AGENTS.md design** — persistent context as drift resistance
2. **Metrics framework to adopt** — Recovery Rate, Element Accuracy for L3 evaluation
3. **LLM-as-judge for Skill validation** — semantic equivalence for output verification
