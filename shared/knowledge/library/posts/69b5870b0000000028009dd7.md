## 核心变革

### 传统流程 vs AI驱动流程

| 阶段 | 传统 | AI驱动 |
|------|------|--------|
| 开发 | 手写代码 | Codex生成 |
| 验证 | 人工测试 | 自动跑test |
| 提交 | git add/commit/push | 自动执行 |
| PR | 手写描述 | AI生成 |
| **人的角色** | 执行者 | **Reviewer** |

> "我不写代码了，我在带 AI 实习生"

## Git Worktree实战技巧

### 核心痛点
以前AI改代码最大的问题：**会把本地仓库改乱**。

### 解决方案
**一个任务 = 一个Worktree**

并行任务示例：
- Worktree 1: 修bug
- Worktree 2: 写README
- Worktree 3: 重构代码
- 本地主分支: 正常开发

**互不影响，非常爽。**

## 自动PR脚本

```bash
# scripts/codex_finish_pr.sh
git checkout -b $branch
git add -A
git commit -m "$msg"
git push origin $branch
gh pr create
```

执行: `./scripts/codex_finish_pr.sh feature/new-api`

## Definition of Done Prompt

```
Work on this task in a Worktree.
Definition of done:
1 implement the change
2 run lint and tests
3 summarize changes
4 create branch
5 git add commit push
6 open PR
```

**结果**: 基本每次都能跑完整流程。

## 关键洞察

| 洞察 | 说明 |
|------|------|
| **工作流即代码** | 把重复流程脚本化，AI执行标准化步骤 |
| **隔离即自由** | Worktree提供并行能力，突破单线程限制 |
| **角色转移** | 从编码者→规则设计者→质量把关者 |
