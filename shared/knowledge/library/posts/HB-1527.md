## Executive Summary

Calinescu et al. propose a **systematic five-stage SLEEC norm operationalisation process** for translating abstract Social, Legal, Ethical, Empathetic and Cultural (SLEEC) norms into concrete, verifiable AI agent requirements. The framework establishes formal methods for ensuring AI agents are demonstrably aligned with human norms and values — directly validating OpenClaw's AGENTS.md/Error Log/SKILL.md architecture.

**SLEEC = Social, Legal, Ethical, Empathetic, Cultural**

---

## Five-Stage Operationalisation Process

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  STAGE 1          STAGE 2              STAGE 3           STAGE 4    STAGE 5 │
│  Capability    →  Requirements    →  Well-formedness →  Implementation → Verification│
│  Specification    Elicitation        Checking           & Guardrails   & Compliance │
└─────────────────────────────────────────────────────────────────────────────┘
                              ↑___________________________________________↓
                                    (Iterative Feedback Loop)
```

### Stage 1: AI Agent Capability Specification
- **Purpose**: Determine high-level functional capabilities
- **Two aspects**: (1) Capabilities that determine which SLEEC norms apply; (2) Capabilities needed to satisfy SLEEC norms
- **Output**: List of informally specified capabilities + use cases

### Stage 2: SLEEC Requirements Elicitation
- **Three activities**:
  1. **Identify high-level principles** (non-maleficence, autonomy, privacy)
  2. **Derive normative-principle proxies** (actionable placeholders)
  3. **Define SLEEC rules** in domain-specific language (DSL)

**SLEEC Rule Syntax**:
```
id when triggerEvent [and triggerGuard] 
   then response [within timeframe]
   [unless defeaterGuard [then defeaterResponse]]
```

- **Defeaters**: Specify circumstances where rule doesn't apply (exceptions)
- **Success criterion**: Stable combination of capabilities and rules
- **Failure outcome**: Halting the process (valid and necessary if infeasible)

### Stage 3: SLEEC Requirements Well-formedness Checking
Detects **four types of well-formedness issues (WFIs)**:
1. **Conflicts**: Pairs of rules that cannot both always be obeyed
2. **Redundancies**: Obeying one rule always means the other is also obeyed
3. **Insufficiency**: Ruleset fails to prevent normatively undesirable behaviors
4. **Over-restrictiveness**: Ruleset disallows desirable behaviors

**Two complementary verification methods**:
- **Process-algebraic** (tock-CSP + FDR model checker) — detects conflicts/redundancies
- **Logic-based LEGOS** (FOL* + satisfiability checker) — detects insufficiency/over-restrictiveness

### Stage 4: SLEEC-aware Implementation
- **Runtime guardrails** co-deployed with agent
- Monitor perceptions and decisions
- Constrain actions when rules apply
- Provide explicit decision points for handling defeaters
- **Revisable/extendable** in response to updated requirements

### Stage 5: Verification of AI Agent Compliance
- Formal verification using CSP-based models
- Novel conformance notion extending timewise refinement
- Verification → deployment; Failure → cancellation

## Open Challenges Identified

1. **Normative-principle reification**: Translating abstract UNESCO/OECD principles into concrete specs
2. **Normative ambiguity and value-conflict resolution**: Transparency vs privacy, safety vs autonomy
3. **SLEEC-capable agent engineering**: Traceability, timing reconciliation, computational capacity
4. **Runtime adaptation**: Dynamic behavior updates while maintaining formal guarantees
5. **Normative competence**: Cross-disciplinary education for engineers, regulators, ethicists

## Key Insights for Our System

### 🔥 Critical Validation
- **"Cancellation is a positive outcome"** — Process explicitly halts if SLEEC compliance is infeasible. Validates OpenClaw's strict constraint model.
- **Defeaters as first-class concept** — `read_by` field captures contextual exceptions formally.
- **Runtime guardrails** — Error Log provides the "monitor perceptions and constrain actions" mechanism.

### 🔥 Design Principle Alignment
- **Conflict detection** — AGENTS.md role separation prevents normative conflicts
- **Traceability** — AGENTS.md ←→ SKILL.md linkage preserves requirement-to-implementation trace
- **Temporal reconciliation** — Heartbeat model reconciles fast agent cycles with slow human norms

### 🔥 Actionable Gap
- **Formal verification tooling** — SLEEC uses FDR model checker and CSP. OpenClaw lacks automated conflict/redundancy detection in AGENTS.md rulesets.
