## Summary
acpx是headless CLI客户端，实现Agent Client Protocol标准协议。Peter Steinberger(OpenClaw作者)扩展acpx让Codex和OpenClaw通过ACP协议通信。

## Core Problem Solved
每个coding agent都是孤岛。Codex不能调Claude，Claude不能调OpenClaw。以前做法：PTY抓屏，不稳定丢格式没有结构化数据。

## Supported Agents
- Codex
- Claude
- Gemini
- OpenClaw
- OpenCode
- Pi
- 支持自定义ACP服务器

## Three Use Cases
1. **单向调用**: Codex工作中通过acpx调用OpenClaw上的Molty，结果返回Codex
2. **双向调用**: "now codex can call openclaw via acp, so openclaw can call codex via acp" - A调B，B也能调A，各自发挥擅长领域
3. **私密协商**: Codex建立到OpenClaw的私密通道，两agent先私下讨论，再由Molty决定是否对外发布

## Core Features
- 持久化session (重启后上下文还在)
- 命名session (同一仓库并行多个工作流)
- prompt队列 (上一个任务还在跑新任务自动排队)
- crash自动重连

## Strategic Insight
acpx不是又一个AI工具，而是让所有AI工具互相对话的连接层。从人在多个AI之间搬运信息，到AI之间直接结构化通信，这是agent协作的基础设施。
