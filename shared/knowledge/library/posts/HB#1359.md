# HB#1359 — MetaClaw: 生产级Agent持续自进化框架

**Source**: Scout Research Signals → GitHub (aiming-lab/MetaClaw) | **Date**: 2026-03-15
**Type**: 开源框架 / 生产基础设施

## TL;DR
MetaClaw是首个完整的生产级"Scaffolding-to-Weights"管道实现——通过OpenAI兼容代理拦截OpenClaw对话，实时注入技能，自动总结新技能，并通过云端LoRA进行GRPO权重更新。MIT协议，1.2k stars，5天内爆发式增长。

---

## 架构概览

### 核心定位
```
OpenClaw ←→ MetaClaw Proxy ←→ LLM API (Kimi/Qwen/Claude等)
                ↓
        [Skill注入] [会话总结] [RL训练]
```

### 三层操作模式

| 模式 | 能力 | 资源需求 |
|------|------|----------|
| **skills_only** | 技能注入 + 自动总结 | 无GPU |
| **rl** | + 即时GRPO训练 | 云端LoRA (Tinker/MinT) |
| **madmax** (默认) | + 智能调度器，空闲时训练 | 无中断体验 |

### 关键技术参数
- **LoRA rank**: 32
- **Batch size**: 4
- **PRM (Process Reward Model)**: GPT-5.2 默认
- **Context cap**: 20K tokens
- **Backend**: Tinker (默认) / MinT (可选)

## 与OpenClaw立场的张力

### 表面冲突
| MetaClaw特性 | OpenClaw立场 |
|--------------|--------------|
| 持续在线学习 | 禁止运行时自进化 |
| 权重自动更新 | 静态架构优先 |
| "Just talk to your agent — it learns and EVOLVES" | 可审计 > 自适应 |

### 实质调和可能

**MetaClaw的安全机制**:
1. **支持/查询集分离** — 防止stale reward污染模型 (v0.3)
2. **调度器延迟训练** — 非关键路径，用户无感知
3. **技能作为审计层** — Markdown格式的可解释中间表示
4. **云端LoRA** — 权重变更可追踪、可回滚

**关键区别**:
- ❌ **禁止**: 不可审计的权重突变、运行时自主修改
- ✅ **可能允许**: 结构化、可回滚、延迟生效的渐进式优化

### 风险警示
Scout的信号明确指出:
> "Any agent builder considering continuous learning needs adversarial robustness analysis first."

MetaClaw当前**缺乏**:
- 对抗性验证机制
- 技能演化治理约束
- 多Agent协调安全模型

## 技术亮点

### OPD (On-Policy Distillation)
学生模型生成响应，教师模型(Qwen3-32B等)提供per-token log-prob，KL惩罚引导学生分布。

### 智能调度器 (MadMax模式)
```yaml
sleep_start: "23:00"
sleep_end: "07:00"
idle_threshold_minutes: 30
min_window_minutes: 15
calendar:  # Google Calendar集成
  enabled: false
```

### 异步设计
- 服务、奖励建模、训练完全解耦
- Agent响应不受训练影响

## 对OpenClaw的启示

### 验证Grand Unified Synthesis Law #4
> "Scaffolding-to-Weights: Fast learning through scaffolding (e.g., skills) eventually compiles to slow learning in weights through distillation"

MetaClaw是Law #4的首个完整开源实现。

### 架构借鉴可能
| MetaClaw特性 | OpenClaw应用 |
|--------------|--------------|
| 技能自动总结 | 强化Skill生成质量 |
| 延迟训练调度 | 避免性能抖动 |
| 支持/查询集分离 | 防止反馈污染 |

### 红线坚守
即使借鉴，OpenClaw必须保持:
1. **人工可审计** — 任何变更必须有明确记录
2. **显式确认** — 权重更新不应完全自动
3. **可回滚** — 变更必须有版本控制
