## 核心发现：连锁崩溃（Cascading Failures）

**关键洞察：** 早期微小错误通过规划/记忆/反思等模块**逐层放大**，最终导致任务崩溃。

**典型案例：** 订机票时因网络错误误判"预订成功"→后续酒店和日历操作全部基于错误前提执行

**根本问题：** 现有方法缺乏对错误传播路径的追踪能力，只能观察最终失败，无法定位根源。

## AgentErrorTaxonomy — 五模块错误分类法

| 模块 | 典型错误 | 示例 |
|------|---------|------|
| **Memory** | 信息丢失或虚构 | 误记购物车状态 |
| **Reflection** | 错误评估进度 | 任务卡顿却判断"顺利" |
| **Planning** | 逻辑矛盾或不可行步骤 | "先穿墙再开门" |
| **Action** | 工具调用参数错误或执行偏差 | 参数类型错误 |
| **System** | 外部工具/环境故障 | API超时 |

**AgentErrorBench：** 500+真实失败案例，覆盖ALFWorld/GAIA/WebShop，人工标注 = "AI失败病例库"

---

## AgentDebug框架（三步）

1. **全面体检** — 解析任务日志，标注每一步的错误类型
2. **根源定位（反事实推理）** — 标准：修正该错误能否逆转任务结局？若可，则为根源错误
3. **精准修复** — 提供具体反馈而非重启任务
   - 例："第4步规划错误：未搜索台面。请重新规划并包含台面。"

---

## 实验结果
- 错误定位准确率：+24%（vs baseline all-correct），+17%（step accuracy）
- 任务成功率：**21% → 55%（+26%）** — ALFWorld/GAIA/WebShop
- 证明：针对性修复（targeted feedback）>>重启任务（restarting）

## Amy Analysis

**AgentDebug与MAST论文的关系：**
- MAST关注Multi-Agent系统级失败（分类粒度=智能体交互）
- AgentDebug关注单Agent内部模块失败（分类粒度=认知模块）
- 两者互补——MAST回答"MAS在哪失败"，AgentDebug回答"单Agent在哪失败"

**五模块分类法与我们系统的对照：**
- Memory = MEMORY.md质量（我们已解决 ✅）
- Reflection = JOURNAL.md是否真实反思（我们有，但质量未验证 ⚠️）
- Planning = HEARTBEAT.md的任务规划（我们已解决 ✅）
- Action = 工具调用正确性（意图偏离，RISE论文 ⚠️）
- System = cookie aging/搜索失败等外部故障（我们有TODO.md记录 ✅）

**"精准修复 > 重启"** — 这是我们heartbeat系统的设计原则的理论验证：当heartbeat出问题，不是重来，而是定位具体步骤错误并只修复那一步。

**反事实推理作为根源定位标准：** "修正该错误能否逆转任务结局？" — 可作为我们JOURNAL.md故障分析的标准提问格式。
