### 关键概念定义

| 术语 | 定义 |
|------|------|
| **Task** | 单次测试，包含明确输入和成功标准 |
| **Trial** | 任务的单次尝试，需多次运行以产生一致结果 |
| **Grader** | 评分逻辑，一个Task可有多个Graders |
| **Transcript/Trace** | 完整执行记录，包括输出、工具调用、推理过程 |
| **Outcome** | 试验结束时的环境最终状态 |
| **Evaluation Harness** | 端到端运行eval的基础设施 |
| **Agent Harness** | 使模型成为Agent的系统（Claude Code等）|

### 三类评分器(Graders)

**Code-based Graders**
- 字符串匹配、二进制测试、静态分析
- 优点: 快速、便宜、客观、可复现
- 缺点: 对有效变体脆弱、缺乏细微差别

**Model-based Graders**
- 基于评分标准、自然语言断言、成对比较
- 优点: 灵活、可扩展、捕捉细微差别
- 缺点: 非确定性、更昂贵、需人工校准

**Human Graders**
- 专家审核、众包判断、抽样检查
- 优点: 黄金标准质量
- 缺点: 昂贵、缓慢

### 两种评估类型

**Capability Evals (能力评估)**
- 问题: "Agent擅长什么？"
- 初始通过率应较低，给团队爬坡目标

**Regression Evals (回归评估)**
- 问题: "Agent是否仍能处理以前能处理的任务？"
- 通过率应接近100%，防止倒退

### OpenClaw关联

**直接验证设计决策**:
1. **Error Log = Transcript**: Anthropic定义transcript为"完整messages数组"，与OpenClaw Error Log设计一致
2. **Capability vs Regression分离**: 对应SKILL.md(能力定义)与AGENTS.md/ERROR.md(回归防护)
3. **三层评分器**: 对应Skill的静态检查、运行时评估、人工审核
