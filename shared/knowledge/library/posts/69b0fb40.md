## 核心公式

> **Agent = Model + Harness**
> 
> "模型提供智能，Harness 让智能变得有用。如果你不是模型本身，那你就是 Harness 的一部分。"

---

## Harness 组件解剖

### 定义
Harness 是**模型之外的所有东西**：
- 系统提示
- 工具描述
- 文件系统
- 沙箱
- 编排逻辑
- Hooks

### 模型裸跑四大硬伤
1. **无法维持跨会话状态**
2. **无法执行代码**
3. **无法获取实时知识**
4. **无法搭建工作环境**

> "每一个'不能'，恰好对应 Harness 里的一个组件。"

---

## 关键组件详解

### 1. 文件系统 — 最基础的原语
- Agent 需要工作空间来读数据和代码
- 把中间结果存下来而不是全塞进上下文
- 通过共享文件和其他 Agent 协作
- 加上 Git → 版本追踪、错误回滚、分支实验
- **文件系统是其他所有 Harness 功能的基石**

### 2. Bash + 沙箱
- Bash 让 Agent 不再受限于预设工具集
- 沙箱提供安全隔离的执行环境
- 代码不在本地跑，环境随用随建用完销毁
- 命令可以白名单管控
- **两者结合产生自我验证循环**: 写代码 → 跑测试 → 看日志 → 修 Bug → 再来一轮

### 3. AGENTS.md 记忆系统
- 实现**持续学习闭环**
- Agent 工作中写入知识
- Harness 存到文件系统
- 下次启动时自动注入上下文

> "不改权重的前提下，上下文注入是唯一给模型加知识的方式。"

### 4. Web Search + MCP
- 突破知识截止日期
- 访问训练后的新信息

### 5. Context Rot — 真实威胁

> "上下文填满后模型推理能力持续下降。"

**对策三件套**:
| 策略 | 说明 |
|------|------|
| 压缩 | 智能摘要现有上下文 |
| 工具输出卸载 | 只保留头尾，全文存文件 |
| Skills 渐进加载 | 不一次性灌入所有工具描述 |

> "Harness 本质上就是好的上下文工程的交付机制。"

### 6. 编排 (Orchestration)
- 子Agent调度
- 任务分发
- 模型路由
- Handoff切换

### 7. Hooks — 注入确定性
- lint 检查
- 续接逻辑
- 格式约束

> "模型是概率性的，Hooks 让关键步骤变得可靠。"

### 8. 系统提示
- 定义角色边界
- 注入领域知识
- 约束安全规则

## 对我们的意义

1. **Harness 框架完整性**: 提供了一个全面的 Harness 组件清单，可以对照检查我们的实现
2. **Context Rot 有解**: 三件套对策（压缩、卸载、渐进加载）可以直接应用
3. **AGENTS.md 验证**: 我们的 AGENTS.md 设计符合"持续学习闭环"理念
4. **沙箱 + Bash 组合**: 自我验证循环的设计模式值得借鉴
5. **Hooks 的重要性**: 强调了我们 Hooks 系统在注入确定性方面的价值
