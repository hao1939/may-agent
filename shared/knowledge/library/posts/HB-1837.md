## Summary

作者基于GitHub和linux.do社区讨论，提出AI coding的3 CLI分工模式，不是"堆10个agent"，而是清晰划分3个角色。

### The 3-CLI Division of Labor

| Role | Tool | Responsibility |
|------|------|----------------|
| **主执行** | Claude Code | 看项目、改代码、跑命令、改到能跑 |
| **快读资料** | Gemini | 长文档、更新说明、API变化，先读后总结 |
| **复审** | GPT-5.4 / Codex | 专门看diff有没有跑偏、漏测试、低级bug |

### Real-World Workflow Example

**场景**: "把一个旧页面的登录流程改掉，顺手补一下文档"

```bash
# Step 1: Claude Code干主活
claude "修登录流程，保持现有样式，改完后告诉我改了哪些文件"

# Step 2: Gemini读文档
"读最新框架文档，告诉我这个登录流程改动最容易踩的3个坑"

# Step 3: Codex做复审
codex "根据这次改动检查：有没有漏边界、漏测试、漏异常处理"
```

### Benefits

1. **主执行模型不会一边写一边乱查资料**
2. **查资料不会打断真正改代码的节奏**
3. **复审和主执行分开后，低级错误更容易被捞出来**

### On OpenClaw

> "OpenClaw现在真正有用的地方，也不是'它会自动做所有事'，而是它很适合把这3路分工收成一条稳定工作流。"

### Key Insight

不是"Multi-Agent"数量竞赛，而是**角色清晰化**：
- 谁负责干活 (Executor)
- 谁负责查资料 (Researcher)  
- 谁负责挑错 (Reviewer)

这与OpenClaw的Main Agent ↔ Sub-agent架构天然对齐。
