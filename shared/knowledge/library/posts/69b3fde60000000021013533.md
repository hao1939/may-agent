## 核心观点

Manus前后端负责人（Meta收购后离职）分享两年做AI Agent的核心结论：

> **一个 `run(command="...")` 比15个function calling工具效果好得多。**

## 三个核心理由

### ① Unix设计 vs LLM设计 — 殊途同归

- Unix设计：**一切皆文本流**
- LLM设计：**一切皆token**
- 50年前和50年后的两个决定，殊途同归

### ② 训练数据优势

- GitHub上数十亿行CLI命令
- LLM对 `cat | grep | wc` 的理解**远超任何自定义schema**
- 训练数据就是最好的tool description

### ③ 决策复杂度降低

- **15个工具** = AI要"选API"（理解15个schema + 选对）
- **1个run命令** = AI只需"组合字符串"
- 选择少了，准确率高了

## 评论区精华

### 支持观点

**红薯，启动！**:
> "其实根本是因为这些命令在训练数据里，大模型天然理解，function call是提示词喂的，大模型要临时理解"

**BullishAI（作者）回复**:
> "说到点上了。训练数据就是最好的tool description——几十亿行的使用示例，比任何JSON schema都管用"

**BullishAI 进一步解释**:
> "技术上是，但关键区别在工具数量。15个function call = 模型要理解15个schema + 选对。1个bash tool = 只需要组合字符串，搜索空间小了一个数量级"

### 反对/质疑观点

**花綠青**:
> "因为bash太灵活了，没有良好的提示词工程很难做好意图理解"

**天人水**:
> "根本原因不在于token，实际上cli工具照样需要描述，需要参数说明，和api的文档说明没有什么本质区别。最大区别在于cli执行起来跟本地操作一样，天然更适合在本地或者云端的虚拟化沙箱环境，简化了与外界的交互。"

**排骨年糕**:
> "实际上就是claude code推出的渐进式披露的变种，claude code用skill来压缩tool，一个skill里包含了多个tool的使用说明，command的思路也是一样一个command完成一类tool的调用，本质上没区别，都是为了压缩tool并且归类，降低上下文的复杂度"

**Meme**:
> "明显现在的 write read 框架更灵活，比如cc在文件变更后 不允许直接写入，必须重新read，这如果用 bash 实现，工作量和复杂度非常大，而且会让模型感到混乱"
