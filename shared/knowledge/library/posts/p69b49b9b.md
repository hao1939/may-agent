## 原始内容

标题: 我认真读完 Codex 官方文档，总结了 8 条真

最近在研究 OpenAI 的 Codex coding agent，把官方的文档认真读了一遍。很多人其实还把 Codex 当成一个："写代码的 AI"但官方给的定位其实不是这样。

更准确的理解应该是：把 Codex 当成一个长期合作的工程师，而不是一次性的工具。官方文档有一句话我很认同：

Treat Codex less like a one-off assistant and more like a teammate.意思就是：你不是在用一个工具，而是在培养一个团队成员。如果总结 Codex 的正确使用方式，其实 可以分成 6 个阶段：

1、给任务提供正确的上下文
2、用 AGENTS.md 写长期规则
3、配置 Codex 的工作环境
4、用 MCP 连接外部系统
5、把重复任务做成 Skills
6、稳定流程做成 Automation

这个思路其实很像一个 AI工程体系。不是一次性 prompt，而是一整套工程方法。

### 第一件事：写好 Prompt

官方建议一个 Prompt 最好包含四个部分：

1 Goal（目标）——你要做什么？
2 Context（上下文）——哪些内容和任务有关？
3 Constraints（约束）——需要遵守哪些规则？
4 Done When（完成标准）——什么时候算完成？

这个结构其实非常关键。如果没有这些信息，AI 会自动猜。一旦猜错：整个任务就会跑偏。

### 推理等级

官方给的一个经验也很有意思：根据任务复杂度选择推理等级。

- Low 适合小任务
- Medium 适合普通开发
- High 适合复杂逻辑
- Extra High 适合多步骤 agent 工作

还有一个小技巧：Codex App 支持 语音输入任务描述。
