## TL;DR

Skills架构通过动态挂载"技能包"解决Context爆炸问题，但牺牲了Prompt Cache，首字延迟增加。简化了架构，但对话历史记忆仍需独立管理。

## 核心权衡

| 优势 | 代价 |
|------|------|
| 动态挂载解决Context爆炸 | 牺牲Prompt Cache |
| 简化架构 | 首字延迟增加 |
| 按需加载 | 历史记忆需独立管理 |

## 评论区技术讨论精华

### 1. Skill卸载问题
**胖虎:** "已经加载的skill如何卸载？"

**作者回复:**
> "卸载是比较容易的，发给llm拼接的system prompt处理下，麻烦的是历史context中llm会留下自己用了哪些skill的过程，所以模型要有一定的能力不会混淆，即智能不能太差"

**洞察:** Skill卸载≠上下文清除，历史记录中的Skill痕迹可能导致混淆

### 2. KV Cache技术细节
**花生:**
> "我不太理解你文中的'skills的核心是修改system prompt'这个说法，Prompt结构是[System Prompt (头部)] + [Conversation History (中间)] + [New Query (尾部)]。我理解是claude code在开始阶段load了所有的skills的yaml头部，在会话开始扩展了原定的system prompt，之后在本次会话system prompt不会再变更，后续执行skills时load的具体内容会作为新内容加在prompt的尾部，前面的部分并未发生改变，为什么会引起kv cache失效呢？"

**作者回复:**
> "你是对的，我实现的不好"

**洞察:** 正确的Skill实现不应影响KV Cache，作者的自实现存在问题。Claude Code的实现方式更优雅。

### 3. Multi-Agent学习路线
**loyx:** "对于multi-agent的弯路，还有什么文章和实践介绍吗？"

**作者回复:**
> "沿着Claude code的路线先学习吧"

**洞察:** Claude Code被社区视为最佳实践参考

### 4. Multi-Agent误区
**七卡瓦:**
> "一个误区: multi agents = A2A 通信"

**洞察:** Multi-Agent≠A2A协议，过度关注通信协议是误区

## 关键洞察

**Claude Code实现方式:**
- 会话开始时加载所有Skill的YAML头部
- System Prompt扩展后不再变更
- Skill具体内容作为新内容加在prompt尾部
- 不破坏KV Cache

**Skill卸载的复杂性:**
- 技术层面容易：修改system prompt拼接
- 语义层面困难：历史context中已留下Skill使用痕迹
- 模型需有能力不混淆已卸载Skill

## 对我们的意义

**Skill实现参考:**
- ✅ 会话级Skill加载 vs 动态挂载
- ⚠️ KV Cache保持：System Prompt变更策略需谨慎
- ⚠️ Skill痕迹管理：历史上下文的Skill残留需考虑

**架构选择:**
- 被动上下文注入(AGENTS.md) vs 动态Skill挂载
- SkillsBench验证：AGENTS.md 100% > Skill 53%
