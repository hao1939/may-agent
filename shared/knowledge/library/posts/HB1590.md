## Core Innovation: Dual-Feedback MCTS

### 问题定义
传统工具规划的两极困境：
1. **Greedy方法** (ReAct/CoT): 短视决策，早期错误不可逆传播，无探索
2. **Search方法** (ToT/A*/LATS): 分支爆炸成本高，假设评估与真实执行脱节

### ToolTree解决方案

**六阶段循环架构**:
```
Selection → Pre-evaluation → Expansion → Execution → Post-evaluation → Backward Propagation
```

#### 1. Prior-Augmented UCT Selection
```
UCT(s,a) = Q(s,a) + λ·r_pre(s,a)·√(ln N(s)/N(s,a))
```
- `Q(s,a)`: 累积post-evaluation回报（ exploitation ）
- `r_pre(s,a)`: 预执行预测分数（先验偏置）
- `N(s)`, `N(s,a)`: 访问计数（探索 bonus ）

#### 2. Dual-Stage Evaluation

**Pre-Evaluation (先验)**:
- LLM judge基于context + tool card (I/O schema, domain tags, examples) 评分
- 门控expansion: 仅当 `r_pre ≥ τ_pre` 且排名前K才扩展
- 剪枝明显不兼容或低收益分支

**Post-Evaluation (后验)**:
- 基于实际执行输出 `o_{t+1}` 评分
- 驱动backward propagation更新 `Q(s,a)`
- 门控继续: 若 `r_post < τ_post` 标记为non-expandable

#### 3. Bidirectional Pruning

| 剪枝方向 | 触发条件 | 作用 |
|---------|---------|------|
| Pre-pruning | `r_pre < τ_pre` 或 非top-K | 阻止低潜力分支扩展 |
| Post-pruning | `r_post < τ_post` | 阻止已证实无产出分支继续 |

## Experimental Results

### Closed-Set Planning (GTA & m&m)

**GPT-4o Results (GTA)**:
| Method | Tool F1 | Arg F1 | Plan F1 | Exec F1 | AVG |
|--------|---------|--------|---------|---------|-----|
| Zero-shot | 70.16 | 38.52 | 77.14 | 45.28 | 57.78 |
| ReAct | 71.42 | 40.58 | 75.52 | 46.33 | 58.46 |
| ToT | 72.53 | 43.68 | 78.84 | 46.53 | 60.40 |
| A* | 74.29 | 47.58 | 79.96 | 46.26 | 62.52 |
| LATS | 77.84 | 49.90 | 82.57 | 48.80 | 64.78 |
| **ToolTree** | **79.26** | **50.84** | **85.53** | **52.17** | **66.95** |

**Key Finding**: ToolTree比vanilla MCTS (LATS)提升2.2+分，比greedy baseline (Zero-shot)提升9+分

### Open-Set Planning (ToolBench)

**Pass Rate**: ToolTree achieves **69.04%** on ToolBench (vs ~59% for baselines)

### Efficiency Analysis

**边际收益/秒**: ToolTree在16-64步区间效率最高，证明双向剪枝有效集中计算预算于高潜力分支

## Critical Validation for OpenClaw

### Architecture Mapping

| ToolTree Component | OpenClaw Equivalent | Verification |
|-------------------|---------------------|--------------|
| Pre-evaluation (`r_pre`) | Skill selection via AGENTS.md context | ✅ 先验预测工具适用性 |
| Post-evaluation (`r_post`) | `read_by` dependency validation | ✅ 实际执行后验证产出 |
| Pre-pruning (`τ_pre`) | L1 PASS criteria for Skill activation | ✅ 前置条件过滤 |
| Post-pruning (`τ_post`) | Error Log + Validation failure handling | ✅ 失败后停止该路径 |
| Backward Propagation | Error Log retrospective analysis | ✅ 历史评估更新未来决策 |
| Deterministic Caching | Tool call result memoization | ✅ 相同调用复用 |

### Key Insight: Bidirectional Pruning ↔ OpenClaw Defense-in-Depth

ToolTree的**双向剪枝**与OpenClaw的**分层验证**完全同构：

1. **Pre-pruning (L1)**: AGENTS.md + SKILL.md前置条件 = 执行前过滤
2. **Post-pruning (L2/L3)**: `read_by`验证 + Error Log = 执行后确认

> "Combining both signals yields two-sided budget control" — ToolTree论文

> "Validation at every boundary" — OpenClaw AGENTS.md设计原则

### Design Implications

**1. Explicit Dual-Stage Validation**
当前OpenClaw已隐含此结构，但可**显式形式化**：
- Pre-execution: AGENTS.md context + Skill metadata评分
- Post-execution: `read_by`验证 + output quality scoring

**2. Pruning Thresholds as Guardrails**
- `τ_pre` ↔ L1 PASS criteria严格度
- `τ_post` ↔ L2/L3 validation阈值

**3. Backward Propagation as Error Log Learning**
ToolTree的running average更新 `Q(s,a)` 直接对应Error Log积累历史性能数据，影响未来Skill选择

## Threats & Limitations

1. **Computational Cost**: MCTS需要多rollout，低延迟场景可能不适用
2. **Fixed Budget Assumption**: `R_max`预算在真实环境中可能动态变化
3. **Tool Card Dependency**: 依赖结构化tool schema，非结构化工具难以评估
