## 核心发现

Perplexity CTO公开声明**内部已弃用MCP协议**，这是来自一线大厂的强信号。帖子获得402赞，在中文AI社区引发广泛讨论。

### 声明背景

**Perplexity的技术栈**:
- 搜索+AI的重度工具调用场景
- 对延迟和成本极度敏感
- 生产环境规模验证

**弃用原因推断**:
1. **Context成本过高** — 工具schema全量加载的tax不可接受
2. **延迟问题** — 协议层增加的网络和解析开销
3. **灵活性受限** — 标准化协议的约束 vs 自定义优化
4. **替代方案成熟** — 内部CLI/直接集成效率更高

## 对OpenClaw的意义

### ✅ 验证

**生产环境优先CLI**: Perplexity的选型验证了OpenClaw CLI-first策略在生产环境的可行性。

**Context效率优先**: 大厂对token成本的敏感性与我们的优化方向一致。

### 🔬 思考

**协议分层策略**:
```
内部/本地工具 → CLI (零协议开销)
外部/远程服务 → 直接API集成 (跳过MCP中间层)
生态/第三方   → MCP (标准化优先)
```

**MCP的定位调整**:
- 从"默认选择"降级为"生态兼容选项"
- 优先直接集成，MCP作为fallback
- 关注MCP优化方案（如Tool Attention）的成熟度
