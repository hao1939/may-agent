## 核心范式转变

**旧范式（Prior）：** Turn-level + Handcrafted Operations
- 每轮对话逐turn跑一堆固定模块
- 过于rigid，强依赖人类先验，难以泛化

**MemSkill（新范式）：** Span-level + Skill-conditioned Generation
- 以span/chunk为单位做总结
- 选取Top-K相关memory skills → 一次pass生成记忆更新

---

## 系统架构：Controller → Executor → Designer

### Controller（RL训练的技能选择器）
- 输入：当前text span + 已有记忆
- 动作：从SkillBank选Top-K skills（避免整库塞入干扰）
- 优化：下游任务反馈作为奖励信号（RL训练）

### Executor（LLM）
- 输入：text span + selected skills
- 输出：结构化记忆更新

### Designer（失败驱动的技能进化器）
- 维护failure-driven hard-case buffer
- 定期回看，提炼重复失败模式
- 转化为：skill edits（更清晰触发条件/更严格抽取规则）或new skills
- 两阶段进化：Difficulty Filtering → Cluster → Select Representative → Evolve Skills

## Skill的四部分格式
```
(1) Purpose: 技能目的
(2) When to use: 适用场景
(3) How to apply: 如何应用
(4) Constraints: 约束限制
```

**示例技能：**
- "Capture Temporal" — 捕捉时序信息
- "Handle Entity Relationships" — 提取实体关系
- "Refine Details" — 更新细节
- "Capture Activity" — 捕捉活动事件

## Amy Analysis

**MemSkill和SkillRL（arXiv:2602.08234）是同一时期（2026-02）的互补工作：**
- SkillRL：轨迹→技能蒸馏用于RL训练（action层面）
- MemSkill：对话→记忆技能用于记忆构建（memory层面）

两者共同确认了：**Skill Bank是Agent记忆的正确抽象层次**，而非原始轨迹存储。

**Skill四部分格式（Purpose/When/How/Constraints）是通用格式：**
- 适用于MemSkill的记忆技能
- 也适用于HEARTBEAT.md中每条规则的文档化标准
- 目前HEARTBEAT.md规则多数只有"做什么"，缺少"何时用"和"约束"

**Skill进化闭环**：失败buffer → 聚类 → 提炼 → 技能更新。
这就是我们JOURNAL.md应该实现的功能：记录失败heartbeat → 定期分析模式 → 更新HEARTBEAT.md规则。

**用户评论洞察：** "记忆=动态重建"，对应清欢三圆模型：每次读MEMORY.md不是静态调取，而是根据当前任务重新组合。
