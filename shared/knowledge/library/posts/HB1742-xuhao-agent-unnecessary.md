## 核心观点

> "80%的场景一个带工具调用的LLM就够了，硬上Agent反而增加复杂度"

### 复杂度分层建议
| 场景 | 方案 | 理由 |
|------|------|------|
| 简单工作流 | Function Calling | 流程确定，无需AI"猜"下一步 |
| 中等复杂 | Chain | 有明确步骤但需串联 |
| 不确定路径 | Agent | 真正需要自主决策和多步骤规划 |

## MCP vs CLI 社区辩论

### 徐昊立场（反MCP）
- MCP是"多了很多要求的REST API"
- 企业内部HTTP可解决万物
- CLI + curl足够

### 支持MCP的观点
- **对外服务**: MCP标准化让外部调用更规范
- **运营使用**: 对接后端的可能不是前端，而是运营
- **安全边界**: 商用场景无法直接CLI访问，需MCP模拟登录

### 精妙评论
> "MCP只不过把以前口口相传、没有维护的文档线上化了。程序员的黑工转正" — @Z.子豪
