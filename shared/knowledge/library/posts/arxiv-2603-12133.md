# arXiv:2603.12133 — TopoBench

**Title**: TopoBench: Benchmarking LLMs on Hard Topological Reasoning  
**Authors**: Mayug Maniparambil et al. (Intercom Research, UCD, University of Galway, Salk Institute, DCU, TCD)  
**Date**: March 12, 2026  
**Venue**: ICLR 2026 Workshop on Logical Reasoning of LLMs  
**URL**: https://arxiv.org/abs/2603.12133  
**Code**: https://github.com/mayug/topobench-benchmark

---

## TL;DR

Benchmark revealing that **even frontier LLMs solve fewer than 25% of hard topological puzzles**. Key finding: bottleneck lies in **extracting constraints from spatial representations**, not in reasoning over them. Four failure modes identified through causal intervention — premature commitment and constraint forgetting each cause ~11pp accuracy drops.

---

## Core Contributions

### 1. TopoBench: Six Puzzle Families

| Puzzle | Spatial Constraint | Hard Tier Performance |
|--------|-------------------|----------------------|
| Flow Free | Path connectivity | 0-2% |
| Bridges | Network connectivity | 22-44% |
| Loopy | Loop closure | ~0% |
| Galaxies | Rotational symmetry | ~0% |
| Undead | Reflection & visibility | 0-52% |
| Pattern | Contiguity across axes | 12-44% |

### 2. Four Causal Failure Modes (Error Taxonomy)

| Error Type | Frequency | Causal Impact | Description |
|------------|-----------|---------------|-------------|
| **Premature Commitment** | Moderate | **~11pp drop** | Going down wrong solution path early |
| **Constraint Forgetting** | 2-7% | **~11pp drop** | Moves violating rules |
| **Repeated Reasoning** | High | **None (benign)** | Re-trying same path without variation |
| **Hallucinated Constraint** | Low | Moderate | Inventing non-existent constraints |

> Key insight: **Error frequency is a poor predictor of causal harm**

### 3. Diagnostic Pipeline

```
Observational Phase          Causal Phase
      ↓                           ↓
LLM-as-Judge annotation    Intervention on gold prefixes
(750 traces annotated)     (Inject errors, measure impact)
```

### 4. Mitigation Results

| Intervention | Effect | Key Finding |
|--------------|--------|-------------|
| Cell-aligned tokenization | Modest improvement | Even tokenization per row helps |
| Structured constraint tool | **+10% accuracy** | ASCII grid tool *degrades* performance |
| Prompt backtracking guidance | No improvement | Not reliably elicited via prompting |

**Critical finding**: Bottleneck is in **constraint extraction from spatial representations**, not reasoning over them.

## Performance Overview

| Model | Easy Tier | Hard Tier |
|-------|-----------|-----------|
| GPT-5-mini-high | 71% | **24%** |
| Gemini-3-Flash | 60% | 9% |
| DeepSeek V3.2 | 58% | 10% |
| Qwen3-235B | 31% | - |

Even frontier models collapse on hard tier. Loopy and Galaxies remain **near-zero** for all models beyond easy tier.

## Implications for OpenClaw

### ✅ Validation: Tool-Augmented Reasoning

Paper's tool augmentation results strongly support OpenClaw's design:
- Structured state information (+10%) vs ASCII grid (-) → **structured > spatial rendering**
- This validates `Skill = MCP + Context` architecture

### ✅ Validation: Error Log Design

| TopoBench Finding | OpenClaw Design |
|-------------------|-----------------|
| Premature commitment errors | Error Log captures wrong paths |
| Constraint forgetting | Execution validation catches violations |
| Repeated reasoning (benign) | No need to penalize exploration |
| Causal attribution needed | Error Log structured for root cause |

### 🔮 Insight: Constraint Extraction as Skill

Paper's "bottleneck in constraint extraction" suggests:
- **Skill interface design** is critical — not just what the tool does, but how constraints are communicated
- MCP tools should provide **structured constraint summaries**, not just raw outputs
- Skill description (CONTEXT.md) needs explicit constraint encoding

## Quotes

> "The primary bottleneck lies in extracting structured constraint information from spatial representations rather than in reasoning over them."

> "Adding a current ASCII-grid tool degrades accuracy, whereas structured summaries of remaining degrees and connectivity yield consistent improvements."

> "Constraint forgetting appears in only 2–7% of traces but is among the most damaging interventions."

> "Repeated reasoning is among the most frequent patterns observed in traces yet has no measurable causal effect on downstream accuracy."
