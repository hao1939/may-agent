# HB#1526 — iSWE Agent: Java代码问题解析的双Agent架构

**Source**: arXiv:2603.11356 [cs.SE] (IBM Research) — Direct Paper Tracking

## TL;DR

IBM Research提出的**iSWE Agent**——首个专门针对Java的代码仓库问题自动解决Agent。采用**Localization + Editing双Sub-agent架构**，结合基于规则的Java静态分析工具(CLDK)，在Java版SWE-bench基准上达到SOTA，且成本仅为其他领先Agent的**1/2到1/3**。

---

## Core Finding: Two-Sub-Agent Pipeline

```
Issue Description + Code
    ↓
┌─────────────────────┐
│ Localization Agent  │ ← 只读工具，定位需修改的代码位置
│   (ReAct Agent)     │
└──────────┬──────────┘
           ↓ 结构化Localization输出
┌─────────────────────┐
│   Editing Agent     │ ← 编辑工具，生成修复代码
│   (ReAct Agent)     │
└──────────┬──────────┘
           ↓
    Modified Code
```

**关键设计决策**:
1. **模块化分离**: 两个Sub-agent可独立运行，支持人工介入检查中间结果
2. **类型化中间输出**: Localization结果是结构化、经过清理的(sanitized)数据
3. **任务简化**: 每个子任务比端到端任务更简单，适合中等规模LLM

## Java-Specific Tool Design

### CLDK (Code Language Development Kit)

基于开源程序分析框架CLDK构建的Java专用工具:

| Tool Type | Function | Benefit |
|-----------|----------|---------|
| **Static Analysis** | 代码结构解析、依赖分析 | 精准定位 |
| **Rule-based Transform** | 基于规则的代码转换 | 安全可控 |
| **Type-aware Search** | 利用Java类型系统 | 减少误报 |

**论文观点**: Java与Python差异显著(语法、类型系统、面向对象特性)，需要语言特定的工具支持。

## PDL: Declarative Prompting Language

使用IBM的PDL(Prompt Declaration Language)实现:

```yaml
# PDL示例结构
description: "iSWE Localization Agent"
text:
  - role: system
    content: "You are a code localization expert..."
  - role: user  
    content: "Issue: {{issue_description}}"
  - role: assistant
    content: "Let me analyze the code structure..."
```

**优势**:
- 提示模板易读、易维护
- 上下文累积和数据流由PDL管理
- 类型检查确保数据一致性
- 无需像传统框架那样分散在Python代码中

## Containerization Strategy

**轻量级容器化**:
- 大部分代码在用户空间运行(无容器)
- 仅**编译/构建步骤**在容器中执行
- 减少时间、内存、磁盘开销

| Component | Container | Reason |
|-----------|-----------|--------|
| Main flow | ❌ No | 简单协调逻辑 |
| ReAct loop | ❌ No | 工具调用 |
| Tool functions | ❌ No | 纯分析操作 |
| Java build | ✅ Yes | 避免副作用 |

### Key Validation

1. **Sub-agent分解验证**: OpenClaw的Main/Sub-agent分离与iSWE的Localization/Editing分离遵循相同原则——复杂任务分解为可管理的子任务。

2. **语言特定工具**: iSWE证明领域特定工具(CLDK)比通用代码操作更有效，支持OpenClaw的SKILL.md领域化策略。

3. **声明式配置**: PDL与SKILL.md采用相同的YAML声明式方法，优于分散在代码中的字符串拼接。

4. **成本效率**: 结构化Sub-agent设计可显著降低成本(2-3×)，验证模块化架构的经济价值。

## Design Insights

### Rule-Based + Model-Based Hybrid

> "By combining the best of rule-based and model-based techniques..."

- **Rule-based**: 结构化分析、确定性转换、安全保证
- **Model-based**: 自然语言理解、推理、代码生成

这与OpenClaw的AGENTS.md(规则) + Skill(模型能力)分层一致。

### Intermediate Result Value

Localization的中间结果本身就有价值:
- 开发者可仅使用定位功能，人工完成编辑
- 支持从其他来源(静态扫描工具)获取定位，跳过第一阶段

**启示**: Skill设计应支持"部分执行"模式，提供中间价值。
