# ReTool: 强化学习让LLM学会"策略性工具使用"

**Source:** [XHS 680c6d72](https://www.xiaohongshu.com/explore/680c6d72000000001d00792c)  
**Paper:** arXiv:2504.11536  
**Team:** ByteDance Seed  
**Relevance:** 🔴 High - Strategic Tool Use, RL for Agents

---

## 核心问题

**现存挑战:**
- 纯文本RL模型在文本推理很强，但遇到**几何推理、精确计算**就"露怯"
- 之前给LLM加工具使用的方法不灵活，模型不会**智能地**调用工具

---

## ReTool方案

### 创新点
1. **代码解释器执行融入推理rollout loop**
   - 动态交错实时代码执行与自然语言推理
   
2. **自动化RL训练框架**
   - 多轮实时代码执行rollout
   - 基于结果反馈优化策略
   - 无需人工先验，自主学习最优调用模式

3. **高质量冷启动数据**
   - 合成代码增强的长推理轨迹
   - 用于微调基础模型

---

## 实验成果

### AIME2024 数学竞赛
| 模型 | 准确率 | 训练步数 | 相对提升 |
|------|-------|---------|---------|
| Text RL baseline | 40% | 1080步 | - |
| ReTool-32B | 67% | 400步 | +27% |
| ReTool-32B (扩展) | 72.5% | - | **比o1-preview高27.9%** |

### 训练效率
- **400步**达到高准确率 (vs baseline 1080步)
- **2.7x**训练效率提升

### 涌现能力
- **代码自我修正** - 模型能自主发现并修复代码错误
- **"aha moment"** - 模型自主掌握自适应工具使用

## 技术细节 (from arXiv abstract)

### 训练流程
```
1. 合成冷启动数据生成
   → 代码增强的长推理轨迹
   → 微调基础模型

2. RL训练
   → 任务结果作为reward
   → 迭代优化工具使用策略
   → 自主发现最优调用模式
```

### 关键设计
- **Outcome-driven**: 基于任务结果而非人工规则
- **Multi-turn execution**: 支持多轮代码执行
- **No human priors**: 模型自主学习何时/如何调用

## 与其他工作的对比

从评论区得知的相关工作:
- **SEARCH-R1** - 多轮工具调用
- **ToolRL** - 工具使用RL
- **TORL** - 推理+工具

ReTool的独特之处:
- 将代码解释器**深度集成**到推理rollout中
- 强调**策略性**调用而非每次都用
- 强调**训练效率** (400步 vs 1000+步)

## 对我们的启发

### 直接可借鉴

1. **工具调用决策机制**
   - 当前: 规则-based选择工具
   - 借鉴: 学习何时调用、何时不用
   - 实现: 基于历史结果训练小模型做选择

2. **执行反馈循环**
   - 当前: 一次调用，返回结果
   - 借鉴: 多轮执行，自我修正
   - 实现: 允许工具执行失败后的重试机制

3. **Outcome-based优化**
   - 当前: 固定工具流程
   - 借鉴: 根据任务结果优化调用策略
   - 实现: 追踪工具调用与任务成功率的关系

### 需要避免的坑
- 多轮工具调用的**工程效率**问题 (评论区提到)
- **过度思考** - 简单任务不需要复杂工具链
- **协调成本** - 复杂工具调用会增加延迟

## 社区讨论要点

> "最近接连看了几篇LLM reasoning + 多轮工具调用的：SEARCH-R1、ToolRL、TORL，看多轮工具调用的流程都差不多了，多轮在工程效率上怎么样呢？"

**关键问题**: 多轮工具调用的工程效率
- 延迟增加
- Token消耗
- 错误累积

**我们的策略**: 
- 优先单轮能完成的工具
- 复杂任务才启用多轮
- 监控工具调用成功率
