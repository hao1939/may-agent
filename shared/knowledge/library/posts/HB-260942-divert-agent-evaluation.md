# DIVERT: 多样性引导的Agent高效评估框架

**来源**: arXiv:2604.21480 | 2026-04-23  
**作者**: Itay Nakash, George Kour, Ateret Anaby-Tavor  
**标签**: #agent-evaluation #user-simulation #efficiency #testing

---

## 核心发现

**DIVERT (Diversity-Induced Evaluation via Branching of Trajectories)** 是一个基于快照、覆盖引导的用户模拟框架，用于系统化探索Agent-用户交互。

### 解决的核心问题

当前Agent评估依赖线性Monte Carlo rollout，存在两大痛点：
1. **计算效率低**: 重复生成相同的早期对话前缀
2. **覆盖不足**: 难以发现由罕见用户行为引发的深层失败模式

### 技术架构

```
┌─────────────────────────────────────────────────────────────┐
│                    DIVERT Framework                          │
├─────────────────────────────────────────────────────────────┤
│  1. 快照捕获 (Snapshot Capture)                              │
│     - 在关键决策点捕获完整Agent-环境状态                      │
│     - 支持从这些快照恢复执行                                 │
│                                                              │
│  2. 前缀复用 (Prefix Reuse)                                  │
│     - 重用共享对话前缀，减少冗余计算                          │
│     - 类似测试中的setup复用                                  │
│                                                              │
│  3. 多样性分支 (Diversity Branching)                         │
│     - 从关键节点分支，使用多样性诱导的用户响应                 │
│     - 定向探索替代交互路径                                   │
│                                                              │
│  4. 覆盖引导 (Coverage-Guided)                               │
│     - 聚焦语义多样性和未充分探索的轨迹                        │
│     - 优先测试边缘场景                                       │
└─────────────────────────────────────────────────────────────┘
```

### 关键收益

- **效率提升**: 每token发现更多失败
- **覆盖扩展**: 扩大发现失败的任务范围
- **系统探索**: 从相同前缀系统化探索多种用户行为路径

## 对OpenClaw的意义

### ✅ 可借鉴的实践

1. **快照机制 (Snapshot Mechanism)**
   - 当前: Session状态通过文件系统持久化
   - 升级: 在关键决策点捕获可恢复的快照，支持快速分支测试

2. **前缀复用 (Prefix Reuse)**
   - 当前: 每个Session独立运行，重复执行相同准备步骤
   - 升级: 对于需要相同setup的测试，复用前置状态

3. **多样性测试 (Diversity Testing)**
   - 当前: 依赖人工设计的测试用例
   - 升级: 自动生成多样性用户行为，测试边缘场景

### 🔬 实验方向

| 实验 | 描述 | 预期收益 |
|------|------|----------|
| Session快照 | 在L0/L1/L2边界捕获可恢复状态 | 加速回归测试 |
| 分支测试 | 从相同前置状态探索多种执行路径 | 提高覆盖率 |
| 失败模式挖掘 | 自动生成边缘case用户输入 | 发现深层bug |

### ⚠️ 实施考量

- **存储成本**: 快照需要存储完整上下文状态
- **确定性**: 需要确保快照恢复后的执行确定性
- **状态边界**: 明确哪些状态可以安全快照/恢复
