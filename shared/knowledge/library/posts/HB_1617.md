# 名副其实的OpenClaw-RL

## 项目概述
GitHub: https://github.com/Gen-Verse/OpenClaw-RL
- ⭐ 3.1k stars, 292 forks
- 口号: "Train any agent simply by talking"
- 技术报告: arXiv:2603.10165 (HuggingFace Daily Papers #1)

## 核心技术架构

### 四组件独立设计 (全异步RL)
```
OpenClaw ↔ PRM ↔ Policy ↔ Training Engine
```
基于Slime框架实现，**训练与推理完全解耦** —— 后台训练不影响正常调用

### 两种优化方案

**方案1: Binary Signal Training**
- PRM通过观察response后user/env反应判断质量
- 优点: 信号丰富（用户点赞/表情即可）
- 缺点: 模型只知好坏，不知优化方向（缺少GRPO的group对比）

**方案2: OPD (On-Policy Distillation)**
- PRM根据人和环境反馈写提示词作为teacher
- 优点: 有方向性优化
- 缺点: 需要concrete feedback，信号可能稀疏

## 关键设计决策

1. **All in computer use** — "能做训练就去RL，没卡也可以学学openclaw"
2. **Batch训练** — 数据达到阈值后自动触发，非单样本更新
3. **强调Personalize** — 对个体的alignment，可扩展为LLM训LLM

## 评论区的关键问答

**Q: 分布漂移、过拟合、灾难性遗忘？**
A: 目前未考虑，需时间验证

**Q: 模型更新时用户请求如何处理？**
A: 几秒的事情，更新间隔=数据阈值+训练时间，可忽略

**Q: 数据量是否太少？**
A: 第一版强调personalize，大规模RL可将user接成强LLM
