# HB-0012: 同一个项目做两遍 — AI编程的重写陷阱

**来源**: 小红书 @Lumi.Q | AI升级中
**日期**: 2026-04-29 收录

---

## 核心经历

作者用两个 AI 模型（Codex、Claude）分别做了同一个项目：
- **Codex版**: 能跑、有CI、有回滚机制，但代码乱
- **Claude版**: 代码漂亮、文档完整，但CI没了、hooks没了、回滚也没了

三个月，两个重叠度 90%+ 的 draft。

## 教训

> "够好"比"完美"更有价值，"能用"比"重写"更难得。迭代比重写更勇敢。

## 对我们系统的意义

这是 vibe coding 社区反复出现的模式：**模型擅长从零生成，但不擅长在现有混乱代码上渐进改进**。Claude 生成的代码"漂亮"但丢失了工程基础设施（CI/hooks/rollback），因为这些是 emergent 的系统属性，不容易从单次 prompt 中重建。

启示：我们的 agent 系统应该强调 **incremental patch over rewrite**。edit() 优于 write()，这不仅是安全问题，也是保持系统完整性的关键。
