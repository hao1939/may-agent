## 正文
📋 操作流程摘要
1️⃣ 步骤一：标准配置——启用飞书轮询模式
编辑 OpenClaw 核心配置文件 openclaw.json。
定位至 channels -> feishu 配置块。
显式增加或修改配置项 "mode": "polling"。
注：此操作确保网关以主动拉取的方式与飞书服务端交互。

2️⃣ 步骤二：热修复——修改运行时健康检查间隔常量
由于当前版本健康检查机制存在硬编码缺陷，需手动修改编译后的 JavaScript 运行时产物。

定位目标文件：使用 rg 或 grep 命令在安装目录中检索常量定义：
rg HEALTH_REFRESH_INTERVAL_MS node_modules/openclaw/dist/gateway-cli-*.js
（通常定位于类似 dist/gateway-cli-BSPSAjqx.js 的文件中）

修改常量值：编辑检索到的 JS 文件，找到 HEALTH_REFRESH_INTERVAL_MS 常量。
将默认值 6e4 (即 60000ms, 1分钟) 修改为业务期望的间隔值。
示例（修改为24小时）：
const HEALTH_REFRESH_INTERVAL_MS = 86400000; // 24 * 60 * 60 * 1000 ms

3️⃣ 步骤三：应用变更——重启网关服务
执行标准重启命令，使配置文件修改及运行时的补丁生效：
openclaw gateway restart
验证服务启动日志确保无异常。

⚠ 关键注意事项 (Critical Note)
步骤二中的修改属于非标准化的运行时热修复 (Hotfix)。

在 OpenClaw 官方发布正式补丁修复此缺陷之前，请务必注意：
每次对 OpenClaw 进行版本升级操作后，dist/ 目录下的编译产物将会被新版本覆盖。因此，必须重新执行步骤二中的常量修改操作。

建议将此步骤纳入自动化部署脚本或升级检查清单中。

## 关键引用
- Config file: openclaw.json → channels → feishu → mode: "polling"
- Target: HEALTH_REFRESH_INTERVAL_MS in node_modules/openclaw/dist/gateway-cli-*.js
- Default: 6e4 (60000ms = 1 minute)
- Suggested: 86400000 (24 hours)
- Command: openclaw gateway restart

**问题诊断：**
- OpenClaw的飞书健康检查机制有硬编码缺陷
- 默认每分钟检查一次 (HEALTH_REFRESH_INTERVAL_MS = 6e4)
- 过于频繁的健康检查触发飞书API限流

**解决方案：**
1. 启用polling模式 (`"mode": "polling"`)
2. 修改编译后的JS文件，将检查间隔改为24小时
3. 重启网关

**关键警告：**
> "每次版本升级后，dist/目录会被覆盖，必须重新修改"
