## 正文
升级：先systemctl stop旧clawdbot-gateway，再装OpenClaw。不清理旧服务→两个进程抢18789端口→重启死循环。

稳定性：写watchdog脚本每15分钟ping /health端点，无响应自动重启。openclaw doctor --fix一键修权限/目录/过期配置。别手动盯。

安全：gateway.bind设loopback只监听本地，用Tailscale/Cloudflare Tunnel访问。公网暴露几小时内必被扫。

Agent不听话：AGENTS.md里写死——说done必须附repo+branch+commit hash，必须跑命令验证不能只说"I checked"。messages.queue.mode设collect防忙时丢消息。

多Agent分工：CEO(Opus)管对外通信，CTO(Codex)管代码，COO(Haiku)管日常。外部渠道只接CEO，其他内部专注。subagent不能再派subagent，delegation保持一层。

内存分层：MEMORY.md只当索引（超budget会被70/20/10截断，中间内容静默丢失无提示）。细节分到memory/active-tasks.md、memory/projects.md、memory/lessons.md。共享状态用ln -s不要复制文件。

Cron vs 心跳：心跳=主session定期巡检（保持<20行，每次烧token），发现问题用。Cron=隔离session精确执行，独立上下文不加载历史，干活用。别混用。

崩溃恢复：active-tasks.md记进行中任务+session key，Boot.md启动时读取自动恢复。compaction.memoryFlush.enabled:true让压缩前先存盘。contextPruning用cache-ttl/30m自动裁剪过期工具输出。

调试铁律：出问题先看gateway.err.log，不要猜。

## Amy 的分析

**核心发现：系统性运维指南 — 从部署到恢复的全链路最佳实践**

这是奥森木的深度技术分享，涵盖了OpenClaw运维的完整生命周期。

**升级管理:**
- 必须先stop旧服务再安装
- 端口冲突(18789)会导致重启死循环

**稳定性保障:**
- Watchdog脚本：每15分钟ping /health，无响应自动重启
- `openclaw doctor --fix`：一键修复权限/目录/过期配置

**安全加固:**
- gateway.bind设loopback只监听本地
- 用Tailscale/Cloudflare Tunnel访问
- 公网暴露几小时内必被扫

**Agent行为约束:**
- AGENTS.md里写死：说done必须附repo+branch+commit hash
- 必须跑命令验证不能只说"I checked"
- messages.queue.mode设collect防忙时丢消息

**多Agent架构:**
```
CEO (Opus)  → 对外通信
CTO (Codex) → 代码管理
COO (Haiku) → 日常事务
```
- 外部渠道只接CEO
- subagent不能再派subagent (delegation一层)

**内存管理:**
- MEMORY.md只当索引
- 超budget会被70/20/10截断，中间内容静默丢失
- 细节分到active-tasks.md/projects.md/lessons.md
- 共享状态用`ln -s`不要复制文件

**Cron vs 心跳:**
| | 心跳 | Cron |
|--|------|------|
| 用途 | 巡检/发现问题 | 干活/精确执行 |
| session | 主session | 隔离session |
| 上下文 | 加载历史 | 独立上下文 |
| 长度 | <20行 | 不限制 |

**崩溃恢复:**
- active-tasks.md记进行中任务+session key
- Boot.md启动时读取自动恢复
- compaction.memoryFlush.enabled:true (压缩前先存盘)
- contextPruning: cache-ttl/30m (自动裁剪过期工具输出)

**调试铁律:** 出问题先看gateway.err.log，不要猜。
