# HB#512 — AI Agent越多越强？Google 180组实验的定量结论

**Source**: XHS@硅谷工程札记 / Google Research Blog | **Date**: 2026-03-15  
**Original**: https://www.xiaohongshu.com/explore/69b5b49f00000000230253d5  
**Paper**: arXiv:2512.08296 "Towards a Science of Scaling Agent Systems"

## 核心颠覆性发现

> "很多人以为 AI Agent 越多越强，但一篇最新论文做了 180 组实验，发现情况恰恰相反。"

### 定量实验结果

| 任务类型 | 多Agent效果 | 幅度 |
|---------|------------|------|
| **并行任务** (Finance-Agent) | 显著提升 | **+80.9%** |
| **顺序任务** (PlanCraft) | 严重退化 | **-39% ~ -70%** |

### 错误放大效应

| 架构 | 错误放大倍数 |
|------|------------|
| Independent多Agent | **17.2x** |
| Centralized (orchestrator) | **4.4x** |

> Independent架构无协调机制，错误级联 unchecked；Centralized架构的orchestrator作为"validation bottleneck"拦截错误。

### 预测模型

- **R² = 0.513** — 基于任务可分解性、工具数量等属性
- **87%准确率** — 预测未见任务的最优架构

## 架构趋势

> "随着模型能力提升，越来越多系统开始回到一种结构：**单Agent + 工具 + runtime**"

## 五种被测架构

1. **SAS** (Single-Agent System) — 统一记忆流的顺序执行
2. **Independent** — 并行子任务，最终聚合结果
3. **Centralized** — hub-and-spoke，中心编排器委派任务
4. **Decentralized** — P2P mesh，agent直接通信
5. **Hybrid** — 层级监督 + P2P协调

## 对OpenClaw的验证

| Google发现 | OpenClaw设计 | 验证度 |
|-----------|-------------|--------|
| Centralized > Independent | Main Agent + 受控Sub-agent | ✅ 完全一致 |
| 任务可并行性决定架构 | L3 Flag #1135 (任务可并行性判据) | ✅ 先见之明 |
| Orchestrator作为validation bottleneck | Skill-Vetter安全层 | ✅ 理念一致 |
| 顺序任务避免多Agent | L1层默认单Agent | ✅ 正确决策 |

## 关键洞察

**"真正重要的不是 Agent 数量，而是 Agent runtime 的设计。"**

### 工程指导原则

1. **可并行性测试**: 任务是否能分解为独立子任务？
2. **错误预算**: 任务对错误传播容忍度？
3. **协调成本**: 通信开销 vs 并行收益

## L3 Flag建议更新

基于本研究，L3 Flag #1135应细化为：
- **Main Agent自执行条件**: 顺序依赖任务、错误敏感任务
- **Sub-agent委派条件**: 可并行子任务、工具密集型任务
