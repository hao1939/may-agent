# 1 任务方向

可扩展长期记忆的对话智能体。目标是突破 LLM 固定上下文限制，在多会话、长时程对话中维持一致性与个性化；论文提出 Mem0（稠密自然语言记忆）与 Mem0g（图记忆）两种体系，并在 LOCOMO 长对话基准上系统评估。站在当前时间点，长期记忆是对话式代理落地的"系统能力"已经不言自明，通常与模型参数外化存储，如向量库、图数据库结合等等。

# 2 基线方法

全上下文：把整段会话（比如 200k tokens）直接交给 LLM，完整度（J）最高但 p95 延迟 17s，成本与时延不可扩展。

RAG：将对话分块 chunking（128–8192 tokens），以 text-embedding-small-3 向量化，检索 top-k（k = 1，2）拼接作上下文；稳定但有噪声冗余。

3 本文创新

Mem0 是一个两阶段可组合管线 pipeline，具体分为抽取和更新阶段。

抽取（extraction）：对每个消息对

$(m_{t-1}, m_t)$

构造提示 P

关键信息（三）

P = (S, {m_{t-m}, ..., m_{t-2}}, m_{t-1}, m_t)

其中 S 为异步维护的会话摘要，不阻塞主链路；有专门的 LLM 基于 P 抽取候选事实集合

Ω = {ω_i}

更新（update）：为每条事实 ω 先检索 top-s 个相似记忆，再通过 function-calling（文中其实已经是 tool call 的思想）让 LLM 直接判定四类操作：ADD / UPDATE / DELETE / NOOP；系统随后执行以保证一致性与去冗余。实验设 **m = 10, s = 10**。如下图。

关键信息（四）

其相当于提出形式化算法，ClassifyOperation(f, M) 以"语义相似 / 矛盾 / 增补"三种判据划分操作，即增删改；UPDATE 仅在 InformationContent (f) 更高时替换旧记忆，即替换。

> 实际上，语义判别可以借助对比蕴含、矛盾提示，等价于在嵌入空间上学习到的非线性决策边界。

Mem0g，直接构建图结构来存储过去上下文的信息，属于显式关系与时序的一阶图表征。

**图的定义：** 有向标注图 G = (V, E, L)；节点含类型、嵌入与时间戳，边为三元组（源实体，关系标签 / 有向边谓词，目标实体）；三元组编码常用"关系文本化 + 向量检索"，与知识图谱中的 path-based reasoning 相衔接。

**两段抽取：** 先实体抽取与类型判定，再关系生成为三元组集合；更新时，以**相似度阈值 t 合并**节点以降低度，并对**冲突关系做"失效标记"**，以保留时间推理（当遇到时序冲突）。

# 关键信息（五）

**双路检索：** 实体中心的邻域扩张 + 三元组语义匹配并行，提高召回与相关性。**实现采用 Neo4j**；抽取 / 更新均用 GPT-4o-mini function calling，同理。

[图：Extraction Phase → Relations Generator (LLM) + Entity Extractor (LLM) → triplets/nodes → Update Phase: Conflict Detector → Search existing nodes → Update Resolver (LLM) → Update graph → Graph Memories]

**实际效果**：相比最强 RAG，Mem0 / Mem0g 的 **Overall-J 明显更高**；对比全上下文，p95 总延迟分别约 **1.44s / 2.6s** vs 大约 17s，成本优势显著。 实际部署中可将"检索延迟 / 生成延迟"拆分观测，以指导索引结构与批处理调优。

**分类型表现：** 单跳 Mem0 最强；时间推理 Mem0g 受益于显式关系与时序；多跳 Mem0 优于 Mem0g。

评测同时跟踪 Token 注入量、检索与端到端延迟，并采用 **LLM-as-a-Judge（J）** 多次打分。

[Slide 8]
知识点！

**RAG（Retrieval-Augmented Generation）**：把外部文档分块向量化，以相似度检索若干块拼接进提示再生成答案；优点是覆盖面广，缺点是容易把无关文本一起带入。

**稠密记忆**：把新消息在"摘要＋近邻窗口"背景下蒸馏成短小的事实条目，并用 LLM 决定增删改操作，保持一致且去冗余。

**图记忆**：把会话信息转成"实体-关系-实体"的三元组，存入图数据库；既能顺着实体邻域追问，也能对三元组做语义匹配，适于**时间与关系推理**。

**LLM-as-a-Judge（J）**：用更强的 LLM 对答案在事实性、相关性、完整性等维度打分，多次运行取均值 ± 方差，弥补 F1 / BLEU 的词面词频偏好。

**p95 延迟**：第 95 百分位的响应时间，更能反映"最慢的一批请求"（最难的一些问题）的体验。LOCOMO 数据集每段对话约有 200 个问题，系统对每个问题先做记忆检索再生成答案；论文汇报了这些问题的**耗时的有序分布**，取第 95 百分位作为 p95。
