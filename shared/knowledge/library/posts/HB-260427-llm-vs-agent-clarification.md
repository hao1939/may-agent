### 核心论点

**LLM ≠ Agent**:
- **LLM**: 语言模型，能力是理解和生成文本
- **Agent**: 智能体，具备感知、决策、行动能力的系统
- 关键区别：是否有**环境交互能力**和**自主决策循环**

**混淆的危害**:
- 用户期望错位：以为有Agent能力，实际只是聊天
- 技术讨论失焦：概念模糊导致方案不匹配
- 产品定位混乱：开发者不清楚该用什么架构

**正确定义**:
- Agent = LLM + 工具调用 + 记忆 + 规划 + 环境反馈循环
- 单纯调用API的LLM wrapper ≠ Agent
- 有system prompt的LLM ≠ Agent

## 对OpenClaw的意义

### ✅ 概念验证

**OpenClaw是Agent吗？** —— 是。
- ✅ 工具调用（bash/read/edit）
- ✅ 环境感知（文件系统、代码库）
- ✅ 规划能力（L0意图分解）
- ✅ 反馈循环（执行→观察→调整）
- ✅ 记忆系统（session历史、insights）

### 🔬 产品定位

**精确描述**:
- 不是"AI编程工具"（太泛）
- 不是"Claude Code替代品"（对标竞争）
- 而是"面向开发者的自主Agent框架"（精确定位）

**市场教育**:
- 帮助用户理解Agent vs LLM的区别
- 强调自主决策循环的价值
- 区分一次性的代码生成 vs 持续的任务执行

### ⚠️ 术语风险

**Agent一词的贬值**:
- 市场上"Agent"概念被滥用
- 可能需要更精确的描述（如"自主开发者助手"）
- 用能力和行为定义，而非标签
