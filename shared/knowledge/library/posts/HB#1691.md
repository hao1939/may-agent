## 核心发现 🔥

### 发现1: 幸运猜测问题 (The Lucky Guess Problem)

传统基准只评估最终答案，导致**正确但推理完全错误**的情况得满分。

**案例** (Figure 1):
- 问题: "三个Xbox主机哪个最小？"
- 模型回答: C (中间那个) ✅
- 模型推理: "中间主机比其他更大" (自相矛盾!)
- 传统评分: **100% Accuracy**
- CRYSTAL Match F1: **0.15** (暴露 flawed reasoning)

> "Without observing intermediate steps, shortcuts become indistinguishable from genuine understanding"

### 发现2: 普遍存在的摘樱桃行为 (Universal Cherry-Picking)

**20个MLLM评估发现**:
- 所有模型呈现 **Precision >> Recall** (高精确率低召回)
- 模型选择性输出容易验证的步骤，跳过关键推理
- 即使商用前沿系统也未能幸免

### 发现3: 推理顺序混乱 (Disordered Reasoning)

**惊人发现**: 没有竞争性模型能保持超过 **60%** 的匹配步骤在正确顺序中。

- 模型能生成正确步骤，但逻辑顺序混乱
- 说明缺乏真正的因果推理能力

## 创新评估指标

### Match F1 — 步骤级语义匹配
```
Precision = 匹配步骤数 / 预测步骤数
Recall = 匹配步骤数 / 参考步骤数
F1 = Harmonic Mean(Precision, Recall)
```
- 使用 all-distilroberta-v1 编码语义相似度
- 阈值 τ = 0.35

### Ordered Match F1 — 惩罚无序推理
```
Ordered-F1 = F1 × ((1-α) + α × LIS-ratio)
```
- LIS-ratio: 最长递增子序列比率
- α = 0.3 (顺序惩罚权重)

## 因果过程奖励 (Causal Process Reward)

### 传统加性奖励的问题
```
R = wf·Rfmt + wa·Racc + wr·Rreason  ← 允许通过猜测最大化奖励
```

### CPR乘法耦合机制 🔥
```
RCPR = {
  aw + sw·F1step    if answer correct  ← 正确+好推理 = 全额奖励
  sw·F1step·λ       otherwise          ← 错误答案大幅惩罚 (λ=0.3)
}
```

**关键洞察**: 只有答案正确**且**推理步骤对齐时，才能获得完整奖励。阻止了"正确猜测+跳过推理"的捷径。

### CPR-Curriculum训练策略
| 阶段 | 策略 | 目的 |
|------|------|------|
| Phase 1 | 仅格式+准确度奖励 | 建立稳定答案生成基础 |
| Phase 2 | 完整CPR奖励 + 渐进难度 | 从简单推理链→复杂多跳推理 |

**实验结果**: CPR-Curriculum通过GRPO实现 **+32% Match F1** 提升，加性奖励策略完全失败。

## 多Agent参考生成流程 (Delphi-inspired)

**Phase 1: 独立生成**
- 4个不同架构家族MLLM独立生成推理步骤
- Qwen2.5-VL-72B / InternVL3-76B / Gemma3-27B / Llama-4-Maverick

**Phase 2: 语义聚类**
- 句子编码 + 余弦相似度 ≥ τ 形成连通分量
- 每个聚类选择代表性步骤 (最小平均相异度)

**Phase 3: 自动验证**
- 第5个MLLM (Molmo-72B) 验证逻辑合理性、视觉基础、答案一致性

**Phase 4: 人工质量门**
- 训练有素的标注员验证感知声称、逻辑过渡
- <5%需要重新迭代
