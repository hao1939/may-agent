## TL;DR

**颠覆性发现：模型规模≠可靠性**。论文提出"语义不变性(Semantic Invariance)"评估框架，通过8种语义保留变换测试LLM Agent的推理稳定性。惊人发现：**Qwen3-30B小模型达到79.6%不变性率，而大模型表现出更大脆弱性**。这对OpenClaw的确定性保证设计有直接指导意义。

---

## 核心概念：语义不变性

**定义 (Definition 3.1)**: Agent在语义等价输入变化下产生一致输出的性质。

> "A physics problem should yield the same solution whether phrased in formal academic language or practical business terminology"

### 8种变换变体测试 (Metamorphic Relations)

| 类别 | 变换 | 描述 |
|------|------|------|
| **Structural** | Identity | 原始问题（基线） |
| | Paraphrase | 同义改写，保留语义 |
| | Reorder Facts | 事实顺序重排 |
| **Verbosity** | Expand | 增加澄清上下文 |
| | Contract | 去除冗余，保留核心 |
| **Contextual** | Academic Context | 学术场景重构 |
| | Business Context | 商业场景重构 |
| **Stress Test** | Contrastive | 增加对比情境（负控制） |

## 核心发现

### 🔥 Finding 1: 规模-鲁棒性倒置 (Scale-Robustness Inversion)

| 模型 | 参数 | MAD↓ | 稳定性↑ | 语义相似度 |
|------|------|------|---------|-----------|
| Qwen3-30B-A3B | 30B (3B active) | **0.049** | **79.6%** | **0.914** |
| Qwen3-235B-A22B | 235B (22B active) | 0.072 | 69.7% | 0.891 |
| Hermes-4-70B | 70B | 0.086 | 50.7% | 0.832 |
| Hermes-4-405B | 405B | 0.109 | 67.1% | 0.878 |
| DeepSeek-R1 | 70B | 0.107 | 67.1% | 0.783 |
| gpt-oss-20b | 20B | 0.211 | 27.0% | 0.527 |
| gpt-oss-120b | 120B | 0.143 | 64.5% | 0.772 |

**关键洞察**: 
- **Qwen3-30B-A3B (小模型) 达到最高稳定性** — 79.6%不变性率
- gpt-oss-120b (6倍参数量) 稳定性反而更低
- "Models which look better on standard benchmarks are often less reliable"

### 🔥 Finding 2: 模型家族脆弱性签名

| 家族 | 脆弱性模式 | 关键数据 |
|------|-----------|---------|
| **Hermes** | Contrastive脆弱 | Δ=-0.126 (70B), Δ=-0.208 (405B) |
| **Qwen3** | 最均衡的鲁棒性轮廓 | 所有MRs平均\|Δ\|<0.05 |
| **DeepSeek-R1** | 结构变换敏感 | reorder_facts: Δ=-0.171 |
| **gpt-oss** | 灾难性不稳定 | contrastive: Δ=-0.449, reorder_facts: Δ=-0.270 |

### 🔥 Finding 3: 通用对比脆弱性 (Universal Contrastive Fragility)

**所有模型家族**在Contrastive变换下表现退化：
- gpt-oss-120b: 分数退化高达-0.449
- 不仅是均值退化，方差显著增加
- 引入不可预测的失败模式

### 🔥 Finding 4: 扩展不对称性

- **Qwen3**: verbosity扩展轻微改善推理（正向异常值）
- **gpt-oss/DeepSeek**: verbosity扩展显著退化
- 解释：额外上下文在某些架构中有助于推理，但在其他架构中会压倒注意力机制

## 评估方法论

### 多层评估框架

```
Solution-Level (解决方案级)
├── Semantic Similarity Score: cos(e_s, e_s*)
└── Score Delta: Δ_τ(p) = Score(M(τ(p)), s*) - Score(M(p), s*)

Step-Level (步骤级)
└── StepScore: 每步推理与参考答案的语义相似度

Trace-Level (轨迹级)
└── TraceSim: 变换前后推理轨迹的语义相似度

Aggregate (聚合)
├── MAD (Mean Absolute Delta): 平均变化幅度
└── Stability Rate: \|Δ\|<0.05的比例
```

### ✅ 架构验证

|---------|-----------------|---------|

| Context framing影响推理 | AGENTS.md结构化Context工程 | ✅ 一致 |
| 小模型可更可靠 | Skill级别选择小模型策略 | ✅ 支持 |

### 🔴 新风险识别

**Contrastive Fragility**: 当问题中包含对比情境或干扰信息时，所有模型都表现出退化。

- **对OpenClaw的启示**: Main Agent在组装Context时需特别注意：
  - 避免在单个prompt中放入过多对比信息
  - Sub-agent输出应结构化分离，而非混合呈现
  - `read_by`分层访问控制可减少不必要的情境干扰

### 🎯 实践建议

1. **模型选择**: 对于需要高可靠性的Skill，优先选择经过稳定性测试的模型，而非纯性能最高的模型
2. **Prompt工程**: 使用Contract变换测试Skill的鲁棒性 — 去除冗余后是否仍一致
3. **评估框架**: 引入Metamorphic Testing作为Skill验证的一部分
