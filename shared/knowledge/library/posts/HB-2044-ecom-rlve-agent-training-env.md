# Ecom-RLVE: 电商对话Agent的自适应可验证训练环境

## 核心概念

将RLVE框架从单轮推理谜题扩展到**多轮、工具增强的电商对话**。

**关键洞察**: 流畅对话 ≠ 任务完成。客户需要能调用正确目录搜索、过滤硬约束、避免幻觉产品ID、处理库存缺货后续问题的Agent。

## 八大训练环境

| 环境 | Agent必须完成的任务 |
|------|-------------------|
| 产品发现 | 找到满足所有用户约束的产品 |
| 替代推荐 | 商品缺货时找到相似兼容替代品 |
| 购物车构建 | 添加用户要求的精确产品、变体和数量 |
| 退货+换货 | 识别正确订单行，发起退货，建议替代品 |
| 订单追踪 | 解析用户指代的订单并报告状态 |
| 策略问答 | 回答关于商店政策的确定性问题 |
|  bundle规划 | 在预算内推荐完整购物清单 |
| 多意图旅程 | 处理串联2-5个上述任务的对话 |

## 奖励信号设计

所有环境使用统一的三部分奖励：

### 1. 任务奖励
- 是否实际完成目标？(正确产品推荐？购物车正确？追踪到正确订单？)

### 2. 效率奖励
- 是否在没有浪费轮次的情况下完成？
- 用户引起的轮次(追问、确认)不计入惩罚
- 仅Agent错误引起的轮次计为浪费

### 3. 幻觉惩罚
- 是否仅推荐实际检索到的产品？
- 推荐从未查找过的产品ID会被惩罚

**无效输出**(畸形JSON、非法工具调用)触发立即失败分数。

## 自适应难度课程

单一难度数字 `d` 同时控制12个独立维度：

| 维度 | d=0(简单) | d=6(中等) | d=12(困难) |
|------|----------|----------|-----------|
| 用户约束数量 | 2 | 5 | 8 |
| 用户遗漏约束频率 | 5% | 70% | ~80% |
| 搜索结果中干扰项比例 | 0% | 12% | 24% |
| 对话中商品缺货频率 | 0% | 30% | 50% |

其他8个维度：轮次预算、输入噪声(拼写错误/俚语)、上下文切换、检索深度、订单历史大小、策略复杂度、工具预算。

**自适应调度**: 每个环境独立跟踪Agent成功率，仅在Agent可靠通过当前级别后才提升到更难问题。保持训练在Agent能力前沿。

## 购物车构建深入分析

**成功需要5个独立技能**：
1. 产品发现 - 用格式良好的查询搜索目录
2. 变体选择 - 识别正确颜色/尺寸/连接器类型
3. 购物车管理 - 按确切变体和数量添加
4. 澄清对话 - 请求模糊时向用户追问
5. 多商品订单 - 单个对话处理多个不同产品

**工具集**：catalog_search, catalog_get_variants, cart_add, cart_view, user_get_visit_history, ask_user

**难度扩展示例**:
- d=0: 1件商品，无变体
- d=6: 3件商品，93%需要特定变体，50%需要数量>1

## 用户模拟器设计

使用Qwen3.5(9.7B)生成自然、多样的用户消息。

**关键设计选择**：
1. **偏好与声明约束匹配**: 每个模拟用户有隐藏偏好集(价格敏感度、品牌忠诚度、配送速度)，故意偏向用户沟通的任何约束
2. **策略性遗漏**: LLM故意从开场消息中遗漏一些约束，迫使Agent提出澄清问题

## 环境扩层次

```
C1 ⊂ C2 ⊂ C4 ⊂ C8
```

| 集合 | 环境 | 训练技能 |
|------|------|---------|
| C1 | 购物车 | 搜索查询构建、购物车操作 |
| C2 | +替代推荐 | 约束下的相似性推理 |
| C4 | +产品发现、退货 | 交易工作流 |
| C8 | +状态、策略、bundle、旅程 | 知识检索、规划、组合性 |

假设: C8 Agent在专家自己的任务上也优于单环境专家(与RLVE发现一致)。

## 初步实验结果

**配置**:
- 基础模型: Qwen 3 8B
- 算法: DAPO (G=8 rollouts/prompt)
- 学习率: 1e-5
- 目录: 200万产品，FAISS索引(Alibaba-NLP/gte-modernbert-base)
- 用户模拟: Qwen3.5 9.7B
- 训练: 300 steps

**观察**: 难度达成度逐步增长，自适应调度产生稳定学习信号。

## 案例对比: 简单vs困难

### d=1 (1件商品，无变体)
- 用户: "购物清单: SonicWave Keypad。请添加所有东西。"
- Turn 1: user.get_visit_history() → 4结果，立即发现目标
- Turn 2: cart.add → 购物车匹配
- 奖励: r_task=+1.00, r_eff=+0.33, r_total=+0.80 ✅

### d=8 (3件商品，变体+拼写错误)
- 用户: "pls add...Eco-Frienly HrenLefa Charger...AqaPure Air Fryer...PixelVault Tank Top (3)" [含拼写错误]
- 错误级联: 
  - 选错充电器变体(100W✓ vs 120W✗)
  - 空气炸锅选Bamboo而非Charcoal
  - 坦克背心选XL而非XS(用户两次纠正仍未修复)
  - 最终幻觉称Charcoal变体不存在
- 奖励: r_task≈0.00, r_eff=-0.43, r_total=-0.06 ❌

这正是自适应训练应教会Agent恢复的**多步骤错误级联**。

## 对我们系统的意义

1. **可验证奖励**: 算法验证vs LLM-as-judge的设计选择对我们的Agent评估有参考价值
2. **自适应课程**: 12轴难度+自适应调度机制可直接应用于我们的Agent训练
3. **幻觉检测**: 验证推荐内容是否实际检索到的机制
4. **环境分层**: C1→C8的渐进式技能构建思路
5. **用户模拟**: 策略性遗漏+偏好匹配的用户模拟器设计
6. **效率奖励**: 区分用户引起和Agent错误引起的轮次浪费的精细化奖励设计
