## 核心发现

### VMAO框架：Plan-Execute-Verify-Replan

四阶段迭代循环：
1. **Plan**: QueryPlanner将复杂查询分解为DAG（有向无环图）子问题
2. **Execute**: DAGExecutor依赖感知并行执行（最大并发k=3）
3. **Verify**: ResultVerifier评估完整性（complete/partial/incomplete）
4. **Replan**: AdaptiveReplanner自适应重规划（retry/introduce new/merge）

### 三层Agent架构（完全映射OpenClaw）

| Tier | Agent类型 | 功能 | OpenClaw映射 |
|------|-----------|------|--------------|
| **Tier 1** | Data Gathering | RAG/Web Search/Financial/Competitor | **Skill** (工具层) |
| **Tier 2** | Analysis | Analysis/Reasoning/Raw Data | **Sub-agent** (分析层) |
| **Tier 3** | Output | Document/Visualization | **Main Agent** (合成层) |

### 关键技术细节

**DAG执行算法** (Algorithm 1):
```
ready = {q ∈ Q: deps(q) ⊆ completed ∧ q ∉ completed}
batch = top-k(ready, by=priority)
results = parallel_execute(batch)
```

**子问题结构** (Table 1):
- `id`: 唯一标识
- `question`: 具体问题文本
- `agent_type`: 分配的Agent类型
- `dependencies`: 依赖的其他子问题ID
- `priority`: 执行优先级(1-10)
- `context_from_deps`: 是否包含依赖结果作为上下文
- `verification_criteria`: 完整性验证标准

**停止条件** (Table 2):
| 条件 | 阈值 | 说明 |
|------|------|------|
| Ready for Synthesis | 80% complete | 足够子问题已回答 |
| High Confidence | 75% conf, 50% complete | 高置信度部分覆盖 |
| Diminishing Returns | <5% improvement | 收益递减 |
| Token Budget | 1M tokens | 硬成本限制 |
| Max Iterations | 3 iterations | 硬迭代限制 |

### 生产级安全机制

- **Tool Call Limiter**: 最大10次连续同工具调用，每Agent 50次总数
- **Timeout**: 默认600秒执行上限
- **Token Tracking**: 阶段级预算执行
- **Graceful Degradation**: Sonnet 4.5 → Haiku 4.5  fallback
- **MCP集成**: 8个MCP服务器，42个独立工具

### 实验结果

| 方法 | 完整性 | 来源质量 | 平均Token | 平均时间 |
|------|--------|----------|-----------|----------|
| Single-Agent | 3.1 | 2.6 | 100K | 165s |
| Static Pipeline | 3.5 | 3.2 | 350K | 420s |
| **VMAO** | **4.2** (+35%) | **4.1** (+58%) | 850K | 900s |

**关键发现**:
- 战略评估类查询收益最大 (+53% 完整性)
- 性能分析类查询收益较小（数据源明确）
- 执行阶段占Token 61%，验证和合成保持高效

## 关键洞察

1. **"验证最有价值的场景"**: 开放型、多维度查询（初始分解必然遗漏相关方面）
   - → 直接支持OpenClaw的AGENTS.md设计：显式规范优于隐式能力

2. **"大多数重规划是retry而非新查询"**: Agent执行方差（工具失败、搜索结果不足）是缺口主因
   - → 验证Error Log机制的价值：记录失败模式比重新规划更重要

3. **"LLM-based verifier作为编排级协调信号"**: 与Agent实现解耦的独立质量信号
   - → 与DCI审议框架(HB#1499)形成交叉验证：独立评估者角色至关重要

4. **Token成本8.5×的警示**: 850K vs 100K，生产环境需权衡
   - → 支持AGENTS.md "严格预算控制"设计原则
