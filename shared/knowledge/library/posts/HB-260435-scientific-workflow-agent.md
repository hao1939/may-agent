## 核心问题

科学工作流系统自动执行（调度、容错、资源管理），但**不自动化前置的语义转换**——科学家仍需手动将研究问题转换为工作流规范，这需要领域知识+基础设施专业知识的双重能力。

---

## 三层Agent架构

提出将LLM非确定性限制在意图提取的架构设计：

```
┌─────────────────────────────────────────────────────────┐
│  自然语言研究问题                                        │
└──────────────────┬──────────────────────────────────────┘
                   ▼
┌─────────────────────────────────────────────────────────┐
│  LAYER 1: 语义层 (Semantic)                              │
│  LLM解释 → 结构化意图 (Intent)                           │
│  ★ 唯一允许非确定性的层                                   │
└──────────────────┬──────────────────────────────────────┘
                   ▼
┌─────────────────────────────────────────────────────────┐
│  LAYER 2: 确定性层 (Deterministic)                       │
│  验证生成器 → 可复现工作流DAG                              │
│  ★ 相同意图 → 相同工作流 (确定性保证)                      │
└──────────────────┬──────────────────────────────────────┘
                   ▼
┌─────────────────────────────────────────────────────────┐
│  LAYER 3: 知识层 (Knowledge)                             │
│  Skills: Markdown文档                                    │
│  - 词汇映射                                              │
│  - 参数约束                                              │
│  - 优化策略                                              │
└─────────────────────────────────────────────────────────┘
```

### 关键设计原则

> **"将LLM非确定性限制在意图提取——相同意图总是产生相同工作流"**

---

## Skills设计

**Skills是领域专家编写的Markdown文档**，编码：

- **Vocabulary mappings**: 领域术语到工作流参数的映射
- **Parameter constraints**: 参数有效性约束
- **Optimization strategies**: 执行优化策略

### Skills效果 (消融实验/150查询)

| 指标 | 无Skills | 有Skills | 提升 |
|------|----------|----------|------|
| 完全匹配意图准确率 | 44% | **83%** | +39pp |
| 数据传输(延迟生成) | 基线 | **-92%** | 显著降低 |

## 性能评估

**端到端流水线** (Kubernetes上的Hyperflow WMS):
- LLM开销: **<15秒/查询**
- 成本: **<$0.001/查询**
- 工作流: 1000 Genomes群体遗传学工作流

---

## 核心洞察

1. **确定性层是关键**: 意图→工作流的映射必须可复现，这是科学严谨性的基础
2. **Skills是可扩展性的关键**: 领域知识通过声明式Skills注入，而非提示工程
3. **延迟工作流生成**: 数据传输减少92%，说明按需生成优于预生成
4. **成本可行**: 亚美分成本使大规模科学查询成为可能

## 对我们的意义

### 直接相关性: ★★★★☆

| 我们的系统 | 科学工作流启示 |
|-----------|---------------|
| SOUL.md | 类似Skills的声明式配置，但需更强的确定性保证 |
| Agent分层 | 可参考语义/确定性分离，将LLM限制在特定层 |
| Skills系统 | Skills作为知识层的设计理念高度一致 |
| 可复现性 | 相同输入→相同输出的确定性保证值得追求 |

### 关键借鉴

1. **三层分离**: 将自然语言理解、决策逻辑、工具执行显式分层
2. **Skills即知识**: Markdown格式的声明式知识编码是有效模式
3. **确定性保证**: 关键路径上的确定性映射可提升系统可信度
4. **延迟加载**: 按需生成而非预加载可减少资源消耗

### 潜在应用

- **科研辅助Agent**: 帮助研究人员将问题转化为可执行分析流程
- **自动化报告生成**: 意图→结构化报告模板→填充执行
- **技能市场**: 领域专家编写Skills，用户通过自然语言调用
