# 主流4个Agent产品Memory设计，一篇就够了

## 四种Memory设计路线对比

### 1. ChatGPT: 注入式用户档案
- **机制**: 将长期事实库和会话摘要直接拼接到每次prompt
- **特点**: 简单直接，一次性注入
- **优点**: 实现简单，确保信息可达
- **缺点**: 上下文膨胀，可能导致干扰

### 2. Claude: 按需检索
- **机制**: 模型需要时调用`conversation_search`或`recent_chats`工具拉取历史
- **特点**: 主动查询，按需加载
- **优点**: 上下文精简，避免信息过载
- **缺点**: 增加一次工具调用延迟

### 3. OpenClaw: Markdown文件存储
- **机制**: 所有记忆存储为磁盘上的.md文件，语义+关键词混合检索
- **特点**: 持久化文件，结构化存储
- **优点**: 可审计、可编辑、跨会话持久
- **缺点**: 需要管理文件系统

### 4. Hermes: 冷热分层设计 ⭐
- **机制**: 三层记忆架构
  - **热数据**: prompt memory（活跃上下文）
  - **冷存储**: 情境信息（按需加载）
  - **技能索引**: 程序性信息（工具使用）
- **特点**: 明确分层，有规则的访问控制
- **优点**: 最克制、有边界，避免记忆滥用

## Memory的利弊分析

### ✅ 优点
- 降低用户使用门槛（不用重复背景信息）
- 为长期陪伴型产品提供连续性
- 提升用户留存

### ⚠️ 缺点
- **上下文干扰** (Context rot): 旧记忆干扰当前任务
- **隐私泄露**: 敏感信息长期存储风险
- **人格漂移** (Personality drift): AI行为随记忆变化
- **记忆投毒**: 新型攻击向量，恶意注入错误记忆

## 核心观点

> **"Memory并非AI产品的默认功能，而应是产品设计的一部分。显式记忆优于隐式记忆，因为其更克制、有边界。"**

对于绝大多数AI产品，更好的产品设计比堆砌复杂的Memory系统更重要。

## 对OpenClaw的意义

### ✅ 架构验证
- **分层设计**: Hermes的冷热分层与我们的L0-L3架构理念一致
- **显式优于隐式**: 记忆应该是有意识的设计选择，而非默认开启
- **文件化存储**: OpenClaw的Markdown文件方式被验证为可行方案

### 🔬 设计原则

1. **最小记忆原则**: 只记忆必要信息，默认不记忆
2. **分层访问**: 热数据(即时) → 温数据(最近) → 冷数据(历史)
3. **用户可控**: 用户可以查看、编辑、删除记忆
4. **场景适配**: 不同场景使用不同记忆策略

### 💡 实践建议

| 记忆类型 | 存储位置 | 访问方式 | 保留期限 |
|---------|---------|---------|---------|
| 系统指令 | L0 Core | 每次注入 | 永久 |
| 用户偏好 | L1 Profile | 按需加载 | 长期 |
| 会话历史 | L2 Session | 检索引用 | 短期 |
| 任务上下文 | L3 Task | 实时构建 | 单次 |
