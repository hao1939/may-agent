# SEA-Eval: OpenClaw Token效率深度分析

> **来源**: arXiv:2604.08988 | Fudan University | 2026-04-14
> **核心发现**: OpenClaw Token消耗比竞品高**7倍**，序列任务第5个后崩溃。Token收敛是区分真伪自进化的金标准。

---

## 论文核心贡献

SEA-Eval 是首个专门针对**自进化Agent (SEA)** 的评估基准，提出了关键洞察：**成功率会产生能力幻觉**，只有Token消耗的序列收敛才能区分真正的进化与伪进化。

### 自进化Agent定义

SEA形式化定义为五元组：
```
SEA = (E, A, M, Φ, Ψ)
```
- **E**: 开放式数字环境 (GUI像素、DOM树、系统接口)
- **A**: 可扩展动作空间 (支持自主工具合成)
- **M = Mp ∪ Me ∪ Md**: 分层持久记忆
  - Mp: 程序知识 (可复用执行策略)
  - Me: 情景知识 (历史轨迹与失败归因)
  - Md: 声明知识 (环境约束与用户偏好)
- **Φ**: 经验蒸馏函数 (原始交互→结构化记忆)
- **Ψ**: 选择性跨任务记忆转移函数

---

## 进化飞轮 (Evolutionary Flywheel)

SEA的核心架构是**双中心飞轮**结构：

```
┌─────────────────┐     ┌─────────────────┐
│  Execution Hub  │◄────►│  Cognition Hub  │
│   (数字肢体)     │     │   (认知核心)     │
└────────┬────────┘     └────────┬────────┘
         │                       │
    1. 执行阶段                   │
         │                       │
         ▼                       │
    生成轨迹τ ───────────────────►│
                                  │
    ◄──────────────────────────  2. 蒸馏阶段
                                  │
    3. 增强执行 ◄── 应用记忆Mp ────┘
```

### 飞轮三阶段

1. **执行**: Execution Hub与环境交互，生成原始轨迹τ
2. **蒸馏**: Cognition Hub应用Φ，从τ提取可复用经验ΔM
3. **增强执行**: 后续任务从M检索策略，替代zero-shot推理

## 关键发现：OpenClaw vs GenericAgent

### Token消耗对比 (惊人差距)

| 指标 | OpenClaw | GenericAgent | 差距 |
|------|----------|--------------|------|
| **总Token消耗** | **27,364K** | **3,918K** | **7×** |
| 单任务最大差距 | - | - | **31.2×** |
| 静态成功率 | 100% | 100% | 相同 |

### 序列任务表现 (致命差异)

**GenericAgent (真正进化)**:
- 学术数据库检索任务: Token消耗从 **520K → 117K** 单调收敛
- 有效将经验转化为低成本执行策略

**OpenClaw (伪进化)**:
- Token消耗在序列任务间**剧烈波动**
- 无法形成稳定收敛轨迹
- 特定序列任务上**完全崩溃**

### 失败模式诊断

| 失败模式 | 症状 | 根因 |
|----------|------|------|
| **蒸馏失败** | 任务成功但记忆无效 | Φ未能从轨迹提取可复用策略，Mp充满死知识 |
| **检索失败** | 有记忆但认不出相似任务 | 执行中心无法识别新任务与M中条目的结构相似性 |

## 核心洞察

> **"成功率会产生'能力幻觉'。Token消耗的序列收敛，才是区分真伪进化的金标准。"**

### 评估指标设计

SEA-Eval建立两个核心指标：

- **SR (Success Rate)**: 任务完成最低可靠性保证
- **T (Token Consumption)**: 检测伪进化的核心信号

**关键**: 跟踪序列任务流中T的收敛轨迹，而非静态单任务测量。

## 对OpenClaw的意义

### 🚨 严重问题

1. **Token效率危机**: 比竞品差7倍，存在严重优化空间
2. **伪进化**: 记忆系统未能有效降低重复任务成本
3. **飞轮失效**: 执行→蒸馏→增强的闭环未能有效运转

### 🔬 研究建议

1. **引入Keff指标**: 建立进化效率系数，追踪跨session的token消耗趋势
2. **闭环验证**: 建立执行→蒸馏→增强三步飞轮的完整性检查
3. **失败模式检测**: 自动识别蒸馏失败vs检索失败
4. **Skill复用审计**: 验证SKILL.md系统是否真正减少重复推理token
