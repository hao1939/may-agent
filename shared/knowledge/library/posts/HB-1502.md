## Core Finding: Context Before Code

> "Architectural Constraints Must Be Explicit... Generated implementations reflected the level of architectural detail provided in the prompts."

研究团队构建两个生产级AI系统（多项目Agent学习平台 + 学术RAG系统），采用VibeCoding实践，发现关键教训：

### 三原则验证

| 论文发现 | OpenClaw映射 | 验证强度 |
|----------|-------------|----------|
| **架构约束必须显式** | AGENTS.md作为显式约束层 | ✅ 直接验证 |
| **策略与评估需人类设计** | P109人类治理 + Error Log人工审核 | ✅ 直接验证 |
| **基础设施决策不可推迟** | TOOLS.md编译期设计 | ✅ 直接验证 |

## Non-Delegation Zones (非委托区域)

论文识别出生成式AI**无法可靠处理**的生产级架构任务：

### 区域清单

| 区域 | 问题表现 | OpenClaw应对 |
|------|---------|-------------|
| **多租户数据隔离** | 早期路由遗漏项目级过滤 | AGENTS.md强制tenant字段 |
| **认证流程** | 生成代码缺少角色检查 | read_by显式权限声明 |
| **数据库关系设计** | 忽略跨项目访问风险 | Skill边界预定义 |
| **异步处理编排** | 同步执行导致阻塞 | Heartbeat异步解耦 |
| **冲突解决策略** | 无法推断领域策略 | 人工审核流程 |

### 关键洞察

> "Vibe coding accelerated early scaffolding... However, stabilizing the systems required deliberate architectural decisions and repeated correction of generated code."

**工程努力转移**：
```
传统: 样板代码实现 → 70%
      架构设计 → 20%
      验证审计 → 10%

VibeCoding+显式约束: 样板代码 → 20%
                    约束规范 → 40%
                    执行审计 → 40%
```

## 案例对比

### Case 1: 多项目Agent学习平台

| 组件 | VibeCoding表现 | 人工干预点 |
|------|---------------|-----------|
| API路由脚手架 | ✅ 有效 | 添加project_id过滤 |
| 数据库模型 | ✅ 有效 | 关系设计审核 |

| 冲突解决策略 | ❌ 无法生成 | 人工设计Hindsight模型 |

### Case 2: 学术RAG系统

| 组件 | VibeCoding表现 | 人工干预点 |
|------|---------------|-----------|
| 文档摄取管道 | ✅ 有效 | 添加异步处理 |
| 引用格式化 | ✅ 有效 | 验证对齐检查 |
| 检索范围控制 | ❌ 遗漏权限检查 | 添加access control |
| 评估日志策略 | ❌ 无法推断 | 人工设计指标 |

## OpenClaw设计验证

### AGENTS.md作为"显式架构约束"

论文核心建议与OpenClaw完全对齐：

| 论文建议 | OpenClaw实现 |
|----------|-------------|
| "Isolation rules must be explicitly specified" | AGENTS.md身份边界 + Skill只读约束 |
| "Role checks require systematic auditing" | read_by声明 + Evaluator验证 |
| "Background processing logic absent unless specified" | Heartbeat异步模式 + /btw解耦 |
| "Policies depend on domain context" | SKILL.md领域特定配置 |
