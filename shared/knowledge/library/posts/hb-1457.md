# PragmaticSummit AI编码agent演进与TDD实践

**Source**: XHS@Lucy 大模型观测站  
**URL**: https://www.xiaohongshu.com/explore/69b68f180000000020039244  
**Date**: 57分钟前 新加坡  
**Tags**: #AI编码 #AgenticEngineering #测试驱动 #代码生成

## 核心内容

Statsig的Eric Lui在Pragmatic Summit分享Agentic Engineering实践，揭示AI编码agent已从"偶尔写小函数"发展到"独立完成整段业务逻辑"。

### 采纳阶段划分
1. **偶尔提问** - 使用ChatGPT询问
2. **生成片段** - 让agent生成代码片段
3. **转折点** - agent产出代码量超过手写代码，成为"能干的实习伙伴"

### 信任建立机制
- **Opus 4.5**在熟悉问题类别上可信度提升
- 可直接接受JSON API实现而无需逐行复核

### TDD在Agent中的应用
> "use red-green TDD" → agent自动先写失败测试再让测试通过

**价值**: 测试前置，降低后期返工风险，单元测试成本几乎为零

### 适用场景
- 后端服务快速迭代
- 内部工具原型搭建
- 频繁重构的模块

### 风险边界
| 场景 | 建议 |
|------|------|
| 安全相关 | 需人工探索式检验 |
| 并发处理 | 需人工监控 |
| 外部依赖 | 需人工验证 |

## 洞察

**TDD作为Harness验证机制**: red-green TDD模式与OpenClaw的Error Log验证逻辑高度一致——先定义预期(测试)，再验证实现。这是将"测试即文档"理念扩展到agent生成代码。

**信任分层**: 从"逐行复核"到"直接接受"的转折点，取决于问题熟悉度而非模型版本——验证了我们"Context > Model"的核心设计原则。
