## 核心内容

MemSkill提出全新记忆总结范式：**Span-level Skill-conditioned Memory Generation**

## 核心问题

目前很多Agent Memory System还停留在：
- "手工搭记忆提取模块流水线"的范式
- 过于rigid且强依赖人类先验
- turn-level顺序处理不够scalable

## 核心创新

### Skill-conditioned Generation
把"怎么构建记忆"升级为一个**可学习、可进化的记忆技能库(Skill Bank)**。

**范式转变:**
- 不再逐turn跑固定模块
- 以span/chunk为单位做总结
- 根据context选取相关memory skills组合

## 架构: Controller → Executor → Designer

```
Text Span → Controller(Top-K skills选择) → Executor(记忆生成更新)
                ↓
          Designer(skill bank进化)
```

### Controller
- 为skill bank候选skills打分
- 选择最佳Top-K，避免把整个库塞进LLM
- **RL训练**: 用下游任务反馈作为奖励信号
- 学习"什么时候该用哪些skills"

### Executor
- 在选定skills约束下进行span-level记忆生成
- 输入: skills + text span
- 输出: 结构化记忆更新

### Designer
- 从failure cases里总结问题
- 维护failure-driven的hard-case buffer
- 定期提炼重复失败模式
- 转化为skill edits或new skills
- 实现skill bank的**self-evolve**

## 实验结果

| 场景 | 数据集 | 表现 |
|------|--------|------|
| 对话记忆 | LoCoMo, LongMemEval | 稳定提升 |
| 具身决策 | ALFWorld | 稳定提升 |
| 泛化能力 | LoCoMo→HotpotQA | 较强泛化 |

## 社区问答精华

**Q: Token会不会爆炸?**
> "使用时配置好参数是不会的...evolve skill的过程可以只占整个长期user-agent交互过程的很小一部分...支持在训练阶段设置不同的executor/designer LLM"

**Q: 核心思路是根据不同chat选择mem skill来总结?**
> "基本是这样，memskill的一大future direction就是可以potentially应用在这种personalized scenario"

**Q: 如何决定何时触发memory操作?**
> "顺序读取每段text span时都会触发，但具体选哪些skills由Controller决定。例如某段文本包含时间相关信息，Controller就倾向于选择temporal skill"

## 关键洞察

1. **Skill-conditioned范式**: Memory生成也可以Skill化
2. **RL训练Controller**: 技能选择可以用强化学习优化
3. **Designer自进化**: 与Self-Evolution禁令形成张力
4. **Memory三层架构**: 值得深入研究的参考
