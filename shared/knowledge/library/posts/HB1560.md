## Formal Skill Definition: Four-Tuple Structure

论文形式化定义Agentic Skill为四元组：

```
S = (𝒞, π, 𝒯, ℛ)
```

| Component | Name | Function | OpenClaw Mapping |
|-----------|------|----------|------------------|
| 𝒞 | Applicability Conditions | 触发条件/激活前提 | SKILL.md trigger + AGENTS.md context |
| π | Policy | 核心过程知识/动作序列 | SKILL.md instructions |
| 𝒯 | Termination Criteria | 成功完成判定条件 | Error Log验证 + handoff标准 |
| ℛ | Interface | 标准化调用边界 | SKILL.md I/O schema + tools |

> "This formal structure ensures that skills remain simultaneously executable, reusable, and governable, distinguishing them from atomic tools (which lack complex procedural logic) and episodic memories (which lack standardized callable interfaces)."

## Progressive Disclosure Architecture (Level 1-3)

| Level | Component | Content | Token Usage | Load Timing |
|-------|-----------|---------|-------------|-------------|
| **L1** | Metadata | YAML frontmatter: name, description, version, trigger | 30-100 | Pre-loaded at startup |
| **L2** | Instructions | Procedural knowledge, workflows, best practices | 200-5,000 | Loaded upon activation |
| **L3** | Resources | Scripts, references, templates, schemas | Unbounded | Loaded on-demand |

**关键洞察**: Level 1作为"table of contents"使Agent能感知数千Skills而不 degrade context window。

## Three-Stage Skill Extraction Pipeline

### Stage 1: Repository Structural Analysis
- 工具: repo2AI生成Markdown格式目录结构和文件内容
- 输出: 核心脚本I/O规格、配置文件、辅助模块、文档示例的层级映射

### Stage 2: Semantic Skill Identification
**两阶段排序问题**:
1. **Dense Retrieval**: Bi-encoder编码任务描述和代码模块，计算cosine similarity
2. **Binary Ranking**: Cross-encoder精细评估，仅超过阈值τ的模块进入提取

**提取四标准**:
1. **Recurrence**: 多上下文出现的模式
2. **Verification**: 功能完整、文档完善、无关键bug
3. **Non-obviousness**: 需要领域 expertise 或调试才能发现的逻辑
4. **Generalizability**: 可参数化或适应不同上下文

### Stage 3: Translation to SKILL.md
**三个组件**:
1. **Frontmatter Generation**: YAML元数据 (name/description/version/trigger/dependencies)
2. **Instruction Drafting**: LLM可消费的过程指导 (工作流分解/错误处理/最佳实践)
3. **Asset Bundling**: scripts/, references/, templates/标准化子目录

## Case Study: TheoremExplainAgent → Skill Extraction

**源系统架构**:
- Planner Agent: 教学设计，将定理转化为故事板
- Coding Agent: 故事板→Manim Python脚本
- Error Correction: 多轮重试+Python stack trace分析
- RAG: Manim文档检索防API幻觉

```yaml
name: visual-theorem-walkthrough
description: Generate Manim animation explaining STEM theorems with synchronized narration and visual proofs
version: 1.0.0
trigger: ["visualize theorem", "animate proof", "mathematical explanation video"]
dependencies: ["manim", "manim-voiceover"]
```

## Case Study: Code2Video → Skill Extraction

**Tri-Agent架构**:
1. **Planner**: 内容结构化+视觉资产检索
2. **Coder**: Storyboard→Python，scope-guided auto-fix
3. **Critic**: VLM精炼空间布局

**创新技术**: Visual Anchor Prompting
- 在渲染帧上叠加10×10网格
- 将连续视觉信息转为离散网格引用
- 精确定位元素位置和遮挡

**评估指标**: TeachQuiz
- VLM先"unlearn"领域知识
- 暴露于生成视频后测量fact recovery
- **结果**: Agent生成视频比基线code generation模型提升40%知识传递效率，某些类别超越人工教程

## Critical Design Implications

### 1. Skill Acquisition at Scale
论文提出三种获取路径对比:
| Path | Pros | Cons |
|------|------|------|
| Manual expert authoring | 可靠性保证 | 严重可扩展性约束 |
| Autonomous discovery | 自动化 | 语义一致性难保证 |
| **GitHub repo mining** | 可扩展+高质量 | 需要提取框架 |

**OpenClaw启示**: 建立`agents/shared/skills/`的自动挖掘流水线

### 2. Four Extraction Criteria → SKILL.md Review Checklist
将论文提取标准转化为Skill贡献指南:
- [ ] **Recurrence**: 此Skill是否解决一类问题（非单次任务）？
- [ ] **Verification**: 是否有测试验证功能完整？
- [ ] **Non-obviousness**: 是否包含领域 expertise（非显而易见）？
- [ ] **Generalizability**: 是否可参数化适应不同场景？

### 3. Semantic Skill Matching Enhancement
论文的两阶段检索(dense retrieval + cross-encoder)可改进OpenClaw的Skill触发:
- 当前: 基于关键词的trigger匹配
- 增强: 向量相似度+相关性排序
