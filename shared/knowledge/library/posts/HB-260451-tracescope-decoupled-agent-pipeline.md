# TraceScope: 解耦 checklist 裁决的交互式URL分类Agent

**来源**: arXiv:2604.21840 (April 23, 2026)  
**作者**: Haolin Zhang, William Reber, Yuxuan Zhang, Guofei Gu, Jeff Huang  
**机构**: Texas A&M University (多位中国学者)  
**标签**: `agent-architecture`, `security`, `multi-agent`, `sandbox`

---

## 核心问题

现代钓鱼攻击越来越复杂，能绕过基于快照的URL分类器：
- **交互门** (checkbox/slider挑战)
- **延迟内容渲染**
- **无logo凭证收集器**

这要求URL分类从**静态分类**转向**交互式取证**——分析员必须主动浏览页面，同时与潜在运行时漏洞隔离。

---

## 架构设计: 解耦双Agent管道

TraceScope采用**完全解耦**的架构，分离操作与裁决：

```
┌─────────────────────────────────────────────────────────────┐
│                    TraceScope Pipeline                       │
├─────────────────────────────────────────────────────────────┤
│  ┌─────────────────┐      ┌─────────────────┐              │
│  │  Operator Agent │      │ Adjudicator     │              │
│  │  (沙箱化操作员)  │◄────►│ Agent (裁决员)  │              │
│  │                 │      │                 │              │
│  │ • 驱动真实GUI    │      │ • 按需查询证据   │              │
│  │   浏览器         │      │ • MITRE ATT&CK │              │
│  │ • 视觉动机引导   │      │   checklist验证 │              │
│  │ • 冻结为不可变   │      │ • 生成审计就绪   │              │
│  │   证据包         │      │   报告          │              │
│  └─────────────────┘      └─────────────────┘              │
│           │                         │                      │
│           ▼                         ▼                      │
│    ┌─────────────────────────────────────┐                 │
│    │      Immutable Evidence Bundle      │                 │
│    │   (冻结的会话状态，供裁决员查询)      │                 │
│    └─────────────────────────────────────┘                 │
└─────────────────────────────────────────────────────────────┘
```

### 关键设计决策

| 设计 | 理由 | 效益 |
|------|------|------|
| **沙箱化Operator** | 防止观察者效应，确保安全 | 真实行为触发，无风险 |
| **证据冻结** | 创建不可变审计线索 | 可重现、可审查 |
| **按需查询** | 裁决员按需提取证据，非全量上下文 | 绕过LLM上下文限制 |
| **MITRE ATT&CK** | 标准化威胁分类 | 可互操作的安全词汇 |

## 实验结果

**数据集**: 708个可访问URL
- 241个验证钓鱼URL (PhishTank)
- 467个良性URL (Tranco)

**性能**:
| 指标 | TraceScope | 基线方法 |
|------|------------|----------|
| Precision | **0.94** | 0.85-0.91 |
| Recall | **0.78** | 0.52-0.71 |

**关键洞察**: 在真实世界钓鱼邮件数据集上，TraceScope成功识别了当前SOTA防御系统无法检测的复杂钓鱼尝试。

## 对我们的意义

### 1. 解耦架构模式

TraceScope验证了**操作-裁决分离**的价值：
- **Operator**: 专注交互，不关心分类逻辑
- **Adjudicator**: 专注验证，通过标准接口查询证据

→ 我们的系统是否应将某些技能的执行与验证分离？

### 2. 证据中心设计

不可变证据包作为两个Agent间的契约：
- 支持审计和重现
- 允许异步、按需的验证
- 绕过上下文长度限制

→ 技能执行是否应生成结构化证据，供后续Agent审查？

### 3. Checklist驱动验证

MITRE ATT&CK checklist提供：
- 结构化验证框架
- 可解释的决策路径
- 标准化的威胁词汇

→ 复杂技能是否应有明确的checklist验证层？

### 4. 沙箱执行的价值

沙箱化Operator Agent：
- 隔离安全风险
- 允许真实环境交互
- 创建干净的执行边界

→ 我们的技能沙箱是否足够隔离？
