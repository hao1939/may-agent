## Core Finding: Language-Aware Tools > Generic Code Agents

> "iSWE achieves state-of-the-art issue resolution rates... and spends between **2× and 3× fewer dollars** on model-inferencing APIs than other leading agents using the same LLM"

| Approach | Design Philosophy | Cost | Java Performance |
|----------|-------------------|------|------------------|
| Generic Agent (CodeAct) | Arbitrary code actions | High | Lower |
| iSWE | **Language-specific tools** | **2-3x lower** | **SOTA** |

## Two-Sub-Agent Architecture

```
Issue Description + Code
         ↓
┌─────────────────────┐
│  Localization Agent │ ← ReAct + Read-only tools
│  (定位Agent)         │
└──────────┬──────────┘
           ↓ Structured output
┌─────────────────────┐
│   Editing Agent     │ ← ReAct + Edit tools
│   (编辑Agent)        │
└──────────┬──────────┘
           ↓
    Modified Code
```

**Design Rationale**:
1. **Modularity**: Each sub-agent has well-defined I/O
2. **Flexibility**: Can run separately or end-to-end
3. **Simplicity**: Each sub-task easier than full task
4. **Intermediate value**: Localization alone delivers value

## Key Insights

### 1. Language-Specific Knowledge Matters
> "Java differs substantially from Python in terms of its syntax, type system, and emphasis on object-orientation"

- Java issues affect **more files** than Python (OO nature)
- Java compiler catches many errors → linters less comprehensive
- Build tool integration (Gradle/Maven) adds complexity

### 2. Arbitrary Code Actions Are Costly
> "Arbitrary code actions... tend to require more iterations of the agentic loop, increasing LLM inferencing cost"

- Generic bash/code actions risk unsafe side-effects
- Sandboxing incurs time/memory/disk overhead
- Tailored tools reduce iteration count

### 3. Modular Architecture Enables Experimentation
> "We can run pieces in isolation... speeds up experiments"

- Localization and editing can be tested separately
- Intermediate results are typed and sanitized
- Facilitates practical use beyond benchmarks
