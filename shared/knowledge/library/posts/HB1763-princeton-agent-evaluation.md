## 论文核心批判

### 当前 Agent 评估五大缺陷

| 挑战 | 问题描述 | 影响 |
|------|----------|------|
| **成本控制缺失** | 不控制评估成本，导致高成本追求排名 | 激励极端昂贵但不实用的Agent |
| **准确性来源误解** | 单一关注准确性，忽视其他指标 | 代理不必要的复杂和昂贵 |
| **基准需求混淆** | 模型开发者 vs 下游开发者需求混合 | 难以识别最适合特定应用的代理 |
| **保留集不足** | 许多基准缺乏适当保留集 | 代理脆弱，易过拟合 |
| **缺乏标准化** | 评估实践不统一 | 普遍缺乏可复制性 |

## 核心贡献

### 挑战1: 成本控制
- 提出三个新的**简单基线代理**
- 在HumanEval上**超越许多复杂架构**，同时成本更低
- **结论**: 评估必须控制成本，否则激励错误方向

### 挑战2: 准确性与成本共同优化
- 提出**帕累托前沿**设计空间
- 改进DSPy框架进行**联合优化**
- HotPotQA上保持准确性同时降低成本

### 挑战3: 差异化基准需求
- NovelQA案例研究
- 下游评估应关注**美元成本**，非代理指标（如参数数量）

### 挑战4: 基准捷径问题
- 四种代理**泛化级别**分类
- WebArena基准测试中的捷径案例
- 缺乏保留集导致无意中采取捷径

### 挑战5: 可复制性危机
- WebArena和HumanEval评估审查
- 可复制性问题**夸大准确性估计**
- 导致对代理能力的过度乐观
