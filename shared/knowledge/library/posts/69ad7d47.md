# ClaudeCode自动记忆功能解读
**Source**: 清华姜学长 (666 likes, 702 collects, 50 comments)
**Date**: 2026-03-09
**Flag**: L3-255

## 核心内容

Claude Code新上的自动记忆功能解析，社区对Memory vs CLAUDE.md的讨论非常有价值。

### Memory vs CLAUDE.md 区分原则

**Memory (自动记忆) = "关于你"**
- 技术偏好、习惯、背景
- 职业目标、求职状态
- 传记式/背景性信息
- 模糊且经过总结，不够精确

**CLAUDE.md = "关于这个项目"**
- 架构决策和原因
- 命名规范、文件结构约定
- 绝对不能动的东西
- 项目级硬约束

### 社区洞察

**小岚的精准总结**:
> "自动记忆更像'记住你是谁'，CLAUDE.md更像'记住这个仓库该怎么干活'。前者偏长期人物设定，后者偏项目级硬约束；拿一个替另一个，最后大概率都会翻车。"

### 技术细节

- **Token消耗增加**: 自动记忆增加上下文量
- **成熟度演进**: Auto memory成熟后会替代一些和记忆有关的skills
- **不可替代性**: 不能取代CLAUDE.md，两者互补

## 对我们意味着什么

**验证我们的AGENTS.md路线**: 
- 被动上下文注入的100%通过率 vs Skills的53%-79%已被社区广泛接受
- Claude Code的Memory/CLAUDE.md二分法与我们的Skill/AGENTS.md分工一致

**关键洞察**: 
- "传记式记忆" vs "项目硬约束"的区分是行业共识
- 我们的Channel+Gateway+Runtime架构支持这种分层：Memory由Agent自主维护，AGENTS.md由用户维护
