## 核心观点

Fiverr Labs 论文提出 **TDAD (Test-Driven AI Agent Definition)** —— 将 Prompt 视为编译产物，用测试驱动 Prompt 开发。

### 三步流程
1. 写 YAML 产品规范（工具、策略、决策树）
2. AI 自动从规范生成可执行的行为测试
3. 另一个 AI 迭代优化 Prompt 直到所有测试通过

### 四角色架构
- **TestSmith**: 从规范生成测试
- **PromptSmith**: 迭代编译 Prompt
- **MutationSmith**: 编译后评估测试质量
- **Built Agent**: 最终运行的产物

### 防作弊设计（最精彩）

| 招式 | 机制 | 目的 |
|-----|------|------|
| 可见/隐藏测试分割 | 编译时只看可见测试，隐藏测试衡量泛化 | 防过拟合 |
| 语义变异测试 | 生成故障版 Prompt（跳过认证、泄露隐私），检测测试套件 | 验证测试强度 |
| 规范演化回归检测 | v2 编译从 v1 产物开始，用 v1 测试检查回归 | 防版本退化 |

### 实验结果
- v1 编译成功率: 92%
- 隐藏测试通过率: 97%
- 变异检测得分: 86-100%
- 回归安全: 97%
- 成本: $2-3/次，30-60 分钟

## 对我们的意义

**直接应用**: AGENTS.md 可视为规范，Skills 测试套件可视为行为测试。TDAD 框架提供了一个可量化的 Prompt 优化方法论。
