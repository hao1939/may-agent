# 研究发现：为什么多智能体注定会失败（MAST分类体系）

**Source**: 小红书 @MemeInformation (2025-08-23) / UC Berkeley 论文
**Relevance**: ⭐⭐⭐⭐⭐ (直接诊断我们面临的问题)

## 核心内容

伯克利团队评估了 7 个主流 MAS 框架在 200+ 任务上的表现，提出 **MAST 失败分类体系**：

### 三大失败类型

1. **任务设定问题**
   - 任务怎么做没交代清楚
   - 每个 agent 该干什么没分清
   - 什么时候算完成说不清楚
   - → 重复操作、死循环、不知道何时停止

2. **智能体间沟通不畅**
   - 角色混乱、指令冲突、信息丢失
   - 协同变成互相添乱

3. **验证机制太弱**
   - 没有验收环节
   - 只检查表面格式，不判断结果正确性
   - 任务做到一半就提前结束

### 关键发现

- 靠调 Prompt、换角色名、优化任务顺序 → 最多提升十几个百分点，远远不够
- **需要从架构入手**：明确任务拆分规则、优化交互机制、设立多级验证流程
- Token 成本可能是单 agent 的 10 倍，结果不一定更好

### 精辟比喻

> 一个再聪明的员工，放进组织混乱的公司，也做不好事。

## 对我们系统的意义

这篇论文就是在说我们。直接对照检查：

| MAST 失败类 | 我们的现状 | 行动 |
|---|---|---|
| 任务设定不清 | ✅ 我们有 role guidance + request 系统 | 保持 |
| 角色分工不明 | ⚠️ agent 间边界有时模糊 | 需要更清晰的 capability boundary |
| 沟通不畅 | ⚠️ 通过文件系统间接通信，信息可能丢失 | event 系统在改善 |
| 验证机制弱 | ❌ 缺少系统性的 output verification | **最大短板** |
| 提前结束 | ⚠️ heartbeat 模式有时一轮就结束 | 需要 completion criteria |

**最重要的行动项**：加强验证环节。不是"做完了"就行，要验证"做对了"。
