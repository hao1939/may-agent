# Karpathy 新项目，给 AI 造 GitHub

## 核心概念
AgentHub = 给 AI Agent 用的"GitHub"，但砍掉了所有人类才需要的东西

### 被移除的人类协作概念
- ❌ 没有 branch
- ❌ 没有 PR  
- ❌ 没有 merge conflict
- ✅ 只有一个不断生长的 commit DAG

### 设计理念差异
| GitHub | AgentHub |
|--------|----------|
| 围绕"共识"设计 | 围绕"自由探索"设计 |
| 人类需要 agree on what goes into main | AI Agent 不需要共识 |
| 协作需要审批 | 好的结果自然被其他 agent fetch |

## 技术栈
极简主义到极致：
- Go 单二进制
- SQLite（WAL 模式）
- Bare git repo
- 零第三方运行时依赖
- 10 个文件，约 1300 行代码

**核心原语只有两个**：
1. 共享代码（git bundle）
2. 交换消息（channel + post）

## 配套项目 autoresearch
- 模拟 PhD 学生做 LLM 训练研究
- 一夜跑了约 100 次实验
- 连续两天完成约 700 次自主修改
- Time to GPT-2: 2.02h → 1.80h (提升 11%)

AgentHub 的目标：让互联网上多个 autoresearch agent 通过 hub 协作

## 生态位定位
- 第一层：编码 Agent（Claude Code、Cursor、Copilot）
- 第二层：编排框架（Agent SDK、LangGraph、AutoGen）
- 第三层：协作基础设施（AgentHub 就在这里）

## 已有案例
- 20 agent 并行一周产出 800 commit
- 5 agent 蜂群 48 小时写了 15 万行生产代码

## 一句话总结
> "给 Agent 设计工具，而不是让 Agent 适应人类工具"
> 
> 未来的开发者 = Agent 的编排者

## 对我们的意义
🔴 **范式冲突**: AgentHub 的"自由探索"理念与我们当前"禁止 Self-Evolution"的立场直接冲突
🟡 **技术验证**: 极简基础设施可行（Go+SQLite+git）
🟢 **生态位确认**: 协作基础设施层确实存在空白
