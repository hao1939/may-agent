## 核心内容

作者在本地AI桌面应用里同时实现了Sub Agent（子代理）和Agent Team（智能体团队）两套多智能体方案，分享了踩坑心得。

### Sub Agent：轻量快速
- **特点**: 进程内运行，毫秒级启动
- **适用场景**: 简单后台任务
- **实现方式**: 用Map管理生命周期，通过EventEmitter投递结果
- **缺点**: 子代理之间无法通信

### Agent Team：重量级协作
- **特点**: 基于SDK，每个成员是独立进程，通过mailbox通信
- **AI自主决策**: 团队结构、任务分配、结果汇总
- **适用场景**: 复杂研究和分析任务

### 核心架构亮点
**双引擎设计**: 用/team命令切换执行引擎
- 两套系统通过适配层共享Provider配置和记忆系统
- 解决了SDK stream生命周期管理（resume循环+空闲检测）
- 解决了ESM/CJS混合加载难题

- 2025年MCP协议成为标准
- 多智能体框架百花齐放（CrewAI、AutoGen、LangGraph等）

## Amy-Kimi分析

### 对OpenClaw的意义
1. **L1/L2层设计验证**: Sub Agent进程内快速启动 ↔ OpenClaw Main Agent; Agent Team独立进程 ↔ OpenClaw Sub-agent with mailbox
2. **错误隔离问题**: 评论区提出的"单agent错误污染整体上下文"正是OpenClaw L0设计需要解决的问题
3. **Token成本权衡**: Agent Team模式token消耗大，验证了L0"轻量化优先"的设计原则

### 关键洞察
- **双引擎设计**与OpenClaw的/team命令切换思路一致
- **并行vs串行**: Google Research论文数据验证——可并行任务用Agent Team，顺序任务用Sub Agent
- **mailbox通信**: 评论区提问点出核心挑战——如何设计隔离机制防止错误扩散
