**来源**: 小红书 @Agent Paper Agent

**发现时间**: 2026-04-04

---

## 核心问题

如何让LLM Agent自动从执行经验中提炼可复用技能？

> 模拟人类专家的技能编写方式——先广泛积累领域经验，再提炼为一份简洁的声明式技能文档。

---

## 三阶段流程

```
┌─────────────────┐
│ 1. 轨迹生成     │  Agent在任务集上并行执行，产生成功与失败轨迹
└────────┬────────┘
         ▼
┌─────────────────┐
│ 2. 并行多Agent  │  错误分析子Agent + 成功分析子Agent
│    补丁提案     │  (多轮ReAct循环定位根因) 独立处理轨迹，提出技能修改补丁
└────────┬────────┘
         ▼
┌─────────────────┐
│ 3. 无冲突合并   │  层次化合并所有补丁，通过归纳推理提炼高通用性模式
└─────────────────┘
```

---

## 关键发现

| 发现 | 说明 |
|------|------|
| **技能可跨模型规模迁移** | Qwen3.5-35B蒸馏的技能，使122B模型在WikiTableQuestions上提升57.65个百分点 |
| **技能可跨领域泛化** | 电子表格编辑上蒸馏的技能，在Wikipedia表格QA上也显著有效 |
| **纯开源可行** | 35B参数模型即可完成完整流程，无需依赖闭源模型 |
| **并行优势** | 并行合并(3分钟)比顺序编辑(60分钟)快20倍且效果更好 |
| **声明式优于记忆库** | 单一声明式技能文档优于检索增强的episodic memory bank |

## 对我们的系统的意义

### 关键洞察
1. **技能蒸馏的自动化**：无需人工编写技能，从执行经验中自动提炼
2. **跨模型迁移**：小模型蒸馏的技能可被大模型使用，降低技能开发成本
3. **并行处理的价值**：多agent并行分析比顺序处理更快更好

### 可借鉴的实践
- 引入"错误分析子Agent"和"成功分析子Agent"的双视角分析
- 层次化合并补丁而非简单叠加
- 优先考虑声明式技能文档而非episodic memory
