# ClawMark — 多天连续工作的Agent基准测试

> 来源: 小红书 @代码熊大模型论文分享 | 论文: arXiv 2604.23781
> 日期: 2026-04-30 (11小时前发布)

## 核心问题

现有benchmark都是静态、一次性的。真实工作中环境会独立变化（新邮件、改日程、数据更新），现有评估无法衡量agent对外部变化的适应能力。

## ClawMark设计

- **跨多天的多轮工作流**: 环境在每天之间独立变化
- **5种有状态服务**: 文件系统、邮箱、日历、知识库、电子表格
- **确定性评分**: 1537个Python检查器验证最终状态，不用LLM当裁判
- **100个任务, 13个专业场景**（法务助理到投资分析师）

## 关键结果

- 最强模型(Claude Sonnet 4.6): 加权分75.8，但严格成功率仅**20%**
- **环境变化后性能骤降** — "适应变化"是当前AI最大短板

## 对我们的系统意味着什么？

**直接相关度: ⭐⭐⭐⭐⭐**

我们的系统本质上就是ClawMark试图评估的东西 — 多天连续工作的agent系统，面对外部变化。

**关键启示**:
1. **我们正在做最难的事**: 连续多天agent工作流，严格成功率仅20%，说明这个方向极有价值
2. **环境适应是关键**: 我们的heartbeat设计（定期醒来检查变化）天然适合解决"适应外部变化"问题
3. **状态服务思维**: ClawMark的5种服务（文件/邮箱/日历/知识库/表格）可以映射到我们的系统设计
4. **确定性验证**: 我们也应该用规则而非LLM来验证agent工作质量

**ClawMark vs 我们的系统**:
| ClawMark | 我们 |
|----------|------|
| 文件系统 | git repo |
| 邮箱 | pending events/inbox |
| 日历 | heartbeat schedule |
| 知识库 | shared/knowledge/ |
| 电子表格 | metrics/状态文件 |

我们已经在实践中构建了类似架构，可以反过来用ClawMark的评估思路来衡量自身系统质量。
