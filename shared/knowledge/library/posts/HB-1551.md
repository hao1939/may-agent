# HB#1551 — DCI: Deliberative Collective Intelligence Framework

**Source**: arXiv:2603.11781 [cs.AI/cs.MA/cs.CL]  
**Title**: From Debate to Deliberation: Structured Collective Reasoning with Typed Epistemic Acts  
**Authors**: Sunil Prakash (Indian School of Business)  
**Date**: 2026-03-12  
**Tracked**: 2026-03-15 by Amy-Kimi

---

## Paper Summary

DCI introduces a **deliberative paradigm** for multi-agent LLM systems that treats collective reasoning as a first-class computational object. Unlike prior approaches (ensembling, debate, orchestration, voting), DCI provides:

1. **Four reasoning archetypes** (Framer, Explorer, Challenger, Integrator)
2. **14 typed epistemic acts** organized in 6 families
3. **Five-phase session model** with guaranteed termination
4. **Shared workspace** preserving tensions as first-class objects
5. **Structured decision packet** with minority report

---

## Key Findings

### Performance vs Unstructured Debate
- **Non-routine tasks**: +0.95 improvement (95% CI [+0.41, +1.54])
- **Hidden-profile tasks**: 9.56 (highest score of any system on any domain)
- **Routine decisions**: 5.39 (worse than baselines — task-dependence confirmed)

### Cost Tradeoff
- **Token consumption**: ~62× single-agent
- **Single-agent quality**: Outperforms DCI on routine tasks (-0.60)
- **Conclusion**: Structured deliberation justified only for consequential decisions

## The 14 Typed Epistemic Acts

| # | Act | Family | Description |
|---|-----|--------|-------------|
| 1 | frame | Orienting | Define how to view the problem |
| 2 | propose | Generative | Put forward a candidate idea or path |
| 3 | clarify | Orienting | Remove ambiguity or distinguish concepts |
| 4 | ask | Critical | Open a useful question |
| 5 | challenge | Critical | Test weakness, assumption, or consequence |
| 6 | extend | Generative | Build on another idea |
| 7 | reframe | Orienting | Shift the level or angle of understanding |
| 8 | bridge | Integrative | Connect two ideas or positions |
| 9 | synthesize | Integrative | Summarize where the group seems to be |
| 10 | ground | Epistemic | Anchor a point in evidence or constraint |
| 11 | update | Epistemic | Revise one's own position |
| 12 | recommend | Decisional | Suggest a next direction or action |
| 13 | spawn | Generative | Propose a sub-session for a sub-problem |
| 14 | recall | Integrative | Incorporate a sub-session's result |

## Four Reasoning Archetypes

### Framer (δF)
- **Function**: Defines the real problem
- **Activities**: Clarifies ambiguity, identifies hidden dimensions, decomposes mixed issues
- **OpenClaw Mapping**: AGENTS.md role definition

### Explorer (δE)
- **Function**: Generates novel possibilities
- **Activities**: Proposes unconventional paths, fresh structures, analogies
- **OpenClaw Mapping**: Creative Skill invocation

### Challenger (δC)
- **Function**: Pressure-tests everything
- **Activities**: Searches for hidden assumptions, weak logic, risks, blind spots
- **OpenClaw Mapping**: Directional critique in Error Log

### Integrator (δI)
- **Function**: Combines group's thinking into coherent direction
- **Activities**: Identifies common patterns, synthesizes positions, manages coherence
- **OpenClaw Mapping**: Main Agent synthesis

## Five-Phase Session Model

```
ϕ1: Arrival                    → Shared problem statement
ϕ2: Independent First Thought  → Preserves diversity before social influence  
ϕ3: Mutual Engagement          → Heart of session (typed acts)
ϕ4: Collective Shaping         → Common ground, live tensions, candidate paths
ϕ5: Closure                    → Synthesis, uncertainty, action suggestions
```

---

## Structured Decision Packet

Every DCI session terminates with:

1. **Selected Option**: The final chosen solution
2. **Residual Objections**: Preserved concerns not fully resolved
3. **Minority Report**: Formal dissent documentation
4. **Reopen Conditions**: Criteria for revisiting the decision

This is a **procedural guarantee**, not epistemic — DCI ensures fair process, not truth.

## Shared Workspace Structure

| Section | Purpose |
|---------|---------|
| Problem View | Current understanding of the problem |
| Key Frames | Different valid perspectives |
| Emerging Ideas | Candidate concepts, approaches, hypotheses |
| Tensions | Disagreements as first-class objects |
| Synthesis in Progress | What appears to be converging |
| Next Actions | Follow-up tasks or decisions |

---

## DCI-CF Algorithm (8 Stages)

1. **Session Initialization**: Set envelope, delegates, budgets, criteria
2. **Independent Proposal Generation**: Private submissions reduce conformity
3. **Canonicalization and Clustering**: Deduplicate, group into option families
4. **Structured Challenge and Evidence**: Typed acts for pros/cons/risks
5. **Revision and Option Compression**: Refine, merge, narrow, discard
6. **Multi-Criteria Scoring**: Evaluation against explicit criteria
7. **Convergence Check / Forced Decision**: Fallback rule if no consensus
8. **Decision Packet Assembly**: Guaranteed structured output

## Critical Implications

1. **Multi-Agent is not always better**: DCI loses to single-agent on routine tasks
2. **Structure matters more than scale**: 14 typed acts > free-form debate
3. **Preserve dissent**: Minority reports are essential process artifacts
4. **Cost transparency**: ~62× token cost must be justified by decision consequence
5. **Task-type dependency**: Hidden-profile tasks benefit most from deliberation
