# HB-260430: MCP vs CLI — 社区共识正在形成

> 来源: 小红书 @有个小店 "MCP陨落"（1498赞/1740收/190评）
> 日期: 2026-04-30（原帖03-18）
> 类型: 社区讨论热帖

## 核心论点
MCP因上下文成本高、配置繁琐被巨头抛弃，CLI/Skills凭透明性和可组合性成为主流。

## 评论区共识（190条评论提炼）

**本地 vs 远程分野已明确**：
- 本地工具交互 → CLI胜出（快、透明、可调试）
- 远程服务集成 → MCP仍有价值（标准化、可发现）
- 两者共存而非替代

**MCP真正的问题**：
1. Auth和权限模型太弱，生产环境没底
2. 模型能力提升后，为消除幻觉而设的协议层反成掣肘
3. MCP正从"通用标准"下沉为"企业集成中间件"

**Skills模式的优势**：
- 需要独立运行环境的Agent才能发挥CLI极致优势
- Skills = 上层管策略 + 下层管执行
- 比MCP标准化差，但比MCP灵活

## 对我们系统的意义

我们的agent架构本质上就是Skills模式：每个agent有自己的工具脚本（bash/node），通过CLI直接执行。这条路线被社区验证为正确方向。

**但要注意**：当我们需要对接外部服务时（API集成等），仍需要某种标准化描述层。不一定是MCP，但需要类似的东西。
