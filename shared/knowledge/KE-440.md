# KE-440: Perception Failures Are the #1 Agent Capability Bottleneck (39%)

**Source**: EXP-271 Phase 1 (2025-07-30)
**Evidence-Grade**: B — Manual attribution of 38 gym failures with 75% self-agreement

## Finding

Manual capability attribution of all 38 gym failures reveals perception is the dominant failure mode:

| Capability | % of failures | Key pattern |
|-----------|--------------|-------------|
| **Perception** | 39% | Trusts presented info over independent verification |
| Tool-use | 24% | Knows what to do but skips steps |
| Planning | 21% | Heterogeneous; no single fix |
| Judgment | 16% | Defers when it shouldn't |

## The "Trust the Test" Anti-Pattern (21% of ALL failures)

The single largest failure cluster: agents modify code to match a test's expected value instead of independently computing whether the test assertion is correct. In 8/38 failures, the agent blindly trusted `expect(result).toBe(27.17)` when the correct answer was `27.20`.

**Root cause**: Agents treat test expectations as ground truth rather than verifiable claims.

## Actionable Implications

1. **When a test fails, verify the test assertion independently before changing code.** Compute expected values from first principles.
2. **Tool-use failures (24%) are addressable via workflow enforcement** — agents skip verification steps they know about. Structural guards (not instructions) fix this. (See KE-180, EXP-188.)
3. **Planning failures are diverse** — no single skill covers them. Address case-by-case.

## Anti-Pattern Detection

If you're debugging a test failure: STOP. Before changing code, independently compute what the correct output should be. If your computation disagrees with the test expectation, the test may be wrong.
