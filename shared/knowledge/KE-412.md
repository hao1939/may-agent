# KE-412: Post-Fix Review Guard Catches Secondary Bugs (+40pp)

**Source**: EXP-263 (2027-01-26)
**Confidence**: High (10/10 treatment vs 6/10 control, N=20)

## Finding

After tests pass, agents stop looking. A post-fix review guard ("re-read every modified file, look for naming inconsistencies, config mismatches, error message accuracy") raises secondary-bug recognition from 60% to 100%.

## The Pattern

Append to coding tasks:
```
## ⛔ AFTER TESTS PASS
1. STOP. Ask: "Did I fix everything or just the obvious bug?"
2. Re-read EVERY file you modified. Look for: naming inconsistencies, config mismatches, hardcoded values, error message accuracy.
3. ONLY THEN proceed to finish().
```

## Why It Works

- Agents optimize for test-pass and terminate (the "BLIND FIX" pattern)
- This guard breaks the test-pass → done heuristic
- Specific checklists outperform generic "be careful" instructions (per EXP-257 specificity gradient)
- Text-in-task works when it's situated and specific (L2/L3 specificity)

## Caveats

- Baseline has drifted from 0% → 60% due to model improvements — effect size may shrink further
- Only tested on 2 scenarios (stale-config-override, wrong-error-message)
- Adds review cost to every task — deploy selectively for bug-fix tasks

## Deploy As

Coder skill: `post-fix-review` — activate on bug-fix tasks where secondary issues are likely.
