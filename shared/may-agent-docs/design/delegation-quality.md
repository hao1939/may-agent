# Delegation Quality

## Status: Identified Problem, Measuring Baseline

## The Problem

Delegation loses context at both ends:

**Sending**: Caller sends vague task ("fix the build"). Delegate re-discovers what caller already knows. Wastes 30-50% of ops.

**Returning**: Delegate returns one-line summary. Caller can't verify without re-reading files (which blocks the interface agent).

## What Good Looks Like

### Good send:
```
Fix src/build.js. Error: 'generated/types.js not found' at line 8.
Run 'node codegen.js' first — it generates types from schema.
Start by reading codegen.js, then run it, then run build.js.
Verify: build.js exits 0 and dist/bundle.js exists.
```

### Good return (finish):
```
finish({
  status: "success",
  summary: "Fixed build — codegen must run before build.js",
  deliverables: [
    { path: "generated/types.js", description: "Generated by codegen.js" },
    { path: "dist/bundle.js", description: "Build output" }
  ],
  verification_evidence: [
    "Step 3: bash(node codegen.js) exit 0",
    "Step 4: bash(node build.js) exit 0, wrote dist/bundle.js",
    "Step 5: read(dist/bundle.js) confirms bundle contains types"
  ]
})
```

## Measurement

Query the DB to establish baseline:
1. What % of delegation tasks include specific file paths or error messages?
2. What % of finish() calls include deliverables + verification_evidence?
3. How many ops do delegates spend discovering context the caller had?

## Fix

Not a system/framework. Just better practice:
- Include what you know in the task description
- Expect structured return data
- Measure if it reduces wasted ops
