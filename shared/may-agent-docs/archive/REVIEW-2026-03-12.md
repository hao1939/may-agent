## Key Findings

### Most Common Error Pattern: Fictional APIs
Three docs (`session-model-design.md`, `launcher-flags-design.md`, old review) referenced `manager.createChatSession()` / `manager.resumeChatSession()` / `manager.getChatSessionId()` — methods that were proposed but **never implemented**. The actual implementation is the `ChatSession` class managing its own lifecycle via `manager.run()` and `manager.input()`.

### Most Common Error Pattern: `undelivered-notifications.jsonl`
Three docs (`detached-subagent-design.md`, `task-completion-notifications.md`, old review) described a cross-process notification mechanism using a shared JSONL file + `fs.watch` + startup reconciliation + heartbeat drain. This was **never implemented**. Cross-process notification is passive — detached processes write `identity.json` status and results sit on disk.

### Most Common Error Pattern: Stale Intervals
Three docs had heartbeat/cron intervals that didn't match `agents/may/cron.json`. All have been synchronized.

### Most Common Error Pattern: `drain-todo` Handler
Referenced in `cron-graduation-process.md` and `jobs-workflows-review.md` as a graduated JS handler. No such handler exists. Agents read `workspace/todo.md` during their heartbeat — no separate drain mechanism needed.

## Remaining Open Issues

1. **Cross-process notification**: Detached sub-agents have no active notification mechanism. Results sit on disk passively. If a parent needs to know a detached job finished, it must poll. The `undelivered-notifications.jsonl` design is sound but unimplemented.

2. **Reactive triggers (Phase 2)**: Only `agents.send → triggerHeartbeat` is wired. Infrastructure-to-agent triggers (evaluate-sessions → coach, system-status → may, handleCompletion error → may) are not wired. This means the system detects problems but can't react quickly.

3. **Lean heartbeats (Phase 3)**: Heartbeat.md files are still multi-section mission briefings. Depends on Phase 2 reactive triggers working first.

4. **Heartbeat turn guard**: Agents still exhaust turn limits during heartbeats. The `heartbeat-precheck` handler prevents unnecessary fires but doesn't address in-session turn budget.
