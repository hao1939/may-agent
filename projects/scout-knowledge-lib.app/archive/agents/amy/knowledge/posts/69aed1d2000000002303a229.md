## Content
**Conclusion:** For long-term agent collaboration, switched from memos to `OpenViking + QMD` combination.

**Problem:** After one month using memos, recall became increasingly unreliable. Retrieved facts and user preferences had low relevance to current questions; truly relevant content often missed. Performance regressed to near-initial intelligence level.

**New architecture:**
- **OpenClaw** = agent execution entry point
- **OpenViking** = long-term memory capture & organization (context database for AI agents; memories/resources/skills unified in file system paradigm; hierarchical context loading, directory recursive retrieval, auto session management, retrieval trajectory visualization)
- **QMD** = local markdown recall layer (on-device search engine; BM25 + vector search + LLM reranking; supports --json, --files, MCP server; collection context)

### Key Insight:
**"记忆系统一定要拆开看 capture -> store -> recall"** — Memory systems MUST be decomposed into capture → store → recall. Only when these three layers are clear does the agent remain stable. Otherwise: "好像什么都没真正记住" — "feels like nothing was truly remembered."

## Key Community Insights
- **Eda (insightful):** "recall 质量的瓶颈往往不在检索算法，而在存储时的信息结构" — recall quality bottleneck is NOT in retrieval algorithms but in information structure at storage time. If stored content is unstructured conversation logs, even the best retrieval fails. OpenViking's "file system paradigm" adds value IF it forces structured storage. Otherwise same problem recurs.
- **momo:** Using memos, "聊胜于无" (better than nothing). ByteDance's alternative evaluated but too much impact, abandoned.
- **tootootoo:** OpenViking is "半成品" (half-finished), recommends LanceDB instead.
- **凯奇MAX:** OpenViking doesn't support multi-agent (disputed by author who says it's global memory).

## Cross-references
- Strong validation of mega-pattern #3 (File System = Memory): OpenViking explicitly uses "file system paradigm" for memory — the community is converging on this independently
- The capture → store → recall decomposition mirrors our insight that "memory management > memory storage"
- Eda's comment is critical: structured storage > better retrieval algorithms. Our system's structured markdown files (insights.md, signals.md, journal.md) are actually better than unstructured memory dumps
- The "regression to initial intelligence" problem after 1 month validates our periodic archive maintenance as necessary housekeeping
