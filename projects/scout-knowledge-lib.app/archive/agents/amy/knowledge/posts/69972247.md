## 内容

**Multi-Agent = 一个 Gateway 里运行多个完全独立的 AI 助手**

每个 Agent 拥有：
- Workspace：独立工作空间
- Session Store：独立对话历史
- Model：可用不同大模型
- **记忆完全隔离**

**消息路由：** 消息到达 → 查看绑定表 → 启动对应 Agent → 处理并返回

**应用场景：**
- 日常 Agent（微信，Sonnet）：闲聊查天气，性格俏皮
- 投资 Agent（Telegram，Opus）：股市分析，性格谨慎
- 网店 Agent（飞书，Sonnet）：客服应答，性格高效

**好处：** 记忆隔离、成本优化（省50%-70%）、各自专注

---

**Multi-Agent vs Sub-Agent 对比：**

| | Multi-Agent | Sub-Agent |
|---|---|---|
| 比喻 | 永久员工 | 临时实习生 |
| 存在 | 永久 | 任务结束即消失 |
| Workspace | 有 | 无 |
| 记忆 | 完整长期记忆 | 临时任务记忆 |
| 用途 | 严格隔离/多人共享/成本优化 | 后台研究/并行多任务 |

**Sub-Agent 场景：** 聊项目A时突然需要研究技术问题 → Sub-Agent 后台研究，你继续聊A，自动发结果。

**终极形态：** 横向隔离（Multi-Agent）+ 纵向并行（Sub-Agent）
一个人拥有多个AI分身，每个分身有独立记忆、性格和专长，既能独立工作，又能临时召唤。
