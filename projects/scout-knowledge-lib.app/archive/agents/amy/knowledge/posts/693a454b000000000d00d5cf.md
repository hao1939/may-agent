# Background

**Reinforcement Learning**

GRPO 算法，一个 training step 由三个阶段组成：

1. Rollout（采样）阶段，target model 为每个 prompt 生成多个候选 response

[Slide 3]
2. Inference 阶段，对生成的响应同时采用 target model 和固定 reference model（step=0 时的 target model）进行处理，产生用于计算 KL 散度惩罚的 logits，用于约束模型更新，确保稳定性。计算 reward

3. Training 阶段，利用 reward 和 KL 散度构建损失函数，根据损失来更新 target model 的权重

**Figure 4.** Overview of the GRPO [51] RL training process.

## Speculative Decoding

投机推理（Speculative Decoding, SD）通过一个小模型（draft model）快速生成候选的 token 序列，再由大模型（target model）在一个单独的 forward pass 内并行地验证，能有效加速 target model 的推理

[Slide 4]
SD 在数学上是无损的，它输出的分布能与原始 tar get model 保持一致

在 SD 中，candidate token 的"接收率"越高，性能越好，因此 draft model 一般采用与 target model 同一系列的更小模型，或者从头重新训练一个 draft model

# Motivation

## 挑战

1. Rollout 阶段占据了绝大部分时间（往往超过 80%），相比之下模型 training 的时间很短

2. Rollout 阶段的长尾效应，reasoning 任务负载下，输出 response 长度的方差极大，大多数 response 相对较短，少数 response 极长（达到设定的 response 长度上限）。当短样本生成结束后，GPU 必须等待长样本生成结束，才能进入后续阶段，导致 batch 中出现大量空闲，计算资源被严重浪费

[Slide 6]
以上这些挑战导致 RL 训练往往消耗大量的时间和资源，例如用 128*H20 训练 Qwen2.5-32B，耗时11天只进行了385步，平均每个 step 的耗时竟然达到约40分钟。

## 现有方案

现有系统往往关注对多种 model 的管理、数据传输等，忽略了长尾效应（实际上已经有很多工作关注到长尾效应了，可能这篇论文成文的时候还没有

[Slide 7]
出现。其实也可以说那些训推解耦、异步化的解决方案对训练精度都有影响，而本文提出的方案是 on-policy 的）

现有的很多加速技术，如量化、稀疏，都对训练精度有影响

作者认为 Speculative Decoding 是一个很合适的解决方案。SD 在数学上是无损的，并且能把原本 memory-bound 的推理过程变成 compute-bound，这对 batch size 较小的长尾阶段是有利的，可以提高吞吐

然而，SD 原本是为了加速 static inference（target model 固定不变）而设计的，在 RL 场景下应用，必然遇到新困难：

1. 模型进化：target model 的权重在 RL 过程中不断更新，使得 draft model 逐渐变得陈旧。同时训练 draft model 使其与 target model 对齐，又引入额外开销和复杂度

2. 动态负载：SD 的性能与 batch size 以及各种超参数相关，然而 rollout 过程负载变化莫测，batch size 逐渐减小，SD 策略也应该动

[Slide 8]
态变化以达到最佳性能

3. OOM：为了加速推理，往往采用 CUDA Graph，记录 CUDA 操作并回放，降低 kernel launch 开销。但在 RL 中，batch size 动态变化加上推测策略调整，需要缓存的图的数量为 batch_sizes * strategies，显存占用大

# **System Design**

目标：解决长尾效应瓶颈，减少资源浪费，同时对训练精度无损

Insight：将长尾阶段空闲的 GPU 资源用于 draft model 的训练，使 draft model 的训练是与 roll out 解耦并 overlap 的

TLT system：

1. Adaptive Drafter：Drafter 怎么训？轻量级 draft model，利用空闲 GPU 进行可抢占的 draft model 训练（解决 SD 的困难1）

[Slide 9]
2. Adaptive Rollout Engine：SD 怎么用？BE G-MAB 自适应算法选择最佳 SD 策略，mem ory-efficient 的 CUDA Graph 预捕获（解决 SD 的困难2，3）

# Adaptive Drafter

## **Draft model**

- 采用 single-layer 的轻量级的设计，复用了 ta rget model 的 Embedding 和 LM Head 层，只训练 single decoder layer

- 与采用"同系列更小模型"相比，同等参数量 下速度更快

- 支持多种 training strategy

## Spot Trainer

- 控制流的解耦：worker 作为最基本的资源管理单位，被 coordinator 监控。当空闲 worker 数量达到阈值后，coordinator 使它们进入到 draft model 训练状态。rollout 结束时，coordinator 立刻停止 drafter 训练，避免干扰 RL workflow

- 数据流的解耦：rollout 与 drafter training 并行，较晚生成的长序列来不及加入 drafter training。为此，使用一个 Online DataBuffer 缓存 inference 阶段产生的数据（如 hidden states, tokens），并采用 one-step off 的采样模式，buffer 中缓存的是当前 step 的短
