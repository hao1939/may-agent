你是否曾对大语言模型（LLM）的"随机性"感到困惑？我们都知道，LLM 在生成文本时，往往会有点"天马行空"，即使是同一个问题，也能给出不同的答案。这很正常，因为模型在生成下一个字词时，会进行一种"采样"操作，从多种可能性中概率性地选择一个。

但更让人不解的是，即使我们明确告诉模型要"老实一点"——把温度参数（temperature）设置为 0，这在理论上意味着模型应该贪婪采样（greedy sampling），总

这种"不确定性"就像科学实验中无法复现（reproducibility）结果一样，给研究和应用带来了很大的困扰。这篇文章，Thinking Machines Lab 的研究员们，正是要揭开这个谜团，找出导致 LLM 推理结果"变来变去"的真正原因，并提供解决方案。



**常见的误解：GPU 的并行计算 + 浮点数误差？**


一个非常普遍的解释是，GPU（图形处理器）在进行高速并行计算时，由于浮点数（floating-point numbers）的特殊性，导致了这种"不确定性"。

具体来说：

[Slide 3]
• 浮 点 数 非 结 合 律 （floating-point non-associativity）： 浮点数是计算机用来表示小数的一种方式。它和我们熟悉的整数不同，由于计算机存储空间的限制，浮点数的精度是有限的。这意味着，对于浮点数来说，(a + b) + c 的结果可能不等于 a + (b + c)。想象一下，你用有限位数的计算器，先算 (1/3 + 1/3) 再 + 1/3，和先算 1/3 + (1/3 + 1/3)，由于中间的舍入，最终结果可能略有不同。

• 并发执行 (concurrent execution)： GPU 有成千上万个核心（可以理解为微型处理器），它们同时进行大量计算。当这些核心同时对某些数字进行加法或乘法时，由于完成顺序的不确定性，浮点数的加法顺序可能会改变，进而导致最终结果的微小差异。
