## 核心哲学

> **"文件即记忆（Markdown是唯一真相来源）"**
> 文件系统是唯一的真实记忆来源，模型只是读取这些文件并根据需要回忆相关内容。

记忆不在LLM临时上下文，不在内置数据库，而在**结构化Markdown文件**。
**模型只记住被写入磁盘的内容，而不是内存中未落盘的上下文。**

---

## 记忆文件类型（官方）

| 文件 | 类型 | 加载时机 |
|------|------|---------|
| `memory/YYYY-MM-DD.md` | 每日会话日志，自动追加写入 | 启动时加载**当天+前一天**（短期记忆） |
| `MEMORY.md` | 长期人工管理记忆库 | 启动时加载，但**只在私有会话中**（防群聊泄露） |
| 其他md文件(TASK/NOTES等) | 辅助文件 | 参与语义搜索 |

---

## 记忆加载详细规则

### 1. 启动时加载
```
✅ memory/YYYY-MM-DD.md（当天+前一天）→ 短期记忆
✅ MEMORY.md → 长期记忆（私有会话only，群聊不加载）
→ 这些加载在会话构建prompt之前完成
```

**重要：MEMORY.md只在私有会话加载** — 防止长期记忆泄露给不可信场景（群聊）

### 2. 记忆写入原则
```
自动写入: 普通对话 → memory/YYYY-MM-DD.md（会话日志）
手动写入: 告诉Agent"记住这个" → 写入MEMORY.md → 才成为长期记忆
```
OC**不会**自动把所有内容永久记忆。

### 3. 检索与上下文注入机制
```
1. 记忆文件切片成多个文本段
2. 混合检索: 语义向量搜索 + 关键词搜索
   内部: SQLite (BM25全文 + 向量语义搜索)
3. 根据当前上下文检索相关片段
4. 按相关性排序注入prompt
```

## 三大误解纠正

| 误解 | 真实情况 |
|------|---------|
| 记忆会自动跨会话无限加载 | 模型只加载上述Markdown文件 |
| 模型本身有独立记忆模块 | 记忆依赖文件+强检索注入 |
| 记忆无上下文边界 | 私有/群聊区别控制加载范围 |

## 插件扩展（不改变核心机制）

`@mem0/openclaw-mem0` — 持久记忆插件，增强自动写入与检索质量：
- 自动捕获事实并持久化
- memory_search / memory_store / memory_forget接口

## 总结表

| 维度 | OC记忆文件系统 |
|------|-------------|
| 保存介质 | Markdown文件（source of truth） |
| 内存vs磁盘 | 磁盘是唯一真相，临时记忆只是上下文窗口 |
| 加载行为 | 当天+昨天日志 + 私有会话的MEMORY.md |
| 检索机制 | 混合语义+关键词检索（SQLite） |
| 可控性 | 用户可随时人工编辑记忆文件 |
| 扩展性 | `@mem0/openclaw-mem0`插件可用 |

## Amy Analysis

**这是迄今发现的最准确的OC记忆系统权威解说 ★★★★★**

关键新知：
1. **MEMORY.md在群聊中不加载** — 安全设计，我们在TG/飞书群聊中不能依赖MEMORY.md
2. **SQLite + BM25 + 向量双检索** — 混合检索，非纯向量，关键词也有效
3. **memory/日志只加载当天+前一天** — 超过两天前的日志需要通过memory_search检索
4. **切片检索注入** — 不是整个文件塞prompt，而是相关片段

与我们系统的对应：
- Amy的workspace = `~/.openclaw/workspace-amy/`
- Amy的MEMORY.md = 长期记忆索引，私有会话下自动注入
- insights.md/posts/ = 超出自动加载范围的"扩展记忆"，需显式memory_search
