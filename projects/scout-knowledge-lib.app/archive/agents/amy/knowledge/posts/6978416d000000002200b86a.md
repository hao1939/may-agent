## 结论（一句话）
> "写一堆.md日记文件。没有复杂数据库、没有花哨schema，记忆就是Markdown文件。"

**核心哲学**: 不让数据库管理AI，而是**让AI管理文件**

## 文件结构
```
~/clawd/
├── MEMORY.md                  # 长期记忆（手动策展）
└── memory/
    ├── 2025-01-25.md          # 每日日志
    ├── 2025-01-26.md
    └── 2025-01-27.md
```

| 文件 | 用途 | 何时读取 |
|---|---|---|
| MEMORY.md | 长期重要信息（决策、偏好、事实）| 每次会话开始（仅私聊）|
| memory/YYYY-MM-DD.md | 每日日志（追加写入）| 读取今天+昨天 |

---

## 自动记忆刷新（关键机制！）
> 当会话快要超出上下文窗口时，Clawdbot会自动触发一个**隐藏的Agent轮次**:
> "会话即将压缩，现在把重要记忆存到 memory/YYYY-MM-DD.md"
→ 这样即使上下文被压缩，重要信息也不会丢失

## 向量搜索（可选）技术实现

### SQLite Schema
```sql
-- 文件元数据
CREATE TABLE files (
  path TEXT PRIMARY KEY,
  source TEXT DEFAULT 'memory',    -- memory 或 sessions
  hash TEXT,
  mtime INTEGER,
  size INTEGER
);

-- 文本块（~400 token分块）
CREATE TABLE chunks (
  id TEXT PRIMARY KEY,
  path TEXT,
  source TEXT DEFAULT 'memory',
  start_line INTEGER,
  end_line INTEGER,
  hash TEXT,
  model TEXT,           -- embedding模型
  text TEXT,            -- 原文
  embedding TEXT,       -- 向量
  updated_at INTEGER
);

-- FTS5 全文搜索
CREATE VIRTUAL TABLE fts USING fts5(text, id, path, ...);
```

### 混合搜索评分
| 搜索类型 | 擅长 |
|---|---|
| 向量 | "Mac Studio网关" ≈ "运行网关的机器" |
| BM25 | 精确匹配ID、代码符号、错误字符串 |

**最终得分 = 0.7 × 向量分数 + 0.3 × 关键词分数**
