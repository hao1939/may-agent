【写在前面的话】

你以为 Agent 的记忆就是往 Prompt 里塞历史消息？最多再加一点离线的用户画像？

错。塞多了爆 token，塞少了健忘。

OpenClaw 的解法完全不一样——我深入阅读它的源码，发现 3 个精妙设计 👇👇👇

**1️⃣ Prompt 强制检索：不搜记忆不许回答**

OpenClaw 直接在 System Prompt 里写死规则：

【 "Before answering anything about prior work, decisions, dates... run memory_search" 】

意思是：回答前必须先搜记忆库。不是"建议"，是"强制"。

[Slide 3]
这招简单粗暴但有效——模型再懒也得先查资料。

2️⃣ **双重存储： 人能看 ＋ 机器能搜**


记忆分两层：

　　**显 式 记 忆**： Markdown 文 件（MEMORY.md），你能直接读写

　　**隐式索引**：SQLite 向量库，后台自动同步，把内容做成向量

　　为什么要两层？

　　人类需要可读性，机器需要可检索性。两者兼顾。

3️⃣ **混合检索：语义 ＋ 精确，双杀**


　　检索用了两种方式：

[Slide 4]
Vector Search（70%权重）：语义匹配（"这句话和那句话意思差不多"）

BM25（30%权重）：精确匹配（ID、代码符号、报错信息）

为什么要混合？

向量搜索语义理解好，精确 token 匹配不强，BM25 正好相反。

两者结合＝最佳召回率。

4️⃣ **Compaction：上下文快满了怎么办?**


每个模型都有 context window 限制。OpenClaw 的解法：

自动压缩：检测到快满 → 旧对话变 summary → 新请求 = summary + 最近消息

记忆刷盘：压缩前先提醒模型"把重要的

[Slide 5]
写到文件里"，然后才压缩。

　　避免关键信息被压没了。

**【最后总结】**


　　记忆不是魔法，是工程： Prompt 强制 + 双重存储 + 混合检索 + 压缩刷盘。
