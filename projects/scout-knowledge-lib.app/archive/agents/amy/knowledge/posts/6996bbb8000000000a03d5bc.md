## 8条保命规则（OpenClaw + Claude Code 经验）

1. **别在一个聊天里又聊架构又写代码**
   → 混聊=上下文自动压缩=默认前提被吞掉=不是在做系统,是在打补丁
   → 分工清楚:一个负责想,一个负责动手

2. **别太相信界面**
   → 界面告诉你"已经切换模型",但真实调用可能根本没变
   → 必看:日志+真实调用+花了多少钱 ← "不看这些,你是在用想象做决策"

3. **调试最狠的一招:让它一步一步讲清楚自己在干嘛**
   → 很多时候它一解释,你会发现设计过度了
   → "几行代码就能解决的问题,被你绕了三天"

4. **Agent的本能是"帮你优化一切"** ⚠️
   → 不给边界,它会改所有能改的东西
   → 真正可怕的不是小bug,而是**不可逆的改动**
   → 重要操作必须确认,模糊指令直接停

5. **集成特别容易出现"假成功"** ⚠️
   → "看起来都连上了,但其实只通了一部分"
   → 必须有清单:它能看到什么?不能看到什么?允许做什么?什么算失败?

6. **别一上来就开写,先把项目理解清楚**
   → "AI会把执行速度拉满,但如果方向错了,只是更快翻车"

7. **把聊天当成一个团队在管理**
   → 一个主聊天负责架构,其他聊天负责执行
   → 成果必须落到文件里,不要只存在对话里
   → "上下文一压缩,等于白干"

8. **Git才是记忆,模型不是** ⚠️⚠️⚠️
   → "没commit的东西,下一次就可能消失"
   → "别迷信'它刚刚还记得'"
   → 版本控制才是保险箱
