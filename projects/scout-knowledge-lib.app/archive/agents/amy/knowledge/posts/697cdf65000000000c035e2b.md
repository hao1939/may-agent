## 双轨制架构设计

```
两个需求维度:
  ① "在特定时间点必须做某事" → Cron Scheduler（精确触发）
  ② "每隔一阵子检查一下状态" → Heartbeat Runner（周期感知）

两者通过 System Events Queue 耦合！
```

---

## Cron调度器详细设计

### 存储与持久化
```
任务定义: ~/.clawdbot/cron/jobs.json（原子写入，防损坏）
运行日志: JSONL格式追加写入
→ Gateway重启后任务不丢失，状态自动恢复
```

### 触发机制
- 底层: Node.js `setTimeout`
- 最大延时限制约24.8天 → 动态计算下次最近任务时间
- 并发控制+锁机制(locked state) → 防止任务重复执行

### 执行模式：Main vs Isolated ← 最精彩部分

**Isolated Session（隔离模式）:**
- 目的: "不污染上下文"（数据分析/API轮询）
- 创建全新 `cron:` 会话，无任何历史记忆
- 可指定独立模型（便宜模型做简单检查/Opus做深度分析）
- 可指定Thinking Level
- 结果直接通过Adapter投递到Telegram/WhatsApp，不经过主聊天窗口

**Main Session（主会话模式）:**
- 目的: "融入对话"（20分钟后提醒我开会）
- 触发时**不立刻执行LLM推理**
- 而是向**System Events Queue注入一条事件**
- 等待下一次Heartbeat唤醒时，连同对话历史一起送入LLM
- Agent可结合上下文（"你刚才在聊代码"）自然处理提醒

---

## Heartbeat心跳机制

### 设计哲学："批处理"与"感知"
- 默认每**30分钟**运行一次
- 不执行具体脚本，而是将**HEARTBEAT.md清单**（检查邮件/日历等）扔给LLM
- LLM结合当前对话上下文+System Events Queue，**一次性处理所有检查项**

### 两大优势
1. **节省Token**: 5个检查项 → 1次LLM唤醒 vs 5个Cron各调1次
2. **智能抑制**: 无事可做 → 输出`HEARTBEAT_OK` → 系统拦截 → 用户**完全无感**

---

## Cron与Heartbeat的协作

```
wakeMode参数（Cron session:main 时）:
  wakeMode:"now"     → Cron触发后，立即强制运行一次Heartbeat（即时响应）
  wakeMode:"next-heartbeat" → 事件入队，等下次自然心跳（非紧急后台同步）

流程: Cron到点触发 → 产生System Event → 触发Heartbeat
```

## 使用场景决策矩阵

| 场景类型 | 推荐方案 | 示例 |
|---------|---------|------|
| 定期关注状态+结合上下文 | Heartbeat | 检查收件箱/日历/待办 |
| 精确时间+独立机械任务 | Cron(Isolated) | 每日早报/定期爬虫/健康检查 |
| 精确时间+融入主对话 | Cron(Main) | 会议提醒/倒计时 |
