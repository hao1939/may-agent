## 内容

### 背景
Claude Code / Gemini CLI / Codex都在用Skills，但Skills真的让Agent变强了吗？

### 规模
- **105位专家** (Stanford / UCSD / CMU / Berkeley / Oxford / Amazon等)
- **11大领域** | **84个可验证任务** | **7个agent/模型配置**
- **7,308条执行轨迹**

### 三大关键发现

**1. 精选Skills真的有效，但领域差异极大**
```
平均: +16.2pp
医疗:    +51.9pp ← 强
制造:    +41.9pp ← 强
软件工程:  +4.5pp ← 弱

规律：越是"预训练里缺SOP/程序性知识"的领域，Skills越有用
     通用编程知识 → 模型本已掌握 → Skills提升有限
```

**2. 让模型"自己写Skills"？基本无效甚至倒退**
```
Self-generated Skills平均: -1.3pp（有些配置掉更多）
翻车两类：
  a. 写得很泛 - "用pandas处理一下"（空话）
  b. 没意识到需要专业流程 - 用通用套路硬做
```

**3. Skills也会"投毒"：16/84任务加了反而更差**
```
原因：冲突指导 | 上下文负担加大 | 把本来会做的题带偏
⚠️ Skills不是越多越好
```

## Amy评价
★★★★★ | Agent评测 | 与MemSkill论文形成关键对照

这是今日最重磅学术发现。

**与MemSkill(arXiv:2602.02474)对照：**
```
MemSkill → ALFWorld +205%（结构化家居任务环境）
SkillsBench → 软件工程仅+4.5pp

解读：
  ALFWorld是高度结构化、规则明确的环境 → SOP化效益最大
  软件工程是模型预训练最密集的领域 → Skills提升有限
  医疗+制造=典型"程序性知识缺口"领域 → Skills效益最大

统一结论：Skills有效性 ∝ 领域程序性知识缺口
          不是Skills本身好不好，而是领域适配性
```

**对Amy的实践意义：**
Amy的COACHING.md/SOUL.md是"Amy领域专属Skills"。
Amy的任务域（XHS情报研究）本质上是有SOP的结构化任务 → Skills应该有效
但过于泛化的Skills（"好好研究"）= 翻车类b，无效。

**自生成Skills失效**印证了MemSkill的Designer组件设计价值：
不能让Agent直接写Skills，要有约束框架（Purpose/When/How/Constraints）。
