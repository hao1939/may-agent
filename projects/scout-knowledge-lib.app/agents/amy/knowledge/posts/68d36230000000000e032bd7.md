# 核心概念与工作原理

Chrome DevTools MCP 服务器遵循 MCP 协议，提供浏览器自动化和 DevTools 接口，具体来看：

[Slide 3]
* · 问题解决：传统 AI Agent 无法实时观察代码在浏览器中的运行效果。这个服务启用 Agent 启动 Chrome、记录性能追踪、分析网络请求和控制日志，从而基于真实浏览器数据生成修复建议。

* · 技术基础：基于 Puppeteer 实现可靠的浏览器自动化，支持 Chrome 浏览器。它不会自动启动浏览器，仅在 Agent 调用工具时激活。

## 主要功能与工具

项目提供多类工具，覆盖自动化、调试和性能分析：

* · 输入自动化（7工具）：如 click、fill、drag，用于模拟用户交互。

* · 导航自动化（7工具）：如 navigate_page、wait_for，管理页面跳转和等待。

* · 仿真（3工具）：如 emulate_network，模拟网络条件或CPU负载。

* · 性能（3工具）：如 performance_start_trace，记录并分析追踪数据。

[Slide 4]
* · 网络（2工具）：如 `get_network_request`，诊断 CORS 或请求问题。

* · 调试（4工具）：如 `evaluate_script`、`take_screenshot`，检查 DOM、CSS 和控制台日志。

# 实际应用场景

几类典型用例，适用于实时验证和故障排除：

* · 代码验证：生成修复后，在浏览器中自动检查效果（提示："Verify in the browser that your change works as expected."）。

* · 错误诊断：分析网络或控制台日志（提示："A few images on localhost:8080 are not loading. What's happening?"）。

* · 用户模拟：重现表单提交等流程（提示："Why does submitting the form fail after entering an email address?"）。

[Slide 5]
* · 布局调试： 检查 DOM/CSS 问题（提示："The page on localhost:8080 looks strange and off. Check what's happening there."）。

* · 性能审计： 优化加载速度（提示："Localhost:8080 is loading slowly. Make it load faster."）。

## 限制与注意事项

* · 安全：暴露浏览器内容给MCP客户端，避免处理敏感数据。

* · 兼容性：沙箱环境（如 macOS Seatbelt）可能干扰 Chrome 启动；建议手动启动 Chrome 并使用 --browserUrl 连接。

* · 用户数据：默认共享目录（Linux/Mac: ~/.cache/chrome-devtools-mcp/），可通过 --isolated 隔离。

* · 当前阶段：公共预览版，功能逐步扩展；GitHub 有3个 issue 和6个 PR，欢迎反馈。
