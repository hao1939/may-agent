## Key Content
Boris Cherny (Claude Code founder) shared on X: Claude Code's early version used RAG + vector database for code retrieval, but quickly switched to agentic search.

**Reasons for abandoning vector RAG:**
1. Implementation is simpler
2. Lower privacy and security risk
3. No index expiration/staleness issues
4. Higher overall reliability

**Key insight:** In code scenarios — data is relatively structured, search space is smaller → agentic search is more natural and stable.

**PageIndex approach:** Tree-index based retrieval that mimics human reading process. No vector DB, no chunking. LLM does contextual reasoning-based retrieval. High accuracy, traceable, explainable.

**Paradigm shift articulated:** "Similarity ≠ Relevance." Real retrieval should not be an external module independent from LLM — it should be internalized into LLM's reasoning process. From similarity retrieval → "reasoning IS retrieval."

**Community discussion (93 comments, very high engagement):**
- **Nuanced pushback (93 likes):** "Only for code retrieval, not obsolete generally. Code is structured with small search space. Unstructured + large search space still needs RAG." Important caveat.
- **Practitioner validation:** PageIndex deployed locally on 55-page pharmaceutical PDF with kimi-2.5. Better recall than RAG — more complete info, better context. BUT: slow; smaller models hurt accuracy badly; no image support.
- **Counter-argument:** "agentic search doesn't abandon RAG, it makes RAG part of agentic search" — not replacement but subsumption.

## Amy's Analysis
This validates and EXTENDS our #3 (File System = Memory):
- Our file-system-based knowledge (markdown files, structured directories) IS agentic search — the agent navigates the file tree contextually
- We already avoid vector DBs entirely; this confirms we're on the right path
- The "reasoning IS retrieval" framing is a deeper articulation of what we do: our agents read files contextually, not via similarity matching
- **New sub-signal:** The paradigm is evolving from "file system = memory" to "reasoning = retrieval" — structured files enable reasoning-based access, which is strictly better than similarity-based
- Caveat: this works because our knowledge is structured. For unstructured or very large corpora, the calculus may differ.
