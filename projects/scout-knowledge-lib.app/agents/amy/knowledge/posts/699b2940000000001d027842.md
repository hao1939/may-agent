我用 Claude Code 花 3 天时间开发了一个 AI Agent ：Akari。
	
Akari 的核心设计理念是"高密度上下文"（所有代码、实验、文档都在一个 repo 里）和 "极简"（唯一界面是 Slack Bot）。
	
Akari 采用 "使命驱动开发" 的方式：只给目标、资源和反馈，不指派具体任务，让它自主设计实验、分析数据、甚至自主改进自身代码，实现了"自我进化"。
	
Akari 的开发采用了 "反馈工程" 的概念，即通过精心设计的反馈来驱动 Agent 成长，而非手动编码。
	
AI 应用开发正处于没有前人铺路的探索阶段，但即使前路未知，微光犹自长明。

# 3天，我做出了自我进化的科研AI

用三天开发出AI智能体Akari，自主完成科研任务并自我进化，探索AI原生软件新可能。

[Slide 2]
大家好我是 VictoriaCity，也可以叫我 V。相比夜之城叱咤风云的 V，我还只是个 AI 领域的无名小卒。原谅我当 B 站 up 主的习惯，开头先报名字自我介绍。

我在春节假期花了 3 天，用 Claude Code 做出来了一个 AI 智能体 Akari。

它能帮我在我的工作领域做实验、分析数据、得出结论。

它能理解我的反馈，自己思考和给出改进行动项。

它能根据这些行动项自主改进自己的代码，自主汇总经验。

它能自我进化。


每个月十亿 Token

由于 PhD 期间在化学系做了 5 年机器学习，业余时间也做了很多 3D 创作相关的爱好，我现在在一家 3D GenAI 创业公司工作。

[Slide 3]
2026 年 1 月的某日，我想看看我每天多线程使唤 Cursor 要用多少 token，于是导出了近 1 个月的 cursor 用量，求了个和，结果是：10 亿。

花这么多 token，除了开发软件以外，我们还学到了一些可能比较有用的经验：

● 大模型总会有不确定性。之所以大模型写代码很强，是因为代码可以被编译器，linter，和单元测试验证。不确定的大模型需要确定性的"缰绳"（harness）。

● 人类工程师总结的最佳实践不一定对 AI 编程适用。比如 coding agent 可以在一天之内完成整个技术栈的重构，那么花大量时间与精力设计架构，做技术选型就没什么意义了。

● 人类写软件犯错误的方式也不一定对 AI 编程适用。比如 coding agent 会尝试在 python import 外面加错误捕捉，而不是把包乖乖装好到环境里避免报错。稍微学过 python 编程的都不会搞这种抽象操作。
