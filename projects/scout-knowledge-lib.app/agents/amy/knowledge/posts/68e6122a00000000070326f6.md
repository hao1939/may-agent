OpenAI 开源 Python 的 Agents SDK
	
用不到 100 行代码就能把“多智能体协作”写成普通 Python 函数，
Agent 之间像打电话一样“转接”，路由、状态、上下文全自动。
	
作者用客服分流举例，3 个 Agent、10 行代码就实现了“西班牙语/英语客服自动切换”，全程无 if-else。
底层只干三件事：LLM 调用 → 是否转接 → 执行工具；用状态机跑事件循环，外加装饰器把任意 Python 函数变成 LLM 工具。
生产注意三点：每次转接都是一次 LLM 调用（烧钱）、记得设超时、上线前把内存会话换成 Redis。
	
如果你已经熟悉 LangChain，可以把它当成“只做多智能体编排的轻量版”；
	
如果只想快速落地多角色 AI 流程，直接 pip install openai-agents 即可。

**先看个例子**

假设你要做个客服系统，需要根据用户语言自动切换到对应的客服。传统做法可能要写一堆 if-else 判断，还得维护状态。用这个 SDK，代码是这样的：

```
from agents import Agent, Runner
# 定义两个专业客服
spanish_agent = Agent(
    name="西班牙语客服", instructions="你只会说西班牙语")
english_agent = Agent(
    name="英语客服", instructions="你只会说英语")
# 定义一个分流客服
triage_agent = Agent(
    name="总台", instructions="根据用户语言转接到对应客服",
    handoffs=[spanish_agent, english_agent])
# 运行
result = Runner.run_sync(triage_agent, "Hola!")
```

就这么几行，系统会自动识别用户说的是西班牙语，然后把对话转给西班牙语客服。中间的路由逻辑、上下文传递、状态管理，全都自动处理了。

# 核心就三个概念

整个框架的设计哲学很克制，没搞一堆花里胡哨的抽象：

1. Agent（智能体）

就是一个配置对象，包含指令、可用工具、能转接的其他 Agent。类比微服务里的一个服务单元。

2. Handoffs（转接机制）

Agent 之间通过特殊的 function call 传递控制权。本质是责任链模式，但实现得很优雅——对开发者完全透明。

3. Tools（工具）

用装饰器把普通 Python 函数变成 LLM 可调用的工具：

```
@function_tool
def query_database(user_id: str) -> dict:
    """查询用户信息"""
    return db.get_user(user_id)
```
