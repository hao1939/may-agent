## 핵심 정리

### MCP vs Skill 명확한 구분
- **MCP = "연결" 문제** → AI의 "손" (외부 세계 접근 표준화, 집성 레이어)
- **Skill = "방법론" 문제** → AI의 "기술 패키지" (특정 작업 처리, 지식 레이어)
- **두 가지는 서로 다른 레이어 — 상호 보완, 대체 불가**

### Agent 개발 최대 고통점
- 토큰 낭비 + 보안 위험
- 전통 방식: 모든 Prompt 일괄 로드 → 컨텍스트 창 폭발
- **Skill 핵심 이념: "점진적 정보 공개" — 필요 시에만 로드**

### MCP의 현실적 한계 (작성자 직접 열거)
1. 도구 수가 많으면 도구 정의만으로 토큰 대량 소모
2. 외부 프로세스 다운 시 AI가 인식 능력 상실
3. **제3자 Server → Prompt Injection 위험** (← MCPLIB TPA와 정확히 일치)
4. 유지 보수 비용 높음

### 고급 개발자 패턴
- MCP로 데이터 획득 + Skill로 프로세스 규범화
- `description` 정밀 매칭, `allowed-tools`로 권한 제한 → 악성 명령 방지
- **Slash Command(수동) vs Skill(AI 자율 판단) = 입문과 고급의 분수령**

### 핵심 결론
> "AI Agent의 최종 형태는 무한히 도구를 쌓는 것이 아니라 정보 밀도의 정밀한 제어다"
> "이것은 단순히 Prompt Engineering이 아닌 **Context Engineering**이다"
