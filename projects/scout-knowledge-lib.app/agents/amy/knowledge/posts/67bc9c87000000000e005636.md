3. **Group Chat**

此机制可以由下面的流程示意文字表达及图片：

1. 首先，用户或外部代理向所有参与者的公共主题发布一条 GroupChatMessage 消息。

2. Group chat manager选择下一个发言者，并向该代理发送一条 RequestToSpeak 消息。

3. 代理收到 RequestToSpeak 消息后，向公共主题发布一条 GroupChatMessage 消息。

4. 这个过程一直持续到群聊管理器达到终止条件，然后停止发送 RequestToSpeak 消息，群聊结束。

# 5. Mixture of Agents

概述流程可以如下：

1. orchestrator agent 接收用户任务，首先将其调度到第一层的worker agents。

2. 第一层的worker agents处理任务并将结果返回给orchestrator agent。

3. orchestrator agent随后综合第一层的结果，并将带有先前结果的更新任务派发到第二层的worker agents。

4. 该过程持续到达到最后一层。

5. 在最后一层，orchestrator agent汇总之前层的输出，并向用户返回一个单一最终结果。

# 6. Multi-Agent Debate

概述流程可以如下：

1. 用户向aggregator agent发送一个数学问题。

2. aggregator agent将问题分配给solver agents

3. 每个solver agent处理问题，并向其邻居agent发布响应。

4. 每个solver agent使用其邻居的响应来完善自己的响应，并发布一个新的响应。

5. 重复第 4 步，进行固定次数的轮次。在最后一轮，每个solver agent发布最终响应。

6. aggregator agent使用多数投票来汇总所有solver agent的最终响应以获得最终答案，并发布该答案。
