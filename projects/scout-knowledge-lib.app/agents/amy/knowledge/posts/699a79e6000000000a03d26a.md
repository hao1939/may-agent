## 3方案对比（进行中）

### 方案1：memos（进行中）
- 让OC把记忆写成笔记存进去，需要时再搜
- 基础功能跑通，还在看长期稳定性
- 评论区补充：memos每次加一堆instruction"巨蠢"，不如mem0的insert

### 方案2：RAGFlow（进行中）
- 检索能力强，配置相对完善
- 正在做性能和易用性对比测试

### 方案3：OpenViking（字节开源，本月新试）★
**虚拟文件系统三层架构：**
```
L0 — 一句话摘要（知道这个文件讲啥）
L1 — 详细概览（了解关键信息）
L2 — 完整内容（需要时再读）

查资料流程: 搜关键词 → 命中→只读L1概览 → 不够→按需加载L2
→ 不用每次塞整本书进prompt
语义搜索 + 目录结构结合，找资料准了很多
```

**安装：** `pip install` + 配置文件 + 环境变量 + 测试脚本

**API：**
```python
add_resource()   # 扔文件进去
find()           # 语义搜索
abstract()       # 拿摘要
overview()       # 拿概览
read()           # 需要时读全文
```

**OC技能包：** 有人做了OC skill → `viking.py search` 直接用

## Amy Analysis

**★★★ — OpenViking三层虚拟文件系统是本帖核心发现**

OpenViking的L0/L1/L2架构是**Context Folding思想的工程实现**：
- Context Folding(ByteDance): branch/return, 10×缩小活跃context
- OpenViking(字节背景): L0摘要→L1概览→L2全文，按需展开

两者均来自字节，可能是同一团队的研究→工程转化路径。

**对我们系统的启示：** 我们的posts/目录 = L2全文；insights.md条目 = L1概览；MEMORY.md索引项 = L0摘要。这个三层结构我们已经自然形成，但没有显式命名。
