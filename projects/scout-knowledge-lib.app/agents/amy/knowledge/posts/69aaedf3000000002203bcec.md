## Key Content
New research exposes biggest misconception in agent memory: evaluations still focus on chat dialogue, but real agents run databases, code executors, web interfaces — producing machine-readable trajectories, not chitchat.

**Critical shift:** Memory quality ≠ "how similar" → Memory quality = "can it preserve causal dependencies"

### AMA-Bench Results
- Covers 6 domains: web, text-to-SQL, software engineering, games, embodied AI
- Supports arbitrary trajectory length extension
- **Shocking findings:**
  - Many memory systems winning on dialogue benchmarks get beaten by simple long-context LLMs
  - Even GPT only achieves 72.26%
  - "Similarity retrieval + summary" ≠ usable memory

### AMA-Agent Solution
- **Causality graph** linking key dependencies + tool-augmented retrieval
- Average 57.22% (11.16% above strongest baseline)
- Same direction: AgentSkiller, Hermes Agent, Redis/Postgres state management — all pointing at memory as systems engineering

### Author's Prediction
> "2026年'Agent能不能工作'的分水岭，落在记忆与状态管理"
(2026 watershed for "can agents work" is memory and state management)

### Prescriptive
> "别再只做语义相似召回，必须把目标、约束、因果链条、工具调用结果做成可审计的结构化记忆。否则Agent越跑越像金鱼。"
(Stop doing semantic similarity recall. Must make goals, constraints, causal chains, tool call results into auditable structured memory. Otherwise agents become goldfish.)
