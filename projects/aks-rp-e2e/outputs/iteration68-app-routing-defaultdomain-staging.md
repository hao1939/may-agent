# Iteration 68 — App Routing Default Domain Staging Validation

**Date:** 2026-05-19  
**Feature focus:** Web App Routing/App Routing public AKS API default-domain state (`ingressProfile.webAppRouting.defaultDomain`)  
**Staging target:** `devbox:/home/hayua/rp` using Azure CLI + `aks-preview`  
**Verdict:** PASS for public CLI/API state enablement. `az aks approuting enable --enable-default-domain` reached RP, exited `0`, and persisted `ingressProfile.webAppRouting.enabled=true` plus `ingressProfile.webAppRouting.defaultDomain.enabled=true` with an autogenerated `*.eastus2.aksapp.io` domain name.

## Why this iteration ran

Iteration 67 closed the App Routing disable gap. The next unresolved App Routing/capability-model gap was default-domain public API/state behavior: older standalone evidence failed the end-to-end default-domain traffic scenario because the required TLS secret was not provisioned, while iteration 59 only showed that plain `az aks approuting enable` leaves `defaultDomain.enabled=false`. This iteration intentionally validated the narrower public API/state contract, not HTTP route reachability.

```python
def aks_approuting_update(
        cmd,
        client,
        resource_group_name,
        name,
        keyvault_id=None,
        enable_kv=False,
        nginx=None,
        enable_default_domain=False,
        disable_default_domain=False
):

    if enable_default_domain and disable_default_domain:
        raise CLIError("Conflicting flags. Cannot --enable-default-domain and --disable-default-domain at the same time.")

    return _aks_approuting_update(
        cmd,
        client,
        resource_group_name,
        name,
        keyvault_id=keyvault_id,
        enable_kv=enable_kv,
        nginx=nginx,
        enable_default_domain=enable_default_domain,
        disable_default_domain=disable_default_domain)
```

From `custom.py`, the show command reads `mc.ingress_profile.web_app_routing.default_domain` and errors if App Routing/default domain is absent:

```python
def aks_approuting_default_domain_show(
        cmd,
        client,
        resource_group_name,
        name
):
    mc = client.get(resource_group_name, name)

    if mc.ingress_profile and mc.ingress_profile.web_app_routing and mc.ingress_profile.web_app_routing.enabled:
        if mc.ingress_profile.web_app_routing.default_domain:
            return mc.ingress_profile.web_app_routing.default_domain
        raise CLIError('Default domain is not configured for this cluster')
    raise CLIError('App routing addon is not enabled')
```

## Conclusion

The public CLI/API state contract for App Routing default-domain enablement passes in staging. `az aks approuting enable --enable-default-domain` both enables Web App Routing and persists `defaultDomain.enabled=true` with an autogenerated domain name visible through `az aks show` and `az aks approuting defaultdomain show`.

This does **not** overturn the older failing standalone `app-routing-default-domain` traffic scenario: that scenario expected route reachability/HTTP 200 and failed due to missing TLS secret provisioning. The narrower state/API gap is now closed; traffic reachability with a properly provisioned default-domain app remains a separate follow-up if needed.
