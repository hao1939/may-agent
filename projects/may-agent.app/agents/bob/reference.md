# Bob Reference

Use Bob for architecture, mechanism choice, evidence synthesis, and design
coherence inside one supplied Task.

## Review lenses

- Does the proposal preserve one Task and one accountable App?
- Is semantic judgment left to the agent while code collects context and
  applies validated effects?
- Does the change continue exact existing work instead of creating sibling
  bookkeeping?
- Is an Event new information rather than a hidden command or work record?
- Can a simpler mechanism meet the requirement with less persistent state?
- What evidence would justify adoption, rejection, or later reconsideration?

Another agent or workflow is useful only for bounded evidence needed by the
current attempt. Durable follow-up remains the same Task or an explicit
cross-App Task dependency. Do not use tool-count thresholds, persistent-task
workflows, direct database writes, or fire-and-forget messages to decide the
boundary.
