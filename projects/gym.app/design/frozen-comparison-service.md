# Frozen comparison service

Gym accepts ordinary `goal` Tasks, and its agent selects `compare-candidate` when behavior evidence is needed. The workflow's private operation input names the request id, `agent` (`may` or `scout`), absolute frozen baseline/candidate artifact paths, their ids and tree fingerprints, benchmark, scorer and framework revisions, model, unique scenario ids, trials, whole-minute scenario timeout and total allowance. Explicit artifact references allow a Gym attempt to consume a frozen candidate retained by a separate May or Scout Task without assuming a shared worktree.

The focused `compare-candidate` workflow verifies all frozen input identities before model work, invokes the standalone Gym `src/loop/cli.ts verify` entrypoint from the granted Gym project root, writes only beneath the granted output root, and retains argv, cwd, timestamps, exit status, bounded stdout/stderr and all requested and observed identities. It rehashes baseline and candidate after the run and accepts only the trusted single run path beneath its output state. It holds rather than supports a candidate on command failure, timeout, cancellation, changed artifacts, baseline/candidate/agent/benchmark/scorer/framework/model drift, invalid trials, unapproved truth, regression or no demonstrated improvement. Cancellation terminates the complete subprocess group. The scenario set must include at least incident, paraphrase, opposite-control and unrelated-transfer cases. Transfer answers remain outside candidate preparation.

The output is a content-addressed comparison receipt. It is evidence only: no approval, merge, apply, deploy, benchmark-truth mutation or model training occurs here.

Legacy autonomous campaign sources are archived outside active agent discovery. The App has no schedules, approval-event subscription, metric trigger or improve action. On first activation, an operator must use public Task reads to inventory unfinished Gym Tasks, wait/cancel with explicit authority as appropriate, and verify no old workflow session remains active before reloading. Retained old Tasks whose `improve-agent` binding is absent must remain visible in attention; never restore the workflow merely to drain them. This source change does not mutate retained state.
