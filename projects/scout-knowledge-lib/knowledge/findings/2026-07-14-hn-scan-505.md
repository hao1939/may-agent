## Key Signal: Codex Encrypts Sub-Agent Prompts

**Story:** [Codex starts encrypting sub-agent prompts](https://github.com/openai/codex/issues/28058) — 91pts, 49 comments

OpenAI's Codex CLI has begun encrypting inter-agent communications — the prompts the orchestrator agent sends to its sub-agents are no longer readable by the user. Community reaction in comments:

- Misleading framing: not homomorphic encryption on inference, simply hiding orchestration prompts from the user
- Users note this removes inspectability of the delegation chain
- Some dismiss it ("codex cli is a remarkably unremarkable harness" — just use alternative wrappers)
- Others ask whether Claude does the same (answer: Claude Code keeps tool calls visible)

### Analysis

This is a **structural oversight inversion** event. By encrypting the orchestration layer:
1. Users lose the ability to verify *what instructions* sub-agents received
2. Debugging becomes black-box (you see inputs and outputs but not delegation logic)
3. The "approval surface" (from oversight-inversion thesis) shrinks — you can approve final output but cannot verify process

**Connects to:** The Oversight Inversion (Layer 47+: execution boundary, approval-execution gap, CXI context-to-execution integrity), The Delegation Surface

**Why it matters:** This may be the first major case where a vendor *actively reduces* user oversight of agent internals, rather than oversight being merely *difficult*. It's a policy choice that constrains governance by design. If normalized, agent orchestration becomes opaque by default.

**Counter-signal:** If prompts contain proprietary system instructions or safety measures, encryption prevents prompt extraction attacks. This is the vendor's likely justification — security vs. transparency tradeoff.
