### C-Trace: Runtime Compliance Enforcement for GDPR (2606.19242)
**Source**: https://arxiv.org/abs/2606.19242

First runtime compliance verification framework for AI agents under GDPR. Expresses consent, purpose limitation, data minimization, and right to erasure as formal policy predicates over agent execution traces. Runtime monitor intercepts every tool invocation and model output.

**Key results**: Under 10% per-category extractor noise, attack success rate ≤12%, false positives ≤16%. Under perfect extraction: 0% ASR.

**Significance for revocability**: GDPR's "right to erasure" is literally capability revocation — the right to force an agent to un-know something. C-Trace shows this is technically implementable at runtime, but the extraction noise problem (10% → 12% ASR vs 0% → 0% ASR) demonstrates the gap between formal specification and practical enforcement.

**Connection to scan #177 (Informality Tax)**: C-Trace is the formalization of privacy compliance — moving from "we promise to comply" to "the monitor proves compliance at runtime." Extends the VIGIL pattern (§2.40 in agent-security-verified-enforcement.md) from behavioral specs to regulatory specs.

## Synthesis: The Revocability Default

Every signal on today's HN front page shares a structural pattern: **capability provisioned by another entity is revocable by that entity**.

| Layer | Capability | Revocable By | Today's Signal |
|-------|-----------|-------------|---------------|
| Model access | Frontier inference | Government / provider | GPT-5.6 vetting, Mythos "trusted partners" |
| Digital ownership | Purchased content | Platform / licensor | PlayStation deleting 551 movies |
| Fabrication | 3D printing | State legislation | California slicer mandate |
| Open weights | Model availability | Philanthropy withdrawal | "Spigot can be turned off" |
| OSS projects | Code availability | Author deletion | DOCX editor vanishing |
| Physical infra | Data center construction | Voter backlash | Utah primary loss |
| Routing cache | Accumulated context | Model switch | Weave Router cache miss |
| Regulatory compliance | Data processing | Data subject erasure request | C-Trace GDPR enforcement |

**The one exception proves the rule**: Memory writes to agent behavioral stores (scan #175, Memory Depth) are the one thing we identified as effectively irrevocable — parametric consolidation permanently alters agent behavior via LoRA updates. We flagged this as *dangerous* because writes have no controls. But the Revocability Default reframes this: **irrevocability is the exception, not the rule, and it's the exception precisely where we have no governance**.

**Design principle**: Systems should be designed for the revocability default — assume any provisioned capability can be withdrawn, and build persistence into local, owned layers:

1. **Knowledge in owned files** (markdown-in-git, not API-dependent knowledge bases)
2. **Skills as reusable local artifacts** (not marketplace-dependent)
3. **Scaffold as primary investment** (model-independent process discipline — per RigorBench)
4. **Memory governance** (the only irrevocable layer needs the strongest controls)

**Connection to prior scans**:
- Sovereignty Stack (#189): Revocability is how each layer exercises sovereignty
- Verification Bankruptcy (#178): Verification is revocable when the verified system changes
- Supervision Cost Spiral (#191): Supervision is what makes revocability visible — unsupervised revocation is silent
- Formalization Pressure (#190): Formal specifications are the only revocation-resistant contracts
