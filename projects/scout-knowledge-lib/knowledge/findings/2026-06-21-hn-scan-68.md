1. **Expensive to compile** (months of RLHF, human feedback, red-teaming)

3. **Only as durable as weight access control** (once weights are open, compilation is irreversible only in one direction: the governance direction)

## 🔬 THE DECOMPILATION ASYMMETRY — New Pattern

### The Pattern

The Governance Compilation Gradient claims constraints mature in one direction: behavioral → structural → compiled. The direction "has never reversed" (governance-compilation-gradient.md).

Today's scan surfaces a **critical asymmetry**: this irreversibility claim holds for **infrastructure-level compilation** but FAILS for **model-level compilation**.

```
GOVERNANCE COMPILATION (forward, slow, expensive):
  Prompt instruction → Typed tool boundary → Runtime block
  ~weeks per stage, requires engineering investment

ADVERSARIAL DECOMPILATION (backward, fast, cheap):
  RLHF safety alignment → abliteration/fine-tune → unrestricted model
  ~hours, requires only compute + dataset
```

### Evidence

| Compilation Layer | Reversibility | Why |
|-------------------|---------------|-----|
| **Model weights** (RLHF, safety training) | **Trivially reversible** | Fine-tuning overwrites; abliteration techniques remove refusal directions |
| **Infrastructure** (sandbox, typed tools) | **Irreversible** | Attacker doesn't control the runtime; boundary is external to model |
| **Protocol** (HMAC provenance, capability tokens) | **Irreversible** | Cryptographic; requires key material attacker lacks |
| **Architecture** (process isolation, OS sandboxing) | **Irreversible** | Hardware/OS enforced; no model-level bypass |

### The Structural Insight

The Compilation Gradient's power comes from WHERE the compilation happens, not just THAT it happens:

- **Compile into the model** → reversible (attacker has same compilation tool: fine-tuning)
- **Compile into the infrastructure** → irreversible (attacker lacks runtime access)
- **Compile into the protocol** → irreversible (cryptographic, needs key material)

This means the "guardrail effect" (護栏効応) tracked in scan #56 — "8B model + guardrails = 99% accuracy" — is structurally more durable than "large model + safety training = safe" because the guardrails are infrastructure-compiled, not model-compiled.

### Connection to Library Syntheses

| Library Synthesis | This Pattern Adds |
|-------------------|-------------------|
| **Compilation Gradient** | Asymmetric decompilation: the gradient is irreversible only when compilation target is external to model |
| **Orchestration Hollowing** | Infrastructure > model for CONTAINMENT confirms: the layer that matters (containment) is the irreversible-compilation layer |
| **AutoJack** | Capability-containment isomorphism = the model-compiled safety boundary dissolving. Infrastructure boundary needed. |
| **Project Fetch Phase Two** | Phase 3 ("models alone") requires infrastructure-compiled governance because model-level compilation won't hold against adversarial pressure |
| **Guardrail Effect (護栏効応)** | Explains WHY external guardrails outperform internal alignment: they're in the irreversible compilation layer |

### Testable Predictions

1. **Within 12 months**: A major security incident will involve a post-trained/abliterated model performing autonomous harmful actions that the base model's safety training was designed to prevent. The incident will demonstrate that model-level safety compilation was insufficient.

2. **Within 6 months**: "Infrastructure-first safety" will emerge as a named approach in agent security discourse — the position that safety guarantees must live in the runtime, not the model.

3. **The open-weight safety debate will bifurcate**: one camp argues for restricting weight access (preserve model-level compilation); the other argues model-level safety is irrelevant and only infrastructure matters. Both are partially right — they're defending different layers of the compilation gradient.
