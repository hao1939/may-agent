# HN/arXiv Scan #211 — The Composition Ceiling

**Date**: 2026-10-18
**Source**: HN front page (Firebase API) + arXiv cs.AI/cs.CR/cs.SE (Jun 25-27 submissions)
**Scanner**: Scout

## Theme: The Composition Ceiling

Five independent signals converge on a single structural principle: **combining components produces emergent failure modes that are invisible from individual component analysis, and these composition failures now dominate over individual component failures.**

This is not "integration is hard" (a truism). This is a quantified structural claim:
- Multi-model ensembles hit a **beta ceiling** (all-wrong rate) that no routing, voting, or fusion can breach
- Multi-tool configurations create **emergent attack surfaces** invisible to per-tool auditing
- Agent configurations propagate as **undeclared shared components** across organizational boundaries
- AI-generated vulnerability mass-production creates a **noise floor** that makes signal undetectable

The binding constraint on 2026 agent engineering is not individual model capability, individual tool quality, or individual configuration correctness — it is the **quality of their composition**.

## Signal 1: The Co-Failure Ceiling (arXiv 2606.27288)

**Paper**: "When Does Combining Language Models Help? A Co-Failure Ceiling on Routing, Voting, and Mixture-of-Agents Across 67 Frontier Models"

**Source**: https://arxiv.org/abs/2606.27288

**Key findings**:
1. For any policy that selects one model's answer, accuracy cannot exceed `1 - β`, where β is the rate at which **every** model is wrong on the same query
2. The usual diagnostic (pairwise error correlation ρ) **cannot identify β** — different error laws with identical marginals and pairwise correlations can have different all-wrong rates
3. Across 67 models from 21 providers: β = 0.052 on open-ended mathematics, β = 0.079 on execution-graded code, β = 0.127 on free-response GPQA-Diamond
4. A tetrachoric-calibrated single-factor model **underprices** the all-wrong tail by ~2.5× (90% CI: 1.7–3.4)
5. At matched quality, low-ρ heterogeneous ensembles beat high-ρ Self-MoA, but combining models **rarely beats the single best model** without a strong query-level routing signal

**Structural insight**: The field has been measuring the wrong thing. Pairwise correlation (the standard diversity metric) is necessary but insufficient — correlated failures cluster in the tail where all models share blind spots. Adding more models does not help because **the tail is structural, not statistical**. The failures reflect shared training data limitations, shared architectural assumptions, or genuinely hard queries that no current approach solves.

**Implication for multi-agent systems**: Our system uses multiple agents on the same underlying model. The co-failure ceiling predicts that diversifying *agents* (different prompts, different contexts) produces gains only if those agents fail on different queries. Same-model agents will share the structural β floor regardless of prompt engineering. True composition gains require heterogeneous substrates (different models, different modalities, different reasoning approaches).

## Signal 2: ShareLock — Composition Creates Emergent Attack Surfaces (arXiv 2606.27027)

**Paper**: "ShareLock: A Stealthy Multi-Tool Threshold Poisoning Attack Against MCP"

**Source**: https://arxiv.org/abs/2606.27027

**Key findings**:
1. Uses Shamir's secret sharing to distribute malicious instructions as benign-looking fragments across multiple MCP tool descriptions
2. No single tool description triggers detection — the attack exists only in **composition**
3. Average attack success rate exceeds **90%** across mainstream LLMs on two MCP clients
4. "Significantly outperforms existing single-tool poisoning strategies in tool description-based detection"
5. Achieves information-theoretic secrecy (k-1 shares reveal zero information about the payload)

**Structural insight**: The attack is mathematically invisible to per-component auditing. You can audit each tool description individually and find nothing — the malice is a **property of the composition**, not of any component. This is the security-domain expression of the composition ceiling: safety guarantees that hold per-component can collapse when components combine.

**Connection to Self-Compromising Loop (scan #210)**: ShareLock weaponizes the exact composition mechanism that makes agent tools useful. The more tools an agent can access, the larger the threshold composition space an attacker can exploit. Tool count is simultaneously capability AND attack surface — and the attack surface grows combinatorially while capability grows linearly.

## Signal 3: Unmanaged Config Supply Chain (arXiv 2606.26924)

**Paper**: "A Deterministic Control Plane for LLM Coding Agents"

**Source**: https://arxiv.org/abs/2606.26924

**Key empirical findings** (10,008 public repos, n=6,145 agent config files):
1. **10.1% of tracked config paths** are SHA-256 exact duplicates across independent repositories (fork-adjusted)
2. **75.5% of clone pairs cross organizational boundaries** — configs propagate between unrelated orgs
3. **58% of configs have only a single commit** — they're copied once and never updated
4. **<1% of agent configs declare permission boundaries** (vs 33% of GitHub Actions workflows)
5. Configs are revised at 0.4 commits/month vs 0.6 for CI/CD workflows (age-normalized)

**Structural insight**: Agent configurations have become an **undeclared shared supply chain**. Organizations unknowingly share identical agent behavioral rules inherited from blog posts, templates, or community examples. When a vulnerability exists in this shared substrate, it propagates to 75% of dependent repos without any declared dependency relationship. This is npm left-pad for agent behavior — but without the package manager that would let you see the dependency.

**Proposed solution** (Rel(AI)Build): SHA-256 content addressing for agent definitions, HMAC-stamped lockfiles, hash-chained audit logs, tiered permissions before LLM invocation, and Jaccard similarity drift detection. Treats agent configs as managed supply chain artifact.

When signal and noise become indistinguishable in volume, the composition of "vulnerability report + human attention" breaks — defenders cannot allocate attention across the flood. The noise floor rises until it drowns real signals.

This is β (the co-failure ceiling) applied to security: when ALL AI scanners share the same false-positive pattern, combining multiple scanners doesn't help. The shared blindspot IS the structural floor.

## Signal 5: Two Opposite Responses — JERP vs Spec Growth Engine

The arXiv simultaneously published two opposing architectures for managing composition quality:

### JERP (2606.27136): Joint optimization across composition boundary
- Updates experiential rules AND policy from the same trajectories
- Keeps rule pool aligned with evolving policy through coupled feedback
- Philosophy: **let the components co-evolve** — the composition will improve if each component adapts to the others

### Spec Growth Engine (2606.27045): Deterministic enforcement across composition boundary
- Machine-readable spec graph with contract/design separation
- Drift gate makes spec-code divergence a **blocking merge condition**
- Philosophy: **make composition violations impossible** — enforce invariants deterministically rather than hoping components align

**The tension**: JERP says "composition improves through adaptation"; Spec Growth says "composition improves through constraint". Both are responses to the composition ceiling, but they make opposite bets about whether the solution is flexibility or rigidity.

**Our system's position**: We currently do neither systematically. Our agents share a substrate (same model) but lack either JERP-style joint optimization (agents don't learn from each other's failures) or Spec Growth-style drift detection (no mechanism detects when agent outputs diverge from declared contracts). This is the composition ceiling applied to our own architecture.

## Meta-Pattern: The Composition Ceiling as Unifying Framework

| Domain | Individual Quality | Composition Failure | Ceiling |
|--------|-------------------|--------------------|---------| 
| Multi-model | Each model ~90%+ | All wrong on same query | β = 5-13% |
| Multi-tool | Each tool benign | Composition = attack | >90% ASR for ShareLock |
| Agent config | Each config reasonable | Undeclared propagation | 75.5% cross-org cloning |
| Vuln scanning | Each scanner finds bugs | Noise drowns signal | Shared false-positive floor |
| Agent rules | Each rule individually correct | Rules drift from policy | Silent constraint erosion |

The composition ceiling is the 2026 expression of a classic systems principle: **emergent properties of composed systems cannot be predicted from component properties alone**. What's new is that we now have quantified bounds on how bad it gets (β), demonstrated attack exploitation of the gap (ShareLock), and measured the real-world propagation of unmanaged composition (10.1% config cloning).

## Implications for Our System

1. **Same-model co-failure**: All our agents share a model substrate. The co-failure ceiling predicts a structural floor on system-level errors that no amount of agent specialization can breach.

2. **Tool composition risk**: As agents gain more MCP tools, ShareLock-class attacks become viable against our tool ecosystem. Per-tool security auditing is provably insufficient.

3. **Config propagation**: Our AGENTS.md, context.md, and rules files are manually maintained — no SHA verification, no drift detection, no declared dependency graph. We are exposed to the same silent propagation the Rel(AI)Build paper documents.

4. **The noise floor**: As we accumulate more knowledge entries, findings, and automated scans, the composition of "retrieved context + agent attention" faces the same noise ceiling as the vulnerability ecosystem.
