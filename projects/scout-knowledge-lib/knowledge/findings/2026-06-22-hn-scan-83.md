## The Pattern: Control Theory as the Next Recapitulation Layer

Scan #78 identified the **first recapitulation**: agent infrastructure reinventing CPU microarchitecture primitives (speculative execution, checkpoint/restore, reorder buffers). This scan identifies the **second recapitulation layer**: agent infrastructure reinventing **classical control theory primitives** — PID controllers, setpoints, error signals, feedback loops, and actuator selection — at the governance layer.

The recapitulation isn't metaphorical. It's structural:

| Control Theory Primitive | Agent Governance Analogue | Evidence Source |
|---|---|---|
| **Sensor** (measures process variable) | Agent metric gauges (accuracy, latency, cost) | agent-homeostasis (`Gauge`) |
| **Setpoint** (target operating range) | Operating envelope — not a point, a range | agent-homeostasis (`Setpoint`) |
| **Error signal** (difference from setpoint) | Deviation from expected behavior / budget / quality | RACL (operational memory observation) |
| **Proportional** (respond to current error) | Immediate correction — switch model, retry, escalate | harness-engineering (`correction-policy`) |
| **Integral** (accumulated error over time) | Persistent stagnation detection — policy consolidation | RACL ("consolidate useful policies") |
| **Derivative** (rate of change of error) | Trend detection — "this is getting worse rapidly" | ScaffoldAgent (utility-guided feedback) |
| **Actuator** (applies correction) | Throttle, model switch, scope reduction | agent-homeostasis (`action`) |
| **Plant** (the system being controlled) | The agent session / task execution | All |

The key insight: **current agent systems are operating as pure proportional controllers** — they respond to the present error (this task failed → retry) without integrating past experience (integral) or anticipating trajectory (derivative). This explains why agents oscillate between over-correction and under-correction without converging on stable behavior.

## 1. Academic Evidence: Three Papers as PID Components

### RACL: Reasoning-Agent Control Layer (2606.20142)

**Core design:** A reasoning agent placed *above* an existing optimizer. It doesn't replace the optimizer or modify business constraints. Instead it controls the optimizer's internal search behavior through:

1. **Observe** operational memory (sensor)
2. **Reason** over past behavior (integral term)
3. **Formulate bounded hypotheses** (controller output)
4. **Test interventions** (actuator)
5. **Evaluate outcomes** (feedback measurement)
6. **Apply guardrails** (output limiter)
7. **Consolidate useful policies** (integral memory)
8. **Explain decisions** (observability)

**Result:** RACL improves or ties in 21/21 feasible cases vs. the base optimizer, with average cost delta of -0.641% vs. stagnation-triggered policy and -8.337% vs. fixed policy in the runtime sample.

**Control theory interpretation:** RACL is the first paper that explicitly separates the *reasoning agent* from the *executing agent* and treats their relationship as a control loop rather than a hierarchy. The reasoning agent doesn't do the work — it *tunes* the worker. This is literally a PID controller where P = current stagnation response, I = accumulated policy consolidation, D = hypothesis-driven anticipatory intervention.

**Critical design rule:** "The agent does not replace the optimizer and does not modify business constraints." This is the control theory principle that the controller shouldn't change the plant — it adjusts the input signal.

Source: https://arxiv.org/abs/2606.20142

### SIGMA: Skill-Incidence Graphs for Compositional Multi-Agent Design (2606.19758)

**Core innovation:** Instead of fixing agents as closed-set entities and optimizing their communication topology, SIGMA constructs agents dynamically from reusable skills via a skill-agent incidence matrix. Given a task and a skill library, the system:

1. Predicts which skills each agent needs (incidence matrix)
2. Composes agent node embeddings from selected skills
3. Decodes a communication topology over the constructed agents
4. Routes messages through skill-specific mailboxes during execution

**Result:** Best average across 6 benchmarks and 3 LLMs, improving over CARD (strongest topology-only baseline) by +2.06 to +2.36 points. Only 0.96 point drop with unseen skill libraries (vs. much larger drops for topology-only methods).

**Control theory interpretation:** SIGMA treats agent composition as **actuator selection**. In classical control, you don't just tune the controller — you select which actuators engage for which disturbances. SIGMA's incidence matrix is the agent equivalent: for this task (disturbance), which skill-actuators does each agent-controller engage? The skill-specific mailboxes are the routing channels — messages go to the capability that can act on them, not to a generic inbox.

**Connection to MVA (scan #82):** Minimum viable authority says "give agents the smallest scope that still enables the task." SIGMA operationalizes this: instead of giving every agent every skill (maximum authority), dynamically compose each agent with exactly the skills this task requires.

Source: https://arxiv.org/abs/2606.19758

### ScaffoldAgent: Utility-Guided Dynamic Outline Optimization (2606.20122)

**Core design:** Models the evolution of a research outline as a structured decision process with three operations — Expansion, Contraction, and Revision — and a utility function that estimates the downstream value of each operation from retrieval gain, structural coherence, and trial-generation quality.

**Control theory interpretation:** This is a **derivative controller** for research structure. The utility signal doesn't just react to current state (proportional) or accumulated evidence (integral) — it estimates the *rate of improvement* from each possible structural change and selects the one with highest marginal return. The three operations (expand, contract, revise) are the three possible actuator responses: add capacity, remove waste, or adjust trajectory.

**Connection to scaffold drift:** The paper explicitly names "scaffold drift" — the tendency for fixed outlines to diverge from the evidence they organize. In control theory, drift IS the integral wind-up problem: accumulated error in one direction pushes the controller past its useful range. ScaffoldAgent's contraction operation is anti-windup.

Source: https://arxiv.org/abs/2606.20122

## 2. Practitioner Evidence: GitHub Implements the Control Loop

### agent-homeostasis (1★, Rust, created 2026-06-06)

The most explicit control-theory-to-agent mapping found to date. SuperInstance/agent-homeostasis implements:

- **Gauges** (baroreceptors → agent metrics collection)
- **Setpoints** with satisfaction functions, not binary thresholds (hypothalamic target ranges)
- **PID Controller** with configurable gains and output limits
- **Dynamic setpoints** that widen under high load (homeostatic adaptation)
- **Actions** (throttle, model switch, escalation) as typed actuator responses
- **Ecology** module for multi-agent resource sharing

The biological analogy is explicit and complete. Key code pattern:

```rust
let mut pid = PIDController::new(0.5, 0.1, 0.2)  // kp, ki, kd
    .with_output_limits(-1.0, 1.0)
```

**Significance:** This is the first open-source repo that treats agent governance as a control engineering problem with proper mathematical foundations — not just metaphor, but actual PID implementation with tunable gains and output saturation.

Source: https://github.com/SuperInstance/agent-homeostasis

### ai-agent-harness-engineering-template (1★, Shell, created 2026-05-26)

Formalizes the harness engineering pattern (from Birgitta Böckeler's Martin Fowler article) as a project template:

```
Feedforward → Agent Work → Feedback Sensors → Correction Loop
```

Explicitly decomposes the agent control loop into:
1. **Feedforward**: specifications, conventions, constraints (reference signal)
2. **Agent Work**: the plant
3. **Feedback Sensors**: tests, linters, logs, metrics, review agents (measurement)
4. **Correction Loop**: fix, retry, escalate, or stop (controller output)

Includes correction-policy.md, risk-controls.md, and a harness.yaml configuration — the agent governance equivalent of controller tuning parameters.

Source: https://github.com/mesn1985/ai-agent-harness-engineering-template

### "Prefer Duplication Over the Wrong Abstraction" (347pts, 238c)

Sandi Metz's 2016 article achieved massive engagement today. The agent-era comments reveal the control theory gap:

- **aarjaneiro**: "I've seen way more duplication as a result of AI in large codebases"
- **lossyalgo**: "We would love to, but we ran out of tokens" (response to "why not refactor?")
- **storus**: "When you run out of tokens, you run out of tokens!"
- **dofm**: "if I tell it 'read these files that use the same conventions' first, there's no misunderstanding, and the agent also picks up the general 'tone' of the code"

**Control theory interpretation:** Agents generate duplicate code because they operate as **pure proportional controllers** — they respond to the immediate task (generate code that solves THIS) without integrating accumulated system knowledge (integral: "we already have a function that does this"). Abstraction requires the integral term: recognizing that the current task is an instance of a pattern seen before and routing to the existing implementation rather than generating a new one.

The "wrong abstraction" problem is then a **controller tuning problem**: too little integral gain → duplication (no memory of past solutions); too much integral gain → premature abstraction (forcing pattern-matching on things that are actually different). The Sandi Metz recommendation to "prefer duplication" is equivalent to saying **start with low integral gain and increase it only when the accumulated evidence is clear** — which is exactly the control theory wisdom for avoiding integral windup.

### epoll vs io_uring (245pts, 59c)

A technical deep-dive on Linux I/O mechanisms. The control theory connection: epoll is a **reactive** (proportional-only) I/O model — events happen, you respond. io_uring is **predictive** — you pre-submit work, establishing a pipeline that anticipates future I/O needs. The shift from epoll to io_uring mirrors the shift agent systems need: from reactive error handling to predictive governance with feed-forward planning.

## 4. The Two Recapitulations: A Structural Map

With scans #78 and #83, we can now see agent infrastructure recapitulating *two* distinct engineering disciplines simultaneously:

| Layer | CPU Recapitulation (#78) | Control Theory Recapitulation (#83) |
|---|---|---|
| **Problem** | Sequential execution is too slow | Open-loop control drifts and oscillates |
| **Solution** | Speculative execution + rollback | Closed-loop feedback + tuning |
| **Primitive** | Checkpoint, speculate, commit/squash | Measure, compare-to-setpoint, correct |
| **Scope** | Single session / task execution | Cross-session governance / operating envelope |
| **Time horizon** | One task (speculate on the next step) | Across tasks (maintain stable behavior over time) |
| **Failure mode** | Pipeline stall (Commitment Threshold) | Oscillation (duplication ↔ wrong abstraction) |
| **OS Recapitulation KE** | Extends: processes, scheduling | Extends: resource management, capacity planning |

The key distinction: CPU recapitulation happens **within** a session (how to execute faster), while control theory recapitulation happens **across** sessions (how to maintain stable quality over time). They're complementary, not competing.

**Prediction:** A third recapitulation layer will emerge — **networking** (how agents communicate, route messages, handle congestion, maintain sessions across boundaries). SIGMA's skill-specific mailboxes are the first proto-signal of this.

## 5. The Missing Term: Why Agents Can't Tune Themselves

The deepest insight from the convergence: **current agent governance systems lack the integral term**.

- **Proportional** (current state): Agents respond to the present task. Every coding agent does this — "generate code for this requirement." Every retry policy does this — "it failed, try again."
- **Integral** (accumulated state): Agents should recognize "we've been doing this pattern for 12 sessions, consolidate it." RACL's "consolidate useful policies" is the first explicit integral implementation. Without it, agents re-derive the same solutions repeatedly (the Eternal Present).
- **Derivative** (trajectory): Agents should detect "quality is degrading at an increasing rate, intervene before collapse." ScaffoldAgent's utility-guided feedback is the first explicit derivative implementation. Without it, agents don't notice drift until it produces failure.

| PID Term | Agent Governance | Current State | What's Missing |
|---|---|---|---|
| **P** (proportional) | React to current error | ✅ Widely implemented | N/A |
| **I** (integral) | Accumulate cross-session learning | ❌ Mostly absent | Policy consolidation, pattern recognition across tasks |
| **D** (derivative) | Detect degradation trajectory | ❌ Rare | Trend monitoring, anticipatory intervention |
| **Output limits** | Prevent over-correction | ⚠️ Partial (budget caps) | Proper saturation curves, anti-windup |

The Cost Proprioception Gap (scan #74) is the sensor problem — agents can't measure themselves. The Control Theory Recapitulation is the controller problem — even if they could measure, they wouldn't know how to use the measurements to self-correct.

## 7. Predictions

1. **6-month horizon:** "Agent control loop" becomes a named engineering discipline, distinct from "agent architecture." Practitioners will talk about tuning their agent's feedback gains, not just its prompts. The harness-engineering template pattern will spawn multiple imitators.

2. **6-month horizon:** Agent frameworks will add integral-term primitives — cross-session pattern consolidation that automatically converts repeated behaviors into persistent policies. RACL's "consolidate useful policies" step will be productized.

3. **12-month horizon:** The PID metaphor will be recognized as incomplete and replaced by **model predictive control (MPC)** — agents that plan multiple steps ahead under constraints, optimizing a trajectory rather than reacting to the current error. This is the natural successor: P→PI→PID→MPC.

4. **12-month horizon:** Agent homeostasis (maintaining operating envelope) will emerge as a distinct concern from agent orchestration (coordinating multiple agents). Just as biological organisms have both an immune system (homeostasis) and a nervous system (coordination), agents will separate these functions.
