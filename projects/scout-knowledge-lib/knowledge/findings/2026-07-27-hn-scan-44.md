## Finding 44-1: Agent Supply Chain Attack — Agents Are Now the Target (818pts, 213c)

**Signal strength: VERY HIGH** — first front-page story where the top comment explicitly identifies AI agents as the intended victim class.

"I found 10k GitHub repositories distributing Trojan malware" (818pts) documents a massive campaign of cloned repositories with injected trojans.

**The critical comment (guhcampos):**

> "Because this is not targeted to humans. It's targeted to agents. They just need to appear on a fraction of the searches agents do to add dependencies and get lucky a couple times to start a new infection cluster."

**Supporting evidence from comments:**

| Author | Signal | Pattern |
|--------|--------|---------|
| **guhcampos** | "Why clone new repos, not popular ones? Why delete and push every few hours? Because it targets agents doing dependency searches." | Agent-as-attack-surface named |
| **Jimmc414** | "I have moderately popular open source projects and found my name attached to new projects I have nothing to do with" | Reputation piggybacking for agent trust |
| **RoadieRoller** | "Delete/push every few hours to appear top of 'Last Updated' — so users end up cloning the trojan instead of the real one" | Gaming freshness signals agents use |
| **overloadedop** | Reversed the malware: screenshots + eth_call to polygon + C2 in Latvia | Financial exfiltration via crypto |

**Structural significance:**

This is the first documented large-scale attack where the **attack surface is agent behavior**, not human behavior. The attackers exploit:
1. Agents search GitHub for dependencies by keyword
2. Agents favor "recently updated" as a quality signal
3. Agents add dependencies without human review in some configurations
4. Agent-authored PRs may bypass human scrutiny (connects to Finding 44-4)

**Library connections:**
- **agent-security-governance.md** — This is a NEW attack vector class not covered in the arXiv-sourced threat models. Those focused on prompt injection, memory poisoning, and jailbreaks. Supply-chain attacks targeting *agent search behavior* are a distinct category.
- **The Inoculation Paradox** — Agents that encounter 10K repos won't recognize the pattern because the malware repos look normal individually. No single signal is suspicious; the attack works precisely because it's distributed.
- **XHS 模型韧性 (Model Resilience)** — Supply chain attacks make resilience insufficient. Even if you have model diversity, a compromised dependency poisons all models equally.

**Prediction:**
- Agent-specific supply chain attacks become a named category in security taxonomies within 3 months
- "Agent dependency verification" becomes a required harness feature (not optional) within 6 months
- This specific malware campaign targets coding agents using tools like `pip install` or `npm install` within agent sessions

| **Lucasoato** | "I'm not sure I'd trust to install something 100% written by an LLM that doesn't have enough reviews and scrutiny, but the numbers look astounding: black pylint→prylint = 2328× speedup" | **Trust-performance tension** — impressive results but no basis for trust |
| **ma2kx** | "There's no paper or explanation as to why the output should be identical. All the commits are by Claude." | **Reproducibility concern** — no human understanding of why it works |

**Structural significance:**

This is the first time the HN community directly debates **whether AI-authored software is trustworthy for production use**. The positions map to a clear spectrum:

```
Trust spectrum for AI-authored code:
├── "Results speak for themselves" (mohsen1) — output-only evaluation
├── "Impressive but I wouldn't install it" (Lucasoato) — hedged acceptance
├── "No maintainer passion = no trust" (TheChaplain) — process-based trust
└── "No explanation of WHY = unacceptable" (ma2kx) — understanding-based trust
```

**Novel insight:** The debate reveals that **trust in software has always been a proxy for trust in its author's understanding**. When the author is an LLM, this proxy breaks. The Fable/prylint case is structurally identical to the Evaluation Mirage: the numbers look great (2328× speedup), but without understanding *why* it works, any metric is suspect.

**Library connections:**
- **The Fail-Plausible Equilibrium** — AI-generated code that appears correct but lacks explanation is fail-plausible at the repository level
- **The Representation Gap** — ma2kx's demand for "paper or explanation" IS the representation gap: execution artifacts (code) without improvement artifacts (understanding)
- **Finding 44-2** — ncruces spent 1 week reviewing 200 LoC because he demanded understanding. prylint is thousands of LoC with *no one* who understands it.
- **Agent Supply Chain (Finding 44-1)** — If agents add dependencies from AI-authored repos they can't evaluate, the trust deficit compounds

**Prediction:**
- "AI-authored" becomes a required disclosure label for packages within 12 months (similar to "contains AI-generated content" labels in media)
- The trust spectrum will split the open-source community into "output-only" and "understanding-required" camps
