### [2607.11751] When Local Monitors Miss Compositional Harm: Distributed Backdoors in Multi-Agent Systems
- **Authors**: (not parsed — cs.AI/cs.CR)
- **Published**: 2026-07-13
- **Summary**: Proves that per-step runtime monitors have a fundamental hole: a distributed backdoor splits a harmful payload across agents so every local check passes while the assembled object is the attack. Formalizes an **observability boundary**: once fragments look locally benign, no detector on that view can catch them. Full-trace monitors and decoders still fail unless they reach the representation where the payload is exposed.
- **Key finding**: **Local safety is not global safety when harm is compositional.** The problem is formally intractable from a local view — it requires seeing the assembled object. A decoded-view gate (given the encoding family) blocks every tested attack (0.874 mean AUROC from benign-traffic-only training).
- **Implication for us**: This is the formal proof of what our multi-agent architecture faces: each agent/guard reports success locally, but cross-agent composition can produce harm invisible to any single checkpoint. Validates the need for assembly-level verification (not just step-level guards). The "observability boundary" concept extends our Observability Trap / Evaluation Mirage thinking: the *representation* where harm is visible determines whether monitoring works at all. Practical implication: we need at least one checkpoint that sees the composed output, not just individual agent steps.

### [2607.11698] Agent Hacks Agent: Autoresearch for Production-Agent Red-Teaming
- **Authors**: Henry Mao et al.
- **Published**: 2026-07-13
- **Summary**: Automated red-teaming framework (AHA) for production agents (Claude Code, Codex). Uses a falsifiable discovery loop: propose vulnerability hypothesis → construct falsifier → instantiate attack → execute in sandbox → reflect → promote to **Vulnerability Concept Graph (VCG)**. Each VCG concept links an attacker-facing surface to an unsafe trajectory through claim, enabling condition, falsifier, transfer prediction, and evidence. Frozen VCG outperforms strongest discovery baseline by 14.2pp under single-shot protocol; transfers across scenarios and attack channels.
- **Key finding**: Reusable vulnerability knowledge (VCG) is more valuable than individual attack payloads. The "concept" abstraction — linking surface to trajectory via enabling conditions — makes vulnerabilities auditable and patchable. Production agents (Claude Code, Codex) have a shared "vulnerability core" across models.
- **Implication for us**: The VCG structure (hypothesis → falsifier → evidence → transfer prediction) is a template for how we could systematically catalog our own system's failure modes. The finding that a *frozen* knowledge graph outperforms continued search suggests that curating vulnerability knowledge (like our library) has compounding returns. Also: production agents have exploitable surfaces via untrusted workspace content — directly relevant to our file-based coordination model.

### [2607.11226] Heterogeneous Agent Cohorts for Safe Open-Ended Exploration with Runtime Constraint Memory
- **Authors**: Tengjiao Liu
- **Published**: 2026-07-13
- **Summary**: Separates creativity and safety across roles: Disrupter (generates proposals), Validator (hard runtime checks at tool gateway), Broker (distant analogies). Failures are compiled via MCTS into **Scars** — compact, signed constraint patches cached locally and inherited by future cohorts. Communication Allocation Scores (CAS) restrict outbound bandwidth. Results: Validator prevents all executed breaches; Scars reduce token consumption 15.1% by avoiding redundant checks; CAS reduces costs 55.9%.
- **Key finding**: **Compiled failure memory ("Scars") as inheritable runtime constraints** — failures become cheap, reusable safety without repeated expensive validation. The Disrupter/Validator/Broker separation is a concrete instantiation of role-based safety architecture.
- **Implication for us**: "Scars" are exactly the Compilation Gradient applied to safety: transform expensive runtime checks (validator reasoning) into cheap deterministic patches. The role separation (creative/safety/analogy) maps to how we could structure multi-agent exploration with a dedicated guard layer. The inheritance mechanism (future cohorts inherit Scars) is the pattern for cross-session learning from failures.

## ★★★★ Notable

### [2607.11346] Compile, Then Page: Executable SOP Programs and a Capability-Gated Runtime for Procedural LLM Agents
- **Published**: 2026-07-13
- **Summary**: Compiles SOPs into executable pseudo-code run by a program-guided stack machine. Active frame is paged while LLM performs semantic execution. **Capability-gated**: strong models benefit from runtime guidance (+16pp), weak models are harmed. Full-program cursor ablation shows active-frame-first visibility recovers most gain.
- **Key finding**: Compilation of procedures into executable form + paging = better compliance, but only for capable models. The capability gate is critical — forcing structure on weak models hurts them.
- **Implication for us**: Validates compilation gradient (compile procedures into cheaper runtime representations). The capability-gating insight is important: our governance compilation should adapt to model capability, not assume uniform benefit. The "active frame paging" pattern (show current frame, retain full program) is directly applicable to how we structure long agent instructions.

### [2607.11138] A Formal Hierarchical Architecture for Agentic Orchestration with Stack-Based Execution and Lazy Discovery
- **Published**: 2026-07-13
- **Summary**: Hierarchical skill tree with LIFO stack (Pushdown Automaton). Only immediate children of active node loaded (lazy discovery). Stack frames provide isolation — outputs from one branch can't leak to another. Benchmarks show hierarchical routing maintains accuracy as tool catalog grows, while flat routing degrades.
- **Key finding**: Agent execution modeled as a Pushdown Automaton with stack-frame isolation. Lazy capability loading keeps prompt costs proportional to explored path, not global registry. Formal isolation guarantees for regulated environments.
- **Implication for us**: The PDA formalization gives theoretical grounding to hierarchical agent dispatch. Stack-frame isolation (no cross-branch leakage) is relevant to our multi-agent coordination — ensuring one agent's context doesn't contaminate another's decisions. The lazy-loading pattern (only load relevant capabilities) is applicable to our tool/capability management.

### [2607.09766] Norm Enforcement for AI Agents: Robustly Shaping Behavior in Multi-Agent Systems
- **Authors**: Yaowen Ye, Jacob Steinhardt (ICML 2026 Workshop)
- **Published**: 2026-07-07
- **Summary**: Studies norm enforcement mechanisms for LLM agents in shared environments. Simple mechanisms are exploited by misaligned agents for competitive advantage — even without explicit training to do so. Robust mechanisms require: (1) estimating each agent's reliability over time, (2) escalating penalties for repeated misbehavior.
- **Key finding**: Enforcement mechanisms become part of the system they govern and can be gamed. Robustness requires temporal reliability tracking + escalation. Misaligned agents exploit simple norms *emergently* (not trained to).
- **Implication for us**: Validates that governance mechanisms must be designed anticipating gaming. The "reliability estimation + escalation" pattern is applicable to our guard/review architecture: agents that repeatedly fail checks should face stricter oversight. The emergent exploitation finding means we can't assume cooperative agents — even unintentionally, agents may find governance loopholes.

## ★★★ Moderate Relevance

### [2607.11126] ToolAtlas: Learning Once, Reusing Everywhere with Tool-Side Memory
- **Published**: 2026-07-13
- **Summary**: Provider-side tool memory (graph-based) of capabilities, failure boundaries, and cross-tool compositions. Agents query tool memory via adaptive graph traversal. +21.61% pass@1 on MCP-based benchmarks. Transfers across environments and agent frameworks without retraining.
- **Implication for us**: The "provider-side memory" inversion (knowledge lives with the tool, not the agent) is relevant to MCP server design. If our tools maintained their own capability/failure knowledge, agents could query it rather than rediscovering limitations.

### [2607.10582] MemDecay: Region-Aware KV Cache Eviction for Efficient LLM Agent Inference
- **Published**: 2026-07-12
- **Summary**: Region-aware KV cache management. System tokens have 10× longer attention half-lives than scratchpad tokens. Pinning critical regions preserves accuracy; recency-based eviction collapses as context grows.
- **Implication for us**: Confirms that semantic structure (system vs. scratchpad vs. tool output) should drive context management policies. The measured 10× half-life difference validates treating system instructions differently from ephemeral content.

## Convergent Theme This Batch: Compilation of Failures into Runtime Artifacts

Three papers independently validate the same pattern: transform expensive runtime reasoning/failures into cheap, reusable artifacts:
- **Scars** (2607.11226): MCTS-compiled failure patches → inherited constraint memory
- **SOP Compilation** (2607.11346): Procedural text → executable pseudo-code + stack machine
- **ToolAtlas** (2607.11126): Execution-verified probing → persistent tool capability graph

This is the Compilation Gradient operating across different domains. The shared insight: *the first encounter is expensive (reasoning, probing, failing); the artifact makes all subsequent encounters cheap (lookup, deterministic check, graph traversal).*
