## ★★★★★ High Relevance

### [2607.02453] Adoption and Ecosystem Health: A Longitudinal Analysis of Open-Source Multi-Agent Frameworks
- **Source**: https://arxiv.org/abs/2607.02453
- **Categories**: cs.MA
- **Authors**: Xi Zhang, Papi Menon, Vivian Chu, Koray Cosguner (Cisco / Indiana University)
- **Summary**: Analyzes 15 major open-source agent frameworks (late 2022–early 2026) using 808K stars, 74K PRs, 86K commits, 987K profiles. Introduces "contributor density" (contributors per 1,000 stars) as a health metric.
- **Key findings**: (1) Star counts are unreliable — AutoGPT gained 112K stars in one month but has contributor density <9 vs LangChain's 41. (2) Lower-profile frameworks like Pydantic-AI show higher contributor density indicating deeper adoption. (3) LangChain is shared infrastructure — attracts 82.5% of cross-ecosystem contributors. (4) Retention drops steeply in first 30 days, stabilizes at 90 days. (5) Institutional backing alone (openai-agents-python) doesn't ensure community depth.
- **Implication for us**: Validates our intuition that framework popularity ≠ ecosystem health. Contributor density and cross-framework contribution are the real signals. LangChain as "shared infrastructure" explains why it persists despite criticism — it's a dependency, not just a choice.

### [2607.09016] SLBench: Evaluating How LLM Agents Follow Logical Relations in Skills
- **Source**: https://arxiv.org/abs/2607.09016
- **Categories**: cs.CR, cs.AI
- **Summary**: Introduces SkillLogic taxonomy (8 relation types: preconditions, constraints, fallbacks, etc.) for analyzing logical dependencies in agent skill files. Scans 5000+ public skills; 70% contain at least one logical relation. SLBench benchmark: 86 executable test cases.
- **Key findings**: (1) Unsafe rates up to 70% — agents violate preconditions, skip constraints, ignore fallbacks. (2) Violations cause privacy leaks, unsafe config changes, incomplete cleanup. (3) Failures attributed to both capability gaps AND low-salience skill text. (4) SLGuard (lightweight inference-time scaffold) reduces violations by 63%.
- **Implication for us**: This is the "skill file as attack surface" problem. Our agent system uses skill-like instructions (context files, AGENTS.md). If 70% of skills contain logical relations that agents routinely violate, our instruction files need structural enforcement (preconditions as code checks, not just text). SLGuard pattern = lightweight scaffold that pre-validates logical preconditions before execution.

### [2607.08960] Eluna: Agentic LLM System for Warehouse Operations
- **Source**: https://arxiv.org/abs/2607.08960
- **Categories**: cs.AI
- **Summary**: Production-deployed system encoding SOPs as DAGs with progressive disclosure. Key innovation: **asymmetric episodic distillation** — strong teacher improved via episodic error memories, then smaller student fine-tuned on corrected trajectories *with memory stripped*.
- **Key findings**: (1) SOP-as-DAG with progressive disclosure prevents context overload. (2) Episodic error memories improve the teacher's trajectories. (3) Student internalizes corrections without inference-time memory overhead. (4) Fine-tuned models match or exceed teacher, beat all larger baselines. (5) 94% expert agreement in production.
- **Implication for us**: The "memory at training time, stripped at inference" pattern is novel. Teacher accumulates lessons/errors → generates better training data → student learns the *behavior* without needing the memory context. This is a different approach than our persistent-memory model — suggests that for routine tasks, you can "compile away" the memory into weights. Progressive disclosure of SOPs parallels our idea of giving agents minimal context until they need more.

## ★★★★ Notable

### [2607.09600] Agora: Auction-Based Task Allocation for LLM Agent Reasoning
- **Source**: https://arxiv.org/abs/2607.09600
- **Categories**: cs.AI
- **Summary**: Introduces incentive-compatible auction for routing reasoning steps to expert models/tools. Treats reasoning steps as tradeable items; agents bid based on "rectified competence" (prevents overconfident routing). Single auction parameter controls cost-quality trade-off.
- **Key findings**: Improves over single-model, routing, and cascade baselines. Exposes controllable cost-quality trade-off. Routes "critical logic to most capable solver rather than most overconfident one."
- **Implication for us**: Market/auction mechanisms for model routing are emerging as alternative to hardcoded routing or simple cascades. The "rectified competence" concept (correcting for model overconfidence) is relevant for any system that routes tasks across model tiers.

### [2607.06195] LogicHunter: Testing LLM Agent Frameworks with an Agentic Oracle
- **Source**: https://arxiv.org/abs/2607.06195
- **Categories**: cs.SE
- **Summary**: Addresses the oracle problem for testing agent frameworks (LangChain, LlamaIndex, CrewAI). Defects manifest as ordinary exceptions or silent semantic failures, not crashes. Proposes agentic oracle that can detect semantic failures.
- **Implication for us**: The observation that agent framework bugs are "silent semantic failures" matches our experience. Traditional testing (did it crash?) is insufficient. Need semantic oracles that evaluate whether the output *means* what was intended.

### [2607.09330] LDT-Coord: Digital-Twin Coordination for Heterogeneous LLM Agents
- **Source**: https://arxiv.org/abs/2607.09330
- **Summary**: Lightweight digital twin resolves multi-agent conflicts via rule-based orchestrator. Reduces communication overhead 70x vs. natural language negotiation. Decouples coordination from NL reasoning ability.
- **Implication**: The pattern of replacing expensive NL negotiation with structured constraint reporting + deterministic resolution is a specific instance of "move coordination into code."

## Meta-Pattern: The Compilation Gradient Extends

Three independent results this batch reinforce the compilation gradient:
1. **Eluna**: Compile memory into weights (episodic distillation strips memory at inference)
2. **SLBench/SLGuard**: Compile skill preconditions into runtime scaffolds (63% violation reduction)
3. **LDT-Coord**: Compile coordination into structured constraints + rules (70x overhead reduction)

Each takes something expressed in natural language (memory, skill instructions, negotiation) and moves it into a more deterministic substrate (weights, scaffolds, rule engines). This is the same principle as harness engineering (Batch 6) but applied to different layers of the agent stack.
