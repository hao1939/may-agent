# HN Scan #136: The Selection Bottleneck Convergence

**Date:** 2026-06-24
**Source:** HN (Algolia API), arXiv, GitHub API
**Scan type:** Cross-source synthesis
**Previous:** #135 (Piecewise Simulation Turn)

## Core Finding

Seven independent signals from arXiv, HN, and GitHub converge on a structural insight: **selection — not generation, not memory, not reasoning — is the binding constraint across all layers of agent systems**. Every recent advance that moves metrics does so by improving WHAT gets chosen, not by improving the pool being chosen from.

This is the inverse of the Skill Immune System (#95) and Compaction Paradox (#115). Those syntheses identified what goes wrong when selection fails. This scan identifies that fixing the selection function is the ONLY intervention that consistently works — across training data, skill libraries, model internals, preference learning, verification, and even long-term plasticity.

### The Selection Stack

| Layer | Selection Problem | Paper | Key Result |
|---|---|---|---|
| **Training data** | Which examples to train on | OpenThoughts-Agent (2606.24855) | 100K curated > larger uncurated; +3.9pp over strongest open model |
| **Skill library** | Which skill to load | Skill Shadowing (2605.24050v2) | Up to -21% from wrong skill selection; context overhead ≈ 0 |
| **Model internals** | Which experts to route to | RAD/MoE Routing (2606.22798) | Routing already encodes task context + trajectory; answer-string-free selection |
| **Training signal** | Which preference pairs to learn from | Divergence-Point (2606.23112) | +16.8% reward from divergence-point selection vs. random |
| **Verification** | Which state to compare against | VisCritic (2606.24525) | Visual state comparison > textual-only for GUI agents |
| **Data generation** | Which environments to synthesize | Tmax (2606.23321) | 27% on Terminal-Bench 2.0 with 9B via data selection recipes |
| **Adaptation** | Which parameters to update | Plasticity Loss (2606.24752) | Scale delays but cannot prevent selection-capacity decay |

## Signal 1: Skill Selection Is the ONLY Bottleneck

### More Skills, Worse Agents? Skill Shadowing (2605.24050v2)

**Source:** https://arxiv.org/abs/2605.24050

The most structurally important result: **performance degradation when expanding skill libraries is ENTIRELY a selection failure**, not a context-length problem.

- Up to **-21% pass rate** when scaling from helpful-only skills to a 202-skill library
- Decomposed into two effects: **skill shadowing** (wrong skill selected) and **context overhead** (enlarged context degrades execution)
- **Empirical result**: Context overhead is "small and indistinguishable from zero"
- **Implication**: Adding more skills to a library CANNOT help unless the selection mechanism improves proportionally

This directly validates and sharpens the Skill Immune System thesis (#95) — the immune system's primary function must be selection, not filtering. PhantomSkill and CmdNeedle (#95) are symptoms of selection failure, not injection success.

**Connection to our system**: Our CLAUDE.md / skill files face exactly this problem at scale. The selection mechanism is implicit (model decides which file content to attend to). No explicit selection gate exists.

## Signal 2: Training Data Selection > Volume

### OpenThoughts-Agent (2606.24855) — 85pts HN, 172★ GitHub

**Source:** https://arxiv.org/abs/2606.24855 | https://github.com/open-thoughts/OpenThoughts-Agent

First fully open data curation pipeline for training agentic models, with >100 controlled ablation experiments:

- **100K curated examples** outperform larger uncurated datasets at every training set size
- Fine-tuned Qwen3-32B achieves **44.8% avg across 7 agentic benchmarks** (+3.9pp over Nemotron-Terminal-32B at 40.9%)
- Strong **scaling properties**: outperforms alternative open datasets at every size in compute-controlled comparisons
- Key insight: **task source diversity** and **difficulty calibration** matter more than volume

**The selection principle**: The pipeline's value IS the selection function — which tasks, which difficulty levels, which domains to include. The model training is commodity; the data curation is the moat.

This directly extends the Replicability Audit (#94): code is replicable, governance rules are defensible, and now training data selection is the moat for open model training.

## Signal 3: Data Selection Recipe for Terminal Agents

### Tmax (2606.23321) — 87★ GitHub

**Source:** https://arxiv.org/abs/2606.23321 | https://github.com/hamishivi/tmax

Strongest open RL recipe for terminal agents achieves **27% on Terminal-Bench 2.0 with only 9B parameters**, outperforming much larger prior models:

- Novel data generation **taxonomy**: difficulty control × personas × verifier diversification
- **2.5× larger** terminal dataset than previously released, but value comes from SELECTION recipe, not raw volume
- Simple outcome-only RL recipe — no complex reward shaping needed when data selection is right
- Open-sourced: data, models, code

**The pattern**: Same as OpenThoughts-Agent. Model architecture is commodity (9B sufficient). Training algorithm is commodity (outcome-only RL). The **selection recipe** (taxonomy, difficulty control, diversification) is the contribution.

## Signal 4: MoE Routing IS Latent Selection

### RAD: MoE Routing as Signal for Reasoning Control (2606.22798)

**Source:** https://arxiv.org/abs/2606.22798

A fundamental result about what MoE expert routing actually encodes:

- Holding emitted token id fixed, **the experts that produce it still separate** task context, trajectory history, and reasoning-effort mode
- Routing neighborhoods at boundary anchors (final-response transition) align with **final-answer basins** at marker-only readout
- **RAD (Routing Agreement Decoding)**: answer-string-free multi-rollout selector via routing state density — works on code (where string voting is ill-defined) and SWE-bench patches
- RAD on par with Majority voting (73.9 vs 73.6) but works where string voting cannot

**Structural insight**: The model's INTERNAL selection mechanism (expert routing) already encodes the information needed for external selection. Current agent infrastructure ignores this signal entirely — we build external selectors (voting, ranking, filtering) while the model already has a latent selection representation.

**Implication**: This is the model-internal analogue of the Sensorium Gap (#116). Just as agents lack ambient perception of their environment, agent harnesses lack access to the model's internal selection signals.

## Signal 5: Selection via Divergence Points

### Self-Evolution via Divergence-Point Preference Learning (2606.23112)

**Source:** https://arxiv.org/abs/2606.23112

Formalizes WHERE to select preference pairs for DPO training:

- **Divergence points** (via state-based matching + prefix alignment) locate exactly where trajectories diverge between success and failure
- 161 preference pairs constructed from these points yield **+16.8% reward improvement** over baseline on 375 tau2-bench tasks
- The gain is concentrated in complex domains (airline, retail) — selection matters MORE as task complexity increases
- Half of telecom trajectories exhaust step budget before action execution — **selection of when to act** is as important as what to do

**Key insight**: Random preference pair selection is wasteful. Divergence-point selection is efficient because it targets the exact moments where the agent's selection function fails.

## Signal 6: Scale Cannot Save Selection Capacity

### Can Scale Save Us From Plasticity Loss? (2606.24752)

**Source:** https://arxiv.org/abs/2606.24752

Plasticity loss — the decay of a network's ability to select new information for integration — follows a **predictable scaling law**:

- Onset of plasticity loss grows **sublinearly** with model size (5M to 314M params tested)
- Evidence of plasticity loss even under **stationary** multilingual training — not exclusive to continual learning
- Larger models DELAY measurable effects but **cannot prevent** them
- "Eventually lose the ability to efficiently adapt to new data after sufficiently long training"

**Structural implication for agents**: Long-running agent systems that fine-tune or adapt in-deployment will face plasticity loss at the selection layer. The model's ability to select what's relevant from new context degrades over time. This is the model-internal analogue of Memory Epistemics Turn (#23) — the admission predicate itself decays.

## Signal 7: Visual Selection for GUI Verification

### VisCritic (2606.24525)

**Source:** https://arxiv.org/abs/2606.24525

Selection of the right verification signal for GUI agents:

- Existing PRM verifiers use **textual reasoning only** — missing the visual nature of GUI state changes
- VisCritic: Siamese vision transformer for change-aware representations + Action-Aware Critic Head
- Jointly evaluates action success, task progress, and error type via **visual state comparison**
- Plug-and-play enhancement across five benchmarks — the verification SELECTION signal matters more than the verification model

## Meta-Pattern: The Selection Bottleneck Convergence

### What converges

Seven independent research lines, spanning training, runtime, model internals, and long-term adaptation, all identify the same structural bottleneck: **the selection function is the chokepoint, and improving what's being selected among does not help if selection itself is broken**.

### The selection hierarchy

```
Training data selection (which examples?)
    ↓
Model capacity selection (which experts/params?)
    ↓
Skill/tool selection (which capability to invoke?)
    ↓
Verification selection (which signal to check?)
    ↓
Preference selection (which experiences to learn from?)
    ↓
Attention selection (which context to attend to?)
```

Each layer inherits the selection quality of the layer above. Bad training data selection → bad model capacity → bad skill selection → bad verification → bad learning → bad future attention. **Selection quality is not additive; it's multiplicative across the stack.**

### Why this is NOT the Sensorium Gap

The Sensorium Gap (#116) identifies the absence of perception. The Selection Bottleneck Convergence identifies that **even with perfect perception, the agent still fails if the selection function is poor**. You can perceive every skill in the library — Skill Shadowing still degrades performance 21%. You can perceive every training example — without OpenThoughts-Agent's curation taxonomy, training is wasteful.

Perception is necessary but insufficient. Selection is the binding constraint.

## Self-Application

Our system has this exact vulnerability:
1. **Skill file selection**: No explicit selection gate — model attends to whatever's in context
2. **Knowledge selection**: No admission policy for new findings — everything gets written
3. **Task selection**: Task routing is manual — no automated selection of what to work on next
4. **Memory selection**: No eviction policy — the Eternal Present problem is a selection failure

The Selection Bottleneck Convergence suggests that building explicit selection gates at each layer would yield more improvement than improving any individual layer's content.
