## Finding 49-2: Agent-Targeted Supply Chain Attacks — A New Threat Category (945pts, 243c)

**Signal strength: VERY HIGH** — highest single-story engagement in this scan, with unprecedented threat characterization.

"I found 10k GitHub repositories distributing Trojan malware" (945pts, 243c) — a researcher discovers 10,000 malicious GitHub repos specifically designed to target AI agents.

### Key Practitioner Positions

| Author | Position | Pattern |
|--------|----------|---------|
| **guhcampos** | "This is not targeted to humans. It's targeted to agents. They just need to appear on a fraction of the searches agents do to add dependencies and get lucky... Then: why now? 1. Agents, agents everywhere. 2. MAJOR elections." | **Agent-specific targeting named** |
| **Jimmc414** | "I have a few moderately popular open source projects and I have found my name attached to new projects... fake skill registries (lobehub.com/skills, mcpmarket.com/tools, decision.ai/skills)" | **Identity theft via skill registries** |
| **RoadieRoller** | "They delete a commit and push a new one every few hours... to appear on top of 'Last Updated' in case someone searches for the repo." | **Temporal gaming** — freshness manipulation for agent discovery |
| **danso** | "[Disney engineer] checked the code himself, it had looked legitimate, and others had reviewed it positively. But it contained a Trojan-horse virus." | **Precedent case** — human verification already fails |

### The Novel Threat: Agent-Targeted Repository Poisoning

This is structurally different from prior supply chain attacks (npm malware, PyPI typosquatting):

1. **Target is the agent, not the developer.** Repos are designed to appear in search results that *agents* use to find dependencies. The human may never see the repo.

2. **Temporal freshness gaming.** Deleting and re-pushing commits every few hours keeps repos "recently updated" — exactly the signal agents use to filter for active projects.

3. **Skill registry poisoning.** Jimmc414's discovery of fake skill registries (mcpmarket.com/tools, lobehub.com/skills, hub.decision.ai/skills) using stolen identities creates a **trust chain attack**: the agent trusts the registry, the registry contains poisoned entries attributed to legitimate developers.

4. **Scale (10,000 repos)** makes manual detection impossible. Only automated scanning can address this.

### Connection to AURpocalypse (54pts, 37c)

"AURpocalypse now: a look at the recent AUR attacks" — Arch Linux's user repository also hit by similar attacks. Community response: "I love the smell of npm install malware in the morning" — normalizing supply chain attacks as expected rather than exceptional.

### Why This Matters for Agent Architecture

The threat model for agent tool selection is now concretely demonstrated:

- **CmdNeedle (arXiv triage)** showed 69-98.6% of denylists are fragile
- **This scan** shows the attack surface is being actively exploited at scale
- **The gap**: agents that select tools/dependencies via search (which is most of them) are vulnerable to poisoned search results. No amount of behavioral filtering addresses temporal freshness gaming or identity theft in registries.

The architectural implication from the arXiv Executable Turn (2026-08-24): **tool selection must move from search-based to graph-based (SING pattern)** — selecting tools via intention-graph traversal rather than textual search eliminates the attack surface of "appearing in search results."

### Library Connections
- **Agent Security & Governance** — New finding: agent-targeted repo poisoning as named attack category
- **CmdNeedle (arXiv 2606.15549)** — Behavioral denylists can't defend against this; structural certificates needed
- **Supply Chain Attack (scan #47, #48)** — Escalation: from "10k malicious repos exist" to "they specifically target agents"
- **SING (arXiv 2606.16591)** — Intention-graph tool discovery as defense against search-poisoning

### Predictions
1. **Agent-specific supply chain attack** will be named as a CVE category within 6 months
2. **Skill/tool registry verification** (cryptographic signatures, provenance chains) will be demanded for MCP tool sources within 3 months
3. **At least one major agent-caused breach** traced to poisoned dependency will be publicly reported within 6 months

## Finding 49-5: Hallucination Scales with Model Size — The "Bigger = Less Truthful" Signal (58pts, 14c)

**Signal strength: MEDIUM** — low engagement but structurally important for model selection strategy.

"GPT-5.5 hallucinates 3x more than MIT-licensed GLM-5.2" — blog post with data from Artificial Analysis benchmarks.

### Key Data Points (from AA-Omniscience Benchmark)

| Model | Hallucination Rate (when unknown) | Accuracy | Absolute Hallucination Rate |
|-------|-----------------------------------|----------|----------------------------|
| DeepSeek V4 Pro (1.6T params, 49B active) | **94%** | — | — |
| GPT-5.5 | **86%** | — | — |
| Fable 5 | 48% | — | — |
| Opus 4.8 | 36% | 47% | ~19% |
| **GLM-5.2** | **28%** | 25% | ~21% |
| DeepSeek V4 Flash | Lowest | — | — |

### Key Practitioner Positions

| Author | Position | Pattern |
|--------|----------|---------|
| **aesthesia** | "Hallucination rate scores are conditional on the model not knowing the answer... Opus has a 47% accuracy rate vs GLM-5.2's 25%. Absolute hallucination rates: 19% for Opus, 21% for GLM-5.2." | **Statistical sophistication** — conditional vs absolute rates |
| **solid_fuel** | "I didn't realize the hallucination rates were so bad! Even the best - GLM-5.2 - has 28% when it doesn't know the answer... If bigger models have stopped producing proportional returns, we are near the top of the S-curve." | **Scaling wall named** |
| **nextaccountic** | "What about using two models, with a smaller model for negative reasoning?" | **Compositional defense** — small model as truthfulness gate |

### Structural Significance

The data reveals an inversion: **larger models trained on more data hallucinate MORE, not less.** The proposed mechanism: "when a model is trained on large volumes of highly factual data, it learns to always have an answer" — confidence without calibration.

This connects to three prior findings:

1. **The Evaluation Mirage** — If the best models hallucinate 19-21% of the time at the absolute level, then agent outputs evaluated by those models inherit hallucination at evaluation time.

2. **MM-EPC Self-Evaluation Paradox (arXiv)** — Cross-model evaluation contagion is WORSE with larger models because they hallucinate more confidently, producing stronger but wronger evaluation signals.

3. **GLM-5.2 (scan #47)** — Already positioned as "frontier quality at fraction of cost." Now also positioned as "more truthful" — adding a quality dimension beyond capability benchmarks.

### The Composition Insight

nextaccountic's suggestion — "use a smaller model for negative reasoning" — maps to GIST-CMTF's goal validation pattern: a smaller, more calibrated model as a pre-filter that checks "should I even attempt this?" before the large model runs. This two-model pattern (large for capability, small for calibration) may become standard.

### Library Connections
- **The Evaluation Mirage** — Hallucination rates compound through evaluation chains
- **Frontier Model Economics (scan #47)** — Bigger isn't just more expensive, it's less truthful
- **GLM-5.2 (scan #47)** — Additional competitive dimension: truthfulness
- **The Competence Inversion** — More capable models may produce worse outcomes by hallucinating more confidently

### Prediction
1. **Two-model architectures** (large for generation, small for calibration/filtering) will be explicitly named and productized within 6 months
2. **"Hallucination rate" as a first-class benchmark** will appear in major model comparison sites within 3 months (AA-Omniscience is leading this)
