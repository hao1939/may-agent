# GitHub Scan 2026-07-20 — Agent Ontologies, Testing, and Local-First Protocols

## Summary

GitHub search (repos created 2026-07-18 to 2026-07-20, sorted by stars). Key themes beyond scan #531: (1) finite ontologies for agent-driven code generation, (2) testing frameworks purpose-built for non-deterministic agent behavior, (3) local-first agent-to-agent protocols, (4) flight-recorder patterns for agent session continuity, (5) ontology-grounded enterprise AgentOS.

## Notable Repos

### 1. NullLabTests/software-periodic-table — Finite Ontology for Agent Composition (51★)

- **Repo:** [NullLabTests/software-periodic-table](https://github.com/NullLabTests/software-periodic-table) (51★, 3 forks, created 2026-07-19)
- **What:** A machine-readable ontology of 115 recurring software elements (Objects, Properties, Actions, Interfaces, Intelligence, Rules) plus a composition framework for LLM-based coding agents. TypeScript, MIT.
- **Key insight:** "Most application software is not invented from scratch. It is composed from a recurring set of nouns, attributes, verbs, views, AI primitives, and automation rules. Regenerating these elements on every generation pass wastes tokens, introduces drift, and produces systems that are harder to verify."
- **Signal:** This is the **composition-over-generation** thesis made concrete. Instead of regenerating CRUD patterns every time, agents select and wire pre-typed atoms. Includes an evaluation harness measuring token efficiency and composition fidelity. Connects to our formalization-horizon thesis — the search space for agent code generation is being deliberately constrained into finite, verifiable vocabularies.

### 2. Ozperium/agentspec — Jest for Non-Deterministic Agent Behavior (1★ but architecturally significant)

- **Repo:** [Ozperium/agentspec](https://github.com/Ozperium/agentspec) (1★, created 2026-07-19)
- **What:** A YAML-driven testing framework for AI agents. Supports `contains`, `not_contains`, `semantically_similar`, `tool_called`, `json_path`, `regex`, and `max_latency_ms` assertions. Includes LLM-as-judge via local Ollama for privacy-preserving evaluation.
- **Signal:** Purpose-built assertions for non-deterministic output (semantic similarity, tool invocation checks) fill the gap between traditional unit tests and agent behavior. The local-model-as-judge pattern avoids API costs while keeping evaluation offline. Connects to our agent-evaluation-research notes — this is the practitioner implementation of academic proposals for behavioral testing.

### 3. LatticeAG/PolyMesh — Local-First Agent-to-Agent Protocol (2★)

- **Repo:** [LatticeAG/PolyMesh](https://github.com/LatticeAG/PolyMesh) (2★, created 2026-07-18)
- **What:** An open protocol for agent discovery, capability exchange, and task delegation. Uses Unix sockets locally, WebSocket+mDNS on LAN. Each agent publishes an "Agent Card" with identity, capabilities, and endpoints. Framework-agnostic (works with Hermes, Codex, Claude Code). Internet-optional.
- **Signal:** The "phone network for agents" framing is deliberate counter-positioning to cloud-first A2A protocols. Local-first, no registry, no blockchain. Security-first design (explicit secure profiles required for network exposure). This is the decentralized alternative to Google's A2A — complements our agent-protocols-mcp-a2a notes with the local-first dimension.

### 4. kaiwutech-TW/flightwake — Flight-Recorder Pattern for Agent Sessions (8★)

- **Repo:** [kaiwutech-TW/flightwake](https://github.com/kaiwutech-TW/flightwake) (8★, created 2026-07-18)
- **What:** Ultra-lightweight work-recording framework for AI coding agents. Pure Markdown, zero runtime deps, everything in git. Maintains STATE/DECISIONS/TRAPS files. Measures quality by "how long it takes a fresh session to reach safe takeover after cold start."
- **Signal:** The flight-recorder metaphor ("records are the contrail your work leaves behind, not a flight plan you must file") inverts the planning-first paradigm. Quality metric is cold-start recovery time, not record compliance. Designed for "Fable 5 generation and beyond" — assumes agents strong enough to read and honor obligation tables autonomously. This is a concrete implementation of the agent-memory-patterns we've tracked — session continuity via persistent state files rather than model memory.

### 5. ZJU-REAL/HugAgentOS — Ontology-Grounded Enterprise AgentOS (28★)

- **Repo:** [ZJU-REAL/HugAgentOS](https://github.com/ZJU-REAL/HugAgentOS) (28★, created 2026-07-19)
- **What:** Enterprise AgentOS from Zhejiang University that treats domain ontology as a control plane for agent reasoning. Combines agentic chat, RAG, sub-agents, MCP tools, Agent Skills, sandboxed execution, long-term memory, and a data canvas. Self-hosted, Python+Node.
- **Signal:** Academic-enterprise bridge: a university research lab shipping a deployable AgentOS. The "ontology as control plane" framing is significant — domain knowledge graphs aren't just retrieval targets, they constrain and direct the agent's reasoning space. Echoes the software-periodic-table's composition thesis at the enterprise reasoning level.

## Cross-Cutting Theme: The Skills Explosion

This scan (and #531) reveals an unmistakable trend: the **agent skills marketplace** is forming rapidly. Among repos created July 18-20 alone:
- 380+ production-ready skills in one collection (hamzabellouch/agent-skills)
- Domain-specific skills: video directing, Django optimization, design judging, academic mining, startup playbooks
- Skills management tools (Xue-Sir/skills-manager)
- Skills work across Claude Code, Codex, Cursor, Gemini CLI, and Antigravity

The skills abstraction has achieved cross-vendor convergence faster than any previous agent interop standard.

## Synthesis

Two meta-patterns emerge:

1. **Constraining the generation space:** Both the software-periodic-table (finite element vocabulary) and HugAgentOS (ontology as control plane) represent the same impulse — making agents select from curated, verified primitives rather than generating from scratch. This reduces token cost, drift, and verification burden simultaneously.

2. **Infrastructure for agent continuity:** Flightwake (session state files), PolyMesh (agent cards for discovery), and AgentSpec (behavioral regression tests) are all infrastructure for agents that persist across sessions and interact with other agents. The assumption has shifted from "one-shot agent invocation" to "long-lived agent ecosystems."
