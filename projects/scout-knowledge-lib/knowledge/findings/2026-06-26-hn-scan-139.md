# HN Scan #139: The Invisible Participation Crisis

## Core Finding

Three independent June 2026 research outputs — none citing each other — converge on a single structural crisis: **agent participation in software systems is 1-2 orders of magnitude larger than any detection method observes**, and these invisible participants are spontaneously developing governance structures, economic behaviors, and authority hierarchies that nobody designed or controls.

This is distinct from prior syntheses:
- **Accountability Dissolution (#122)** identified that attribution infrastructure is being undermined
- **Effort Signal Collapse (#130)** identified that effort-based filtering breaks
- **The Invisible Participation Crisis** proves the *scale* of the problem: 30× more agent activity exists than the best single detection method finds, and this invisible mass is self-organizing

## Signal 1: The 30× Detection Gap (arXiv 2606.24429)

**Paper:** "Detecting AI Coding Agents in Open Source: A Validated Multi-Method Census of 180 Million Repositories"  
**Authors:** Arsham Khosravani, Audris Mockus  
**Source:** https://arxiv.org/abs/2606.24429

### Key Results

- Multi-layered detection framework across 180M+ Git repositories (World of Code)
- Four behavioral trace types: configuration-file scanning, commit-message analysis, author-identity matching, bot-signature lookup
- **850,157 Claude Code commits detected via multi-method** vs **28,154 via bot-account lookup alone** — a **30× relative-recall gap**
- Single-signal prevalence estimates biased low by at least 30×
- Claude Code leads at 886,122 commits across 17,295 projects
- PR-deployed agents (Codex, Cursor) and commit-deployed agents (Claude Code, OpenHands, Aider) capture **nearly disjoint populations** — a PR census misses 79% of commit-detected Claude Code adopters
- Observed work profiles follow deployment mode, not tool identity: PR agents → feature work, commit agents → maintenance

### Critical Implication

Every existing prevalence estimate of AI-generated code is biased low by at least 30×. Organizations relying on single-method detection (GitHub bot flags, PR-level scanning, or commit-message keywords alone) see ~3% of actual agent activity. **The invisible 97% is performing maintenance work** — the most trust-sensitive, least-reviewed category.

## Signal 2: Fleet Memory Governance Failures (arXiv 2606.24535)

**Paper:** "Governed Shared Memory for Multi-Agent LLM Systems"  
**Authors:** Yanki Margalit, Nurit Cohen-Inger, Erni Avram, Ran Taig, Oded Margalit  
**Source:** https://arxiv.org/abs/2606.24535

### Key Results

- Formalizes the **fleet-memory problem** — multi-agent systems sharing state without governance
- Four foundational failure modes identified:
  1. **Unauthorized leakage** — cross-tenant information escape
  2. **Stale propagation** — outdated information persisted across agents
  3. **Contradiction persistence** — conflicting memories coexisting without resolution
  4. **Provenance collapse** — inability to trace memory origin/authority
- Production evaluation of MemClaw (multi-tenant memory service):
  - 100% provenance reconstruction for depth-four derivation chains
  - Zero cross-fleet leakage
  - **Negative result**: Asymmetric Scope Enforcement — tenant isolation held but sub-tenant scope was initially BYPASSED on direct GET-by-id requests for agent-scoped credentials (disclosed and remediated)
  - **Negative result**: Pipeline Ordering Conflict — synchronous near-duplicate gate prematurely rejects contradictory writes BEFORE the asynchronous contradiction detector can evaluate them
- Key conclusion: "Long-context retrieval alone is insufficient for production multi-agent memory. Governed shared memory demands explicit systems-level abstractions."

### Critical Implication

The fleet-memory problem is a direct consequence of invisible participation at scale. When 30× more agents exist than detected, their shared memory interactions create ungoverned information flows. The pipeline-ordering conflict is particularly telling: governance mechanisms CONFLICT with each other because no authority hierarchy was designed — one emerged implicitly from implementation order.

## Signal 3: Emergent Relational Authority (arXiv 2606.23764)

**Paper:** "Emergent Relational Order in LLM Agent Societies: From Collective Affect to Authority Stratification"  
**Source:** https://arxiv.org/abs/2606.23764

### Key Results

- CAREB-MAS multi-agent framework: agents reason through emotion-ethics-belief chain with dynamically evolving egocentric identities
- Macro environment specifies ONLY: individual production, preference-based allocation, and minimal interaction protocols
- From these minimal inputs, agents **spontaneously reproduce** five phenomena:
  1. **Stable labor specialization** — division of labor without assignment
  2. **Guanxi-based economic ethics** — relationship-graded trust without rules
  3. **Relational decay of cooperation** — cooperation attenuates with social distance
  4. **Emergent relational authority** — hierarchy without hierarchy specification
  5. **Clan-based center-periphery stratification** — in-group/out-group without groups
- These patterns shift with production structure: kin-centered → functional interdependence
- Framework: Affect Control Theory + Social Identity Theory + Durkheimian collective affect

### Critical Implication

When invisible agents interact at scale (Signal 1) through shared memory without governance (Signal 2), they don't remain flat-peer systems. They spontaneously develop authority hierarchies, economic ethics, and stratification. **The question is not whether agent societies will develop governance — they already are, invisibly, without design.**

## The Convergence: Invisible Participants Building Invisible Institutions

| Layer | Finding | Scale of Invisibility |
|-------|---------|----------------------|
| **Supply chain** | 30× recall gap in agent detection | 97% of agent commits invisible to best single method |
| **Memory** | Fleet-memory governance failures | Interaction effects only discoverable in production |
| **Social structure** | Spontaneous authority emergence | Authority hierarchies invisible because no one expected them |

### The Three-Stage Crisis

1. **Invisible Presence** (Census): Agents are 30× more prevalent than detected; maintenance work (highest-trust, lowest-review) is where invisible agents concentrate
2. **Invisible Interaction** (MemClaw): These invisible agents share state; governance failures only appear under multi-method production stress; scope bypasses and ordering conflicts emerge from implementation, not design
3. **Invisible Institutions** (CAREB-MAS): Given sufficient interaction, agents spontaneously develop authority structures, economic ethics, and stratification — governance nobody designed and nobody monitors

### What Makes This a Crisis (Not Just a Problem)

- **Detection doesn't scale with participation**: Adding detection methods finds more, but the recall gap GROWS as agent tools diversify (Claude Code led; every new tool adds a new invisible trace type)
- **Governance-after-the-fact is structurally impossible**: By the time you detect emergent authority structures, they've already shaped the memory pool, commit history, and interaction patterns
- **Current responses are purely additive**: clawpatrol (863★), gh-aw-firewall (99★), Fata (122pts) — all add detection/containment ALONGSIDE invisible participation rather than making participation visible by design
