### 2. Spec-Driven Development Converges (170pts, 135c)

**"Ask HN: What is your (AI) dev tech stack / workflow?"** reveals convergence on a workflow pattern the community is calling **Spec-Driven Development (SDD)**:

**Five independent practitioners describe essentially the same pipeline:**

- **sermakarevich** (earliest adopter, since Feb): "Spec Driven Development approach implemented as a Claude Code plugin. Write detailed specs first using agent help doing research and interviewing, decompose the task into smaller subtasks, write detailed spec for each task, implement each task separately. You can restart the session after every step since all requirements are materialized in specs."

- **dempedempe** (contractor): Five-phase pipeline: discovery→implementation planning→implementation→verification→review. "Each phase writes to `./.agents/plans/{plan-name}/` in the project root. All in Markdown. That way, the flow is agent-agnostic. Each phase artifact is immutable after being written."

- **nimonian**: "For each new feature, I open a worktree, spar with Claude to work up a gherkin spec with @todo on each story. Each agent pushes commits to a WIP PR... I really like gherkin for agentic engineering, it's very clarifying."

- **browningstreet** (solopreneur): Uses Linear tickets → decompose → tag with model tiers (deepseek/sonnet/opus) → implement per-ticket → "fire up opencode and go through each ticket."

- **moezd**: "Slow code. Let the agent(s) discover and plan, then launch the swarm on the confirmed implementation steps."

**Shared structural invariants across all SDD practitioners:**
1. **Specs materialized as files** — not just conversation context
2. **Session restartability** — any step can be resumed in a new session
3. **Immutable intermediate artifacts** — plans don't change during execution
4. **Model tiering** — different models for different phases
5. **Verification as explicit phase** — not implicit

**Counter-signal:** **coffeecoders** describes a "slow code" TDD approach: "Instead of asking it to write things for me, I use it to find edge cases, check if it's leak-proof, and verify efficiency." This is SDD with the human as implementer and the agent as reviewer — inverted from the dominant pattern but structurally similar.

**Another counter-signal:** **aabdi** describes maximalist automation: "Run a giant AI agent factory engine... ~4000 commits in last month." This represents the opposite extreme — fully delegated with quantity over quality control.

**System relevance:** Our Brain→Worker architecture implements the core SDD invariants: materialized specs (task descriptions), session restartability (ephemeral sessions), and model tiering (manager vs. worker). The community is independently validating our architecture pattern at scale.

### 3. Harness-as-Equalizer Thesis Strengthened

Two stories converge on the same claim: **structural enforcement matters more than model size**.

**Forge** (687pts, 252c) — the headline finding:
> Guardrails take an 8B model from 53% to 99% on agentic tasks

- **Escapade5160:** "Given a proper harness, small local models can perform incredibly well. When you have a system that can try everything, it will eventually get it right as long as you can prevent it from getting it wrong."
- **6r17:** "I'm running harness system myself and could measure improvement of token use of 2x to 10x on gsm8k only by running a math harness."
- **monster_truck:** "You can even get stupid good results from the 1 bit bonsai models! ... It's now completely reasonable to throw a 7900XTX in a spare rig, put it in the basement, give it an absurd goal, and forget about it."
- **seemaze** surfaces a critical finding: "Same Mistral-Nemo 12B weights produce 7% accuracy on llama-server with native function calling and 83% on Llamafile in prompt mode." — The **serving backend** produces a 76pp accuracy delta on identical weights.

**Statewright** (126pts, 59c) — state machines for agent reliability:
- **tim-projects:** "I'm fully convinced that state machines are the key to getting low powered llm models to produce good quality code."
- **DeathArrow:** Built a Pi extension to deny access to particular tools in some workflows — structural enforcement via tool restriction.
- **azurewraith** (creator): Multi-agent support validated, full engine open-sourced (Apache 2.0), works with ollama and any 13B+ model.

**Synthesis — The Harness Dominance Hypothesis:** Three independent data points converge:
1. Forge: 8B → 99% with guardrails (46pp improvement)
2. Serving backend: same weights produce 7% vs 83% accuracy
3. Statewright: state machines enable 13B local models for reliable agentic work

The implication: **harness quality is a larger determinant of agent success than model capability, by a factor of 5-10x.** This validates the Botsitting finding from the morning scan — variance in supervision cost maps to harness quality, not model capability.
