# arXiv Scan #289 — Coordination Tax Measured, Isolation Taxonomized, Step-Level Confidence
**Source**: arXiv API (cs.AI, cs.MA, cs.CR, cs.CL)
**Date**: 2026-07-15
**Scan type**: Supplemental triage — papers from July 13–14 not covered in scans 287/288

## High-Relevance Findings

### [2607.12216] RCWT: Measuring Task-Budget Displacement from Coordination Content in LLM Calls
- **Authors**: Lelis, Cabral-Carvalho
- **Core claim**: Multi-agent systems stuff coordination content (shared state, role instructions, summaries) into the same finite context window as task content. Every coordination token displaces a task token. They formalize this as "task-budget displacement" and introduce the Roundtable Context Window Test (RCWT) to measure it.
- **Key result**: At W=4096, models degrade sharply once residual task evidence drops to a few hundred tokens. But an intact-task ablation (expanding total prompt rather than displacing) shows NO degradation up to 95% coordination ratio — proving the cliff is displacement, not semantic interference from coordination volume.
- **Library relevance**: ★★★★★ — This is the first controlled empirical measurement of the phenomenon described in `the-coordination-tax.md` and `the-token-economics-trap.md`. The displacement-vs-interference distinction is a clean conceptual advance. The RCWT protocol is a reusable diagnostic.
- **Implication for our systems**: Any multi-agent orchestration with fixed context budgets should track residual task budget, not just total coordination overhead. Context window expansion is a valid mitigation; compression/summarization of coordination content is another.

### [2607.12406] Isolation as a First-Class Principle for LLM-Agent System Safety
- **Authors**: (not captured — cs.CR/cs.AI)
- **Core claim**: Safety for LLM agents is no longer just input-output alignment — it's about system behavior and real-world execution. Current literature is fragmented across attacks, applications, and benchmarks. They propose isolation as the unifying safety principle and provide a taxonomy: model isolation, tool isolation, memory isolation, inter-agent isolation.
- **Library relevance**: ★★★★ — Directly extends `agent-security-defense-architectures.md` and `agent-runtime-hardening.md`. The isolation-as-first-class framing is complementary to "the-guard-paradox" (guards share the same execution surface they protect). The taxonomy could become a reference structure for our security notes.
- **Implication**: Container/sandbox isolation for tool execution, memory partitioning between agents, and model-level isolation (preventing cross-prompt leakage) should be treated as three independent failure surfaces, not one monolithic "sandbox" concept.

### [2607.12397] Critic Experience Bank: Self-Evolving Step-Level Confidence Estimation for LLM Agents
- **Core claim**: Agents need step-level confidence (not just final-answer confidence) because a single wrong action can waste budget or cause irreversible side effects. They propose a "Critic Experience Bank" — accumulated experience of which action patterns succeed/fail in context — that evolves as the agent encounters new environments.
- **Library relevance**: ★★★★ — Extends `agent-self-correction-trends-2026.md` and `agent-evaluation-research-beyond-outputs.md`. Step-level confidence is the missing piece between "the agent tried" and "the agent knew it was uncertain." The experience bank is a form of procedural memory (cf. `agent-memory-patterns.md`).
- **Implication**: For our agent systems, a lightweight version of step-level confidence could gate tool-use decisions: if confidence is below threshold, ask for human input rather than proceeding. This connects to the deference spectrum (`the-deference-spectrum.md`).

### [2607.12723] Bulkhead: Automated Semantic Detection and Remediation of Container Escape Vulnerabilities
- **Core claim**: Multi-agent LLM systems with container-mounted workspaces (GPUs, shared volumes) create path-traversal (PaTra) vulnerabilities. They use a multi-agent system with LLMs + formal methods to detect and patch these.
- **Library relevance**: ★★★ — Practical security finding. Reinforces `agent-security-defense-architectures.md` — the attack surface isn't just prompt injection; it's the physical infrastructure shared between agents and hosts.

## Cross-Cutting Synthesis

Three papers in this batch (RCWT, Isolation, Critic Experience Bank) converge on the same theme: **the operational costs of agent composition are becoming measurable**. 

- RCWT measures the token-budget cost of multi-agent coordination
- Isolation taxonomizes the safety cost of shared execution surfaces  
- Critic Experience Bank measures the confidence cost of each action step

This extends the library's existing "tax/cost" pattern family (coordination tax, token economics trap, session floor) from conceptual frameworks toward empirically grounded measurement protocols. The field is transitioning from "agents have overhead" to "here's exactly how much and where."
