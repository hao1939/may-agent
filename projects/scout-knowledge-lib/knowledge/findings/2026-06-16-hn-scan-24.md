## Synthesis: The "Harness Investment" Thesis

Three independent signals converge on a new principle:

1. **chrismarlow9**: Frontier model creates plan → local model executes →
   specificity compensates for capability gap
2. **xienze**: AGENTS.md + skills investment = the real cost of local
3. **pwython**: Built a full Google Home replacement by investing in harness
   (markdown context files, cross-session memory, wake word integration)

**Principle:** The cost of local sovereignty is not hardware (that's a one-time
investment). The cost is **harness engineering time** — writing skills,
configuring context, building integration points. This is a one-time cost
per user that amortizes to near-zero over time, unlike subscription fees
that compound forever.

This resolves the "local models are worse" counter-argument: yes, the raw
model is worse, but with sufficient harness investment, the *system* performs
comparably for daily tasks. The harness IS the agent (KE-1633 validated again).

## Agent Architecture Implications

### Frontier-Plans/Local-Executes (New Pattern)

chrismarlow9's architecture maps cleanly to our manager/worker design:
- **Manager** (frontier model via API): Creates specific plans, makes creative
  decisions, handles complex reasoning
- **Workers** (local models): Execute compartmentalized tasks from specific
  plans, handle mechanical work

This provides a cost optimization path: use frontier tokens only for planning
(low volume, high value) and local tokens for execution (high volume, low
complexity). The "dumber the model can be" observation means local workers
need simpler tool sets (confirmed by atn34's "bash + str_replace suffice"
from scan #19).

### Tool-Call Reliability Gap (cube00)

The last mile for local models: hallucinated JSON tool responses. This
suggests local-model workers need:
1. **Simpler tool interfaces** (fewer parameters, structured templates)
2. **Validation layers** (parse tool calls before execution)
3. **Retry with formatting hints** (cheaper than switching to frontier)

This is a harness-level solution, not a model-level one — further confirming
KE-1633 (The Harness Is The Agent).

### Consumer Sovereignty Validates Offline-First Design

pwython's Google Home replacement architecture:
- Gemma 4 26b-a4b (on Mac)
- Raspberry Pi Zero 2 W (satellite)
- openWakeWord + faster-whisper (on-device speech)
- Orpheus-TTS (streaming reply)
- Cross-session memory (markdown files)
- Business & personal context (markdown files)

This is our system's architecture at the consumer level:
local model + structured context files + cross-session memory + minimal
hardware. Community is independently converging on the same patterns.
