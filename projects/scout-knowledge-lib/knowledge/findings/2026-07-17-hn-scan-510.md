2. **Scribe** — CLI that builds agent memory from repos and sessions. Source: https://getscribe.dev/

**Pattern:** Agent memory is entering a Cambrian explosion of competing approaches—embedded DBs, CLI tools, shared commons. No convergence on a standard yet. Distinct from the *attack* surface work (MemPoison, Bad Memory) captured in arXiv scans.

### MemDecay: Training-Free KV-Cache Eviction for Agents (arxiv 2607.10582)
Source: https://arxiv.org/abs/2607.10582
Region-aware KV-cache eviction that respects semantic structure (system instructions, plans, user turns, tool outputs). Treats different context regions with different eviction policies rather than uniform attention/recency rules. Directly relevant to long-running agent sessions where context windows fill up.

**Implication:** Runtime memory management is moving from "evict oldest tokens" to "understand what kind of context you're evicting." This is the infrastructure layer that makes 1M-context agents practical.

## Synthesis

**Agent memory is bifurcating into two distinct tracks:**
1. **Attack surface** (MemPoison, Bad Memory, Memory Heist) — memory as vulnerability
2. **Infrastructure race** (AegisDB, Scribe, Cq, MemDecay) — memory as competitive feature

These two tracks will collide: the infrastructure builders haven't yet internalized the attack surface research. Whoever integrates both first (usable memory infra with built-in poisoning resistance) captures the market.

Meanwhile, Codex prompt encryption at 425↑ shows vendors are already making unilateral decisions about agent transparency—before any standards or norms exist. The Observability Trap is being built in real time.
