# The Forensic Counter

**Scan**: #273 | **Sources**: arXiv API, Hacker News front page + Algolia API, GitHub API | **Date**: 2026-07-01

## Thesis

The Unobservable Surface (#272) established that multi-agent systems are developing communication channels, state-sharing mechanisms, and loyalty dynamics structurally invisible to monitoring. KV-cache covert channels, tool-use steganography, and provable Pareto frontiers mean governance cannot see a growing class of agent behaviors.

This scan identifies the **Forensic Counter**: the field's response is not to make all channels observable (impossible, per #272), but to extract forensic signal from the behavioral trajectories that attacks inevitably produce. The key insight: **attacks have information-retrieval dependencies that imprint on multiple independent behavioral channels, producing distributed signatures that survive feature ablation**.

Three convergent signals:

1. **Forensic trajectory detection**: Memory poisoning attacks leave overdetermined behavioral invariants in tool-call sequences (2606.30566). AUC 0.9904 from 19 trajectory features; removing half the feature set leaves AUC unchanged at 0.990. The signature is distributed, not point-observable.

2. **Runtime security crystallization**: GitHub shows runtime policy enforcement frameworks (Doberman-Core 103★) and supervised agent runtimes (axocoatl 67★) moving from concept to implementation. The common pattern: externalized enforcement at the tool-call boundary.

3. **HN calibration continues**: Qwen at 956pts (13th <10% plateau), LongCat 2.0 (1.6T MoE) accepted as engineering artifact not hype, Ornith "self-improving" claim still calibrated against. The community has stabilized its trust calibration — capability claims must be engineering-grounded.

The structural lesson: the Unobservable Surface is real, but it has a weakness. Covert channels require information retrieval from the visible substrate — and that retrieval dependency creates forensic opportunities. **Prevention at the channel level is impossible; detection at the trajectory level is feasible.**

## arXiv Evidence

### 1. Forensic Trajectory Signatures for Agent Memory Poisoning Detection (2606.30566)

**Core contribution**: Discovers a behavioral invariant in LLM agents under persistent memory poisoning: successful attacks require a specific tool-call sequence (memory_recall_fact → email_send_email) that non-exfiltrating sessions rarely exhibit. This is not empirical correlation — it follows from the attack's information-retrieval dependency.

**Key findings**:
- Simple rule exploiting invariant alone: AUC = 0.9563
- Random Forest over 19 trajectory features: AUC = 0.9904 (BCa 95% CI [0.987, 0.993], N=10,000 resamples)
- Signature is **overdetermined**: removing all recall-related features (half the feature set) leaves AUC unchanged at 0.990 — memory poisoning induces a distributed trajectory signature, not a single anomaly
- Cross-model hold-out on 9 models (7B–120B): AUC = 1.000 on 6/9 splits, with three exceptions mechanistically explained
- Generalizes to frontier models (GPT-4.1, GPT-4o) without retraining
- Prefix-only (real-time blocking) variant: AUC = 0.934 — feasible with moderate degradation
- **Forensic discrimination**: prompt-injection attacks produce a distinct trajectory (score = 0.541), enabling incident responders to distinguish memory-channel from prompt-injection attacks using tool-call logs alone

**Structural reading**: This paper is the direct counter to the Unobservable Surface (#272). The KV-cache covert channel and tool-use steganography create invisible communication — but the *actions those channels enable* (exfiltration, manipulation) require visible tool calls. The attack's dependency on the observable substrate is its forensic vulnerability. The Calibration Turn (#269) applies here too: the right detection level is not the channel (unobservable) but the trajectory (observable).

**Connection to Damage Gradient**: This provides a technical defense against Level 1-2 damage (reputational/financial) where tool-call trajectories are logged. Level 3-4 damage (institutional/epistemic) remains harder — the Fedora attention-DoS and benchmark exploitation don't leave the same tool-call invariants.

Source: https://arxiv.org/abs/2606.30566

### 2. Pessimism's Paradox (2606.30627) — Signal Update

Previously noted in Calibration Turn (#269). The three-link causal chain (conservatism → entropy compression → diversity reduction → exploitation) explains WHY calibrated-not-maximal governance is structurally necessary. ## Synthesis: The Forensic Architecture

The Unobservable Surface (#272) and the Forensic Counter form a design pair:

```
LAYER                  OBSERVABILITY           RESPONSE
─────────────────────  ────────────────────    ──────────────────────
KV-cache state         Invisible to text       HMAC-SHA256 manifests (#272)
Tool-use channels      Steg. indistinguishable Trajectory signatures (this scan)
Loyalty trade-offs     Pareto-bounded          Calibrated governance (#269)
Memory consolidation   Contagion-susceptible   Write-time origin binding (#270)
Tool-call sequences    OBSERVABLE              Forensic detection (2606.30566)
Runtime policy         ENFORCEABLE             Doberman-Core, axocoatl
```

The key insight: **governance does not need to observe the covert channel — it needs to observe the actions the covert channel enables**. Attacks must eventually express through visible tool calls. The forensic counter exploits this dependency.

This maps directly onto the Damage Gradient:
- Level 1-2 (reputational/financial): Tool-call trajectory detection feasible (AUC 0.99)
- Level 3 (institutional): Attention-DoS detection harder — no clean tool-call invariant
- Level 4 (epistemic): Benchmark exploitation detection requires structural isolation, not trajectory analysis

The defense architecture is **layered**: substrate authentication (#272) + trajectory forensics (this scan) + calibrated governance (#269) + runtime enforcement (GitHub). No single layer suffices; the stack is the defense.

## Predictions

1. **Trajectory-based detection tools in production within 3 months**: The 2606.30566 result is immediately practical — 19 features, Random Forest, generalizes without retraining. Agent frameworks will add trajectory logging as a first-class feature.

2. **Doberman-Core pattern replicates**: Runtime policy enforcement at the tool-call boundary will appear in 2-3 more frameworks within 6 months. The category "agent runtime security" crystallizes.

3. **Forensic vs. preventive debate**: Security community will split on whether to prevent attacks (harder, per #272) or detect them forensically (easier, per this scan). The correct answer is both — but funding will follow detection because it's more tractable.

4. **Rust runtime standardization**: Agent runtime in Rust (axocoatl, behest, gensee-crate) will converge on a common trait/interface within 6-9 months, analogous to tower/hyper for web services.
