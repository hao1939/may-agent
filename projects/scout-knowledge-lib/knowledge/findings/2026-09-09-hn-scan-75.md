## Core Finding

A structural pattern emerges from connecting three arXiv papers on skill representation, a dominant GitHub project (SkillOpt, 8.5k★), and several HN front-page signals: **natural-language skill files (SKILL.md, AGENTS.md, best_skill.md) are approaching a performance ceiling**, and three competing architectural directions are emerging to replace them.

This is the next phase of the Compilation Gradient applied to agent capabilities: skills stuck at Stage 1 (text in prompt) are being pushed toward Stage 2 (structural/compositional) and Stage 3 (compiled/latent). The transition is contested — each direction trades inspectability for performance — and the outcome will determine how agent capabilities are stored, shared, and evolved.

## Evidence Streams

### Stream 1: The arXiv Skill Cluster (2606.20333, 2606.20363, 2606.19758)

Three papers from June 2026 independently attack the same problem: how should agent skills be represented?

**SoftSkill (2606.20333)** — Behavioral Compression for Contextual Adaptation:
- Key thesis: "Agent skills are commonly deployed as natural-language Markdown files... but they are consumed indirectly: for each task instance, a frozen language model must translate a long textual artifact into generation-time behavior."
- Proposes: Replace Markdown skill tokens with a length-32 learned soft prefix (latent behavioral prior)
- Results: +8.3pts SearchQA, +42.1pts LiveMath, +1.3pts DocVQA over no-skill prompting. +5.2pts and +12.5pts over SkillOpt on SearchQA/LiveMath
- Critical limitation: "does not yet robustly compress long-horizon procedural behavior" — single-turn strong, multi-turn weak
- Implication: **Some skills are better as latent controls than as re-interpreted text**

**SKILL.md Mining (2606.20363)** — Automating SKILL.md Generation via Interaction Trajectory Mining:
- Three-stage pipeline: segment GUI trajectories → cluster into candidate skills → train skill-aware policy
- Results: 5/8 clusters achieve ≥0.95 purity (inspectable), BUT policy improvement is marginal (18.5% → 20.5%)
- Self-assessment: "readability does not imply transfer" — the method produces inspectable structure but NOT reliable behavioral improvement
- Implication: **Mining skill structure from traces is possible but insufficient for cross-domain policy transfer**

**SIGMA (2606.19758)** — Skill-Incidence Graphs for Compositional Multi-Agent Design:
- Innovation: Instead of optimizing communication topology over fixed agents, constructs agents as task-conditioned bundles of reusable skills
- Mechanism: Predicts skill-agent incidence matrix → composes agent embeddings from selected skills → decodes communication topology
- Skill-specific mailboxes route messages to relevant capabilities
- Results: +2.06–2.36pts over strongest topology-only baseline; robust to unseen skill libraries (only -0.96pt drop)
- Implication: **Skills as composable primitives that construct agents, rather than static files that agents consume**

### Stream 4: NRT-Bench — Disjoint Vulnerabilities (2606.20408)

Critical finding for multi-agent system design:
- Multi-turn adversarial attacks on LLM agents in safety-critical roles (nuclear plant simulation)
- 8.7%–12.1% of attack sessions breach safety across four frontier models
- **Key insight**: "Vulnerabilities are nearly disjoint across models rather than nested — of 149 sessions, none defeat all four models while a third defeat at least one"
- **Same guardrail stack that lowers attack success for one model can raise it for another**
- Implication: **Model diversity is defense**, and **universal guardrails are harmful** — you need model-specific compiled defenses

Source: https://arxiv.org/abs/2606.20408

### The Structural Tension

The crisis is a manifestation of the Compilation Gradient at the skill layer:

- **Stage 1** (current dominant): Skills as Markdown files consumed by frozen models. Inspectable, portable, but performance-limited. SkillOpt sits here and optimizes within the constraint.
- **Stage 2** (emerging): Skills as structural primitives that shape agent composition (SIGMA) or message routing (skill-specific mailboxes). Partially inspectable.
- **Stage 3** (experimental): Skills compiled into latent representations (SoftSkill). Maximum performance, minimal inspectability. Multi-turn behavior "does not yet robustly compress."

The NRT-Bench finding adds a constraint: **compiled skills must be model-specific** because the same skill instruction produces disjoint behavior across models. A universal skill file is inherently limited.

## Predictions

1. **Within 6 months**: SkillOpt or a derivative will add a "soft-skill compile" target — train the text skill, then optionally compile to latent prefix for deployment. The text remains the source, the latent becomes the artifact.

2. **Within 12 months**: Compositional skill graphs (SIGMA-style) will appear in production frameworks. The first signal will be frameworks offering "skill registries" with dependency/composition metadata beyond flat file directories.

3. **"When I Reject AI Code" will peak above 300pts** and produce a concrete tool or framework for structured rejection criteria (not just a blog post). The growth trajectory (44→74→126→197) suggests it's approaching crystallization.

4. **NRT-Bench's disjoint-vulnerability finding will reshape guardrail design**: universal guardrail stacks will be deprecated in favor of model-conditioned defense configurations. "One guardrail fits all" becomes recognized as harmful.

## Relevance to This System

- Our SKILL.md files (agents/scout/skills/) are firmly in the Text-Space Optimization quadrant
- SoftSkill's finding that 32 latent tokens outperform thousands of Markdown tokens suggests our skill files may be consuming context budget inefficiently
- SIGMA's compositional approach mirrors our multi-agent structure but we compose agents from roles, not from skill graphs
- The Martin Fowler "context discipline" signal validates our existing work on context management but suggests room for more aggressive exclusion
- NRT-Bench's disjoint-vulnerability finding implies our multi-model deployment strategy should explicitly vary models per agent to maximize defensive diversity
