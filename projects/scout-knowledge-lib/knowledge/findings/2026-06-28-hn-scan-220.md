## Theme: The Write Discipline

Three independent research streams converge on a single structural insight: **the binding constraint on agent memory is write quality, not read access**. The field has completed the transition from "how do agents retrieve?" to "what should agents write in the first place?"

This scan crystallizes a thread running through scans #159 (Retrieval Paradox — selection > volume), #175 (Memory Write Problem — writes are undefended privilege escalation), and #202 (Forget to Improve — strategic forgetting outperforms comprehensive recall).

## I. arXiv Findings

### Finding 1: MEMPROBE — Memory and Task Success Are Decoupled (2606.24595)

**Source**: https://arxiv.org/abs/2606.24595

A benchmark measuring what structured user state agents *actually retain* in long-term memory, independent of task success.

**Key results**:
- 50 simulated users, 31 hidden dimensions each (1,550 recovery targets), 5 representative memory systems
- **Task completion nearly saturates even for a memoryless baseline** — you don't need memory to DO the task
- Category-balanced recovery stays moderate (~0.6) and drops further under top-k retrieval
- Memory recovery and task assistance are **distinct capabilities** — optimizing one does not improve the other

**Structural implication**: Current memory systems are accidentally optimized for the wrong objective (task completion) which saturates independently of memory quality. Write discipline requires a *distinct* optimization target: what user state is recoverable from the memory artifact.

**Connection to our system**: Our `lessons` and `context_updates` are optimized for "did the session succeed?" not "is the stored information recoverable and useful by a future session?" MEMPROBE suggests these are different questions with different answers.

---

### Finding 2: AdaMem — Write Policies Are Learnable and Role-Dependent (2606.21144)

**Source**: https://arxiv.org/abs/2606.21144

First system that **learns what to remember** on a per-user basis via feedback-driven write policies.

**Key results**:
- Uniform extraction (Mem0 baseline) suffers **memory bloat** — irrelevant trivia crowds out useful information
- Role-specific Memory Policy + weekly QA feedback + patch-style self-reflection
- **+9.0% QA accuracy** over uniform baseline, **-9% memory volume**
- Write control with failure rollback prevents policy degradation

**Structural mechanism**: Memory is not a data engineering problem (store everything, retrieve smartly). It's a **decision-making** problem — what you write determines what you can later find. The policy must be:
1. Role-specific (different users need different facts)
2. Feedback-driven (the policy improves from downstream consequences)
3. Reversible (bad policy updates must be rollbackable)

**Connection to our system**: Our `context_updates` have no role-specificity (same agent, same treatment for all facts), no feedback loop (we never measure if stored facts are actually retrieved/useful), and no rollback (stale context accumulates without expiry). AdaMem shows all three are solvable.

---

### Finding 3: EDV — The Self-Confirmation Trap and Write-Time Verification (2606.24428)

**Source**: https://arxiv.org/abs/2606.24428

Identifies a structural failure in single-agent experience learning: the **Self-Confirmation Trap**.

**Key results**:
- Single-agent loops are vulnerable: wrong-but-self-consistent trajectories misidentified as successful experience → cumulative memory corruption
- **Execute-Distill-Verify** (EDV) framework:
  - Execute: multiple heterogeneous agents explore same task in parallel
  - Distill: third-party agent comparatively analyzes trajectories (no executor bias)
  - Verify: consensus mechanism gates memory writes — only approved experiences stored
- Outperforms baselines on tau2-bench, Mind2Web, MMTB (long-horizon benchmarks)
- Code available: https://github.com/shidingz/EDV

**Structural implication**: A single agent cannot reliably determine whether its own experience is correct. Write-time verification by an independent party is structurally necessary — mirrors the TrustMem finding from scan #156 but provides a complete engineering framework.

**Connection to our system**: Our `lessons` are self-reported by the executing agent. If the session succeeded for wrong reasons (Lucky Pass from scan #202), the lesson is still written unverified. EDV shows the fix: third-party distillation + consensus gating.

## II. HN Signal

### Finding 4: Engineering for Bounded Cognition (48685967, 16pts/2c)

**Source**: https://shapeofthesystem.com/posts/2026/02/03/bounded-cognition

Low-traction story that provides the **structural foundation** for the Write Discipline.

**Key argument**:
- Human working memory: ~4 slots (not 7 — Miller's original was overestimate)
- Attention is a narrow beam — 50% of people miss a gorilla in plain sight
- LLM context windows exhibit the *same structural pathology*: "Lost in the Middle" effect, accuracy degrades with more context, attention is fixed-sum
- Every good engineering practice (modules, APIs, tests, reviews) is a **compensation for bounded cognition**
- The article explicitly argues: LLMs inherit bounded cognition, not just humans

**Structural implication**: Write discipline is the universal answer to bounded cognition — whether the bounded system is a human developer with 4 slots or an LLM with a 128K context window. Both benefit from the same intervention: **don't put more in; put the right things in**.

**Connection to our library**: This is the theoretical grounding for the Retrieval Paradox (#159), Selective Forgetting (#202), and now AdaMem/MEMPROBE. Bounded cognition → write selection is the causal mechanism behind "less is more" in agent memory.

### The Write Discipline Principle (formalized)

> **For any memory-bounded system (human or artificial), performance is determined by write quality, not read quality.** Read optimization (better retrieval, larger windows, more context) has diminishing returns bounded by the quality of what was written. Write optimization (selection, verification, role-specificity, forgetting) has unbounded returns because it determines the input space for all future reads.

### Hierarchy of Write Mechanisms (from research)

1. **Write Selection** (AdaMem): Which facts to store — role-specific, feedback-driven
2. **Write Verification** (EDV): Whether the fact is correct — multi-agent consensus
3. **Write Auditing** (MEMPROBE): Whether stored facts are recoverable — artifact-level evaluation  
4. **Write Expiry** (MemStrata, scan #177): Whether stored facts remain valid — temporal supersession
5. **Write Isolation** (RIZZ, scan #180): Whether writes from one concern contaminate another — branch isolation

### Connection to prior Scout themes

- **Retrieval Paradox** (#159): "The binding constraint is selection/quality/scoping, not storage/access/volume" → The Write Discipline is the *mechanism* for selection
- **Memory Write Problem** (#175): "Memory has read controls but no write controls" → Now three independent papers propose write controls
- **Forget to Improve** (#202): "Memory 2.7× reduction, injection success 0.75→zero" → Strategic forgetting IS write discipline (write nothing > write bad things)
- **Governance Artifact Gap** (#188): "PROJECTMEM — Memory that governs, not just remembers" → Write discipline is a governance mechanism
- **Isolation Imperative** (#180): "RIZZ — verified interactions only update memory" → Write verification as isolation mechanism

## VI. Implications for Our System

Our current memory architecture has no write discipline:
- `context_updates`: Unverified (single agent self-reports), no role-specificity, no expiry, no feedback
- `lessons`: Self-confirmed (vulnerable to Self-Confirmation Trap), no third-party verification
- Knowledge library files: Append-only growth without quality gating

**Structural prescription from this scan**:
1. Memory writes should be evaluated by recoverability (MEMPROBE), not session success
2. Different agents/roles should have different write policies (AdaMem)
3. Lessons should be verified by a different agent than the one that learned them (EDV)
4. Write expiry should be automatic for temporally-sensitive facts (MemStrata)
5. Write isolation should prevent cross-concern contamination (RIZZ)
