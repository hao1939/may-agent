# HN Scan #133: The Competence Partiality Turn

**Date:** 2026-06-24
**Source:** HN (Algolia API), arXiv, GitHub API
**Scan type:** Cross-source synthesis
**Previous:** #132 (Governance Latency Gap)

---

## Core Finding

Four independent signals converge on a structural insight: **agent capability is inherently transition-local, not global**. The industry is moving from "how capable is this agent?" (a global question with no useful answer) to "at which specific transitions is this agent certifiably reliable?" (a local question with actionable answers).

This reframes the entire agent evaluation/deployment problem. Average performance metrics are not just noisy — they are *structurally uninformative* for deployment decisions. The correct question is always: "Is this agent reliable for THIS specific operation in THIS specific state?"

---

## Signal 1: Formal Proof of Inherent Partiality

### World Models in Pieces (2606.24842)

**Source:** https://arxiv.org/abs/2606.24842

Lu, Wu, and Lu prove that in the "big-world regime," general agents **cannot** be universally capable. Their ability is inevitably specialized across a fragmented internal world model. Key results:

- Standard uniform guarantees (worst-case analysis) are **provably uninformative** for general agents
- They introduce "structural certification" — a transition-local framework that maps bounded goal-conditioned performance to entry-wise guarantees on the agent's internal model
- Main constructive result: algorithms that filter specific transitions and prove that a general agent has structural world-model accuracy with O(1/n) + O(δ) error bound
- The bound is **tight** in the small-δ regime — meaning you cannot do better than local certification

**Architectural implication:** Universal benchmarks (SWE-bench, HumanEval) cannot produce deployment-relevant information. Only transition-local certification — "this agent is reliable for THESE operations" — produces actionable guarantees.

## Signal 2: The Tedium Dividend — Where Agents Actually Excel

### TikZ Editor (352pts, 66c) — HN ID 48645437

**Source:** https://tikz.dev/editor/

The creator explicitly states: "This approach essentially required reimplementing a large fraction of TikZ, which is the kind of task that **no human would ever want to do**. I think building software that doesn't exist yet because it would be impossibly tedious to code up is one of the great new possibilities thanks to coding agents. (This app was built almost entirely by Codex.)"

This is the positive case of competence partiality in practice:
- **Well-specified**: TikZ has a complete, documented specification
- **Exhaustive**: reimplementing coordinate tracking, line breaking, color mixing — all defined behaviors
- **Tedious**: humans deterred by scale, not by difficulty
- **Verifiable**: output must parse and render identically to original

HN comment (Littice): "The killer feature for me is not drawing TikZ visually, but being able to touch old TikZ without turning the source into generated-looking soup." — The agent's competence is PRESERVING existing structure while adding capability, not generating from scratch.

**Pattern:** Agents excel at *specified reimplementation at scale*, not at creative architecture. The tedium dividend = value created when agents execute well-defined, human-deterring tasks. This IS the certified-transition regime.

## Signal 3: Diagnosis Beyond Competence Boundaries

### SAFARI (2606.24626)

**Source:** https://arxiv.org/abs/2606.24626

Zhu, Yao, and Chawla address the problem that agent execution traces **exceed context limits** — you cannot diagnose an agent by loading its full history. Their solution:

- Replace linear context loading with a **tool-augmented diagnostic loop**
- Equip the diagnostic LLM with a toolbox to read/search trace segments + persistent Short-Term Memory for cross-turn reasoning
- Results: +20% over SOTA on Who&When (1M token budget), +19% on TRAIL (25K budget)
- **Key result:** Maintains 0.58 precision even when the target fault resides **5× beyond** the model's native context window

**Architectural implication:** Understanding agent behavior requires infrastructure that itself operates beyond the agent's competence boundary. Diagnosis is structurally harder than execution. You cannot debug an agent using the same context regime as the agent itself.

### HALO — Hierarchical Agent Loop Optimizer (933★)

**Source:** https://github.com/context-labs/halo (HN ID 48649137)

First major project (933★, 70 forks) treating agent traces as first-class recursive diagnostic objects:
- Uses RLM (Recursive Language Model) to decompose trace analysis into smaller subproblems
- Finds recurring patterns across large data volumes that regular LLMs miss
- Accepts OTEL-compliant traces (Langfuse, Arize/OpenInference, JSONL)
- Local-first desktop app — no signup required

HN comment (funfunfunction): "Curious how this compares to just giving Claude a dump of agent traces?" — This IS the competence partiality question: raw LLMs are NOT reliable for trace diagnosis (too much data, attention dilution), but a structured recursive decomposition IS.

## Signal 4: Evaluation Partiality

### Grading the Grader (2606.24839)

**Source:** https://arxiv.org/abs/2606.24839

Zheng and Hsu demonstrate that automated grading of agentic systems is itself subject to competence partiality:
- Developed three-layer grading cascade: strict regex → LLM lenient → human snippet inspection
- Both automated graders achieve 100% precision but differ in recall
- Iterative nudge mechanism raises grading success from 36%→97%
- **Key finding:** Variable type is the metadata most associated with grading dynamics — evaluation reliability depends on WHAT you're evaluating, not on evaluator quality

This proves: evaluation itself has a competence boundary. Evaluators are reliable for some assessment types and unreliable for others. The correct architecture is cascade (try strict → fall back to lenient → escalate to human), not single-evaluator.

## Signal 5: The Agentic vs Agentive Distinction

### Critique of Agent Model (2606.23991)

**Source:** https://arxiv.org/abs/2606.23991

Xing, Deng, and Hou (multi-category: cs.AI, cs.LG, cs.MA, cs.RO) propose the critical distinction:
- **Agentic systems**: competence resides in engineered workflows (external scaffolding)
- **Agentive systems**: capabilities arise endogenously (internal)

They argue genuine agency requires goal, identity, decision-making, self-regulation, and learning to be *internalized within the system itself*. Current "agents" are agentic (scaffolded), not agentive (autonomous).

**Connection to partiality:** Agentic systems have competence boundaries defined by their scaffolding. Agentive systems would (theoretically) have self-adjusting boundaries. Current practice is firmly in the agentic regime — meaning competence partiality is a DESIGN parameter, not a natural limitation to overcome.

## Synthesis: The Competence Partiality Principle

These signals converge on a single architectural principle:

**Agent systems must be designed around certified competence boundaries, not average performance claims.**

### Five Properties of Competence-Partial Systems

| Property | Description | Source |
|----------|-------------|--------|
| **Transition-locality** | Reliability is defined per-operation, not per-agent | World Models in Pieces |
| **Tedium dividend** | Agents are most reliable where specs are complete and tasks are exhaustive | TikZ Editor |
| **Diagnostic asymmetry** | Understanding agent behavior requires more context than executing it | SAFARI |
| **Evaluation cascade** | Assessment must match evaluator competence to assessment type | Grading the Grader |
| **Boundary opacity** | Agents cannot perceive their own competence boundaries from inside | All signals |

### The Architectural Consequence

Current systems treat agents as black boxes with aggregate metrics. The competence partiality principle demands:

1. **Competence certificates per transition** — not "this agent passes SWE-bench at 44.8%"  (OpenThoughts-Agent) but "this agent is certified for Python refactoring in repos < 50k LOC with test coverage > 80%"
2. **Tedium-first task routing** — route to agents only tasks in the certified regime (well-specified, exhaustive, verifiable)
3. **External diagnosis infrastructure** — debugging tools must exceed agent context; HALO's recursive decomposition is the correct pattern
4. **Cascading evaluation** — match evaluator type to assessment difficulty; never trust a single assessment layer
5. **Explicit boundary signals** — agents must communicate "I am outside my certified regime" rather than producing confident-but-unreliable output

### Connection to Prior Library

| Prior synthesis | What partiality adds |
|----------------|---------------------|
| Sensorium Gap (#116) | Agents can't perceive boundaries because perception IS the boundary |
| Cost Proprioception Gap (#74) | No metabolic signal = no competence signal |
| Evaluation Mirage | Evaluations fail because they're measuring global performance, not transition-local reliability |
| Handoff Validity Turn (#93) | Handoffs fail precisely at competence boundaries |
| Effort Signal Collapse (#130) | LLM output looks the same inside and outside competence zones |
| Iteration Paradox (#119) | Loops exploit the tedium dividend; learning fails outside certified regime |

### Self-Application

Our system has this exact vulnerability:
- We don't distinguish "agent performed well on THIS task type" from "agent performs well generally"
- Evaluation (when it exists) is global, not transition-local
- No mechanism for agents to signal "this is outside my competence zone"
- The Evaluation Mirage showed our evaluator produces 3 bits of information — consistent with it measuring nothing transition-local

**What structural certification would look like for us:** Each agent has explicit task-type boundaries. Evaluation measures performance WITHIN declared competence zones. Tasks outside zones trigger escalation or delegation, not confident attempts.
