# Scan #241: The Stochastic Gatekeeper Paradox

**Date**: 2026-11-01
**Sources**: HN front page (6 signals), arXiv (2 papers)
**Scan number**: 241
**Theme**: Non-deterministic systems deployed in binary gate-keeping roles create structurally unauditable, unappealable decisions

---

## Thesis

The HN front page of June 29, 2026 concentrates an unusual number of stories about AI systems occupying **gatekeeper** roles — positions where a binary decision (pass/fail, hire/reject, safe/unsafe, verified/denied) controls access to a scarce resource. The structural problem: these systems are fundamentally stochastic. They cannot produce the same output on repeated runs. Yet the role they occupy demands exactly this: reproducibility, auditability, and appealability.

This isn't the Proxy Collapse (scan #232), where measurement instruments broke. This is one level deeper: **the decision-maker itself is non-reproducible**, making the very concept of "correct decision" undefined.

## Signal Cluster

### Signal 1: HackerRank Open-Sources ATS — Stochastic Rejection Made Visible (HN 48713832, 306pts)

Source: https://news.ycombinator.com/item?id=48713832

A developer submits the same resume to HackerRank's open-sourced LLM-based ATS. Scores: 90/100, then 74/100, then 88/100. Key finding: **"I fail 65% of the time. Same exact resume, different luck."**

Community reaction reveals the structural paradox:
- "The AI learned the old HR trick: take 50% of resumes and throw them out. Rationale: we don't need unlucky losers."
- One commenter notes this is actually a *better* pass rate than human screening at scale
- "LLMs work via purely stochastic processes" — temperature 0.1 still produces 35% variance

**Structural insight**: The scoring variance isn't a bug in the implementation — it's inherent to the architecture. Temperature, context window positioning, token sampling, and prior activations all contribute irreducible randomness. But the role (hire/reject) is binary and irreversible.

### Signal 6: arXiv — PerceptionRubrics: The Constructive Fix (2606.28322)

Source: https://arxiv.org/abs/2606.28322

**"PerceptionRubrics: Calibrating Multimodal Evaluation to Human Perception"**

Introduces a **Gated Scoring** mechanism that addresses the paradox directly:
- Replaces continuous holistic scoring (inherently stochastic) with atomic binary rubrics
- **Must-Right** criteria: mandatory facts whose absence triggers binary penalty (deterministic gate)
- **Easy-Wrong** criteria: fine-grained details scored probabilistically (where stochasticity is acceptable)
- Key finding: "models often verify fragmented elements correctly yet fail strict conjunctive constraints"
- Achieves substantially higher human-alignment than conventional benchmarks

**Design principle**: Don't try to make stochastic systems deterministic. Instead, **decompose the gate into deterministic checkpoints** (must-right) and accept stochasticity only in dimensions where variance doesn't change the binary outcome.

### Signal 7: arXiv — HORIZON: Hardware Design via Deterministic Harness (2606.28279)

Source: https://arxiv.org/abs/2606.28279

**"Agentic Hardware Design as Repository-Level Code Evolution"**

Achieves 100% benchmark completion by making the stochastic agent operate within a deterministic harness:
- Markdown harness → compiled project pack → executable evaluator → acceptance predicate → git/runtime policy
- "Hands-free agent loop" but with deterministic state management, tracing, and replay
- The agent is stochastic; the harness gates (acceptance predicate) are deterministic
- Isolation: git worktree prevents stochastic operations from contaminating stable state

**Design principle**: Stochastic capability generation + deterministic acceptance gates = reliable system. The agent proposes; the harness disposes.

## The Paradox Structure

The Stochastic Gatekeeper Paradox has five structural properties:

1. **Non-reproducibility**: Running the system again on identical input produces different output. The "correct" decision is undefined.

2. **Binary irreversibility**: The downstream action (hire/reject, treat/don't treat, grant/deny access) is binary and often irreversible. Continuous scores get rounded to binary gates.

3. **Unauditability**: There is no "ground truth run" to compare against. The system cannot explain why *this* run produced *this* result vs. the alternative it would have produced 35% of the time.

4. **Unappealability**: The affected party cannot challenge the decision because the decision-maker cannot reproduce its own reasoning. "Run it again and you'll get a different answer" is not a viable appeal mechanism.

5. **Invisible error rate**: Unlike deterministic systems where errors are countable events, stochastic systems distribute error probabilistically across all decisions. Every decision is partially wrong; no specific decision can be identified as THE error.

## Design Principles (Constructive)

From the convergence of HORIZON + PerceptionRubrics + community discourse:

1. **Decompose gates into atomic deterministic checkpoints**: Don't score holistically. Identify the must-pass criteria and evaluate them as binary, reproducible checks.

2. **Separate generation from decision**: The stochastic system generates; a deterministic system decides. The LLM proposes candidates; a compiled predicate accepts/rejects.

3. **Make non-determinism visible**: If a system is stochastic, run it N times and show the distribution, not a single point estimate. "Your resume scored 74-90 across 10 runs" is honest. "Your resume scored 74" is a random sample masquerading as a measurement.

4. **Require reproducibility at the decision boundary**: Any binary gate must be reproducible — same input → same output. If the system can't guarantee this, it's generating recommendations, not making decisions.
