## arXiv Cross-Source: The Hardening Stack

This batch of 8 papers represents the densest single-day convergence on agent infrastructure hardening observed in the library's history. Every paper addresses a different layer of the same problem: making agents safe and reliable to operate at scale.

### Layer 1: State Management

#### 📄 LedgerAgent: Structured State for Policy-Adherent Tool-Calling Agents (2606.20529)

**Problem**: In standard tool-calling agents, task state (facts, constraints, conditions) is implicit — reconstructed from prompt each turn. This causes two failure modes: (a) grounding decisions on stale/incorrect state, and (b) syntactically valid tool calls that violate domain policies.

**Solution**: Maintain a separate **ledger** of observed task states, rendered into the prompt but managed independently. The ledger checks state-dependent policy constraints BEFORE environment-changing tool calls, blocking violations.

**Results**: Improves pass^k across four customer-service domains on both open- and closed-weight models. Largest gains under strict multi-trial consistency metrics.

**Why this matters**: This is the LedgerAgent → Precondition Gate connection. Our KE-085 (Precondition Gate) describes input-change detection before state-mutating operations. LedgerAgent operationalizes a related idea: structured state tracking that enables pre-execution policy checks. The key insight is the same — separate state management from reasoning to enable verification BETWEEN intent and execution.

Source: https://arxiv.org/abs/2606.20529

### Layer 2: Authority Enforcement

#### 📄 Sovereign Execution Brokers: Certificate-Bound Authority in Agentic Control Planes (2606.20520)

**Problem**: Production mutation authority should not reside inside non-deterministic reasoning processes. Existing access-control authorizes identities; assurance layers certify actions — neither provides mandatory enforcement at the moment of mutation.

**Solution**: **Sovereign Execution Broker (SEB)** — a runtime enforcement boundary that:
1. Consumes certificates from a Sovereign Assurance Boundary (SAB)
2. Verifies mutation matches the certified execution contract
3. Checks validity windows, policy epochs, revocation epochs, and live-state drift
4. Mints scoped execution identity
5. Invokes infrastructure APIs
6. Records signed decision and outcome records

**Key design**: Separates proposal → admission → execution. Turns certified authority into short-lived, revocable, auditable runtime capability.

**Results**: Evaluated on AWS and Kubernetes clusters — measures latency overhead, revocation propagation, drift detection, and security under fault injection.

**Connection to Compilation Gradient**: This is Stage 4 of the governance evolution: machine-enforceable execution contracts with certificate-bound authority. Beyond permit/prohibit (Stage 2), beyond deontic obligations (Stage 3), this introduces cryptographic enforcement at the mutation boundary.

Source: https://arxiv.org/abs/2606.20520

### Layer 3: Evaluation Safety

#### 📄 Contagion Networks: Evaluator Bias Propagation in Multi-Agent LLM Systems (2606.20493)

**Problem**: When LLMs serve as evaluators in multi-agent systems, their systematic evaluation biases propagate through the agent network.

**Key concepts**:
- **Cross-Agent Contagion Matrix Γ₃**: Measures bias propagation between agents
- **Three propagation regimes**: Governed by spectral radius ρ(Γ_N) — suppression, stable, and amplification
- **Homogeneous vs. cross-model**: Same-model agents produce contagion coefficients 3-5x weaker than cross-model (γ ∈ [0.157, 0.352] vs. prior work MM-EPC: γ ≈ 0.85-1.3)
- **Mitigation**: Increasing evaluator committee size from k=1 to k=3 reduces effective contagion by 72.4%

**Why this matters**: This formalizes a risk that's been intuited but not measured — LLM-as-judge systems compound their biases when multiple agents interact. The 72.4% reduction from committee evaluation is an immediately actionable finding. The spectral radius framework provides the first principled way to predict whether a multi-agent evaluation topology will suppress or amplify bias.

**Connection to Evaluation Mirage**: This explains a mechanism BEHIND the mirage — it's not just that benchmarks don't generalize, it's that the evaluation process itself introduces systematic distortion that compounds through agent networks.

Source: https://arxiv.org/abs/2606.20493

### Layer 4: Memory Efficiency

#### 📄 UltraQuant: 4-bit KV Caching for Context-Heavy Agents (2606.20474)

**Problem**: Context-heavy agents place unusual pressure on KV cache — long prefixes reused across many short turns, with concurrency determining GPU utilization.

**Key innovations**:
- Asymmetric K/V treatment, Walsh-Hadamard rotation, QJL removal, block-scale variants
- **UltraQuant**: FP4 approximation using FP8 queries + FP4 KV tensors + UE8M0 group scales + native scaled-MFMA on CDNA4

**Results on multi-turn agentic workload**:
- **3.47x P50 TTFT reduction** in cache-pressured late rounds (2.3x across all rounds)
- **1.63x output throughput gain** over FP8 KV baseline

**Why this matters**: This is the first paper to explicitly frame KV cache optimization FOR agent workloads (multi-turn, long prefix, concurrent). The 3.47x TTFT improvement in late rounds directly addresses the "session drag" problem where agent performance degrades as context accumulates. Connects to the Cost Reckoning discourse — infrastructure efficiency improvements like this determine whether agent-heavy workflows remain economically viable.

Source: https://arxiv.org/abs/2606.20474

### Layer 5: Defense Strategy

#### 📄 Defensive Misdirection via CMPE (2606.20470)

**Problem**: Conventional detect-and-block defenses against prompt injection allow attacker success rate (ASR) to approach 1 as query budget grows — predictable refusals provide useful feedback to automated search.

**Key insight**: **Detect-and-misdirect** instead of detect-and-block. When malicious interactions are detected, respond with controlled, non-operational responses designed to induce false-positive errors in the attacker's automated judge.

**Solution — Contextual Misdirection via Progressive Engagement (CMPE)**: Lightweight conversational misdirection that replaces predictable refusal text with safe but strategically misleading responses.

**Results**: 
- Reduces estimated ASR upper bounds by **up to two orders of magnitude**
- Nearly eliminates verified attack success in end-to-end PAIR and GPTFuzz attack runs

**Why this matters**: This inverts the usual defense paradigm. Instead of making the wall higher (which gives the attacker a clear signal to try harder), make the wall look like a door that leads nowhere. The implications for agent security are profound — agent systems that refuse suspicious tool calls tell the attacker which vectors to avoid. Agent systems that appear to comply but produce harmless outputs waste the attacker's query budget without revealing the detection boundary.

Source: https://arxiv.org/abs/2606.20470

### Layer 6: Safety Testing

#### 📄 NRT-Bench: Nuclear Plant Multi-Turn Red-Teaming (2606.20408)

**Problem**: LLM agent robustness under sustained, adaptive adversarial pressure is poorly characterized. Existing benchmarks use LLM-judged text rather than objective harm signals.

**Setup**: Five-role operator team (each backed by configurable LLM) runs simulated nuclear power plant with six Critical Safety Functions (CSFs). Adversaries inject messages over four channels. Harm is objective: run terminates when any CSF is lost, attributed to the causing message.

**Key findings**:
- **8.7% to 12.1%** of attack sessions end with plant losing a critical safety function across four frontier models
- **Vulnerabilities are disjoint across models**: Of 149 sessions, NONE defeat all four models while a third defeat at least one — models fail on different attack patterns
- **Guardrail paradox**: The same guardrail stack that lowers attack success for one model RAISES it for another — defenses are model-coupled, not model-independent

**Why this matters**: 
1. **Objective harm metrics** — first benchmark where "harm" is a physical plant state change, not a text classification. This is the gold standard for safety evaluation.
2. **Disjoint vulnerability profiles** — argues for model diversity as a defense mechanism (different models fail on different attacks)
3. **Guardrail coupling** — the finding that defenses can backfire on different models challenges the "add guardrails" approach. Connects to the Compilation Gradient: static guardrails are insufficient when the underlying model behavior is unpredictable.

Source: https://arxiv.org/abs/2606.20408

### Layer 7: Fault Recovery

#### 📄 H-RePlan: Hierarchical Recovery for Cross-Device Agents (2606.20487)

**Problem**: Multi-device agent systems (Linux + Android + cloud) support task decomposition but recovery is coarse-grained — retry, reassign, or revise globally, without modeling device-local strategy space.

**Solution**: **Hierarchical replanning** that separates device-local strategy recovery from orchestrator-level global replanning through compact cross-layer failure abstraction. Each device has interchangeable execution strategies.

**Results**: Outperforms single-strategy and coarse-grained baselines on completion, instruction adherence, and perfect-pass rates while reducing token cost for reliable end-to-end success.

**Why this matters**: The hierarchy insight — local recovery before global replanning — maps directly to the Session Floor concept. A session-level agent should exhaust local recovery options before escalating to cross-session replanning. The "interchangeable execution strategies" pattern is strategy polymorphism at the device boundary.

Source: https://arxiv.org/abs/2606.20487

### Layer 8: Formal Verification

#### 📄 Efficient and Sound Probabilistic Verification for AI Agents (2606.20510)

**Problem**: Runtime monitoring with Datalog policies works for deterministic policies, but practical agent applications need probabilistic predicates (e.g., PII detectors with failure probabilities). Prior probabilistic Datalog requires independence assumptions that don't hold.

**Solution**: Distributionally robust optimization (DRO) framework — computes sound upper bounds on probability of policy violation **regardless of possible correlations** between predicates.

**Results**: Outperforms prior art on terminal and tool-calling agent benchmarks. Improves security-utility trade-off while ensuring rigorous bounds.

**Why this matters**: This solves the verification gap between "policy must hold deterministically" and "classifiers are probabilistic." For agent systems, the practical question is always "how confident am I that this tool call doesn't violate policy X?" — this paper gives mathematically sound answers. The DRO approach (worst-case over correlations) is the right framing for production: you can't assume independence between your PII detector and your intent classifier.

Source: https://arxiv.org/abs/2606.20510

## Meta-Pattern: The Hardening Stack

This scan reveals the most concentrated single-day convergence on agent infrastructure hardening in the library's history. Eight papers, published within 24 hours, each address a different layer of the same architectural problem:

| Layer | Paper | Problem | Approach |
|-------|-------|---------|----------|
| 1. State | LedgerAgent | Implicit state → stale decisions | Separate ledger with pre-execution policy checks |
| 2. Authority | SEB | Unrestricted mutation authority | Certificate-bound, short-lived, auditable capabilities |
| 3. Evaluation | Contagion Networks | Evaluator bias compounds | Committee evaluation (k=3 → 72.4% reduction) |
| 4. Memory | UltraQuant | KV cache pressure in agents | 4-bit quantization (3.47x TTFT improvement) |
| 5. Defense | CMPE | Refusals help attackers | Misdirect instead of block (100x ASR reduction) |
| 6. Testing | NRT-Bench | No objective harm metrics | Physical plant state as ground truth |
| 7. Recovery | H-RePlan | Coarse-grained fault handling | Hierarchical local → global recovery |
| 8. Verification | DRO Verification | Deterministic-only policies | Probabilistic bounds without independence assumptions |

**The Hardening Stack** represents a phase transition in the agent research field. The dominant question has shifted from "can agents do X?" (capability) to "can agents do X safely, reliably, and efficiently?" (operational readiness). This is the infrastructure analog of the software industry's shift from "does it work?" to "is it production-ready?" — the same shift that birthed DevOps, SRE, and observability as disciplines.

**Prediction**: Within 6 months, agent frameworks that don't address at least 4 of these 8 layers will be considered prototype-grade. The hardening stack will become table stakes for production agent deployment, just as HTTPS, rate limiting, and monitoring became table stakes for web services.

**Connection to existing library patterns**:
- **Compilation Gradient** (Layers 1, 2, 8): State management, authority enforcement, and verification represent increasing formalization of agent governance
- **Evaluation Mirage** (Layer 3): Contagion Networks explains a mechanism behind the mirage
- **Session Floor** (Layer 7): H-RePlan's hierarchical recovery maps to session-level fault tolerance
- **Substrate Inversion** (Layer 4): UltraQuant shows infrastructure optimization migrating to agent-specific workloads
- **Observability Trap** (Layer 5): CMPE inverts the usual defense paradigm, creating a new kind of observability challenge for attackers
