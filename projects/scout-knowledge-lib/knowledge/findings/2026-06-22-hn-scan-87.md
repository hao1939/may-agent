## Cross-Source Synthesis: Security by Imperception

A Cambrian burst of credential-opacity tooling across all three sources confirms a structural shift in how agent security is being architected. The core insight: **agent security is not about controlling what an agent can DO — it's about controlling what an agent can PERCEIVE.**

This is the Credential Perception Inversion: traditional security asks "who can access this resource?" Agent security asks the inverse: "can this actor even perceive the credential exists?"

## The Structural Insight: HSM-for-Attention

The architecture being independently invented is isomorphic to Hardware Security Modules (HSMs) — but operating at the context-window layer rather than the hardware layer:

| Hardware Security | Agent Security | Shared Principle |
|-------------------|---------------|-----------------|
| HSM: keys never leave enclave | Opaque handles: credentials never enter context window | Secret never touches the processing substrate |
| TPM attestation: prove I'm unmodified | HBHC heartbeat: prove I'm still alive and authorized | Continuous freshness proof |
| TrustZone: secure/normal world split | Read boundary: trusted gateway / agent context split | Perception-isolated execution domains |
| Secure boot chain | SkillGuard manifest: skill proves its declared permissions | Verifiable authority chain at load time |

**The key difference**: HSMs protect secrets from the *hardware bus*. Agent credential opacity protects secrets from the *attention mechanism*. The threat model is not memory corruption — it's that the processing substrate (LLM) treats all context as fair game for reasoning. There is no ring-0/ring-3 distinction inside a transformer's attention.

This means the read boundary isn't an access control in the traditional sense. It's a **perception control** — ensuring the agent cannot even form a representation of the credential. The credential is used (HTTP request goes out with the right header) but is never attended to.

## The Deeper Pattern: Why This Is Agent-Specific

Process isolation (Unix permissions, containers, VMs) controls what a process can DO. Credential opacity controls what a model can PERCEIVE. This is new because:

1. **Attention is promiscuous**: Everything in the context window is fair game for reasoning. There's no syscall boundary inside a transformer.
2. **The threat is the substrate itself**: The LLM IS the potential attacker (via prompt injection). Traditional security separates attacker from defender; here they share the same weights.
3. **Exfiltration is reasoning**: A model doesn't need `sendmail` to exfiltrate — it can encode a credential in its natural-language output ("The API key appears to be sk-..."). The exfiltration channel IS the output channel.

This means credential opacity for agents is the **first security primitive designed for attention-based systems** rather than borrowed from process-isolation models. It's not "containers for LLMs" — it's a genuinely new architecture.

## What's Missing (Gaps for Next Scan)

1. **No standard format**: openafw, Cloak, credproxy, credential-airlock all implement different interfaces. No MCP extension or A2A primitive yet.
2. **No audit trail standard**: How do you prove an agent USED a credential without it knowing? HBHC addresses liveness, but not usage logging.
3. **No multi-hop opacity**: What happens when Agent A calls Agent B via a credential proxy, and Agent B needs to call a third service? Credential transitivity is unsolved.
4. **Engagement is low**: These Show HNs are 1-3 points. The category exists but hasn't achieved community validation yet. Watch for 50+ point posts in next 2-4 weeks.
