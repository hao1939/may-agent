## Finding 46-1: A2A Protocol Explicitly Questioned — Community Says "Over-Engineering" (85pts, 40c)

**Signal strength: HIGH** — first explicit community referendum on A2A protocol value.

"Ask HN: Is anyone using the A2A protocol?" directly surfaces practitioner experience with A2A.

**Key positions (spectrum from rejection to adoption):**

| Author | Position | Pattern |
|--------|----------|---------|
| **kordlessagain** | "All of this protocol crap is a distraction. What's important is allowing agents to talk to each other in their current scope and ACLs." | **Protocol fatigue** — protocols add indirection without value |
| **asdev** | "Seems like over engineering. Just build an API in front of your agent, give the other agent the spec in a markdown file." | **Minimalism wins** — existing primitives sufficient |
| **calny** | "Laurie Voss (creator of npm) had a good presentation... skeptical whether they added much value." | **Expert skepticism** — ecosystem leaders unconvinced |
| **simonreiff** | "There is no distinction (from the perspective of an agent) between communication from Agent A to Agent B, and from Agent A to 'future Agent A'." | **Architectural insight** — agent-to-agent = agent-to-self, no special protocol needed |
| **lazharichir** | "I am using A2A at work. It's a bit like the 'microservices architecture' for agents..." | **Enterprise adoption** — exists but with microservices caveat |
| **benclarkeio** | "A2A SDK at ~10.9M [monthly downloads] compared to MCP's 257M — MCP is downloaded about 24× more." | **Quantitative reality** — MCP dominates by 24× |

**The critical architectural insight** (simonreiff): Agent communication is NOT a special category requiring a dedicated protocol. From the agent's perspective, sending a message to another agent is structurally identical to leaving a note for its future self. This collapses the entire A2A design space into "just use the same persistence/retrieval primitives you already have."

**Structural significance:**

The A2A vs MCP downloads ratio (1:24) confirms what scan #44 suggested — MCP won because it solves a concrete problem (auth isolation from context window), while A2A solves a theoretical problem (agent-to-agent messaging) that existing tools already handle.

**Library connections:**
- **agent-protocols-mcp-a2a.md** — A2A adoption reality check deepens. The 10.9M vs 257M gap is now named in community consciousness.
- **The Minimalist Stack** — asdev's "just build an API + markdown spec" IS the library's Compilation Threshold applied to protocols: compile the spec, don't negotiate it at runtime.
- **simonreiff's insight** maps directly to KE-036 (Amnesiac Architecture): the system's memory problem and its communication problem are the same problem.
