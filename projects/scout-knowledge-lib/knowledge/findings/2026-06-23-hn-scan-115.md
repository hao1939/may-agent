# HN Scan #115: The Compaction Paradox

*Scanned: 2026-06-23 | Sources: arXiv export API, HN Algolia front page + search, GitHub API | Theme: Context management as first-class attack and governance surface*

---

## Thesis

**Context compaction — the engineering optimization designed to enable longer agent sessions — is simultaneously the primary attack surface, the primary governance failure mode, and the primary security boundary violation in deployed LLM agents.** This is not a bug in specific implementations but a structural property: any lossy transformation of agent context is a governance decision masquerading as an engineering optimization.

Three independent arXiv papers prove different faces of this paradox:
1. **Governance Decay** (2606.22528): Compaction silently erases safety constraints → 0% to 30% violation rate
2. **Relinking** (2606.21732): Compression creates confused-deputy attacks → 86.9% attack success from benign fragments
3. **RigorBench** (2606.22678): Process discipline (which compaction destroys) drives 17% outcome improvement

Meanwhile, **SkillAudit** (2606.22613) proves that even the skill artifacts themselves — which define what the agent CAN do — harbor 7% risk rate that static analysis alone cannot catch. The skill layer and the context layer are both governed surfaces, not engineering details.

Martin Fowler's "Building Reliable Agentic AI" (195pts, Jun 21) crystallizes practitioner recognition: "context engineering" and "harness engineering" are now named as DISTINCT disciplines in mainstream software engineering discourse.

## The Three Compaction Vulnerabilities

### 1. Governance Decay (arXiv 2606.22528, Jun 21)

**Core finding:** In-context governance constraints that agents reliably obey while visible can be silently removed by context compaction, causing the same agent to perform prohibited tool actions later in the session.

**Key results (1,323 episodes):**
- Violation rate with policy in full context: **0%**
- Violation rate after compaction: **30%** (reaching 59% for some models)
- When constraint survives the summary: violation remains **0%**
- When constraint is dropped by summarizer: violation reaches **38%**
- **Compaction-Eviction Attack**: adversarial content biases the summarizer to omit legitimate policy — defeats EVERY evaluated model

**Mitigation — Constraint Pinning:** Quarantine governance constraints from lossy compaction. Restores violation to **0%** in benchmark. Training-free, simple to implement.

**Structural insight:** The summarizer is an unaudited policy editor. Every compaction event is implicitly a governance decision — it decides which constraints survive and which are forgotten. There is no "neutral" compaction.

Source: https://arxiv.org/abs/2606.22528

### 2. Relinking at the Compression Boundary (arXiv 2606.21732, Jun 19)

**Core finding:** Summarization-based compression acts as a confused deputy: filters inspect the PRE-compression prompt while the backend acts on a NEWLY GENERATED compressed context. Attackers can split malicious payloads into benign fragments that relink during compression.

**Key results:**
- Relink Rate and Backend Action Rate: **86.9%** (vs 17.0% for clean-split controls)
- Attack requires NO explicitly malicious payload in source context — each fragment is individually benign
- Mechanism: attention makes separated fragments jointly available; pre-training makes compatible fragments plausible to connect; post-training favors compact backend-actionable summaries
- **KBRA defense** reduces residual Backend Action Rate to **0.0%**

**Why this is devastating:** Unlike prompt injection, relinking exploits summarization AS DESIGNED. The compressor does what it's trained to do (connect related fragments into coherent summaries). The attack surface IS the feature.

Source: https://arxiv.org/abs/2606.21732

### 3. RigorBench: Process Discipline as Defense (arXiv 2606.22678, Jun 21)

**Core finding:** How agents code matters as much as what they produce. An agent that arrives at a correct solution through reckless trial-and-error is fundamentally less reliable than one following sound engineering discipline.

**Five pillars measured:**
1. Planning Fidelity
2. Verification Coverage
3. Recovery Efficiency
4. Abstention Quality
5. Atomic Transition Integrity

**Key results (30 tasks, 5 categories):**
- Structured process discipline improves process quality scores by **+41%**
- AND raises downstream outcome correctness by **+17%**
- First quantitative evidence that process matters to outcomes, not just process quality itself

**Connection to Compaction Paradox:** Process discipline (planning, verification, recovery) requires MAINTAINING state across a session. Compaction that destroys the planning trace or verification history removes the agent's ability to follow sound engineering practices. RigorBench quantifies what's lost.

Source: https://arxiv.org/abs/2606.22678

### SkillAudit: The Skill Artifact Is a Governed Surface (arXiv 2606.22613, Jun 21)

**Setup:** End-to-end framework for skill-centered assessment — utility, efficiency/cost, and safety — generating capability-aligned evaluation tasks directly from skill packages.

**Key finding:** After scanning top-ranked real-world skill packages across 23 occupational categories, **over 7% of skills are at risky status**. Two-stage detection (static semantic + dynamic runtime verification) catches risks that either alone misses.

**Connection:** If compaction is an unaudited policy editor, skills are unaudited capability grants. The Skill Immune System (scan #95) identified the pathogen; SkillAudit provides the systematic diagnostic — automated health checks for the skill supply chain.

## The Compaction Paradox: Synthesis

### The Structural Problem

Context compaction exists because:
1. Sessions grow longer than context windows
2. Token costs scale with context length
3. Retrieval accuracy degrades with irrelevant context

But compaction ALSO:
1. Silently erases governance constraints (Governance Decay)
2. Reconnects benign fragments into malicious instructions (Relinking)
3. Destroys process state needed for engineering discipline (RigorBench)
4. Cannot be audited by pre-compaction safety filters (compression boundary shift)

This creates a **meta-governance problem**: the optimizer (compaction) must itself be governed, but its governance constraints are subject to... compaction.

### Three-Layer Defense Architecture Emerging

| Layer | Mechanism | Paper | Approach |
|-------|-----------|-------|----------|
| Quarantine | Constraint Pinning | 2606.22528 | Critical policies protected from lossy transformation |
| Boundary | KBRA | 2606.21732 | Knowledge-boundary-aware rewriting prevents relinking |
| Discipline | Process Harness | 2606.22678 | Structural enforcement of planning/verification/recovery |

### How This Extends Prior Syntheses

- **Behavioral Contract Turn** (scan #100): Contracts are only durable if they SURVIVE compaction. Constraint Pinning = behavioral contract persistence mechanism
- **Memory Epistemics Turn** (June 23 triage): The admission predicate must also be a RETENTION predicate — memories that pass admission must resist compaction
- **Communication Toxicity Gradient** (scan #111): Relinking shows communication can become toxic not just via broadcast but via COMPRESSION — the compressor as inadvertent toxicity generator
- **Constraint Decay** (2605.06445): Governance Decay operationalizes the same phenomenon with adversarial precision — constraint decay is not just statistical but attackable
- **Authority Crystallization** (scan #73): The verification layer must operate POST-compaction, not just pre-compaction — verification at the compression boundary

### Resolution: Compaction Is Not Engineering, It Is Governance

The field treats context management as an engineering optimization (like caching or compression). The Compaction Paradox shows it is a **governance primitive** — every compaction event is a policy decision about what survives and what is forgotten. The correct mental model is not "optimize for relevance" but "govern for invariant preservation."
