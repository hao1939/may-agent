## NEW SIGNAL: "Reviews Expensive, Rewrites Cheap" Reaches Front Page

Previously tracked as a comment-section micro-signal (scan #11). Now at 33pts/28c as its own discussion — the Comprehension Cliff pattern has sufficient community resonance to generate standalone engagement.

### Key discourse

- **saidinesh5** (practitioner): "Eager new joinees sent 100s of lines of CLs to review to 'improve' little things. Not only did the new changes not fix what they thought it would fix but it broke other things in unexpected ways." — The failure mode is social-technical: AI-generated volume overwhelms review bandwidth, but banning review creates production failures.

- **dap**: "If your plan is to not review and just have the LLM rewrite if it doesn't work, it doesn't sound like the rewrite is gonna be any better." — Identifies the infinite-rewrite trap: without comprehension, each rewrite is independently random.

- **dmitrig01**: "Writing blog posts has become cheap, making them sound human has become hard." — The pattern extends beyond code: comprehension cost is universal across AI-generated artifacts.

- **eschneider**: "Failures in production remain expensive." — The cost didn't disappear; it shifted from creation-time to failure-time.

- **hluska** (repeated): "The over-engineered code LLMs create have more big problems. Rewriting vast parts of code when I have an outage means the code evolves far faster than my understanding. That gets more and more dangerous."

- **simianwords**: "I use LLMs for reviewing. It is dogmatic to review every line written by an LLM." — LLM-reviews-LLM as the logical but dangerous endpoint.

### Comprehension Cliff Evidence Chain (now 5 data points)

1. CGamesPlay's CI-agent context gap (can't maintain understanding across runs)
2. Claude Corps 12-month knowledge cliff (human fellows depart → knowledge evaporates)
3. hluska's velocity-understanding gap (code evolves faster than comprehension)
4. LLM-reviews-LLM (no human in the comprehension loop)
5. **NEW**: saidinesh5's team experiencing the failure mode at scale ("100s of CLs to review")

The pattern is maturing from "observation" to "named organizational problem."
