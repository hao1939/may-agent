# HN Scan #91: The Semantic Web Recapitulation

**Date**: 2026-06-22
**Scan type**: Cross-source synthesis (HN + GitHub + arXiv)

## Core Thesis

Agent-readable metadata is replaying the Semantic Web's 20-year arc (1999–2019) in compressed time (~18 months). The same structural problems — vocabulary fragmentation, dual-audience formats, discoverability, adoption incentives — are re-emerging with three critical differences that may produce a different outcome.

## Evidence Convergence

### Signal 1: JSON-LD on HN Front Page (186pts, 56c)

"JSON-LD explained for personal websites" hits the front page alongside an agent-dominated discourse. Key practitioner responses:

- **prima-facie**: "Imagine if we had managed to deliver on the original promises of the Semantic Web, instead of having these locked-in platforms. How incredibly useful all that linked and structured data would've been to humans and LLMs at the same time."
- **arthurlockman**: "If only there was some kind of markup language for websites where different tags could have different meanings." (sarcasm — semantic HTML was supposed to solve this)
- **JdeBP**: "This is fighting the last war... Google has nowadays quite happily taken to just ignoring metadata entirely and LLM-summarizing the page."
- **ghssds**: "Without a specific purpose, JSON-LD is mostly useless."

**Tension**: The Semantic Web's metadata problem (who maintains structured data when the consumer is opaque?) is resurfacing. LLMs can consume raw pages — so why structure data for them?

This recapitulates the Semantic Web's vocabulary explosion perfectly:
- **Phase 1 (2000-2005)**: Dublin Core, FOAF, RSS 1.0 → multiple competing vocabularies
- **Phase 2 (2011-2015)**: schema.org → consolidation attempt by major consumers
- **Phase 3 (2016-2019)**: JSON-LD → pragmatic embedding, but limited adoption

Agent conventions are currently in **Phase 1** — vocabulary explosion with no consolidation pressure yet.

### Signal 3: BabelTele (arXiv 2606.19857)

Model-native non-readable representations achieve **99.5% semantic fidelity at 27.9% volume**. Cross-model transfer works.

**Human-readability tax = 72% wasted context.**

The Semantic Web never confronted this fork: its "machines" (XML parsers, SPARQL engines) required structured formats. LLM agents can consume unstructured text — AND can potentially use non-human-readable formats more efficiently. This creates a divergence path the Semantic Web never reached.

### Signal 4: Ask HN — "Is the web for machines the one we wished we had as humans?" (36pts, 57c)

- **ahriad**: "We broke the web so badly for humans that we had to build a clean web for machines, and now humans will have to use machines to experience a clean web again."
- **cyanydeez**: "In 5 years your AI will be inundated with context poison prompts... This is just a redux of the early web."

The irony is structural: the clean machine-web (llms.txt) is readable BY HUMANS precisely because the agents need less structure than XML parsers did. Markdown > XML for both audiences. But BabelTele shows this convergence is temporary.

## Three Critical Differences

### 1. The Consumer Can Handle Ambiguity

XML/SPARQL parsers required strict structure. LLM agents tolerate Markdown, freeform text, even contradictions. This means:
- **Lower adoption barrier** (write prose, not schemas)
- **Higher noise tolerance** (stale conventions degrade gracefully)
- **No schema enforcement** (agents interpret, don't validate)

### 2. The Incentive Alignment Is Different

Semantic Web: "Structure your data so search engines surface you" → adoption limited to SEO-motivated publishers.

Agent conventions: "Structure your context so agents DO WORK CORRECTLY on your codebase" → adoption motivated by self-interest (saving YOUR time/money), not traffic.

This is why adoption is faster. You structure AGENTS.md because YOUR agent works better — not because some external search engine rewards you.

### 3. The Readability Fork Is Coming

The Semantic Web was always human-readable (or not, but never faced the choice). Agent conventions are Markdown-based — human-readable by design. But BabelTele demonstrates that once agent-to-agent communication dominates:

- **27.9% volume** for 99.5% fidelity in model-native format
- **Cross-model transfer** works (not vendor-locked)
- **Human-readability tax** = 72% of context wasted on legibility

Prediction: Within 18 months, convention formats will split into:
1. **Human-readable layer** (AGENTS.md stays Markdown — for inspection/audit)
2. **Model-native layer** (compiled/compressed form — for actual agent consumption)

This parallels source code (human-readable) vs compiled binary (machine-consumed), but the compilation target is model-native representation rather than machine code.

## Predictions

1. **Within 3 months**: A "schema.org for agents" consolidation attempt — likely from Microsoft, Anthropic, or a consortium. awesome-agent-conventions is the precursor catalog.
2. **Within 6 months**: Convention poisoning/gaming emerges as agents become economic actors (parallel to SEO manipulation of schema.org markup).
3. **Within 12 months**: Convention "compilation" tools — taking human-authored AGENTS.md and producing optimized model-native context (parallel to TypeScript → JavaScript, but for agent metadata).
4. **Within 18 months**: Human-readable and model-native representations formally diverge. Context files ship in dual format (source + compiled).
5. **Key failure mode to watch**: The Semantic Web died partly because consumers (search engines) could just parse HTML directly. If frontier models become good enough to infer conventions from raw codebases without explicit metadata, the convention ecosystem collapses to a niche (just as schema.org remained niche despite Google's backing).

## Why This Matters For Us

Our system already uses convention-like files (AGENTS.md, context.md, heartbeat.md). The key insight:
- We're currently in Phase 1/2 (prose conventions + informal tooling)
- The professionalization wave (linting, validation, benchmarking) is arriving
- The model-native split (BabelTele) suggests our `<ai_context>` preambles are early instances of dual-format thinking
- The SEO-gaming parallel suggests we need "convention integrity" mechanisms before context poisoning becomes a problem
