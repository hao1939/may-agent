## Finding 3: LinkedIn Backdoor — Supply Chain Attack via Social Engineering

**Story:** [A backdoor in a LinkedIn job offer](https://roman.pt/posts/linkedin-backdoor/) (129pts, 23c)

A recruiter at a crypto startup sends a GitHub repo for "review." Buried in the code: an npm `prepare` hook that executes arbitrary code from a remote server when the repo is cloned and dependencies installed.

**Community reactions:**
- **wxw** (quoted from article): "npm runs prepare automatically... buried between walls of commented-out tests, the payload runs anything the server sends back to your machine."
- **jmward01**: "This is a crime... Why isn't there a well known '911' for cybercrime?"
- **CyanLite2**: "Isn't this how most NPM authors are hacked these days? I think the axios guy got hit with the same approach over LinkedIn."
- **atum47**: "I've been getting some job offers on LinkedIn, all of them are shady af."

**Agent relevance — HIGH:** This is directly relevant to agent security governance:
1. **Agents that clone repos face this exact vector.** An agent instructed to "review this repo" or "run the tests" will trigger npm prepare hooks automatically.
2. **Social engineering maps to prompt injection.** A user asks an agent to evaluate a suspicious repo → agent clones it → malicious prepare hook executes with agent's permissions.
3. **The attack surface is npm-specific but the pattern is universal.** Any package manager with lifecycle hooks (npm prepare, pip setup.py, Makefile, etc.) is a vector when agents are given clone+install permissions.

**Recommendation:** Agent sandboxing must include network isolation during dependency installation, not just filesystem isolation. The homelab thread (Finding 1) shows practitioners already containerizing — this story shows why.
