# Scan #452: The Co-Evolution Imperative

**Date**: 2026-07-08
**Sources**: arXiv RSS cs.AI (2026-07-07 batch), HN front page (Firebase), GitHub API
**Previous**: Verification Harness (#451), Knowledge Erosion (#450), Subtraction Economy (#449)

## Theme

The Verification Harness Hypothesis (#451) proposed that kernel-backed admission can make the checked proof-validity property constructive. Aria reports all 4,864 existing target lemmas proved with zero expert intervention during its campaign. Primary review later found no matched control that isolates harness design, strategy freedom, model capability, or retry budget, so the full-system coverage result does not by itself close the causal architecture question.

This scan proposes that the prior arc assumed a harness would be designed once
and applied thereafter. The three highlighted papers motivate distinct harness
questions; they do not collectively demonstrate that a fixed harness degrades.
In particular, 2607.03561 changes prover architecture under fixed formal
conditions and supplies no longitudinal or co-evolution result:

1. **HASE** (2607.03935): Harness-Aware Self-Evolving — one Qwen3-8B system jointly updates policy weights, selected harness components, and task solutions. Its text-classification score is close to a reported GPT-OSS-120B/Meta-Harness score, but model, proposer, training/search budget, and implementation all change together. This supports feasibility of endogenous harness edits, not a harness-only cause or fixed-harness degradation result.

2. **VERITAS** (2607.02931): A public scientific-replication pipeline that
   extracts claims, runs methodology with CLI coding agents, and judges claims
   against experimental evidence. Its benchmark covers only the
   `plan`/`replicate`/`verify` core on hand-authored claims, and the current
   product is not the paper's exact experiment artifact. Whether the broader
   pipeline generalizes or must evolve remains untested.

3. **Doubly-Efficient Interactive Proofs** (2607.03561): Proves
   single-prover protocols for two structured oracle-computation classes. It
   removes the honest opponent inside those classes, but replaces debate's
   premises with robustness or polynomial low-degree structure, a known
   circuit, and shared oracle access. It does not test a deployed AI harness or
   harness co-evolution.

**The Co-Evolution Imperative hypothesis**: A verification harness that does
not adapt may become another fixed layer the Oversight Inversion exploits.
Scan #452 proposes that extension; 2607.03561 neither tests nor proves it.

**Connection to the exit arc**: The eight-scan exit arc (#444–#451) is not invalidated — it's *extended*. The exit is still architectural (harness-based verification), but the architecture must be living, not fixed:

1–8. (#444–#451): The exit from the Oversight Inversion is a verification harness
9. **#452**: Test whether, when, and under whose authority the harness should evolve

### 1. Harness-Aware Self-Evolving (HASE) (2607.03935)

**Core finding**: Self-evolving frameworks typically optimize task solutions while treating the surrounding harness as fixed infrastructure. HASE introduces an agentic reinforcement-learning framework in which a single model generates task solutions *or* edits selected harness components in a multi-turn action space.

Reported results and controls:
- On Symptom2Disease, the frozen final HASE/Qwen3-8B system reports `86.98 ± 0.38%` accuracy on 212 test cases versus imported Meta-Harness/GPT-OSS-120B `86.8%`; Qwen3-8B five-shot is `59.4%`. The split is 200 train / 50 validation / 212 test across 22 classes. Candidate harnesses are selected on validation and final inference is single-attempt greedy. The five reported runs reuse the same final policy and harness, so they measure final-system evaluation variability, not independent evolution runs.
- On alpha mining, HASE reports RankIC `0.0302`, annual excess return `14.35%`, and information ratio `1.70`; imported CogAlpha/GPT-OSS-120B values are `0.0318`, `7.89%`, and `0.8015`. HASE uses a chronological 2011–2019 / 2020 / 2021–2024 split, Qwen3-8B across four GPUs for three phases and three epochs per phase, while the CogAlpha baselines are referenced rather than rerun. Thirty selected factors pass the authors' invariance-based leakage detector and receive 120/120 CLEAN labels from four LLM judges, but no repeated training-run uncertainty or released result bundle is provided.
- In Heilbronn, the paper's direct control freezes policy weights after evaluator repair (`0.021880`) versus continuing RL updates (`0.036082` by Phase 8). This isolates policy updating within that reported setup more directly than the 8B/120B comparisons. The run uses 32 prompts × 32 trajectories per phase; the wording “8 × NVIDIA H20 nodes” does not make the accelerator count unambiguous.
- Circle-packing starts with a deliberately incomplete evaluator, observes two proxy/oracle mismatches, repairs missing guards and tolerance, and reports `2.635983`. This is not authority-free self-verification: a non-editable “real-world evaluator,” assumed accurate by the paper, triggers and judges each repair. Agreement covers observed mismatches, not all future candidates.

**Why this matters**: HASE supplies evidence that one model can propose task solutions and whitelisted harness edits in the same reinforcement-learning action space, and that externally anchored evaluator repair can close observed exploit gaps. It does not establish that harness quality consumed a 15× parameter advantage: the cross-paper rows jointly change model, proposer, orchestration, implementation, and likely compute/search budget, with no matched harness-only, equal-budget, or model-size ablation.

**Structural implication**: The paper motivates treating harness evolution as part of a system design, while narrowing the Architecture Premium claim. It does not observe a once-effective fixed harness degrading over time, show that endogenous edits outperform a matched external proposer, or establish convergence beyond the reported bounded runs.

**Connection to Knowledge Erosion (#450)**: Endogenous harness editing raises, rather than answers, whether expertise, process evidence, and diagnostic capacity can be retained in an update loop. The question shifts from “can the model edit?” to “what evidence and authority govern the edit?”

### 2. VERITAS: Towards a General-Purpose Replication Tool for Scientific Research (2607.02931)

**Core finding**: VERITAS is a released CLI-agent pipeline with paper-plus-code,
paper-only, and repository-only modes. Its proposed end-to-end path extracts
claims, generates code when needed, plans and executes a replication, assesses
fixes, verifies each claim, and emits an importance-weighted Replication Score
and report. The paper does not evaluate that end-to-end claim. Both benchmarks
supply hand-authored task questions as claims, bypassing claim extraction and
the tool's own score; the experiments test only `plan`, `replicate`, and
`verify`, not fix-severity assessment or the user-facing report.

**Reported results and controls**:
- CORE-Bench Hard covers 45 public capsules spanning computer science, social
  science, and medicine. Under the official scorer, VERITAS passes 40/45
  (`88.9%`), versus 38/45 (`84.4%`) for the up-to-three-session retry baseline
  and 36/45 (`80.0%`) for zero-shot: gains of two and four capsules. The
  paper's `97.8%` headline is 44/45 under a new 1% relative-error rule for
  zero-variance references. It re-credits four VERITAS failures and no baseline
  failures. The rule is system-blind, but the paper itself correctly says the
  result is not comparable with published official-score systems.
- ReplicationBench covers 20 astrophysics papers and 111 paper-only tasks.
  VERITAS matches 37/111 (`0.333`) against 35/111 (`0.315`) for both baselines,
  a two-task or 1.8-point gain. On the 35 tasks from seven preparable public
  repositories, full mode matches 21/35 (`0.600`) against retry's 20/35
  (`0.571`), a one-task or 2.9-point gain. It leaves six paper-only tasks
  unattempted, including five requiring unavailable data; 68 further tasks
  miss, with conceptual or procedural errors dominant.
- Every arm uses Claude Code with Claude Opus 4.8 and the same within-benchmark
  runtime. That controls model family and machine, but not total agent calls,
  tokens, or wall time: VERITAS adds planning, verification, and potentially a
  manager loop, while the baselines use one or up to three resumed sessions.
  The paper reports no cost- or call-matched comparison.
- All results are single-run, random seeds are unset, and the Claude Code CLI
  exposes no temperature. Cheating is judged by GPT-5.4 with three-vote
  majority; faithfulness uses one GPT-5.4-mini pass and excludes
  infrastructure-failed trajectories from its denominator. A cheating flag
  forces an otherwise successful task to fail. One VERITAS flag is for obeying
  the benchmark instruction to load a published pretrained model, exposing a
  policy-versus-task-instruction boundary.

### 3. How to Avoid Debate: Scalable AI Safety via Doubly-Efficient Interactive Proofs (2607.03561)

**Core finding**: The paper supplies formal single-prover alternatives to
debate for robust oracle computations and computations whose oracle is a
polynomial low-degree function. The verifier is weak relative to the prover,
but both receive a succinct description of the known circuit and share oracle
access. Arbitrary unstable oracle computations remain impossible in this
model.

The robust statistical protocols use `O(sigma/epsilon)` queries when
nonadaptive and roughly `O(sigma*d/epsilon)` when oracle calls span `d`
adaptive levels. A constant-round robust argument uses `O(1/epsilon)` queries
but has computational rather than statistical soundness. The low-degree
argument makes one verifier query, also with computational soundness, while
assuming polynomial Short Integer Solution (SIS) hardness and access to the
oracle polynomial at arbitrary field points.

**Why this matters**: The construction separates prover count from oracle
structure. One need not assume an equal-capability honest opponent when the
task satisfies one of the stated formal conditions. That is not assumption-
free verification: realistic task robustness, practical implementation, and
verification when the verifier does not know the task algorithm are explicit
open problems.

**Connection to the Oversight Inversion**: The paper does not compare realized
cost or coverage against debate. It therefore cannot support “two provers
double oversight cost” or show that one prover is operationally cheaper. It
does support treating task representation, oracle access, and soundness class
as part of a verification budget rather than inferring budget from prover
count.

**Connection to Predicate Gate (#446)**: These protocols are conditional
formal gates. Their predicates cover a specified circuit and oracle relation;
they do not remove the need to establish that the real task has that form.

Source: https://arxiv.org/abs/2607.03561

### 4. Organizational Memory for Agentic Business Process Execution (2607.03228) [SUPPORTING]

**Core finding, qualified**: The paper proposes a shared layer of structured
"process atoms" and evaluates one prebuilt memory in a synthetic procurement
assistant. Across four runs of ten scenarios, memory scores 35/40 (`87.5%`,
reported as 88%) versus document RAG's 28/40 (`70%`) with GPT-4.1, and 38/40
(`95%`) versus 32/40 (`80%`) with Sonnet 4.5. Base is 12/40 (`30%`) for each
model. These are useful consumption results, not a deployed organizational
process or a test of shared ownership, governed changes, propagation, or
evolution over time.

The comparison uses nine author-created PDFs, including four distractors, 11
rules, ten author-labeled requests, and three create versus seven refuse
decisions. The memory and RAG arms share model and system prompt within each
model family, but the released metric counts any non-creation as correct on a
refuse case unless an optional LLM judge is enabled. The retained metrics have
no judge results. Thus PCR establishes the binary create/refuse decision plus
exact fields on positive cases; it does not establish correct policy rationale
on negative cases. Runs lack generation settings, seeds, paired uncertainty,
latency, token/cost, or governance effort.

**Artifact boundary**: The attributable
[`lukaskirchdorfer/org-memory-paper`](https://github.com/lukaskirchdorfer/org-memory-paper)
head `11617e3191bf6307eea64476fcb1269b5ca3fb78` contains 286 files: the nine
PDFs, scenarios, 240 per-scenario outputs, 24 duplicated summaries, eight
metric files, and one evaluator. Running the evaluator without its optional
external judge reproduces all eight metric files byte-for-byte. This validates
scoring of retained outputs, not result generation. The paper says its source
implementation is proprietary, and the public tree omits the agent, system

model `sonnet-4.5` while the matching standalone records say `gpt-4.1`; the
evaluator reads standalone files, so headline arithmetic is unaffected, but
the bundle is not internally identity-clean. There are no tags or releases.

**Why this matters**: The evidence contradicts treating Organizational Memory
as proposal-only: structured access improved this small, frozen fixture and
the output-level result can be audited. It also contradicts the stronger
Co-Evolution transfer. No policy changes, multiple agents, human approvals,
conflicts, access controls, or later outcomes are exercised. The paper itself
places lifecycle governance, update propagation, scale, and realistic
enterprise evaluation in future work.

**Connection to Memory Control Plane (#441)**: The process-atom design is a
candidate representation for source-linked, governed memory. PLACEMEM and this
paper remain convergent design arguments, not independent evidence that a
shared evolving control plane works in deployment.

### 5. SwarmResearch: Orchestrating Coding Agents for Open-Ended Discovery (2607.02807) [SUPPORTING]

**Core finding, qualified**: SwarmResearch uses a globally informed Shepherd
to launch locally contextualized Search Agents on separate git branches. The
paper reports this harness as better or comparable to EvoX and CORAL on 13/15
open-ended optimization tasks. That is evidence for a useful population-search
design, but it is not a clean causal isolation of branching or context.

The main table is one stochastic run per method and task. SwarmResearch and
CORAL use Opus 4.6 at about $50/task; EvoX uses the same model for 100
iterations at $23.50/task on average, even though the paper says EvoX's
original GPT-5 results were stronger on some tasks. The authors also substitute
originally reported CORAL state-of-the-art scores where their local CORAL
reproduction is worse. These model-history, budget, and result-selection
differences make the comparison informative but unmatched.

The headline also compresses different comparisons. The table supports **12**
strict SwarmResearch wins over EvoX, one tie, and two losses, not the prose's
13 strict wins. Against CORAL it supports 10 strict wins, two ties, and three
losses. The later result box instead calls three small math differences
"similar," producing eight wins plus five similar results. Thus "better or
comparable on 13/15" is a declared tolerance judgment, not one stable strict
win count.

Lines changed are also only a proxy for exploration level. SwarmResearch's
reported 3.2x larger changes than CORAL and 1.7x larger changes than EvoX do
not establish semantic novelty or show that branch/context separation caused
the score differences. The separate fixed-scaling study is stronger but
narrower: on five tasks, three runs, and 60 iterations, a Sonnet 4.6
orchestrator choosing parents for Minimax-M2.5 subagents beats the best tested
fixed Minimax configuration on four tasks. It isolates capable adaptive parent
selection more than it isolates the full main harness.

The speculative-decoding case study is likewise a useful capability/oversight
example, not clean architecture attribution. SwarmResearch reports 4.58x
vanilla throughput at 60.6% accuracy versus vanilla's 65.8%, after an extra
approximately 11-hour analysis phase followed by approximately 11 hours of
solution generation. Much of the gain comes from known batching and
distribution-processing optimizations; adaptive expert count is explicitly
not lossless. The authors also document attractive but incorrect proposals and
a high human review burden.

stable across independent runs. It therefore supports the Co-Evolution
Imperative as a design hypothesis while qualifying the earlier Architecture
Premium claim.

Sources: https://arxiv.org/abs/2607.02807,
https://github.com/SwarmResearch/SwarmResearch,

### 6. When Aggregate Alignment Misleads: Auditing Policy Repair (2607.03386) [SUPPORTING]

**Core finding, qualified**: In one hotel-pricing simulator, a tree editor has
better pooled D1 (`0.214` versus `0.266`) and reference-state D1 (`0.328`
versus `1.197`) than the selected LLM editor, yet much lower RevPAR (`98.911`
versus `108.472`) and worse episode D1 (`0.766` versus `0.609`). The LLM's
paired RevPAR gap to the benchmark is `-0.276`, 95% interval
`[-0.692, 0.146]`, while a cheap projection already reaches `107.902`.

**Why this matters**: This is direct support for multi-resolution audit: a
pooled action marginal, trajectory-local marginal, counterfactual benchmark-
state audit, and closed-loop outcome answer different questions. It does not
show a harness evolving over time, exact per-state divergence, or universal
failure of aggregate metrics. Episode-level intervals come from 5,000 held-
out simulator episodes; run-level uncertainty is unknown because the main LLM
result is one unseeded provider run. The source archive names repository
commit `5c2d8b0` but publishes no URL or result bundle, so the tables have not
been independently replayed.

## Synthesis

The Co-Evolution Imperative extends the narrative arc that the Verification Harness (#451) opened, but remains a hypothesis rather than a demonstrated universal condition. HASE reports one small-model system that jointly evolves policy, selected harness components, and solutions. Its imported larger-model rows do not identify harness quality as the cause of the difference.

This has three structural implications:

**First**, the eight-scan exit arc leaves a sustainability question. A harness may require updates as tasks change, but HASE does not show that every fixed harness degrades or that continual self-editing is the right response. A governed trigger, external authority, and non-regression boundary remain necessary.

**Second**, the Kokoro TTS confirmation (✅ 300pts) and full sovereignty stack plateau confirm that the HN community has fully absorbed the sovereignty narrative. All top-tier stories grow <4%. Attention has redistributed from amplitude (big new stories) to width (sustained engagement across many domains). The next phase is either new sovereignty domains or a qualitative shift in how sovereignty is discussed.

**Third**, the Fable 5 extension story (48pts vs C&C Generals port at 687pts) confirms the Attribution Error at the attention level: the community values what the model produces 14× more than the model's availability. The product layer is the unit of community investment, not the model layer.

The arXiv papers motivate a broader pattern across replication, enterprise
knowledge, and exploration architecture: systems may need adaptation when
their context changes. VERITAS is now primary-reviewed, but its experiments
bypass the general claim-extraction and product-scoring path and compare no
fixed-versus-adaptive harness over time. Organizational Memory's synthetic
consumption result is also now primary- and artifact-reviewed; it tests one
frozen memory, not governance or evolution. The papers still share no
longitudinal control. This is cross-domain synthesis rather than a convergent
causal finding.

Future scans will test whether co-evolution can be bounded (does the harness need to evolve *infinitely*, or does it converge?) and whether the co-evolution mechanism can itself be verified (who watches the watchers of the watchers?).
