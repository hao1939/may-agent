**Relevant parallels for agent systems:**

### Analysis

The +16% growth (228→264pts) and deepening discourse indicates this isn't just an "interesting study" — it's resonating as **a felt practitioner problem**. The community is settling on a consensus:

1. **Scale amplifies confabulation**: Larger models have more "knowledge" to confabulate from, and are more confidently wrong
2. **Training incentives are the root cause**: RLHF rewards helpfulness over honesty; "I don't know" is under-trained
3. **Benchmarks misframe the problem**: Conditional hallucination rates ≠ experienced hallucination rates

**Agent implication**: Agent systems that rely on frontier models for factual grounding may need explicit "uncertainty gates" — smaller verification models or retrieval layers that check frontier model outputs. The pattern of "big model generates, small model verifies" may be architecturally necessary, not just a nice-to-have.

## Finding 54-4: CozoDB Fork for Agent Cognitive Primitives (3pts, 0c)

A developer forks CozoDB (embedded relational-graph-vector database) to build agent memory infrastructure, reviving a project that went quiet after Dec 2024.

**Source:** HN (id: 48605896) — "Forked CozoDB to give agents cognitive primitives"

### Context

CozoDB combined Datalog + vector search (HNSW) + full-text search in a single embedded engine, originally envisioned as "the Hippocampus for AI." The original project went quiet; KuzuDB (similar embedded graph+vector DB) was archived in Oct 2025. This fork aims to continue that vision.

### Analysis

This is low-engagement (3pts) but architecturally significant because it represents the **third wave of agent memory infrastructure**:

- **Wave 1 (2023-2024)**: Vector databases (Pinecone, Weaviate) — flat similarity search
- **Wave 2 (2025)**: RAG-augmented vector stores — chunking + retrieval
- **Wave 3 (2026)**: Integrated graph-vector-relational stores — structural memory with semantic lookup

The "cognitive primitives" framing suggests the developer is building toward episodic/semantic/procedural memory separation at the database level — not just "store embeddings" but "store relationships, episodes, and retrievable procedures."

**Connection to BitBoard (58pts, Launch HN, Jun 12)**: Both represent practitioners building specialized infrastructure for agents rather than forcing general-purpose tools to work. BitBoard is analytics; CozoDB-fork is memory. The pattern is **agent-specialized infrastructure emerging as a category**.
