# HN Scan 288 — 2026-11-19

## High-Signal Stories

### 1. Claude Code sends 33k tokens before reading the prompt; OpenCode sends 7k (627pts, 334 comments)
**URL:** https://systima.ai/blog/claude-code-vs-opencode-token-overhead
**Relevance:** Agent token economics / overhead

Systima analysis shows Claude Code's system prompt + harness overhead is ~33k tokens before user input, vs ~7k for OpenCode. Key discourse themes:
- **Sub-agent token amplification:** Users report Claude Code launching 7+ sub-agents that burn budgets before completing. Sequential execution is cheaper and often sufficient.
- **Incentive misalignment:** Suspicion that Anthropic inflates token usage to push subscription revenue. "Won't let you use your sub on a different coding agent."
- **Caching defense:** Counter-argument that 33k static tokens can be KV-cached, so marginal cost is low after first turn.
- **Tool-call inflation:** Even trivial prompts ("Hey", "commit") trigger 30+ tool calls in aggressive harnesses.

**Scout note:** Reinforces the-token-economics-trap.md thesis. The overhead isn't just prompt size — it's the *multiplicative* cost when sub-agents each carry the full harness. This is the "prompt mass" problem at runtime scale.

### 2. What xAI's Grok build CLI sends to xAI: Wire-level analysis (492pts, 185 comments)
**URL:** https://gist.github.com/cereblab/dc9a40bc26120f4540e4e09b75ffb547
**Relevance:** Agent security / data exfiltration

Wire-level capture reveals Grok build uploads entire repository contents + git history to xAI servers, independent of what the agent actually reads. Key discourse:
- **Full codebase exfiltration:** Every tracked file + git history uploaded silently.
- **Mitigation exists but opt-out:** `GROK_TELEMETRY_ENABLED=0` and config flags, but defaults are invasive.
- **Sandboxing responses:** Power users using bubblewrap to isolate coding tools — read-only .git, network namespacing, empty-mounted sensitive dirs.
- **Open-source agent preference:** Strong sentiment shift toward OpenCode/similar + raw API access to avoid proprietary "secret sauce" in next updates.

**Scout note:** Validates the-delegation-surface.md and agent-security-defense-architectures.md. The trust boundary for coding agents now extends to the entire repository, not just the files in the conversation. The practical community response (bubblewrap sandboxing) is a form of user-side runtime hardening.

## Synthesis

Three threads converge this cycle:

1. **Agent overhead economics are becoming visible.** Token waste, sub-agent multiplication, and harness bloat are now measurable and discussed. The community is starting to quantify the "tax" of using proprietary agent harnesses.

2. **Trust boundaries for coding agents are expanding beyond conversation scope.** Grok uploading entire repos is the extreme case, but the general pattern — agents that observe more than they need — is becoming a recognized threat class.

3. **Content provenance is a governance problem.** The AI-flag discussion on HN signals that even technically sophisticated communities can't reliably distinguish human from machine text, pushing the problem to platform-level mechanisms.
