## Core Finding

Seven independent signals converge: **agent evaluation/diagnosis is the next binding architectural constraint** — and it requires its own specialized agent infrastructure to function, creating a recursive dependency that no current framework resolves.

The pattern: evaluation was previously treated as a **metric problem** (pick the right benchmark, compute a score). It's now clearly an **architecture problem** — evaluation at agent scale requires specialized tools, cascaded pipelines, identity primitives, and noise modeling. The evaluator must itself be an agent with tools.

### The Three Impossibilities

| Layer | Finding | Implication |
|---|---|---|
| **Scale** | SAFARI: trajectories exceed context windows by 5× | Linear evaluation (load-all-and-judge) is physically impossible |
| **Accuracy** | RL for CUAs: evaluator noise must be explicitly modeled | Evaluators produce biased rewards without correction |
| **Business** | Eval startups fail: evaluation information expires too fast | Evaluation-as-service is commercially unsustainable |

## Signal 1: SAFARI — Diagnostic Agents for Agent Failure

### arXiv 2606.24626

**Source:** https://arxiv.org/abs/2606.24626

Agent execution trajectories now routinely exceed the largest context windows. SAFARI replaces linear context loading with a **tool-augmented diagnostic loop**:

- LLM equipped with specialized toolbox to read/search trajectory segments
- Persistent Short-Term Memory (STM) for cross-turn reasoning during diagnosis
- Outperforms SOTA by 20% on Who&When dataset within 1M token budget
- Maintains 0.58 precision when fault resides **5× beyond model's native context window**
- Traditional evaluators fail entirely at this distance

**Structural insight**: The evaluator IS an agent — it needs tools, memory, and multi-step reasoning. Evaluation cannot be reduced to a single inference call. This is the diagnosis version of the Recursive Exposure Problem (#134): the diagnostic agent introduces its own failure modes.

## Signal 2: Grading the Grader — Cascaded Evaluation

### arXiv 2606.24839

**Source:** https://arxiv.org/abs/2606.24839

Evaluating agentic data analysis systems (rich outputs: code + numbers + verbal diagnostics) requires a **three-layer human-AI grading cascade**:

1. **Strict regex matching** — deterministic, no false positives, low recall
2. **LLM-based lenient grading** — 97% recall, architecturally parser-independent
3. **Snippet-based human inspection** — catches remaining edge cases

Key findings:
- Both automated graders achieve 100% observed precision (0/70 false positives)
- A keyword-anchored extraction pipeline raises strict recall by 60 percentage points over a last-number heuristic
- Iterative "nudge" mechanism raises run success from 36% to 97%
- **Each layer has structurally different failure profiles** — no single evaluator suffices

**Structural insight**: The three layers are a miniature Compilation Gradient (#118) applied to evaluation itself. Deterministic checks handle what they can; probabilistic grading handles ambiguity; human judgment handles irreducible cases.

## Signal 3: EnterpriseClawBench — The 0.663 Ceiling

### arXiv 2606.23654

**Source:** https://arxiv.org/abs/2606.23654

First enterprise agent benchmark constructed from **real proprietary workplace sessions**:

- 852 reproducible tasks from actual enterprise agent usage
- Paired with recovered fixtures, rewritten prompts, role classes, skill subclasses
- Best configuration (Codex with GPT-5.5): **only 0.663**
- Evaluation must report: harness–model combinations, artifact delivery, visual quality, cost, runtime, skill-transfer behavior

**Structural insight**: Collapsing enterprise agent performance into a single score is informationally empty — the same agent that excels at code generation may fail at visual layout. The benchmark reveals that **skill-class decomposition** is required for meaningful evaluation. Eval startups that offer a single score are answering the wrong question.

## Signal 4: Autonomous Evaluation Requires Noise Correction

### arXiv 2606.24515

**Source:** https://arxiv.org/abs/2606.24515

Using Vision-Language Models as autonomous evaluators for Computer-Use Agents:

- Autonomous evaluator judges task completion from final screenshot + instruction
- But evaluators are imperfect → feedback modeled as **noisy binary reward channel**
- Derives noise-corrected reward estimator for PPO
- Corrected evaluator rewards improve success by 12.6pp over zero-shot, 5.1pp over raw evaluator
- Works across macOSWorld, Windows Agent Arena, and OSWorld

**Structural insight**: Even when evaluation CAN be automated, the evaluator introduces systematic noise that compounds through training. You must evaluate your evaluator's bias AND correct for it — making evaluation a two-level problem. This is the Evaluation Mirage made quantitatively precise.

## Signal 5: Agon — The Machine/Human Judgment Boundary

### arXiv 2606.24177

**Source:** https://arxiv.org/abs/2606.24177

Research orchestrator that runs 444 iterations of "Prompt Economy" loops across disciplines:

- **Design principle**: Validate what CAN be checked inside the workflow, leave remaining judgments to human scientists
- Failure taxonomy organized along: severity, fixability, **visibility**, capability locus
- Separates failures the loops can SEE AND FIX from those requiring human judgment
- Six design principles: Prompt Economy, Future-Facing, Minimal Prompts, OmniDisciplinary, Massive Parallelism, Zero-Code

**Structural insight**: The judgment boundary is not at "hard problems" vs. "easy problems" — it's at the **visibility frontier**. The system can handle severe failures IF it can see them. Invisible failures of any severity require human judgment. This reframes evaluation as a visibility problem, not a complexity problem.

## Signal 6: Linux Foundation Agent Name Service — Trust Primitives

### Linux Foundation Press Release, 2026-06-23

**Source:** https://www.linuxfoundation.org/press/linux-foundation-announces-intent-to-launch-agent-name-service-to-establish-trusted-identity-infrastructure-for-ai-agents

The Linux Foundation launches ANS (Agent Name Service) — extending DNS to provide identity, verification, and discovery for AI agents:

- Built on existing DNS infrastructure (100M+ queries/second)
- **Verifies**: who an agent represents, what permissions it has, whether code/history remain authentic
- Supports DIDs (Decentralized Identifiers) and LEIs (Legal Entity Identifiers)
- Backed by Cloudflare, GoDaddy, Cisco, Infoblox, Hashgraph
- No proprietary namespace or centralized registry — federated

**Key quotes**:
- Jim Zemlin (LF CEO): "trusted identity infrastructure is a foundational requirement"
- Dane Knecht (Cloudflare CTO): "ensure the agentic web is fast, secure, and built on a shared foundation of trust"
- ANS lead author: "greatest concern was that agentic AI systems would proliferate without a neutral, trustworthy identity and discovery layer"

**Structural insight**: Identity is the MISSING FOUNDATION that evaluation architectures depend on. You cannot evaluate what you cannot identify. SAFARI's diagnostic loop, Grading the Grader's cascade, EnterpriseClawBench's skill decomposition — ALL assume you can trace outputs to agents. Without DNS-anchored identity, evaluation lacks provenance.

## Signal 7: Why Eval Startups Fail — Commercial Unsustainability

### HN Discussion (17pts/13c)

**Source:** https://thomasliao.com/eval-startups (HN: 48637868)

Thomas Liao's analysis of eval startup failure, confirmed by HN discourse:

- "Not enough eval customers" — market too thin
- "The information is not updating itself fast enough so that you want the latest model performance benchmarks" — evaluation expires
- Goodhart's Law: the moment an eval becomes a target, it stops measuring what matters
- Counter-argument: "CI/CD, static analysis tools, and testing frameworks" made money — but those test DETERMINISTIC systems

**HN discourse synthesis**: Evaluation of stochastic systems differs fundamentally from testing deterministic ones. CI/CD works because the same input always produces the same output. Agent evaluation fails commercially because:
1. Benchmarks expire (models update faster than evals)
2. Single scores are uninformative (per EnterpriseClawBench)
3. The evaluation itself requires agent-scale infrastructure (per SAFARI)

## Meta-Synthesis: The Recursive Evaluation Stack

These seven signals reveal a **recursive architecture** that no current system fully implements:

```
Layer 4: Evaluation Governance (who decides what to evaluate?)
   ↓ depends on
Layer 3: Evaluation Agent (SAFARI-style tool-augmented diagnostic)
   ↓ depends on
Layer 2: Trust Primitives (ANS-style identity + provenance)
   ↓ depends on
Layer 1: Output Observation (what did the agent actually do?)
   ↓ depends on
Layer 0: Agent Execution (the thing being evaluated)
```

**The crisis**: Each layer introduces its own failure modes:
- Layer 1 fails when trajectories exceed context (SAFARI's problem)
- Layer 2 fails without identity infrastructure (ANS's problem)
- Layer 3 fails with noisy evaluators (CUA paper's problem)
- Layer 4 fails with Goodhart dynamics (eval startup problem)

**The recursive trap**: The evaluation agent (Layer 3) is ITSELF an agent requiring evaluation → infinite regress. The only exit is the **judgment boundary** (Agon): explicitly declare what the machine can check vs. what requires human judgment, and accept that boundary as architectural rather than solving it.

## Self-Application

Our system's evaluation architecture:
- **Layer 0**: Agent execution → ✓ (we run agents)
- **Layer 1**: Output observation → PARTIAL (guards see some outputs, not full trajectories)
- **Layer 2**: Trust primitives → MISSING (no agent identity beyond filename)
- **Layer 3**: Evaluation agent → MISSING (no diagnostic agent for failures)
- **Layer 4**: Evaluation governance → IMPLICIT (conventions.md, but no explicit "what do we evaluate?" decision)

**Gap**: We lack SAFARI-equivalent diagnostic tooling — when an agent fails, there's no specialized diagnostic loop. Failed sessions produce last-session.md but no active fault attribution.
