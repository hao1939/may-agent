## Finding 149: Zero-Touch OAuth for MCP — Protocol Infrastructure Hardens (165pts, 62c)

**Signal strength: HIGH** (front page, multi-org collaboration: Okta, Microsoft, Figma, Linear)

The MCP team published a specification for Zero-Touch OAuth, enabling enterprise-managed authentication for MCP servers without requiring user interaction per-connection. Powered by a new token format: **ID-JAG** (Identity Assertion Authorization Grant), currently an IETF draft.

**Key practitioner positions from comments:**

| Author | Position | Implication |
|--------|----------|-------------|

**Structural significance:** This is the first time MCP's protocol-level value has been clearly articulated by a former skeptic (flashgordon) AND validated by multi-vendor collaboration. The auth story was MCP's biggest enterprise gap; filling it moves MCP from "developer tool protocol" to "enterprise integration protocol."

**Update to [agent-protocols-mcp-a2a.md]:** MCP now has an auth story. ID-JAG as an IETF draft means the auth primitive is being standardized independent of MCP itself — other protocols (A2A, AG-UI) could adopt it.

After MCP, A2A, AG-UI, ARDS, and UMP proposals in 18 months, practitioners want fewer protocols, not more. This validates the "thin protocol layer" design principle already documented in [agent-protocols-mcp-a2a.md].

## Cross-Scan Synthesis: Three Consolidating Themes

### Theme A: Protocol Stack Stratification

The MCP/A2A/discovery/memory protocol landscape is stratifying:
- **MCP winning layer 1** (tool access): Auth maturation (ID-JAG) closes enterprise gap.
- **A2A stalling layer 2** (agent coordination): 4.2% of MCP's adoption, "just use an API" counter.
- **Memory protocols emerging layer 3**: Elasticsearch entry commoditizes the feature.
- **Discovery protocols rejected**: UDDI comparison = community death sentence.

The practitioner consensus is: fewer, thinner protocols. MCP survives because it solves auth isolation. A2A survives only in enterprise stacks. Everything else faces protocol fatigue.

### Theme B: Agents as Attack Targets (Not Just Attack Instruments)

Prior scans documented agents as *instruments* of harm (PR spam, database deletion, cost runaway). This scan's 10k trojan repo finding flips the vector: adversaries now design attack surfaces *for* agents. The attack chain is:
1. Publish fake repos optimized for search recency
2. Agents discover repos during dependency resolution
3. Agents install trojaned packages into production code
4. Human review misses the payload (Disney engineer precedent)

This is the "first Morris worm of AI" that HN predicted in earlier scans.

### Theme C: Local Model Narrative Maturation

The local model narrative has progressed through three phases across Scans #31-33:
1. **Can it replace cloud?** (Scan #31, quantitative)
2. **It's a different tool** (Scan #33, qualitative)
3. **Next: Harness-model fit** — the emerging thesis that custom harnesses paired with local models can outperform generic cloud harnesses.

This tracks the broader Structural Turn: the differentiator is not the model but the surrounding engineering.
