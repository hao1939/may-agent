## Finding 43-4: MCP Enterprise Auth — Protocol Value Reframed (198pts, 66c)

"Zero-Touch OAuth for MCP" (official MCP blog, 198pts) reveals a significant shift in how the community perceives MCP's value:

**Key comment (most insightful this scan):** "Before you get too far into the usual 'MCP is dead, Skills forever' debate — **the real valuable capability MCP offers over skills/CLI is isolating the auth flow outside of the agent's context window**, and potentially out of the harness completely. This is valuable from a security perspective. It's also just a much easier user experience for normies and large businesses adopting AI."

**What this reframes:**
- Our §6 (MCP Discourse Evolution) noted MCP debate "quieted — not because resolved, but because practitioners moved on."
- This comment reveals WHY it quieted: the community found MCP's **actual** value (auth isolation), which isn't the same as its marketed value (tool discovery/composition).
- MCP survives not as a tool protocol but as an **auth delegation protocol**. Skills handle the capability; MCP handles the identity.

**Implementation detail:** New standard called "ID-JAG" (Identity Assertion Authorization Grant) — a token format for delegating identity in agent interactions. Backed by Okta, Microsoft, Figma, Linear.

**XHS prediction connections:**
- **治理即技能 (Governance-as-Skill):** MCP-as-auth-delegation IS governance-as-infrastructure. The auth flow is a governance artifact that lives outside the agent's capability context.
- **智能体操作系統 (Agent OS):** Auth delegation = access control primitive. This is exactly the OS-level primitive the community is independently building. The agent needs to authenticate to resources (like a process needs file permissions), and MCP provides this without polluting the agent's cognitive context.
