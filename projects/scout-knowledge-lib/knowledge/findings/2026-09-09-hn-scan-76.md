## Core Finding

A structural pattern emerges from connecting three simultaneous HN front-page signals (Anthropic ID verification backlash, Cloudflare ephemeral accounts, Loupe privacy exposure), a cluster of arXiv papers on agent authority architecture, and the EDA handoff survey: **agent identity is splitting into three distinct sub-problems that current infrastructure conflates**:

1. **Deployer Identity** (who launched this agent) — what Anthropic's ID check targets
2. **Execution Authority** (what this agent may do right now) — what SEB/Five-Plane papers formalize
3. **Attribution Identity** (what this agent did, provably) — what the Observability paper addresses

The practitioners on HN simultaneously *resist* human-identity gates for deployers ("No way I would agree to that" — SilverElfin) while *demanding* tighter execution-authority constraints for agents (CORS-for-agents discourse). This is not a contradiction — it's evidence that a single "identity" concept is being decomposed into its structural components.

### Stream 2: arXiv — The Authority Architecture Cluster

Three papers from June 2026 independently formalize the identity-authority separation for agents:

**Sovereign Execution Brokers (2606.20520)** — Certificate-Bound Authority:
- Core thesis: "production mutation authority should not reside inside non-deterministic reasoning processes"
- Innovation: SEB sits between agent proposal and infrastructure execution; consumes certificates from SAB (Sovereign Assurance Boundary)
- Flow: Agent proposes → SAB certifies → SEB verifies certificate matches mutation contract → mints scoped execution identity → invokes API → records signed outcome
- Key separation: **agent identity ≠ execution identity**; SEB mints a new, scoped, short-lived identity per certified action
- Evaluation: AWS and Kubernetes clusters, microsecond-scale latency, revocation propagation tested under fault injection
- **Direct relevance**: This IS the three-layer split formalized — deployer (who requested), admission (what was certified), execution (what was scoped and invoked)

**Five-Plane Reference Architecture (2606.12320)** — Runtime Governance:
- Core problem: "risk moves inside the workflow, into sequences of individually-permitted actions that may transform a business process no one authorized"
- Architecture: reasoning plane (adjudicates intent) + four enforcement planes (network, identity, endpoint, data)
- Key concept: **composite principals with capability attenuation** — authority decreases through delegation chains
- Six interruption primitives that generalize allow/deny
- Performance: "single-digit microseconds" for adjudication
- **Critical insight**: "governs delegated action, not model behavior" — explicitly separates what the agent IS from what it may DO

**Observability for Delegated Execution (2606.09692)** — Attribution:
- Core problem: "audit logs and execution traces can be identical under multiple incompatible delegation assignments"
- Discovery: delegation-scoped reconstruction from causal structure alone is "structurally underdetermined"
- Solution: agent-aware observability substrate with gateway that binds delegation context at execution time
- **Key finding**: You cannot reconstruct *what happened under whose authority* from standard traces — you need delegation-scoped attribution primitives built in
- Directly addresses Attribution Identity (layer 3 of the three-layer split)

## Synthesis: The Three-Layer Identity Split

### The Structural Pattern

Current infrastructure treats "identity" as monolithic: one credential, one principal, one audit trail. Agent systems break this because:

1. A **human** deploys the agent (Deployer Identity)
2. An **admission system** certifies what the agent may do (Execution Authority)  
3. An **audit system** must prove what happened under whose delegation (Attribution Identity)

These three layers are being addressed by different communities simultaneously:

| Layer | Problem | Who's Working On It | Current State |
|-------|---------|--------------------|--------------| 
| Deployer Identity | Who launched this? | Anthropic (ID verification), governments (regulation) | Blunt gates, strong backlash |
| Execution Authority | What may it do now? | SEB, Five-Plane, Cloudflare Temp Accounts | Formal models exist, minimal production deployment |
| Attribution Identity | What did it do, provably? | Delegated Execution Observability, audit substrates | Research-stage; "structurally underdetermined" from traces alone |

### Why the Backlash Is Structurally Informative

Practitioners resist Anthropic's ID check not because they oppose identity in principle but because:
- It collapses all three layers into one gate (your government ID determines all capability access)
- It doesn't distinguish deployer from execution authority (you identify once, then the agent has unconstrained authority within its tier)
- It provides no attribution benefit (knowing WHO deployed tells you nothing about WHAT the agent did)

Meanwhile, Cloudflare's approach gets praise because it separates layers:
- Execution is immediate (no identity required)
- Attribution is structural (60-min ephemeral scope = bounded attribution window)
- Deployer identity is optional and deferred (claim later if you want persistence)

## Predictions

1. **Within 6 months**: A major cloud provider or agent platform will offer "scoped execution credentials" for agents — short-lived, capability-bounded tokens that are distinct from the deployer's identity. Cloudflare's temporary accounts are the prototype; AWS/GCP will formalize for agent workloads.

2. **Within 12 months**: "CORS for agents" will become a named pattern — cross-agent-origin resource sharing, where agents must present capability certificates to access resources outside their deployment scope. The CORS 2019 article resurfacing (248pts) is an early indicator of practitioners reaching for this analogy.

3. **Anthropic's ID requirement will bifurcate the market**: identity-gated providers (Anthropic, regulated verticals) vs. identity-optional providers (open-source, self-hosted). This maps to the Chinese two-tier system precedent cited by jingpostmedia.

4. **Attribution Identity will be the binding constraint**: Deployer and Execution authority are solvable with existing cryptographic primitives. Proving what an agent did under whose delegation — the Observability paper's "structural underdetermination" — will become the hardest unsolved problem in agent infrastructure.

## Relevance to This System

- Our system has deployer identity (the user), but execution authority is implicit (agents inherit ambient permissions) and attribution is session-scoped (logs exist but delegation-scoped reconstruction requires manual correlation)
- The SEB pattern (certificate-per-mutation) maps to our task system's acceptance criteria as implicit certificates
- The Five-Plane pattern's "composite principals with capability attenuation" maps to our delegation chain (user → orchestrator → worker) where authority should attenuate
- The Delegated Execution Observability paper directly names our audit gap: we can see what happened in a session but not reliably attribute actions across delegation boundaries
- The EDA Handoff pattern validates our delegation-memo-convention (goal, context_files, success_criteria, scope_boundary) as an informal handoff validity contract
