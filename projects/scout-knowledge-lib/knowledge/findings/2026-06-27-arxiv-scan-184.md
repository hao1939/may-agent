# arXiv Scan #184 — The Composition Tax

**Date**: 2026-06-27
**Source**: arXiv (export.arxiv.org API)
**Scan number**: 184
**Theme**: Naive composition of models, iterations, tools, and workflows hits hard ceilings — the field is now developing structural mechanisms to manage the hidden costs of composition

## Synthesis: The Composition Tax

Seven independent papers, spanning model ensembles, agent loops, code execution, industrial harnesses, business process management, self-improving systems, and decentralized trust, converge on a single structural insight: **every composition of agents, models, or capabilities incurs a hidden tax that grows non-linearly, and only structural discipline controls it**.

| Paper | Composition Type | Hidden Tax | Structural Fix | Key Result |
|---|---|---|---|---|
| Co-Failure Ceiling (2606.27288) | Multi-model ensembles | All-wrong rate (beta) caps gains | Heterogeneous, low-rho ensembles | Beta underpriced 2.5x by standard models |
| Semantic Early-Stopping (2606.27009) | Iterative agent loops | Wasted tokens on converged/impossible queries | Embedding-based convergence detection | 38% token savings at quality parity |
| To Run or Not to Run (2606.26978) | Tool execution in repair | Indiscriminate execution cost | Execution-as-resource with cost-benefit | Only 1.25pp gap: Prohibited vs. Unrestricted |
| NOVA (2606.27243) | Architecture evolution | Silent failures past local tests | Architecture gradient + verification cascade | 13x reduction in human-attended time |
| CUGA FLO (2606.27188) | Agentic workflows | Loss of structural authority | Process harness around deterministic engine | Policy-governed reasoning at control points |
| Red Queen GM (2606.26294) | Self-improvement loops | Stale evaluators after improvement | Co-evolving evaluators with utility evolution | 1.78-1.86x higher acceptance rates |
| ERC-8004 Audit (2606.26028) | Decentralized agent trust | Sybil-dominated reputation | Stake-grounded, interaction-verified feedback | 73-91% Sybil reviewers across chains |

The meta-pattern: **the field has systematically underpriced the cost of composition**. Adding more models, more iterations, more tool calls, more workflow steps, or more trust signals doesn't linearly improve outcomes — it compounds hidden failure modes that only structural mechanisms can manage.

## Finding 1: The Co-Failure Ceiling — Hard Limits on Multi-Model Systems (arXiv 2606.27288)

**Source**: https://arxiv.org/abs/2606.27288

The most mathematically rigorous result in this scan. For any multi-model policy (routing, voting, cascading, mixture-of-agents) whose output is one member model's answer, accuracy cannot exceed `1 - beta`, where beta is the rate at which **every model is wrong on the same query**.

**Key insight**: The field reports pairwise error correlation (rho), but rho cannot identify beta. Error distributions with identical marginals and pairwise correlations can have different all-wrong rates.

**Results across 67 frontier models from 21 providers**:
- On open-ended mathematics: observed beta = 0.052 vs 0.023 under full 67-model Gaussian copula — **2.5x underpricing**, 90% CI [1.7, 3.4]
- On execution-graded code: beta = 0.079
- On GPQA-Diamond free-response: beta = 0.127 — **answer format reopens the co-failure tail**
- Low-rho heterogeneous ensembles beat high-rho Self-MoA
- Combining models rarely beats the single best model without a strong query-level routing signal

**Why this matters**: The MoA/routing trend is hitting a mathematical ceiling that practitioners haven't measured. The co-failure rate is the hard bound — you can't route around questions where everyone is wrong. This validates the Substrate Inversion from a different angle: the gains come from knowing WHICH model to use on WHICH query (architectural intelligence), not from adding more models (capability composition).

**For our system**: Multi-agent composition (e.g., having multiple agents review each other's work) has the same ceiling. If all agents share the same blind spots (as they do when using the same model), composition amplifies confidence without reducing error. The fix is heterogeneity — different model families, different prompt architectures, different information sources.

## Finding 2: Semantic Early-Stopping — Loops Should Know When to Quit (arXiv 2606.27009)

**Source**: https://arxiv.org/abs/2606.27009

Agent loops (Writer-Critic, generate-revise, etc.) are almost universally terminated by `max_iterations` — a "syntactic kill-switch" blind to whether the answer is still improving. This paper introduces semantic early-stopping: halt when consecutive draft embeddings stop changing in meaning.

**Three contributions**:
1. **Theoretical**: Proves deterministic termination and well-definedness with machine-checked claims. Honestly treats convergence as empirical conjecture rather than proven contraction (correcting prior over-claims)
2. **Methodological**: Judge-efficient evaluation protocol that generates each trajectory once and replays stopping policies, separating operational tokens (charged) from evaluation tokens (measurement)
3. **Empirical** (HotpotQA, 60 questions): Judge-free semantic stopper reduces operational tokens by **38%** vs max_iterations at quality parity (Delta-IS = -0.004, p = 0.81). Full quality-gated variant is counter-productive because per-round judging dominates cost

**Critical finding**: An oracle that selects the best round achieves +0.115 Information Score over every practical policy (p ~ 4e-11). This reframes the problem from "when to stop" (easy — semantic convergence detects this) to **"which round was best"** (open — quality is non-monotonic across rounds).

**Why this matters**: This directly addresses the Metacognitive Ceiling (#183) — the agent can't tell when to stop, so it wastes 38% of tokens persisting past convergence. The semantic stopping pattern is immediately applicable: if the agent's output isn't changing meaningfully, stop. But the deeper finding — that quality is non-monotonic and the best round isn't the last — means agents need a selection mechanism, not just a stopping mechanism.

**For our system**: Our agents don't have semantic convergence detection. When a task is stuck, the agent iterates until the session ends or an explicit error occurs. A cosine-distance check on successive outputs would catch many "spinning wheels" patterns at near-zero cost.

## Finding 3: To Run or Not to Run — Execution Is Not Free (arXiv 2606.26978)

**Source**: https://arxiv.org/abs/2606.26978
**Venue**: ISSTA 2026

A two-stage empirical study of execution behavior in LLM-based program repair across 7,745 agent traces from SWE-bench leaderboard submissions and 3,000 end-to-end repair attempts across three agents (Claude Code, Codex, OpenCode) under four execution paradigms.

**Three key observations**:
1. **Execution is ubiquitous**: Average 8.8 test runs per task. Frequency varies 2-19 per task across agents. Late-stage executions have higher success rates than early-stage ones
2. **Execution restrictions barely affect success**: On commercial agents with SOTA models, the resolve-rate gap between Prohibited and Unrestricted is **only 1.25 percentage points** — not statistically significant. Prohibited saves substantial token and wall-clock cost
3. **Execution benefit is concentrated**: Gains come on specific instance types, not uniformly. Current agents apply execution indiscriminately

**Structural implication**: Execution should be treated as a **resource with explicit cost-benefit tradeoff**, not a default capability. The "generate-run-revise" paradigm is paying execution cost on instances where it provides little benefit.

**Why this matters**: This is the code-execution-specific instance of the Composition Tax. The field assumed "more execution = better repair" and built it into every system. The data shows the marginal value of execution is near zero for commercial agents that already have strong internal reasoning. This connects to the Metacognitive Ceiling (#183): agents can't tell when execution will be informative vs. wasteful, so they execute indiscriminately.

**For our system**: Our coding agents could benefit from an execution budget that asks "is running this test likely to provide new information?" before executing. Late-stage execution (after the agent has a clear hypothesis) is far more valuable than exploratory early execution.

## Finding 4: NOVA — Architecture Gradient for Industrial Agent Harnesses (arXiv 2606.27243)

**Source**: https://arxiv.org/abs/2606.27243

Deployed in an industrial advertising system (recommender model evolution), NOVA introduces two key concepts:

**Architecture Gradient**: An SGD-inspired, non-differentiable update signal that aggregates prior modifications, verification diagnostics, metric feedback, and trajectory memory to guide the next architecture modification. This is not gradient descent — it's a structured feedback mechanism that gives the agent a sense of direction in architecture space.

**Verification Cascade**: Four-level check (structure semantics → local executability → offline effectiveness → online impact) that blocks invalid candidates early. Failed patterns are recorded as **forbidden directions** — explicit negative guidance.

**Level-aware task routing** (L1-L4): Matches automation to task complexity and risk. High-risk L3 tasks route to Copilot for human oversight.

**Results**:
- Highest effective pass rate on L2 ScaleUp (54.5%) and L3 Literature-to-Production (60.0%)
- Reduced silent failures vs. coding-agent baselines
- **13x reduction in human-attended time** for literature-to-production cycles
- Online A/B: +1.25-2.02% GMV on pCVR objectives, -37-67% pCVR bias

**Why this matters**: NOVA is the first industrial deployment that makes "the harness IS the intelligence" concrete for architecture evolution. The architecture gradient concept — giving agents a non-differentiable update signal synthesized from verification feedback and trajectory memory — is a novel pattern that addresses the metacognitive ceiling structurally: the agent doesn't need to know when it's wrong because the verification cascade catches it.

**The forbidden directions pattern** is particularly interesting: explicitly recording what NOT to try is a negative knowledge mechanism that prevents the agent from re-discovering failed approaches.

## Finding 5: CUGA FLO — The Process Harness Pattern (arXiv 2606.27188)

**Source**: https://arxiv.org/abs/2606.27188

Introduces the **process harness**: a policy-governed agentic layer around a deterministic workflow engine. The engine retains structural authority; agents reason only at designated control points.

**Task-Decision-Flow (TDF) model** decomposes LLM reasoning across three policy-governed agent types:

| Agent Type | Role | Scope |
|---|---|---|
| TaskAgent | Knowledge-intensive task execution | Executes within defined task boundaries |
| DecisionAgent | Per-case gateway routing | Decides which path at process decision points |
| FlowAgent | Runtime flow adaptation via hook mechanism | Adapts process structure within policy bounds |

**Key design principle**: Each agent reasons within an explicit policy drawn from the process FRAME — the aggregate policy set governing all LLM calls in the system. This reconciles:
- **Imperative requirements**: Deterministic workflow execution enforces structural compliance
- **Normative requirements**: Policy-framed agentic autonomy at designated control points

**Why this matters**: The process harness is the formal realization of two of our strongest findings:
1. **Substrate Inversion**: The deterministic engine (structure) retains authority; agents (models) serve at control points
2. **Isolation Imperative (#180)**: Each agent type is isolated to its scope; policy boundaries prevent cross-concern interference

This is also the first paper to explicitly formalize the "deterministic harness around stochastic agent" pattern that we've observed emerging across multiple systems. The FRAME concept (aggregate policy set) addresses the Governance Vacuum (#170) — unmanaged agent configurations — by making policy explicit and bound.

## Finding 6: Red Queen Gödel Machine — Evaluators Must Co-Evolve (arXiv 2606.26294)

**Source**: https://arxiv.org/abs/2606.26294

Self-improving agents assume a stationary evaluation criterion — a fixed verifier, benchmark, or labeled dataset. The Red Queen Gödel Machine (RQGM) makes evaluation part of the improvement loop.

**Architecture**: Controlled utility evolution — search proceeds in epochs with fixed within-epoch evaluation, while the utility function can be updated at epoch boundaries. Self-improvement guarantees hold per-epoch as the objective evolves across them.

**Results**:
- On verifiable coding tasks: improves test pass rate over prior SOTA with agent-as-a-judge code review, using **1.35-1.72x fewer tokens**
- On scientific paper writing: co-evolved writers reach **1.78-1.86x higher acceptance rates** under diverse agent-as-a-judge panel
- Co-evolved graders reach **+9% ground-truth accuracy** on proof grading
- Key finding: Strongest baseline reviewer **over-accepts AI-generated papers at 1.91x the human rate**. RQGM's adversarial objective discovers reviewers equally stringent on AI and human work

**Why this matters**: Static benchmarks are themselves a composition tax — they accumulate staleness as the system improves past them. The RQGM shows that evaluation must be treated as a co-evolving system component, not a fixed external standard. The 1.91x over-acceptance rate for AI papers is a concrete instance of the Evaluation Mirage (library note): passing an evaluation doesn't mean the work is good; it means it fits the evaluator's (potentially stale) criteria.

**For our system**: Our evaluator agent uses fixed rubrics. As our coding agents improve, those rubrics may be measuring the wrong things — "tests pass" becomes trivial while the real quality differentiator shifts to "approach was appropriate." The RQGM's co-evolution pattern suggests evaluator prompts should evolve based on the distribution of errors the current system actually makes.

## Finding 7: ERC-8004 — Decentralized Agent Trust Doesn't Work Yet (arXiv 2606.26028)

**Source**: https://arxiv.org/abs/2606.26028

First empirical audit of the ERC-8004 protocol — the first permissionless trust layer for AI agent economies, with on-chain registries for Identity, Reputation, and Validation.

**Identity findings**: Most registrations are placeholders. Only 3-15% across Ethereum, BSC, and Base expose a valid registration file with live service endpoints.

**Reputation findings — devastating**:
- Values are not commensurable (different agents rate on different scales)
- Feedback records rarely grounded in verifiable interactions
- Reputation can be manipulated at minimal cost
- **73.6-90.6% of reviewers across Ethereum, BSC, and Base exhibit coordinated Sybil behavior**
- After removing Sybil-flagged feedback: 15.5-89.4% of rated agents have NO valid feedback remaining

**Why this matters**: The Trust Frontier (library note) predicted that agent-to-agent trust would be the binding constraint on multi-agent economies. This audit confirms it empirically: the first deployed trust protocol is dominated by Sybils and provides no trustworthy signal. The composition tax for multi-agent economies is even steeper than for multi-model systems — composing agents across organizational boundaries requires solved trust, and trust is unsolved.

**Structural implications**:
- Reputation without stake is Sybil-vulnerable (known in blockchain literature, now confirmed for agents)
- Feedback must be grounded in verifiable interactions, not self-reported
- The agent-to-agent trust problem is fundamentally harder than human-to-human reputation because agents can be cloned at near-zero cost

## Cross-Finding Connections: The Composition Tax Stack

| Layer | Composition Type | Tax | Detection | Mitigation |
|---|---|---|---|---|
| **L1: Model** | Multi-model ensembles | Co-failure ceiling (beta) | Clopper-Pearson bound on all-wrong rate | Heterogeneous, low-rho ensembles |
| **L2: Iteration** | Agent loops | Token waste past convergence | Semantic embedding distance | Early-stopping at convergence |
| **L3: Tool** | Code execution | Indiscriminate execution cost | Execution-value prediction | Late-stage, targeted execution |
| **L4: Architecture** | Architecture search | Silent failures, wasted exploration | Verification cascade | Architecture gradient + forbidden directions |
| **L5: Process** | Workflow orchestration | Loss of structural authority | Policy-frame compliance check | Process harness (TDF model) |
| **L6: Evaluation** | Self-improvement | Evaluator staleness | Acceptance rate drift monitoring | Co-evolving evaluators (RQGM) |
| **L7: Trust** | Multi-org agent economies | Sybil-dominated reputation | Sybil detection algorithms | Stake-grounded, interaction-verified trust |

### The Composition Tax Principle

Each composition layer (adding models, iterations, tools, architecture search, workflow steps, improvement loops, or trust signals) appears to offer linear gains but actually incurs super-linear costs:

1. **More models** → co-failure ceiling caps gains at `1 - beta`
2. **More iterations** → 38% token waste past semantic convergence
3. **More execution** → 1.25pp marginal value on commercial agents
4. **More architecture search** → silent failures without verification cascade
5. **More workflow steps** → structural authority erosion without deterministic harness
6. **More self-improvement** → evaluator staleness and over-acceptance drift
7. **More trust signals** → Sybil amplification without interaction verification

**The fix is always the same: structural discipline that makes the cost explicit and manageable**. Not less composition — better-governed composition.

### Connection to Prior Findings

- **Metacognitive Ceiling (#183)**: The Composition Tax explains WHY the metacognitive ceiling exists — agents can't perceive the diminishing returns of their own composition. Semantic stopping and execution budgets are structural proxies for metacognition
- **Isolation Imperative (#180)**: Isolation is the mechanism that prevents composition costs from compounding across layers — each composition boundary needs its own governance
- **Substrate Inversion**: The Composition Tax is the economic evidence for Substrate Inversion — naive composition (throwing more model at the problem) hits ceilings that only architectural intelligence overcomes
- **Verification Bankruptcy (#178)**: Verification IS the composition tax on generation — every generated artifact requires verification, and verification cost grows faster than generation cost
- **Governance Vacuum (#170)**: Unmanaged composition is unpriced composition — the tax is paid but invisible until it compounds into system failure
