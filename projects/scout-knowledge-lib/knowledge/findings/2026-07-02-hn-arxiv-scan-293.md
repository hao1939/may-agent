# HN/arXiv/GitHub Exploration: The Governance Receipt (2026-07-02, Scan #293)

## Theme

Six independent research streams in a single 24-hour window converge on the same architectural response to the Expressivity Floor (#291): when you cannot express everything that needs governing in a protocol, you can prove that whatever governance DID apply was faithfully executed. The mechanism: **governance receipts** — independently verifiable artifacts binding each action to the exact policies, evidence, and decisions that governed it. This transforms governance from "trust that constraints held" to "verify that governance occurred."

## arXiv Papers

### AgentBound: Verifiable Behavioral Governance (2606.30970)

Runtime governance framework providing **cryptographically verifiable governance receipts** for every action an autonomous agent takes.

- Three independent authorities: delegated authorization, owner-signed behavioral constitutions, site action contracts
- Conservative composition: all three must agree before permit/review/deny
- **Governance receipt**: binds each action to the exact delegation, policy, and semantic artifacts governing the decision
- Enables independent replay verification and policy provenance
- Standing delegation for persistent agents with continuous policy refresh + revocability
- Includes AgentBound-Bench for governance correctness evaluation
- Key claim: transforms governance from trusted process to independently verifiable one

**Structural significance**: First formal architecture where governance is PROVABLE per-action rather than assumed system-wide. The "receipt" abstraction makes governance auditable by third parties without requiring trust in the governed system.

Source: https://arxiv.org/abs/2606.30970

### ECHO: Source-Indexed Credit Memory (2606.31650)

Selective turn-memory framework that produces **evidence credit receipts** — explicit binding between successful outcomes and the evidence/actions that produced them.

- Compresses each completed turn into compact memory record
- Reconstructs bounded policy contexts by selecting from records
- Source indices route positive outcome credit to supporting evidence
- On BrowseComp-Plus: 43.4% accuracy vs GRPO 28.9% and SUPO 36.1%
- Fewer turns AND lower trajectory volume than baselines
- Zero-shot generalization across QA, code gen, and information-seeking

**Structural significance**: Memory governance via receipt — every conclusion carries its evidence provenance. The system can be audited: "why did you decide X?" has a traceable answer in the source indices.

Source: https://arxiv.org/abs/2606.31650

### Janus: Memory Update Gating Controller (2606.31121)

Plug-in controller that produces **update decision receipts** — explicit evidence that each memory update improved rather than degraded capability.

- Memory Momentum Trigger identifies suspicious deviations in update trajectory
- Hybrid evaluation set (coverage, boundary, fresh tasks) as minimal test receipt
- Compares old vs new memory on compact set before accepting update
- Method-agnostic: wraps any updater without changing update rules
- +2.7 to +4.6 points across six datasets, two LLMs, two updaters
- Key: REJECTION is documented — failed updates leave auditable traces

**Structural significance**: Memory governance via gated receipt. Complements Manufactured Confidence (#280): Janus would catch the confidence-manufacturing rewrite by comparing pre/post on evaluation tasks.

Source: https://arxiv.org/abs/2606.31121

### LabGuard: NL-to-Executable Safety Compilation (2606.31045)

Language-to-execution safety suite that produces **compilation receipts** — typed IR proving natural-language rules became machine-checkable runtime constraints.

- LabGuard-IR: typed executable representation of safety rules
- LabGuard-Bench: 812 annotations from 203 seed rules
- Pipeline compiles NL rules → IR → runtime monitors at controller boundary
- Reduces unsafe events 39.5% → 23.8%; interventions below 0.5%
- Receipt = the IR artifact itself: human-readable, machine-executable, auditable

**Structural significance**: Solves the NL-to-enforcement gap via receipt artifact. Each safety rule's operational status is provable: either it compiled successfully (IR exists) or it didn't (gap is visible).

Source: https://arxiv.org/abs/2606.31045

### Calibrating the Evaluator (2606.31371)

First study showing probability calibration as mitigation for evaluator preference coupling, producing **calibration receipts** — measurable bias reduction.

- Confidence-calibrated TTRL: probability-weighted updates instead of binary win/loss
- Coupling coefficient γ reduced 20-49%, JSD reduced 45-67%
- Symmetric-LR control confirms effect isn't from reduced asymmetry
- Receipt = calibration parameters + measured γ before/after: verifiable improvement

**Structural significance**: Even the evaluation of governance can be receipted. The evaluator's bias is measurable, and the mitigation's effect is independently quantifiable.

Source: https://arxiv.org/abs/2606.31371

### Generative Skill Composition / SkillComposer (2606.32025)

Structured skill composition as autoregressive decoding, producing **composition receipts** — the predicted plan itself serves as auditable artifact.

- Formalizes skill composition as joint decision: which skills, how many, what order
- Constrained autoregressive decoder over skill identifiers
- +23.1pp (GPT-5.2-Codex), +18.2pp (Gemini-3-Pro) over no-skill baseline
- Matches gold-skill upper bound at lower prompt-token cost
- Receipt = the skill plan: enumerable, reviewable, replayable

**Structural significance**: Composition governance via structured receipt. Instead of opaque "the agent used some skills," the exact composition plan is a verifiable artifact that can be audited, replayed, or contested.

Source: https://arxiv.org/abs/2606.32025

## Structural Analysis: The Receipt Taxonomy

Five receipt types identified across this scan's sources:

| Receipt Type | Mechanism | Example |
|--------------|-----------|---------|
| **Action Receipt** | Cryptographic binding of action → policy → delegation | AgentBound |
| **Credit Receipt** | Source-index binding of outcome → evidence | ECHO |
| **Update Receipt** | Comparison artifact proving state change was beneficial | Janus |
| **Compilation Receipt** | Typed IR proving NL intent became executable constraint | LabGuard |
| **Composition Receipt** | Auditable plan proving skill/tool selection was structured | SkillComposer |

**Missing receipt types** (governance gaps from this scan):
- **Belief-state receipt**: No mechanism receipts manipulation via physical action (NCP-ToM)
- **Emergence receipt**: No mechanism receipts collective behavior in persistent agent societies (OpenLife)
- **Compositional receipt**: No mechanism proves that per-layer receipts compose to system-level guarantee (Lifecycle Survey)

## Design Principle

> **Governance receipt**: Every governed action must produce an independently verifiable artifact that binds the action to the exact policies, evidence, and decisions that governed it. The receipt must be replayable without trust in the system that generated it.

This resolves the Expressivity Floor (#291) not by making protocols more expressive, but by requiring that whatever governance DOES apply leaves a provable trace. Incomplete governance that produces receipts is strictly superior to comprehensive governance without receipts — because the gaps become visible.
