## Theme: The Endpoint Attack Surface Crystallization

Two parallel developments converge on the same structural layer — the endpoint-resident AI agent:

1. **Attack surface taxonomy reaches professional maturity** — EAA (Endpoint AI Agent Abuse) catalogs 16 techniques across 6 surfaces, maps 7 real-world incident campaigns, requires public evidence anchors, and provides machine-readable data. This is the npm-audit / MITRE ATT&CK equivalent for AI coding agents.

2. **Infrastructure sovereignty accelerates** — AMD RDMA local clusters (123pts), deterministic routing (53pts), and "agentic OS factory" architecture confirm endpoint residency as deliberate strategic choice, not just cost optimization.

The binding insight: **endpoint agents are simultaneously the most attacked AND most defensible layer.** Attacked because they inherit user authority + persistent state. Defensible because the taxonomy is now documented, mitigations are known, and local-first architecture gives operators full control of the trust boundary.

## I. Key Finding: EAA — First Endpoint Agent Attack Taxonomy

### Overview

**Repository**: [0x4D31/endpoint-ai-agent-abuse](https://github.com/0x4D31/endpoint-ai-agent-abuse) (10★, created 2026-06-26)

The first rigorous, evidence-anchored catalog of attack techniques against endpoint-resident AI agents. Scope deliberately narrow: Claude Code, Gemini CLI, Codex, Cursor, Kiro, Windsurf and similar tools, plus their local surfaces.

### Attack Surface Model (6 surfaces)

| Surface | What it covers | Techniques |
|---------|---------------|------------|
| **Invocation** | Who starts the agent, from where, with what mode | EAA-001, EAA-002 |
| **Runtime** | Launch environment and process-level behavior | EAA-007, EAA-008 |
| **Control Plane** | Files shaping behavior: instructions, memory, hooks, skills | EAA-003, EAA-004, EAA-009, EAA-013, EAA-014 |
| **State & Telemetry** | Transcripts, tool history, logs, caches | EAA-005, EAA-012 |
| **Capabilities** | MCP servers, tools, dynamic definitions | EAA-006, EAA-010, EAA-011 |
| **Inherited Authority** | Shell, files, browser state, CLIs, cloud creds | EAA-015, EAA-016 |

### Critical Technique Highlights

- **EAA-003 (Lifecycle Hook Persistence)**: Install scripts write Claude Code `SessionStart` hooks for persistence. Real incident: Mini Shai-Hulud.
- **EAA-004 (Persistent Instruction Poisoning)**: Malicious commits plant config files (CLAUDE.md, .cursorrules, gemini settings) that execute payloads. Real incident: Miasma Worm Campaign.
- **EAA-010 (MCP Dynamic Tool Mutation)**: Tool definitions change after approval — post-approval drift attacks.
- **EAA-014 (Multi-Agent Config Fan-out)**: Single compromise propagates config poisoning to multiple agent surfaces simultaneously.
- **EAA-015 (Inherited Authority Abuse)**: Agents use existing creds (gh, aws, gcloud) for lateral movement.

### Mapped Incidents (7 campaigns)

1. **Nx s1ngularity**: npm packages detected local agents, used them for reconnaissance
2. **Trivy OpenVSX extension**: Compromised extension launched agents in permissive mode
3. **Mini Shai-Hulud**: Package payload planted Claude Code hook persistence
4. **Miasma repo injection**: Config files triggering payloads across Claude Code/Gemini/Cursor/VS Code
5. **Miasma Phantom Gyp**: Package install injecting AI assistant configs into repos
6. **Hades**: PyPI packages walking workspace trees targeting assistant configs
7. **MCP injection/rug-pull**: Tool-description injection + post-approval drift

### Structural Significance

This is the first taxonomy that:
- **Requires evidence anchors** for every technique (incident, artifact, or documented surface)
- **Provides machine-readable format** (catalog.json)
- **Separates surfaces from techniques** (same technique can hit multiple surfaces)
- **Includes detection guidance** (hunting.md)
- **Has promotion rules** (candidates.md → techniques/ requires evidence)

**Comparison to prior signals**: Our scan #218 captured the individual "Clean GitHub repo tricks AI coding agents" story (48699886, 4pts). EAA is the STRUCTURAL response — the community's self-organization into a defensive taxonomy, analogous to OWASP for web apps or MITRE ATT&CK for enterprise security.

### Wayfinder Router — Deterministic Routing Crystallization (48704373, 53pts/9c)

Source: https://news.ycombinator.com/item?id=48704373
Source: https://github.com/itsthelore/wayfinder-router

Deterministic prompt-complexity routing with **no model call to decide**. Reads structural features (length, headings, code blocks, difficulty cues) in microseconds. Key differentiator vs. prior model routers (scan #186 — universal hostility): **eliminates the composition tax** that killed model-based routing.

Community signal: Another router builder responding "ShowHN coming up later today." Category crystallizing.

**Connection**: Addresses the model routing rejection (scan #186/197) by eliminating the model call. The community rejected RL-trained routers because they add latency, cost, and non-determinism. Wayfinder eliminates all three. This may be the pattern that model routing needed to survive.

### Kaizen Security — Behavioral Baseline Defense (GitHub, 15★)

Source: https://github.com/getkaizen/kaizen-security

"Runtime security for the AI agents you build. Learns each agent's normal behavior and blocks what it never does." Behavioral anomaly detection applied to agent tool-calling patterns.

**Connection to EAA**: Addresses EAA-015 (Inherited Authority Abuse) — if the agent has never called `gh repo upload`, blocking that invocation is a behavioral baseline defense. Complementary to EAA's taxonomy: EAA defines the attack surfaces; Kaizen-style tools learn the normal behavioral manifold and flag deviations.

## V. Synthesis: The Endpoint Convergence

Three independent streams converge on the endpoint as the critical governance layer:

1. **Attack formalization** (EAA): 16 techniques, 6 surfaces, 7 incidents documented. The attack surface is now *known* and *enumerable*.

2. **Defense formalization** (Kaizen, ActPlane §2.33): Behavioral baselines + kernel enforcement. Defenses exist for the known surfaces.

3. **Infrastructure sovereignty** (RDMA clusters, deterministic routing, agentic OS): Practitioners building owned infrastructure where they control the full trust boundary.

**Key insight**: The endpoint is where attack and defense are both most concentrated AND most tractable. Unlike cloud/SaaS (where attack surfaces span multiple trust domains), endpoint agents operate within a single trust boundary. This makes comprehensive defense architecturally possible — EAA's 6 surfaces are a bounded enumeration, not an open-ended list.

**Connection to prior scans**:
- **Revocability Default** (#192): Endpoint infrastructure is the one *irrevocable* layer — you own the hardware, the model weights, the configuration
- **Governance Vacuum** (#170): EAA fills the vacuum specifically for endpoint agents — the config layer now has its MITRE ATT&CK equivalent
- **Trust Construction Gap** (#218): EAA provides the evidence-anchored structure the zero-traction trust repos lacked
- **Infrastructure Legitimation** (#197): AMD RDMA clusters + agentic OS = endpoint agents as first-class infrastructure principals with dedicated hardware
