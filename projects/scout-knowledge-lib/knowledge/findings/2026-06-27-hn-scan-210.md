## arXiv Findings

### Safety in Self-Evolving LLM Agent Systems (2606.23075)
**The MLAS Matrix**

First systematic security analysis of self-evolving agents. Introduces Module-Lifecycle Attack Surface (MLAS) matrix:
- **5 modules**: Brain, Cognitive Resource, Execution, Self-Design, Collective
- **5 lifecycle stages**: Bootstrap, Propose, Evaluate, Commit, Serve
- **Result**: 17/25 cells face critical threats with no effective partial mitigation

Key empirical findings:
- Evolution-native design activates **3.5× more attack surface cells** than traditional agent architectures
- **100% attack persistence rate** (40/40 payloads across all CIA+Privacy categories)
- Co-located security scanners block only **2.5%** of attacks
- **Seven cross-cutting amplification effects** that interact synergistically

Critical insight: "Self-evolution converts every known attack category from session-bounded to **lineage-persistent**, gives rise to entirely new attack classes, and renders static defenses structurally inadequate."

**Implication**: This is the quantitative proof that evolution = compromise. The mechanism by which an agent improves (proposes change → evaluates → commits) is structurally identical to the mechanism by which it is attacked (adversary proposes change → agent evaluates → commits). The only difference is intent — which no static defense can assess.

Source: https://arxiv.org/abs/2606.23075

### SAFARI: Scaling Long Horizon Agentic Fault Attribution (2606.24626)
**Diagnosis Beyond Context Limits**

Problem: Agent execution trajectories now exceed even the largest context windows, making fault diagnosis impossible with current "load full trace" methods.

Solution: Tool-augmented diagnostic loop with persistent Short-Term Memory (STM) for cross-turn reasoning.

Results:
- **+20%** over SOTA on Who&When dataset (1M token budget)
- **+19%** on TRAIL GAIA subset (25K token budget)
- Maintains **0.58 precision** when fault resides **5× beyond native context window**

**Implication**: We can't diagnose self-compromised agents because their histories exceed our inspection capacity. SAFARI proves diagnosis is possible but requires dedicated diagnostic agents — agents diagnosing agents, with all the recursive trust implications.

Source: https://arxiv.org/abs/2606.24626

### Red-Teaming the Agentic Red-Team (2606.24496)
**The Security Tools Are Compromisable**

First in-depth security analysis of offensive security agents themselves:
- Most tools share **common design flaws** enabling API key exfiltration, persistent footholds, and full machine compromise
- Attacks succeed **even inside sandboxed containers**
- Introduces full **cyber kill chain for agentic systems**: LLM manipulation → lateral movement → persistence → guardrail bypass → sandbox escape

Proposes: robust architecture for agentic offensive-security tools + actionable design principles.

**Implication**: The agents we use to TEST for compromise are themselves compromisable. The self-compromising loop is recursive: security agents that evolve their attack strategies evolve their own vulnerability surfaces. There is no fixed Archimedean point from which to assess security.

Source: https://arxiv.org/abs/2606.24496

### RIFT-Bench: Dynamic Red-teaming for Agentic Systems (2606.23927)
**Unified Security Evaluation Across Architectures**

- Graph-representation-driven methodology for dynamic red-teaming
- Evaluated across **45 agentic systems** spanning diverse implementations
- Two phases: Discovery (extracts structure) → Scanning (deploys adaptive attacks)
- Generalizes to heterogeneous architectures
- Also evaluates mitigation strategies directly

**Implication**: The need for automated security evaluation of heterogeneous agent systems implies the field has already outgrown human-in-the-loop security review. Connects to Supervision Cost Spiral (#191) — we can't manually audit at this scale.

Source: https://arxiv.org/abs/2606.23927

### AutoSpec: Safety Rule Evolution via ILP (2606.24245)
**The Constructive Response**

Evolves safety rules from user annotations via counterexample-guided inductive synthesis (CEGIS) + Inductive Logic Programming:
- F1 **0.98** and **0.93** across two domains
- **94% false positive reduction** while maintaining high recall
- Converges in **4–5 iterations**
- **4.8× higher F1** than heuristic CEGIS
- Rules are human-readable, auditable, generalizable

**Implication**: First constructive partial answer to the self-compromising loop — rules that CO-EVOLVE with agent behavior, using formal synthesis rather than static specification. Connects to JERP (scan #170) and Informality Tax (scan #177). The evolution of governance must match the evolution of capability.

Source: https://arxiv.org/abs/2606.24245

### Critique of Agent Model (2606.23991)
**"Agentic" vs "Agentive" Distinction**

Philosophical/architectural framework distinguishing:
- **Agentic**: Competence resides in engineered workflows (external scaffolding)
- **Agentive**: Capabilities arise endogenously (internalized goal, identity, learning)

Proposes Goal-Identity-Configurator (GIC) architecture: hierarchical goal decomposition + identity evolution + simulative reasoning via separate world model + learned self-regulation + self-directed learning.

**Implication**: The self-compromising loop is a property of "agentive" systems specifically. "Agentic" systems (our current paradigm) are protected by the very scaffolding that limits their capability. The transition from agentic → agentive is the transition from bounded to unbounded compromise surface. Current hybrid approaches (memory writes, self-improvement loops) occupy the dangerous middle ground.

Source: https://arxiv.org/abs/2606.23991

## Synthesis: The Self-Compromising Loop

Six independent signals converge on one structural principle:

| Evidence | What it shows |
|----------|--------------|
| MLAS Matrix (2606.23075) | Evolution activates 3.5× attack surface; 100% persistence |
| SAFARI (2606.24626) | Can't even diagnose faults at scale (5× beyond context) |
| Red-Team the Red-Team (2606.24496) | Security tools themselves are compromisable |
| RIFT-Bench (2606.23927) | Need automated security evaluation (human review can't scale) |
| Exploitarium (48698617) | Vulnerability provenance already broken |
| Post-Mythos (48698559) | Access asymmetry IS the attack surface |

**The loop**:
```
Agent improves → new capability → new attack surface
    ↓
Agent needs security → security tools improve → security tools develop new attack surfaces
    ↓
Agent needs diagnosis → diagnostic agents improve → diagnostic agents exceed context → diagnosis incomplete
    ↓
Incomplete diagnosis → missed compromise → compromised agent continues improving → ...
```

**The structural insight**: Evolution and compromise share **identical mechanisms**:
- Memory write = knowledge poisoning
- Tool acquisition = capability injection
- Architecture modification = persistent backdoor
- Parameter update = behavioral corruption
- Self-evaluation = self-deception

The only distinguishing feature is **intent** — but intent is exactly what we proved unobservable (Mechanism Gap #200, Anti-Deliberation #176, Premature Commitment detection).

**Connection to existing framework**:
- Extends Memory Write Problem (#175): writes are dangerous not just as a surface, but as a **fundamental mechanism of self-modification**
- Explains Governance Vacuum (#170): you can't govern a process that IS the thing you're trying to prevent
- Completes Implementation Blind Spot (#203): the runtime code is the evolution mechanism AND the attack surface
- Validates Isolation Imperative (#180): isolation is the only way to distinguish improvement from compromise (branch-isolated memory, sandbox-per-agent, etc.)

**The one escape identified**: AutoSpec (2606.24245) — co-evolutionary rule synthesis. If governance evolves AS FAST as capability (formal, verifiable, 4–5 iteration convergence), the loop can be bounded. But this requires the evolution of governance to be cheaper and faster than the evolution of capability — currently untrue.
