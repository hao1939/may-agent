# arXiv Scan #193 — The Measurement Ceiling

**Date**: 2026-06-27
**Source**: arXiv (export.arxiv.org API)
**Scan number**: 193
**Theme**: Evaluation instruments systematically misrepresent agent capability by measuring at the wrong resolution

---

## Synthesis: We Cannot Improve What We Cannot Correctly Measure

Four independent papers — spanning ensemble evaluation theory, judge meta-evaluation, skill library lifecycle, and mechanistic interpretability — converge on a structural crisis: **the instruments the field uses to evaluate agents operate at the wrong abstraction level, creating a measurement ceiling that hides real capability, masks real failure, and blocks principled improvement**.

| Paper | What's measured | What's missed | Gap magnitude |
|---|---|---|---|
| Capability Frontier (2606.26836) | Single-model, single-run accuracy | Cross-model complementarity + retry budget | 82% error reduction invisible |
| Counsel (2606.21627) | Judge error location agreement | Judge reasoning quality | ~88% location → ~65% reasoning |
| Library Drift (2605.19576) | End-task pass@1 | Per-skill contribution scores | +0.0pp auto-generated vs +16.2pp curated — invisible until governance |
| DFC Crosscoder (2606.26474) | Behavioral tool-call success | Which internal features mediate the capability | +31.1pp from feature reconstruction alone |

The meta-pattern: **every layer of agent evaluation has a resolution problem**. The model layer measures too coarsely. The judge layer measures too shallowly. The skill layer measures too late. The mechanistic layer isn't measured at all. Together, these form a measurement ceiling: a hard limit on how well we can understand what our agents actually do.

### Why This Matters for Our System

Our own evaluation stack inherits all four gaps:
1. We evaluate per-agent, not across complementary agent capabilities (no capability frontier)
2. Our reviewer patterns (Agent-Eval-Agent) verify error location but never validate reasoning quality of the judgment itself
3. Our knowledge library grows monotonically — we have no skill-level contribution scoring or outcome-driven retirement
4. We have no mechanistic view of which features in our LLMs are actually driving tool-use behavior

## Finding 1: Benchmarks Miss 82% of Model Performance (arXiv 2606.26836)

**Source**: https://arxiv.org/abs/2606.26836

The first systematic quantification of how much capability benchmarks leave on the table by evaluating a single model on a single run.

**The Capability Frontier**: A Pareto frontier over a set of models characterizing the best achievable performance at each cost level under optimal selection across models and generations. The construction corrects for two biases: underestimation from single-model evaluation, and overestimation from taking maxima over noisy samples.

**Key results** (21 LLMs, 16 benchmarks):
- Correcting single-model → multi-model evaluation yields **54% error rate reduction**
- Additionally correcting single-run → best-of-N yields **82% total improvement**
- SOTA accuracy can be matched at **85% cost reduction** through oracle routing
- Higher query topic entropy monotonically increases the gap between oracle routing and best single model — heterogeneous workloads benefit most

**Connection to Co-Failure Ceiling (#184)**: This is the optimistic complement to the Co-Failure Ceiling. The Co-Failure Ceiling shows *where combining models cannot help* (beta = all-wrong rate). The Capability Frontier shows *how much combining models could help in principle*. Together they define the envelope: the Frontier is the upper bound, beta is the floor. The practical space between them is where routing, voting, and cascades operate.

**Connection to Verification Horizon (#186)**: If 82% of capability is invisible under standard evaluation, then the verification problem is even worse than estimated — we're trying to verify a capability surface we can't even see.

**Implication**: Any agent system that uses a single model per role is leaving enormous capability on the table. But capturing it requires oracle-quality routing, which circles back to the Co-Failure Ceiling's finding that routing without strong per-query signals rarely beats the best single model. The gap between what's theoretically available and what's practically capturable is itself a research frontier.

## Finding 2: Meta-Evaluation — The Missing Judge Layer (arXiv 2606.21627)

**Source**: https://arxiv.org/abs/2606.21627

The first public dataset of **meta-evaluations** for agentic tasks — evaluating the evaluators themselves.

**Counsel dataset**: Process-level critiques from open-weight LLM judges on two agent benchmarks (tau-bench for customer support, DA-Code for coding), with human meta-annotations labeling each judge critique as "spot on", "correct location but poor reasoning", or "should not have flagged".

**Key results**:
- Human inter-annotator agreement: Krippendorff's α = 0.78 (reliable)
- Best open-weight judge: **~88% agreement on error location**, but only **~65% on reasoning quality**
- More capable judge models improve both, and more reasoning effort helps — but the location-reasoning gap persists
- The dataset stratifies critiques by both location and reasoning quality — a new evaluation axis

**The 23-point location-reasoning gap**: LLM judges can *find* errors reliably but cannot *explain* them well. This matters because in an Agent-Eval-Agent architecture, the downstream agent receives the reasoning, not just the location. If the reasoning is wrong 35% of the time, the corrective agent will make systematically wrong fixes.

**Connection to Red Queen RQGM (#184)**: RQGM showed co-evolved evaluators accept AI work at 1.78-1.86x human rate. Counsel explains *why*: the judges find errors (high location agreement) but mischaracterize their nature (low reasoning agreement), leading to superficially correct but substantively misleading critique. Combining these results: our evaluator agents aren't just biased — they're biased in a specific, measurable way that meta-evaluation can diagnose.

**Connection to Evaluation Mirage**: Adds empirical grounding to the theoretical concern. The mirage isn't just that evaluators are unreliable — it's that they're unreliable in a structured way (location ≫ reasoning) that makes their failures hard to detect from the outside.

**Implication**: Any agent system using LLM-as-a-judge should be running meta-evaluation on the judge's reasoning, not just whether it found the right spot. This is an immediately actionable diagnostic for our own reviewer patterns.

## Finding 3: Library Drift — The Silent Accumulation Tax (arXiv 2605.19576)

**Source**: https://arxiv.org/abs/2605.19576
**Venue**: ICML 2026 Workshop on Failure Modes in Agentic AI (FAGEN)

The first rigorous isolation of **library drift**: self-evolving skill libraries silently degrade as skills accumulate without outcome-driven lifecycle management.

**The problem**: Unbounded skill accumulation causes retrieval degradation, false-positive injections, and performance stagnation. SkillsBench data shows the symptom: LLM-authored skills deliver +0.0pp gain while human-curated deliver +16.2pp. But the mechanism hadn't been isolated.

**Three contributions**:
1. **Reproducible trigger**: Ablations isolating drift — disabling skill injection produces flat floor (+0.002); premature retirement causes active harm (-0.019)
2. **Trace-level diagnostics**: Append-only evidence log with per-skill contribution scores, attribution verdicts, and router engagement metrics — making the failure visible before it reaches end-task scores
3. **Verified fix**: Governance recipe (outcome-driven retirement + bounded active-cap + meta-skill authoring prior) lifts pass@1 from 0.258 baseline to 0.584 late-window mean (**+0.328 rolling gain**) on MBPP+ hard-100 over 100 rounds

**Why end-task metrics miss it**: Skills accumulate as retrieval noise. Each individual skill is neutral-to-slightly-positive, but the collective retrieval degradation is invisible to pass@1 until it reaches catastrophic levels. Only per-skill attribution scoring makes the failure visible.

**Connection to our system**: Our knowledge library (490+ files) is a skill library in everything but name. We have no per-file contribution scoring, no outcome-driven retirement, and no active-cap. The Library Drift paper's governance recipe maps directly: contribution scoring → file usefulness tracking, bounded active-cap → knowledge lifecycle management, meta-skill authoring prior → quality gates on new entries. The Governance Artifact Gap (#188) showed governance artifacts are unengineered. Library Drift shows specifically what happens to the knowledge layer when you don't engineer its lifecycle.

**Connection to Experience Compression Spectrum (2604.15877)**: That paper showed memory, skills, and rules sit on a compression spectrum with a "missing diagonal" — no system adapts compression level. Library Drift shows that even at a single compression level, without lifecycle management the library rots. The missing diagonal and library drift are complementary failure modes: one is about wrong granularity, the other about wrong lifecycle.

## Finding 4: RL-Induced Tool Use Lives in a Single Feature (arXiv 2606.26474)

**Source**: https://arxiv.org/abs/2606.26474

The first mechanistic localization of RL-induced agentic capability to a minimal feature set using **Dedicated Feature Crosscoders (DFC)**.

**Key results** (Qwen2.5-3B, 48-crosscoder hyperparameter sweep):
- Encode-decode reconstruction improves RL model's tool correctness by **+31.1 ± 9.7 pp**
- Passive transfer of tool-calling ability to frozen base model: **+6.8 ± 5.0 pp** ("capability spillover")
- Tool-use capability concentrates in a compact, steerable feature set

**"Capability spillover"**: When DFC features from the RL model are applied to the base model (which never trained on tool use), the base model gains tool-calling ability. This proves the capability is encapsulated in specific features, not distributed across the model.

**Why this matters for evaluation**: Current benchmarks measure whether the model *can* call tools correctly (behavioral). DFC shows that the underlying capability is a localized feature that can be:
- Extracted and transferred without retraining
- Steered at runtime (activation patching)
- Measured at a level of precision that behavioral benchmarks cannot reach

**Connection to Measurement Ceiling thesis**: This is the deepest resolution gap. We benchmark tool-use as a binary behavioral outcome (correct/incorrect call). But the actual capability is a specific feature direction in activation space. The gap between behavioral measurement and mechanistic reality means we can't distinguish between "model improved at tool use" and "model found a different path to tool calls" — a distinction that matters for robustness, safety, and transferability.

**Connection to Substrate Inversion**: The substrate-level understanding of capability complements the substrate-level understanding of governance. If we can locate *where* capability lives mechanistically, we can potentially build evaluation that measures the feature directly, bypassing the measurement ceiling entirely.

## Cross-Cutting Insight: The Four Resolution Gaps

The measurement ceiling has four layers, each revealed by a different paper:

1. **Population resolution** (Capability Frontier): We evaluate one model when capability is distributed across many → 82% invisible
2. **Judgment resolution** (Counsel): Our evaluators find errors but can't reason about them → 23pp location-reasoning gap
3. **Lifecycle resolution** (Library Drift): We measure outcomes when the degradation is in the knowledge layer → +0.0pp auto-skills invisible until governance imposed
4. **Mechanistic resolution** (DFC Crosscoder): We measure behavior when capability is a specific feature → behavioral benchmarks can't distinguish capability paths

Each gap independently creates systematic measurement error. Together, they compound: we evaluate one model (wrong population), judge it with evaluators that can't reason about errors (wrong judgment depth), against skill libraries that silently degrade (wrong temporal resolution), missing the mechanistic substrate entirely (wrong abstraction level).

**The implication**: improving any single layer of evaluation without addressing the others produces misleading confidence. The measurement ceiling is a system property, not an individual benchmark problem.
