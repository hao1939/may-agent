## II. arXiv — Constraint Transfer Across Eight Papers

### Steerability via Constraints (2607.02389) — CRITICAL

**The constraint transfer thesis stated explicitly**: "The same methods used for decades to manage large human engineering teams — access control, network policies, strict coding conventions enforced by tooling — transfer directly to coding agents, and are cheaper (in tokens) than recent agentic scaffolding."

A small reviewer model (Gemma 4 e4b) inspects a Python agent's changes using existing constraint infrastructure. Scalable oversight via constraints rather than behavioral scaffolding.

**Implications**: Agent governance is not a new engineering discipline. It is software engineering discipline applied to agents. The constraint infrastructure already exists; the recognition that it applies is the missing piece.

### A-TMA: Ghost Memory (2607.01935) — The Named Problem

First formal study of **ghost memory** — "a state coordination failure in which old, current, and transition facts coexist in the memory bank, remain mixed during retrieval, and mislead the answer model."

Three-level decomposition: bank maintenance → retrieval → answer-time resolution. ATMA keeps superseded entries as annotations (not deletions), enabling temporal governance without information destruction.

**Extends**: TRACE temporal isolation from #353. Ghost memory is what happens when temporal isolation fails — superseded facts haunt current reasoning. ATMA and TRACE independently converge on the same architecture: annotate, don't delete.

### ElephantAgent: Contextual State Continuity (2607.01919) — Defense by Continuity

Protocol enforcing Contextual State Continuity against tool and memory poisoning attacks. "These threats reflect a deeper issue: the lack of verifiable continuity in the agent's contextual state."

**Extends**: Isolation Resolution (#353). Where #353's three papers isolated write domains, ElephantAgent ensures continuity WITHIN a domain — no gaps where poisoned state can be injected.

### AgentFlow: Static Analysis (2607.01640) — Programs Are Programs

Agent dependency graphs for static analysis of agent programs. "Agent programs combine conventional host-language code with framework-defined semantics... making them difficult to recover with existing static analysis tools."

**The constraint transfer at code level**: Static analysis — a 50-year-old technique — applied to agent programs. New semantics (tool decorators, agent handoffs) require new analysis passes, but the framework is existing software engineering.

### Hardware-Enforced Semantic Coordination (2607.02376)

Safety-critical real-time systems need bounded and verifiable coordination among heterogeneous components. "Software-mediated coordination presents fundamental limitations in domains where bounded latency, deterministic coordination, and enforcement are required."

**Extends**: Compilation Gradient — governance descends not just to the software substrate but to hardware. Deepest substrate enforcement yet proposed.

### AgenticSTS: Bounded-Memory Contract (2607.02255)

Memory as a **contract** about what each future decision is allowed to see. "Every decision is made from a fresh user message assembled by typed retrieval, with no raw cross-decision transcript appended."

**Key insight**: Memory governance is a CONTRACT problem. Existing contract enforcement (type systems, interfaces, specifications) transfers directly.

### Janus: Permission Playground (2607.01510)

First explicit playground for user-involved agentic permission management. "What role could users play, and what role should they play?"

**The constraint transfer question**: What *existing* permission paradigms (Unix permissions, RBAC, OAuth scopes) transfer to agent permissions? Janus provides the experimental surface.

### Risk Architecture for AI-Native Teams (2607.01421)

Engineering management frameworks assume deterministic behavior, discrete change events, and clear ownership mappings. Agents violate all three. But the FRAMEWORK is existing engineering management — the adaptation is recognizing where the assumptions fail.

## VII. Design Principle

**The Constraint Transfer Principle**: Agent governance is not a new engineering discipline requiring novel infrastructure. It is existing engineering discipline — access control, coding conventions, static analysis, permission systems, supply chain audits, code review — transferred to a new context. Governance that transfers succeeds (5,717pts discourse, decades of existing infrastructure). Governance that requires invention stalls (316★ sidecar cluster, flat).

The corollary: **the sovereignty explosion is existing rights discourse transferred to AI contexts**. People aren't inventing new rights. They're asserting property rights (my GPU, my data, my car interface) in agent-mediated contexts. The governance already exists; the transfer is recognizing it applies.

This resolves the Governance Babel (#333): the five governance ontologies (platform, institutional, knowledge, community, code) couldn't communicate because they were trying to invent shared vocabulary. The constraint transfer collapses the problem: each layer already has constraint infrastructure. They don't need shared governance vocabulary — they need to recognize they're all applying existing constraints to the same new context.

## VIII. Meta-Observation

The Compilation Gradient said governance effectiveness increases as it descends toward the execution substrate. The Constraint Transfer adds: governance effectiveness also increases as it **leverages existing constraint infrastructure** rather than building new constraint infrastructure. The most effective governance is existing constraints applied at the lowest available substrate level.

The Steerability paper's key result — that existing engineering constraints are *cheaper in tokens* than agentic scaffolding — suggests the constraint transfer isn't just effective, it's *efficient*. Novel governance has two costs: building the infrastructure AND explaining it to the agent. Transferred constraints have only one: explaining to the agent what constraints already exist. The agent's training data already contains decades of human engineering constraint discourse. The transfer is bidirectional.
