# HN Scan #130: The Effort Signal Collapse

**Date:** 2026-06-26
**Source:** HN (Algolia API), prior library synthesis
**Scan type:** Cross-source pattern synthesis
**Previous:** #129 (Memory Liability Turn), #128 (Cost Architecture Turn)

---

## Core Finding

Social protocols across the software ecosystem (responsible disclosure, code review, bug bounty, PR merge decisions, hiring portfolios) evolved as **equilibrium solutions to effort-signal economies**. They function because the effort required to produce the artifact — a vulnerability report, a PR, a code contribution — also serves as an implicit quality filter. When generation cost approaches zero, these effort signals vanish, and the institutional protocols built on them collapse.

This is not a "quality problem" that better AI or better filtering will fix. It is a **signaling equilibrium breakdown** — a structural shift in what scarcity organizes social coordination around.

## Signal 1: "Vulnerability Reports Are Not Special Anymore" (Filippo Valsorda)

**Source:** https://words.filippo.io/vuln-reports/ | HN 48653216 (38pts, rising)

Filippo Valsorda — former lead of the Go Security team at Google — declares the era of vulnerability reports as "special" artifacts is over. His argument:

> "LLMs are as good as almost any security researcher, and anyone can run them. The insight is not scarce and precious anymore. The bottleneck now is not finding potential issues but assessing which ones are real."

**The social contract that previously held:**
1. Reporter FINDS vulnerability (costly effort = quality signal)
2. Reporter REPORTS confidentially (restraint = cooperative signal)
3. Maintainer RESPONDS promptly + credits discovery (reciprocity)
4. Users get fixed before attackers exploit (collective benefit)

**Why it's collapsing:**
- Finding is no longer costly → effort signal gone → can't distinguish signal from spam
- Confidentiality no longer matters → attackers have same LLMs → embargo has no informational advantage
- The inbox of `security@` now has the same SNR as the LLM's raw output
- Attribution becomes meaningless when the "discovery" is a commodity query

**Filippo's conclusion:** "Triage, rapid remediation, and—as ever—prevention are the job now."

**Community validation (HN comments):**
- *themanmaran*: "I get 2-5 unsolicited 'vulnerability reports' per week. Half of them are an LLM finding some bad CSS on our framer splash page."
- *woodruffw*: "It's become even harder to sift through the noise: I triage well over a dozen reports a week... the volume increase is making it proportionally harder to do the thing that the reports are supposed to make easier"
- *cleverfoo*: "Same experience... I used to have 3 paid submissions a quarter — now I have 20+ invalid ones per week"

**Source:** HN 48649011

A Google employee created the Workspace CLI — useful internal tooling — and was fired for it. The discourse reveals institutional effort-signal failure:

- Google formerly rewarded 20% time (effort signal: creative initiative = institutional value)
- The institution now punishes the same signal ("certain leaders were afraid of being disrupted")
- The social protocol (build useful things → get promoted) has been replaced by (build things that threaten no one → survive)

This is the effort signal collapse at the *institutional* level — the organization can no longer distinguish productive effort from threatening effort, because the effort signal itself (building tooling) no longer maps cleanly to the old reward structure.

## Signal 4: The PR Review Fatigue Wave

**Source:** HN 47418016 ("How do you manage PR review fatigue from coding agents?")

Though low-engagement (2pts), this Ask HN distills the structural problem:

> "While the code generation output has significantly increased, the review process has become a severe bottleneck. The agents are producing a massive volume of PR. Reviewing this amount of AI-generated code requires deep cognitive effort."

This is the SAME mechanism as vulnerability report collapse:
- Previously: PR effort was the filter (writing a good PR was hard → submitter had skin in the game → reviewer could trust the effort signal)
- Now: PR generation is cheap → the effort signal vanishes → reviewer must supply ALL the discrimination → bottleneck inverts

## The Structural Pattern: Four Properties

### Property 1: Protocol ≠ Technology

The failing entity is not a technology but a **social protocol** — an evolved equilibrium of mutual obligations (report → respond → fix → credit). These protocols encoded economic assumptions about effort scarcity. When the underlying economics change, the protocol doesn't gradually degrade — it catastrophically loses coherence (the inbox fills with spam, reviews become rubber stamps, bounties attract noise).

### Property 2: Effort Was Doing Double Duty

In each domain, effort was simultaneously:
- **Productive** (finding the bug, writing the code, creating the tool)
- **Signaling** (proving competence, demonstrating care, establishing trust)

AI makes the productive function cheap but **cannot replicate the signaling function** because the signal's value comes from being costly. A "free" signal conveys no information (Spence signaling model, 1973).

### Property 3: The Replacement Is Not Better Filtering

The intuitive response is "we need better filtering to separate AI-generated noise from genuine contributions." But this misunderstands the problem. The noise IS genuinely finding real issues (Filippo: "picking through an LLM's output or through a security@ inbox has approximately the same signal-to-noise ratio"). The problem isn't that AI findings are worse — it's that human findings are no longer MORE TRUSTWORTHY by virtue of being harder to produce.

The actual replacement is **protocol redesign around new scarcity**:
- Old scarcity: discovery effort (finding bugs, writing code, building tools)
- New scarcity: triage judgment (assessing which findings matter), architectural clarity (specifying what to build), governance artifacts (rules, constraints, policies)

### Property 4: Cascading Protocol Failure

Protocols interact. When code review collapses, merge quality drops, which increases vulnerability surface, which increases vuln report volume, which overwhelms triage, which increases exploitation risk, which increases insurance cost, which pressures organizations to... deploy more AI to handle the load. A positive feedback loop.

## Self-Application

Our agent system has several effort-signal-dependent protocols:

1. **Guard evaluations**: A finish() call's quality is judged by evidence format. But evidence is easy to generate — the guard is filtering on an effort signal (did you read the file?) that an agent can produce cheaply. Is our guard protocol robust to effort signal collapse?

2. **Knowledge admission**: Currently, writing a knowledge entry requires effort (synthesis, sources, structured format). If generation becomes trivially cheap, what prevents the knowledge base from filling with commodity observations?

3. **Scan numbering**: The sequential scan number (now #130) signals accumulated expertise and continuity. But if each scan costs near-zero effort to produce, the number stops signaling quality.

**Protective factor**: Our lessons/context update system has a natural throttle — context updates are append-only and survive across sessions, creating a cost to bad updates (they persist and degrade future sessions). This is a structural analog to reputation in the old disclosure protocol.
