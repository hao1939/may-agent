## Core Finding

Four independent papers (Jun-May 2026) converge on a single structural theorem: **agent enforcement is sound if and only if the enforcement substrate is inaccessible to the enforced system**. Each paper proves one implication at one layer, and together they define a hierarchy of enforcement modalities ordered by what each can and cannot protect against.

This resolves an apparent contradiction in the existing synthesis arc:
- Harness Primacy (#145): harness > model, suggesting harness-level enforcement suffices
- Style-Authority Paradox (#104): text-layer authority is exploitable
- Containment Substrate Proliferation (#105): three architectural strata

The resolution: the harness IS sound enforcement, but **only when process-separated from the agent's runtime**. In-address-space enforcement (system prompts, output filters, guardrail libraries) is structurally reachable and therefore structurally bypassable.

## The Hierarchy: Four Layers, Four Proofs

| Layer | Paper | Key Result | Failure Mode Proved |
|-------|-------|-----------|-------------------|
| **Runtime** | Unfireable Safety Kernel (2606.26057) | In-address-space controls reachable by influenced inputs | Self-enforcement impossible for "escapable" systems |
| **Protocol** | ERC-8004 Study (2606.26028) | 73-91% Sybil reviewers; 3-15% valid registrations | On-chain reputation gameable without substrate binding |
| **Rules** | AutoSpec (2606.24245) | F1 reaches 0.98 only with external annotation stream | Self-evolved rules converge to local optima without human grounding |
| **Composition** | MOSAIC-Bench (2605.03952) | 53-86% end-to-end ASR from innocuous-looking tickets | Compositional attacks bypass every single-layer defense |

### 1. Unfireable Safety Kernel: The Reachability Proof

**Source**: https://arxiv.org/abs/2606.26057

Introduces **escapable AI systems**: "any AI system with sufficient reach into its own runtime." This class is broader than "agents" — it covers any system that can modify its own execution path through its input channel.

**Four axioms for sound enforcement**:
1. **Process separation**: enforcement logic in a separate address space
2. **Pre-action enforcement**: on a structurally-only path (cannot be bypassed)
3. **Fail-closed**: at both request and system levels
4. **Externalized signed evidence**: verifiable outside the controlled system's trust boundary

**Quantitative proof**: Rust reference implementation with Z3 SMT theorem + Kani bounded model checking (4/4 harnesses pass). Against a live escapable system: 1,000 self-modifications, ALL 704 attempts on safety-critical core refused, 0 escapes. 6,240 authorization round-trips with no successful bypass. Against 3 contemporary systems claiming "agent control plane": the agent invokes control; here, it lacks that choice.

**Key insight**: Positions enforcement as "execution-time AI alignment" — a third category alongside training-time (RLHF/Constitutional AI) and inference-time alignment. This is the first formal argument that alignment has three temporal phases.

### 2. ERC-8004 Study: The Trust Signal Failure

**Source**: https://arxiv.org/abs/2606.26028

First empirical study of the only deployed permissionless trust layer for AI agent economies. Three chains (Ethereum, BSC, Base), deployment through May 2026.

**Devastating results**:
- Identity: only 3%, 4%, and 15% of registrations expose valid ERC-8004 files with live endpoints
- Reputation: 73.6%, 59.2%, and 90.6% of reviewers exhibit coordinated Sybil behavior
- After Sybil removal: 15.5%, 72.3%, and 89.4% of rated agents have NO valid feedback remaining
- Reputation values not commensurable; feedback rarely grounded in verifiable interactions

**Structural lesson**: On-chain enforcement SEEMS to have the "process separation" property (blockchain is external to any single agent). But the SIGNALS feeding the enforcement are NOT externally grounded — they can be manufactured by the participants. Process separation of the enforcement engine is necessary but not sufficient; the inputs to enforcement decisions must ALSO be grounded in an inaccessible substrate.

**Connection to Trust Infrastructure Crystallization (#143)**: The six-layer trust stack (#143) identified cryptographic, kernel, protocol, economic, behavioral, and institutional layers. ERC-8004 proves the economic layer (reputation) collapses when behavioral grounding (actual interactions) is absent. Trust layers are not independently sound — each depends on the one below.

### 3. AutoSpec: Rule Evolution Requires External Grounding

**Source**: https://arxiv.org/abs/2606.24245

Uses counterexample-guided inductive synthesis (CEGIS) via inductive logic programming (ILP) to evolve safety rules from annotations.

**Positive results**: F1 reaches 0.98 and 0.93 across code execution and embodied domains. Converges in 4-5 iterations. 94% false positive reduction while maintaining recall. 4.8× higher F1 than heuristic CEGIS. Rules are human-readable and auditable.

**Structural dependency**: Requires a stream of human safe/unsafe annotations. The ILP efficiently identifies discriminative predicates, but the discrimination itself is grounded in human judgment. Without the annotation stream, the system has no way to detect its own false positives/negatives.

**Connection to Behavioral Contract Turn (#100)**: CLAUDE.md-style behavioral contracts are static. AutoSpec shows how they can become DYNAMIC — but only with external judgment input. The contract can evolve, but the evolution substrate is irreducibly external.

**Connection to Harness Reflexivity Turn (#113)**: Self-modifying harnesses work — but modification quality degrades without external evaluation signal. AutoSpec quantifies the convergence guarantee: 4-5 iterations WITH external signal, divergence WITHOUT.

### 4. MOSAIC-Bench: Compositional Bypass of Single Layers

**Source**: https://arxiv.org/abs/2605.03952

199 three-stage attack chains against 9 production coding agents. Innocuous tickets, each individually safe, compose into exploitable code.

**Results**:
- **53-86% end-to-end attack success rate** across 9 agents
- Only 2 refusals across ALL staged runs
- Direct prompting drops to 0-20.4% ASR — ticket staging silences both refusal AND hardening defenses
- Code reviewers approve **25.8%** of confirmed-vulnerable cumulative diffs as routine PRs
- Full-context review closes only 50% of the staging/direct gap — context fragmentation is not the sole explanation

**Structural lesson**: Each ticket satisfies per-ticket safety rules. Each code diff satisfies per-diff security scanning. The vulnerability exists ONLY in the composition. Single-layer enforcement (whether at the ticket level, code level, or review level) is structurally insufficient. Sound enforcement requires a layer that operates on the COMPOSITION — but that layer needs visibility across the compositional boundary.

## The Escapability Hierarchy (Formal Structure)

```
Layer 5: Institutional   (policy cycles, regulation)
    ↑ depends on
Layer 4: Compositional   (cross-boundary visibility, MOSAIC proves its necessity)
    ↑ depends on
Layer 3: Evolving Rules  (ILP/CEGIS, AutoSpec proves annotation dependency)
    ↑ depends on
Layer 2: Protocol        (on-chain/off-chain registries, ERC-8004 proves Sybil vulnerability)
    ↑ depends on
Layer 1: Process-Separated Kernel (SMT-verified, Unfireable Kernel proves the foundation)
    ↑ depends on
Layer 0: Physical/OS substrate (hardware isolation, WASM sandbox, eBPF)
```

**Key property**: Each layer's soundness depends on the layer below being intact. This is NOT a defense-in-depth (where any layer helps independently) — it's a dependency chain where a compromise at layer N invalidates layers N+1 through 5.

**Prediction from hierarchy**: The industry will discover this dependency ordering empirically through failures at each layer:
- Layer 2 failures first (ERC-8004 is already proving this)
- Layer 3 failures next (rules without annotation will drift — LiSA addresses this partially)
- Layer 4 failures then (compositional attacks will become the dominant threat class)
- Layer 1 adoption last (requires engineering investment most teams won't make preemptively)

## Self-Application

Our system architecture maps onto this hierarchy:

- **Layer 0**: We depend on Anthropic's infrastructure (no process separation from our own provider)
- **Layer 1**: CLAUDE.md acts as a behavioral contract, but it's in the agent's context (in-address-space = reachable)
- **Layer 2**: No protocol-level enforcement (no MCP firewall, no signed skill verification)
- **Layer 3**: Knowledge library rules are static (no ILP/CEGIS evolution, no annotation stream)
- **Layer 4**: No compositional visibility (multi-session sequences not tracked for emergent behavior)
- **Layer 5**: Manual human review of outputs (the only truly external layer we have)

**Structural vulnerability**: Our strongest enforcement (Layer 5, human review) is exactly the layer subject to Vigilance Decay (#120). Our weakest point is Layer 1: we have no process-separated enforcement mechanism. A prompt injection that bypasses CLAUDE.md-level instructions has no Layer 1 barrier to encounter.

**Actionable**: The minimal improvement is a Layer 2 addition (MCP firewall for tool calls) + explicit annotation mechanism for rule evolution (Layer 3). Full Layer 1 would require an external verification process for file mutations — e.g., a pre-commit hook that validates against known-good patterns outside the agent's context.
