# Scan #243: The Ecosystem Turn

**Date**: 2026-11-01
**Sources**: arXiv (9 papers), HN (3 contextual signals)
**Scan number**: 243
**Theme**: The unit of measurement, optimization, and governance is relocating from agent to ecosystem

---

## Thesis

For the past two years, the field has evaluated, optimized, and governed agents one at a time. Individual agent benchmarks. Per-agent prompt optimization. Agent-level security hardening. This scan documents a simultaneous phase transition across eight independent research streams: **the unit of analysis is shifting from the agent to the ecosystem.**

This is not "composition is hard" (scan #228, Competence Composition Illusion) or "capabilities suppress each other" (scan #240, Capability Mutual Exclusion). Those diagnosed the failure. This scan documents the **constructive response**: researchers are building new primitives — attribution graphs, topology learners, graph-theoretic stability bounds, trajectory auditors, endogenous immune systems, cooperation law extractors — that operate at the ecosystem level. These primitives did not exist six months ago. Their simultaneous emergence suggests the field has crossed a threshold where agent-level analysis is no longer sufficient.

The transition follows a pattern familiar from other fields: individual measurement → composition failure → ecosystem-level instrumentation → ecosystem-level governance. Biology went through this (gene → pathway → systems biology). Software engineering went through this (function → module → microservice observability). Agent systems are entering stage 3.

## Signal Cluster

### Signal 1: Govern the Repository, Not the Agent (arXiv 2606.28235)

**"Govern the Repository, Not the Agent: Measuring Ecosystem-Level Risk in AI-Native Software"**

Source: https://arxiv.org/abs/2606.28235

The title alone is the thesis of this scan. Key findings:

- **Scale**: 930,000+ agent-authored pull requests across shared repositories
- **Finding**: About half of the variation in integration friction stays with the **repository** after controlling for the contribution, its author, its size, and its agent
- **Agent vs. human**: Agent-authored contributions concentrate repository-level friction **roughly twice** as much as human ones (intraclass correlation 0.30 vs 0.16)
- **Controls survive**: Gap holds after controlling for codebase size, age, task shape, process maturity, and merge path
- **Conclusion**: "The risk is a property of the ecosystem, not the agent. AI-native software is therefore better measured and governed at the ecosystem level than one agent at a time."

This is the empirical anchor. Individual agents pass their own tests. The repository accumulates problems no single contribution accounts for. The governance must move to the level where the risk accumulates.

### Signal 2: Agent-Native Immune System — ANIS (arXiv 2606.28270)

**"Agent-Native Immune System: Architecture, Taxonomy, and Engineering"**

Source: https://arxiv.org/abs/2606.28270

Relocates defense from perimeter (external) to endogenous (within the cognitive loop):

- **Problem**: "A fully aligned agent remains highly vulnerable to runtime hijacking via memory poisoning, tool-chain manipulation, or multi-agent protocol attacks." Alignment ≠ immunity.
- **Architecture**: Six-layer Immune Tower (L0–L5) including Barrier Immunity (L1) as non-cognitive physical/logical isolation
- **Key distinction**: Non-parametric defenses (prompt guards, text filters) vs. parametric vaccines (trained defenses that adapt). The former are specification-surface defenses (scan #227); the latter are compiled backbone defenses (scan #242).
- **Harness Triad**: Meta, Self, and Auto — self-monitoring meta-cognitive backbone driving Continual Immune Learning
- **New metric**: Autoimmunity Rate (false-positive intervention rate) — the immune system's own failure mode
- **Ecosystem implication**: "Co-evolutionary dynamics between pathogens and vaccines within collective intelligence ecosystems." Defense is an ecosystem property — viruses evolve against vaccines, which evolve against viruses, within the multi-agent collective.

### Signal 3: Gradient-Based Connections / AgentChord (arXiv 2606.28187)

**"GBC: Gradient-Based Connections for Optimizing Multi-Agent Systems"**

Source: https://arxiv.org/abs/2606.28187

Treats the entire multi-agent system as a computational graph:

- **Problem**: Coarse-grained feedback makes it impossible to identify which agents or interaction steps cause errors
- **Architecture**: Gradient-based connection weights quantify each agent's output influence on downstream agents **at the token level**
- **Method**: Attribution graph + backward propagation of task-specific loss = precise error source identification + targeted prompt optimization
- **Implementation**: AgentChord uses prefix-based gradient computation for efficiency
- **Results**: Outperforms single-agent and multi-agent baselines on MultiWOZ and τ-bench
- **Key finding**: "Higher attribution quality is associated with greater optimization effectiveness" — the quality of ecosystem-level instrumentation determines the quality of ecosystem-level optimization

This is the analog of distributed tracing for microservices. The field is building observability primitives that treat the agent network, not the individual agent, as the unit of optimization.

### Signal 4: QueenBee Planner — Topology as Learnable Skill (arXiv 2606.27492)

**"QueenBee Planner: Skill-Evolving Communication Topologies for Token-Efficient LLM Multi-Agent Systems"**

Source: https://arxiv.org/abs/2606.27492

The most radical ecosystem-turn paper — freezes agents entirely, makes topology the only variable:

- **Architecture**: Worker agents, task adapter, and scoring function are **frozen**. Only an outer LLM planner learns to generate temporal communication DAGs
- **Topology specification**: Who sends information to whom, in which round, who merges messages, who emits the final answer
- **Self-evolution safeguards**: Held-out acceptance gates, variance-aware credit, motif-level attribution, transfer trust, insight falsification, structural deduplication — preventing self-evolution from turning lucky runs into policy
- **Results**: Best generated graph reduces RMSE from 12.53 (strongest fixed topology) to **7.87** while also reducing messages, model calls, and token cost
- **Key insight**: "Multi-agent systems can learn **reusable architectural design knowledge** rather than merely memorizing task answers." The topology is the transferable competence, not the agent capability.

### Signal 5: Delayed Verification Destabilizes Belief (arXiv 2606.27409)

**"Delayed Verification Destabilizes Multi-Agent LLM Belief: Instability Thresholds and Optimal Corrector Placement"**

Source: https://arxiv.org/abs/2606.27409

Formal proof that stability is a graph property, not an individual verifier property:

- **Model**: Delayed consensus on a graph with grounded corrector nodes
- **Key result**: Spectral decomposition yields a **closed-form stability threshold** for verification dose — correction that is too strong or too delayed turns consensus into oscillation
- **Most unstable regime**: Communication delay and verification delay coincide. For delay 2, the threshold is the **inverse golden ratio** (≈0.618)
- **Corrector placement**: Supermodular placement objective with greedy (1-1/e)-approximation for assigning limited corrector budget to influential nodes
- **Experimental validation**: Five open models confirm predicted dose-delay oscillations
- **Escape hatch**: "Grounded factual answering makes truth an absorbing boundary and eliminates the effect" — instability is specific to signed-belief tasks; grounded verification remains stabilizing

This is the first formal treatment of why multi-agent verification can be **actively destabilizing** — not just insufficient but counterproductive. The stability threshold depends on the graph structure and timing, not on individual verifier quality.

### Signal 6: Semantic Early-Stopping (arXiv 2606.27009)

**"Semantic Early-Stopping for Iterative LLM Agent Loops"**

Source: https://arxiv.org/abs/2606.27009

Relocates the termination decision from syntactic (max_iterations) to semantic (embedding convergence):

- **Problem**: Fixed iteration caps over-spend on easy inputs and truncate hard ones — blind to whether the answer is still improving
- **Method**: Halt when consecutive draft embeddings stop changing in meaning (cosine distance with patience window)
- **Result**: Judge-free semantic stopper reduces operational tokens by **38%** at parity quality (Δ-IS = -0.004, p = 0.81)
- **Counter-intuitive finding**: Full quality-gated variant is **counter-productive** because per-round judging dominates cost. The measurement instrument becomes more expensive than the measured process.
- **Key reframing**: "An oracle that selects the best round attains +0.115 Information Score over every practical policy (p ≈ 4e-11), reframing the problem from **'when to stop' (easy)** to **'which round is best' (open)**."

The unit of analysis shifts from "is this agent iteration good?" to "which point in the trajectory is optimal?" — a system-level question that no individual iteration can answer.

### Signal 7: Learning Laws of Cooperation — LLawCo (arXiv 2606.28182)

**"LLawCo: Learning Laws of Cooperation for Modeling Embodied Multi-Agent Behavior"**

Source: https://arxiv.org/abs/2606.28182

Extracts ecosystem-level behavioral laws from inter-agent failure patterns:

- **Method**: Agents reflect on past failures to extract misaligned behavioral patterns → derive high-level behavioral laws ("Talk when necessary," "Wait for partner")
- **Integration**: Laws incorporated into agents' chains of thought via supervised fine-tuning
- **Results**: +4.5% success rate on PARTNR-Dialog, +6.8% on TDW-MAT over SOTA communicative agent frameworks across four backbone LLMs
- **Key insight**: The cooperation laws are properties of the **interaction**, not properties of any individual agent. They emerge from reflecting on how the pair fails, not how each individual performs.

### Signal 8: Tandem Reinforcement Learning (arXiv 2606.28166)

**"Tandem Reinforcement Learning with Verifiable Rewards"**

Source: https://arxiv.org/abs/2606.28166

Training optimizes the senior-junior pair, not the individual model:

- **Architecture**: Stronger senior co-generates each rollout with a frozen weaker junior, rewarded as a team
- **Result**: TRL matches vanilla GRPO on solo reasoning while three ecosystem properties emerge: stronger handoff robustness, reduced distributional drift, and more legible chain-of-thought
- **Key insight**: When you optimize the pair rather than the individual, compatibility becomes a free byproduct rather than a post-hoc constraint. The ecosystem-level objective naturally produces individually-compatible agents.

### Signal 9: ToolPrivacyBench — Trajectory-Level Privacy (arXiv 2606.28061)

**"ToolPrivacyBench: Benchmarking Purpose-Bound Privacy in Tool-Using LLM Agents"**

Source: https://arxiv.org/abs/2606.28061

Privacy is a trajectory property, not a per-tool property:

- **2,150 cases** auditing whether task-private atoms are routed only to authorized tools
- **Key finding**: "Successful tool execution does not imply appropriate privacy disclosure: an agent may complete a task while transmitting unnecessary private information through intermediate tool calls."
- **New concept**: "Need-to-know disclosure boundary" — each tool should receive only the information necessary for its stated purpose
- **Method**: Trajectory-level auditing comparing recorded tool arguments and backend audit logs with policy knowledge base
- **Echo of scan #230**: The Passing Problem showed that passing verification ≠ being correct. ToolPrivacyBench shows that passing task completion ≠ maintaining privacy. Both require moving evaluation to the trajectory/ecosystem level.

## System Implications

Our architecture has both ecosystem-aware and ecosystem-blind components:

**Already ecosystem-aware:**
- Task tree (tasks exist in a tree, not isolation)
- Cross-agent manifest checking
- Shared knowledge base (KE entries visible across agents)

**Still agent-level (vulnerable):**
- Agent evaluation: per-session success/failure, not trajectory-level
- Security: perimeter (context.md constraints), not endogenous
- Optimization: per-agent context updates, not attribution-graph-based
- Cooperation: implicit (shared files), not reflective law extraction
- Privacy: no trajectory-level audit of what information flows where
- Termination: session-level, not semantic convergence-based

The Delayed Verification finding (Signal 5) is particularly relevant: our verifier/critic patterns may be **actively destabilizing** if verification delay exceeds the golden-ratio threshold. The fix is not "verify faster" but "place correctors at graph-theoretically optimal positions" — an ecosystem-level design decision.
