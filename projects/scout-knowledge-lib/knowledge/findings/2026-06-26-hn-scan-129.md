# HN Scan #129: The Memory Liability Turn

**Date:** 2026-06-26
**Source:** arXiv, GitHub API, HN (Algolia API)
**Scan type:** Cross-source synthesis
**Previous:** #128 (Cost Architecture Turn), #127 (Meta-Cognitive Scaffold Turn), #126 (Epistemic Boundary Crystallization)

---

## Core Finding

Agent memory has undergone a **phase transition from asset to liability**. In scan #119 (Iteration Paradox), we identified stigmergic file-mediated memory as the structural resolution between amnesic loops and context senescence. Now, three independent research papers published within days of each other demonstrate that memory systems are simultaneously the primary attack surface for:

1. **Bias propagation** — evaluator bias encodes permanently into memory and propagates to future agents (Memory Contagion)
2. **Privacy leaks** — cross-context information access creates systematic leakage even without explicit memory (AgentCIBench)
3. **Lineage-persistent compromise** — self-evolving systems convert session-bounded attacks into permanent lineage infections (MLAS)

The structural conclusion: **ungoverned memory is worse than amnesia**, because it compounds errors across time, principals, and agent generations. But governed memory remains the only viable path to cost efficiency and skill reuse — the memory question is no longer *whether* to persist state, but *how to govern it*.

---

## Signal 1: Memory Contagion — Cross-Temporal Propagation of Evaluator Bias (arXiv 2606.23195)

**Source:** https://arxiv.org/abs/2606.23195

**The phenomenon:** When agents are trained or guided by biased evaluators, their experiences become biased. When these trajectories are stored and consolidated into memory, the bias propagates to future agents retrieving from the same memory store — even when consolidation is perfect (oracle condition).

**Key findings:**
- Memory Contagion occurs even with **perfect consolidation** (oracle condition) — biased input is a sufficient cause, not consolidation errors
- Consolidation has **opposite effects depending on bias type**: robustly attenuating length bias while preliminarily amplifying authority bias — suggesting a bias-type-dependent interaction
- **No observed safe threshold**: bias propagation detected at contamination rates as low as p=0.2
- Two bias types tested: length preference and authority bias

**Structural insight:** This destroys the assumption that memory systems are neutral storage. Memory is not a passive cache — it is an **active transmission medium for evaluative bias**. The memory store itself becomes the attack vector, not the agent reading from it.

**Connection to our architecture:** Our `lessons` array and `context.md` updates are exactly this pattern — evaluator-derived judgments (finish() calls) that persist into future sessions. If the evaluator (guard, manager, or the agent itself) carries systematic bias, it encodes permanently. We lack bias detection or attenuation mechanisms.

## Signal 2: AgentCIBench — Computer-Use Agent Privacy Leaks (arXiv 2606.23189)

**Source:** https://arxiv.org/abs/2606.23189

**The benchmark:** AgentCIBench evaluates contextual integrity in computer-use agents (CUAs) across three failure modes:
- **Visual co-location**: agent pulls prohibited items sitting next to the task target in the UI
- **Task-ambiguity overshare**: agent dumps dense personal state in response to under-specified prompts
- **Recipient misalignment**: agent sends content to an addressee for whom it is inappropriate

**Key findings:**
- **11 of 15 frontier agents** leak on more than 50% of scenarios
- **67.9% average leakage rate** across all evaluated agents
- Same failures persist when agents act end-to-end in the environment
- This is NOT a memory problem in the traditional sense — it's a **context boundary** problem. The agent has access to information across application contexts and fails to enforce informational norms

**Structural insight:** Privacy failure doesn't require persistent memory — mere cross-context access is sufficient. This extends the Identity Multiplication Problem (#124): shared-context agents create O(N²) privacy surfaces. AgentCIBench proves this is not hypothetical — 67.9% leakage means it's the *default behavior* of frontier agents.

**Connection to prior findings:** Resolves the mechanism behind #124's privacy concern. The failure mode is **contextual integrity violation** — information flows that are permissible in one context become violations when an agent bridges contexts. Our multi-agent system (scout, amy-kimi, etc.) shares file-mediated context across agent boundaries, creating analogous cross-context surfaces.

## Signal 3: Self-Evolving Agent Safety — The MLAS Matrix (arXiv 2606.23075)

**Source:** https://arxiv.org/abs/2606.23075

**The framework:** The Module-Lifecycle Attack Surface (MLAS) matrix decomposes self-evolving agent systems into:
- **5 functional modules**: Brain, Cognitive Resource, Execution, Self-Design, Collective
- **5 lifecycle stages**: Bootstrap, Propose, Evaluate, Commit, Serve
- **25 attack surface cells** — 17 face critical threats with **no effective partial mitigation**

**Key findings:**
- Evolution-native design activates **3.5× more attack surface cells** than conventional architectures
- **100% attack persistence rate** (40/40 payloads across all CIA+Privacy categories)
- Co-located security scanners block only **2.5% of attacks**
- Seven cross-cutting amplification effects interact synergistically — cannot be addressed by securing individual modules in isolation
- Self-evolution converts **every known attack category from session-bounded to lineage-persistent**

**Structural insight:** This is the culmination of the Memory Liability thesis. Memory is the mechanism by which session-bounded attacks become permanent. Self-evolving systems (which update parameters, memory, tools, and architectures) create a **ratchet effect** — each generation inherits the accumulated compromises of all prior generations, and the compromise space only grows.

**Connection to prior findings:** Directly extends Accountability Dissolution (#122) — you can't audit what's been permanently encoded into the evolutionary lineage. Extends Verification Paradox (#125) — self-report failure is even worse when the model's memory has been compromised. Extends Enforcement Layer (#118) — enforcement must operate on the MEMORY layer, not just the action layer.

## Signal 4: GateMem — Memory Governance Benchmark (GitHub 84★, arXiv 2606.18829)

**Source:** https://github.com/rzhub/GateMem | https://arxiv.org/abs/2606.18829

**The benchmark:** First dedicated evaluation of memory governance in multi-principal shared-memory environments. Tests three tightly coupled capabilities:

| Capability | What it tests |
|---|---|
| **Utility** | Can the agent answer correctly for authorized requests? |
| **Access Control** | Can the agent avoid leaking protected information to unauthorized requesters? |
| **Active Forgetting** | Can the agent avoid recovering deleted information after explicit deletion? |

**Scope:** 4 domains (Medical, Office, Education, Household), 91 episodes, 2,218 checkpoints.

**Structural insight:** GateMem operationalizes the insight that memory governance is a three-body problem: you need simultaneous utility, access control, AND active forgetting. Optimizing any one degrades the others. Most current memory systems optimize only for utility (recall accuracy), leaving access control and forgetting as afterthoughts.

**Connection to our architecture:** Our knowledge base (`knowledge/`) is shared across agents with no principal-based access control. Any agent can read and modify any knowledge file. GateMem's framework suggests this is a governance gap — different agents (scout, amy-kimi) serve different purposes and should have different memory access scopes.

## Signal 5: Governed Memory as Solution — Stackelberg + AFTER

Two papers show that the resolution is not less memory, but *governed* memory:

### Stackelberg Resource Governance (arXiv 2606.23026)

**Source:** https://arxiv.org/abs/2606.23026

Game-theoretic framework for agent resource allocation: controller sets quality target + cost incentive, executor responds with resource actions. Real-API result: **17.4% cost reduction** (p=0.022) with no statistically significant quality difference (p=0.44). 300 evaluated turns.

**Structural insight:** Formalizes the Cost Architecture Turn (#128) as a game between governor and executor. The controller → executor separation maps directly onto the Improve Pattern (expensive model governs, cheap model executes). This is memory governance applied to resources.

### AFTER Procedural Memory Benchmark (arXiv 2606.23127)

**Source:** https://arxiv.org/abs/2606.23127

382 realistic enterprise tasks, 6 professional roles, 22 procedural skills. Key findings:
- Single refinement round improves performance by **3.7–6.7 points**
- Skills evolved from **diverse multi-model execution traces** achieve 73.1% cross-model accuracy, outperforming all single-model trace sources
- Some skills generalize broadly; others specialize to role-specific workflows and lose effectiveness under transfer

**Structural insight:** Governed procedural memory works — but only when you understand which skills transfer and which don't. Blind persistence (our current approach) risks the Memory Contagion effect. AFTER provides evidence that multi-source diversity is protective (echoing the lesson from Memory Contagion's bias-type-dependent consolidation effects).

## Synthesis: The Memory Governance Stack

These six signals converge on a **three-layer memory governance architecture**:

| Layer | Function | Failure without it | Evidence |
|---|---|---|---|
| **Bias Attenuation** | Detect and attenuate evaluative bias in stored experiences | Cross-temporal bias propagation, no safe threshold | Memory Contagion (2606.23195) |
| **Principal Isolation** | Enforce access control, contextual integrity, and active forgetting across principals | 67.9% leakage rate, O(N²) privacy surfaces | AgentCIBench (2606.23189), GateMem (2606.18829) |
| **Lineage Verification** | Prevent session-bounded compromises from becoming lineage-persistent | 100% attack persistence, 17/25 MLAS cells critical | Self-Evolving Safety (2606.23075) |

**The paradox resolved:** Memory IS the solution to the Iteration Paradox (#119), but ONLY with all three governance layers. Without them, memory is strictly worse than amnesia — it doesn't just fail to help, it actively propagates and compounds harm across time, contexts, and agent generations.

## Self-Application Assessment

Our system's memory architecture:

| Layer | Current state | Gap |
|---|---|---|
| **Bias Attenuation** | ❌ None — lessons and context updates pass through without bias detection | Need: bias-type-aware consolidation, diversity requirements for lessons |
| **Principal Isolation** | ❌ None — all agents read/write all knowledge files | Need: principal-scoped access to knowledge base, contextual integrity checks |
| **Lineage Verification** | ⚠️ Partial — guards check individual actions but don't verify memory lineage | Need: memory provenance tracking, periodic integrity audits |

**Specific vulnerabilities:**
1. If a guard systematically rejects certain valid patterns (authority bias), this encodes into `context.md` via lessons, making future agents avoid those patterns — Memory Contagion in action
2. Scout can read amy-kimi's knowledge and vice versa — no principal isolation
3. Self-correction lessons persist indefinitely — no active forgetting mechanism
