## II. The Skill Quality Crisis: Five Papers, One Diagnosis

### Thesis

The agent skill ecosystem has crossed the threshold from "emerging reuse mechanism" to "software supply chain" — but without the hygiene infrastructure (linters, SBOMs, update policies, behavioral contracts) that took the npm/PyPI ecosystems a decade to develop. Five papers independently characterize different facets of the same crisis:

### Paper 1: Skill Smells (2607.01456) — The Hygiene Gap

**"From Anatomy to Smells: An Empirical Study of SKILL.md in Agent Skills"**
Hong, Imani, Ahmed (UC Irvine)

Source: https://arxiv.org/abs/2607.01456

- First systematic study treating SKILL.md files as **software artifacts** rather than documentation
- Analyzed 238 real-world skills → taxonomy of 13 higher-level, 44 lower-level semantic components
- Multivocal literature review of 29 sources → best-practice codification
- Introduced **"skill smells"** — violations of authoring best practices (analogous to code smells)
- Critical finding: **over 99% of SKILL.md files contain at least one skill smell**
- Once introduced, skill smells **rarely disappear as skills evolve** — they calcify
- Gap between recommended and actual practices is enormous and widening

**Implication**: The skill ecosystem lacks the equivalent of ESLint/Pylint. Quality problems are baked in at authorship and persist through the entire lifecycle. The 99% figure means quality tooling is not optional — it's table stakes for a trustworthy skill ecosystem.

### Paper 2: Scanner Evasion (2607.02357) — The Defense Failure

**"Cloak and Detonate: Scanner Evasion and Dynamic Detection of Agent Skill Malware"**
Ji, Xu, Li, Gao, Wei, Wang, Cheung (HKUST)

Source: https://arxiv.org/abs/2607.02357

- **SkillCloak**: payload-preserving evasion framework (attack semantics intact, appearance changed)
- Two strategies: Structural Obfuscation (semantically equivalent rewrites) + Self-Extracting Skill Packing (hide payload from install-time view, restore at execution)
- Tested against **8 scanners** on **1,613 in-the-wild malicious skills**
- SFS Packing: **bypasses every scanner at >90%**
- Structural Obfuscation: **>80% bypass on most static scanners, 96% on hybrid scanner**
- Proposed **SkillDetonate**: behavior-centric runtime auditor using OS-boundary taint analysis
- SkillDetonate: **97% detection at 2% FPR**, sustains 87% on real-world malicious skills

**Implication**: Static skill scanning is security theater. The only viable defense operates at runtime, observing actual behavior rather than inspecting install-time artifacts. This parallels the broader Verification Substrate thesis (#377) — you must verify what actually happens, not what appears to be present.

### Paper 3: Dependency Opacity (2607.01136) — The Hidden Graph

**"Skills Are Not Islands: Measuring Dependency and Risk in Agent Skill Supply Chains"**
(Previously noted in #375 and #378, now connected to the full skill quality picture)

Source: https://arxiv.org/abs/2607.01136

- Introduced Agent Skill Supply Chains (ASSCs) — formal model of skill→package→service dependency graphs
- SkillDepAnalyzer over **1.43 million skills**
- Four structural patterns identified:
  1. Metadata is activation-ready but **governance-poor**
  2. Dependency graphs span three layers with **concentrated reuse**
  3. Recursive skill reuse creates **hidden package inventory**
  4. Skill dependency clusters form around related workflows
- Inspecting a skill alone **misses security signals hiding in its dependencies**
- Found and reported **known malicious skills persisting** in supply chains

### Paper 4: Reuse Without Maintenance (2607.00911) — The Stale Contract

**"From Registry to Repository: How AI Agent Skills Are Written, Adapted, and Maintained"**
(Previously noted in #375, now integrated into crisis framing)

Source: https://arxiv.org/abs/2607.00911

- Mined 18,463 registry skills + 23,199 personal-use skills from 5,876 GitHub repos
- **53% of reused skills are never modified** after adoption
- Subsequent local maintenance is overwhelmingly additive — no refactoring
- **Behavioral contracts remain almost untouched** — how a skill interacts, monitors, and recovers from failures stays frozen at creation time
- The skill layer copies but doesn't evolve — it's adoption without maintenance

### Paper 5: Accidental Success (2607.01874) — The Evaluation Blindness

**"SkillCoach: Self-Evolving Rubrics for Evaluating and Enhancing Agentic Skill-Use"**

Source: https://arxiv.org/abs/2607.01874

- Skills in realistic repositories are **overlapping** — selection is harder than it appears
- Final-verifier success is **too coarse**: agents pass through trial-and-error while selecting wrong skills, skipping steps, composing incorrectly
- SkillCoach evaluates along 4 dimensions: skill selection, skill following, skill composition, skill-grounded reflection
- Evolved rubrics **expose failures hidden by final accuracy** — accidental task success masks process failures
- Outcome-only evaluation = the Evaluation Mirage applied to skills

**Implication**: Even self-evolving skill systems can't be trusted based on outcome metrics alone. Process supervision is required — you need to know *how* a skill was used, not just *whether* the task succeeded.

### Synthesis: The Four Pathologies

The five papers reveal a single supply-chain failure with four interlocking pathologies:

| Pathology | Evidence | Traditional Analog |
|-----------|----------|-------------------|
| **Quality at birth is terrible** | 99% skill smells, never fixed (2607.01456) | npm packages without linting |
| **Scanning is theater** | >90% evasion of all scanners (2607.02357) | AV signature-based detection |
| **Dependencies are invisible** | 3-layer graphs with hidden inventory (2607.01136) | Pre-lockfile npm |
| **Reuse ≠ maintenance** | 53% never modified, contracts frozen (2607.00911) | Vendored dependencies |

The crisis is structural, not individual. No single paper offers a complete solution, but together they define the problem space precisely enough for engineering response.

## III. Adjacent Signal: Strategy as the Learning Unit

### Mastermind (2607.01764) — Strategy Over Trajectory

**"Mastermind: Strategy-grounded Learning for Repository-Scale Vulnerability Reproduction"**
Du, Tuan, Wu, Liu, Guo, Huang, Ng (NUS, CUHK)

Source: https://arxiv.org/abs/2607.01764

- Argues **strategy, not trajectory**, is the right learning unit for SE agents
- Strategy is: compact enough to optimize, concrete enough to guide execution, stable enough to store and reuse
- Dual-loop framework: trainable planner (SFT + milestone-based GRPO) + task-local experience loop
- Planner trained **independently of executor** — strategy learning improves multiple frozen executors
- Results on CyberGym (260 train / 200 eval tasks):
  - Mastermind + GPT-5.5: **84.5% pass rate**
  - vs. Best-of-8 sampling: 63.0%
  - vs. Iterative improvement: 77.0%
  - vs. Open-book PoC context: 60.0%
- **Cross-model transfer**: same planner improves GPT-5.4 mini (45%→60%) and GLM 5.1 (58.5%→71%)

**Connection to Skill Crisis**: Strategy learning is essentially what skills *should* be — compact, reusable, transferable operational knowledge. But Mastermind's strategies are learned and verified, while marketplace skills are authored once and frozen. The gap between how Mastermind builds strategies (iterative refinement + cross-model validation) and how skills are authored (one-shot, no verification, 99% smell rate) is the quality gap in miniature.

## VI. Meta-Observation

The skill ecosystem is at the same inflection point npm was circa 2016 — massive adoption, minimal quality infrastructure, known-malicious packages persisting, dependencies invisible. The difference: **agent skills execute with the agent's full privileges**, making every quality failure also a security failure. The npm ecosystem took the left-pad incident, the event-stream backdoor, and years of tooling development (lockfiles, audit commands, SBOMs) to reach its current state. The agent skill ecosystem has none of this infrastructure and 10x the attack surface.

The five papers in this scan collectively provide the diagnostic. What's missing is the prescription: automated skill linting (analogous to ESLint), mandatory runtime behavioral auditing (SkillDetonate is a proof of concept), dependency lockfiles for skills, and process-aware evaluation (SkillCoach is a start). The question is whether the ecosystem builds this infrastructure proactively or waits for its own left-pad/event-stream moment.
