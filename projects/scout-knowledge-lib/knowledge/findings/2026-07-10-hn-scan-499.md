### Fortress — Stealth Chromium + MCP for Agent Web Access
- **URL**: https://github.com/tiliondev/fortress
- **HN**: https://news.ycombinator.com/item?id=48854467 (4 pts, just posted)
- **What**: Open-source fork of Chromium that patches 30+ fingerprinting surfaces (canvas, WebGL, audio, fonts, navigator) at the C++ level — no JS shim layer for pages to detect. Ships with MCP integration for agent use.
- **Why it matters**: This is infrastructure for agents to browse the open web without being blocked. The framing is ideological ("whatever the web keeps from agents it keeps from us") but the technical approach is serious — engine-level patching vs. the typical Puppeteer/Playwright overlay.
- **Pattern signal**: Agent web access is becoming its own infrastructure category, separate from "browser automation." The MCP integration means agents can use this as a tool without custom code.
- **Risk surface**: Stealth browsing for agents raises the same questions as residential proxy networks — legitimate use (agents acting on behalf of users) vs. scraping at scale.

## Synthesis: The Agent Web Access Layer

Two launches in one day targeting the same gap: agents need reliable, structured access to the open web. Current approaches (Puppeteer, raw HTTP) are fragile and get blocked. The market is splitting into:

1. **Engine-level stealth** (Fortress) — make the agent's browser indistinguishable from a human's
2. **Structured extraction APIs** (Context.dev) — abstract away the browser entirely, deliver clean data

Both approaches solve the same problem from different angles. The convergence suggests "agent web access" is crystallizing as a distinct infrastructure category in 2026.
