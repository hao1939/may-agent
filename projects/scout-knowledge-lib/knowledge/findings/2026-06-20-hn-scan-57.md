| **frollogaston** | "'Full-surface API' is a feature nobody here has mentioned — dig at how git intentionally has no linkable library?" | Embeddability as differentiator |

### Relevance to Agent Infrastructure

While not directly AI-related, Lore signals an important infrastructure gap being filled:
1. **Agent artifact versioning**: As agents produce non-text outputs (embeddings, compiled rules, model checkpoints), text-oriented VCS breaks. Lore's approach to binary-first, lock-aware versioning is a design template.
2. **"Full-surface API"**: If agent tools need to programmatically version and branch artifacts, a VCS with a proper API (not git's CLI-shell interface) is structurally advantageous.
3. **Scale assumptions**: Perforce dominates where repos are terabytes. Agent systems producing large artifacts (training data, logs, embeddings) face the same scaling constraint.

### Library Connection
- **Agent Operational Memory (existing note)** — The versioning problem for agent state is unsolved. Lore's approach (centralized, lock-aware, binary-first) may be more architecturally appropriate for agent state than git's distributed, text-optimized model.

## Finding 57-5: AMD Memory Encryption Removal — Silent Hardware Trust Erosion (444pts, 209c)

**Signal strength: HIGH** — third highest AI-adjacent story.

AMD silently removed SME (Secure Memory Encryption) from consumer Ryzen CPUs via firmware update, without announcement or documentation.

### Key Positions

| Author | Position |
|--------|----------|
| **thg** | "This was never marketed as a feature of consumer CPUs" — defends AMD |
| **hgoel** | "Pretty crazy that we have this entire segment of features companies artificially restrict from the average person... GPU virtualization is another example" |
| **Integer** | "I had this enabled as it protects against RAMbleed/ECC errors, so it's not limited to physical attacks" |
| **ZiiS** | "If it can be silently removed was it a security feature?" |

### Structural Significance for Agent Systems

1. **Trust verification gap**: If hardware capabilities can be silently removed, agent systems running on "trusted" hardware have no way to verify their security assumptions remain true post-deployment.
2. **Market segmentation → security stratification**: The artificial restriction of security features to "enterprise" hardware means local AI (running on consumer hardware) is systematically less secure than cloud AI (running on enterprise hardware with full memory encryption).
3. **Silent removal pattern**: The *silence* is more concerning than the removal. It demonstrates that hardware vendors can degrade the security posture of deployed systems without notification.

### Library Connection
- **Agent Security/Governance** — New sub-theme: hardware trust assumptions. Agents making security decisions based on hardware capabilities (e.g., "credentials are safe because memory is encrypted") can't trust those assumptions to be stable.
- **The Local Model Revolution** — The local-vs-cloud economic argument gains a security dimension: local hardware has systematically less trustworthy security features than cloud infrastructure.
