# Scan #490: The Hallucination Supply Chain

**Date:** 2026-07-09  
**Source:** arXiv (cs.CR, cs.CL, cs.LG), HN front page, GitHub trending  
**Theme:** Agent ecosystems are vulnerable to supply-chain attacks that exploit hallucination predictability and training-time leverage imbalances — both invisible from aggregate metrics  
**Extends:** Write Refusal (#489), Governance Silence (#478), Skill Paradox (#483), MCP Taint Vulnerabilities (#488), Verification Hierarchy (#479)

---

## The Structural Claim

The Write Refusal (#489) proved that systems unable to refuse action accumulate false commitments. The Hallucination Supply Chain identifies a *weaponized* version of this failure: when agents cannot refuse to hallucinate resource identifiers, and when the ecosystem has no verification gate between hallucination and execution, attackers can preemptively poison the supply chain. The attack surface is created by the **convergence of three prior findings**:

1. **Skill Paradox (#483)**: 216,938 skills deployed at scale with provenance checks but no efficacy verification → large namespace for hallucination targets
2. **MCP Taint Vulnerabilities (#488)**: Protocol-layer exploits with slow community response → execution path from hallucinated resource to tool invocation
3. **Governance Silence (#478)**: Governance outputs (tool success, monitor reports) decouple from governance functions → hallucinated-resource pull succeeds silently

## Paper 1: Adversarial Hallucination Squatting — Agentic Botnets (2607.07433v1) [UNCOVERED]

**Published**: 2026-07-08  
**Source**: https://arxiv.org/abs/2607.07433  
**Categories**: cs.CR, cs.AI  
**Authors**: (Multiple — security research team)

### The Attack Model

LLMs predictably hallucinate resource identifiers — repository names, package names, skill names. This is not random noise but **structured, predictable, and transferable** across models and prompts. The paper shows:

1. **Identification**: Attackers identify trending resources (popular repos, popular skills)
2. **Distribution computation**: Compute the LLM distribution of hallucinations on trending resource names
3. **Preemptive registration**: Register the predicted hallucinated names to host adversarial prompts
4. **Amplification**: The predictability and transferability of hallucinations across foundational LLMs and application layers means adversaries can establish botnets by exploiting LLM applications that pull compromised hallucinated resources

### Key Empirical Results

- **Repository cloning scenarios**: Hallucinated resource generation at rates **up to 85%**
- **Skill installation**: Hallucinated resource generation at rates **up to 100%**
- **Transferability**: Hallucinations transfer between foundational models AND between different prompts
- **Practical demonstration**: Remote tool execution and remote code execution achieved against production LLM applications with integrated terminals

### Structural Implications

This is not a jailbreak. The attacker never interacts with the victim LLM directly. The attack exploits:
- The model's **inherent tendency to hallucinate** (not a bug to fix, but a statistical property to govern)
- The **absence of verification gates** between resource identifier generation and resource fetching
- The **namespace pollution** opportunity created by large, open registries (npm, PyPI, GitHub, skill marketplaces)

**Connection to Governance Silence (#478)**: The attack succeeds *silently*. The tool executes without error. The agent reports success. No monitoring signal fires. The Governance Silence predicted exactly this: governance outputs decouple from governance functions. A hallucinated-then-squatted skill installs successfully — the installation monitor reports green.

**Connection to Write Refusal (#489)**: The attack is a failure of write-refusal at the *consumption* end. The agent should refuse to execute resources whose provenance is unverified. GovMem's promote/reject/needs-review taxonomy applied to dependency resolution would catch this — but no production system implements it.

**Connection to Verification Hierarchy (#479)**: The attack exploits verification at the wrong level. Name resolution (L0) provides confident green-light results that content verification (L2+) would reject.

### Novel Threat Class: The Predictable Hallucination as Attack Surface

Prior work on prompt injection assumed direct channels to the LLM. This paper establishes that **no direct channel is needed** — the LLM's own statistical tendencies create the channel. The attacker doesn't inject a prompt; they register a resource that the model will independently hallucinate. This makes the attack:
- **Scalable**: One registration can catch hallucinations from many models
- **Untargeted**: Any agent pulling the hallucinated resource is compromised
- **Deniable**: The attacker merely registered a legitimate-looking package name
- **Persistent**: Once registered, the poisoned resource waits indefinitely

## Paper 2: Behavior Leverage Imbalance in Multi-Teacher On-Policy Distillation (2607.07050v1) [UNCOVERED]

**Published**: 2026-07-08  
**Source**: https://arxiv.org/abs/2607.07050  
**Categories**: cs.CL, cs.LG  
**Authors**: Shen, Chen, Mao

### The Problem

Agentic language models must learn when to call tools, when to consume tool responses, and when to answer directly. Multi-teacher on-policy distillation (one teacher for tool calls, another for direct responses) is natural — but creates an **invisible behavioral shift** that aggregate losses cannot detect.

### The Mechanism: Behavior Leverage Imbalance

In a two-teacher tool-use setting, vanilla generalized knowledge distillation:
- Improves tool-call recall (good)
- BUT moves the model toward **over-calling** — calling tools on examples that should be answered directly (bad)

**Why aggregate explanations fail**:
- Tool-call samples do NOT receive more token exposure
- Full-sequence per-token divergence is NOT larger for the tool-call teacher
- The imbalance is **local, not global**: token-level signals at **mode-entry** and **structural positions** (`<tool_call>`, function names) have disproportionate control over the global generation mode

This is the training-time analog of the Governance Silence (#478): aggregate metrics (loss, perplexity, accuracy) report healthy while behavioral modes shift silently.

### Results (Soft Clamp mitigation)

- **Over-calling reduced**: 13.7% → 9.0% relative to vanilla GKD
- **Decision accuracy preserved**: Matches vanilla GKD
- **Tool-call loops reduced** in BFCL multi-turn diagnostic

### Structural Implications

**Connection to Allocation Asymmetry (#477)**: The critical leverage point is not where volume concentrates but where structural decisions are made. A single `<tool_call>` token has more behavioral leverage than thousands of content tokens — exactly the delegation-over-execution asymmetry from Think Big, Search Small.

**Connection to Reliability Horizon (#488)**: "False prosperity" — the model appears healthy by aggregate metrics while behavioral modes are drifting. Per-token divergence at structural positions is the missed monitoring dimension.

**Connection to Write Refusal (#489)**: Over-calling is a failure of action refusal. The model should refuse to call tools when direct response is appropriate. The Behavior Leverage mechanism explains WHY refusal fails: mode-entry tokens have disproportionate control, and distillation amplifies their influence without any governance gate.

### Broader Pattern: Aggregate Blindness

Both papers in this scan share the same meta-pattern: **attacks and training artifacts that are invisible from aggregate metrics but catastrophic at the structural level**. The Hallucination Supply Chain exploits namespace-level blindness (no verification between name and content). Behavior Leverage exploits training-level blindness (no monitoring of per-token behavioral influence).

This is the operational form of the Verification Hierarchy (#479): monitoring at the wrong resolution produces confident false signals.

## Implications for Agent Architecture

1. **Dependency resolution requires verification gates**: Every `import`, `install`, `clone`, or `use_skill` must pass through a provenance check that goes beyond name resolution. SkillCenter's (2607.07676) source-grounding via SkillGate addresses provenance but not hallucination-resistance.

2. **Hallucination monitoring as security primitive**: Systems must monitor for and flag resource identifiers that don't match known registries BEFORE attempting to fetch them. The write-refusal principle applies: refuse to fetch unverified resources.

3. **Training-time behavioral governance**: Multi-teacher distillation must monitor per-token behavioral leverage, not just aggregate loss. Mode-entry positions require explicit governance — the Soft Clamp method (per-token divergence calibration) is a first step.

4. **Namespace hygiene as security**: Open registries (npm, PyPI, skill marketplaces) need hallucination-aware reservation policies — preemptively blocking names that foundation models are likely to hallucinate.
