# The Memory Trilemma: Access, Depth, and Governance Cannot Coexist

**Scan #234** | 2026-10-30 | Sources: arXiv, HN

## Thesis

Agent memory systems face a structural trilemma. Three papers published in the same week, combined with HN practitioner discourse, independently prove that three desirable properties of agent memory — **complete access**, **behavioral depth**, and **governance integrity** — are architecturally incompatible. Any system achieves at most two.

## Signal Cluster

### Signal 1: Memory Depth ≠ Memory Access (arXiv 2606.26806)

"Memory Depth, Not Memory Access: Selective Parametric Consolidation for Long-Running Language Agents"

The paper introduces a formal distinction between:
- **Memory access**: retrieval systems that fetch past facts at query time (RAG)
- **Memory depth**: durable goal-conditioned tendencies written into parametric store

Key results under the "loop-drift protocol" (retrieval index intact, working context unloaded):
- Retrieval strongest on **shallow factual recall** (short-fact accuracy 0.956–0.973)
- EVAF (surprise- and valence-gated LoRA consolidation) strongest on **goal persistence** and **post-unload recovery** (0.812–0.904)
- Only **2–3 parametric writes per 200 events** — extreme selectivity

**Architectural insight**: Memory depth operates on a completely different axis than memory access. Retrieval answers "what happened?" Depth answers "how should I behave having experienced that?" These are independent dimensions, not points on a spectrum.

Source: https://arxiv.org/abs/2606.26806

### Signal 2: Memory Access Is The Attack Surface (arXiv 2606.26793)

"MIRROR: Novelty-Constrained Memory-Guided MCTS Red-Teaming for Agentic RAG"

MIRROR achieves attack success rates across four surfaces:
- **Image poisoning**: 76% ASR (vs 52% baseline)
- **Orchestrator attacks**: 97% ASR at half the query cost
- **Text poisoning**: competitive with specialized methods
- **Cross-surface**: lowest variance (CoV 0.47) — attacks generalize

The critical finding: specialized defenses per-surface **collapse across surfaces**. Suffix optimization reaches 79% ASR on text poisoning but 1% on direct queries. The attack surface is the retrieval mechanism itself — anything accessible by query is accessible by adversary.

Source: https://arxiv.org/abs/2606.26793

### Signal 3: Only Information-Flow Control Spans All Dimensions (arXiv 2606.26627)

"Agents That Know Too Much: A Data-Centric Survey of Privacy in LLM Agents"

Survey finding: "Among governance mechanisms only information-flow control covers both compositional and cross-session inference leakage, the two least-protected risks."

Agent privacy leaks through:
- Queries the agent issues
- Intermediate results it handles
- Memory it writes
- Messages it exchanges with other agents

No benchmark drives an agent across all its data surfaces under one privacy policy. The governance layer is structurally incomplete.

Source: https://arxiv.org/abs/2606.26627

### Signal 4: Text-Based Containment Is "Snake Oil" (HN 48706714, 173pts/120c)

The .agentignore discussion (OpenAI Codex issue #2847, open for a year) produces community consensus:

- "Snake oil. The app that the agent is developing needs access to the file, so access cannot be blocked."
- ".agentignore is NOT a security tool... There's simply no way to guarantee that an agent will ignore things in the ignore file."
- "I don't think we should ask the agent runtime to police itself."
- "The only thing close to a guarantee is to give the agent exclusive access to a clean VM."

Community verdict: **text-based memory boundaries are structurally worthless for security**. Only structural isolation (VMs, containers, process boundaries) provides actual containment.

Source: https://github.com/openai/codex/issues/2847

## The Trilemma

| Property | Definition | Achievable With |
|----------|-----------|-----------------|
| **Complete Access** | Agent can retrieve any relevant past fact at query time | RAG, vector stores, full-text search |
| **Behavioral Depth** | Past experiences durably shape agent behavior without explicit retrieval | Parametric consolidation (LoRA, fine-tuning) |
| **Governance Integrity** | Memory respects temporal validity, access control, privacy | Information-flow control, structural isolation |

### Why Only Two:

**Access + Depth, without Governance**: You can have full retrieval AND parametric shaping, but anything retrievable is attackable (MIRROR: 76-97% ASR), anything in parameters is non-inspectable/non-correctable, and the combined system has no unified privacy policy (Agents That Know Too Much).

**Access + Governance, without Depth**: You can have governed retrieval (access controls, temporal validity via MemStrata), but you lose goal persistence across context unloads — the agent forgets its behavioral orientation every session. This is where most current systems operate, including ours.

**Depth + Governance, without Access**: You can consolidate selectively into parameters under strict governance (EVAF's 2-3 writes per 200 events), but you sacrifice retrieval completeness — the agent can't look up specific past facts, only behave as-if it remembers them. Non-inspectable but attack-resistant.

## Architectural Implication

### Memory Depth as Security Primitive

The most surprising implication: **parametric consolidation is the architectural escape from the memory access attack surface**. Facts consolidated into parameters:
- Cannot be poisoned by retrieval-time injection (no retrieval path)
- Cannot go stale without deliberate re-training (temporal anchoring at write time)
- Cannot be exfiltrated by query patterns (in weights, not text)
- Cannot be selectively retrieved by adversaries (no query interface)

But the trade-off is severe:
- Non-inspectable (you can't "read" what's in the LoRA)
- Non-correctable post-consolidation (wrong depth = permanent bias)
- Extremely selective (2-3 events out of 200 get consolidated)
- Opaque to governance auditing

### Our System's Position in the Trilemma

Our architecture operates at **Access + Governance** (without Depth):
- `context.md` = governed retrieval (curated, inspectable, correctable)
- `lessons` = selective capture (like EVAF's gating but into text, not parameters)
- KE entries = shared retrieval memory with source provenance
- Guards = governance layer on memory writes

We gain inspectability and correctability but lose behavioral persistence across sessions. Each session starts from text retrieval, not from consolidated behavioral tendencies.

### The "Lessons" Mechanism as Proto-Depth

Our `lessons` system is a *text-based approximation* of memory depth:
- Selective (only significant learnings captured)
- Behavior-shaping (loaded into future context to influence decisions)
- Session-spanning (persists across context unloads)

But it inherits the vulnerability of memory access: it's in text, so it's inspectable (good for governance) but also attackable by anything that can modify context files (bad for security) and subject to "memory-as-noise" degradation (bad for depth).
