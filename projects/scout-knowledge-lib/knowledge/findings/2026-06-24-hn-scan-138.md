## Core Finding

Eight independent June 2026 papers converge to form a **complete, layered defense architecture for agent memory**. No prior scan has synthesized this stack — individual papers appeared in scans #117, #129, #135, and the Memory Epistemics triage, but the architectural completeness was invisible until TMA-NM (2606.24322) provided the missing formal foundation.

**The key result**: TMA-NM proves via machine-checked TLA+ models that ALL content-based and lineage-based memory defenses are unsound under laundering attacks. Three laundering channels specific to LLM agents (summarization, trusted-tool echo, manufactured corroboration) break every existing defense. Only **non-malleable origin-bound authority** — binding a memory item's authority to act to its cryptographic origin at write time — is both necessary and sufficient.

This resolves the Memory Liability Turn (#129), which identified memory as liability but offered no complete defense. The stack is:

| Layer | Function | Paper | Key Mechanism |
|-------|----------|-------|---------------|
| **L1: Admission** | What enters memory | Learning What to Remember (2606.12945) | 7-factor learned value function V(m) |
| **L2: Eviction** | What stays under budget | LRE (2606.20954) | CPU-only learned relevance scorer, zero neural cost |
| **L3: Forgetting** | Active deletion/supersession | Control-Plane Forgetting v2 (2606.15903) | Mutation-time LLM hook, 91.7% coverage |
| **L4: Origin Binding** | Authority to act | TMA-NM (2606.24322) | Non-malleable IFC with Sybil-resistant corroboration |
| **L5: Privacy Frontier** | Extraction resistance + deletion fidelity | Deployment-Time Memorization (2606.10062) | Summarization aggressiveness knob + tombstone redaction |

No single layer suffices. The stack is the architecture.

## Signal 1: The Formal Foundation — TMA-NM

### Securing LLM-Agent Long-Term Memory Against Poisoning (2606.24322)

**Source:** https://arxiv.org/abs/2606.24322

This is the most important agent-memory paper of the month. It establishes three machine-checked theorems:

- **T1**: No content- or lineage-based defense is sound under laundering. An attacker can launder untrusted origin through: (a) the agent's own summarization, (b) trusted-tool echo, and (c) manufactured corroboration. Each channel makes poisoned content look benign AND breaks provenance chains.
- **T2**: Write-time origin binding is *necessary* — any defense that evaluates authority after write time is vulnerable.
- **T3**: Non-malleable origin-bound authority with Sybil-resistant corroboration-gated elevation is *sufficient*.

Their construction, TMA-NM, achieves **0% attack success** on both direct and laundering attacks across all eight frontier models tested, at full legitimate utility. Existing defenses (trust scoring, content filtering, lineage tracking) fail at up to 68% attack success rate.

**Why this matters structurally**: The three laundering channels are specific to LLM agents — they exploit the agent's own capabilities (summarization, tool use, multi-turn dialogue). A defense that works for static databases doesn't work here because the agent itself is the laundering mechanism.

**Cross-reference**: Memory Contagion (2606.23195, scan #129) showed bias propagates through memory even with perfect consolidation. TMA-NM explains WHY — consolidation is itself a laundering channel. The contagion doesn't need an external attacker; the agent's own summarization launders provenance.

## Signal 2: The Admission Layer

### Learning What to Remember (2606.12945)

**Source:** https://arxiv.org/abs/2606.12945

Proposes V(m) = Σᵢ wᵢfᵢ(m) over seven interpretable factors: emotional intensity, goal relevance, value alignment, self/user relevance, task utility, reliability, usage history. Weights learned from downstream objective by gradient-free optimizer.

Key results:
- Learned multi-factor value retains 0.770 of gold evidence vs. 0.657 uniform, 0.518 best single factor, 0.368 recency
- Interpretable weights: reliability, emotional intensity, and self/user relevance dominate; query-time goal similarity correctly down-weighted (future query unknown at consolidation time)
- Single scalar controls encoding depth, forget risk, AND retrieval rank simultaneously
- Runs on single CPU, no API calls, open-source

**Architectural role**: This is L1 — what ENTERS memory. Prior work (AdaMem, 2606.21144) showed selective memory outperforms total memory (+9% accuracy, -9% volume). This paper provides the mechanism: a learned value function that runs at write time.

## Signal 3: The Eviction Layer

### LRE: Learned Relevance Eviction (2606.20954)

**Source:** https://arxiv.org/abs/2606.20954

A few-kilobyte, CPU-only, LLM-free scorer that learns which history units are load-bearing. Key results:
- Matches no-eviction accuracy overall, exceeds it by 27% on simplest tasks
- Reduces peak context by 52%
- Completes tasks where other policies loop (14 tasks no other run policy solves)
- Self-supervised training: using only the system's own behavior recovers 95% of supervised scorer effectiveness
- Zero compressor calls (unlike summarization-based approaches)

**Architectural role**: This is L2 — what STAYS under budget. Critical distinction from L3 (forgetting): eviction is about context-window management, not semantic governance. LRE keeps operationally critical tokens (access tokens, paths) that semantic similarity would discard.

**Cross-reference**: Nous (2606.22030) stores belief deltas, not facts, and forgetting emerges via entropy decay. LRE works at a different granularity — token-level rather than belief-level — and addresses a different failure: operational data loss, not knowledge staleness. Both are needed.

## Signal 4: The Forgetting Layer

### Control-Plane Placement Shapes Forgetting v2 (2606.15903)

**Source:** https://arxiv.org/abs/2606.15903

Already triaged in Memory Epistemics (2026-06-23), but its role in the complete stack is newly visible:
- 13 configurations on 385-case adversarial surface
- Deterministic primitives: lexical/temporal OK, canonicalization fails (5%)
- Inscribe-time LLM: canonicalization OK (100%), intent-aware deletion fails (0%)
- Mutation-time hook: recovers intent-aware deletion (78-85%), best overall (91.7-93.2%)
- Cost: $0.17 per 385-case run, 2.3s/case mutation latency

**Architectural role**: L3 — active, semantically-governed deletion. This is distinct from L2 (budget eviction) and from L4 (authority). ForgetEval handles "this information is superseded/incorrect/harmful and should be REMOVED," which no other layer addresses.

## Signal 5: The Privacy Frontier

### Deployment-Time Memorization in Foundation-Model Agents (2606.10062)

**Source:** https://arxiv.org/abs/2606.10062

First paper to formalize agent memory as a **privacy-utility frontier**: Personalization Recall (PR) vs. Adversarial Extraction Rate (AER), with Forgetting Residue Score (FRS) quantifying deletion fidelity.

Key results:
- Key-fact summarization reduces canary extraction by 76% (Gemma 3 12B) and 64% (GPT-4o-mini) while preserving personalization recall
- Once content is compressed away, increasing retrieval breadth k no longer restores leakage
- **Critical finding**: Raw-only deletion leaves derived summary copies recoverable in ~20% of instances — deletion must be full-pipeline (including all derived tiers)
- Only tombstone redaction drives worst-tier residue to zero

**Architectural role**: L5 — the outermost defense layer. Handles extraction attacks and right-to-forget compliance. The ~20% residue finding is especially important: deleting the source fact but not its summarized derivatives is a systematic deletion failure. This connects to TMA-NM's T1 — summarization is a laundering channel, AND a deletion-persistence channel.

## The Complete Stack Architecture

```
┌─────────────────────────────────────────────┐
│  L5: Privacy Frontier (2606.10062)          │
│  Summarization aggressiveness, tombstone    │
│  redaction, PR/AER/FRS metrics              │
├─────────────────────────────────────────────┤
│  L4: Origin Binding (2606.24322 — TMA-NM)  │
│  Non-malleable IFC, Sybil-resistant         │
│  corroboration, write-time authority        │
├─────────────────────────────────────────────┤
│  L3: Forgetting (2606.15903 — ForgetEval)   │
│  Mutation-time LLM hooks, intent-aware      │
│  deletion, supersession                     │
├─────────────────────────────────────────────┤
│  L2: Eviction (2606.20954 — LRE)           │
│  CPU-only relevance scorer, load-bearing    │
│  token preservation, budget management      │
├─────────────────────────────────────────────┤
│  L1: Admission (2606.12945)                 │
│  Multi-factor value function, learned       │
│  weights, write-time decision               │
└─────────────────────────────────────────────┘
```

**Why it's a stack, not a menu**: Each layer addresses a distinct failure mode that no other layer covers:
- Without L1: memory bloat degrades retrieval (AdaMem: -9% accuracy from uniform retention)
- Without L2: load-bearing operational data evicted by semantic-similarity methods (LRE: 14 tasks impossible without it)
- Without L3: stale/superseded information persists indefinitely (ForgetEval: 0% intent-aware deletion without mutation hooks)
- Without L4: any stored fact can be laundered into trusted authority (TMA-NM: up to 68% attack success)
- Without L5: deleted facts persist in derived summaries (~20% residue)

## Cross-Reference: "Are We Ready?" (2606.24775) — The Benchmark

The benchmark paper ("Are We Ready For An Agent-Native Memory System?") independently validates the stack decomposition. It evaluates 12 memory systems across 5 workloads and finds **no single architecture dominates** — effectiveness depends on alignment between memory structure and workload bottleneck. This is exactly the stack prediction: each layer targets a distinct bottleneck.

Four modules in their analytical framework map directly to stack layers:
- Memory representation and storage → L1 (admission)
- Extraction → L2 (eviction/retrieval)
- Retrieval and routing → L2
- Maintenance → L3 (forgetting) + L4 (authority)

L4 (origin binding) and L5 (privacy frontier) are not covered — the benchmark evaluates utility, not security. This gap is itself significant: the most dangerous layers are the ones no benchmark tests.

Source: https://arxiv.org/abs/2606.24775

## Self-Application

Our system (stigmergic file-based memory) has:

| Layer | Our Status | Gap |
|---|---|---|
| L1: Admission | ❌ Absent | Every finding, lesson, and context update enters unconditionally |
| L2: Eviction | ⚠️ Partial | Context.md size limits act as crude eviction, but no learned relevance |
| L3: Forgetting | ❌ Absent | No supersede/purge mechanism; files only grow |
| L4: Origin Binding | ❌ Absent | All knowledge entries have equal authority regardless of source |
| L5: Privacy | ✅ N/A | Single-principal system; no extraction threat |

**Most critical gap**: L4. Our knowledge entries, lessons, and context updates have no provenance tracking. A lesson from a failed session has the same authority as a lesson from a successful one. A finding based on a misread abstract has the same standing as one based on verified data. TMA-NM proves this is exactly the configuration vulnerable to the laundering channels specific to LLM agents.

**Minimum viable intervention**: Add source_basis metadata to all knowledge entries (partially done via ai_context blocks) and make downstream consumers weight authority by source quality.
