## Finding 1: Iroh 1.0 and P2P as Agent Transport Layer

**Story:** [Iroh 1.0](https://www.iroh.computer/blog/v1) (848pts ↑ from 807pts scan-7, 267c)

Iroh is a Rust library that replaces IP addresses with cryptographic keys for endpoint identity. Mental model: "Tailscale at the application layer" (apitman). Used in production for distributed ML training (arilotter). The general HN reception is enthusiastic but questions center on differentiation from Tailscale.

### The agent-relevant signal:

**ramoz** (eqtylab) explicitly connects Iroh to A2A:

> "I think this tech (modern p2p) represents what agent-to-agent (a2a) should be built on. Every agent should be reachable to each other without hosting itself as an http server."

Links to two prototypes:
- **agentbeam** (github.com/eqtylab/agentbeam) — P2P agent communication
- **real-a2a** (github.com/eqtylab/real-a2a) — A2A implementation on P2P substrate

**mckirk's** response ("Every agent? I surely hope not. But it would be an interesting... artisocial experiment?") captures the tension: P2P agent meshes enable permissionless discovery but create a coordination/security surface area.

### Why this matters:

Google's A2A protocol assumes HTTP-based agent cards and task delegation. A P2P substrate would change the trust and discovery model fundamentally:

1. **Identity without registry** — agents identified by cryptographic key, not URL. No DNS, no certificate authority, no central agent directory.
2. **NAT traversal built in** — agents on home hardware, behind firewalls, become first-class network participants. This directly enables the sovereignty cascade: local model + local agent + P2P communication = fully decentralized agent system.
3. **Transport agnosticism** — Iroh supports custom transports (rklaehn, Iroh developer). Agents could communicate over BLE, LoRa, or relay depending on context.

The combination of Iroh's 848pts (massive community attention), arilotter's production ML use case, and ramoz's explicit agent framing makes this the strongest "P2P as agent infrastructure" signal observed on HN.

**Cross-reference:** Updates the protocol gap analysis in `agent-protocols-mcp-a2a.md` — neither MCP nor A2A currently considers P2P transport.

## Finding 2: LinkedIn Backdoor Continues Acceleration — New Attack Variants

**Story:** [A backdoor in a LinkedIn job offer](https://roman.pt/posts/linkedin-backdoor/) (441pts ↑ from 311pts scan-7, 87c ↑ from 66c)

The +42% growth maintains this as the fastest-accelerating agent-security-relevant story. Score trajectory: 129 (scan-6) → 311 (scan-7, +141%) → 441 (scan-8, +42%).

### New attack variant: fake VPN downloads

**dolebirchwood** reports a different vector using the same social engineering pattern:

> "I was given login credentials so I could sign in to a site where I was prompted to download a VPN client... They made the site look like it was an official OpenVPN page... The method of downloading their 'VPN' was to copy and paste a script to run in my terminal."

The script starts with `( brew install openvpn )` but hides malicious payload after the visible portion. This is the **clipboard truncation attack** — UI shows benign prefix, actual command includes download and execution of arbitrary code.

### Near-misses are common

- **srikanth86**: "I had this playout as is on Friday. I luckily got on the zoom call 20 mins late. Found it weird that the interviewer was pushy and wanted me to download and run an npm repo."
- **Yhippa**: "This has nearly gotten me before, and I got lucky."
- **robotnikman**: "With how many desperate software engineers there are on the market right now looking for a job, there are going to be scumbags out there trying to take advantage of the desperation."

### Expanding agent attack surface taxonomy:

The original npm `prepare` hook vector (scan-6/7) has been joined by:

| Vector | Social engineering | Technical payload | Agent risk |
|--------|-------------------|-------------------|------------|
| npm repo clone | "Review this codebase" | `prepare` hook runs arbitrary code | Agent told to clone and evaluate repos |
| Fake VPN download | "Join our secure network" | Obfuscated terminal command | Agent prompted to install tools |
| Clipboard truncation | "Copy this setup command" | Hidden payload after visible prefix | Agent processing terminal instructions from untrusted sources |

**binsquare's** defense recommendation ("Would highly recommend running any repo in an isolated environment like a vm") maps directly to agent architecture: sandbox-first execution with no network access during dependency installation.

## Finding 3: Homelab AI Dev Platform — The Self-Hosted Agent Infra Pattern

**Story:** [My Homelab AI Dev Platform](https://rsgm.dev/post/ai-dev-platform/) (201pts ↑ from 186pts scan-7, 41c)

This is no longer a single blog post — it has triggered recognition of a **convergent architectural pattern**. Multiple HN users independently report building the same thing:

### The pattern:

```
Local/self-hosted LLM + coding agent (opencode/pi) + git server (forgejo/gitea) + CI/CD = self-hosted agent development platform
```

### Independent implementations:

- **david-giesberg**: Runs opencode inside Forgejo action runners. Invokes agents with `/oc` in a Forgejo issue; agent returns a PR for review. (codeberg.org/dragonfyre13/forgejo-opencode)
- **doctorspazz**: "My setup is a similar idea, just with n8n/git/argo/k3s. It's mainly for automated workflows that Qwen or Gemma4 can handle."
- **MisterPea**: "I am also creating this... a lot of people in tech independently go through the same things right around the same time."
- **orangeisthe**: Runs Pi coding agent on Mac with full software suite (Redis, Postgres, Kratos). Prefers co-located agent over VM-based for faster iteration.

### What's converging:

| Layer | Common choices | Purpose |
|-------|---------------|---------|
| Model | Qwen3.6, Gemma4, GLM via Ollama | Local/self-hosted inference |
| Agent | OpenCode, Pi | Coding task execution |
| VCS | Forgejo, Gitea, bare git | Self-hosted version control |
| Orchestration | n8n, Argo, k3s, Forgejo Actions | Workflow automation and CI |
| Interface | Issue comments (`/oc`), chat, PR review | Human-agent interaction |

This is the **sovereignty cascade reaching the agent layer**: it started with "can I run a model locally?" (scan-4), passed through "can I replace my cloud subscription?" (scan-5-7), and has now reached "can I build a complete agent development platform at home?"
