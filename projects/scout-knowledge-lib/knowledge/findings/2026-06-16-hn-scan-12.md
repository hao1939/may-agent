## New Signal: GitHub AI Capacity Overflow

**"Microsoft turns to AWS as GitHub faces AI capacity crunch"** (25pts, 2c — early stage, likely to grow)

Key data points from the story and comments:
- **Commits on pace to hit 14 billion in 2026, up from 1 billion in 2025.** 14x growth entirely attributed to AI-generated code.
- csbrooks: "So AI means 14x the checkins? That's not 14x features completed, but still... wow."
- ashishb: Notes cascading updates from dependabot as possible multiplier — agent-generated PRs creating agent-reviewed PRs.
- Microsoft (GitHub's parent) turning to AWS for overflow compute — same company that owns Azure choosing a competitor for capacity. This signals genuine scarcity, not just cost optimization.

### Analysis

This validates the infrastructure cost squeeze from a completely different angle:
1. **Hetzner**: Hardware/RAM scarcity → 3x VPS pricing
2. **GitHub → AWS**: AI commit volume overwhelms existing capacity → platform-level overflow
3. **Amazon Missouri DC**: Multibillion-dollar buildout to serve exactly this demand

The 14x commit growth number is the most concrete quantification we've seen of AI's impact on infrastructure demand. If even a fraction of these commits trigger CI (builds, tests, reviews), the downstream compute multiplication is enormous.

**Agent implication**: Every agent that writes code and opens a PR creates downstream compute demand (CI, review bots, deployment). The system is self-reinforcing: AI generates code → AI reviews code → AI tests code → each layer multiplies infrastructure demand.

## Signal Evolution: Homelab Platform Maturity

**"My Homelab AI Dev Platform"** (255pts, 50c) — the homelab agent platform story has graduated from "I built this" to production-grade architecture.

### Key new architectural patterns

**constGard** describes the most mature homelab agent pipeline observed:
```
forgejo tag listeners → argo workflows orchestrating:
1. issue tag → 2. write PR → 3. testing → 4. review+revise loop →
5. merge mutex → 6. rebase and merge
```

Critical addition: **SPIFFE-attested identity** for agent pods:
> "I've been trying really hard to have it properly implement agentic identity where the pod gets a spiffe-attested token and then trades that for access to the vault secret for a project-scoped forgejo service account."

This is the first practitioner implementation we've seen of **cryptographic agent identity** in a CI pipeline — connecting to the Iroh 1.0 thesis (key-based identity for agents) but applied to the CI layer rather than the network layer.

**CGamesPlay** reiterates the context gap:
> "There's not a great way to manage the context there: you get what's in the issue or PR, but it gets muddy once you have multiple rounds and/or discussion moves from the issue to the PR."

This is now the **third time** CGamesPlay has surfaced this exact problem across HN threads — indicating it's a structural blocker, not a passing frustration.

**dlxfoo** adds Discord integration layer (Kimaki):
> "Chatting with your codebase (voice messages, too, if that's your jam), is very very cool."

Multi-modal agent interaction (text + voice + codebase) entering the homelab stack.

### Maturity Assessment

The homelab platform has crossed from "single-shot agent tasks" to:
- ✅ Multi-step orchestrated workflows (write → test → review → revise → merge)
- ✅ Concurrency control (merge mutex)
- ✅ Identity management (SPIFFE attestation)
- ✅ Secret management (Vault integration)
- ❌ Cross-session memory (still unsolved — CGamesPlay's gap)
- ❌ Multi-agent coordination beyond sequential pipeline
