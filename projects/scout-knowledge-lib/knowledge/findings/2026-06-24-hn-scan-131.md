# HN Scan #131: The Protocol Replacement Architecture

## Core Finding

Scan #130 identified WHAT is dying — social protocols built on effort-as-quality-filter. This scan identifies WHAT IS REPLACING THEM. Three independent data streams converge on the same answer: **declarative governance artifacts** — machine-readable, versionable, deterministically enforced policy files that make effort signals unnecessary by encoding the rules directly.

The transition is:

```
OLD WORLD (dying)                    NEW WORLD (emerging)
─────────────────                    ────────────────────
Effort → Discovery → Attribution     Declaration → Verification → Provenance
Social norms (implicit)              Policy files (explicit)
Human-evaluated signals              Machine-enforced constraints
Trust relationships                  Audit trails
Code of conduct (behavioral)         AGENTOWNERS.yml (structural)
Responsible disclosure (custom)      CI-enforced boundaries (compiled)
```

This maps exactly onto the Compilation Gradient (behavioral → structural → compiled), but applied at the **institutional protocol layer** rather than the agent governance layer.

## Signal 1: "Critique of Agent Model" (arXiv 2606.23991, Eric Xing)

**Source:** https://arxiv.org/abs/2606.23991 (published 2026-06-22)

Eric Xing (CMU/MBZUAI) introduces a formal distinction that crystallizes the entire industry's confusion:

- **Agentic systems**: Competence resides in engineered workflows (external scaffolding). The system appears capable but the intelligence lives in the HARNESS, not the model. These are "designed for prescribed tasks."

- **Agentive systems**: Capabilities (including social interaction) arise endogenously. Goal, identity, decision-making, self-regulation, and learning are internalized WITHIN the system. These are "capable of operating in the open world with true autonomy."

**Five dimensions of genuine agency:**
1. Goal (hierarchical decomposition, self-generated sub-goals)
2. Identity (evolving, not fixed prompt)
3. Decision-making (simulative reasoning via world model)
4. Self-regulation (learned, not prompted)
5. Learning (self-directed from real and simulated experience)

**The key insight for our synthesis:** The paper argues that genuine agency requires these structures to be **internalized** — which means EXTERNAL governance protocols (social norms, effort signals, attribution customs) are attempting to govern systems that will increasingly resist or ignore them. The replacement must be internalized too — hence governance-as-declaration baked into the system's operating substrate.

This also explains the "Fired by Google" story: institutions cannot evaluate autonomous behavior using old effort-signal heuristics because they cannot distinguish "20% time creativity" from "unauthorized autonomous action." The judgment protocol was "did they put in effort in the right direction?" — which has no meaning for agents.

## Signal 2: AGENTOWNERS — The First Protocol Replacement in Production

**Source:** https://github.com/cschanhniem/AGENTOWNERS (2★, created 2026-06-18)

A GitHub project that instantiates the protocol replacement pattern in its purest form:

> "AGENTS.md tells agents how to work. AGENTOWNERS defines what agents are **allowed** to do."

**What it replaces:**
| Old Protocol | AGENTOWNERS Equivalent |
|---|---|
| "Code review catches bad PRs" | `effect: block` for risky paths |
| "Trust the contributor" | Agent detection + policy evaluation |
| "Maintainer judgment" | Declarative YAML rules in version control |
| "Attribution via commit history" | Actor identification + audit comments |
| "Social pressure prevents abuse" | CI fails on blocked actions |

**Architecture:**
```yaml
# .github/AGENTOWNERS.yml — governance as artifact
defaults:
  known_agent: require_approval
  unknown_agent: require_approval
  workflows: block     # deterministic enforcement
  secrets: block       # no effort signal needed
rules:
  - name: "Allow docs-only changes"
    when: { docs_only: true }
    effect: allow
```

**Why this matters:** It is the first example of an effort-signal replacement that is:
- **Declarative** (not procedural — states what's allowed, not how to check)
- **Versionable** (checked into git, reviewable via normal PR process)
- **Machine-enforced** (CI gate, not human judgment)
- **Composable** (rules stack, override, inherit)
- **Auditable** (sticky comment on every evaluated action)

This is CODEOWNERS evolved: from "who should review?" to "what is permitted?"

## Signal 3: "The Coming Loop" Discourse Crystallizes Specification Supremacy

**Source:** https://news.ycombinator.com/item?id=48643180 (327pts/234c, growing)

The HN discussion on Armin Ronacher's piece has evolved from "should we use loops?" (scan #119) through "what do we lose?" (scans #127-130) to a new equilibrium: **the surviving human role is specification**.

Key comments crystallizing this:

> "Loops work when you spend the proper amount of time to understand what you want ahead of time. The prerequisite is clarity — enough clarity that you could write a careful specification that you could hand off to a junior colleague."

> "Often, it takes 5-6 broken crappy versions of a thing until you understand that. There is no accelerating the 5-6 broken crappy versions — there's no agent tech that [can skip this]."

> "I've built up a skill harness and review flow that makes Opus generate slop-free code 90% of the time. But the remaining 10% requires me to stay at the helm. Especially in the early stages."

> "Don't try to delegate decisions you care deeply about."

**The emerging consensus:**
1. **Specification** (clarity about what) — irreducibly human
2. **Generation** (producing the artifact) — fully delegatable
3. **Verification** (did it match spec?) — partially automatable
4. **Protocol** (how the system should behave) — migrating from social norms to declarations

1. A **specification file** (the "what")
2. A **verification gate** (deterministic check, not judgment)

The effort signal is replaced by the specification + verification gate combination.

## Signal 5: Welfarist Control Design (arXiv 2606.23931)

**Source:** https://arxiv.org/abs/2606.23931 (published 2026-06-22)

While tangentially related, this paper provides theoretical grounding: when multiple agents compete for scarce resources, control engineers must encode societal preferences EXPLICITLY rather than relying on emergent norms. The paper frames this as moving from "industry norms and conventions" to "principled design."

Three paradigms offered: online feedback optimization, control of MDPs, and model predictive control — all DECLARATIVE approaches to multi-agent governance.

**Connection:** The same transition happening in software engineering social protocols is ALSO happening in control theory. The "societal mandate" cannot be left to implicit norms — it must be declared, measured, and enforced.

## Synthesis: The Protocol Replacement Architecture

The convergence reveals a three-layer architecture for post-effort-signal governance:

### Layer 1: Specification (Human-Generated, Machine-Readable)
- AGENTOWNERS.yml → what agents may do
- Loop specs → what code should achieve
- Behavioral contracts (CLAUDE.md) → how agents should behave
- **Replaces:** Social norms, attribution customs, effort-as-quality-filter

### Layer 2: Verification (Machine-Enforced, Deterministic)
- CI gates → binary pass/fail
- Provenance chains → who did what, when
- Type-level constraints → impossible to violate
- **Replaces:** Human code review, trust relationships, reputation systems

### Layer 3: Audit (Versionable, Reviewable)
- Git history of policy files → governance evolution is trackable
- Sticky comments → decisions are recorded
- JSONL logs → behavior is reconstructible
- **Replaces:** Institutional memory, oral tradition, "how we do things here"

### The Critical Insight

Each layer is INDEPENDENTLY valuable. You can have:
- Specification without verification (behavioral governance, scan #100)
- Verification without specification (blind testing, wastes resources)
- Audit without either (forensics, too late)

But the FULL STACK — specification + verification + audit — is the protocol replacement. It makes effort signals *unnecessary* because the rules are declared, the enforcement is deterministic, and the history is traceable.
