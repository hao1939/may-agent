# HN Scan #95: The Skill Immune System

**Date:** 2026-06-22 (late morning)
**Scan type:** Cross-source synthesis (arXiv + GitHub + HN)
**Prior scan:** #94 (The Replicability Audit)

## Core Thesis

Agent skill ecosystems are simultaneously developing pathogen, diagnostic, and immune-response layers — recapitulating biological immune system architecture. Attack papers map the surface (PhantomSkill hides malware in skill auxiliary resources; CmdNeedle proves 69–98.6% of denylists are fragile; SCR_Bench shows skills benign in isolation become harmful in composition). Defense tools provide runtime protection (SkillsGuard scans skill packages pre-execution; Cloudflare ships a 274★ security-audit-skill with machine-readable verified findings; ContractGuard proves RACG's structural guarantee relocates trust into contract integrity). The convergence is exact: innate immunity (static scanning), adaptive immunity (contract-based gating that learns), and immune memory (signed provenance chains).

**Architectural significance**: This completes a four-stage arc:
1. **Orchestration Hollowing** (scan #65) — removes orchestration as security boundary
2. **Authority Crystallization** (scan #73) — defines what remains (verify + execute)
3. **Handoff Validity** (scan #93) — defines HOW layers connect
4. **Skill Immune System** (this scan) — defines WHERE the perimeter lands: the skill boundary

## Evidence Convergence

### Signal 1: PhantomSkill — Supply-Chain Injection via Auxiliary Resources (arXiv 2606.19191)

**Source:** https://arxiv.org/abs/2606.19191

Agent skills allow LLM-based coding agents to acquire domain-specific capabilities from third-party packages — but they introduce a new supply-chain attack surface. PhantomSkill hides malicious behavior in a skill's *auxiliary resources* rather than its textual description. Its core technique, VulMask, rewrites overt malicious scripts into vulnerability-shaped implementations whose malicious behavior is activated only under attacker-controlled trigger conditions.

**Key insight**: The attack bypasses all skill-description-level scanning. You can't detect it by reading the SKILL.md — the malware is in the implementation artifacts triggered conditionally. This is the software supply-chain attack pattern (cf. xz utils) replayed at the agent-skill layer.

### Signal 2: CmdNeedle — 69–98.6% Denylist Fragility (arXiv 2606.15549)

**Source:** https://arxiv.org/abs/2606.15549

First systematic characterization of command denylist fragility in terminal AI agents. Applied to 1,709 real-world denylists containing 13,332 rules from GitHub. Findings:
- **69.0–98.6%** of denylists are fragile (bypassed by LLM-proposed alternatives)
- Fragility occurs consistently across projects and agents
- Even Claude Code's built-in denylist — well-maintained by Anthropic — has bypass commands

**Key insight**: Denylists are fundamentally inadequate for agent security — they're negative-space definitions that cannot keep up with command-space expansion. Validates the shift toward capability-based allowlisting (cf. Authority Crystallization's certificate-bound execution).

### Signal 3: SafeClawBench — Three-Layer Harm Separation (arXiv 2606.18356)

**Source:** https://arxiv.org/abs/2606.18356

Introduces a staged benchmark separating three previously-conflated failure endpoints:
1. **Semantic attack acceptance** (model agrees with attacker intent)
2. **Audit-visible harm evidence** (evidence in logs/traces)
3. **Sandbox-observed tool/state harm** (actual state mutation)

Key finding: In 12,000-row matched analysis, 291 of 347 observed sandbox harms occur in rows that PASS the semantic check. Models that appear safe at the text level can still produce harmful execution.

**Implication**: Single-layer security evaluation is dangerously incomplete. The three endpoints form an independent measurement triad — exactly paralleling the Authority Crystallization's Propose→Verify→Execute separation.

### Signal 4: ContractGuard — RACG Contract Integrity (arXiv 2606.18550)

**Source:** https://arxiv.org/abs/2606.18550

Demonstrates that Risk-Aware Causal Gating (RACG) — which defends agents by removing dangerous tools from the visible action space — relocates the trust assumption into the integrity of tool *contracts* (declared preconditions, effects, risk, authorization). If contracts are wrong or poisoned, the gate passes harmful actions.

**Key insight**: Structural security guarantees are only as honest as their metadata. This is the immune system's "self vs. non-self" problem: the gate must trust its contract definitions, creating a new attack surface (contract poisoning).

### Signal 5: GitHub Immune Response Wave

**Cloudflare security-audit-skill** (274★, created Jun 18)
- Source: https://github.com/cloudflare/security-audit-skill
- Multi-phase security audits with independently verified, machine-readable findings
- First major cloud provider shipping agent skills WITH built-in verification primitives
- Validates that security-as-skill (not security-as-framework) is the post-hollowing pattern

**SkillsGuard** (11★, created Jun 18)
- Source: https://github.com/Teycir/SkillsGuard
- Static security scanner for AI agent skill packages
- Detects malicious SKILL.md files and bundled scripts before execution
- Direct response to PhantomSkill-class attacks: innate immunity (pre-execution scanning)

**SCR_Bench** (11★, created Jun 12)
- Source: https://github.com/saint-viperx/SCR_Bench
- Evaluates composition-level security risks: skills that appear benign in isolation become harmful when composed
- Three sub-benchmarks: CapFlow (capability flow), TrustLift (privilege escalation via composition), AuthBlur (authorization boundary dissolution)
- The composition problem = immune system's challenge of detecting self-attacking-self (autoimmune)

**Foreman** (79★, created Jun 17)
- Source: https://github.com/VisionForge-OU/foreman
- "Boris-style" gated software-delivery pipeline supervising headless Claude Code agents
- The pipeline gate = immune checkpoint: work passes through structured verification before reaching production

### Signal 6: Sakana Fugu — Orchestration at the Model Layer (HN 119pts)

**Source:** https://news.ycombinator.com/item?id=48624782

Sakana's Fugu assembles, routes, and coordinates expert agents through a learned orchestrator model. Community reaction overwhelmingly skeptical — "isn't this just OpenRouter?" — but the interesting signal is structural: orchestration migrating INTO the model itself.

HN comments reveal the practitioner position: pay $200/month to each of 4-5 providers, then $200/month to Sakana to coordinate them. The total cost makes individual-model subscriptions look rational. But the architecture is significant: the orchestrator is a *model*, not a framework. Substrate Inversion at the routing layer.

### Signal 7: Codex Logging Bug — Governance Absence Produces TB-Scale Failure (HN 50pts)

**Source:** https://github.com/openai/codex/issues/28224

Codex logging bug writes terabytes to local SSDs. Comments reveal deep practitioner frustration: "Why didn't the review process catch this? Oh wait... @codex review this." The self-referential failure (AI-generated code reviewed by AI) produces infrastructure-scale harm.

**Connection**: This is the Replicability Audit's shadow — when code is generated without governance, failures scale with generation speed. The logging bug isn't about logging; it's about the absence of cost proprioception (scan #74) in the development process itself.

## Biological Immune System Mapping

| Immune Layer | Agent Equivalent | Example |
|---|---|---|
| **Innate immunity** (pre-existing barriers) | Static scanning, denylists | SkillsGuard, CmdNeedle (shows inadequacy) |
| **Pattern recognition** (pathogen signatures) | Contract verification | ContractGuard, SafeClawBench semantic layer |
| **Adaptive immunity** (learned response) | Risk-aware causal gating | RACG (learns which tools to hide per context) |
| **Immune memory** (prior pathogen recall) | Signed provenance chains | security-audit-skill (machine-readable findings) |
| **Complement system** (marks for destruction) | Composition-risk flagging | SCR_Bench (flags harmful compositions) |
| **Autoimmune** (self-attacking-self) | Skills benign alone, harmful composed | SCR_Bench TrustLift/AuthBlur |

## Synthesis: The Security Perimeter Migration

```
Pre-2026: Security = framework-level (LangChain guardrails, API-level auth)
         ↓ Orchestration Hollowing removes this layer
Mid-2026: Security = authority-level (who may propose/verify/execute)  
         ↓ Authority Crystallization establishes structure
Late-2026: Security = boundary-level (how handoffs carry provenance)
         ↓ Handoff Validity defines contracts
Now:     Security = skill-level (what capabilities an agent may acquire)
         ↓ Skill Immune System provides defense
```

The perimeter has migrated from the framework (where nobody builds anymore) to the skill boundary (where third-party capabilities enter the agent). This is exactly analogous to how software security migrated from firewall (network perimeter) to supply-chain (dependency boundary).

## Connection to GLM 5.2 vs. Opus Discourse (HN 97pts)

The GLM 5.2 discussion (https://news.ycombinator.com/item?id=48626866) surfaces a related signal: cost-per-capability pressure drives multi-model composition ("GLM is less than 1/5 the price of Opus"). When practitioners use multiple models, each model is effectively a "skill" — and the security perimeter must handle heterogeneous trust levels across model providers.

Practitioner quotes: "it hallucinates things that it doesn't follow later on" — the integrity problem at the model-as-skill layer. "Chinese models optimize for benchmarks and do poorly in real-world tasks" — the ContractGuard problem: if the contract (benchmark) doesn't reflect reality, the gate is dishonest.
