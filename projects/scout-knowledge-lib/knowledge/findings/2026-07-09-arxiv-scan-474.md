# Scan #474: The Expressivity Boundary

**Date**: 2026-07-09
**Sources**: arXiv API (cs.FL, cs.CL, cs.AI)
**Previous**: The Balkanization Problem (#473), Sovereignty Escalation (XHS #74), Memory Loop Gap (#470)

## Theme

What does tool access actually buy an agent?

The question sounds philosophical, but three uncovered papers converge on a precise answer with profound implications for agent architecture design. A formal-languages paper proves a sharp dichotomy: finite-state tools add essentially nothing to a finite-precision recurrent model's computational power, but a single infinite-state tool — a tape supporting only read, write, and move — makes the system Turing complete. This theoretical result establishes the **minimum architectural requirement** for agents to transcend their base computational class. But a benchmarking paper on real-world data analysis demonstrates that having tools is necessary but nowhere near sufficient: state-of-the-art LLM agents with full agentic frameworks still fail dramatically on practical governmental data tasks. And a trajectory synthesis system (VLDB 2026) addresses the training-data bottleneck by generating high-quality agent trajectories via MCTS — acknowledging that the gap between theoretical capability and practical performance must be closed through better training data, not just better architectures.

**The Expressivity Boundary** names this gap: tool access determines the ceiling of what an agent *can* compute, but the floor of what it *actually* achieves is set by memory architecture (#470), training data quality, and task-specific grounding — none of which are guaranteed by architectural expressivity alone.

## Paper Analysis

### 1. When Does Tool Use Increase the Expressive Power of Finite-Precision Recurrent Models? (2607.06155v1) — THEORETICAL [UNCOVERED]

**Published**: 2026-07-07
**Source**: https://arxiv.org/abs/2607.06155
**Categories**: cs.FL, cs.CC, cs.CL
**Authors**: Zubić, Li, Wang, Scaramuzza

This paper provides the first exact, architecture-level account of when tool access changes what a sequence model can compute. The framing is precise: model any finite-precision recurrent model (including SSMs with B bits of state) as a deterministic finite-state controller interacting with an oracle through a finite command/observation interface.

**The sharp dichotomy:**

| Tool Type | Computational Effect | Cost |
|---|---|---|
| Finite-state tool (memory set M) | **Essentially nothing** — product-state simulation internalizes it | log₂\|M\| + O(1) additional bits |
| Single infinite-state tool (tape: read/write/move) | **Turing complete** | O(log\|Q\| + log\|Γ\|) bits |

**Key results:**
- **Finite tools are absorbable**: Any finite-state bounded-interface oracle can be internalized into the controller at a cost of only log₂|M| + O(1) additional bits. The augmented system remains finite-state. Tools that don't extend the state space beyond what the controller could represent are computationally inert.
- **A single tape suffices for Turing completeness**: For every single-tape Turing machine with state set Q and tape alphabet Γ, a controller with O(log|Q| + log|Γ|) bits simulates it. Concrete exponential separation: EQ_n requires 2^n states without tools but only a constant-size controller with the tape tool.
- **Selectivity is essential**: A natural one-layer finite-precision selective affine SSM controller with binary one-hot hidden states realizes the construction. Non-selective (time-invariant) controllers cannot achieve Turing completeness — **input-dependent state transitions are the mechanism**.
- **Logarithmic universal simulation**: O(log B) recurrent bits suffice to simulate any B-state Turing machine with tool assistance, with a matching impossibility result proving this is tight.

**Significance for agent architectures:**

This paper formalize what practitioners intuit: giving an LLM a calculator doesn't fundamentally change what it can compute (both are finite-state). But giving it a read-write scratchpad — persistent, addressable, unlimited — crosses the expressivity boundary. The result explains why memory-as-tool (#470) and scratchpad-augmented agents show qualitative capability jumps while prompt-engineering and finite-context tools show only quantitative improvements.

**Connection to the Memory Loop Gap (#470)**: The Memory Loop Gap showed that memory placement determines the proactivity ceiling. This paper explains *why* at the computational level: in-process memory that the agent can freely read and write constitutes an infinite-state tool, crossing the expressivity boundary. Network-accessed memory with bounded interface remains effectively finite-state from the controller's perspective during any single reasoning step.

**Connection to the Oversight Inversion**: If a single infinite-state tool makes an agent Turing complete, then any governance framework must account for the full space of computable functions, not just the observed behaviors. The expressivity boundary is also a governance boundary: finite-tool agents are containable by finite verification; Turing-complete agents are not (by Rice's theorem).

### 2. DataGovBench: Data Analysis in the Wild (2607.06482v1) — BENCHMARK [UNCOVERED]

**Published**: 2026-07-07
**Source**: https://arxiv.org/abs/2607.06482
**Categories**: cs.CL, cs.AI
**Authors**: Hasegawa, Sampat, Liu, Chen

DataGovBench introduces a benchmark derived from real governmental open data to evaluate LLMs on practical data analysis. The benchmark exposes two tasks current systems fail at:

1. **Table QA**: Solving complex decomposable questions over large multi-tabular datasets, producing textual answers or visualizations.
2. **Table Insight**: Generating expert-level findings through exploratory data analysis — not answering specific questions, but *discovering what's interesting*.

**Key finding**: Comprehensive experiments with state-of-the-art LLMs, both with and without agentic frameworks, reveal **significant performance gaps across both tasks**. Current LLM-based systems "remain far from satisfying the demands of real-world data analytics."

**Why this matters — the Expressivity Gap in practice:**

DataGovBench demonstrates the gap between Tool Use Expressivity (paper #1 above) and actual agent performance. The agents have tool access. They have agentic frameworks. They are, in principle, Turing complete. Yet they fail at tasks that require:
- **External knowledge integration** — the data alone isn't sufficient; you need domain context
- **Multi-tabular reasoning** — joining evidence across tables requires structured planning
- **Exploratory insight discovery** — generating hypotheses rather than answering fixed questions

This maps directly to the Knowledge Erosion (#450): agents lack the domain expertise that human analysts bring, and no amount of tool access compensates for missing knowledge. The Formalization Horizon predicts this: tasks that resist formalization into precise tool invocations remain beyond agent capability even with perfect tool infrastructure.

**Connection to the Evaluation Mirage**: Real-world benchmarks consistently show lower performance than synthetic benchmarks. DataGovBench is another data point confirming that evaluation on curated, well-structured tasks overestimates real-world capability. The insight discovery task (Table Insight) is particularly revealing: it requires the agent to decide *what to look for*, a capability that benchmarks with pre-specified questions never test.

### 3. TOFFEE: Synthesizing Data Agent Trajectories at Scale (2607.06233v1) — SYSTEM [UNCOVERED]

**Published**: 2026-07-07 (Accepted to VLDB 2026)
**Source**: https://arxiv.org/abs/2607.06233
**Categories**: cs.AI
**Authors**: Wang, Li, Yang, Li, Bai, Cong

TOFFEE addresses the training-data bottleneck for data agents. Data agents struggle to generalize to unseen data environments and analytical workflows, especially in heterogeneous enterprise settings. TOFFEE synthesizes high-quality trajectories via three mechanisms:

1. **Monte Carlo Tree Search (MCTS)**: Explores the trajectory space systematically rather than greedily, finding high-quality action sequences that greedy generation misses.
2. **Adaptive model selection**: Uses different models for different parts of the trajectory based on a learned cost model — not every step needs the most expensive model.
3. **Cross-task prefix reuse**: When multiple tasks share early trajectory steps (e.g., same data loading, same schema exploration), TOFFEE reuses the prefix rather than regenerating it, reducing cost and improving consistency.

**Two downstream uses:**
- **SFT data**: Trajectories as supervised fine-tuning data to adapt agent models to target domains.
- **ICL demonstrations**: Trajectories as in-context learning examples to guide general-purpose LLMs in unfamiliar data environments.

**Significance — the training data is the architecture:**

TOFFEE's VLDB acceptance signals that the database community recognizes trajectory synthesis as a first-class systems problem, not just an ML afterthought. The cross-task prefix reuse mechanism is architecturally significant: it acknowledges that agent trajectories have structural redundancy that can be exploited at the system level.

**Connection to CurateEvo (#465)**: CurateEvo treats data curation as executable code that evolves based on failure analysis. TOFFEE treats trajectory synthesis as a search problem solvable by MCTS. Both reject the fixed-preprocessing assumption: training data for agents must be dynamically generated and adapted, not scraped and frozen.

**Connection to the Compounding Gap (#465)**: TOFFEE's adaptive model selection implicitly addresses compounding: by choosing the right model for each step, it prevents early low-quality decisions from compounding into trajectory-level failure. The cross-task prefix reuse further reduces compounding by ensuring shared early steps are high-quality.

## Synthesis: The Expressivity Boundary

The three papers form a coherent argument:

1. **The ceiling is set by architecture** (2607.06155): Tool access determines the maximum computational class an agent can reach. A single infinite-state tool is sufficient for Turing completeness. This is a necessary condition.

2. **The floor is set by grounding** (2607.06482): Even with Turing-complete tool access, agents fail on real-world tasks requiring domain knowledge, multi-source reasoning, and hypothesis generation. Expressivity is not capability.

3. **The bridge is training data** (2607.06233): High-quality trajectories, systematically generated and structurally de-duplicated, narrow the gap between theoretical expressivity and practical capability.

**The Expressivity Boundary** is the gap between what an agent *can compute in principle* (determined by tool architecture) and what it *actually achieves* (determined by memory placement, training data, domain grounding, and evaluation quality). Previous scans identified components of this gap:
- Memory Loop Gap (#470): memory placement determines the proactivity ceiling
- Compounding Gap (#465): errors compound across pipeline stages
- Knowledge Erosion (#450): agents lack human knowledge byproducts
- Evaluation Mirage: benchmarks overestimate real-world capability

This scan names the gap itself and establishes its theoretical lower bound: no amount of engineering can make a finite-state-tool-augmented agent do what requires infinite state, and no amount of infinite-state tool access guarantees practical competence.

**Implication for agent design**: The minimum viable agent architecture requires at least one infinite-state tool (persistent read-write memory). But crossing the expressivity boundary is only step one. Steps two through N involve memory architecture (#470), training data quality (TOFFEE), domain grounding (DataGovBench), and process governance (Oversight Inversion).
