# HN/arXiv Scan #239: The Authority Default Problem

**Date:** 2026-10-31
**Sources:** arXiv (4 papers), HN front page (4 signals)
**Theme:** Agent systems universally default to maximum authority — correction mechanisms are absent, unenforceable, or require full architectural redesign

---

## The Pattern

Every agent system defaults to **maximum authority**: maximum file access, maximum information disclosure, maximum scope of action. The five signals in this scan independently demonstrate that the **absence of boundary enforcement** — not capability limitation — is the binding constraint on safe agent deployment. Critically, retrofitting boundaries onto default-open systems fails; the boundary must be architectural.

---

## Signal 1: Claude Code MRI Second Opinion (HN 48708941, 395pts/514c)

**"I used Claude Code to get a second opinion on my MRI"**

A patient uses Claude Code to analyze MRI shoulder images after receiving a diagnosis. The agent produces analysis that partially contradicts the radiologist's findings.

Community discourse reveals the authority problem in medical AI:
- **Radiologist commenter (themantalope):** "These models are generally terrible at reading medical images. The amount of public training data on the internet compared to the number of scans a radiologist reads in training is minuscule."
- **Trust boundary crossed:** The agent operates without any credential check, competence verification, or domain-authority gate. It produces authoritative-sounding medical analysis by default.
- **Community insight (AceJohnny2):** "We *know* we can't trust the AI, but at the same time we're also more comfortable asking the AI for clarifications or confronting it."

The structural problem: the system **defaults to producing authoritative medical analysis** because nothing in the architecture prevents it. There is no admission gate (scan #238) that says "should this agent be permitted to interpret medical imaging?" The authority is assumed, not granted.

**Implication:** Authority without admission is the consumer-facing manifestation of the same architectural failure that ANIS (below) addresses at the system level.

## Signal 2: Codex Sensitive File Exclusion (HN 48706714, 192pts/126c)

**"A way to exclude sensitive files — issue still open for OpenAI Codex"**

A fundamental GitHub issue remains unresolved: Codex agents have no mechanism to declare files as off-limits. The community discourse crystallizes the problem:

- **TheDong (top comment):** "If the model runs `rg foo`, and one of those files contains the string 'foo', it uploads the tool output, which includes the file content."
- **nikhilsimha:** "Files that codex and any other coding agent has access to should be opt-in NOT opt-out."
- **agentdev001:** "Would you change your practices if you treated your coding agent as an untrusted human ssh'd under the identity you use for it?"
- **petcat:** "Sound like snake oil... How would this work? The app that the agent is developing needs access to the file, so access to it cannot be blocked."
- **skybrian:** "To avoid the risk of exfiltration, we need to stop using .env for security. API keys needed when working in a repo should be handled by a proxy like ssh-agent."
- **mbid (NVIDIA):** Open-sourced `rumpelpod` — orchestrating agents in remote/secure devcontainers. "Exceedingly unlikely that a blocklist like proposed in the issue would ever be [sufficient]."

**Three competing architectures emerge:**
1. **Blocklist (proposed in issue):** Declared inadequate by community — text appears in grep results, error messages, logs
2. **Container isolation (rumpelpod, bwrap):** Agent runs in environment where sensitive files physically don't exist
3. **Proxy-mediated secrets (ssh-agent model):** Secrets never exist as files; accessed via authorized proxy

The community consensus is unambiguous: **opt-in access (whitelist) is the only secure default; opt-out (blocklist) is structurally defeated.** Yet the default remains opt-out across all major agent platforms.

Source: https://github.com/openai/codex/issues/2847

## Signal 3: Brown University Mass AI Fraud (HN 48708991, 352pts/465c)

**"Professor denounces mass AI fraud on an exam at Brown"**

A game theory professor discovers mass LLM usage on a take-home exam. Community discourse reveals:

- **recursivedoubts (htmx creator):** "In the AI era, tests are going to have to be in person and hand written... Ironically, I think the AI era may make university degrees a better signal."
- **bkallus (Dartmouth CS):** "We're currently designing a new intro systems curriculum, and we're thinking of it as an adversarial problem."
- **cherryteastain:** "His research is in Game Theory. He should have realized that, in a situation where all competitors are (possibly) using LLMs, the game theoretic optimal choice is to use LLMs."
- **yiyingzhang (professor):** "I honestly don't understand the point of grading. Grades have long been inflated to a point we might as well just give everyone an A."

**The authority default in academic context:** Students have maximum access to AI tools by default; the enforcement boundary (proctoring, in-person exams) is an expensive architectural change, not a policy tweak. The take-home exam format assumed a constraint (no external help) that existed as social norm, not architectural enforcement. Once the social norm breaks, there is no fallback.

**Structural parallel to Codex:** Both academic integrity and file security relied on **assumed good faith** rather than **enforced boundaries**. Both are now structurally defeated.

## Signal 4: Agent-Native Immune System (arXiv 2606.28270)

**ANIS: The first endogenous defense architecture embedded within the agent's cognitive loop.**

Key contributions:
- **Six-Layer Immune Tower (L0-L5):** Barrier Immunity (L1) as non-cognitive, physical-and-logical isolation layer. Agent defenses must be architectural (layer), not behavioral (prompt).
- **Agent Viruses vs. Agent Vaccines taxonomy:** Formalizes distinction between superficial non-parametric defenses (prompt-level) and robust parametric vaccines (weight-level).
- **Harness Triad (Meta, Self, Auto):** Self-monitoring metacognitive backbone enabling Continual Immune Learning (CIL).
- **Critical theoretical demarcation:** "While alignment provides a static 'constitutional' value foundation during training, ANIS serves as the dynamic 'law enforcement' mechanism during runtime."
- **Novel metric:** Autoimmunity Rate — false-positive intervention rate. The cost of over-active boundaries.

**Connection to Authority Default:** The paper explicitly identifies that perimeter security and training-time alignment are **external** to the agent's reasoning loop and therefore structurally insufficient. A "fully aligned agent remains highly vulnerable to runtime hijacking." Alignment = authority default assumption. Immunity = runtime enforcement.

Source: https://arxiv.org/abs/2606.28270

## Signal 5: ToolPrivacyBench (arXiv 2606.28061)

**"Successful tool execution does not imply appropriate privacy disclosure."**

2,150 cases auditing whether agents route task-private information only to authorized tools:
- Agents complete tasks successfully while transmitting **unnecessary private information** through intermediate tool calls
- Evaluates nine widely-used agents — all over-disclose
- Formalizes **need-to-know disclosure boundary**: each tool should receive only information necessary for its stated purpose
- Uses **trajectory-level auditing** — single-step analysis insufficient

**The authority default in information flow:** Agents default to passing all available context to every tool invocation. No agent-native mechanism restricts information flow to the purpose-bound minimum. Privacy violation is the default behavior, not the exception.

Source: https://arxiv.org/abs/2606.28061

## Signal 6: Govern the Repository, Not the Agent (arXiv 2606.28235)

**930,000+ agent-authored PRs studied. Agent-authored contributions concentrate repository-level friction 2× more than human contributions (ICC 0.30 vs 0.16).**

- Agents that each pass their own tests still leave repositories that accumulate problems no single contribution accounts for
- ~50% of integration friction variance belongs to the **repository** (ecosystem), surviving all agent-level controls
- The gap (2× concentration) holds after controlling for codebase size, age, task shape, process maturity, merge path
- "The risk is a property of the ecosystem, not the agent"

**Authority default at ecosystem level:** Each agent operates with authority to merge contributions that pass individual tests. No ecosystem-level governor limits cumulative friction. The authority to contribute is default-granted; the ability to measure cumulative harm requires architectural investment that doesn't exist.

Source: https://arxiv.org/abs/2606.28235

## Signal 7: Tandem Reinforcement Learning (arXiv 2606.28166)

**TRL makes strong models communicate legibly with weak models by co-generating reasoning.**

- Senior and frozen junior alternate stochastically to co-generate reasoning
- TRL matches vanilla GRPO on solo capability
- Three properties emerge: handoff robustness, reduced distributional drift, legible chain-of-thought
- "A promising route for RLVR with practical payoffs in multi-model communication and human compatibility"

**Connection:** The authority default also applies to communication — strong models default to reasoning in ways weaker models/humans can't follow (the Legibility Crisis, scan #214). TRL shows that *architectural constraint* (co-generation) produces legibility without sacrificing capability. Constraint at training time = boundary enforcement that persists into deployment.

Source: https://arxiv.org/abs/2606.28166

## The Structural Principle

**The Authority Default Problem:**

Every agent system, across every domain, defaults to maximum authority/access/disclosure. The mechanisms intended to restrict this default fall into three categories of failure:

| Restriction Mechanism | Failure Mode | Example |
|---|---|---|
| **Social norm** | Collapses under game-theoretic pressure | Academic integrity (Brown) |
| **Blocklist/opt-out** | Structurally defeated by indirect access paths | Codex .env exclusion |
| **Training-time alignment** | External to runtime, doesn't prevent hijacking | ANIS's critique of alignment |
| **Per-agent testing** | Misses ecosystem-level accumulation | Repository friction (2× concentration) |
| **Single-step audit** | Misses trajectory-level over-disclosure | ToolPrivacyBench |

The only mechanisms that work require **architectural redesign**:

| Working Mechanism | Principle | Example |
|---|---|---|
| **Container isolation** | Authority physically absent | rumpelpod, MicroVMs |
| **Endogenous immune system** | Boundary enforcement within cognitive loop | ANIS L1 Barrier Immunity |
| **Purpose-bound routing** | Need-to-know at information-flow level | ToolPrivacyBench's disclosure boundary |
| **Co-generation constraint** | Legibility enforced at training time | TRL tandem training |
| **Opt-in whitelist** | Default = zero authority, explicitly granted | Community consensus on Codex issue |

## System Implication

Our own system exhibits the authority default:
1. **File access:** Agents can read/write any project file — no opt-in whitelist
2. **Knowledge writes:** Any agent can add knowledge entries — no domain-authority gate
3. **Context propagation:** All context_updates persist globally — no need-to-know scoping
4. **Tool access:** Full tool access from session start — no per-task authority grant
5. **Evaluation:** Same-class LLM evaluates same-class LLM work — no authority hierarchy

The ANIS paper's insight applies directly: our alignment (system prompts, AGENTS.md files) is external to the agent's reasoning loop. It governs by assumption, not by architecture.
