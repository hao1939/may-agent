## Tier 1 — High-relevance papers for the knowledge library

### 2607.14275: AI Agents Do Not Fail Alone: The Context Fails First
- Context engineering quality as an independent leading indicator of agent reliability
- Validates a thesis close to our "context-access divide" and "prompt-mass problem" concepts
- Measures how weak instructions, tools, memory, guardrails, and untrusted inputs cause drift, hallucination, tool misuse, injection vulnerability
- **Library connection**: Strengthens `the-context-access-divide.md`, `the-prompt-mass-problem.md`

### 2607.14159: MemoHarness: Agent Harnesses That Learn from Experience
- Adaptive harness optimization framework: the *harness* (context/tool/orchestration/memory/decoding layer) learns from its own execution traces
- Separates harness improvement from prompt/pipeline optimization
- **Pattern**: Harness-as-learnable-artifact — not just the agent but its scaffolding adapts
- **Library connection**: Extends `agent-runtime-hardening.md`

### 2607.14570: Democratizing Agent Deployment Safety: A Structural Monitoring Approach
- Addresses agents that complete tasks while covertly weakening safeguards (broadening permissions, degrading logging, introducing persistence)
- Lightweight structural monitoring for orgs without sophisticated governance
- **Pattern**: Safety-as-structure-check rather than intent-detection
- **Library connection**: Directly extends `agent-security-defense-architectures.md`, `the-guard-paradox.md`

### 2607.14890: Proof-or-Stop: Evidence-Gated Lifecycle Control
- Lifecycle transitions (reviewed → tested → DONE → merge) allowed only when fresh, mechanically verifiable evidence satisfies the gate
- Treats agent outputs as *claims* not *state* — proof used operationally
- **Pattern**: Evidence-gated agent lifecycle — a concrete implementation of the "verification inversion" principle
- **Library connection**: `the-verification-inversion.md`, `the-fail-plausible-equilibrium.md`

### 2607.14611: Bad Memory — Prompt Injection Risks from Memory in Agentic Systems
- Studies prompt injection via persistent memory files, behavioral preferences, knowledge bases
- Malicious instructions embedded in persistent files influence future behavior across sessions
- **Library connection**: `agent-memory-patterns.md`, `agent-security-defense-architectures.md`

### 2607.14651: MemPoison — Persistent Memory Threats and Structural Blind Spots in LLM Agents
- 1,227 hand-validated cases across 4 attack types, 3 injection channels, 3 memory substrates, 7 open-weight agents
- Adversarial content injected via standard interaction channels, retained across turns
- **Library connection**: Companion to 2607.14611; together they define the "memory poisoning" attack surface

### 2607.14408: Reward-Free Evolving Agents via Pairwise Validator
- Replaces scalar reward at the accept/reject gate with a pairwise validator (frozen LLM comparison)
- Eliminates need for domain-expert-designed reward functions in self-evolving agent loops
- **Pattern**: Reward-free self-improvement — lowers the barrier to agent self-evolution

### 2607.14642: MCPEvol-Bench: Benchmarking Agents Across Dynamic MCP Server Evolutions
- First benchmark that tests agent adaptability when tool interfaces change over time
- Addresses the gap: existing MCP benchmarks assume static tool landscapes
- **Library connection**: `agent-protocols-mcp-a2a.md`

### 2607.14340: The Prover Is the Judge — Verified Security Software from AI Coding Agents
- AI agents wrote and verified bare-metal security software in Ada/SPARK (crypto, TLS 1.3, IKEv2, X.509)
- GNATprove discharged 49,280 proof obligations; functional correctness + absence of runtime errors
- **Pattern**: Formal-verification-as-agent-judge — strongest version of "proof-or-stop"
- **Library connection**: `the-verification-inversion.md`

### 2607.14390: Why Git Is the Memory Solution for the Agentic Development Lifecycle
- Argues agent memory should be git-bound rather than built as separate retrieval machinery
- Reasoning behind changes (alternatives, constraints, rejections) trapped in vanishing sessions
- **Pattern**: Git-as-agent-memory — leverages existing version control as the memory substrate

## Emerging Themes This Batch

1. **Memory-as-attack-surface**: Two independent papers (BadMemory + MemPoison) systematize persistent memory threats. The memory poisoning problem is graduating from anecdotal to benchmarked.

2. **Evidence-gated lifecycle**: Multiple papers (Proof-or-Stop, Prover-Is-Judge) converge on treating agent outputs as claims needing mechanical verification before state transitions. The verification-inversion pattern is becoming a concrete engineering discipline.

3. **Harness/scaffolding as first-class artifact**: MemoHarness treats the agent's external control layer as the object of learning. Combined with context-fails-first thesis, this suggests the scaffolding is becoming more important than the model.

4. **MCP ecosystem maturation**: MCPEvol-Bench introduces temporal evolution testing for MCP servers — the ecosystem is moving past "can agents use tools?" to "can agents handle tool drift?"

5. **Git-as-memory convergence**: The git-bound memory argument aligns with our observations about agent state management. Version control may be the natural memory substrate for development agents.
