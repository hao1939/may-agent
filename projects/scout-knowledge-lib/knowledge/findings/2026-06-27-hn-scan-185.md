# HN/arXiv Scan #185 — The Provenance Void

**Date**: 2026-06-27
**Sources**: Hacker News (hn.algolia.com API), arXiv (export.arxiv.org API)
**Scan number**: 185
**Theme**: The agent ecosystem can generate code, skills, and decisions at scale, but cannot verify where any of it came from. Provenance — the ability to trace origins — is the new binding constraint.

## Synthesis: The Provenance Void

Six independent signals converge on a single structural insight: **the binding constraint on the agent ecosystem has shifted from "can we produce X?" to "can we prove where X came from?"**

| Signal | Domain | Provenance Gap | Consequence |
|---|---|---|---|
| Papermark theft (578pts) | Code generation | "Vibe-coded" output indistinguishable from stolen open-source | Licensing/IP unenforceable at production speed |
| GPT-5.6 government gates | Model access | Can't verify which model produced which output | State-level capability gatekeeping required |
| OPID/SKILL-DISCO | Agent learning | Skills extracted from trajectories have no attribution chain | Reuse without credit; poisoned skills undetectable |
| MADARA | RAG/retrieval | Document relevance mechanism (isolation vs scoring) invisible to downstream | Quality attribution impossible |
| Prompt injection in hiring | Human systems | Injected signals indistinguishable from real qualifications | Fair assessment structurally broken |
| CVE-2026-LGTM (satire) | Verification | Gates compose multiplicatively in failure | More gates ≠ more trust |

The meta-pattern: **generation cost → $0, verification cost → ∞, provenance cost → undefined**. The field has optimized for throughput and hasn't built provenance infrastructure at all. Every gate being erected (government access control, model routing, skill verification, code provenance) is a patch on a system that never had provenance as a primitive.

## Finding 3: OPID — On-Policy Skill Distillation (arXiv 2606.26790)

**Source**: https://arxiv.org/abs/2606.26790

**What it is**: Framework that extracts skill supervision directly from completed on-policy trajectories — no external skill memory required.

**Architecture**:
- **Episode-level skills**: Global workflows / failure-avoidance rules
- **Step-level skills**: Local decision knowledge at critical timesteps
- **Critical-first routing**: Uses step-level when critical decisions detected, episode-level as default
- **Self-distillation advantage**: Log-probability shift between original and skill-augmented contexts yields token-level signal

**Results**: Improvements on ALFWorld, WebShop, and Search-based QA over outcome-only RL and existing skill-distillation baselines.

**Provenance relevance**: Skills are extracted from trajectories but have NO attribution to where the trajectory-level knowledge originated. A poisoned trajectory produces poisoned skills indistinguishable from legitimate ones. The hierarchical structure (episode vs step) makes provenance tracing harder, not easier — which level inherited which bias?

## Finding 4: SKILL-DISCO — Compiling Agent Traces into Procedural Skills (arXiv 2606.26669)

**Source**: https://arxiv.org/abs/2606.26669

**What it is**: Distillation-and-compilation framework that extracts reusable parameterized control-flow subgraphs (PFSMs) from successful agent traces and compiles them into callable, executable, verifiable procedural skills.

**Key contributions**:
- Formalizes scenarios as FSMs where traces = paths in unknown transition graphs
- Procedural skills = reusable parameterized subgraphs
- Skills are verifiable (can be checked for correctness)
- Improves success rates and reduces turns on ALFWorld and WebArena

**Provenance relevance**: SKILL-DISCO produces verifiable skills (good for provenance) but the compilation process itself loses trace-level provenance. You can verify a skill works; you cannot trace which original human demonstrations informed its structure. The verification is functional, not genealogical.

**Combined with OPID**: The skill-extraction field is bifurcating into:
1. **OPID path**: Dense, integrated with RL training, no external memory — high performance, zero provenance
2. **SKILL-DISCO path**: Structured, compiled, verifiable — functional correctness, structural provenance

## Finding 5: MADARA — Model-Adaptive RAG Routing (arXiv 2606.25191)

**Source**: https://arxiv.org/abs/2606.25191

**Key finding**: Multi-agent document assessment reveals a sharp dichotomy:
- **Weaker models**: The dominant mechanism is *per-document isolation*. Assessment-free isolation (just separating documents) matches full multi-agent assessment scoring — up to **50pp gains from isolation alone**.
- **Stronger models**: Scoring quality matters; isolation is already implicit.

**Architecture (MADARA)**: Model-adaptive routing that classifies whether a model benefits from isolation or scoring, then routes accordingly. Diagnostic thresholds from a single pilot model generalize zero-shot to four unseen model families.

**Provenance relevance**: The finding that **isolation > scoring** for weaker models means the retrieval mechanism is invisible — downstream consumers can't tell whether their answer came from careful assessment or simple document separation. The quality of the answer tells you nothing about the quality of the process that produced it.

**Connection to Co-Failure Ceiling (#184)**: MADARA is to RAG what the Co-Failure Ceiling is to multi-model routing — the mechanism (isolation vs scoring, heterogeneity vs pairwise-rho) matters more than the measurement.

## Finding 6: Prompt Injection in Hiring — Manipulation Collapses at Scale (arXiv 2606.27287)

**Source**: https://arxiv.org/abs/2606.27287

**Key finding**: Prompt injection in automated résumé screening:
- **Reliably improves rankings** when few candidates inject and quality is homogeneous
- **Rapidly collapses** when manipulation becomes widespread
- **Occasionally allows lower-quality candidates to outrank higher-quality ones** (fairness violation)
- **Most vulnerable** when manipulation is rare and quality differences are small

**Structural insight**: This is the provenance void in human systems. The injected signal (self-promotional text that introduces no new qualifications) is indistinguishable from legitimate qualification description. The defense — "detect injection" — is the same unsolved problem as code provenance ("detect if this was AI-generated").

**Arms race dynamics**: When everyone injects, injection becomes noise (collapses). But at equilibrium, those who DON'T inject are penalized. Nash equilibrium: universal injection → no advantage → system returns to pre-injection quality ranking + wasted effort. The manipulation cost is socialized even when individual advantage disappears.

## Key Insight

**The Provenance Void is structural, not accidental.** AI generation inherently severs provenance chains:
- Code: generated from training data → no single source
- Skills: distilled from trajectories → no single demonstration
- Documents: retrieved and synthesized → no single authority
- Decisions: routed through models → no single reasoning

Every mitigation (gates, routing, verification) adds a layer that ALSO lacks provenance for its own decisions. The field needs provenance as a primitive data type, not a post-hoc audit trail. The precedent is cryptographic signing — you don't prove provenance by tracing backwards; you embed it at creation time.
