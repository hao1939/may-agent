# HN Scan #145: The Harness Primacy Proof

**Scan date**: 2026-06-27
**Scan number**: 145
**Synthesis**: #31 — The Harness Primacy Proof

## Core Thesis

Eight independent June 2026 papers + coordinated HN front page signals constitute the formal quantitative proof that **agent harness design is the binding variable, not model capability**. The Substrate Inversion (#23) described the *direction* — intelligence migrating from model to architecture. This scan documents the *proof phase*: independent teams with no coordination have quantified the dominance of harness over model across performance, security, governance, and longevity dimensions.

## Primary Evidence

### 1. StaminaBench (2606.19613): The 6× Harness Gap

**What it shows**: 100-turn coding sessions, 6 harnesses × 7 models. ALL models fail within 5-6 turns without harness support. With harness: 12× improvement. Key finding: **stronger models exhibit up to a 6× gap between their best and worst harness** — meaning harness choice creates more variance than model choice.

**Why it matters**: This is the first benchmark that measures what production agents actually do (multi-turn, long sessions) rather than single-shot tasks. It proves model capability is necessary but NOT sufficient — and harness quality is the multiplier.

Source: https://arxiv.org/abs/2606.19613

### 2. Looking Is Not Picking (2606.16364): The Readout Bottleneck

**What it shows**: When LLM agents mis-call tools, the model attends to the correct tool **80% of the time** (vs 21% chance). The failure is at the decision readout, not perception. Harness-side interventions recover **59-91% of failures** vs prompt-side only ≤23%. Two gold-pointed interventions in different representations recover the same failures (Jaccard 0.865), localizing the bottleneck to the harness-model boundary.

**Why it matters**: Directly refutes the "crowded harness" explanation. The model SEES correctly but ACTS incorrectly — the gap is at the boundary where harness meets model, and the fix must be harness-side.

Source: https://arxiv.org/abs/2606.16364

### 3. Position: Coding Benchmarks Are Misaligned (2606.17799)

**What it shows**: "A coding agent is not a model: it is a system harness — a composite of models, harnesses, contexts, environments, and feedback signals, any one of which can move the benchmark score by margins comparable to those between adjacent model generations." Three formal symptoms: scores conflate model with harness, single-reference grading penalizes valid alternatives, no component-level signal.

**Why it matters**: The evaluation infrastructure itself encodes the wrong assumption (model=agent). Until benchmarks decompose into harness-level components, the field cannot systematically improve.

Source: https://arxiv.org/abs/2606.17799

### 4. LemonHarness (2606.24311): The Runtime Boundary

**What it shows**: Unified execution boundary (workspace constraints + rule knowledge base + time-aware execution) reaches 84.5-86.5% on Terminal-Bench 2.0. Key mechanism: state-changing operations through structured tool interfaces with execution feedback as observations. Time-awareness lets the agent rebalance exploration/implementation/validation as budget shifts.

**Why it matters**: Proves three harness primitives — workspace boundary, callable rules, time awareness — are individually measurable and independently contribute. The harness is decomposable, not monolithic.

Source: https://arxiv.org/abs/2606.24311

### 5. Code-Augur (2606.18619): Harness > Model Specialization

**What it shows**: Security-specification-first harness for vulnerability detection. Exposes agent's tacit assumptions as assertions, uses guided fuzzer to falsify them. **Outperforms Claude Mythos** (a curated specialized model) using general LLMs (Sonnet, DeepSeek). Found 22 new vulnerabilities in key open-source projects.

**Why it matters**: The strongest possible proof of harness primacy — a general model with a well-designed harness beats a *specialized model*. The specification-inference harness does what model specialization cannot: ground understanding against runtime reality.

Source: https://arxiv.org/abs/2606.18619

### 6. Red-Teaming the Agentic Red-Team (2606.24496): Security is Architecture

**What it shows**: First in-depth security analysis of widely-used agentic offensive security tools. Common design flaws enable API key exfiltration, persistent footholds, and full machine compromise — **even when the agent operates inside a sandboxed container**. Introduces full cyber kill chain for agentic systems.

**Why it matters**: The most capable offensive AI agents are themselves vulnerable — not because of model weakness but because of harness design flaws. Security is a structural property of the harness, not a capability of the model. The kill chain is architectural, not cognitive.

Source: https://arxiv.org/abs/2606.24496

### 7. Harness-MU (2606.21856): Governance is Infrastructure

**What it shows**: First model-agnostic, zero-tuning framework for multi-user LLM agents. Decouples language generation from safety orchestration. Achieves +0.28-0.39 utility score improvement and +48.9pp instruction-following accuracy. Governance constraints (who, what, precedence) enforced by execution hooks, not model behavior.

**Key insight**: "Governance constraints are deterministic runtime variables that should be enforced by execution hooks rather than entrusted to the LLM." This is the formal proof of what The Compilation Gradient described as soft→hard migration.

Source: https://arxiv.org/abs/2606.21856

### 8. RIFT-Bench (2606.23927): The Architecture IS the Attack Surface

**What it shows**: Graph-representation-driven methodology for dynamic red-teaming. Evaluated 45 agentic systems. Uses hierarchical representation for automated discovery and adaptive adversarial scanning. Attack vectors target system structure, not model weights.

**Why it matters**: Security evaluation of agents requires understanding their *architecture*, not their *model*. 45 systems, all with different models, share common architectural vulnerability classes.

Source: https://arxiv.org/abs/2606.23927
