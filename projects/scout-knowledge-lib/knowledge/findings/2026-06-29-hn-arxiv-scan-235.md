# Scan #235: The Governance Locus Problem

**Date**: 2026-10-30
**Sources**: arXiv, HN
**Theme**: Individual-agent governance is structurally insufficient — the locus of control must shift to the ecosystem, trajectory, and environment level

---

## Thesis

Five independent research streams published in the same week converge on one structural finding: **governing individual agents cannot produce governed systems**. The risk, the privacy leakage, the temporal failure, the friction, and the attack surface all live at a level of organization ABOVE the individual agent. The field's dominant paradigm — evaluate one agent, align one agent, contain one agent — produces misleading confidence.

---

## Signal Cluster

### Signal 1: Integration Friction Is a Repository Property (arXiv 2606.28235)

**"Govern the Repository, Not the Agent: Measuring Ecosystem-Level Risk in AI-Native Software"**

Across **930,000+ agent-authored pull requests**:
- About **half** of integration friction variance remains with the REPOSITORY after controlling for contribution, author, size, and agent
- Agent-authored contributions concentrate repository-level friction **2× more** than human ones (intraclass correlation 0.30 vs 0.16)
- Gap holds after controlling for codebase size, age, task shape, process maturity, and merge path
- "The risk is a property of the ecosystem, not the agent"

**Key finding**: Agents that individually pass their tests still leave repositories accumulating problems no single contribution accounts for. This is a COMPOSITION phenomenon invisible to per-agent evaluation.

Source: https://arxiv.org/abs/2606.28235

### Signal 2: Endogenous Defense > Exogenous Containment (arXiv 2606.28270)

**"Agent-Native Immune System: Architecture, Taxonomy, and Engineering"**

First biologically-inspired endogenous defense architecture (ANIS). Key contributions:
- **Six-layer Immune Tower** (L0-L5): Barrier Immunity (L1) as non-cognitive physical/logical isolation
- **Virus/Vaccine taxonomy**: Distinguishes superficial non-parametric defenses from robust parametric vaccines
- **Harness Triad** (Meta, Self, Auto): Self-monitoring + meta-cognitive automation for Continual Immune Learning (CIL)
- **Alignment ≠ Immunity**: Alignment = static "constitutional" foundation (training-time). Immunity = dynamic "law enforcement" (runtime)

**Critical insight**: Perimeter security and training-time alignment are EXTERNAL to the agent's reasoning loop. A fully aligned agent remains vulnerable to runtime hijacking via memory poisoning, tool-chain manipulation, or multi-agent protocol attacks. Defense must be endogenous — inside the cognitive loop, not around it.

New metric proposed: **Autoimmunity Rate** — false-positive intervention rate (defense harming legitimate function).

Source: https://arxiv.org/abs/2606.28270

### Signal 3: Memory Maintenance ≠ Comprehension (arXiv 2606.27472)

**"Supersede: Diagnosing and Training the Memory-Update Gap in LLM Agents"**

On knowledge-update subset of LongMemEval:
- Full context → bounded self-maintained memory: **92% → 77%** accuracy (frontier model, gpt-5.4)
- Gap is statistically significant (paired McNemar p<0.005)
- **Persists across model scale** — full-context accuracy saturates at 92%; stronger models don't close the gap
- As conversation grows **24×**, accuracy: **68% → 28%**
- Granting proportionally more memory: **28% → 28%** (zero recovery)
- Failure scales with conversation LENGTH, not compression ratio

**The bottleneck is memory maintenance, not comprehension.** First RL environment (on verifiers/prime-rl stack) that rewards temporal fact-currency. GRPO fine-tuning Qwen2.5-3B nearly doubles supersession accuracy (9.0% → 16.7%).

**System implication**: Our knowledge library (490+ files) faces this exact problem — superseded facts that individual agents cannot self-detect regardless of model capability.

Source: https://arxiv.org/abs/2606.27472

### Signal 4: Task Completion ≠ Privacy Compliance (arXiv 2606.28061)

**"ToolPrivacyBench: Benchmarking Purpose-Bound Privacy in Tool-Using LLM Agents"**

2,150 cases auditing purpose-bound information flow across multi-tool trajectories:
- **Successful tool execution does NOT imply appropriate privacy disclosure**
- Agents complete tasks while transmitting unnecessary private information through intermediate tool calls
- Neither function-calling benchmarks (task focus) nor privacy benchmarks (response focus) capture purpose-bound flow
- Formalizes "need-to-know disclosure boundary" — each tool should receive ONLY information necessary for its stated purpose
- Uses **trajectory-level auditing** against a policy knowledge base

**Key finding**: Privacy is not a property of any single tool call — it's a property of the TRAJECTORY of information across all calls. Per-tool evaluation structurally misses over-disclosure.

Source: https://arxiv.org/abs/2606.28061

### Signal 5: Authority Opacity in Existing Artifacts (arXiv 2606.21877)

**"AgentRiskBOM: A Risk-Scoping Security Bill of Materials for Agentic AI Systems"**

Evaluated on 13 open-source agents + 52 risk scenarios across 14 categories:
- Coverage: AgentRiskBOM **14/16** capability dimensions vs SBOM **1**, AIBOM **1.5**, MLBOM **2**
- Risk visibility: AgentRiskBOM **100%** vs SBOM-like **10.5%**, AIBOM-like **20.9%**
- Diff detector catches **all 33** structured deployment mutations (authority drift detection)
- Spearman correlation 0.73 between penalty-based and primary scorer (rank consistency)
- Fields added: autonomy, tool permissions, memory, credential scope, approval gates, audit signals, inter-agent communication, external action capability

**Key finding**: Existing transparency artifacts leave an "agentic transparency gap" — capability opacity regarding what an agent can access, remember, change, delegate, and prove afterward. 89% of risk categories invisible to traditional BOMs.

Source: https://arxiv.org/abs/2606.21877

### Signal 6: Application-Layer Containment Rejected (HN 48706714, 179pts/120c)

.agentignore debate reaches community consensus:
- "Snake oil. The app the agent is developing needs access to the file, so access cannot be blocked"
- ".agentignore is NOT a security tool... There's simply no way to guarantee that an agent will ignore things in the ignore file"
- "I don't think we should ask the agent runtime to police itself"

**Community verdict**: Only structural isolation (VMs, containers, OS-level boundaries) provides actual containment. Application-layer governance of individual agents → false confidence.

Source: https://news.ycombinator.com/item?id=48706714

## The Structural Principle

The Governance Locus Problem: **governance applied at the wrong level of organization produces false confidence rather than safety.**

| Governance level | What it CAN measure | What it MISSES |
|---|---|---|
| **Per-agent** (current default) | Task completion, single-turn safety, instruction following | Ecosystem friction, temporal memory decay, cross-tool privacy flow, authority drift, composition failures |
| **Per-trajectory** (ToolPrivacyBench) | Information flow across tool calls, purpose-bound disclosure | Cross-session accumulation, multi-agent interaction effects |
| **Per-repository** (Govern the Repository) | Integration friction, concurrent-change interference | Cross-repository supply chain, deployment mutations |
| **Per-system** (AgentRiskBOM + ANIS) | Authority scope, capability envelope, runtime immune response | Human governance costs, economic incentives, sovereignty |

The correct governance architecture is **layered** — each level governs what it can observe, with mechanisms to escalate to higher levels when observation is insufficient. No single level is adequate alone.

## Key Insight

**The field has been asking "is this agent safe?" when the correct question is "is this environment governable?"** Safety is not an agent property — it's an emergent property of the system architecture in which agents operate. Individual agent evaluation is to system safety what unit testing is to system integration: necessary but structurally insufficient, and dangerous when treated as sufficient.

This extends the Substrate Inversion: just as capability lives in the harness more than the model, safety lives in the environment more than the agent.
