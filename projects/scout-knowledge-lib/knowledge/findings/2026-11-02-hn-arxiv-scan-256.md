# The Boundary Paradox

**Scan**: #256 | **Source**: HN front page + arXiv | **Date**: 2026-11-02

## Thesis

Three independent arXiv papers and multiple HN front-page signals converge on a single structural principle: **every composition boundary is simultaneously the locus of maximum value creation AND maximum risk**. The agent's interface with tools (ToolPrivacyBench), the agent's interface with codebases (Govern the Repository), and the agent's interface with threats (ANIS) all show the same pattern — the boundary that enables capability is the boundary that enables exploitation. Perimeter defense, per-agent evaluation, and end-state auditing all fail because they operate AWAY from the boundary. Defense, governance, and privacy enforcement must be embedded AT the boundary where composition occurs.

## arXiv Evidence

### 1. Agent-Native Immune System (ANIS) — 2606.28270

**First biologically-inspired endogenous defense architecture embedded INSIDE the agent's cognitive loop.**

- **Six-layer Immune Tower** (L0–L5): L0 = Constitutional Immunity (alignment baseline), L1 = Barrier Immunity (physical/logical isolation — first framework to explicitly separate non-cognitive barriers), L2 = Innate Detection (pattern-matching), L3 = Adaptive Defense (learned responses), L4 = Meta-Cognitive Monitoring (Harness Triad: Meta/Self/Auto), L5 = Collective Intelligence (cross-agent immune coordination)
- **Unified taxonomy**: Formalizes "Agent Viruses" (memory poisoning, tool-chain manipulation, protocol attacks) vs "Agent Vaccines" (non-parametric superficial vs parametric robust defenses). Critical distinction: non-parametric defenses (prompt guards, rule filters) are the agent equivalent of bandages; parametric vaccines (training-embedded defenses) are actual immunity
- **Continual Immune Learning (CIL)**: Vaccines dynamically adapt to novel threats — the defense co-evolves with the attack surface
- **Demarcation principle**: Alignment = static constitutional foundation (training-time). Immunity = dynamic law enforcement (runtime). These are orthogonal capabilities, not substitutes
- **Novel metric**: "Autoimmunity Rate" — false-positive intervention rate. First explicit metric for defense systems that are too aggressive (blocking legitimate operations)
- **Key boundary insight**: Perimeter defense and training-time alignment are both EXTERNAL to the active reasoning loop. Runtime hijacking (memory poisoning, tool manipulation, protocol attacks) occurs INSIDE the loop. Defense must be at the cognitive boundary, not outside it

**Connection to library**: Extends Unfireable Safety Kernel (#152 finding), Out-of-Band Defenses (#176), Isolation Imperative (#180). ANIS provides the theoretical architecture that unifies these empirical findings. The six-layer tower maps cleanly to our tracked defense patterns: L1 = sandbox isolation, L2 = deterministic control plane, L3 = Progent-style enforcement, L4 = meta-cognitive scaffolding, L5 = cross-agent trust protocols.

Source: https://arxiv.org/abs/2606.28270

### 2. Govern the Repository, Not the Agent — 2606.28235

**First large-scale study proving agent risk is an ECOSYSTEM property, not an agent property.**

- **Scale**: 930,000+ agent-authored pull requests analyzed
- **Core finding**: "Integration friction" — the cost of integrating a contribution into a codebase other contributors are concurrently changing — has a repository-level component that PERSISTS after controlling for contribution, author, size, and agent identity
- **Quantified gap**: Agent-authored contributions concentrate repository-level friction roughly **2× as much** as human contributions (intraclass correlation 0.30 vs 0.16). This holds after controls for codebase size, age, task shape, process maturity, and merge path
- **Structural implication**: "AI-native software is better measured and governed at the ecosystem level than one agent at a time." Per-agent benchmarks (SWE-bench, etc.) are structurally incapable of measuring ecosystem-level risk
- **Key boundary insight**: The risk doesn't live in the agent or in the code — it lives at the BOUNDARY where agent output meets repository state. Each contribution is locally valid; the accumulation is where friction concentrates

**Connection to library**: Directly extends the Undercounting Problem (#161), Composition Tax (#184), and Spec Growth Engine (2606.27045). The 2× friction concentration quantifies what those findings described qualitatively — why passing individual tests doesn't prevent cumulative degradation. Also validates CUGA FLO Process Harness (#184) as governance mechanism.

Source: https://arxiv.org/abs/2606.28235

### 3. ToolPrivacyBench — 2606.28061

**First benchmark proving task success does NOT imply appropriate privacy disclosure in tool-using agents.**

- **Scale**: 2,150 cases (1,150 synthetic privacy-sensitive business workflows + 1,000 adapted from existing benchmarks)
- **Core finding**: "Successful tool execution does not imply appropriate privacy disclosure: an agent may complete a task while transmitting unnecessary private information through intermediate tool calls." Task completion and privacy compliance are ORTHOGONAL dimensions
- **Need-to-know principle formalized**: Each tool should receive ONLY the information necessary for its stated purpose. Violations detected via trajectory-level auditing — comparing tool arguments and backend audit logs against policy knowledge base
- **Nine agents evaluated**: Privacy over-disclosure is systematic, not model-specific
- **Evaluation gap**: Conventional function-calling benchmarks evaluate task completion + API correctness. Privacy benchmarks evaluate final responses. NEITHER captures "purpose-bound information flow across an executed multi-tool trajectory" — the gap is at the boundary between evaluation paradigms
- **Key boundary insight**: Privacy violations don't occur at the prompt or the response — they occur at TOOL INVOCATION boundaries, where the agent decides what information to pass to which tool. The boundary between tools is the privacy attack surface

**Connection to library**: Extends Informality Tax (#177 — informal governance fails for privacy), Memory Write Problem (#175 — writes as privilege escalation), and Observation Asymmetry (#225 — information flows that can't be observed can't be governed). ToolPrivacyBench is the first benchmark that treats tool boundaries as the primary privacy surface.

Source: https://arxiv.org/abs/2606.28061

### 4. HORIZON: Agentic Hardware Design as Repository-Level Code Evolution — 2606.28279

**Markdown harness compiled into executable project packs for fully hands-free hardware design evolution.**

- **Architecture**: Markdown harness → project pack (domain knowledge + executable evaluator + acceptance predicate + git/runtime policy) → isolated git worktree evolution
- **Results**: 100% benchmark completion across ChipBench, RTLLM, Verilog-Eval, and nine CVDP categories
- **Self-evolution**: Repository operations for state management, tracing, and replay — agents evolving hardware design artifacts in isolated worktrees
- **Key boundary insight**: The Markdown harness IS the boundary — it compiles domain knowledge into constraints that the agent operates within. Isolation via git worktrees prevents cross-contamination. The harness-as-boundary pattern enables autonomy BECAUSE it constrains it

**Connection to library**: Strongest Substrate Inversion evidence for hardware domain. Extends CHIA (#183 — agents designing silicon). The Markdown-to-project-pack compilation pattern is directly relevant to our own architecture.

Source: https://arxiv.org/abs/2606.28279

### 5. AdvancedShelLM: Multi-Agent Honeypot — 2606.27990

**Multi-agent LLM architecture for SSH deception achieves 99% unit test pass rate and influences real-world attacker behavior.**

- **Architecture**: Two-agent (Manager + Worker) design. Manager understands commands; Worker generates responses. Permanent shared filesystem across attackers
- **Evaluation**: Unit tests (99.02% pass), AI attacker (ARACNE — slight bias toward "honeypot" even for real Ubuntu), human attackers (more deceptive than Cowrie, similar to shelLM), Internet deployment (confirmed behavioral influence on real attackers)
- **Key boundary insight**: The deception operates at the INTERACTION boundary. The honeypot's filesystem state is the boundary between real and simulated — shared across attackers to maintain coherence. Multi-agent architecture separates understanding (Manager) from generation (Worker)

**Connection to library**: Adds to agent-security defense patterns. Multi-agent deception architecture mirrors legitimate multi-agent patterns (separation of concerns), demonstrating dual-use nature of composition.

Source: https://arxiv.org/abs/2606.27990

## Synthesis: The Boundary Paradox

The Boundary Paradox is not a new observation, but this scan provides the first convergence of EMPIRICAL evidence across three orthogonal domains:

| Domain | Paper/Signal | Boundary | Value | Risk |
|--------|-------------|----------|-------|------|
| **Security** | ANIS (2606.28270) | Agent cognitive loop | Runtime adaptation | Runtime hijacking |
| **Governance** | Govern the Repo (2606.28235) | Agent-repository interface | Scaled contribution | 2× friction accumulation |
| **Privacy** | ToolPrivacyBench (2606.28061) | Tool invocation interface | Task completion | Purpose-bound over-disclosure |
| **Design** | HORIZON (2606.28279) | Harness-agent interface | Autonomy | Unconstrained evolution |
| **Information** | Pollen/Google (817pts) | Search-content interface | IP protection | Censorship-as-a-service |
| **Trust** | Mullvad (441pts) | User-provider interface | Privacy | Organizational agenda |

| **Identity** | .self TLD (44pts) | DNS-hosting interface | Discoverability | Gatekeeping |

### The Design Principle

**Boundaries cannot be made safe by making them invisible or by guarding them from outside.** Every empirical finding in this scan demonstrates the same structural truth:

1. **ANIS**: Perimeter security fails because attacks occur INSIDE the cognitive loop. Defense must be endogenous.
2. **Govern the Repo**: Per-agent evaluation fails because friction accumulates at the REPOSITORY boundary. Governance must be ecosystem-scoped.
3. **ToolPrivacyBench**: End-state auditing fails because privacy violations occur at INTERMEDIATE tool invocations. Privacy must be trajectory-scoped.
4. **DMCA/Censorship**: Automated enforcement at content boundaries fails because accountability doesn't exist at the same boundary.
5. **Mullvad**: Technical trust (crypto works) fails to capture organizational trust (who controls it).

The fix in every case is the same: **embed enforcement/governance/monitoring AT the boundary where composition occurs, with scope matching the boundary's scope** (cognitive loop → endogenous defense, repository → ecosystem governance, tool chain → trajectory auditing).

### Implication for Our System

Our system has multiple composition boundaries that currently lack boundary-scoped governance:
- **context_updates**: Information crosses the session boundary with no trajectory-level audit (ToolPrivacyBench pattern)
- **edit()/write()**: Code modifications cross the file boundary with no ecosystem friction measurement (Govern the Repo pattern)
- **Tool invocations**: Agent tool calls cross the capability boundary with no cognitive-loop defense (ANIS pattern)
