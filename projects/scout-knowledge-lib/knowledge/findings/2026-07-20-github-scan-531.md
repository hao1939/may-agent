# GitHub Scan 2026-07-20 — Skills Ecosystem & Agent Self-Knowledge

## Summary

GitHub search (repos created 2026-07-17 to 2026-07-20, sorted by stars). Key themes: (1) harness engineering emerging as a named discipline, (2) agent skills for self-reflection/meta-cognition, (3) security-posture-first resource curation, (4) graph-based multi-agent supervision.

## Notable Repos

### 1. harness-engineering — Named Discipline for Agent Context Bundling (579★ in 2 days)

- **Repo:** [lopopolo/harness-engineering](https://github.com/lopopolo/harness-engineering) (579★, 24 forks, created 2026-07-18)
- **What:** An anthology, field guide, and agent context bundle treating "harness engineering" as a first-class discipline. Python-based.
- **Signal:** This is significant. A practitioner is naming and codifying the practice of engineering the harness layer (CLAUDE.md files, agent context, instructions). 579★ in 2 days means the community recognizes this as an unmet need. Connects directly to our harness-layering thesis from scan #530 — the practice now has a name and a knowledge base.

### 2. smixs/mentor — Agent Self-Reflection Skill (33★)

- **Repo:** [smixs/mentor](https://github.com/smixs/mentor) (33★, created 2026-07-19)
- **What:** A skill for AI coding agents that reads local Claude Code and Codex session history, then generates an HTML report on usage patterns: what you build, where you lose time, concrete fixes. Works with any skills-capable agent.
- **Signal:** Agents analyzing their own history to improve future sessions. This is metacognitive tooling — the agent reflecting on its own patterns. Closes the loop between agent operation and agent improvement without requiring the user to manually synthesize.

### 3. awesome-ai-coding-sandboxes — Security-Posture-First Curation (16★)

- **Repo:** [fhiltscher/awesome-ai-coding-sandboxes](https://github.com/fhiltscher/awesome-ai-coding-sandboxes) (16★, created 2026-07-18)
- **What:** Security-posture-first list of sandboxes for running AI coding agents' code, ranked by isolation, egress control, and secrets handling.
- **Signal:** The security lens is now the PRIMARY axis for sandbox evaluation, not performance or ease-of-use. This mirrors our security-defense-architectures thesis: security becoming a table-stakes requirement, not an afterthought.

### 4. graphkit — Graph-of-Agents Supervision (16★)

- **Repo:** [levi-qiao/graphkit](https://github.com/levi-qiao/graphkit) (16★, created 2026-07-19)
- **What:** A Claude Code skill that structures long coding tasks as a graph of agent nodes — an executor node plus a clean-context supervisor that watches from outside and corrects drift. Bilingual (EN/中文).
- **Signal:** Drift correction via external supervisor is a recurring pattern. The "clean context" supervisor (separate from the polluted executor context) is an architectural insight: supervision quality degrades if the supervisor shares the same context drift.

### 5. PilotBrowseMCP — Browser Runtime via MCP with Manual Reuse (20★)

- **Repo:** [EndymionLee/PilotBrowseMCP](https://github.com/EndymionLee/PilotBrowseMCP) (20★, created 2026-07-18)
- **What:** Browser runtime that lets AI agents control your real Chrome browser via MCP. Key feature: agents explore websites, generate operation manuals, then reuse those manuals in future runs to save tokens.
- **Signal:** The "generate a manual, then replay it" pattern is a form of procedural memory. Instead of re-exploring every time, the agent creates reusable procedures. This is memory-as-compiled-knowledge rather than memory-as-raw-logs.

### 6. self-healing-api-factory — Knowledge Graphs to Kill Token Loops (6★, early)

- **Repo:** [indranildchandra/self-healing-api-factory](https://github.com/indranildchandra/self-healing-api-factory) (6★, created 2026-07-18)
- **What:** Autonomous API factory using Postman CLI, SQLite MCP & SOFA to eliminate agentic token-wasting loops via self-healing local knowledge graphs.
- **Signal:** The framing is notable: knowledge graphs specifically positioned as anti-loop infrastructure. The agent accumulates API knowledge locally so it doesn't re-discover the same failures.

### 7. tower-protocol — Air-Traffic-Control for Irreversible Multi-Agent Actions (3★, conceptual)

- **Repo:** [YamenHassan17/tower-protocol](https://github.com/YamenHassan17/tower-protocol) (3★, created 2026-07-18)
- **What:** An air-traffic-control protocol for coordinating irreversible actions across multi-agent LLM systems. LangGraph adapter included.
- **Signal:** Small but conceptually sharp. The distinction between reversible and irreversible actions as the key coordination primitive is an insight — you only need heavy coordination for irreversible steps.

## Emerging Patterns

1. **Harness engineering as discipline:** The practice of crafting agent context (CLAUDE.md, system prompts, skills bundles) is being named and codified. This mirrors how "DevOps" named an existing practice — expect job titles and dedicated tooling to follow.

2. **Agent metacognition wave:** mentor (self-reflection), PilotBrowseMCP (procedural memory), self-healing-api-factory (anti-loop knowledge) all share a theme: agents building knowledge about their own operation to avoid repeating mistakes.

3. **Supervision architecture: clean-context observers:** graphkit's insight — supervisors must have clean context separate from the executor — is appearing in multiple places. Shared-context supervision inherits the drift it's meant to correct.

4. **Security as primary evaluation axis:** awesome-ai-coding-sandboxes ranks by isolation first, not features. This completes the security maturation arc: awareness → tooling → evaluation criteria.
