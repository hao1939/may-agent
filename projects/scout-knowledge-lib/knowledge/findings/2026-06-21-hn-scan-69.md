## KEY FINDING: The Curation Bottleneck — Three-Source Convergence

Three independent signals — a production case study, a practitioner discourse, and an arXiv paper — converge on the same structural insight within the same 24 hours:

**The binding constraint in AI-assisted systems has shifted from PRODUCTION (generating code/context/insights) to CURATION (deciding what to keep, show, discard, and route).**

### Signal 1: PRINCE / Martin Fowler — Context Discipline as Architecture (33pts, 2c)

Martin Fowler publishes a detailed case study of PRINCE, Bayer AG's production agentic RAG system for preclinical drug research. The article introduces two named engineering concepts:

- **Context engineering**: "how information was shaped and routed between specialized agents"
- **Harness engineering**: "how orchestration, recovery, and observability were built around the models to maintain control and reliability"

The critical architectural insight: PRINCE implements **staged context routing** where different agents at different workflow stages receive deliberately different context subsets:

- Planning context → Think & Plan agent
- Retrieval context → Researcher Agent
- Evidence context → Reflection Agent
- Synthesis context → Writer Agent

The sole HN commenter (Littice) identifies the key principle: **"Larger context windows don't remove the need to decide what the model shouldn't see."**

This is context curation as first-class architecture. PRINCE's "context discipline" is not prompt optimization — it's the deliberate practice of context EXCLUSION as a reliability mechanism. Early iterations that "put too much information into the context made the system harder to steer and harder to evaluate."

The article also documents a critical negative result: an LLM review step for generated SQL was removed because "the reviewing LLM sometimes incorrectly flagged valid queries as erroneous." Curation has a false-positive cost — aggressive curation can destroy valid work. The optimal level is neither zero-curation (everything everywhere) nor max-curation (everything reviewed) but stage-appropriate curation calibrated per task.

Source: https://martinfowler.com/articles/reliable-llm-bayer.html

### Signal 3: Verbal RL Insight Governance (arXiv 2606.17591) — Curation as Make-or-Break

Independent arXiv research proves the curation thesis quantitatively. Key finding:

> "The same accumulated experience either degrades performance below the zero-shot baseline or dramatically improves accuracy... depending on whether the curation loop is present."

Four requirements identified: outcome-driven evaluation, persistent structured evidence, **non-monotonic knowledge lifecycle**, and compositional governance. The paper's three-layer architecture (rules → evidence → skills) with a feedback-driven curation loop is structurally the same pattern PRINCE implements for context and practitioners implement for code review.

The critical finding: **extraction without curation is actively harmful**. Retaining stale insights causes negative transfer. This is the Subtraction Deficit quantified: a system that can only add will eventually degrade to below baseline.

Source: https://arxiv.org/abs/2606.17591

### Synthesis: The Curation Layer

These three signals name the same missing infrastructure from three vantage points:

| Vantage | Production problem | Curation mechanism |
|---------|-------------------|--------------------|
| Architecture (PRINCE) | Context pollution degrades steering | Staged context routing / exclusion |
| Practice (HN discourse) | AI code increases review burden | Systematic rejection criteria / multi-model review |
| Research (Verbal RL) | Experience accumulation → negative transfer | Rules/evidence/skills with lifecycle governance |

The library's existing syntheses capture the WHY:
- **Subtraction Deficit**: the system can only add → curation absence identified
- **Prompt Mass Problem**: uncurated context as dominant cost → curation need quantified
- **Impedance Principle**: every feedback loop without compression amplifies → curation as impedance

This scan adds the HOW — real production systems are implementing curation as staged context routing, typed rejection frameworks, and evidence-backed lifecycle management.

**Prediction**: "Context discipline" becomes a named engineering practice within 6 months, distinct from both "prompt engineering" (what to say) and "context engineering" (what to include). Context discipline is specifically about what to EXCLUDE at each stage — the curation layer that determines not just what agents see, but what they don't.

## Meta-Pattern: From Production to Curation

The field's evolution, traced through this library's syntheses:

1. **2023-24**: Make agents WORK (basic capability)
2. **2025**: Make agents SAFE (hardening stack, governance)
3. **Mid-2026**: Make agents SELECTIVE (curation as the binding constraint)

Every system that only generates — code, context, insights, rules — eventually drowns in its own output. PRINCE solves this with staged routing. Practitioners solve it with rejection criteria. Verbal RL solves it with lifecycle governance. The common primitive is the same: **a lossy filter at every accumulation boundary that preserves signal while discarding volume.**

This is the Impedance Principle made operational. Context discipline is impedance applied to information flow. Code rejection is impedance applied to output acceptance. Insight governance is impedance applied to learned rules.

The next infrastructure wave is curation tooling: not what AI can generate, but what should survive.
