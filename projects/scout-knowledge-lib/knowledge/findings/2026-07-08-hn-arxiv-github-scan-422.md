## arXiv Analysis: The Bounded Verification Problem

Three new papers converge on a structural finding: **bounded systems outperform unbounded ones** — not because they see more, but because they see *better*.

### HIGH: AgenticSTS — Memory as Contract, Not Transcript (2607.02255)

Source: https://arxiv.org/abs/2607.02255

First formal treatment of agent memory as a **contract** — specifying what each future decision is allowed to see, rather than appending raw cross-decision transcripts. Instantiated in Slay the Spire 2 (deck-building game requiring hundreds of tactical and strategic decisions). Public benchmarks report zero wins across frontier LLMs at lowest difficulty (human win rate: 16%).

Key findings:
- **Bounded contract** (typed retrieval, no raw transcript): each decision assembled from fresh user message, prompt stays bounded across runs of any length
- Single-layer ablation shows **triggered strategic skills** produce the largest observed difference (3/10 → 6/10 wins)
- Any single memory component can be ablated in isolation — impossible in unbounded append-all architectures
- Released 298 completed trajectories with condition tags, frozen memory/skill snapshots, prompt records

**Structural significance**: This is the theoretical foundation for why `Self-GC Context Lifecycle` (#405, 2607.00692) works — context management as object lifecycle, not text pruning. Memory-as-contract connects to the Trust Floor Ratchet: when the system specifies what each decision can see, verification becomes tractable. When the system appends everything, verification is impossible.

**For our system**: Directly validates the bounded-context architecture pattern. The session floor problem (Abstention Decay) is a contract violation — the system acts on information that should be out of scope.

### MEDIUM: Online Safety Monitoring — Simple Monitors Win (2607.02510)

Source: https://arxiv.org/abs/2607.02510

Despite alignment training, LLMs remain prone to generating unsafe outputs at deployment time. This paper studies a simple real-time monitor: threshold on a verifier signal from an external model, with the threshold calibrated via risk control.

Key finding: **This simple design is competitive with more advanced monitors based on sequential hypothesis testing** — on both mathematical reasoning and red teaming datasets.

**Structural significance**: Connects to the Oversight Inversion in a counterintuitive way. The insight isn't "monitoring is easy." The insight is that **calibrated simple monitors beat uncalibrated complex monitors**. The verification bottleneck isn't monitoring architecture — it's threshold calibration. This parallels the Reasoning Precedence (#416): effort in the right place beats capability in the wrong place.

### MEDIUM: EvoPolicyGym — Budget Allocation > Raw Capability (2607.02440)

Source: https://arxiv.org/abs/2607.02440

First benchmark for evaluating how agents iteratively improve executable policies under a fixed interaction budget. GPT-5.5 achieves strongest aggregate performance, but the key finding is diagnostic: **strong autonomous policy evolution depends on budget allocation and mechanism discovery, not just task wins.**

Key finding: Trajectory-level diagnostics distinguish how agents allocate budget and convert feedback into parametric tuning. Agents that discover task-appropriate mechanisms and refine policies under bounded feedback outperform agents that simply attempt more iterations.

**Structural significance**: Another instance of the bounded-beats-unbounded pattern. Fixed budget + good allocation > unlimited budget + poor allocation. Connects to the Repair Turn (#419): repair capacity (quality) matters more than detection breadth (quantity).
