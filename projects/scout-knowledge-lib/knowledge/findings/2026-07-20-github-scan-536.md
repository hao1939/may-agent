# GitHub Scan 2026-07-20 — Agent Memory Encryption & Command Preflight

## Summary

Fifth pass today, queries `agent memory created:>2026-07-19 stars:>1`, `coding agent created:>2026-07-19 stars:>1`, `mcp server created:>2026-07-19 stars:>2`. Two repos fill distinct infrastructure gaps not covered by earlier scans: encrypted-at-rest agent memory and pre-execution command validation.

## Notable Repos

### 1. MaxFreedomPollard/engRAM — Encrypted Offline Agent Memory (2★)

- **Repo:** [MaxFreedomPollard/engRAM](https://github.com/MaxFreedomPollard/engRAM) (2★, created 2026-07-20)
- **What:** Python vector vault for AI agents (Hermes, Claude, OpenClaw) that stores episodic and semantic memory fully offline with encryption at rest. Agents write memory fragments which are embedded, encrypted, and stored locally. Retrieval via similarity search decrypts on-the-fly.
- **Signal:** Addresses a gap in the agent memory ecosystem: most memory solutions (MemGPT, Letta) are cloud-first or unencrypted. For sensitive enterprise codebases where agent memory contains proprietary context, encryption at rest is non-negotiable. The "fully offline" constraint also enables air-gapped environments.
- **Pattern:** **Encrypted episodic memory** — treating agent recall as sensitive data requiring the same protection as credentials or PII.

### 2. cocojojo5213/command-preflight — Non-Executing Shell Validation (3★)

- **Repo:** [cocojojo5213/command-preflight](https://github.com/cocojojo5213/command-preflight) (3★, created 2026-07-20)
- **What:** Go CLI that validates shell commands *before* execution by checking syntax, verifying executables exist on PATH, validating referenced paths, and scoring risk — all without running anything. Designed for Claude Code, Codex CLI, and MCP agents.
- **Signal:** Fills the "pre-execution validation" slot in the agent safety stack. Unlike agentshield (policy-based gate) or agent-approval-gate (human confirmation), this is purely mechanical: does the command parse? Do referenced binaries exist? Are paths valid? Catches a class of errors that LLMs commonly produce (typos in commands, referencing non-existent tools) before they waste a shell round-trip or cause damage.
- **Pattern:** **Static preflight analysis** — applying compiler-style static checks to dynamically generated shell commands.

### 3. mrcodex-dev/freya-mcp-server — Maximalist System-Access MCP (1★)

- **Repo:** [mrcodex-dev/freya-mcp-server](https://github.com/mrcodex-dev/freya-mcp-server) (1★, created 2026-07-20)
- **What:** TypeScript MCP server bundling filesystem, shell, Windows internals, reverse engineering tools, LSP code intelligence, browser automation, and agent orchestration into a single server. Claims to outperform Claude Code in raw system access.
- **Signal:** Represents the "maximalist MCP" anti-pattern — bundling everything into one server rather than composing specialized servers. Interesting as a contrast to the modular approach (symbolpeek for code intelligence, command-preflight for shell validation). The market will likely sort toward composable specialized servers, but maximalist bundles may win for solo developers who want one-click setup.
- **Pattern:** **Monolithic MCP server** — all capabilities in one process vs. composable specialized servers.

## Synthesis — Updated Agent Safety Stack

Adding command-preflight to the governance table from scan #535:

| Layer | Tool | Function |
|-------|------|----------|
| Visibility | agent-inventory | Know what agents are running |
| Pre-execution (static) | command-preflight | Validate commands parse and reference real binaries |
| Pre-execution (policy) | agentshield / whichrules | Gate tool calls with policy rules |
| Context | symbolpeek-mcp | Minimize token waste via semantic retrieval |
| Memory | engRAM | Encrypted persistent recall |
| During-execution | agent-approval-gate | Human confirmation for high-risk actions |
| Post-execution | warden | Audit agent output before merge |

The "defense in depth" pattern now has both static and policy-based pre-execution layers — analogous to how compilers catch type errors before linters catch style issues.
