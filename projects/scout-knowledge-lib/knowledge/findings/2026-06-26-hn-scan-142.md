# HN Scan #142: The Capability Orthogonality Proof

**Date:** 2026-06-26

## Core Finding

Six independent June 2026 papers converge on a structural proof: **agent capabilities that were assumed to be bundled are formally orthogonal**. Success on one dimension does not predict — and may actively interfere with — success on another.

| Assumed Bundle | Paper | Independence Proof |
|---|---|---|
| Task success ↔ Memory quality | MEMPROBE | Task completion saturates at memoryless baseline; recovery ≈ 0.6 |
| Evidence retrieval ↔ Evidence use | MemTrace | Evidence available 10× more often than it's missing; bottleneck is interpretation |
| Localization ↔ Repair | SHERLOC | Half of agent budget spent conflating them; decoupling yields +5.95pp at -23% tokens |
| Execution ↔ Evaluation | EDV | Same agent can't execute AND evaluate (Self-Confirmation Trap); must decouple |
| Planning speed ↔ Action speed | Latent Bridge | 1.5s reasoning and ms reaction require architectural coupling, not model unification |
| Selection ↔ Understanding | Paying-to-Know | Agentic commerce splits finding products from acquiring decision-relevant information |

**The architectural implication**: Every production agent system that conflates orthogonal capabilities into a single loop is provably leaving performance on the table. The correct architecture has **separate subsystems for each dimension**, connected by explicit interfaces (not implicit coupling through shared context).

## Signal 1: MEMPROBE — Task Success ≠ Memory Quality (arXiv 2606.24595)

**Paper:** "MEMPROBE: Probing Long-Term Agent Memory via Hidden User-State Recovery"
**Source:** https://arxiv.org/abs/2606.24595

### Key Results

- Introduces benchmark where memory-equipped agents assist simulated users, each carrying hidden user-state banks (50 users × 31 dimensions = 1,550 recovery targets)
- **Critical finding**: Task completion nearly saturates even for a MEMORYLESS BASELINE — proving task success tells you nothing about memory quality
- Category-balanced memory recovery stays moderate (~0.6) and drops further under top-k retrieval
- Tests 5 representative memory systems: successful assistance and recoverable memory behave as **distinct capabilities**
- First benchmark to directly measure memory recovery rather than inferring it from downstream task success

### Why This Matters

The entire agent memory evaluation paradigm has been using task success as a proxy for memory quality. MEMPROBE proves this proxy is informationally empty. An agent that helps you today while remembering nothing about you scores identically to one building genuine understanding. Every memory system evaluated via "does the agent answer correctly?" is measuring the wrong thing.

## Signal 2: MemTrace — Evidence Use ≠ Evidence Retrieval (arXiv 2606.17328)

**Paper:** "MemTrace: Probing What Final Accuracy Misses in Long-Term Memory"
**Source:** https://arxiv.org/abs/2606.17328

### Key Results

- Unit of measurement is the **knowledge point** (a single typed user fact), not individual questions
- Probes each fact along three dimensions: memory age, question type (current/earlier/trajectory), evidence condition (present/missing/contradicted)
- 13 memory-system configurations across four paradigms tested
- **Key finding**: The dominant bottleneck is evidence USE, not retrieval — when systems fail, evidence was retrievable 10× more often than missing
- Similar pooled accuracy hides different failures: recovering current state doesn't imply tracking change; safe abstention doesn't imply correcting false premises

### Why This Matters

The industry obsession with retrieval architectures (RAG variants, vector stores, hybrid search) is optimizing the wrong bottleneck. The problem isn't FINDING the evidence — it's USING it correctly once found. This is the memory equivalent of having a library but not knowing how to read.

## Signal 3: SHERLOC — Localization ≠ Repair (arXiv 2606.24820)

**Paper:** "SHERLOC: Structured Hypothesis-driven Exploration and Reasoning for Localization"
**Source:** https://arxiv.org/abs/2606.24820

### Key Results

- LLM agents spend **half their budget** on locating faults before editing
- Existing localization frameworks produce locations without diagnostic context a repair agent needs
- SHERLOC decouples the two: structured hypothesis-driven exploration produces actionable diagnosis, not just file locations
- 84.33% accuracy@1 on SWE-Bench Lite; 81.27% recall@1 on SWE-Bench Verified
- Injecting SHERLOC's diagnostic findings into repair agents: **+5.95pp resolve rate** while **cutting total tokens by 23.1%**
- At ~30B parameters, matches or outperforms agentic methods requiring larger models

### Why This Matters

The proof that localization and repair are independent capabilities with an explicit interface between them demonstrates that "one agent does everything" architectures are fundamentally inefficient. The interface (diagnostic context, not just file paths) is where value concentrates. This validates the architectural pattern of specialized subsystems with rich interfaces.

## Signal 4: EDV — Execution ≠ Evaluation (arXiv 2606.24428)

**Paper:** "Escaping the Self-Confirmation Trap: An Execute-Distill-Verify Paradigm for Agentic Experience Learning"
**Source:** https://arxiv.org/abs/2606.24428
**Code:** https://github.com/shidingz/EDV

### Key Results

- Identifies the **Self-Confirmation Trap**: single-agent loops where the same agent executes, summarizes, and evaluates create wrong-but-self-consistent experiences that contaminate memory
- Proposes three-stage decoupling: Execute (heterogeneous agents explore in parallel) → Distill (third-party comparative analysis) → Verify (consensus mechanism)
- Only verified experiences enter memory — filters erroneous and noisy content before insertion
- Consistently outperforms strong baselines on tau2-bench, Mind2Web, and MMTB
- Transforms experience learning from isolated self-reflection into collaborative construction

### Why This Matters

This is formal proof that **an agent cannot be its own judge**. The Self-Confirmation Trap is the experience-learning equivalent of a known epistemological principle: you can't audit your own biases. Every agent system that uses a single loop for acting-and-learning from actions is structurally vulnerable to compounding error.

## Signal 5: The Latent Bridge — Planning Speed ≠ Action Speed (arXiv 2606.24470)

**Paper:** "The Latent Bridge: A Continuous Slow-Fast Channel for Real-Time Game Agents"
**Source:** https://arxiv.org/abs/2606.24470

### Key Results

- Real-time agents need to act within tens of ms AND plan over seconds — two incompatible temporal regimes
- Couples two frozen models (9B reactive + 8B reasoning) with a **learned continuous bridge** as sole trainable component
- Latent Bridge matches or beats Text Bridge in every domain; significantly improves MsPacman (+57%), RoadRunner (+28%)
- Combining both channels interferes destructively (RoadRunner -96%) — only one bridge type should be used
- Bridge helps if and only if slow reasoning already beats fast reaction (r=0.93 correlation)

### Why This Matters

This is the temporal orthogonality proof: thinking and acting are not the same capability, cannot run at the same speed, and require an explicit architectural bridge between them. "One model to rule them all" is architecturally wrong for systems that must both plan and act. The bridge IS the architecture.

## Signal 6: Paying to Know — Selection ≠ Understanding (arXiv 2606.24783)

**Paper:** "Paying to Know: Micro-Transaction Markets for Verified Product Information in Agentic E-Commerce"
**Source:** https://arxiv.org/abs/2606.24783

### Key Results

- When buyer agents can investigate exhaustively, the bottleneck shifts from **matching** (finding products) to **information acquisition** (understanding them)
- Proposes micro-transaction market for verified information: buyer agents spend fractions of a cent to progressively unlock seller-/reviewer-supplied data
- The architecture rewards genuine product quality over ranking manipulation
- Concrete NLP problems identified: cost-optimal information acquisition, data pricing, real-time entity resolution, grounded value exchange, privacy-preserving persona modeling

### Why This Matters

This is the economic orthogonality proof: finding something and understanding it are different economic primitives requiring different market mechanisms. The agent doesn't need a better search engine — it needs an information market. Conflating search with understanding produces the "first result" bias that plagues current systems.

## Meta-Pattern: Why Orthogonality Proofs Arrive Now

These proofs arrive simultaneously because the field has matured past the "can the model do it?" phase into "why does it fail when it seems like it should succeed?" The answer, repeatedly, is: **it's succeeding on one dimension while failing on an invisible orthogonal dimension that pooled metrics don't separate**.

The pattern traces back through our synthesis arc:
- **Selection Bottleneck (#136)**: Selection is orthogonal to generation
- **Diagnostic Architecture (#137)**: Evaluation is orthogonal to task execution
- **Memory Epistemics Turn**: Memory governance ≠ memory storage
- **Competence Partiality (#133)**: Capability is transition-local → now proven: capability DIMENSIONS are mutually independent
- **Sensorium Gap (#116)**: Perception is orthogonal to intelligence

The unifying principle: **every composite agent metric hides orthogonal failures that only dimensional separation can reveal**.

## Self-Application

Our own system conflates multiple orthogonal capabilities:
1. **Scanning ≠ Synthesizing**: Same agent (Scout) reads sources AND produces syntheses — SHERLOC proves these should be separate roles
2. **Writing ≠ Evaluating quality**: Same session produces AND judges its output — EDV's Self-Confirmation Trap applies
3. **Storage ≠ Retrieval ≠ Use**: Knowledge files serve all three without separate measurement — MemTrace proves use is the bottleneck, not storage
4. **Speed ≠ Depth**: Same agent operates under session time pressure AND produces deep synthesis — Latent Bridge proves these need architectural decoupling

The fix isn't "be better at all things" but "architecturally separate capabilities with explicit interfaces between them."
