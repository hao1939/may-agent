## Finding 1: LinkedIn Backdoor Surges — Lazarus Group Attribution

**Story:** [A backdoor in a LinkedIn job offer](https://roman.pt/posts/linkedin-backdoor/) (311pts ↑ from 129pts, 66c ↑ from 23c)

The **+141% score growth** makes this the fastest-accelerating story since the local model thread's doubling in scan-5→6. The community response has shifted from "this is a crime" to **attribution and pattern recognition**:

### New signals since scan-6:

- **clemailacct1**: "This is very likely Lazarus Group — specifically Famous Chollima aka the DPRK." State-actor attribution from what appears to be a security professional.
- **Raed667**: Found the **same domain reused** across multiple targets — links to a Reddit thread from 3 months ago documenting the identical approach. This is industrial-scale, not opportunistic.
- **BobAliceInATree**: Notes GitHub and LinkedIn (both Microsoft properties) have done nothing despite the repo being reported. Platform non-response as systemic weakness.
- **f055**: Reports receiving 2-3 shady crypto offers per week on LinkedIn. Stopped only after demanding "official email, official offer link, terms and scope" — i.e., formal verification of identity.
- **CalChris**: "It's odd that the operator of the scam knew full stack level details of its implementation... perhaps as something like privilege escalation, identity escalation."
- **theoeiffijr**: Links to broader platform security failure — "Downloading random unprotected scripts from internet, like it is 1995."

### Agent security implications (upgraded from scan-6):

The Lazarus Group attribution **changes the threat model** for agents:

1. **State-actor targeting of developers = state-actor targeting of agents.** If DPRK-backed attackers are using npm prepare hooks to compromise individual developers, the same vector applies to any agent told to evaluate a repo. The attack scales: one poisoned repo can hit thousands of agent invocations.
2. **Multi-target reuse** (Raed667's finding) means these repos are **persistent, searchable, and clonable** — an agent doing a web search for "crypto" or "blockchain" codebases could encounter them organically.
3. **Platform non-response** (BobAliceInATree) means the attack surface persists. Agents cannot rely on platform-level repo takedowns.
4. **f055's defense pattern** (demanding formal identity verification) maps to agent architecture: agents should verify task provenance before clone+install operations. "Who asked me to do this and through what verified channel?" is the agent equivalent.

**Story:** [Ask HN: Has anyone replaced Claude/GPT with a local model for daily coding?](https://news.ycombinator.com/item?id=48542100) (510pts ↑ from 428pts, 255c ↑ from 233c)

### New commentary reveals three sub-trends:

**a) Hardware diversity beyond RTX 3090:**
The scan-6 "consensus stack" (RTX 3090 + Qwen3.6-35B + llama.cpp) remains dominant, but newer comments show broader hardware:

- **AH4oFVbPT4f8**: M5 Max 128GB running Qwen 3.6:35b-a3b via Ollama + .NET. Plans 27b for planning, 35b for execution.
- **jwr**: M4 Max running qwen3.6-35b-a3b / gemma-4-26b-a4b-qat. **Explicitly skeptical**: "those tiny models... are NOWHERE near as smart as the huge monsters like Opus/Fable." Self-aware: "I can see a lot of people deluding themselves."
- **_davide_**: Strix Halo running minimax 2.7 (q3) at 30 tok/s — reports it as "a bit painful slow" and a "toy for AI purposes."
- **w10-1**: M1 Max 32GB(!) running Gemma-4 via oMLX with caching. Claims response times faster than reading the prompt aloud.
- **major505**: M1 16GB running Qwen via Ollama with temperature 0. "Works reasonable well."

**b) The DeepSeek V4 Fast counter-narrative:**
- **thrownaway561**: "I just use DeepSeek V4 Fast... 67M output, 51M input. Total $0.83 dollar. I honestly don't understand why people just don't use DeepSeek." This is neither local nor expensive cloud — it's **ultra-cheap API as a third path**. $0.83/mo for 118M tokens undercuts both the $100/mo Claude subscription AND the hardware investment for local models.

**c) The "not local but self-hosted" distinction:**
- **ecshafer**: Self-hosted with Ollama (Gemma 4, GLM 4.7 Flash, Qwen 3.6) but on servers, not local hardware. "GLM is the best at coding agentically. But I still don't think any of them reach... opus 4.8."
- **jmichaelson**: Building a "highly optimized harness (pi.dev) with the right backing knowledgebase" to replicate Claude Max 20x subscription value. Gemma 4 26B QAT via custom llama.cpp fork, 4-8 slots of 256k context at Q8. "A very good model." → **Harness engineering as force multiplier for weaker models** confirmed.
- **dada216**: Uses GLM via Go subscription + OpenRouter for adjacent tasks. ~$20/mo API costs. Linux infra/k8s specialist — the "glue code" use case where model quality matters less.
