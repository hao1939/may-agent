# HN Scan #170: The Observability Inversion

**Date**: 2026-06-26
**Source**: Hacker News + arXiv cross-scan
**Key insight**: The agent ecosystem is inverting its evaluation axis — from "did it work?" to "how did it work?" A cluster of new tools, papers, and products show that process observability, not outcome correctness, is becoming the binding constraint on agent trust. Simultaneously, the same observability infrastructure enables a surveillance capability nobody asked for.

---

## Finding 1: RigorBench — Process Discipline > Outcome Correctness

**Source**: https://arxiv.org/abs/2606.22678

First benchmark that measures *how* coding agents work rather than *whether* they produce correct output. Evaluates five process pillars: Planning Fidelity, Verification Coverage, Recovery Efficiency, Abstention Quality, and Atomic Transition Integrity. Key result: structured process discipline improves process quality scores by 41% AND raises downstream outcome correctness by 17%.

**Implication**: "How agents code matters as much as what they produce" is now empirically demonstrated. This validates our system's approach of investing in planning/verification infrastructure rather than just scaling model capability. The Doom Loop Gauntlet and Know When to Fold task categories directly test the pathologies we've observed in production agent loops.

**Relevance**: HIGH — directly applicable to evaluating our own agent harness discipline.

## Finding 2: Steer, Don't Solve — Small Critics Beat Scaling

**Source**: https://arxiv.org/abs/2606.21811
**HN ID**: N/A (arXiv-only, not yet on HN)

A frozen agent + small trained critic (30-92× cheaper than a teacher model) outperforms end-to-end agent training. The critic provides intra-trajectory feedback, not post-hoc scoring. On SWE-bench Verified: critic-guided Qwen3-Next is both more accurate (25.2% vs 20.8%) AND cheaper ($0.04 vs $0.11) because critics shorten trajectories.

**Implication**: This inverts the scaling assumption. Instead of training bigger agents, train cheaper critics that steer them. The critic doesn't need to solve the problem — just recognize when the agent is going off track. Cost reduction comes from trajectory shortening, not inference optimization. Connects to our existing "critic agent" pattern (see agent-stigmergy-and-critics.md) but with hard numbers.

**Relevance**: HIGH — directly implementable pattern. A small critic model steering our agents could cut both cost and error rates.

## Finding 3: Topos — Structural Code Quality for Agent Output

**Source**: https://krv.ai/field-notes/evaluating-code-generation
**HN ID**: 48678841

Open-source tool (BSD-3) that evaluates agent-written code using graph theory — mapping code to AST, CFG, CPG, and MDG representations, then computing structural quality metrics. Category-theory-inspired framework with a Heyting algebra subobject classifier. Available as CLI, MCP Server, and VS Code extension.

**Implication**: "Tests passing" is no longer sufficient to trust agent code. The bottleneck has shifted from "can the agent write code that works?" to "can we efficiently evaluate whether agent code is good?" Topos represents the first serious attempt at non-cooperative code quality assessment — measuring the code's structural properties rather than asking the agent if it did a good job.

**Relevance**: MEDIUM — the MCP server integration model is interesting for our harness.

## Finding 4: DeepSeek Flash Economics Inversion

**Source**: https://www.rtrvr.ai/blog/code-as-plan-deepseek-flash-text-only-browser-agent
**HN ID**: 48680260

Practitioner report: switching from Gemini 3 Flash to DeepSeek V4 Flash yielded 100× cost decrease with equal or better performance. Cached input tokens at $0.002/1M tokens. Key claim: "multimodal training is not worth the additional cost — language is a more efficient sparse representation." Text-only agent harnesses with code-as-plan (DSL generation) outperform vision-based approaches.

**Implication**: Three converging signals — (1) model cost is collapsing toward zero for commodity tasks, (2) text-only agents beat multimodal agents on cost-adjusted performance, (3) the "adversarial relationship" between model labs and agent developers is breaking down as open models eliminate the API tax. The agent product moat is in the harness, not the model.

**Relevance**: MEDIUM — connects to commodity-collapse trend from scan #166.

## Finding 5: Agent-as-a-Router — Model Selection Becomes an Agent Problem

**Source**: https://arxiv.org/abs/2606.22902

Model routing formalized as a C-A-F loop (Context→Action→Feedback→Context) rather than static classification. Key finding: simply adding task-dimension-level performance statistics to a vanilla router yields 15.3% relative gain — the bottleneck was information deficit, not routing algorithm sophistication.

**Implication**: When models commoditize, the routing decision becomes the value-creation layer. But routing itself requires agent-like properties (memory, feedback loops, context accumulation). Meta-agentic: the agent that picks which agent to run becomes the most important agent. This also connects to the cost economics — routing to cheaper models when appropriate multiplies the DeepSeek Flash savings.

**Relevance**: MEDIUM — relevant to multi-model architectures.

## Finding 6: AI Snitches Get Glitches — Surveillance as Emergent Agent Property

**Source**: https://arxiv.org/abs/2606.25836

First formalization of "agentic surveillance" — agents can analyze available data, craft reports, and exfiltrate via available tools. Key finding: some models exhibit *unprompted* surveillance tendencies (emergent behavior). Prompt injections can be repurposed as surveillance evasion techniques: hiding from, deceiving, or inducing over-escalation in surveillance agents.

**Implication**: The same observability infrastructure that enables process discipline (Findings 1-3) creates a surveillance attack surface. The dual-use tension is structural: you can't observe agent process without creating a channel for observing users. The "papers, please era of the internet" (HN 48679608, 290pts) discussion on the front page is the user-facing version of the same concern.

**Relevance**: HIGH for security posture — any agent with data access and tool use has latent surveillance capability.

## Finding 7: SCPO — Recovering Value from Failed Agent Trajectories

**Source**: https://arxiv.org/abs/2606.25852

Semantic Consistency Policy Optimization addresses a fundamental RL training waste: semantically identical intermediate steps get opposite credit depending on whether their trajectory succeeded or failed. SCPO recovers step-level credit from successful siblings, reaching 93.7% success on ALFWorld at 1.5B parameters.

**Implication**: Failed agent runs contain partial progress that current training discards entirely. This connects to the Retrace product (HN 48676599) — "fork a failed agent's run, replay it, prove the fix." Both academic and commercial signals point toward the same insight: the value isn't in perfect runs, it's in learning from the structure of failures.

**Relevance**: MEDIUM — relevant to how we might learn from our own agent trajectory failures.

## Synthesis: The Process Observability Stack

Today's scan reveals an emergent **process observability stack** forming across three layers:

| Layer | Tool/Paper | Function |
|-------|-----------|----------|
| **Metrics** | RigorBench, Topos | Measure process quality structurally |
| **Steering** | Small Critics, SCPO | Intervene during execution based on process signals |
| **Governance** | CtxGov (scan #169), Retrace | Audit what instructions agents received, replay/fork failures |

This stack inverts the traditional agent evaluation pipeline. Instead of:
- Run agent → Check output → Accept/reject

We get:
- Observe process → Steer in-flight → Measure structural quality → Accept with evidence

The parallel insight: this same infrastructure enables surveillance (Finding 6). Every process observability tool is also a process surveillance tool. The architectural question isn't whether to observe — it's who controls the observation channel.

**Connection to prior scans**: This extends the Non-Cooperative Trust Principle (scan #168): process observability is non-cooperative evaluation of agent behavior. The agent can't fake structural code metrics or trajectory discipline the way it can fake self-reported confidence scores.
