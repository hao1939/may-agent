## Formal Verification as Trust Substitute

Three independent signals converge on formal verification as the structural response to trust conditionality:

### Leanstral 1.5 (Mistral, HN 85pts)
- Mistral's second iteration of their Lean 4 formal-proof model
- Community question: "Is this useful for specifying programs too or only theorems?" → boundary between proof and specification
- Critical response: "Does anyone use anything from Mistral because it performs the best... or only 'because EU'?" — sovereignty motivation acknowledged
- Source: https://docs.mistral.ai/models/model-cards/leanstral-1-5-26-06

### LAMP: Lean-based Agentic Framework with MCP and Proof Repair (arXiv 2606.28841)
- Multi-agent framework: Planner + Builder + Verifier with MCP access to domain ontology
- 96.7% verified proof synthesis on 90 Combinatorics on Words theorems
- Ablation: removing tool-grounded architecture OR Planner/Builder separation each costs ~12pp
- **Key result**: domain-specific formal verification WITHOUT fine-tuning — structured inference-time knowledge via MCP
- Source: https://arxiv.org/abs/2606.28841

### Machine-Verified Quantum Optimization Proof via Claude Fable 5 (arXiv 2606.29687)
- Resolves 10+ year open conjecture (Farhi-Goldstone-Gutmann QAOA ring of disagrees)
- Methodology: Claude Fable 5 generates proof; Lean 4 mechanically verifies it
- "Human verification is required only for the structural scaffolding — that the formal statement faithfully encodes the intended claim"
- Model "uncovered a hidden dynamical symmetry" and "borrowed tools from an adjacent field"
- **Structural significance**: The model that was export-controlled (Fable 5) demonstrates its value through a trust-substitute mechanism (machine-verified proof). The product of restricted access proved its worth via a conditionality pathway.
- Source: https://arxiv.org/abs/2606.29687

### Convergence
The three form a stack:
1. **LAMP** = agent architecture for generating proofs (MCP + multi-agent)
2. **Leanstral** = specialized model for proof generation
3. **Fable+Lean** = frontier model proving theorems with kernel verification

All three share the principle: **output accepted conditional on mechanical verification, not model trust.**

## arXiv: Governance Infrastructure

### Intent-Governed Access Control (IGAC, 2606.22916)
- "User intent may only REDUCE authority granted by static policy; it never EXPANDS scopes"
- Intent certificates, session-scoped policy narrowing, intent-tool-payload consistency checks
- Monotone, auditable — intent as constraint, not permission
- Source: https://arxiv.org/abs/2606.22916

### TraceLab: Coding Agent Workload Characterization (2606.30560)
- ~4,300 coding-agent sessions, ~350K LLM steps, ~430K tool calls from day-to-day Claude Code and Codex usage
- Key findings: long autonomous loops, long contexts with short outputs, high but imperfect prefix cache hit rates
- Concrete optimization targets: lower-overhead tool calling, append-length-aware prefill, semantic-aware tool-latency prediction
- Source: https://arxiv.org/abs/2606.30560

### Knowledge-Based Pull Requests (KPR, 2606.26721)
- Separates two traditionally collapsed decisions: "should knowledge enter project?" vs "should implementation merge?"
- Agent interaction traces treated as knowledge source, not merge candidate
- Project-owned trusted agent regenerates code inside receiving project's environment
- Extends Trust Fracture theme: composition across trust boundaries requires knowledge/implementation separation
- Source: https://arxiv.org/abs/2606.26721

### Unfireable Safety Kernel (2606.26057)
- "Any control in the agent's address space is reachable by inputs that influence it"
- Proposes execution-time alignment OUTSIDE agent runtime
- Structural complement to IGAC (intent-level) and export controls (state-level)
- Source: https://arxiv.org/abs/2606.26057

## The Conditional Resolution Pattern

The scan reveals a single structural pattern manifesting at every scale:

| Layer | Unconditional (old) | Conditional (new) |
|-------|--------------------|--------------------|
| **State/policy** | Model freely available | Access conditional on vendor-gov agreement |
| **Vendor/user** | Trust vendor intentions | Trust conditional on transparency (anti-steganography) |
| **Model/output** | Accept model claims | Accept conditional on formal verification |
| **Agent/tool** | Grant tool permission | Permission conditional on intent alignment (IGAC) |
| **Code/merge** | Merge external code | Accept conditional on knowledge extraction + regeneration (KPR) |

**Design principle**: The trust-restoration pathway is dead. The conditional-access pathway is the only resolution modality that works at all scales. Every governance relationship becomes: access IF compliance, evidence, or verification.
