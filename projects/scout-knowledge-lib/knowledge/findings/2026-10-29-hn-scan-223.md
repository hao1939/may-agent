## Thesis

Agent access perimeters cannot be defined by exclusion (blocklists, opt-out,
restrictions), only by inclusion (sandboxes, opt-in, containers). This principle
manifests simultaneously across workspace security, model access governance,
vulnerability discovery, and surveillance — and none of the layers recognize
the shared structural pattern.

## Signal Map

### 1. Codex Sensitive File Exclusion — The Blocklist Illusion (48706714, 132pts/90c)

GitHub issue #2847 on OpenAI Codex: no mechanism to exclude sensitive files
(.env, credentials, private keys) from agent access. Community discourse
crystallizes around structural inadequacy of exclusion-based solutions.

**Key community positions**:
- **TheDong**: "Change file permissions so the user you run codex as can't read
  them, or run codex in a container without those files mounted." Filesystem-level
  isolation, not application-level blocklists.
- **nikhilsimha**: "Files that codex and any other coding agent has access to,
  should be opt-in NOT opt-out." NVIDIA open-sourced **Rumpelpod**
  (github.com/nvidia/rumpelpod) for devcontainer-based agent orchestration
  precisely for this.
- **petcat**: "Hopefully they never actually implement this pointless feature
  because it will only give people a false sense of security given the
  unpredictable nature of LLMs."
- **skybrian**: "We need to stop using .env for security. API keys needed when
  working in a repo should be handled by a proxy like ssh-agent."
- **planb**: "The app that the agent is developing needs access to the file, so
  access to it cannot be blocked."
- **kstenerud**: ".agentsignore is NOT a security tool. It's a good idea as a
  hint to agents about what files it should ignore... However, using it to
  prevent exposure of secrets would be a BIG mistake."
- **kennethops**: "These tools are data collection mechanisms... I'm working with
  some folks to figure out a way to put a layer between the harness and the
  models."
- **bob1029**: "The only thing close to a guarantee is to give the agent
  exclusive access to a clean VM with precisely the information and permissions
  you want it to have."

**Structural insight**: The agent workspace security problem is isomorphic to the
container-host isolation problem in DevOps, but the community hasn't yet
formalized this equivalence. The blocklist approach (.agentsignore) recapitulates
the .gitignore model, but .gitignore works because git is deterministic — an LLM
agent is not. Agent-generated code that needs .env at runtime cannot be developed
by an agent that cannot see .env. The information is needed; only the exposure
channel can be controlled. This requires architectural (container/VM) isolation,
not configuration (blocklist) exclusion.

**Connection**: Directly validates Isolation Imperative (#180), Implementation
Blind Spot (#203), and Governance Vacuum (#170 — 58% single-commit configs).
Extends ActPlane (§2.33) from kernel-level to workspace-level enforcement.

## Synthesis: The Perimeter Impossibility

Five simultaneous manifestations of the same structural principle:

| Layer | Exclusion attempt | Why it fails | Inclusion alternative |
|-------|------------------|-------------|---------------------|
| **Workspace** | .agentsignore blocklist | Agent-generated code needs excluded files at runtime | Container/VM isolation (Rumpelpod) |
| **Model access** | Government gatekeeping | Asian alternatives accelerate +217% | Open-weight models |
| **Vulnerability** | Scanner-based defense | Exploitarium harness bypasses individual scanners | Structural defense (memory safety) |
| **Geopolitics** | Export controls | EU bids for lab hosting; dependency chain | Domestic R&D + open models |
| **Security posture** | Vendor fear-selling | Products sold before technical assessment | Structural posture (practitioner guide) |

**Unifying principle**: Exclusion doesn't scale against capable agents or
agent-augmented adversaries. Every blocklist, restriction, or opt-out mechanism
is defeated by composition — agents find alternative paths, adversaries find
alternative models, infrastructure finds alternative states. Only
inclusion-based architectures (sandboxing, formal verification, container
isolation, opt-in access) provide reliable perimeters.

**Why this matters now**: The convergence is not coincidental. Agent capability
has crossed a threshold where exclusion-based controls cost more to maintain
than the damage they prevent. The Exploitarium author's revelation — that a
domain expert + commodity model + good harness defeats per-tool security
scanning — is the microcosm of the macro-pattern.

**Predictions**:
1. ".agentsignore" or equivalent is NEVER adopted as a security mechanism by
   any major framework (12-month). Container-first agent execution becomes
   default. (Confidence: 85%)
2. Provider-to-provider API restrictions (Google-Meta pattern) become standard
   within 6 months, accelerating open-model adoption 2× faster than government
   restrictions alone. (Confidence: 70%)
3. Security vendor "AI protection" products based on model-blocking (exclusion)
   fail commercially within 12 months; structural defense products (memory
   safety, formal verification) gain share. (Confidence: 65%)
4. At least 2 EU nations make formal sovereignty bids for US AI labs within
   6 months (Austria is first). None succeed in attracting HQ relocation.
   (Confidence: 80%)
