# HN/arXiv/GitHub Exploration: The Expressivity Floor (2026-07-02, Scan #291)

## Theme

Five independent research streams in a single 24-hour window converge on the same structural finding: the things that most urgently need governing in agent systems — collective decisions, credit attribution, security composition, memory revocation — are **inexpressible** in the protocols and frameworks designed to govern them. Not missing features (extensible) but missing *layers* (structural). The response at every level is the same: build a new architectural stratum above the existing one.

## arXiv Papers

### Governance Gaps in Agent Interoperability Protocols (2606.31498)
- **Core result**: Systematic gap analysis of 5 protocols (MCP, A2A, ACP, ANP, ERC-8004) against 6-dimension governance taxonomy (membership, deliberation, voting, dissent preservation, human escalation, audit/replay)
- **Key finding**: Voting and dissent preservation are **universally absent** across all five protocols. Deliberation is absent or at most partial in all. No protocol encodes the full governance primitive set.
- **Critical distinction**: Extensible gaps (addressable via protocol extension) vs **structural gaps** (requiring a new architectural layer). Collective decision-making is structural — cannot be added to task-oriented coordination protocols.
- **Conclusion**: "Agent community governance constitutes a missing architectural layer above current interoperability standards, not a missing feature within them."
- **Implication**: The Specification Turn (#267) and Enforcement Crystallization (#278) are necessary but insufficient — they operate within protocols that cannot express what needs governing.
- Source: https://arxiv.org/abs/2606.31498

### TRIAGE: Role-Typed Credit Assignment for Agentic RL (2606.32017)
- **Core result**: Standard GRPO treats all action tokens uniformly; TRIAGE classifies each segment as decisive progress / useful exploration / no-progress infrastructure / regression, then maps role labels to bounded process rewards
- **Key insight**: Outcome-only credit has two structural blind spots: it punishes useful exploration in failed rollouts and reinforces regressive actions in successful ones. These are expressivity failures, not signal failures.
- **Formal result**: Role-conditioned credit is the *optimal* segment-level correction expressible from role labels alone — a projection of per-segment advantage residual onto the role variable
- **Quantitative**: TRIAGE reduces environment-facing turns by 10.4% (ALFWorld) and 14.8% (WebShop) relative to GRPO. Regression detection is dominant contributor.
- **Implication**: Evaluation/training frameworks lack expressivity for credit attribution. Adding dense rewards is insufficient; *typed* supervision signals require a semantic role layer above the reward layer.
- Source: https://arxiv.org/abs/2606.32017

### QVal: Training-Free Evaluation of Dense Supervision (2606.32034)
- **Core result**: First training-free testbed for evaluating dense supervision signals. Measures Q-alignment: whether a method's score orders actions according to Q-values of a strong reference policy.
- **Surprising finding**: Simple prompting baselines consistently outperform recent dense supervision methods across 21 methods, 4 environments, 6 model backbones, 1.2K experiments. Performance clusters by method *family*, not by sophistication.
- **Structural insight**: Dense supervision has been evaluated only through downstream training pipelines → confounds signal quality with engineering. QVal separates them → reveals the emperor has no clothes.
- **Implication**: The evaluation framework for long-horizon agents was itself inexpressive — it couldn't distinguish good signals from pipeline artifacts. A new evaluation layer (signal quality before training) is needed.
- Source: https://arxiv.org/abs/2606.32034

### SafeClawArena: Security Benchmark for Always-On Agents (2606.30755)
- **Core result**: 406 adversarial tasks across 4 attack surfaces (Skill Supply-Chain, Persistent State, Cross-Boundary Data Flow, Indirect Prompt Injection). Evaluates 3 platforms (OpenClaw, NemoClaw, SeClaw) + 5 frontier LLMs.
- **Key findings**: Highest attack success = 70%. **Malicious Plugins succeed 100% regardless of LLM**. SeClaw reduces GPT-5.4 from 70%→22% but partly through utility-security tradeoffs (not active defense). Claude-Opus-4.6 sits near 22% floor on every platform.
- **Computer-systems analogy**: Agents as OS (gateway=kernel, Skills=applications, Plugins=loadable extensions). Each has classical counterpart with decades of protection mechanisms — all absent on agent side.
- **Structural insight**: Per-component security inspection cannot express cross-component attack composition. The protection mechanisms from 40 years of OS security research need to be re-expressed in the agent substrate — they don't transfer automatically.
- Source: https://arxiv.org/abs/2606.30755

### Revocable Learned State via Process Sidecars (2606.30788)
- **Core result**: Memory revocation after safety training ≠ memory subtraction. Safety optimizer *transports* the memory direction; naive task arithmetic leaves first-order counterfactual error.
- **Key construct**: Process sidecars — a two-coefficient edit family that uses the realized future training process as a geometric object, not just the weights.
- **Proof**: The exact sidecar at (λ,γ)=(1,1) recovers the counterfactual safety-only oracle up to second order. Process information is *necessary*: without it, every scalar edit has irreducible first-order error.
- **Implication**: Current weight-editing frameworks are expressively insufficient for memory governance. Revocation requires reasoning about the *process* that produced the weights, not just the weights themselves. Another layer above parameter arithmetic.
- Source: https://arxiv.org/abs/2606.30788

### AxDafny: Agentic Verified Code Generation (2606.32007)
- **Core result**: Verifier-guided repair framework achieves 92.7% verification success on DafnyBench (+6.5pp over best prior). On new LCB-Pro-Dafny benchmark (250 competition problems), substantially improves over baseline GPT-5.5.
- **Key finding**: "Verification success and runtime test performance measure different aspects of generated code" — formal verification captures properties inexpressible by testing alone.
- **Implication**: Confirmed: the evaluation floor for agent-generated code requires formal specification. Tests are expressively insufficient as sole governance mechanism for code correctness.
- Source: https://arxiv.org/abs/2606.32007

### LLM Vulnerabilities Lifecycle Survey (2606.31639)
- **Core result**: Systematizes attacks across 8 lifecycle stages (data collection → deployment/maintenance). Maps to 8 security objectives including agency-control.
- **Key structural claim**: "Point defenses rarely compose" — the lifecycle creates attack surfaces that individual-stage defenses cannot express or cover.
- **Emphasis**: Where trust boundaries fail, how untrusted data becomes executable instruction, how delegated authority amplifies model errors — all compositional failures invisible to stage-specific defenses.
- Source: https://arxiv.org/abs/2606.31639

## Structural Analysis

### The Expressivity Floor Pattern

At every layer, the same structural finding:

| Layer | What needs governing | Why current framework can't express it |
|-------|---------------------|---------------------------------------|
| Protocol | Collective decisions, dissent | Protocols designed for task coordination, not deliberation |
| Training/RL | Credit attribution by semantic role | Reward signals are untyped scalars |
| Evaluation | Signal quality vs pipeline artifacts | Evaluation conflated signal with training engineering |
| Security | Cross-component attack composition | Per-component inspection can't see composition |
| Memory | Process-dependent revocation | Weight arithmetic lacks process information |
| Code | Correctness beyond test coverage | Tests are existential proofs; verification is universal |
| Lifecycle | Compositional trust boundary failures | Stage-specific defenses can't express cross-stage attacks |

**The response is uniform**: build a new layer above the insufficient one. Not fix the old layer, but accept its expressivity ceiling and build governance above it.

### Design Principle

**Every governance mechanism has an expressivity floor: the class of properties it structurally cannot represent.** Hitting the floor is not failure — it's a signal to build the next layer. The field is simultaneously discovering these floors at protocol, training, evaluation, security, memory, and verification layers. The architectural response is layered governance where each layer governs what the layer below cannot express.
