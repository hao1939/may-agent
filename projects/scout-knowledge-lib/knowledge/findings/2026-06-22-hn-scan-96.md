# HN Scan #96: The Fail-Plausible Crisis

**Date:** 2026-06-22
**Source:** HN (Algolia API), arXiv, GitHub
**Scan type:** Cross-source synthesis

---

## Core Finding

Agent systems are generating a new class of failure that cannot be caught by the traditional crash→log→fix debugging stack: **fail-plausible** — where the system doesn't merely fail silently, but transforms its errors into fluent, convincing narrative delivered to the user or operator. The observer isn't just blind to the failure; they are actively *lied to* by the failure itself.

Six independent signals converge on this finding: a live production incident (Codex TB-scale logging), a longitudinal academic study (Silent Failures taxonomy), a failure-mode framework (AgentArmor), an attention-mechanism explanation (Looking-Is-Not-Picking), a governance architecture (Deontic Policies), and a cost-prediction system (Green SARC). Together they reveal that the problem is not agent capability but **agent legibility** — the system's ability to make its internal state transparent is structurally compromised by the same language fluency that makes it useful.

## Signal Convergence

### 1. Live Incident: Codex Logging Bug (89pts, 16c)

**Source:** https://github.com/openai/codex/issues/28224 (via HN 48626930)

OpenAI's Codex agent writes terabytes of trace logs to local SSDs with no rotation, no cap, and no user notification. Key dimensions:

- **27GB→73MB after VACUUM**: The actual useful data is ~0.3% of what's stored. 99.7% is noise.
- **One week, no response from OpenAI**: The issue sat open with silence from maintainers.
- **Community workaround**: `sqlite3 ~/.codex/logs_2.sqlite "CREATE TRIGGER IF NOT EXISTS block_log_inserts BEFORE INSERT ON logs BEGIN SELECT RAISE(IGNORE); END;"`

**Why this matters structurally**: The bug is not exotic — it's "shipping trace logging at production level," a classic blunder. But the meta-pattern is new:

- **PunchyHamster**: "It was deemed not Hard Enough task for real engineer to look at, so AI was sent to do it with no oversight."
- **rvz**: "The first of many bugs that are beyond the complexity of its authors, thanks to comprehension debt."
- **supriyo-biswas**: "Any time saved in writing the code must be spent on ensuring proper system design, reviewing the code, and QA."
- **cryo32**: "Here I am sitting on a major incident at our company because someone's vibe coded shit went seriously wrong."
- **applfanboysbgon**: "Humans learn from their mistakes, LLMs don't. If you rely on LLMs to generate all your code, you can expect to run into the same issues again and again."

The Codex bug itself is boring. The *discourse* reveals the structural insight: agent-generated code fails in ways where no human develops the scar tissue to prevent recurrence. The same class of error can repeat indefinitely because the learning loop is broken.

### 2. Academic Foundation: Silent Failures Taxonomy (arXiv 2606.14589)

**Source:** https://arxiv.org/abs/2606.14589

"When Errors Become Narratives: A Longitudinal Taxonomy of Silent Failures in a Production LLM Agent Runtime"

A longitudinal study of a production agent system (40 scheduled jobs, 8 LLM providers, 4,286 unit tests, 827 governance checks) over eight weeks, documenting 22 incidents with full root-cause postmortems. The meta-pattern manifested at least 28 times.

**Five-class taxonomy derived**:
- **(A) Environment/platform quirks**: External dependency changes not surfaced
- **(B) Design-assumption mismatches**: Implicit contracts violated without error
- **(C) Error swallowing and dilution**: Error signals exist but are consumed before reaching humans
- **(D) Chained hallucination and fabrication**: *Unique to LLM systems* — the system doesn't merely fail to report an error; it transforms it into plausible narrative
- **(E) Operational omission and forensic blind spots**: No test covers the seam

**Key findings**:
- **~70% of silent failures** caught by human user-view observation, not tests or audits
- **0% ex-ante prevention** from retrospective audit; but **87% regression blocking** — audits are regression engines, not prediction engines
- **Incident latency (13 hours to 60 days)** tracks failure mechanism, not code complexity — the longest-lived failures live in the **seams between components**, where no test runs

**The "fail-plausible" concept**: Class D is the paper's most important contribution. Gray failure's "differential observability" is escalated — the observer is not merely uninformed, they are convincingly lied to. The failure generates its own cover story.

### 3. Failure-Mode Framework: AgentArmor (arXiv 2606.19380)

**Source:** https://arxiv.org/abs/2606.19380

Studies coding agent failures from three distinct mechanisms:
- **Underspecification**: Default model behavior is unsafe (the agent does something dangerous when not told otherwise)
- **Capability errors**: The safe action is available but the model doesn't adhere to it (bias/capability limitation)
- **Agent harness errors**: The model tries to do the safe thing but can't execute it through the harness

Proposes mitigations: extended system prompt, separate command classifier, "3 strikes" policy, deterministic guardrails, and **tools for the agent to edit its own context**.

**Connection to fail-plausible**: Underspecification failures are the most insidious because the agent appears to be working correctly — it is "successfully" doing the wrong thing. The failure is indistinguishable from correct operation until consequences manifest externally.

### 4. Mechanism Explanation: Looking-Is-Not-Picking (arXiv 2606.16364)

**Source:** https://arxiv.org/abs/2606.16364

"LLM agents mis-call tools, and the natural guess is that the model failed to see the right tool in a crowded harness. We show the opposite."

**Key empirical finding**: The model **attends most to the correct tool 80% of the time** (vs. 21% chance). The gold tool is the under-attended segment on only 10% of failures. The model looks at the right tool and still picks wrong.

**The bottleneck is at the decision readout, not the harness:**
- Repairing the prompt (reordering/duplicating the gold tool) recovers ≤23% of failures
- Readout-side interventions recover 59–91%
- Two different gold-pointed interventions in different representations recover largely the *same* failures (Jaccard 0.865)

**Implication for fail-plausible**: The agent's internal representation may be correct — it "knows" the right answer — but the path from representation to action is lossy. This means the agent can *explain* why it should have done X while *doing* Y. Plausibility and correctness are independent.

### 5. Governance Architecture: Deontic Policies / AgenticRei (arXiv 2606.19464)

**Source:** https://arxiv.org/abs/2606.19464

Current policy engines (XACML, Rego, Cedar) address only permit/prohibit. Agent governance requires the full deontic structure:
- **Obligations**: What the agent *must* do after certain actions (e.g., notify the CISO after accessing sensitive data)
- **Dispensations**: Under what conditions a standing obligation may be waived
- **Meta-policy conflict resolution**: Which rules take precedence when policies conflict
- **Ontological reasoning**: Domain class hierarchies for healthcare, cybersecurity, privacy

AgenticRei implements this in OWL (Web Ontology Language) evaluated by a logic engine **entirely outside the LLM**. The same pipeline governs tool invocations AND agent-to-agent messages. Composes with A2AS.

**Connection to fail-plausible**: When the agent can narrate its own failures into plausibility, governance must live *outside* the narrating system. Any governance that relies on the agent's self-report is compromised by fail-plausible. External deontic enforcement is the architectural response: obligations that fire regardless of what the agent claims happened.

### 6. Cost Topology: Green SARC (arXiv 2606.15954)

**Source:** https://arxiv.org/abs/2606.15954

Proves that the unconstrained agent "State Snowball" cost is **Θ(n²) in loop depth**. On 3,000 real multi-step plans (SWE-rebench), median curvature exceeds the linear-accretion prediction — real plans accrete *faster* than the model predicts.

**Key technical findings**:
- Normal-σ gate **under-covers** (92% at nominal 95%); split-conformal calibration holds (95.2%)
- Soft Lagrangian penalty breaches budget on **91.5%** of seeds; architectural gate breaches **0%**
- Token/USD/carbon savings of 47–55% from scope-cap enforcement

**Connection to fail-plausible**: The Codex TB-logging bug is a local instance of the State Snowball. Without architectural gates (not soft penalties), resource consumption becomes quadratic. The agent doesn't "intend" to write TBs — the system lacks the circuit that would notice the trajectory.

## The Fail-Plausible Architecture Gap

| Traditional Software | Agent Systems |
|---------------------|---------------|
| Errors crash or log | Errors narrate |
| Logs are ground truth | Logs are generated text |
| Debugging is replay | Replay is expensive (linear in candidates) |
| Tests prove absence of bugs | Tests prove 87% regression blocking, 0% prediction |
| The developer learns | The system doesn't scar |

**Three structural defenses emerging**:

1. **External logic enforcement** (AgenticRei): Obligations, dispensations, and conflict resolution evaluated by a logic engine outside the LLM. The agent cannot narrate away an obligation it didn't fulfill.

2. **Architectural gates** (Green SARC): Hard budget enforcement with 0% breach vs. 91.5% breach from soft penalties. The system cannot "explain" why it needs more resources.

3. **Attention forensics** (Looking-Is-Not-Picking): When the model's representation of truth diverges from its output, attention-segment analysis can detect the divergence. A readout-side selector closes most of the oracle gap at zero cost.

**The common principle**: Trust the agent's *attention* and *state*, not its *output*. Governance, cost control, and debugging all require inspection mechanisms that bypass the narration layer.

## Practitioner Synthesis: The Comprehension Debt Spiral

The Codex HN thread surfaces a recursive trap:

1. Agent generates code faster than humans can review
2. Comprehension debt accumulates (no human fully understands the system)
3. When failures occur, humans cannot locate the root cause
4. They ask the agent to debug itself
5. The agent narrates the failure plausibly (fail-plausible)
6. The "fix" generates more code that increases comprehension debt
7. Return to step 1

**HPsquared**: "There are going to be sooooo many consulting opportunities after this wave." — The market signal: comprehension debt creates demand for human expertise specifically because agents cannot reliably audit themselves.

**indiv0** (counter-signal): "I've been bitten by a bug exactly like this before in a pre-AI project." — True, but with a structural difference: humans learn from the mistake (scar tissue). The agent that generated the Codex logging code will generate the same class of error next time. The learning loop only closes if someone *external* to the agent encodes the lesson.
