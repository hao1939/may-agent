# Verify both replacement and equivalence in agent migrations

**Date:** 2026-08-25  
**Source:** https://arxiv.org/abs/2608.23564  
**Primary text:** https://arxiv.org/html/2608.23564  
**PDF:** https://arxiv.org/pdf/2608.23564

## Signal

SWE Refactor Bench exposes a failure mode that ordinary red-to-green coding benchmarks cannot see. A whole-repository migration has two distinct obligations: remove the unwanted language, framework, platform, or build toolchain, and preserve the old system's behavior. A submission can satisfy behavioral tests perfectly by returning the original repository unchanged. Hong et al. call this evaluator **Blindness**.

The benchmark therefore evaluates 20 migrations with three ordered stages:

1. **Migration Audit:** source-level criteria check that the old stack disappeared from both repository and build. Each criterion is judged independently three times, with re-checkable evidence required for a failure verdict.
2. **Behavioral Tests:** 130,118 checks replay inputs against the original system's recorded outputs and exit statuses. One mismatch blocks progression.
3. **Agentic Verification:** six coding agents receive both source trees and search for behavior present in the original but missing from the migration. A claimed difference counts only as an executable test that passes on the original, fails on the submission, and reproduces three times.

The funnel separates failure classes that a single score would blur. Across 520 runs from eight models and 26 model-effort configurations, only 28 runs (5.4%) passed all three stages, and 13 of 20 tasks had no accepted solution. Among the 340 runs that passed the migration audit, 58% reached 99% of fixed checks but only 26% reached 100%. Build-toolchain rewrites scored 31.4, versus 5.6 for language rewrites, so “repository migration” is not one uniform capability.

## Design implication: acceptance is a conjunction, not a test total

For a production migration, encode the goal as separately observable predicates:

- **Replacement predicate:** forbidden dependencies, source forms, build paths, and runtime artifacts are absent; required target-stack artifacts are present.
- **Compatibility predicate:** old and new systems agree on a captured behavior corpus, including outputs, errors, exit status, interfaces, packaging, and installation behavior.
- **Residual-risk search:** independent testers generate differential or metamorphic cases outside the fixed corpus, and only executable counterexamples affect the verdict.

Order matters. The replacement predicate should veto before compatibility can earn credit, otherwise an agent can preserve behavior by declining the migration. Compatibility should then be exact where the deliverable promises a drop-in replacement; an aggregate 99% can hide the one downstream consumer that breaks. Finally, exploratory verification should supplement rather than replace the fixed contract.

The same pattern generalizes beyond code migration. Whenever a task says both “change the substrate” and “preserve the service,” evaluation must prove the intended internal transition and the external invariant independently.

## Boundary of the evidence

This is strong benchmark evidence, not proof that the protocol establishes semantic equivalence:

- the suite contains only 20 migrations and category results vary substantially;
- Migration Audit uses model judgments over prompt criteria, although failures must cite evidence and the paper reports human-agreement analysis;
- fixed tests remain bounded by their authored input space;
- six verifier agents finding no counterexample increases confidence but does not demonstrate equivalence—the paper explicitly scores this as degree of evidence;
- the reported results apply to the evaluated repositories, harnesses, model versions, and time budgets, not all long-horizon maintenance.

The durable conclusion is narrower: **behavior-only acceptance is structurally incapable of proving that a requested migration happened**. Source-level completion and behavior preservation need separate gates, followed by adversarial differential search for what both predefined gates missed.
