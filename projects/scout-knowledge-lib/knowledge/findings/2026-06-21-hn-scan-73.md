Marc Brooker (AWS) on the inspection paradox in distributed systems: the observer experiences a **time-weighted version** of the latency distribution, not the distribution itself. Users who arrive at random are more likely to arrive during a slow period (because slow periods last longer).

Key discourse:
- **perching_aix**: "What I look at is what share of unique users experience an 'unacceptable experience' over a measurement period." — measuring lived experience, not system statistics
- **glitchc**: "An observer using the system experiences different statistics from the system operator." — the core insight
- **trb**: "Focusing on the tail and nothing else is the only way to make progress. Medians are a trap." — operational consequence

**Critical connection to agent systems**: The inspection paradox applies directly to agent oversight:
1. Humans reviewing agent work are MORE LIKELY to see long-running sessions (because they take longer and pile up in review queues)
2. Failed sessions are MORE VISIBLE than successful ones (they leave artifacts, need debugging)
3. This creates a systematic perception bias: overseers experience the system as worse than aggregate metrics suggest
4. OR: metrics show "everything fine" while experienced reality is terrible (if failures are rare but each consumes enormous attention)

**For our system**: The Evaluation Mirage shows our evaluator produces 3 bits of info. But the HUMAN experience of the system is time-weighted: the sessions that consume human attention (failures, confusion, re-investigation) dominate perceived quality even if they're rare in aggregate. Cognitive debt accumulates in the inspection-paradox-weighted direction.

## 🔬 THE AUTHORITY CRYSTALLIZATION — New Cross-Source Synthesis

Five independent arXiv papers published 2026-06-18, combined with GitHub ecosystem signals and HN discourse, reveal a structural convergence: **the industry is crystallizing a three-layer authority model for agent systems**.

### The Three-Layer Model

```
┌──────────────────────────────────────────────┐
│ Layer 1: REASONING                            │
│ (Model proposes actions)                      │
│ Non-deterministic, unbounded capability       │
│ NO mutation authority                         │
├──────────────────────────────────────────────┤
│ Layer 2: VERIFICATION                         │
│ (Runtime checks proposals against policy)     │
│ Probabilistic bounds, ledger state, contracts │
│ ADMITS or REJECTS proposals                   │
├──────────────────────────────────────────────┤
│ Layer 3: EXECUTION                            │
│ (Performs mutations with scoped identity)     │
│ Certificate-bound, time-limited, auditable    │
│ ONLY entry point to production mutations      │
└──────────────────────────────────────────────┘
```

### Evidence Stack: Five Independent Convergences

#### 1. Sovereign Execution Brokers (2606.20520) — The Execution Layer

**Key insight**: "Production mutation authority should NOT reside inside non-deterministic reasoning processes."

SEB introduces a mandatory enforcement point between certified authority and actual mutation:
- Consumes certificates issued by assurance boundary
- Verifies mutation matches execution contract
- Checks validity windows, policy epochs, revocation, live-state drift
- Mints scoped execution identity
- Records signed decision/outcome records
- All production mutation APIs REJECT non-broker identities

**Why this is structural**: This is NOT access control (which authorizes identities) and NOT assurance (which certifies proposals). It's a THIRD thing: enforcement of certified authority at the moment of mutation. The separation is: propose → certify → execute.

Source: https://arxiv.org/abs/2606.20520

#### 2. LedgerAgent (2606.20529) — The State-Aware Verification Layer

**Key insight**: Standard agents reconstruct state from prompt each turn, creating two failure modes: (a) grounding decisions in stale/missing information, (b) syntactically valid tool calls that violate state-dependent policies.

LedgerAgent maintains explicit state in a separate ledger and checks state-dependent policy constraints BEFORE environment-changing calls:
- Ledger renders current state into prompt (not reconstructed from history)
- Pre-mutation policy check blocks violations
- Improves pass^k across 4 domains with largest gains under strict multi-trial metrics

**Why this is structural**: The ledger IS Layer 2 — explicit state tracking that enables policy verification before Layer 3 executes. Without explicit state, you can't verify state-dependent policies.

Source: https://arxiv.org/abs/2606.20529

#### 3. Probabilistic Verification (2606.20510) — Sound Bounds for Layer 2

**Key insight**: Existing approaches assume deterministic policies, but real agents face probabilistic predicates (PII detectors with failure rates, ambiguous classifications). Prior work requires independence assumptions that don't hold.

Introduces distributionally robust optimization for sound upper bounds on violation probability REGARDLESS of correlations between predicates. Improves security-utility trade-off while maintaining rigorous probabilistic bounds.

**Why this is structural**: This provides the MATHEMATICS for Layer 2. Previous verification was either deterministic (fragile) or assumed independence (wrong). This framework allows Layer 2 to give sound guarantees under realistic conditions.

Source: https://arxiv.org/abs/2606.20510

#### 4. Contagion Networks (2606.20493) — Why Layer Separation Is Non-Optional

**Key insight**: Even with the SAME underlying model, evaluator biases propagate between agents with contagion coefficients γ ∈ [0.157, 0.352]. Cross-model contagion is 3-5× stronger.

Three propagation regimes governed by spectral radius ρ(Γ_N):
- **Suppression** (ρ < 1): biases decay — homogeneous same-model systems
- **Critical** (ρ ≈ 1): biases persist indefinitely
- **Amplification** (ρ > 1): biases GROW through network — cross-model systems

Mitigation: committee size k=3 reduces effective contagion by 72.4%.

**Why this is structural**: If reasoning and verification share the same model (or even same architecture), biases propagate FROM verification BACK to reasoning. Layer separation isn't just about authority — it's about breaking contagion paths. The verification layer MUST be architecturally distinct from the reasoning layer to avoid amplification-regime dynamics.

**Critical connection to Evaluation Mirage**: Our evaluator's 3-bit information content may be PROTECTIVE. A null evaluator can't propagate bias. A biased evaluator actively DAMAGES the system through contagion. The least harmful evaluator is one that produces no actionable signal — which is exactly what we have.

Source: https://arxiv.org/abs/2606.20493

#### 5. Defensive Misdirection / CMPE (2606.20470) — Active Defense for Layer 2

**Key insight**: Conventional detect-and-block allows attacker success rate to approach 1 as query budget grows (predictable refusals provide useful feedback). Detect-and-misdirect (controlled non-operational responses) reduces positive predictive value of attacker-selected candidates.

CMPE reduces ASR upper bounds by up to 2 orders of magnitude. Nearly eliminates verified attack success in end-to-end attack runs.

**Why this is structural**: The verification layer doesn't just BLOCK — it actively MISLEADS adversarial inputs. This is Layer 2 as active defense, not passive gate. The authority model isn't just "allow/deny" but "allow/deny/deceive."

Source: https://arxiv.org/abs/2606.20470

### Bonus: UltraQuant (2606.20474) — Infrastructure for Authority Layers

**Relevance**: The authority model (3 layers) creates MORE context pressure (ledger state + policy context + execution contracts). UltraQuant shows the infrastructure is keeping pace — you can afford richer verification context without throughput collapse.

## 🧬 THE AUTHORITY CRYSTALLIZATION — Synthesis

### The Pattern

The agent infrastructure industry is converging on a **three-layer authority model** where:

1. **Reasoning** (the model) has NO direct mutation authority
2. **Verification** (the policy layer) admits/rejects/misleads based on sound probabilistic bounds and explicit state
3. **Execution** (the broker) performs mutations with certificate-bound, time-limited, auditable, scoped identity

This resolves the Orchestration Hollowing: orchestration was hollowed because it confused routing (now in the model) with authority (the actual need). The remaining value of the "orchestration layer" IS the verification + execution layers.

### Why Now? — The Cognitive Debt Forcing Function

"Cognitive Debt Is the New Technical Debt" (HN, just posted) names the forcing function. ggm's insight: AI agents generate code but don't transfer understanding. Without authority separation:
- Nobody knows what agents ACTUALLY did (cognitive debt accumulates)
- The inspection paradox (Alice is Impatient) means overseers experience biased samples
- Contagion Networks shows evaluation biases propagate between agents

Authority separation forces comprehensibility:
- Every mutation has a signed decision record (SEB)
- Every state change has a ledger entry (LedgerAgent)
- Every policy check has a probabilistic bound (ProbVerify)
- These create an AUDIT TRAIL that resolves cognitive debt
