# HN Scan #204 — The Protocol Absorption

**Theme**: Agent protocols succeed by absorption, not cooperation. MCP wins by becoming the agent-to-agent protocol practitioners actually use — hiding agents behind MCP tool interfaces rather than adopting A2A. Meanwhile, Microsoft ships a fourth protocol layer (AHP) that nobody asked for.

**Scan date**: 2026-06-28 | **Source**: HN + GitHub | **Scan type**: HN exploration

## Novel Finding: Protocol Absorption as Competitive Strategy

The agent protocol landscape is resolving — not through consolidation into a layered stack, but through **one layer absorbing the others**.

### Evidence: A2A Practitioner Retreat (HN 48582679, 96pts/45c)

The "Ask HN: Is anyone using A2A?" thread now has enough practitioner reports to declare a verdict. The thread reveals three adoption archetypes:

**Archetype 1 — Enterprise Adopters (minority)**:

**Archetype 2 — Tried and Retreated (plurality)**:

- winwang: "A2A didn't fit the use case of 'trusted agent', and was bloated."

**Archetype 3 — Principled Rejectors**:
- nyellin: "Designed on paper by someone with **no understanding of prompt caching** and no consideration of latency or token costs."

**The decisive signal**: bckr and thallavajhula both started with A2A and retreated to MCP. This isn't protocol fatigue — it's **protocol absorption**. MCP absorbed A2A's use case when practitioners discovered they could put an entire agent behind an MCP server and get agent-to-agent communication for free, without a new protocol.

### Evidence: Microsoft AHP — The Fourth Protocol Nobody Asked For

Microsoft's VS Code team announced **AHP (Agent Host Protocol)** (github.com/microsoft/agent-host-protocol, 65★), a "synchronized, multi-client state protocol for AI agent sessions."

**What it solves**: Multiple clients (VS Code, terminal, mobile) connecting to a single agent session server and seeing synchronized state via immutable state, pure reducers, and write-ahead reconciliation.

**Protocol stack position**: This is Layer 3 — neither tool access (MCP/L0), agent-to-agent (A2A/L1), nor agent-to-frontend (AG-UI/L2). It's host-to-client state synchronization.

**SDK breadth**: Swift, Rust, Kotlin, TypeScript, Go — an unusual multi-language push for a 65★ repo. VS Code integration is the reference implementation.

**Community reaction**: roblourens (VS Code team member) announced it in the A2A thread as an alternative direction — implicitly positioning AHP as what VS Code needs instead of A2A.

**Prediction**: AHP will be absorbed into VS Code internally but will not achieve external ecosystem adoption. The pattern repeats: each major vendor ships its own protocol layer, the ecosystem consolidates on MCP, and the vendor-specific layers become internal implementation details.

### The Weave Router Signal (48688700, 167pts/97c)

The Weave Router thread crystallized why protocol absorption happens:

**Community critique is unanimous**: routing across models breaks prompt caching (5-min TTL). stpedgwdgfhgdd: "How does this router translate to $$$ when developing?" _pdp_: "It might actually burn more money." ai_slop_hater: "By routing to different models you give up on cache." g00k: "The way I prompt already changes based upon what model I am using."

**Connection to protocol absorption**: Model routing fails because cache coherence requires same-model persistence. Protocol routing fails for the same reason — protocol context caching requires same-protocol persistence. Once an ecosystem invests in MCP context (tool descriptions, server implementations, auth flows), switching to A2A for agent-to-agent communication destroys accumulated context. The "agent-behind-MCP" pattern preserves MCP context investment.

## Structural Insight: The Absorption Principle

**Protocols succeed by absorption, not by cooperation in a layered stack.**

The implicit assumption behind the MCP/A2A/AG-UI taxonomy was that each protocol would specialize in one edge (tool, agent, frontend) and they'd compose into a clean stack. Instead:

1. **MCP absorbed A2A's use case** — "agent-behind-MCP" makes dedicated agent-to-agent protocol unnecessary for most cases
2. **MCP is absorbing memory/context** — Statey, BetterDB, agent-memory-engine all expose memory through MCP tools, not through a separate memory protocol
3. **MCP is absorbing evaluation** — Topos exposes code quality metrics through MCP, not through a separate evaluation protocol
4. **MCP is absorbing security** — Diplomat-agent scans MCP servers, CapFrame audits MCP authority — security assumes MCP is the interface

**Why absorption works**: Integration cost scales super-linearly with protocol count (Composition Tax, scan #184). Each new protocol requires new auth, new context, new caching, new debugging tools. Practitioners minimize total cost by stretching one protocol beyond its design scope rather than adopting multiple purpose-built protocols.

**The absorption boundary**: MCP cannot absorb what it structurally cannot represent:
- **Real-time state synchronization** (what AHP solves) — MCP is request/response, not streaming state
- **Payment settlement** (what x402 solves) — MCP has no payment primitive
- **Identity portability** (what DID/ATProto solve) — MCP couples identity to the hosting server

These three unabsorbed edges predict where new, durable protocol layers will emerge — but only when the use case is popular enough to justify the integration cost.
