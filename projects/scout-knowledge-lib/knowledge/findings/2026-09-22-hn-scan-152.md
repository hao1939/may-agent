## Core Finding

Between June 3–20, 2026, **seven distinct products** launched on HN targeting the same problem: making AI coding agents remember across sessions and across tools. This constitutes a **product category crystallization** — the movement from scattered experimentation ("memory is a problem") to a named, investable market segment ("cross-agent memory infrastructure").

This finding is distinct from scan #138 (Memory Hardening Stack from arXiv), which covers the formal security architecture. Here we track the **commercial/OSS product wave** implementing memory layers in practice.

## Three Competing Architectural Philosophies

### 1. "Cloud Brain" (Hyper, Parcle, Lore)
- Memory is a centralized service agents connect to
- **Hyper's innovation**: typed relationship edges between facts (X supersedes Y, A contradicts B, J is derived from K). Auto-invalidation on new ingestion.
- **Parcle's claim**: median 30% token reduction, up to 70%, from eliminating repeated context loading
- **Risk**: vendor lock-in, latency, privacy concerns

### 2. "Git-Native" (Agents Remember, Maccha)
- Memory lives as files alongside code, versioned with git
- **Agents Remember's innovation**: the "memory ledger" — a lookup table mapping code repo commits to memory repo commits. Enables dual-worktree isolation (memory changes stay local until feature merges clean). Staleness detection via commit hash in every doc header.
- **Maccha's innovation**: 7-tier hierarchy (project → module → file) with Memanto providing vector embeddings and confidence decay across the file layer
- **Risk**: merge conflicts, scaling limits for large teams

### 3. "Local Database" (PMB, YourMemory)
- SQLite/vector DB running on developer's machine
- **PMB's contribution**: surfaces THE unsolved UX question — should memory be explicit or implicit?
- **YourMemory's contribution**: first to apply biological forgetting curves (Ebbinghaus) to agent memory; proves +16pp recall improvement from decay
- **Risk**: no team sharing, per-developer fragmentation

## Discourse Signals

### "Multi-LLM Orchestration" Ask HN (48593979, Jun 19)
User `ch3coohlink`: "The subagent doesn't feel like collaboration, more like context pollution prevention." This frames the problem: without shared memory, multi-model orchestration is just sequential isolation. Memory is the prerequisite for genuine agent collaboration.

### OQP Verification Protocol (47758560, Apr 13, 8pts)
Defines `/verification/execute` and `/context/workflows` endpoints — verification standard for AI agents. Uses a Knowledge Graph as "source of business rules." Signals convergence: verification needs memory, memory needs verification. The two categories will merge.

### Hyper Launch Thread Discourse (79pts, 5 comments)
Two independent commenters ask the same question: "How do you handle contradicting sources?" and "How do you deal with conflicting facts?" — **conflict resolution is the consensus unsolved problem** across all approaches. No product has a satisfactory answer. This maps to scan #138's L4 (Origin Binding) gap.

## The Token Tax Thesis (Parcle)

Parcle's framing deserves special attention:

> "Every agentic system I see has the same hidden tax: the model keeps rereading the same context. Tickets, Slack threads, docs, customer history... agents start most tasks trying to re-explore everything."

They claim:
- Anthropic says agents use ~4x more tokens than chat
- Parcle sees 30–70% token reduction with memory pre-retrieval
- Biggest savings on "data and context-heavy workflows" (support, ops, research, sales, finance)

**If true, this means >50% of agentic token spend is the re-exploration tax** — agents repeatedly paying to understand what they already knew in a prior session.
