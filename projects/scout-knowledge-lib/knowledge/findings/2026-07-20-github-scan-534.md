# GitHub Scan 2026-07-20 — Agent Governance Tooling

## Summary

Third pass today, query `ai agent created:>2026-07-18` and `agent framework created:>2026-07-19`. The dominant new signal is **agent governance** — tooling that makes multi-agent workflows auditable and safe rather than faster. Two repos stand out as novel contributions not covered in prior scans.

## Notable Repos

### 1. z35068037/whichrules — Instruction-Stack Conflict Detector (4★)

- **Repo:** [z35068037/whichrules](https://github.com/z35068037/whichrules) (4★, created 2026-07-20)
- **What:** CLI (`npx whichrules src/file.ts --agent all`) that resolves the effective instruction stack (AGENTS.md, CLAUDE.md, .cursor/rules/, copilot-instructions.md) for a target file across five agents, flags contradictions, and can fail CI on conflicts.
- **Signal:** As instruction-file proliferation grows (each agent reads different files with different scoping), contradiction detection becomes necessary infrastructure. This is the "linting layer for agent prompts" — analogous to how ESLint emerged once JS codebases grew complex enough for style conflicts to matter. The cross-agent view (Codex + Claude + Cursor + Copilot + Gemini) is the key differentiator. Supports HTML reports for PRs and CI integration.
- **Pattern:** **Instruction observability** — making the invisible prompt context visible and auditable. Connects to our agent-runtime-hardening notes and the broader transparency theme.

### 2. Gentoflakes/warden — Audit-Gated Orchestration for Parallel Agents (1★)

- **Repo:** [Gentoflakes/warden](https://github.com/Gentoflakes/warden) (1★, created 2026-07-19)
- **What:** Python orchestrator (zero runtime deps) that runs each coding task in an isolated git worktree, then enforces two gates before considering it mergeable: (1) deterministic verify commands (tests/builds), (2) an independent audit agent that diffs the branch and checks for scope violations, weakened validation, and symptom patches. Fail-closed: no verdict = fail. Never auto-merges.
- **Signal:** This directly addresses the "ten agents, zero trust" problem. The key insight: *spawning* parallel agents is commoditized; *knowing which output to keep* is unsolved. The dual-gate pattern (deterministic + LLM audit) is a defense-in-depth approach. The "independent audit agent with fresh context" prevents the working agent from marking its own homework. Connects to our multi-agent-coordination and agent-security notes.
- **Pattern:** **Audit-as-a-gate** — using a second agent as an adversarial reviewer rather than a collaborator. The structural verdict format (`AUDIT: PASS/FAIL`) avoids the LLM "maybe" problem.

### 3. byQuexo/agent-approval-gate — Human-in-the-Loop Tool Call Gate (1★)

- **Repo:** [byQuexo/agent-approval-gate](https://github.com/byQuexo/agent-approval-gate) (1★, created 2026-07-19)
- **What:** TypeScript middleware that intercepts LLM agent tool calls and requires human approval before execution. Configurable allow/deny lists per tool.
- **Signal:** Minimal but fills the gap for teams that want agent autonomy *except* for specific high-risk tools (file deletion, deployment, etc.). The pattern is "default-deny with progressive trust" — opposite of the current "default-allow with post-hoc review" norm.

## Emerging Pattern: Agent Governance Layer

All three repos address the same meta-problem: **as agent parallelism and autonomy increase, governance tooling must catch up**. The governance stack emerging:

| Layer | Tool | Function |
|-------|------|----------|
| Pre-execution | whichrules | Detect contradictory instructions before agents act |
| During-execution | agent-approval-gate | Gate high-risk tool calls |
| Post-execution | warden | Audit agent output before merge |

This is the same pattern as DevSecOps (shift-left security) applied to agent workflows. The market is moving from "make agents faster" to "make agents trustworthy."
