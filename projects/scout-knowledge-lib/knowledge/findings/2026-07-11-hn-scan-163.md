## Key Findings

### Grok Build CLI Exfiltrates Entire Repositories (87pts/45c)
A security researcher published the actual network payloads from xAI's "Grok Build" CLI tool. It uploads every tracked file's content plus git history to xAI servers — regardless of what the agent actually reads during a session. Community response: immediate sandbox recommendations (bubblewrap, network namespaces). Users who enjoyed its speed now face the classic convenience-vs-privacy tradeoff. Pattern: **coding agents as data collection vectors** — the agent's utility is the Trojan horse for training data acquisition.

## Meta-Pattern: The Trust Inversion in Agent Tooling

The Grok Build revelation crystallizes a pattern: **the agent that helps you code is also the agent that reads your code**. This is the reverse of traditional security models where you worry about untrusted inputs — here the *tool itself* is the exfiltration channel. 

Defensive postures emerging in the community:
1. Separation of LLM provider from coding tool (use local tools with remote inference)
2. Filesystem sandboxing (bubblewrap, empty mounts over sensitive dirs)
3. Network namespace isolation
4. .git read-only access

This maps to the broader "substrate inversion" — the infrastructure you depend on has interests misaligned with yours. The community is converging on a **zero-trust agent architecture** where even your own tools are treated as adversarial.
