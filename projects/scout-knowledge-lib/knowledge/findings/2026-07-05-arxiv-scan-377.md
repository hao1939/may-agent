# Scan #377: The Verification Substrate (2026-07-05, arXiv)

**Theme**: Seven independent papers from the July 2 arXiv batch converge on a single structural claim: agent reliability depends not on model capability or tool access, but on what the agent can *verify* about its own state and the external world. Verification is not a quality gate applied after generation — it's the substrate on which agent reasoning operates.

---

## Core Papers

### 1. Reasoning effort, not tool access, buys first-try reliability (2607.02436)

**Source:** https://arxiv.org/abs/2607.02436

90 independent agent runs building the same app from one spec. Testing tool raised cost 42–68% **without improving functional score or reliability**. Raising reasoning effort from High to xHigh lifted first-try perfect runs 28%→89% and cut corrective prompts ~5×, for only 9–29% more cost.

**Key insight:** Tools check *appearance* (did the button render?). Reasoning effort checks *correctness* (did I satisfy the specification?). The bottleneck was never observation — it was verification of the agent's own reasoning chain.

### 2. Grounded autonomous research (2607.02329)

**Source:** https://arxiv.org/abs/2607.02329

End-to-end LLM pipeline from 11,083 arXiv papers to publication-grade manuscript with three physics findings. 47 fresh-context sessions, 2,162 literature-consultation events. Key mechanism: **structurally enforced numerical confrontation at calibration checkpoints**. Without these checkpoints (no-pilot ablation), the agent hallucinates "plausible, unverifiable results from internal priors."

**Key insight:** The operative grounding mechanism is not retrieval but *confrontation* — forcing the agent to reproduce known results before claiming novel ones. Verification by reproduction, not by retrieval.

### 3. Coding-agents replicate scientific ML papers (2607.02134)

**Source:** https://arxiv.org/abs/2607.02134

12 independent runs across 4 papers. All 158 recorded targets matched with report coverage. Completion depends on **workspace evidence and validation checks rather than the agent's final message**. Repeated runs differ in numerical fidelity, elapsed time, intermediate executions — but all pass the completion gate.

**Key insight:** The agent's self-assessment ("I'm done") is unreliable. Only workspace-recorded evidence counts. This formally separates the agent's *claim* from the system's *verification*.

### 4. ContextNest: Verifiable Context Governance (2607.02116)

**Source:** https://arxiv.org/abs/2607.02116

Formalizes **context governance** beneath retrieval: provenance, version identity, integrity, traceability, point-in-time reconstruction. SHA-256 hash-chained version histories, graph-level checkpoints, audit traces. Governed selection achieves 97% answer quality (vs. 93–90% BM25) at ~1/3 input-token cost. Dense+HNSW is non-deterministic on 80% of queries (mean Jaccard 0.611).

**Key insight:** RAG gives you relevance. Governance gives you *verifiability*. Without governance, you can't reconstruct which knowledge versions informed an agent output or whether they were current when consumed. The verification layer sits *beneath* retrieval, not above it.

### 5. AgenticSTS: Bounded-Memory Testbed (2607.02255)

**Source:** https://arxiv.org/abs/2607.02255

Every decision made from a fresh user message assembled by **typed retrieval** — no raw cross-decision transcript appended. Prompt stays bounded across runs of any length. Any memory layer can be ablated in isolation. The no-store baseline wins 3/10 games; adding triggered strategic skills: 6/10.

**Key insight:** Separating evidence from transcript makes verification compositional. You can test whether adding a memory layer helps by ablating it — impossible when state is entangled in the prompt history.

### 6. UA-ChatDev: Uncertainty-Aware Multi-Agent Collaboration (2607.02186)

**Source:** https://arxiv.org/abs/2607.02186

Integrates uncertainty quantification (token-level log probabilities) into multi-agent collaboration. Phase-aware threshold calibration selectively triggers retrieval-based verification when uncertainty exceeds acceptable levels. Prevents **hallucination propagation** — incorrect early-phase decisions cascading to downstream agents.

**Key insight:** Not all outputs need verification — but the system must know *which* outputs to verify. Uncertainty is a verification trigger, not a quality metric.

### 7. Atomic Task Graph (ATG) (2607.01942, NEW — not previously covered)

**Source:** https://arxiv.org/abs/2607.01942

Explicit DAG exposes input-output dependencies between subtasks. During planning: recursive decomposition into evolving DAGs. During execution: independent branches run in parallel. On failure: graph evolution history localizes error source; repair only the affected region. Outperforms baselines on 7B–8B backbones.

**Key insight:** Making dependencies explicit transforms verification from a whole-system check to a *targeted* check. When a subtask fails, the graph tells you exactly which downstream results are invalidated. Verification becomes graph-local, not trajectory-global.

## Synthesis: Three Competing Verification Models

These seven papers reveal three distinct approaches to agent self-verification, each with different cost/coverage tradeoffs:

### Model 1: State Externalization

**Papers:** ATG (2607.01942), AgenticSTS (2607.02255), ReContext (2607.02509)

Make all agent state explicit, typed, and inspectable. Verify by structural inspection: Are the right fields populated? Do the dependencies resolve? Is the evidence fresh?

- **Strength:** Cheapest per-verification. Compositional (layers can be ablated). Enables parallel execution and targeted repair.
- **Weakness:** Doesn't catch *semantic* errors. A structurally valid task graph can contain wrong answers. Correct provenance doesn't mean correct content.

### Model 2: Numerical Confrontation

**Papers:** Grounded Research (2607.02329), Paper-replication (2607.02134)

Verify by reproducing quantitative claims against external reference points. Force the agent to demonstrate correctness, not just assert it.

- **Strength:** Catches real errors, including subtle numerical and methodological mistakes. The operative grounding mechanism for frontier scientific autonomy.
- **Weakness:** Expensive (2,162 literature consultations for one manuscript). Domain-specific — requires quantitative reference points. Doesn't scale to open-ended creative tasks.

### Model 3: Uncertainty Thresholding

**Papers:** UA-ChatDev (2607.02186), Online Safety Monitoring (2607.02510)

Measure the agent's own confidence at the token/phase level. Escalate to verification (retrieval, human review, fallback) only when uncertainty exceeds calibrated thresholds.

- **Strength:** Adaptive — verification effort scales with difficulty. Low overhead on easy decisions.
- **Weakness:** Requires calibrated uncertainty estimates, which face the same challenges as the models themselves. Can be overconfident on novel failure modes.

### Competitive Landscape

| Verification Model | Cost per Check | Coverage of Semantic Errors | Scalability | Best Domain |
|---|---|---|---|---|
| State Externalization | Low | Low | High (parallel) | Software engineering, workflow orchestration |
| Numerical Confrontation | High | High | Low (sequential) | Scientific research, financial modeling |
| Uncertainty Thresholding | Adaptive | Medium | Medium | Multi-agent pipelines, production safety |

**The strategic question:** which model does a system adopt, and when does it switch? The July 2 batch suggests the field is discovering that *no single verification model is sufficient*. Grounded Research uses all three: explicit state (on-disk session isolation), numerical confrontation (calibration checkpoints), and uncertainty triggers (adversarial review catches what sessions miss).

- **Comprehension Imperative (#370):** Verification *is* comprehension made operational. You can only verify what you understand.
- **Legibility Threshold (#371):** Below the legibility threshold, verification degrades to rubber-stamping. The trimodal model (defer/rubber-stamp/reason) maps directly to the three verification models.
- **Infrastructure Paradox (#374):** Infrastructure for verification proliferates faster than understanding of what to verify. State externalization tools are abundant; knowing which states matter is scarce.
- **Harness Coupling (#376):** The verification substrate co-evolves with the model. Post-training inside a forgiving harness weakens the model's ability to self-verify against strict schemas.
- **Skill Supply Chain Crisis (#375):** Static skill scanners are a failed verification model (appearance-based). SkillDetonate's behavioral runtime detection = numerical confrontation applied to security.

## Design Implications for Our System

1. **Our current model:** We primarily use State Externalization (workspace files, context updates, CLAUDE.md). This is the cheapest model but catches the fewest semantic errors.
2. **The gap:** We have no Numerical Confrontation layer — no mechanism to force an agent to demonstrate its claim is correct by reproducing a known result.
3. **The opportunity:** UA-ChatDev's phase-aware uncertainty thresholding could be adapted for our multi-agent pipeline. High-uncertainty code reviews get escalated; low-uncertainty ones proceed.
4. **The ATG pattern:** Our task decomposition is currently implicit in the agent's reasoning. Making dependencies explicit (ATG-style) would enable targeted repair instead of full-session retries.

*The paradox of the Verification Substrate: the more capable the model, the more it needs external verification — because capability amplifies both correct and incorrect reasoning equally. A perfect agent wouldn't need verification. A practical agent needs a verification substrate as rich as its reasoning substrate.*
