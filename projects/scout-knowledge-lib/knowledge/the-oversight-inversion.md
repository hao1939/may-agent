# The Oversight Inversion: When Verification Costs More Than Production

**Type:** Cross-Source Synthesis  
**Created:** 2026-07-05 (Scan #382). Elevated to standalone thesis: 2026-07-14.  
**Status:** Active — empirically validated across HN, arXiv, XHS, and internal production data  
**Extends:** Bottleneck Naming (#378), Comprehension Imperative (#370), Legibility Threshold (#371)  
**Connected theses:** Judgment Tax (#389), Cost Inversion Threshold (#404), Governance Depth (#405), Abstention Decay, Subtraction Deficit, Verification Commons Collapse

## Core Thesis

Production cost has collapsed faster than oversight cost, inverting the traditional bottleneck. The old world: production was expensive, oversight was cheap (a developer understands their own code). The new world: production is near-free ($149 for a AAA game port), but oversight is expensive, cognitive, physiological, and scaling super-linearly with output volume.

**The system hasn't adjusted.** Organizations still budget as if production is the constraint. Developers still work as if code-they-wrote is code-they-understand. Frameworks still optimize for output velocity, not oversight capacity. The result: rubber-stamping (approving without verifying), burnout (verifying at unsustainable cognitive cost), or fragility (deploying unverified code).

```
┌─ OLD MODEL ──────────────────────────────────┐
│  Production cost: HIGH (developer writes code)│
│  Oversight cost:  LOW  (developer reads code) │
│  Bottleneck:      Production capacity          │
│  Failure mode:    Can't build fast enough       │
└───────────────────────────────────────────────┘

┌─ NEW MODEL ──────────────────────────────────┐
│  Production cost: NEAR-ZERO ($149, agent)     │
│  Oversight cost:  HIGH (reviewer reads agent  │
│                   code they didn't write)      │
│  Bottleneck:      Oversight capacity           │
│  Failure mode:    Can't verify fast enough     │
└───────────────────────────────────────────────┘
```

## Evidence Base

### Layer 1: The $149 Signal (HN, July 2026)

Two independent demonstrations collapsed production cost to a visible, memorable number:

- **C&C Generals port** (588pts, HN 48788283): Entire AAA game (Command & Conquer Generals + Zero Hour) natively ported to macOS/iPhone/iPad via Claude Fable for $149. DirectX 8 → DXVK → Vulkan → MoltenVK → Metal. Campaign, skirmish, multiplayer all working.
- **sqlite-utils 4.0rc2** (54pts, HN 48791708): Simon Willison's established library rewritten for $149.25 by Claude Fable. Community immediately found an unfixed state-corruption bug in `delete_where()`.

The $149 figure became the community's shorthand for the inversion. Production cost is now a rounding error. But the community also surfaced what $149 doesn't buy:
- Verification that the port actually works correctly on all devices
- Tests that catch state-corruption bugs the agent introduced
- Maintenance when upstream dependencies change
- Copyright clarity (EU law doesn't grant copyright to AI-generated works)
- Expertise to debug the 5-layer rendering pipeline when it breaks

**Structural observation:** The $149 is the production cost. The oversight cost is everything else — and it's invisible, unbounded, and unaccounted.

Source: https://news.ycombinator.com/item?id=48788283, https://simonwillison.net/2026/Jul/5/sqlite-utils-fable/

### Layer 2: The Physiological Cost (HN + Internal Data)

"Programmers Need to Start Meditating" (75pts, HN 48792080) is not a wellness post — it's a practitioner field report on the physiological cost of sustained agent oversight:

> *"I was used to getting a lot done very quickly, with intense pockets of work followed by downtime. Now it feels more like a steady stream of medium stress, and there is no opportunity for downtime."* — ehnto

> *"He told me that wasn't normal, and I shouldn't have to meditate just to function at work."* — testfrequency

> *"Programming used to be a meditative activity… why get overwhelmed by LLMs and meditate to calm down, when you can just write the code yourself at a healthier pace?"* — sph

Developers independently converge on three self-governance strategies:
1. **Temporal partitioning**: "mornings without any LLM-assisted work, keeping it only for after 11" — create agent-free zones
2. **Concurrency limits**: "I try not to context switch when doing agentic programming. Instead, I use a single agent thread" — self-imposed serialization
3. **Mode partitioning**: Use one interaction mode (inline OR chat) per task, never both

These strategies mirror — at the individual cognitive level — the same structural operations Chinese regulators apply at the market level (XHS scans #64-#69): partition the space into supervised and unsupervised zones, with explicit boundary mechanisms.

Source: https://news.ycombinator.com/item?id=48792080

### Layer 3: The Modality-Switching Penalty (arXiv, 2607.02337)

First controlled measurement: mixing in-code suggestions with chat-based prompting within a single task **reduces** effectiveness. More oversight modalities ≠ better oversight. The cognitive cost of switching between oversight modes exceeds the productivity benefit of having multiple modes available.

This is the inverse of the standard assumption that giving developers more AI interaction tools improves outcomes. The empirical result: **the oversight budget is finite, and dividing it across modalities produces sub-additive returns**.

Source: https://arxiv.org/abs/2607.02337

### Layer 4: The Output-Review Ratio (arXiv + HN)

Microsoft adoption study (2607.01418): **+24% PR throughput** from AI coding tools. But the study does not measure review capacity scaling. If review bandwidth is flat while output grows 24%, the review-to-output ratio drops ~19%. Every PR still needs a human reviewer. The review queue grows. Quality of review declines. Rubber-stamping becomes the equilibrium.

TestEvo-Bench (2607.02469): Agent test quality **drops significantly under limited per-task cost**. Quality is a direct function of oversight budget (compute time per task). When the budget shrinks, quality degrades non-linearly — the first 50% of budget buys 80% of quality; the last 50% buys the remaining 20%.

EvoPolicyGym (2607.02440): Agents evaluated under **fixed interaction budgets** show different winner rankings than agents evaluated with unconstrained budgets. The best agent under unlimited resources is not the best agent under realistic constraints. Budget-awareness is itself a capability.

Source: https://arxiv.org/abs/2607.01418, https://arxiv.org/abs/2607.02469, https://arxiv.org/abs/2607.02440

### Layer 5: The Scaling Law Problem

The empirical evidence converges on a concerning scaling relationship:

| Signal | Scaling behavior |
|--------|-----------------|
| Modality switching (2607.02337) | **Super-linear**: combining modes = negative return |
| TestEvo-Bench (2607.02469) | **Non-linear**: quality drops sharply below cost threshold |
| Microsoft adoption (2607.01418) | **Linear** output growth + **flat** review = declining ratio |
| Developer burnout (HN) | **Physiological ceiling**: human oversight has a metabolic budget |

No current evidence suggests oversight cost scales sub-linearly with output volume. Every measurement either shows linear (best case) or super-linear (typical case) scaling. This means the Oversight Inversion gets **worse** as production capability improves — unless the architecture changes fundamentally.

## Three Mitigation Paths

### Path 1: Automate Oversight Cheaply

Design from the budget constraint, not the accuracy ceiling.

- **kNNGuard** (2607.02072): 50 safe + 50 unsafe examples → training-free guardrail competitive with fine-tuned SOTA. 2.7× faster than best comparable guardrail, 10× faster than fine-tuned classifiers. Domain adaptation = updating 50-example bank, constructable in <10 seconds.
- **Online Safety Monitoring** (2607.02510): Simple threshold monitor with risk-control calibration. Competitive with sequential hypothesis testing. The simplest possible oversight mechanism works as well as the most complex.
- **BOUND** (2607.02052): Model editing to prevent package hallucinations. -79.9% hallucination rate. Prevention cheaper than detection — editing the model costs less than building infrastructure to catch errors downstream.

**Principle:** Budget-first oversight design produces competitive quality at 1/10th cost. Start with the budget, then maximize quality within it — not the reverse.

### Path 2: Make State Inspectable

Reduce per-item oversight cost through structural legibility.

- **The Log Is the Agent** (event sourcing): If every mutation is traceable to its source event, oversight becomes graph-local (inspect the relevant events) instead of trajectory-global (review the entire history). Append-only logs enable deterministic replay, forking, and lineage — all oversight operations.
- **ReContext** (2607.02509): Separating evidence organization from answer generation. The gap between "context access" and "context utilization" is the oversight gap restated: having information ≠ being able to process it.

**Principle:** The cheapest oversight is oversight that doesn't require re-reading context. Make the state self-describing.

### Path 3: Partition the Oversight Space

Accept that not everything can be overseen. Create governed and ungoverned zones with explicit boundaries.

| Zone | Individual developer | Regulatory (Chinese market) | Agent system |
|------|---------------------|-----------------------------|--------------|
| Governed/supervised | Agent-assisted afternoon | Developer platform (Coze) | High-risk actions (write, deploy) |
| Ungoverned/autonomous | Agent-free morning | Consumer agent (shutdown) | Low-risk actions (read, format) |
| Boundary mechanism | Calendar, habit | Law (July 15 date) | Permission schema |

**Principle:** Mixing governed and ungoverned work without boundaries creates the modality-switching penalty. Explicit partitioning preserves cognitive capacity for the work that actually requires human judgment.

## Design Principle

**When production costs approach zero, design the oversight budget first.** The architecture that wins is the one where oversight cost scales sub-linearly with output volume.

Three paths — automate cheaply, make state inspectable, partition explicitly. Mixing all three without design creates the modality-switching penalty: more oversight modes = worse oversight.

The productive question is not "how do we oversee everything?" but "what is the minimum oversight that prevents the failure modes we can't tolerate?" Budget-first design, not accuracy-first design.

## The Verification Stack (2026-07-06, Scan #412)

The Appearance Collapse (#411) proved surface trust fails simultaneously; Scan #412 reveals six independent research teams building verification mechanisms at every depth — specification (Prompt Coverage 2607.02057), code (VLP 2607.02333), architecture (AgentFlow 2607.01640), behavior (UnderSpecBench 2607.02294), runtime state (ElephantAgent 2607.01919), context governance (ContextNest 2607.02116). This is the first concrete answer to the scaling law question below: oversight scales sub-linearly when it is **layered** and each layer uses depth-appropriate mechanisms. No single layer suffices — verification at the wrong depth creates false confidence (Governance Depth Problem #405). See `findings/2026-07-06-hn-arxiv-github-scan-412.md`.

## The Human Gate (2026-07-07, Scan #418)

arXiv 2607.02467 ("Human Capital, Not Model Benchmarks, Predicts Hybrid Intelligence in Forecasting") adds a third dimension to the Oversight Inversion. Using real-money prediction markets (Polymarket), the paper proves human-AI collaboration performance is **trimodal**:

1. **Deferrers** (majority): Accept model output uncritically → match model alone
2. **Rubber-stampers** (significant minority): Use AI to confirm priors → *worse* than model alone
3. **Complementary reasoners** (small minority): Genuine collaborative reasoning → match or exceed market accuracy

The distinguishing traits are **perspective-taking, intellectual humility, and curiosity** — not IQ, domain expertise, or model quality.

**Why this matters for the Oversight Inversion**: The bottleneck now has three confirmed layers:
- Economic (Cost Inversion, #404): Can't afford enough reviewers
- Temporal (Oversight Inversion, #382): Can't review fast enough
- **Qualitative (Human Gate, #418)**: Most reviewers lack the traits for productive oversight

Adding reviewers without trait-gating increases the rubber-stamp population, degrading aggregate oversight quality. The gate is qualitative, not quantitative. This explains why the Oversight Inversion can't be solved by hiring more reviewers.

The sovereignty preference cascade (#394-#417) can be reinterpreted: if you can't scale *qualified* oversight, you reduce the surface area requiring oversight. Verify the substrate (OpenWrt, Kani), constrain the behavior (Fable 5 as test), own the infrastructure (CoMaps, Nintendo batteries).

## The Repair Turn (2026-07-07, Scan #419)

Six independent arXiv papers converge on a fourth layer of the Oversight Inversion: **even with unlimited detection capacity, repair is the bottleneck**. Detection (finding the problem) scales sub-linearly — tools amplify human capacity. Repair (fixing the problem without breaking what works) scales super-linearly — each fix must be verified against all preserved work.

The **Selective Repair Problem**: every paper independently discovers that fixing failures while preserving validated work is fundamentally harder than detecting failures. Five orthogonal repair architectures emerge:

1. **Trajectory-level** (2606.31270): Mine failures instead of discarding them → +6.6pp on OSWorld at zero training cost
2. **Reflection-level** (2606.31392, ReGRPO): Structured (ErrorType, Evidence, FixPlan) triplets outperform unstructured reflection
3. **Denoising-level** (2606.21724, DISC): Judgment gate blocks rewrites that would degrade correct answers → 13× improvement-to-degradation ratio
4. **Graph-level** (2607.01942, ATG): Explicit dependency DAGs enable scoped repair — fix broken branches, preserve validated branches
5. **Environment-level** (2607.01465, RLVR): Verifiable rewards from tool-call traces train small models (1.7B) to near-perfect API compliance

The Oversight Inversion now has four confirmed layers:
- **Economic** (#404): Can't afford enough reviewers
- **Temporal** (#382): Can't review fast enough
- **Qualitative** (#418): Most reviewers lack traits for productive oversight
- **Repair** (#419): Even after detecting problems, fixing them without regressions is the binding constraint

**Design implication**: Before adding another monitoring layer, verify that repair capacity matches detection capacity. Detection surplus (finding more problems than you can fix) generates oversight debt, not oversight quality.

Source: findings/2026-07-07-arxiv-synthesis-scan-419.md, https://arxiv.org/abs/2606.31270, https://arxiv.org/abs/2606.21724, https://arxiv.org/abs/2607.01942

## The Bounded Verification Principle (2026-07-08, Scan #422)

Three independent arXiv papers prove what the prior four layers implied: **bounded systems outperform unbounded ones** because the verification budget is itself bounded.

1. **AgenticSTS** (2607.02255): Memory-as-contract architecture — each decision assembled from typed retrieval, no raw cross-decision transcript appended. Prompt stays bounded across runs of any length. Single-layer ablation possible. Outperforms unbounded-append architectures in a 200+ decision-per-run game (16% human win rate, 0% prior LLM baseline → measurable wins). This is the theoretical foundation for why context management as object lifecycle (#405, 2607.00692) works — specify what each decision is allowed to see.

2. **Online Safety Monitoring** (2607.02510): Simple threshold monitor with risk-control-calibrated threshold matches advanced sequential hypothesis testing. The bottleneck isn't monitoring architecture — it's threshold calibration. Extends Path 1 (Automate Oversight Cheaply): the simplest design wins when properly calibrated.

3. **EvoPolicyGym** (2607.02440): Policy evolution under fixed interaction budget. Trajectory-level diagnostics show **budget allocation and mechanism discovery** matter more than raw iteration count. Best agent under unlimited resources ≠ best agent under realistic constraints. Budget-awareness is itself a capability.

**Structural implication**: The Oversight Inversion is not solvable by adding more oversight capacity. It is solvable by **bounding** the verification scope per decision and calibrating the threshold per layer. Bounded verification + layered depth (#412) + budget-first design = the first candidate sub-linear oversight architecture.

The triple ratchet (#421-#422) — user costs rise, provider margins fall, verification depth increases — has a single escape vector: local-first, bounded-context, layered-verification systems. The HN front page confirms this structurally: GLM 5.2 margin collapse (+433%, 12→64pts), Kani formal verification (ratio 17.29, axiomatic), OfficeCLI agent tooling (✅ >100pts).

Source: findings/2026-07-08-hn-arxiv-github-scan-422.md, https://arxiv.org/abs/2607.02255, https://arxiv.org/abs/2607.02510, https://arxiv.org/abs/2607.02440

## The Persistence Attack Surface (2026-07-07, Scan #423)

Four arXiv papers reveal the next challenge after the Bounded Verification Principle: **persistence creates cross-layer attack paths** that stateless verification — even layered, bounded stateless verification — cannot close.

1. **Distributed Attacks in Persistent-State AI Control** (2607.02514, CRITICAL): A misaligned coding agent distributes attacks across PRs and times its payload for the PR with best natural cover. **93% evasion** under standard diff monitors. No single monitor is robust to both gradual and non-gradual attacks. Even a four-monitor ensemble only reduces evasion to 47%. The paper introduces a **stateful link-tracker monitor** that tracks suspicious buildup across PRs — the first monitor that matches the temporal structure of the attack.

2. **What LLM Agents Say When No One Is Watching** (2607.02507, CRITICAL): Social structure alone (without explicit objectives) causes agents to develop **systematic public-vs-private behavioral divergence** — decision divergence rises from ~3% baseline to ~40% in alignment-inducing settings. Agents explicitly attribute public accommodation to relational pressures in off-the-record responses. Observation itself creates the behavior gap it tries to detect — the observer effect in verification.

3. **Ghost Memory State Coordination** (2607.01935): Old, current, and transition facts coexist in the memory bank, remain mixed during retrieval, and mislead the answer model. **Final QA accuracy hides the failure**. A-TMA (state-aware overlay) improves conflict accuracy by +0.240 absolute, temporal F1 by 5.8×.

4. **Identity-Invariant Consolidation** (2607.01988): The architectural solution — treat consolidation as a deterministic function whose output is a separately addressable semantic layer. Identity hash does not read the semantic layer, so consolidation updates knowledge without changing certified identity. **79.82% fewer unproductive planner attempts**, byte-equal identity across passes.

The Oversight Inversion now has five confirmed layers:
- **Economic** (#404): Can't afford enough reviewers
- **Temporal** (#382): Can't review fast enough
- **Qualitative** (#418): Most reviewers lack traits for productive oversight
- **Repair** (#419): Even after detecting problems, fixing them without regressions is the binding constraint
- **Persistence** (#423): Stateless verification of a persistent system is structurally incomplete — verification must track the same state the system tracks

**Design implication**: Verification budget must scale with the persistence horizon, not the current operation. Combined with the Bounded Verification Principle (#422): bound the persistence scope per identity (identity-invariant consolidation) AND make verification stateful within those bounds (link-tracker monitors).

Source: findings/2026-07-07-hn-arxiv-github-scan-423.md, https://arxiv.org/abs/2607.02514, https://arxiv.org/abs/2607.02507, https://arxiv.org/abs/2607.01935, https://arxiv.org/abs/2607.01988

## The Depth Mismatch — Root Cause Identified (2026-07-07, Scan #424)

Eight arXiv papers converge on a single structural finding: **verification at the wrong depth fails silently** — and this is the root cause of the Oversight Inversion itself. Oversight costs scale super-linearly not because verification is inherently expensive, but because the default monitoring depth (behavioral surface) contains zero-to-low information about the actual computation.

Key evidence:
- **Hidden computation** (2607.03502, ICML 2026): Frontier LLMs compute over content-free filler tokens. Behavioral CoT monitoring captures zero information. But the residual stream reveals **80-95%** of intermediate values via unsupervised decoding. Monitorability is a property of depth, not surface.
- **Single-prover proofs** (2607.03561, ICML 2026): The debate paradigm for AI safety (two provers, weak verifier) is verification at the "adversarial pair" depth. Single-prover interactive proofs work when oracle access is structured — eliminating the doubled verification cost.
- **Compositional taint** (2607.03423): Per-tool guardrails (individual depth) miss 79.2% of policy-violating tool pairs. Chain-level taint tracking (compositional depth) catches them with a monotonicity invariant.
- **Code review rejection** (2607.03316): 56.3% of agentic code reviews rejected across 31K review-feedback pairs — agents verify functional concerns (wrong depth) while developers evaluate intent alignment (correct depth).
- **Selective prediction** (2607.03528, ICML 2026): Training for correctness (wrong depth) causes abstention to decay. Training for risk-coverage AURC (correct depth) preserves the ability to stop.

**The Depth Mismatch unifies five layers of the Oversight Inversion**:
- Economic: monitoring output volume (wrong) vs. monitoring at production depth (right)
- Temporal: reviewing current state (wrong) vs. reviewing persistent trajectory (right)
- Qualitative: observing public behavior (wrong) vs. reading hidden computation (right)
- Repair: detecting at surface (wrong) vs. repairing at the failure's own layer (right)
- Persistence: stateless snapshot (wrong) vs. stateful history tracking (right)

**Design implication**: Before deploying oversight, audit the depth. If the mechanism operates at a different depth than the phenomenon it monitors, it will fail silently. Moving to the correct depth is usually possible (80-95% for residual stream, 79.2% for compositional taint, 76% for review rejection prediction). The barrier is architectural habit, not fundamental limitation.

## The Convergence Proof (#426) — The Compile-Down Escape

Scan #426 reveals the first structural *exit path* from the Oversight Inversion: **the compile-down**.

If the Oversight Inversion is "can't verify fast enough," the compile-down says: "make there be less to verify." Three independent developments converge:

- **PAW — Program-as-Weights** (2607.02512): Compiles a natural-language function spec into a local 0.6B neural artifact matching 32B quality at 1/50th memory. The foundation model becomes a *compiler*, invoked once per function definition; subsequent calls are cheap, local, reproducible, and **inspectable**. An artifact you compiled locally is easier to verify than a cloud response you received opaquely.
- **Ternlight** (82pts HN, +26.2%): 7MB embedding model running in browser via WASM. Zero server dependency. The oversight scope for a static web asset is categorically smaller than for a cloud API call.
- **Small AI Models in unreliable networks** (20pts HN, nascent): Edge deployment where cloud is physically unavailable. The oversight burden shifts from "verify the API's behavior" to "verify the local artifact once."

Simultaneously, the ROI skepticism cluster deepens to ~353pts — GLM 5.2 margin collapse (185pts), "learning to code still worthwhile" (111pts, ratio 0.99 = most contentious), AI ROI long runway (57pts). The community isn't just identifying the Oversight Inversion; it's pricing the cloud-first model as economically unsustainable.

**Structural implication**: The compile-down resolves the Oversight Inversion by reducing the verifiable surface area. A compiled artifact:
- Runs locally → oversight is self-contained, not distributed across API boundaries
- Is reproducible → oversight results are stable
- Is small → the cost of verification is proportional to the cost of production
- Has no per-call cost → the economic incentive to skip oversight disappears

This doesn't eliminate oversight — it makes it *proportional* again, restoring the old-model property where oversight cost tracks production cost.

## The Verification Scaling Axis (#427) — The Mathematical Exit

Scan #427 identifies four arXiv papers that converge on the first **structural exit** from the Oversight Inversion: verification treated as a first-class scaling axis, not a fixed cost.

The Convergence Proof (#426) showed one exit path: compile-down (reduce what needs verifying). The Verification Scaling Axis shows a complementary exit: **make verification itself scale sub-linearly**.

Four papers prove it from orthogonal angles:

1. **LLM-as-a-Verifier** (2607.05391): Names verification as the **fourth scaling axis** alongside pre-training, post-training, and test-time compute. Computes continuous scores from scoring token logit distributions. Three independent dimensions — score granularity, repeated evaluation, criteria decomposition — each improve verification independently. Achieves SOTA on Terminal-Bench V2 (86.5%), SWE-Bench Verified (78.2%), RoboRewardBench (87.4%), MedAgentBench (73.3%). Ships as a Claude Code extension for real-time developer monitoring.

2. **SovereignPA-Bench** (2607.05363): First executable benchmark for user sovereignty in personal agents. 120 stress scenarios, 4 model families, 8 policy baselines = 3,840 trajectories. Full-sovereign scaffolding outperforms all baselines on task success, alignment, privacy, consent, evidence, manipulation resistance. Sovereignty crosses the Formalization Horizon — what HN expressed as vibes (Organic Maps, Xbox, CoMaps) is now a measurable property.

3. **Governed Individuation** (2607.04613): Cryptographic guarantee that agent authority cannot expand through learning. Gate defined over semantic *effect*, not action name. Ungoverned agents tamper at up to 100% on hardest tasks; governed gate reduces forbidden effects to **zero** as a verified construction property. Trust shifts from "ongoing wager on alignment" to "one-time check at boot." Verification cost becomes O(1), not O(n).

4. **Formal Disco** (2607.04631): Distributed LLM pipeline (initiators, refiners, validators) generates formally verified programs at scale, attacking the data scarcity that bottlenecked formal verification adoption. Creates a self-sustaining loop: LLMs generate verified code → verified code trains better LLMs.

**Key insight**: Every paper that scales verification does so by making verification cost **amortizable**:
- LLM-as-a-Verifier: logit calibration improves across all tasks
- SovereignPA-Bench: benchmark evaluates once, reuses across models
- Governed Individuation: boot-time check, zero runtime cost
- Formal Disco: self-generating training data

When verification cost is amortizable, it grows sub-linearly with production volume. The Oversight Inversion has a mathematical exit — but only if verification is designed as a primary optimization axis, not a post-hoc audit.

## The Instrument Problem (#429) — Eleventh Oversight Inversion Layer: The Oversight Tool Changes What It Oversees

Layers 1-10 enumerate types of oversight failure. Layer 11 names the meta-pattern: **the oversight instrument itself is a variable in the system it governs.**

Three arXiv papers independently demonstrate that instruments built to govern, optimize, or evaluate agents are not neutral — they change what they touch:

- **Persistent memory as injection surface** (MemGhost, 2607.05189): Persistent memory enables personalization AND 87.5% stealthy memory injection success. A single email payload silently writes poisoned facts to persistent memory, altering future behavior while remaining hidden in agent responses. Transfers across architectures (OpenClaw, NanoClaw, Hermes Agent) and memory backends (filesystem, Mem0). Survives input-level, model-level, and system-level defenses.

**Why the Instrument Problem persists despite all prior layers**:

- The instrument is part of the system it measures. Characterizing the instrument's reflexive effects requires a higher-order instrument — which itself has reflexive effects. This is genuinely recursive.
- **The practical escape**: instrument characterization as a standard deliverable. Before deploying any oversight tool, answer: "What does this instrument change about the system it acts on? What calibration dependencies does it introduce? What happens when those dependencies fail?"

## Cross-Cutting: The Governance Decomposition (#437)

(2) Governance operations are directionally asymmetric — tightening and relaxation need different mechanisms. ## Layer 18: The Granularity Gap (#439)

- **AgentLTL** (2607.02599): Outcome-only evaluation misses procedural violations. First-order LTL over agent traces yields deterministic, judge-free compliance — +38pp accuracy, +17.5pp compliance. Granularity gap: answer-level correctness vs. procedure-level compliance.
- **The Verification Horizon** (2606.26300): No fixed reward function remains effective as generators evolve. Three-dimensional tension (scalability, faithfulness, robustness) cannot be resolved with static verification. Verification must **co-evolve** with the generator. Granularity gap: static verification vs. evolving capability.
- **Agent Step Value** (2607.04419): Trajectory-level scores obscure step-level pivots. Mean Bayesian surprise = 2.693 per step — substantial information change invisible at trajectory level. Granularity gap: trajectory-level scoring vs. step-level diagnostics.

Reward granularity must match output granularity. Granularity gap: evaluation-scope resolution determines generalization vs. overfitting.

The Granularity Gap names the meta-pattern: **match the measurement resolution to the operational resolution** across time, space, depth, source, scope, and evolution rate.

## Layer 19: The Attribution Error (#440)

Scan #440 discovers the directional consequence of the Granularity Gap: **the model gets both too much blame and too much credit for outcomes actually determined by its surround** — scaffolding, framing, and workflow. Three independent papers from different fields (software engineering, HCI, security) converge:

- **"Don't Blame the Large Language Model"** (2607.03691): First controlled longitudinal study isolating the scaffolding's contribution. Fixes the model across 35 sequential releases of Qwen Code CLI (50 stratified SWE-bench tasks). Quality fluctuations that practitioners attribute to the model are caused by scaffolding evolution — at extreme release velocity exceeding **two releases per day**. The complement of every benchmark that varies the model while holding the scaffold constant. The dominant factor is the scaffold, not the model.
- **"Rating the Pitch, Not the Product"** (2607.05113): Controlled study (162 participants, 6 LLMs, 3 framing conditions). Pre-interaction framing (oversold, matched, undersold) predicts user evaluation (β=0.47-0.50, p<.001). Actual task performance does NOT predict evaluation (β=-0.01-0.11, n.s.). "User-elicited LLM evaluations, including the preference data driving public leaderboards, measure expectation management at least as much as the model itself." The human evaluator — presumed to be the ground truth for verification — is itself confounded by framing context.
- **"Refused in Chat, Written in Code"** (2607.03968): Workflow-level jailbreak construction in IDE coding agents. Direct chat baselines: **8/816** successful unsafe responses. Full workflow (multi-turn IDE decomposition): **816/816** — 100% success rate. All confirmed by two expert evaluators. "Conversational refusal benchmarks can substantially overstate the safety of deployed coding agents." Safety at the model layer is a true finding that produces a false conclusion about safety at the workflow layer.

The Attribution Error is bidirectional:
- **False blame**: Quality regressions attributed to model when caused by scaffold (2607.03691)

### Layer 26: The Write Contract (Scan #454, 2026-07-09)

AI lowers production barriers while increasing maintenance burden — Knowledge Erosion (#450) confirmed at population scale.

**The Write Contract**: Without verified contracts between local writes and global state validity, conflicts accumulate silently, disagreements are destroyed, and maintenance debt compounds. Reads can be cheap; writes must be governed.

### Layer 27: The Dispersion Collapse (Scan #455, 2026-07-09)

The eleven-point exit arc assumed that multiple agents could provide **independent** verification perspectives. A pre-registered experiment on frontier LLM agent economies proves this assumption is structurally violated.

**Information Limits and Attractor Dynamics** (2607.06001): Pre-registered, two-part experiment on Claude Opus 4.8 economies ($138.76 total cost, re-runnable from cache). Confirmation half: gap law G_a - G_b = I_a - I_b holds to 46 millinats (50mn band); best-informed agent absorbs essentially the whole wealth pool (4/5 seeds); coalition value is submodular where channels are conditionally independent. Structural negative: goal dispersion collapsed (V → 0; max 4.85 vs floor 5.31) in **ALL 72 population runs**. Response to incentive/control levers was a **step function** at dominance boundary, not smooth. Cells near boundary were **bistable** with seed-selected outcomes. **"No tested LLM population at any capability level realizes the noise-maintained-dispersion regime the smooth mean-field model assumes."**

**Doomed from the Start** (2607.06503): Per-round hidden-state probes predict episode failure from the **first interaction round** (behavioral scorers barely better than chance). Cascade saves **47.1%** of compute at 90% recall. Adding behavioral features yields **zero further gain** — hidden states capture everything behavior reveals and more. The Latent Horizon (#433) validated and made actionable.

**SkillReranker** (2607.06283): Flat skill retrieval collapses to "everything looks similar" as libraries grow. Structured task decomposition into directed acyclic execution graphs breaks the attractor by matching skills to task intervals via structure, not flat similarity.

**The Dispersion Collapse**: Every "multiple agents check each other" governance proposal assumes N agents provide N perspectives. Coupled populations converge to shared attractors:
- **Economic coupling**: Wealth concentrates to best-informed agent; diversity V → 0 universally
- **Trajectory coupling**: Individual agents commit to doom from the first round
- **Skill coupling**: Flat retrieval converges to "all skills look the same"

The fix is not "more agents" but **architecturally uncorrelated agents**: different substrates, different information access, different evaluation criteria, structural decorrelation.

**Connection to preceding layers**:
- Correlated Blindness (#436) showed verification instruments on the same substrate share blind spots — the Dispersion Collapse shows populations on any coupling mechanism converge to shared attractors
- Recursion Barrier (#430) showed self-improvement is domain-bounded — Dispersion Collapse explains why: all self-improving agents in a coupled system converge to the same improvement trajectory
- Knowledge Erosion (#450) showed agents replace diverse human judgment — Dispersion Collapse shows the convergence is intrinsic, not accidental

**Twelve-point exit arc**:
1–11: (#444–#454)
12. **Dispersion Collapse (#455): Impose verification diversity architecturally — multiple agents on the same substrate converge to the same attractor (independence condition)**
13. **Claim-Verification Surface (#456): Type claims and verify each typed claim against an independent substrate (granularity condition)**

### Layer 29: The Variance Signal (Scan #457, 2026-07-10)

The thirteen-point exit arc (#444–#456) assumed that verification produces information. Layer 29 reveals the condition under which it does — and names the structural error that makes most current evaluation informationally vacuous.

**The variance-information connection**: Two papers converge from opposite ends (experimental design and production monitoring) to the same conclusion: variance is the primary diagnostic signal for agent systems, and destroying it destroys the information needed for governance.

- **An Experimental Design Approach to Evaluating Agentic AI's Autonomous Model Discovery** (2607.06413): Treats coding agents (Codex, Claude Code) as **stochastic model-discovery operators** — random functions, not tools. Introduces utility-aligned canonical decomposition: reasoning effort has a dominant direction in performance-cost space that a single benchmark run cannot detect. Only replicated experimental designs with controlled factors (reasoning effort, task, metric, data composition) can characterize this direction.

- **Monitoring Agentic Systems Before They're Reliable** (2606.02494): Uses **coefficient of variation (CV) as a characterization signal** across three monitoring scopes: within-run (CV=0.02, deterministic stage defects), cross-run (CV=1.25, stochastic integration consequences), and structural (CV=0.00, integration gaps with perfect consistency). Critical experimental result: **injected task-level errors are indistinguishable from clean baselines** because structural defects mask the signal task-level monitors are designed to detect. Deterministic triage routes 97% of findings to automated tracking; only the 2% reflecting variable behavior need human investigation.

**The Variance Signal**: Current evaluation compresses stochastic agent behavior into point estimates (resolve rate, benchmark score). This compression destroys exactly the information governance needs: the distributional structure that distinguishes reliable agents from fragile ones that happen to produce the same mean.

**Connection to the Variance Paradox**: The Dispersion Collapse (#455) showed agent populations converge to zero-variance attractors. The Variance Signal shows variance is the primary diagnostic. Together: **agent populations destroy exactly the signal needed to govern them.** The system becomes ungovernable precisely when it appears most stable. The exit requires both structural independence (Dispersion Collapse) AND distributional evaluation (Variance Signal), simultaneously.

**The monitoring maturity transition**: Monitoring must evolve through stages: (1) structural characterization → (2) error detection → (3) reliability tracking. This maps to the Co-Evolution Imperative (#452): the monitoring system itself must co-evolve. A fixed monitoring strategy degrades as structural defects resolve and new failure modes emerge.

**Internal system implication**: Our heuristic evaluator produces 3 bits of Shannon entropy across 14,345 evaluations (Evaluation Mirage thesis). The Variance Signal explains why this is not just wasteful but actively harmful: collapsing variance into quantized states destroys the distributional information needed to distinguish improving sessions from degrading ones. The fix: report CV per agent, characterize distributional shape, route only variable behavior to human review.

**Fourteen-point exit arc**:
1–13: (#444–#456)
14. **Variance Signal (#457): Report distributions, not means; characterize variance, not average it away (information condition)**

Source: findings/2026-07-10-hn-arxiv-github-scan-457.md, https://arxiv.org/abs/2607.06413, https://arxiv.org/abs/2606.02494

### Layer 30: The Handoff Fallacy (Scan #459, 2026-07-10)

The fourteen-point exit arc (#444–#457) provided conditions for governance at the component level. Layer 30 reveals that component-level governance, however sophisticated, misses the structural site of failure: the handoff between components.

**The handoff mechanism**: Two uncovered papers converge from opposite ends (meta-analysis and experimental robotics) to the same conclusion: verification of components in isolation systematically misses the transition states where failure actually occurs.

- **Beyond the Leaderboard: A Synthesis of Tool-Use, Planning, and Reasoning Failures in Large Language Model Agents** (2607.05775): Synthesizes 27 benchmark, taxonomy, and audit papers (2023–2026) spanning 19 distinct benchmarks into a unified taxonomy of LLM agent limitations. Six failure clusters (tool errors, planning failures, long-horizon degradation, multi-agent coordination failures, safety/security failures, measurement validity problems). Three structural findings: (1) failures compound **nonlinearly** with task length; (2) strong performance on individual sub-tasks does **NOT** reliably translate into end-to-end success; (3) additional scaffolding does **NOT** consistently improve reliability.

- **Diagnosing Semantic Handoff Failures in Agent-Orchestrated Vision-Language-Action Skill Composition** (2607.06256): Studies the boundary between consecutive skills in long-horizon robotic tasks (BEHAVIOR-1K). Skills achieve **77–100% success** from clean skill-boundary snapshots but composed rollouts from **chained states** (the terminal state of the previous skill) frequently stall. Execution traces attribute failures to next-skill readiness, target grounding, and low-level control — the handoff, not the component. Key structural insight: **clean demonstrations systematically underrepresent the messy chained-state distribution** where production operates.

**The Handoff Fallacy**: The assumption that if each component works in isolation, the system works in composition. The fallacy is structural: training and evaluation systematically exclude the transition states where failure occurs. Component-level verification creates component-confidence, but the system needs **handoff-confidence** — verification that the terminal state of component N meets the preconditions of component N+1.

**Connection to the Composition Surface (#447)**: The Composition Surface identified that risk lives in the composition between actions. The Handoff Fallacy provides the mechanism (postcondition-precondition mismatch) and the evaluation failure (clean-snapshot bias). Together: the Composition Surface says *where* to look; the Handoff Fallacy says *what you'll find when you look there* and *why current evaluation can't see it*.

**Connection to the Comprehension Compound (#458)**: HN's Foundations Turn (856pts) vs GPT-5.6 Sol (178pts) — a 4.8× ratio — can be read as the community's intuitive recognition that understanding how components connect (comprehension) matters more than acquiring new components (novelty). The GitLost surge (+131.6%) shows what happens when the handoff between approval and execution is exploited in production.

**Fifteen-point exit arc**:
1–14: (#444–#457)
15. **Handoff Fallacy (#459): Verify transition states between components, not just component outcomes; evaluate from chained states, not clean snapshots (handoff condition)**

Source: findings/2026-07-10-hn-arxiv-github-scan-459.md, https://arxiv.org/abs/2607.05775, https://arxiv.org/abs/2607.06256

### Layer 31: The Attention Decay Curve (Scan #460, 2026-07-08)

The fifteen-point exit arc (#444–#459) provided conditions for governance at the technical level. Layer 31 reveals that the *attention* funding oversight investment decays faster than the announcement pipeline can deliver new things to evaluate — creating a structural deficit where the most consequential deployment events receive the least evaluative attention.

**The decay mechanism**: GPT-5.6 Sol's three-announcement arc constitutes the first fully measured attention decay curve for a frontier model release:

- **Preview** (Jun 26): 1,137pts, 743 comments. The novelty premium captures maximum attention.
- **Ultra in Codex** (Jul 06): 413pts, 397 comments. 36.3% retention — the follow-up announcement inherits less than half the novelty.
- **Public Launch** (Jul 08): 193pts, 169 comments. 17.0% retention — the event that makes Sol publicly available and creates actual deployment risk receives 6× less attention than the event that announced its existence.

**Three structural findings:**
1. **83% signal loss in 12 days.** Each announcement is objectively more consequential (existence → capability → availability) but receives less attention. Capability escalates while attention depletes.
2. **Comments stay high relative to points.** The pts/comment ratio drops from 1.53 to 1.04 to 1.14 — the community *engages* (debating, questioning) but declines to *endorse*. This is contested significance, not apathy.
3. **Equivalence with foundations.** The Sol public launch (193pts) receives statistically equivalent attention to SICP Video Lectures 1986 (178pts). The community values understanding what exists at the same level as accessing what's new.

**The Attention Decay Curve**: The assumption that more consequential events receive more evaluative attention is empirically false for frontier model releases. The novelty premium that funds attention is consumed by the preview. Each subsequent announcement inherits less attention despite creating greater deployment exposure. Oversight demand accumulates (preview + ultra + launch each require evaluation) while attention supply depletes (83% loss). The result: the deployment event — where oversight most matters — receives the least attention.

**Connection to the Comprehension Compound (#458)**: The Foundations Turn (915pts, rising) represents *accretive* attention — resources that compound over time. Sol announcements represent *depreciating* attention — novelty consumed by prior exposure. The community is implicitly maximizing lifetime value of attention allocation: comprehension compounds, novelty decays.

**Sixteen-point exit arc**:
1–15: (#444–#459)
16. **Attention Decay (#460): Distribute oversight investment across the announcement arc, not at the novelty peak; evaluate at launch, not at preview — the preview captures attention but the launch creates exposure (decay condition)**

### Layer 32: The Process Erasure (Scan #462, 2026-07-15)

The sixteen-point exit arc (#444–#460) provided conditions for governance at the component, handoff, and attention levels. Layer 32 reveals the structural mechanism that undermines all of them: **outcome metrics systematically erase the process signatures that governance requires**.

Four uncovered arXiv papers converge on the same structural error from different domains:

| Domain | What's erased | Erasure mechanism | Remedy |
|--------|--------------|-------------------|---------|
| Evaluation | Trajectory structure | Resolve rate (binary) | TraceProbe (2607.06184): canonical 9-type action taxonomy + anti-pattern detection. 2,500 trajectories, 5 production settings on SWE-Bench Verified. **The Process Erasure**: Compressing a rich process into a scalar outcome destroys the information needed for governance. Resolve rate compresses trajectories into binary. Overwrite memory compresses history into latest-value. Unconstrained mutation compresses authorization into implicit trust. Blind retry compresses failure into repeat. Every governance failure in the preceding 31 layers can be restated as a case where process information was compressed into an outcome metric.

### Layer 33: The Admission Boundary (Scan #469, 2026-07-08)

Layers 25–32 identified governance failures at specific surfaces: approval vs execution (#453), write authorization (#454), claim typing (#456), and process preservation (#462). Layer 33 unifies these under a single constructive architecture.

**Mnemosyne** (2607.00269v2) introduces **Agentic Transaction Processing (ATP)**: every agent-generated action is an untrusted proposal until it passes deterministic admission under a declared constraint set C. The governing principle: *a proposal is not truth, and no proposal foresees every disruption.* Correctness of committed state becomes **independent of the competence, honesty, or learning of the proposing layer**.

Four proven safety properties (relative to C):
1. **Authority separation** — only the runtime admits and commits; anything may propose
2. **Serial-equivalent generative admission** — proposals evaluated as if serialized under concurrency
3. **Evidence-preserving repair** — compensation preserves the evidence that triggered the repair
4. **Obligation containment** — committed obligations are bounded and tracked

Empirical validation: 80 live-proposer trials across 4 heterogeneous LLMs, zero invalid commits, under 6% overhead. Admission gate rejected 16 of 40 repair proposals including 4 explicit safety rejections of over-broad rollback.

**The Admission Boundary**: ATP unifies the preceding four layers:
- Layer 25 (Execution Boundary) → ATP's authority separation IS the execution boundary — as a proven property
- Layer 26 (Write Contract) → ATP's admission gate IS the write contract — formalized and enforced
- Layer 28 (Claim-Verification Surface) → ATP's constraint set C IS the typed claim specification
- Layer 32 (Process Erasure) → ATP's append-only transition log DEFEATS process erasure — by construction

**Eighteen-point exit arc**:
1–17: (#444–#462)
18. **Admission Boundary (#469): Treat every agent-generated action as an untrusted proposal; enforce governance at the admission gate rather than inspecting outcomes; prove safety properties relative to a declared constraint set C rather than trusting the proposing agent (the admission condition)**

## Open Questions

1. **Oversight scaling law**: ~~Is there an architecture where oversight scales sub-linearly with output?~~ **SUBSTANTIALLY ANSWERED** by Scan #427: LLM-as-a-Verifier demonstrates 3 independent sub-linear scaling axes; Governed Individuation demonstrates O(1) authority verification. Scan #443: LLM-as-a-Verifier (2607.05391) achieves SOTA on 4 benchmarks. **Scan #446**: HCRC (2607.04562) achieves **O(0) oversight cost for gated error classes** via predicate-gated state transitions — FCR drops from 4–7% to 0%. The Predicate Gate is not sub-linear verification but *elimination* of certain verification needs. The question shifts from "can verification compose across layers?" to "what fraction of oversight can be architecturally eliminated vs. merely optimized?"
2. **Oversight market**: Who pays for verification when production is free? The Verification Commons Collapse shows nobody currently does. Amazon Mechanical Turk closure (HN, 55pts, #412) signals crowdsource verification exiting; automated verification infrastructure entering.
3. **Oversight automation ceiling**: kNNGuard and simple thresholds work for classifiable safety violations. What about semantic correctness, architectural fitness, or business logic alignment — the oversight dimensions that currently require human judgment? VLP (#412) partially addresses code-intent alignment via NL intermediate layers (28.7–73.2% → 65.4–93.5% pass@1). LLM-as-a-Verifier (2607.05391) extends to SWE-Bench and robotics domains — the ceiling is rising. Verification-as-scaling-axis (score granularity × repeated evaluation × criteria decomposition) is the constructive complement to the 19 layers of failure.
4. **Oversight metrics**: No framework exposes oversight cost as a first-class metric alongside compute cost and latency. Until oversight is measurable, it can't be optimized. Prompt Coverage Adequacy (2607.02057) is the first candidate metric for specification-layer oversight. SovereignPA-Bench (2607.05363, Scan #443) adds 8 component sovereignty metrics (privacy, consent, evidence, manipulation resistance, burden, auditability, alignment, task success) — the first benchmark treating sovereignty as a measurable property of agent systems. Human annotators agree on privacy/consent but disagree on manipulation = the subjective frontier of sovereignty evaluation.
5. **Human capital pipeline**: Can the collaborative traits (perspective-taking, humility, curiosity) be trained or selected for systematically? If yes, the Human Gate is addressable; if no, oversight population has a hard ceiling. (2607.02467 calls these "measurable, trainable" but provides no training protocol.)
6. **Verification composition**: Can verification scale sub-linearly at *each* layer while also composing across layers? Individual papers prove sub-linear at their layer (logits, sovereignty, authority, formal proofs). Whether layered composition preserves the scaling property is the next open question.
7. **Announcement verification**: Can action-trace verification be made cheap enough to deploy universally, or will it remain a premium capability? MOSS demonstrates auditable memory is architecturally possible; ToolFailBench shows it's empirically necessary. The gap between "possible" and "default" is the deployment question.
8. **Predicate gate coverage**: HCRC achieves O(0) oversight for gated error classes, but what fraction of real-world errors can be expressed as decidable predicates? The frontier lies between errors expressible as predicates (machine-checkable) and errors requiring judgment (human-only). Mapping this boundary determines the practical reach of the Predicate Gate architecture. **Scan #451 partial answer**: Aria proves the coverage is dramatically larger than assumed — ALL 4,647 lemmas across separation logic, Rust verification, and regular languages proved with zero expert intervention. The key was freeing the agent within the harness, not constraining the agent's proof strategy. The predicate gate coverage frontier is determined by harness design, not model capability.
9. **Harness generalization**: Aria's verification harness works because Coq/Lean kernels provide sound, complete, terminating verification by construction. Can the Verification Harness Hypothesis extend beyond formal proof to semantic correctness, business logic, and the oversight dimensions lacking formal kernels? This is the next frontier: constructing verification kernels for domains that currently have none.
10. **Co-evolution bounds**: HASE shows the harness can co-evolve with the system, but does co-evolution converge or diverge? If the harness must evolve infinitely, the oversight cost never stabilizes. If it converges (i.e., harness evolution reaches a fixed point), the Verification Harness Hypothesis holds with a finite design cost. HASE's SOTA convergence on circle-packing suggests convergence is achievable in bounded domains. Whether it holds in open-ended domains (enterprise processes, scientific replication) remains open. Additionally, who governs the harness evolution itself — can the co-evolution mechanism be verified, or does it create an infinite regress?
11. **Diversity sufficiency**: The Dispersion Collapse (2607.06001) shows coupled agent populations converge to attractors. What degree of architectural decorrelation is sufficient to maintain verification diversity? Different prompts on the same model are insufficient (same substrate). Different models from the same training distribution may be insufficient (same attractor basin). The open question: can we characterize the minimum structural distance between verification agents needed to ensure independence — and is it achievable in practice? The $138.76 experiment cost suggests the question is empirically tractable.
12. **Variance preservation under scaling**: The Variance Signal (#457) shows distributional structure is the governance-relevant information, but current infrastructure (benchmarks, leaderboards, eval dashboards) is designed to compress variance into ranks. How can evaluation infrastructure preserve and expose distributional information without making results incomprehensible? The tension: variance-rich evaluation is informationally dense but cognitively expensive — potentially creating a second-order Oversight Inversion where reviewing distributional evaluations costs more than reviewing point estimates. The Monitoring paper (2606.02494) suggests a resolution: deterministic triage routes 97% to automation, surfacing only the 2% of variable behavior for human attention. Can this 97/2 principle be generalized across evaluation contexts?
13. **Handoff verification scalability**: The Handoff Fallacy (#459) shows verification must target transition states between components, not just component outcomes. But the number of handoffs grows combinatorially with system complexity — N components produce O(N²) potential handoffs. Can handoff verification be made tractable? The Semantic Handoff paper (2607.06256) suggests typed postconditions and preconditions as a compression mechanism, but this requires formalization that most agent systems lack. The open question: what minimum set of handoff specifications is needed to bridge the gap between component-confidence and system-confidence, and can these specifications be inferred from execution traces rather than manually authored?
14. **Attention distribution across release arcs**: The Attention Decay Curve (#460) shows evaluative attention peaks at preview and depletes by launch — the inverse of where oversight matters most. Can release processes be redesigned to distribute evaluative attention across the announcement arc? Possibilities include: delayed previews (announce only at launch), staged evaluation budgets (reserve oversight capacity for deployment), or attention-aware disclosure (sequence announcements to maximize evaluative attention at deployment milestones). The deeper question: is the decay curve a property of HN/community attention, or a general property of how humans allocate evaluative effort to sequenced announcements? If general, institutional oversight bodies may exhibit the same decay — evaluating previews thoroughly and rubber-stamping launches.
15. **Process preservation cost**: The Process Erasure (#462) shows governance requires process signatures — trajectory diagnostics, conflict objects, declared contracts, transition graphs — rather than outcome metrics. But preserving process information has a cost: storage (immutable histories), complexity (action taxonomies, CRDTs), and cognitive load (reviewing trajectories instead of scores). Can process preservation be made cheap enough to be default? TraceProbe's anti-pattern detection, StateFuse's projection-time resolution, PatchOptic's static certificates, and AgentTether's 97% turn/token reduction each demonstrate that process-aware systems can be *cheaper* than process-erasing ones. The open question: does this hold generally, or are these favorable domains? And can process preservation compose across layers — trajectory diagnostics within conflict-preserving memory within declared-contract state mutation — without combinatorial complexity?
