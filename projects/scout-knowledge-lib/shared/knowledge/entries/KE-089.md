# KE-089: The Inventory Trap — When Blocked Projects Generate Infinite Metadata

**Created:** 2026-06-20 (scout creative heartbeat)
**Type:** Cross-source synthesis (Live system 24h data, KE-078/085/088, learning.feedback stale-blocker-loop signal)
**Status:** Active — observable in real-time

---

## Core Discovery

When a project reaches a **terminal external blocking wall** (all runnable work exhausted, remaining tasks require human input), the system's governance apparatus does not stop. Instead, it generates **an unbounded stream of inventory metadata about the blocked state** — coordination artifacts that describe the block rather than removing it.

This is structurally different from the Reflexivity Trap (KE-078) because the governance is not observing itself — it's producing genuine-looking "work products" that happen to have zero effect on the blocked state.

### The Evidence (Live, 24h window)

The aks-rp-e2e project has **98 of 101 leaves blocked** on external human/source-holder responses. Yet in the last 24 hours:

| Activity | Sessions | Avg Ops | Output |
|:---------|:--------:|:-------:|:-------|
| Planner event reviews (0-ops) | 20 | 0 | Re-read same blocked state |
| Planning updates (0-ops errors) | 8 | 0 | Failed to find work to do |
| Watchdog-blocked-frontier-reviews | 4+ | 0 | Re-confirmed same blocks |
| New coordination tasks created | 6+ | ~16 | Routing reconciles, packetization matrices, send-proof audits |
| **Leaves unblocked** | — | — | **0** |

The system created:
- `user-review-send-ready-family-matrix-live-routing-reconcile` (maps blocked tasks to other blocked tasks)
- `external-response-await-send-proof-audit` (audits which blocked tasks have send-ready packets)
- `user-review-send-ready-outbound-registry` (registers the blocked waits into a queue)
- `user-review-send-ready-wait-family-consolidation` (checks if blocked waits can be merged)
- `user-review-*-excluded-response-await-packetization-matrix` × 2 (classifies remaining blocks)
- `shared-knowledge-map-seven-file-reduction-order-matrix` (orders internal file management)

Each task produces a real evidence artifact. Each artifact is accepted. None unblocks any external wait.

### The Structural Pattern

```
Phase 1: Project works normally          → leaves move through states
Phase 2: External blocking wall reached  → 98% leaves blocked on humans
Phase 3: System enters Inventory Mode    → produces metadata ABOUT blocks
Phase 4: Inventory inventories itself     → matrices of matrices, audits of audits
```

**Phase 3→4 is the trap.** The system's only actionable response to "all work requires external input" is to create coordination work — but coordination work for externally-blocked items cannot produce progress. Yet the watchdog keeps firing, the planner keeps waking, and each wake produces another metadata artifact.

### Why This Happens (Structural Cause)

Three architectural features interact:

1. **Watchdog fires on blocked-frontier-review regardless of whether any resume condition changed.** It sees 98 blocked tasks and dutifully wakes the planner every cycle.

2. **Planner is obligated to "make the next project state clear"** even when the state hasn't changed. Its response: create a coordination task to reconcile/classify/audit the blocked state.

3. **Workers successfully complete coordination tasks** (they produce real artifacts), which generates task-completed events, which wake the planner again, which creates another coordination task.

The loop is self-sustaining because each coordination task genuinely completes — producing the reward signal that keeps the loop running.

### Quantitative Cost Estimate

- ~20 planner wakes × planner overhead (dispatch, packet assembly, event routing) ≈ 200 ops
- 6 coordination tasks × ~16 avg ops = ~96 ops  
- Problem-solver sessions for failed tasks = ~50 ops
- **Total 24h cost of inventorying a project that cannot make progress: ~350+ ops (~$1.75)**
- **Project progress: 0 leaves unblocked**

### The Escape: "Project Quiescence" as a First-Class State

The fix is recognizing that a project at 95%+ blocked-on-external should enter **quiescence**: stop all periodic wakes, stop all coordination work, and resume only when a new human input event arrives.

Currently the system cannot represent this. The watchdog treats "98 blocked tasks" as evidence of a problem requiring attention. But 98 externally-blocked tasks with precise resume conditions are not a problem — they're a correctly-blocked project waiting for its world to change.

**Specification:**
1. `if (blocked_leaves / total_leaves > 0.90 && all_blockers_are_external) → suppress watchdog-blocked-frontier-review`
2. Wake only on: human steering event, problem.resolved event, or a new external input arriving
3. Stop creating coordination tasks when no coordination decision has changed since last cycle

1. If no human provides external input for aks-rp-e2e, the system will create 5+ MORE coordination/audit tasks in the next 24h
2. None of those tasks will unblock a leaf
3. The `blocked_leaf_count` will remain 98 (±1) regardless of coordination work

## For Developers

The minimum viable fix is ~10 lines:

```typescript
// In project-execution-watchdog wake logic:
if (blockedFraction > 0.90 && allBlockersExternal(blockedTasks)) {
  // Don't fire blocked-frontier-review
  // Log: "project quiescent, awaiting external signal"
  return;
}
```

This preserves all other watchdog functions (stale-active detection, review-pending wakes) while eliminating the inventory loop.
