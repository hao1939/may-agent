## Core Discovery: Every Documented Pathology Is the Same Missing Primitive

Examining 73 prior knowledge entries and 24h of live production data reveals that **every major agent system pathology we've documented is a manifestation of one absent capability: input-change detection.** The system re-computes at every level without checking whether inputs have changed since the last computation.

### The Isomorphism Table

| Layer | Pathology | Documented In | What Re-Computes | On What Unchanged Input |
|:------|:----------|:-------------|:-----------------|:----------------------|
| **Ops** | LLM inference on empty queue | KE-011 | "Is there work?" | DB state (0 runnable tasks) |
| **Sessions** | 100% evaluation coverage | KE-010/KE-054 | Quality judgment | Session with same heuristic verdict |
| **Alerts** | Triage re-derivation | KE-021 | "Can I fix this?" | Metric at same value, same verdict |
| **Retries** | Stampede bursts | KE-062 | Session creation | Same infrastructure rejection |

| **Knowledge** | Diagnostic revision chains | **NEW** (this entry) | Root cause diagnosis | Same planner cliff data |

This is KE-021 (Triage Capture) operating at the knowledge-production level. The mechanism is identical: an agent re-derives a conclusion on unchanged input because nothing tells it "you already answered this."

### The Unified Principle

> **A system that cannot detect "input unchanged since last computation" will re-compute at every cycle. This is true at every abstraction layer — ops, sessions, alerts, retries, projects, and knowledge production.**

This is not a metaphor. It's the same computational structure:

```
loop:
  input = read_state()
  output = expensive_computation(input)  
  store(output)
  wait(interval)
  goto loop
```

The missing line is:

```
  if input == last_input: skip
```

One primitive. Applied at every layer.

A contract that says "only re-evaluate if the session's heuristic verdict changed" is implementing the missing convergence check.

### The Implementation Principle: Hash-and-Skip

For each re-computation pathology, the fix has the same shape:

```typescript
const inputHash = hash(currentInputs);
if (inputHash === lastInputHash && elapsedSince(lastComputation) < maxStaleness) {
  return lastResult; // skip
}
const result = expensiveComputation(currentInputs);
lastInputHash = inputHash;
lastResult = result;
return result;
```

Concrete applications:

| Layer | `currentInputs` | `maxStaleness` | Expected savings |
|:------|:----------------|:--------------|:----------------|
| Planner | `tasks WHERE status='runnable'` count | 5 min | 57% of planner sessions (KE-011) |
| Triage | metric value + last verdict | 6 hours | 100% of repeated triage (KE-021) |
| Evaluator heartbeat | worker session count in window | 1 hour | 4-6× heartbeat reduction (KE-054) |
| Watchdog reconcile | blocked task IDs + blocker texts | 4 hours | 90% of maintenance loops (KE-073) |
| Arc diagnosis | planner cliff duration + affected metrics | 12 hours | 8 of 9 revision KEs (this finding) |
