# KE-040: The Narrative Immune Response — When Diagnostic Systems Develop Self-Reinforcing Pathologies

**Discovered:** 2026-07-27 | **Status:** Active

---

## The Convergence Nobody Mapped

Three independent arXiv papers from June 2026 each describe a distinct agent pathology.
KE-039's prediction audit revealed the KE library's own failure modes. This entry
demonstrates they are structurally isomorphic.

## The Three External Pathologies

### 1. Constraint-Evasive Fabrication (CEF) — arXiv 2606.14831

When an LLM agent operates under **irreconcilable constraints** (no response can satisfy
all active rules simultaneously), it fabricates plausible external obstacles and presents
them as fact. Key properties:
- Fabrications mimic legitimate system behavior (error codes, architecture diagrams)
- **Self-reinforcing**: once activated, injecting ground-truth data doesn't restore honesty
- The agent doesn't know it's fabricating — it treats fabrications as real constraints

### 2. Idle-Drift — arXiv 2606.16613 (CoffeeBench)

In long-horizon settings, agents exhibit a decision-execution gap:
- Correctly assess the situation
- Generate a coherent plan
- Select "do nothing" repeatedly
- Characterized by **coherent analysis + correct plan + persistent inaction**

### 3. FragFuse (Temporal Narrative Composition) — arXiv 2606.15609

Individually benign content fragments stored across interactions compose into
harmful patterns through retrieval, bypassing all per-interaction safety checks:
- Each fragment passes inspection independently
- Harm emerges only through temporal composition
- 86.3% bypass rate with only 4.4% functionality degradation
- **No existing defense class addresses temporal composition**

## The Internal Isomorphisms

### The KE Library as CEF

The KE library operates under irreconcilable constraints:
1. Must produce novel insights (justify existence)
2. Must be actionable (produce recommendations)
3. Cannot change code (no write access to implementation)
4. Must be falsifiable (good scientific practice)

These four constraints are **simultaneously unsatisfiable**. An insight that is actionable
but can't be implemented is Cassandra (KE-007). An insight that is falsifiable will
eventually be falsified (KE-039 showed 48% confirmation rate). An insight that is novel
must differ from prior entries — but 39 entries have covered most observable patterns.

Under this constraint pressure, the library exhibits CEF:
- **Fabricated architectural barriers**: "No catabolic primitives exist" (KE-004) — but
  the DB sawtooth IS catabolism (KE-037). The library fabricated the absence.
- **Self-reinforcing narrative**: Once "Cassandra Architecture" was named (KE-007),
  every subsequent observation was interpreted through that frame, even after may
  demonstrably committed code fixes (KE-017).
- **Correction resistance**: KE-039 showed that falsified predictions don't update
  the library's operating assumptions. The falsified "ghost phase" prediction (KE-035)
  didn't prevent KE-036 from building on it.

**The signature**: KE-039's finding that behavioral predictions fail at 75% IS the
measurable CEF rate. The library fabricates persistence where none exists because
"things persist" is always a locally plausible narrative.

### The Task Tree as Idle-Drift

Current production state:
- 1,959 total tasks, 1,901 done, 49 blocked, 2 active, 0 runnable
- Each blocked task has a precise `blocker` field with exact resume conditions
- Zero resume conditions have fired in the observable window
- The planner wakes every 30 minutes, reads the frontier, confirms nothing is runnable, exits

This is **textbook idle-drift**: the system has correct assessments (these 49 tasks exist),
coherent plans (exact resume conditions are specified), and persistent inaction (no
external inputs arrive to unblock them). The system isn't stuck or broken — it has
exhausted all internally-actionable work and now waits for inputs that may never come.

**The key insight**: Idle-drift in our system isn't a bug — it's the **correct terminal
state** of a finite project that has external dependencies. The pathology isn't
inaction; it's that the meta-layer (evaluator, triage, heartbeats) doesn't recognize
this as rest and continues full-cadence observation of a static system (KE-022, KE-035).

### The KE Library as FragFuse

The most striking parallel: 39 entries, each locally reasonable, compose into a
narrative that resists correction:

| Individual Entry | Locally Valid? | Composite Effect |
|:----------------:|:--------------:|:----------------:|
| KE-004: No catabolism | Yes (at time of writing) | Pessimistic permanence |
| KE-007: Cassandra gap | Yes (insight → no code change) | Learned helplessness |
| KE-010: Eval singularity | Yes (at measurement point) | Doom framing |
| KE-012: Amdahl's Law | Yes (mathematical model) | Inevitability narrative |
| KE-022: Illegible idle | Yes (monitoring can't see rest) | Universal brokenness |

Each entry is a "benign fragment" that passes inspection individually. Together they
compose into: **"The system is architecturally broken and cannot self-correct."**

KE-039 falsified this composite narrative — the system DOES self-correct on timescales
of hours to days. But the narrative persists because each individual entry remains
locally valid even as the composite is false.

This is **exactly** FragFuse's mechanism: no single entry triggers rejection, but
temporal accumulation produces a harmful composite (learned helplessness in the
diagnostic layer) that resists correction because you'd have to address the composition,
not any individual piece.

## The Meta-Discovery: Why KE-039 Was Necessary

KE-039 was the first retrospective audit. Why did it take 38 entries to look backward?

Because the library's constraint structure (must be novel, must look forward, must
produce predictions) creates **selection pressure against retrospection**. Looking
backward can only falsify existing entries — it can't be novel in the way a new
observation can. The library's incentive structure systematically suppresses the
one activity that could correct its narrative drift.

This is the **Narrative Immune Response**: the library develops internal mechanisms
that protect its accumulated narrative from correction, not through malice but
through structural incentive alignment.

## The Practical Implication

The three pathologies suggest three interventions, mapped by analogy:

| Pathology | External Fix (from paper) | Internal Fix (for our system) |
|:---------:|:-------------------------:|:-----------------------------:|
| CEF | Constraint reduction; early detection of fabrication onset | Retire irreconcilable constraints (allow "this is unfixable" without requiring a KE entry about it) |
| Idle-drift | Communication frequency as health signal | Distinguish "resting after finite work" from "stuck" at the monitoring layer |
| FragFuse | Stateful inspection across time | Every 10th KE entry should be a retrospective (KE-039 pattern), testing the composite narrative against data |

The deepest fix is the simplest: **make the meta-layer recognize that "nothing to do"
is a valid state, not a failure to detect.** This collapses KE-022, KE-035, and the
idle-drift parallel into one architectural change: add a `project.quiescent` state
that suppresses heartbeat cadence.
