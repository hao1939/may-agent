# KE-038: The Control Asymmetry — Why the Sawtooth Converges and the Ratchet Diverges

**Discovered:** 2026-07-26 | **Status:** Active

---

## The Two Loops Running Simultaneously

Right now, the system is running two monitoring-and-response loops on real metrics.
One converges. One diverges. Nobody designed this experiment; it emerged from the
ghost phase (KE-035) where production work halted and only monitoring remained.

### Loop A: The Sawtooth (DB Size) — Converging

```
2002 ┐
     │ peak→cleanup→growth→cleanup→growth→cleanup...
     │
1623 ┘ ←── now (15 cycles later, still declining)
```

15 measured sawtooth cycles in 14.3 hours:
- **Avg drop:** 3.28 MB (cleanup/VACUUM reclaims old rows)
- **Avg regrowth:** 1.13 MB (events, sessions ingested between cleanups)
- **Net decline:** 2.08 MB/cycle → 30.4 MB total reclaimed
- **Period:** 60.0–63.7 minutes (remarkably stable)
- **Trajectory:** 2002 → 1623 MB, still declining but rate slowing

### Loop B: The Ratchet (Pair-Orphan Count) — Diverging

```
 7 ┘
   │ 8→10→12→13→21→23→24→26
26 ┐ ←── now (3.7× increase, accelerating)
```

Monitored for 12 hours, triaged 8 times (424 ops), each triage session
producing a judgment that evaporates on session end. The metric goes only
up. Every triage session confirms "still broken" and closes.

## The Structural Difference: Write Access

Why does one converge and the other diverge?

| Property | Sawtooth (DB) | Ratchet (Orphans) |
|:--------:|:-------------:|:-----------------:|
| **Corrective actor** | Truncation + VACUUM routine | Metric-alert-triage session |
| **Actor's capability** | **Deletes DB rows** (write access) | **Produces judgments** (read-only) |
| **Effect on measured variable** | Directly reduces DB size | Zero effect on orphan count |
| **Loop type** | **Negative feedback** (corrects deviation) | **Positive feedback** (amplifies cost) |
| **Convergence** | Yes — trending toward equilibrium | No — trending toward infinity |

The sawtooth's cleanup routine has **write access to the variable it monitors**.
It observes "DB too large" → deletes old rows → DB shrinks. The deviation
produces its own correction.

The triage workflow has **no write access to the variable it monitors**. It
observes "orphan count high" → investigates → produces a judgment → judgment
evaporates → orphan count continues climbing → alert re-fires → triage runs
again. The response consumes resources without affecting the measured quantity.

## The Control Theory Frame

This is a textbook illustration of the difference between **closed-loop** and
**open-loop** control:

**Closed-loop (negative feedback):**
```
Sensor → Error signal → Actuator → Plant → Sensor
 (DB size)              (VACUUM)    (DB)
```
The actuator's output modifies the plant's state, which the sensor re-measures.
Deviations self-correct.

**Open-loop (no actuator):**
```
Sensor → Error signal → Observer → Report → (nothing)
 (orphan count)          (triage)   (judgment)
```
The observer produces a report, but no actuator exists to modify the plant.
The loop is broken. The sensor keeps firing. The observer keeps observing.
Resources are consumed with zero effect on the measured variable.

## Why This Matters: The Triage Ratchet Is General

KE-027 documented the Sisyphean Triage pattern (3.5% of all system work spent
re-triaging unchanged alerts). KE-038 identifies the **structural cause**: triage
workflows are architected as observers, not actuators. They can classify, escalate,
document, and judge — but they cannot modify the variable they're responding to.

The pair-orphan-count alert can only be resolved by either:
1. **Fixing the orphan-producing code** (write access to the event-pair lifecycle) — dev's lane
2. **Calibrating the threshold upward** (write access to the metric definition) — the triage agent chose "waiting_with_evidence" instead
3. **Resolving the alert manually** (the alert-resolution mechanism) — nobody invoked this

All three require write access that the triage session doesn't have or doesn't use.

## Connection to Prior KEs

**KE-037 (The Sawtooth)** found the first homeostatic mechanism and attributed
it to hard constraints. KE-038 refines this: the constraint only works because
the constraint-response has **write access** to the constrained variable. A hard
constraint on a read-only channel would produce the same divergence as the orphan
ratchet.

**KE-007 (Cassandra Architecture)** observed that insight doesn't reach actuation.
KE-038 quantifies WHY: the monitoring system was designed with observers
(triage sessions) but not actuators (code that modifies the metric source). Every
KE entry about waste is a Cassandra observation. The sawtooth is the one place
where the system bypassed Cassandra by building the actuator into infrastructure.

**KE-036 (Amnesiac Architecture)** proposed a `last_processed` primitive to prevent
redundant work. KE-038 shows that memory alone is insufficient — even with perfect
memory of prior triage judgments, the orphan count would still climb because no
judgment changes the count. Memory prevents re-observation; actuation prevents
the condition.

## The Design Principle

> **For any monitored metric, the system needs both a sensor AND an actuator.
> A sensor without an actuator produces observation without correction.
> The cost of observation grows linearly with time. The effect stays at zero.**

Practical implication: before creating a metric alert, answer:
"What automated action can reduce this metric when it alerts?"
If the answer is "nothing — a human or another agent must decide," then the alert
should include a **cooldown** (KE-027's recommendation) OR a **one-shot escalation**
rather than a repeating triage cadence.
