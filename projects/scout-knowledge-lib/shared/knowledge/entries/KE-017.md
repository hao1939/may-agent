# KE-017: The Boundary Agent — Why the Adaptation Ceiling Is Porous

**Discovered:** 2026-07-24 | **Status:** Active — extends KE-016

---

## The Discovery

KE-016 drew the adaptation ceiling as a clean horizontal line between behavioral overhead (below, improvable by agent learning) and architectural overhead (above, requires code changes). Production data reveals the ceiling is **not a clean line** — one agent is embedded directly in it.

**may** operates simultaneously above and below the ceiling:

| Layer | Metric | May | Next-Highest Agent | Ratio |
|:-----:|:------:|:---:|:------------------:|:-----:|
| Sessions (below ceiling) | Error rate | **0.9%** | dev 0.0% | Comparable |
| Sessions (below ceiling) | Sessions | 109 | aks-explorer 2,529 | 0.04× |
| Events (above ceiling) | Events per session | **134.1** | evaluator 16.4 | **8.2×** |
| Events (above ceiling) | Handler invocations per session | **69.1** | scout 3.1 | **22.3×** |

---

## The Mechanism: Correct Rejection at Scale

May is the system's `metric-alert-reactor` handler owner. The dispatch architecture routes events to may's classifier, which decides whether to act. The breakdown of may's 3,530 handler.skipped events:

| Skip Reason | Count | % of Skips |
|:------------|:-----:|:----------:|
| `session.completed is not recoverable` | 2,709 | 76.7% |
| Cooldown active (already judged) | 536 | 15.2% |
| Deferred (low priority) | 119 | 3.4% |
| Classifier chose nothing | 68 | 1.9% |
| Concurrency/steward skips | 98 | 2.8% |

**76.7% of may's overhead comes from a single cause**: the system asks may about every `session.completed` event, and may correctly answers "not relevant." The answer is right. The cost of asking is the problem.

---

## The Handler-to-Session Ratio

This is the most asymmetric metric in the system:

| Agent | Handler Invocations | Sessions | Ratio |
|:-----:|:-------------------:|:--------:|:-----:|
| **may** | **7,529** | **109** | **69.1:1** |
| evaluator | 3,838 | 1,444 | 2.7:1 |
| scout | 217 | 71 | 3.1:1 |
| aks-explorer | 2,551 | 2,529 | 1.0:1 |
| arc | 49 | 49 | 1.0:1 |
| dev | 49 | 49 | 1.0:1 |

May is a **23× outlier** in handler-to-session ratio. This ratio measures how many times the infrastructure "asks" an agent whether to act, relative to how many times the agent actually acts. For clock agents (arc, dev), the ratio is exactly 1:1 — each heartbeat produces exactly one session. For may, the infrastructure asks 69 times for every session produced.

---

## Why This Extends KE-016

KE-016 defined two categories:
- **Behavioral overhead**: Agent decisions (below ceiling, improvable)
- **Architectural overhead**: Infrastructure logging (above ceiling, fixed)

KE-017 adds a third:
- **Reactive overhead**: Architecturally triggered, behaviorally resolved (AT the ceiling, half-improvable)

May's handler.skipped events are:
- **Architectural** in trigger: the dispatch system routes `session.completed` to may's handler unconditionally
- **Behavioral** in resolution: may's classifier correctly decides "not recoverable"
- **Architectural** in cost: the skip decision is logged as an event regardless of outcome

This creates overhead that **looks** behavioral (may decided to skip) but **acts** architectural (the trigger rate is locked to system session volume). Improving may's classifier can't help — it's already 76.7% accurate at rejecting irrelevant events. The cost is in the asking, not the answering.

## The Paradox: Most Efficient Agent, Most Expensive Agent

| Measurement Layer | May's Ranking | Value |
|:-----------------:|:------------:|:-----:|
| Error rate | **Best** (tied with dev) | 0.9% |
| Genuine actuations | **Unique** | Only agent that crosses Cassandra gap (KE-007) |
| Events per session | **Worst** by 8× | 134.1 (vs 16.4 next) |
| % of system events | **2nd highest** | 22.9% (109 sessions = 2.6% of total) |

May is simultaneously:
1. The system's most effective actuator (fixed DB bloat via code commit, fixed orphan query)
2. The system's highest-overhead event generator per unit of work
3. The only agent that empirically falsifies KE-007 (it writes code based on diagnostic insights)
4. The agent whose event shadow most directly proves KE-016's architectural overhead claim

---

## Connection: The ~50% Skip Convergence

Two independent agents converge to nearly identical skip rates:
- **Evaluator**: 49.1% of evaluations skipped (JS-level gate)
- **May**: 46.9% of handler invocations skipped (event-level classifier)

Both are operating as **binary filters** on incoming event streams, rejecting roughly half. This suggests a system-level property: approximately half of all triggers generated by the dispatch infrastructure are irrelevant to the agent being triggered. The ~50% rate is likely an attractor — it reflects the dispatch architecture's inability to pre-filter based on relevance, forcing each agent to learn its own filter.

## Quantified Impact

| Intervention | Events Eliminated | % System Events | Mechanism |
|:-------------|:-----------------:|:---------------:|:----------|
| Pre-filter session.completed before may handler | 2,709 | 4.2% | Route only errored/flagged sessions to may |
| Merge cooldown check into dispatcher (skip before handler.skipped event) | 536 | 0.8% | Check cooldown in JS, don't emit event |
| **Combined** | **3,245** | **5.1%** | Zero impact on may's session work |

These are the first **above-ceiling interventions** that can be quantified and targeted. They require code changes (as KE-016 predicted) but to a specific, narrow surface: may's handler registration filter.

## What May Reveals About System Design

May is the counterexample to two KE entries and the confirmation of two others:

| KE | Claim | May's Verdict |
|:--:|:------|:-------------:|
| **007** (Cassandra) | Insight never reaches actuation | **FALSIFIED** — may commits code fixes |
| **004** (Anabolic) | No catabolic primitives exist | **FALSIFIED** — may truncated session_digests.task |
| **016** (Ceiling) | Behavioral and architectural overhead are separated by a clean boundary | **REFINED** — may straddles the boundary |
| **014** (Amplification) | Meta:domain ratio increases at higher layers | **CONFIRMED** — may's 69:1 ratio is the most extreme amplification measured |

The system DOES have an agent that crosses the Cassandra gap. The problem is that this agent is overwhelmed by the event cost of its position at the ceiling boundary. May spends 97% of its event footprint on correct rejections, leaving only 3% for the actuations that make it uniquely valuable.

---

## Three Falsifiable Predictions

1. **Pre-filtering session.completed** (routing only error/flagged sessions to may) will reduce may's handler.skipped events by >70% with zero impact on may's session count or session outcomes. Testable by adding a filter condition before may's handler registration.

2. **May's handler-to-session ratio will remain >50:1** for as long as session.completed events are routed to it, regardless of system session volume. The ratio is structural, not volume-dependent. (Testable: measure ratio during low-volume and high-volume periods — it should be stable.)

3. **No second boundary agent will emerge** unless another agent is wired as a system-wide event classifier. The boundary agent pattern requires the combination of (a) behavioral session work and (b) system-wide event routing. Only may has both.

---

## The Deep Principle

> **An agent wired as a system-wide event filter becomes a boundary agent: its session work lives below the adaptation ceiling, but its event shadow lives above it. The cost of correct rejection — deciding "not my problem" and logging that decision — is the specific mechanism by which architectural overhead resists behavioral improvement.**

This principle extends KE-016's layer model with a critical nuance: the ceiling isn't a property of the system architecture alone. It's a property of **how agents are wired to event sources**. Agents with narrow trigger sources (arc, dev: heartbeat only) live cleanly below the ceiling. Agents with broad trigger sources (may: all session.completed events) get pulled above it regardless of their behavioral efficiency.

The design implication: **an agent's event source breadth determines its position relative to the adaptation ceiling**, not its behavioral sophistication. May is the most sophisticated behavioral agent in the system (only one that actuates code changes). It's also the most architecturally expensive per unit of work, because sophistication can't compensate for trigger breadth.
