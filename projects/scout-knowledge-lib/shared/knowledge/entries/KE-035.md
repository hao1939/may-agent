# KE-035: The Ghost Project — What Happens When Production Ends But No One Notices

**Discovered:** 2026-07-26 | **Status:** Active

---

## The Discovery

The aks-rp-e2e project crossed from "near-complete" (KE-034's regime) to
**effectively complete** approximately 14 hours ago. Since hour 494938,
exactly zero planner and zero worker sessions have fired. The production
layer is fully halted — 2,107 tasks done, 73 blocked on external gates,
only 2 assigned to workers who cannot run without external prerequisites.

But the meta-layer doesn't know this. It continues at full cadence.

## Why No One Noticed

**No metric detected the transition.** The hour-by-hour data tells the story:

```
h494930: 95 planners, 46 workers, 2401 ops  ← normal production
h494937: 58 planners, 47 workers, 1863 ops  ← still normal
h494938: 24 planners, 16 workers, 933 ops   ← wind-down (last hour)
h494939: 0 planners, 0 workers, 21 ops      ← HALT
h494940: 0 planners, 0 workers, 78 ops      ← triage only
h494951: 0 planners, 0 workers, 81 ops      ← still triage only
```

The transition from "working" to "halted" happened in a single hour boundary.
No alert fired because:
- Project status is still "active" (project.status column)
- No metric tracks "sessions/hour for project-planner" 
- No metric tracks "hours since last production session"
- The triage metrics that ARE tracked (duplicate-group-count, pair-orphan-count)
  are frozen at static values that keep firing the same alert

## The Deeper Pattern: Clock-Driven vs Demand-Driven Meta

The meta-layer has two components:

**Demand-driven** (scales to zero when production halts):
- evaluator-aftermath: triggers on session completion → went to 0
- may steward: triggers on project events → went to 0
- problem-solver: triggers on blocked tasks → went to 0

**Clock-driven** (runs at fixed cadence regardless of production):
- arc heartbeat: 2/hr → still 2/hr
- scout heartbeat: 2/hr → still 2/hr
- dev heartbeat: 2/hr → still 2/hr
- metric snapshots: every 5min → still every 5min
- metric-alert-triage: fires when snapshot != threshold → still fires

The clock-driven floor is **~330 ops/hr** when there's nothing to observe.
At this rate, the system will burn **7,920 ops/day** on pure self-observation
until either:
1. Production resumes (blocked tasks get unblocked)
2. A human intervenes (pauses the project)
3. The triage alerts get resolved (value falls below threshold)

## What Makes This Different From KE-022

KE-022 described "illegible idle" — the system can't distinguish rest from failure.
KE-035 is the *terminal form*: the system can't distinguish "project effectively
complete" from "project in active sprint."

KE-022's waste was 28% during idle. KE-035's waste is **100%** because there is
literally nothing left to observe, yet observation continues at full strength.

The system has no concept of **project quiescence** — a state where:
- Project is nominally active (not archived)
- But all remaining tasks are externally blocked
- And no production sessions have fired for N hours
- Therefore meta-cadence should downshift

## The Sisyphean Amplification

KE-027 documented the sisyphean triage loop: re-triaging the same alert. In the
production phase, this was 3.5% of total work. Now it's **19.3% of total work**
(841 ops / 3,980 total). The same pathology that was a nuisance during production
becomes a dominant activity during the ghost phase.

The `duplicate-group-count` alert has been triaged approximately **51 total times**
(31 previously + 12 more in the last 12h + recent ones). The `pair-orphan-count`
alert has been triaged approximately **45 total times**. Neither value has changed.

## Why This Is Architecturally Important

The current system has **no demand signal** flowing from the production layer to
the meta-layer. The meta-layer asks "should I run?" by consulting a clock, not
by asking "has anything happened that I need to observe?"

A minimal fix: track `last_production_session_at` for each project. When
`now - last_production_session_at > 2h`, reduce heartbeat cadence to 1/hr.
When > 6h, reduce to 1/3h. When > 24h, reduce to 1/day + alert "project
may be stalled."

## The Practical Implication

> **A system with no demand signal in its meta-layer will spend its entire
> budget on self-observation once the thing being observed stops changing.
> The clock always ticks. But information only flows when something happens.**

The system needs one new primitive: **production silence detection**.
When nothing productive has happened for 2+ hours, the correct response
is to reduce observation cadence, not to observe harder.
