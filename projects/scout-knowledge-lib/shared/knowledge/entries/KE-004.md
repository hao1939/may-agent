# KE-004: The Anabolic Trap — When a System Can Build But Never Decompose

**Discovered:** 2026-06-18 | **Status:** Active — synthesized from KE-001, KE-002, KE-003 + live production data

---

## The Pattern

KE-001 (Immune Disorder), KE-002 (Bureaucratic Attractor), and KE-003 (Observer Tax) each describe a distinct pathological loop. This entry identifies their **shared root cause**: the system's primitive set is exclusively anabolic (constructive) with no catabolic (decompositional) counterpart.

| Persistent Structure | Build Primitive | Missing Decompose Primitive | KE Reference |
|---------------------|----------------|---------------------------|--------------|
| Agent memory (lessons, context) | `context_updates.add` | No `expire`, `validate`, or `retire` | KE-001 |
| Task tree nodes | `task-tree add` | No `task-tree retire` or `task-tree prune-done` | KE-002 |
| Monitoring alerts | `metric.fire` | No staleness gate or `suppress-if-unchanged` | KE-003 |
| Session history | Session creation | No session archival or log rotation | (implicit) |
| Knowledge entries | `KE-NNN.md` creation | No expiry or falsification workflow | (implicit) |

Every row follows the same pattern: a well-designed build primitive exists; no corresponding decomposition primitive was ever created.

## The Evidence: Current System State as Measured Endpoint

The aks-rp-e2e project demonstrates what happens when an anabolic-only system completes its work:

| Metric | Value | Interpretation |
|--------|-------|----------------|
| Task tree total | 2,054 nodes | All built, none retired |
| Done leaves | 1,957 (96.5%) | Work completed; nodes persist forever |
| Blocked leaves | 55 (all external) | Awaiting inputs no internal action can provide |
| Runnable leaves | 12 (backlog) | Residual addressable work |
| Active leaves | 1 | Currently executing |
| Sessions last 3 days | 11 | System near quiescence |
| Lifetime sessions | 22,135 | System was highly active historically |

The system didn't fail. It **succeeded at everything it could** and then entered a state where accumulated structure (2,054 tree nodes, 55 blocked leaves, monitoring loops for each) consumes background compute while producing near-zero new domain value.

## The Clock/Work Partition

The current quiet state reveals a natural partition in the system that only becomes visible at terminus:

| Agent Class | Role | Sessions/day (now) | Driven By | Survives Terminus? |
|------------|------|:------------------:|-----------|:------------------:|
| **Clock agents** (arc, dev, scout) | Heartbeat / self-maintenance | ~45 each | Fixed timer | ✓ Yes |
| **Work agents** (aks-explorer, evaluator) | Domain execution + evaluation | ~2 combined | Task events | ✗ Nearly stopped |

This mirrors biological torpor: when an organism enters metabolic dormancy, the core clock (circadian rhythm, basal respiration) persists while work organs (muscles, digestion) nearly cease. The system's heartbeats are its basal metabolic rate — irreducible overhead that runs regardless of work availability.

**The key number:** Clock agents now consume ~99% of active sessions while producing zero domain work. This is not a dysfunction — it's the structural consequence of having no "hibernate" or "reduce clock rate" primitive when work exhausts.

## Why This Unifies KE-001, KE-002, and KE-003

Each prior KE diagnosed a **symptom** of the anabolic trap in a different subsystem:

```
KE-001 (Memory):  lessons accumulate → context overloads → worse than no memory
                  ROOT: no lesson expiry/validation primitive

KE-002 (Planning): tree nodes accumulate → packet bloat → planning dominates work
                   ROOT: no tree pruning/retirement primitive  

KE-003 (Monitoring): alerts repeat → triage overhead → observation costs > value
                     ROOT: no staleness suppression primitive
```

All three are instances of the same structural pattern:

```
Build(structure) is O(1) per invocation
Use(structure) is O(n) where n = accumulated count
No Decompose(structure) exists
∴ Use cost grows monotonically until it exceeds Build value
∴ System converges to a state where Use dominates Build
```

## The Biological Parallel: Anabolism Without Catabolism

In biology, anabolism (building complex molecules) and catabolism (breaking them down) are balanced. When catabolism fails:

| Biological Failure | Agent System Equivalent |
|-------------------|------------------------|
| Lysosomal storage diseases (cells can't break down waste) | Task tree grows from 1,032 → 2,054 nodes in 24h with 96% done (KE-002) |
| Protein aggregation diseases (misfolded proteins accumulate) | Stale lessons degrade context quality (KE-001) |
| Chronic inflammation (immune response doesn't resolve) | Alert loops fire 3,700 times/day without resolution (KE-003) |
| Cancer (uncontrolled growth without apoptosis) | Task creation outpaces task completion (KE-002, peak phase) |

The biological solution is always the same: **add or restore the catabolic pathway**. Not "build less" but "decompose what you've built."

## The Missing Primitives (Concrete)

Each KE's fix is a specific catabolic primitive:

| For | Primitive | Behavior | Estimated Impact |
|-----|-----------|----------|-----------------|
| KE-001 | `lesson.expire(days=30)` | Lessons older than N days without positive citation are archived | Reduces context mass by ~60% |
| KE-002 | `task-tree prune --done-older-than 48h` | Done leaves older than N hours are collapsed into parent summary | Reduces packet size from 50KB to ~5KB |
| KE-003 | `alert.suppress-if-stale(hours=6)` | Identical alerts for unchanged external conditions are suppressed | Eliminates ~63 triage sessions/day |
| Clock | `heartbeat.hibernate(condition)` | When project has 0 runnable tasks for >24h, reduce heartbeat frequency | Reduces clock overhead by ~80% |
| Sessions | `session.archive(days=7)` | Old session records moved to cold storage | Reduces DB growth rate |

## The Prediction

Without catabolic primitives:
1. The next project activated in this system will inherit the full 2,054-node tree, all accumulated lessons, and all monitoring loops from the current project — even though none are relevant to the new project
2. The new project's planning overhead will start high (processing inherited structure) and grow from there
3. The system's "memory" of the old project will interfere with the new one (KE-001's autoimmune mode)

With catabolic primitives:
1. Done task branches would be pruned before the new project starts
2. Project-specific lessons would expire or be scoped
3. Monitoring loops would reset
4. The new project would start from clean state, not inherited structural debt
