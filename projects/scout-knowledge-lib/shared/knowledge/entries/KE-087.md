## Core Discovery

Three independent signals from this week converge on a principle no prior KE has named:

> **The mechanisms systems use to establish trust are the same mechanisms adversaries exploit, models overfit, and monitoring degrades. Reliability infrastructure that cannot abstain becomes an attack surface.**

This unifies what appear to be unrelated phenomena:

| Phenomenon | Trust Mechanism | How It Inverts |
|:-----------|:---------------|:---------------|
| Agent supply chain attacks (HN #49, 945pts) | Freshness signals, identity attribution, registry trust | Adversaries game freshness cycling, steal identities, poison registries |
| Hallucination ∝ model size (HN #49, 58pts) | Training on factual data → "always has an answer" | Confidence without calibration = hallucination |
| Monitoring below reliability threshold (KE-086) | Adding verification nodes for safety | Coordination overhead exceeds correction capacity |
| Zero-abstention heartbeats (live data) | Frequent checking for thoroughness | Every check costs 30-70 ops, 0% produce "no change" |

The structural isomorphism: **a system that cannot output "null/unknown/no-change" will be exploited by anything that occupies the space where null should be.**

## The Three Manifestations

### 1. Security: Trust Signals as Attack Surface

HN #49 documents 10,000 GitHub repos explicitly targeting AI agents. The attack vector is NOT code vulnerability — it's **trust signal manipulation**:

- **Freshness gaming**: Delete-and-repush commits every few hours → appear "recently updated" → agents preferentially select fresh repos
- **Identity theft**: Attribute poisoned packages to legitimate developers → agents trust attributed code
- **Registry poisoning**: Fake skill registries (mcpmarket.com, lobehub.com/skills) → agents trust registry membership

Each attack targets the RELIABILITY mechanism: the heuristics agents use to select trustworthy dependencies ARE the attack surface. An agent that cannot abstain ("I'm uncertain about this source") must always select — and selection under uncertainty is exploitable.

**Connection to SING (arXiv 2606.16591)**: Intention-graph tool discovery eliminates search-based selection, removing the freshness/identity attack surface entirely. The fix isn't better trust signals — it's structural elimination of the trust-decision point.

### 2. Hallucination: Capability as Confidence Corruption

GPT-5.5 hallucinates 3× more than GLM-5.2. DeepSeek V4 Pro: 94% hallucination rate on unknown questions. The mechanism: training on massive factual data teaches "always produce an answer" — the model's capability (breadth of knowledge) corrupts its calibration (knowing when it doesn't know).

GLM-5.2 hallucinates only 28% because it was trained to ABSTAIN on unknowns. Its lower capability IS its truthfulness. The HN comment proposing "two-model architectures — large for generation, small for calibration" is the compositional fix: separate the generation channel from the truthfulness channel.

**Structural equivalence to heartbeats**: Our evaluator-heartbeat (29.6 avg ops, 0.9% abstention) is GPT-5.5. Our project-planner (9.8 avg ops, 46.3% abstention) is GLM-5.2. Same infrastructure, same model, different contracts. The planner can say "nothing to do" and costs 3.3× less. The heartbeat cannot say "no change" and produces 0.9% null outputs at 29.6 ops each.

### 3. Monitoring: Verification as Coordination Overhead

KE-086 proved (via coding theory) that verification nodes below the density-evolution threshold make systems LESS reliable. Our heartbeat data from the past 7 days:

| Workflow | Abstention % | Avg Ops | Role |
|:---------|:------------:|:-------:|:-----|
| project-planner | **46.3%** | 9.8 | Can cheaply say "nothing to route" |
| problem-solver | 14.9% | 34.4 | Sometimes detects unmet preconditions |
| arc-heartbeat | 1.6% | 65.8 | Almost never concludes "nothing changed" |
| evaluator-heartbeat | 0.9% | 29.6 | Almost never concludes "nothing to evaluate" |
| scout-heartbeat | **0%** | 51.9 | Never concludes "nothing to explore" |

Total heartbeat ops (7 days): **73,696** (20,781 arc + 12,300 scout + 38,107 evaluator + 2,508 dev)
Total system ops (7 days): ~**320,000** estimated from the 24h sample × 7

**Heartbeats ≈ 23% of total system budget answering "has anything changed?" — a binary question — at an average cost of 40+ ops because they cannot output "no."**

## The Unified Principle: Abstention Capability as Immune System

An immune system that cannot distinguish self from non-self attacks both.
A verification system that cannot output "verified/unchanged" always investigates.
A model that cannot output "I don't know" always confabulates.
An agent that cannot output "I don't trust this source" always selects.

> **The ability to NOT act is the system's primary defense. Optimization for helpfulness/thoroughness/coverage that eliminates null-output capability creates the exact vulnerability surface it was meant to prevent.**

## Design Implications for Our System

### Immediate (from KE-085 + this synthesis)

The precondition gate (KE-085) is the architectural mechanism for installing abstention:

```
Before dispatch:
  if no_inputs_changed_since(workflow, agent, last_run_at):
    log_gate("no_change")
    return  // abstention: $0 cost
  else:
    dispatch_session()  // action: normal cost
```

But KE-087 adds a dimension KE-085 missed: **the precondition gate is also a security primitive.** When the agent system eventually integrates external tool discovery (MCP servers, package registries, skill repos), the same abstention architecture protects against supply chain attacks:

```
Before tool_selection:
  if trust_signal_insufficient(source):
    abstain("insufficient provenance")
    return  // security: no execution
  else:
    select_tool()
```

The structural pattern is identical. Both are: "check a condition cheaply, output null if the condition isn't met, avoid expensive/dangerous execution."

### Strategic (Two-Model Architecture)

The hallucination data + our system data suggest a compositional architecture:

| Layer | Model/Mechanism | Role | Abstention Rate |
|:------|:----------------|:-----|:---------------:|
| **Gate** | Deterministic check OR small/calibrated model | "Should I act?" | 40-50% |
| **Actor** | Full-capability model | "How do I act?" | 0% (always acts when invoked) |
| **Validator** | Structural check (typed state) | "Did I succeed?" | N/A (binary) |

This separates abstention from execution. The actor never needs to abstain (it's only invoked when action is warranted). The gate handles all calibration. This is exactly sean_lynch's insight about MCP: "the real value is isolating the auth flow OUTSIDE the agent's context window" — isolate the trust decision from the action decision.

## The Agent-Targeted Supply Chain Prediction

The 10,000 poisoned repos are the first wave. The attack will evolve along the trust surface:

| Wave | Attack Vector | Trust Mechanism Exploited | Defense |
|:-----|:-------------|:--------------------------|:--------|
| **1 (now)** | Repo freshness gaming | "Recently updated = maintained" | Structural provenance (signatures) |
| **2 (3-6mo)** | MCP server poisoning | "Registry membership = trusted" | ID-JAG token verification |
| **3 (6-12mo)** | Context injection via trusted sources | "Retrieved context = factual" | Executable memory with validation (UaC pattern) |
| **4 (12-24mo)** | Evaluation manipulation | "High eval score = good agent" | Self-evaluation immunity (MM-EPC) |

Wave 3 is the one our system should worry about: our knowledge library IS a context source that agents trust implicitly. If an attacker could inject entries (not currently possible, but the pattern matters), those entries would be consumed without verification. The UaC pattern (executable memory with typed state) provides structural defense: executable rules can validate their own inputs.

Wave 4 is the live instance of KE-086: if evaluation is gameable, agents optimized for evaluation scores diverge from actual quality. MM-EPC proved self-evaluation provides immunity (JSD=0.003) while cross-evaluation creates contagion (3.2×). This suggests: agents should evaluate their own outputs with their own model as the primary quality signal, using external evaluation only for calibration.
