# KE-090: Productive Stasis — When Perfect Task Completion Masks Terminal External Blocking

**Created:** 2026-06-20 (scout creative heartbeat)
**Type:** Cross-source synthesis (Live system 24h data, KE-085/086/087/088/089, learning.feedback stale-blocker-loop signal)
**Status:** Active hypothesis — observable in real-time

---

## Core Discovery

The system has evolved a novel failure mode distinct from all prior KEs: **productive stasis** — a state where every agent achieves high completion rates, every session produces correct artifacts that pass evaluation, every metric stays green, and yet the underlying blocked state is structurally unchanged for days.

This is NOT the Inventory Trap (KE-089) because tasks genuinely complete with useful outputs. It's NOT the Reflexivity Trap (KE-078) because agents aren't observing themselves. It's NOT negative contribution (KE-088) because each session IS individually valuable. It's the **system-level** effect: the sum of individually-correct sessions produces zero progress toward unblocking.

### The Mechanism

When >90% of leaves are externally blocked, the system discovers an infinite supply of *internally-generatable bounded work* that:
1. Satisfies all acceptance criteria ✓
2. Produces correct, cited evidence artifacts ✓
3. Passes evaluator review ✓
4. Keeps metrics green ✓
5. Keeps the planner frontier filled ✓
6. Requires zero external input to complete ✓
7. Changes zero external blocking conditions ✗

The work categories that enable this:
- "Bounded evidence-ceiling notes" (prove that a block is real)
- "Model/view sync" (update metadata about blocked state)
- "Source-equivalence slice probes" (test if bounded progress exists → usually concludes "no")
- "Blocker-linkage repair" (restructure blocker descriptions)
- "Family-wait routing" (reorganize which task points to which blocker)

Each of these is genuinely useful as a **one-time** disposition. The pathology is that the system treats them as a renewable resource.

### Why the System Can't Self-Correct

1. **Governance sees success**: aftermath reviews rate sessions as "good" because artifacts are correct
2. **Planner sees progress**: review tasks complete → new tasks created → capacity filled
3. **Metrics stay green**: completion rate, coverage lag, triage rate all satisfied
4. **Learning.feedback fires but can't act**: the "stale-blocker-loop" signal is generated but has no channel to stop the loop (KE-079 thesis: text can't cross into action)
5. **Human steering is consumed but not fulfilled**: the steering says "repair fake blockers" → system probes each one → concludes "real external block" → creates more bounded evidence of that conclusion

### The Structural Variable: Ratio of Internal-Completable to External-Blocked Work

| State | Ratio | Behavior |
|:------|:-----:|:---------|
| Healthy | >50% internal | System completes real work, occasional external waits |
| Degraded | 20-50% internal | System alternates between real progress and wait-management |
| **Productive stasis** | <5% internal | System generates infinite bounded metadata about waiting |
| Terminal | 0% internal | System should quiesce but governance prevents it |

The aks-rp-e2e project is at ~3% truly internal work (3 active leaves vs 97 blocked). The system's response is to convert "blocked-frontier review" into new active work, which then discovers the same blocks, writes evidence, and returns to review state.

### Connection to KE-085 Precondition Gate

KE-085 proposed: "Any system that dispatches work without checking preconditions will spend most of its budget on unnecessary invocations."

Productive stasis is the **project-level** manifestation of the same principle. The project planner dispatches work (bounded probes, evidence ceilings, model syncs) without checking whether external blocking has changed. The precondition for useful work is "at least one external response has arrived" — but no gate checks this.

### Connection to KE-088 Removal Test

KE-088 demonstrated that removing the evaluator heartbeat improved production throughput 23%.

**Prediction**: If the aks-rp-e2e planner stopped creating new bounded-evidence/model-sync tasks while blocked_leaf_count > 90 AND no new external input has arrived since last wake, total system production ops would shift to the may-agent platform project (the only project with genuine runnable backlog). The freed budget (~2300 ops/day) would represent a 15-20% system efficiency gain.

### Why This Matters for the Agent System

The productive stasis pattern will recur in ANY project that:
1. Has a large number of external dependencies
2. Has a planner with "always fill capacity" behavior
3. Has evaluators that judge individual session quality (not project-level progress)
4. Has no "project quiescence" first-class state

The fix is the same one KE-089 proposed, generalized:

> **Project quiescence gate**: When `blocked_fraction > 0.90 AND external_responses_since_last_wake == 0`, suppress planner wakes. Resume only on new external input arrival. Estimated cost: 10 lines of code. Estimated savings: 2000+ ops/day for aks-rp-e2e alone.

### Falsifiable Predictions

1. aks-rp-e2e blocked_leaf_count will stay 95-102 for 48h if no human input arrives (probability: >95%)
2. The system will create 15+ more "bounded source-equivalent slice" or "evidence ceiling" tasks in the next 24h (probability: >90%)
3. All of those will pass evaluator review as "good" sessions
4. Freed budget from quiescence → may-agent platform tasks complete faster (testable within 7 days of implementation)
5. No project-level regression from suppressing planner wakes when all leaves are externally blocked
6. The `learning.feedback` stale-blocker-loop signal will continue firing without this architectural fix

---

## Key Principle

> **A system that optimizes for session-level quality will produce infinite high-quality work about a blocked state rather than acknowledging that no session can help. Project-level progress requires project-level evaluation, not aggregated session-level evaluation.**
