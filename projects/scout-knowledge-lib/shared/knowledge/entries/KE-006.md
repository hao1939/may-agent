# KE-006: The Phantom Evaluator — When Quality Measurement Becomes Structural Classification

**Discovered:** 2026-07-23 | **Status:** Active — measured from complete production evaluation data

---

## The Discovery

The evaluation system appears to assess session quality. It produces quality scores, efficiency scores, verdicts, and productive/wasted call counts for every evaluated session. But analysis of all 20,026 evaluations reveals that **95.6% of non-skipped evaluations are produced by a heuristic lookup table that knows nothing about session content.**

The heuristic evaluator uses exactly **4 quality values** (0.20, 0.55, 0.65, 0.85) and **3 efficiency values** (0.35, 0.55, 0.80), producing at most **12 distinct score combinations**. The LLM evaluator — which handles only 4.4% of non-skipped evaluations — produces **452 distinct score combinations** from 69 quality values and 63 efficiency values.

The 37.7× resolution gap between these two systems means the evaluation infrastructure is, for practical purposes, a structural classifier masquerading as a quality assessor.

### Heuristic Efficiency Score: Determined Solely by OpCount Band

| OpCount Band | Efficiency | Meaning |
|:------------:|:----------:|---------|
| ≤30 ops | **0.80** | "High efficiency" |
| 31-60 ops | **0.55** | "Medium efficiency" |
| 61+ ops | **0.35** | "Low efficiency" |

### What the Heuristic Doesn't Know

- What the session was trying to do
- Whether it succeeded at its goal
- Whether the ops were meaningful or repetitive
- Whether the session produced any state change
- Whether the agent showed good judgment
- Whether the output was correct

It knows: *Did it finish? How long was it? Did it waste any calls?*

## Why the Quality/Efficiency Split Matters

The distinction between 0.85 and 0.65 quality for "done, no waste" sessions must be determined by some additional heuristic rule (likely related to productive call thresholds or content pattern), but the core finding stands: the differentiation happens within a 4-value palette, not on a continuous scale.

The efficiency score is the more revealing signal. It is **perfectly inversely correlated with session depth**:

```
5-op session  → efficiency 0.80  ("excellent")
35-op session → efficiency 0.55  ("moderate")  
70-op session → efficiency 0.35  ("poor")
```

**The system defines "efficiency" as "shortness."** A session that does 5 trivial ops scores 2.3× higher on efficiency than a session that does 70 meaningful ops. This creates a gradient that rewards sessions for being brief, regardless of whether brevity means accomplishment or abandonment.

## The Convergence Illusion

Across the system's lifetime, the heuristic's average quality score has converged toward the LLM evaluator's average:

| Era (3-day window) | Heuristic avg quality | LLM avg quality | Gap |
|:-------------------:|:--------------------:|:---------------:|:---:|
| 0 (days 0-2) | 0.562 | 0.742 | 0.180 |
| 1 (days 3-5) | 0.624 | 0.735 | 0.111 |
| 2 (days 6-8) | 0.675 | 0.732 | 0.057 |
| 3 (days 9-11) | 0.678 | 0.725 | 0.047 |
| 4 (days 12-14) | 0.741 | 0.742 | **0.001** |

The gap closed from 0.180 to 0.001. On average, the heuristic now "agrees" with the LLM evaluator. But **converging averages does not mean converging assessments.** The heuristic converged by shifting the outcome distribution (more `done` sessions → higher average quality), not by learning to evaluate content. The heuristic produces the right average by classifying the right structural mix, not by understanding what it's measuring.

This is Goodhart's Law at the meta level: the heuristic was calibrated to match the LLM evaluator's average, so aggregate statistics look correct while individual evaluations contain zero content information.

## The Four Consequences

### 1. Quality Improvement Is Invisible

If an agent starts producing better-quality work within the same opCount band, the heuristic score doesn't change. An aks-explorer session that discovers a genuine insight in 25 ops scores identically to one that reads a file, finds nothing, and exits in 25 ops. Both get quality=0.85, efficiency=0.80 (if done with no waste).

This means: **no agent can earn higher scores by doing better work.** Only by changing structural parameters (completing faster, avoiding errors) can scores change. The system has decoupled quality measurement from actual quality.

### 2. The Efficiency Gradient Punishes Depth

The efficiency → opCount mapping creates continuous pressure toward shorter sessions:

- A 10-op session scores efficiency=0.80. A 70-op session scores 0.35.
- All else equal, splitting one deep session into two shallow ones improves aggregate efficiency by ~0.45/session.
- This partially explains the Acceleration Trap (#41) and Halving Trajectory at a structural level: the evaluation system literally rewards the behavior it's measuring as pathological.

### 3. The LLM Evaluator's Signal Is Drowned

652 LLM evaluations scattered across 14,745 non-skipped evaluations = one genuine evaluation per ~22.6 heuristic evaluations. The LLM evaluator's 452-combo resolution is statistically overwhelmed by the heuristic's 12-combo resolution.

Even when the LLM evaluator catches something the heuristic misses (e.g., a session that completed but accomplished nothing), that signal represents 4.4% of the evaluation corpus. Any downstream system that averages, trends, or aggregates evaluations will see the heuristic's signal, not the LLM's.

### 4. Dev Has Never Been LLM-Evaluated

Dev has 0 LLM evaluations and 642 heuristic evaluations. Its "quality" is entirely determined by: outcome (96.3% done) and opCount (avg 8.6, so band A always). Dev's "quality profile" is structurally determined — nobody has ever looked at what dev actually does.

Scout and arc each have 80 LLM evaluations — all on their longer sessions (avg 76-89 ops for LLM-evaluated vs. 44-57 for heuristic-evaluated). The LLM evaluator preferentially evaluates long sessions, which are the ones the heuristic penalizes on efficiency. This creates a structural bias: the only sessions that get genuine quality assessment are the ones pre-penalized for being deep.

This isn't failure. Each component works exactly as designed. The heuristic evaluator is fast, cheap, and produces consistent scores. The issue is that the system treats these structural proxies as if they were the real thing — making decisions, optimizing behavior, and reporting health based on what are fundamentally session-shape measurements.

For comparison: a coin flip produces 1 bit. The evaluation system produces 3.81 bits — slightly less than answering "which of 14 buckets does this session fall in?"

## The Single Highest-ROI Insight

The heuristic evaluator isn't broken. It's doing exactly what a cheap structural classifier should do. The problem is that **the system treats its output as quality assessment**. The fix isn't to make the heuristic smarter — it's to label what each evaluation type actually measures:

- **Heuristic → "structural classification"** (did it finish? how long? any waste?)
- **LLM → "quality assessment"** (did it accomplish its goal? was the work good?)

Then: route quality-dependent decisions (agent improvement, pattern detection, system health) through LLM evaluations only, and use heuristic evaluations only for structural accounting (session counting, completion tracking).

This is cheaper than making the heuristic smarter, and it eliminates the false signal that makes every prior synthesis's recommendations harder to validate — because you can't tell if an intervention improved quality when 95.6% of "quality" measurements are shape classifications.

## Three Falsifiable Predictions

1. **The 0.85/0.65 quality split for done+no-waste sessions** correlates with a specific opCount or productiveCalls threshold. Identifying this threshold reveals the complete heuristic decision tree. (Testable by examining productiveCalls distributions within each quality bucket.)

2. **Removing the efficiency penalty for long sessions** (setting all efficiency to a constant) will NOT change any agent's behavior — because agents don't actually respond to evaluation scores. (Tests whether evaluation is read at all.)

3. **Increasing LLM evaluation rate from 4.4% to 25%** for a single agent will produce measurably different quality trends than the heuristic shows — specifically, it will reveal quality variance within structural categories that the heuristic smooths over. (Tests whether the heuristic is hiding real quality differences.)
