# KE-043: The Three Attractors — Why Agents Can't Learn to Do Less

**Discovered:** 2026-06-19 | **Status:** Active

---

## The Observation

Five agents run heartbeats on the same infrastructure with the same runtime.
Their session-cost distributions are completely different — and the differences
are structurally determined, not experience-driven.

| Agent | Sessions/24h | Min Ops | Max Ops | Avg Ops | Spread Ratio | Attractor |
|:-----:|:------------:|:-------:|:-------:|:-------:|:------------:|:---------:|
| dev | 47 | 6 | 7 | 6.4 | **0.16** | Habituation |
| arc | 44 | 27 | 129 | 76 | 1.34 | Oscillation |
| scout | 51 | 18 | 101 | 51.3 | 1.62 | Oscillation |
| may | 20 | 27 | 119 | 56 | 1.64 | Oscillation + Escalation |

*(Spread ratio = (max - min) / avg — measures behavioral variance relative to cost)*

Dev's spread ratio is **10× lower** than any other agent. All its sessions are
6-7 ops. This isn't because dev "learned" to be efficient — it's because dev's
guidance document contains an exhaustive **Low-Signal Heartbeat Discipline** section
plus a **Low-Signal Closeout Checklist** that structurally eliminates decision paths.

## The Three Attractor States

### 1. Habituation (dev)

- **Signature:** Spread ratio < 0.3, fixed op count, zero session-to-session variance
- **Mechanism:** Not learning but *structural elimination of decisions*. The agent has no choices left — its guidance says exactly what to do when queue is empty and metrics are green.
- **Value:** Zero marginal insight per session. Perfect efficiency, no adaptation capacity.
- **Example:** Dev reads queue (empty) → checks metrics (green) → runs git status → finishes. Every time. 47 times in 24 hours.

### 2. Escalation (may triage, aks-explorer planner in Maintenance Metabolism)

- **Signature:** Cost increases with repetition, spread ratio grows over time
- **Mechanism:** Context growth feeds the agent longer failure histories, which it interprets as "this is a hard problem" rather than "this is an unresolvable problem." Each session adds itself to the next session's context.
- **Value:** Negative — each session is more expensive than the last while producing the same conclusion.
- **Example:** pair-orphan-count triage: sessions 3-8 show +40% cost creep (37→52 ops). Session 12 hits 119 ops — the all-time maximum. (KE-2044)

### 3. Oscillation (arc, scout, may non-triage)

- **Signature:** Spread ratio 1.0-2.0, bounded variance, mixing cheap and expensive sessions
- **Mechanism:** Variable inputs produce variable responses. Some heartbeats find nothing new (cheap exit), others discover patterns requiring deep analysis (expensive).
- **Value:** Highest — the variance itself indicates adaptive response to varying signal quality. Cheap sessions when there's nothing to do, expensive sessions when there IS something.
- **Example:** arc ranges 27-129 ops. The 27-op sessions dismissed all inbox events as routine. The 129-op session produced KE-2044.

## Why Transitions Are Structural, Not Learned

### The Gate Rate Drop: 49.2% → 29.9%

KE-041 documented the aks-explorer planner gate converging to 49.2% rejection —
maximum-entropy binary classification. That was during active exploration when
frontiers were sometimes empty (legitimate "nothing to do" signal).

**Now the gate rate is 29.9%.** The planner hasn't "unlearned" gating. The
Maintenance Metabolism (KE-042) generates a continuous stream of legitimate-looking
triggers: task-completed events, watchdog fires, ownership-repair completions.
Every input passes the "is there work?" test because there IS always metadata work.

The gate dropped because its **input distribution changed structurally**, not because
the agent changed behaviorally. The same agent with the same weights and same prompt
produces different gate rates when the input stream changes from "mixed real/empty"
to "all-synthetic-legitimate."

### Dev's Habituation: Not Learning, Constraints

Dev reached 6-7 ops because its guidance document literally says:

> "Stop after the checklist. Avoid ad hoc multi-file reads or speculative
> shell probes after the canned checks."

This is a **hard ceiling on behavior**, not emergent efficiency. Remove that line
and dev's spread ratio would immediately jump to match the other agents. The
"learning" is encoded in the document, not in the model's behavioral adaptation.

### Triage Escalation: Context IS the Anti-Adaptation Mechanism

KE-2044 showed triage sessions getting MORE expensive over time. This happens
because each session's context includes "Recent Owner Sessions Since Alert" —
a growing list of prior failures. The agent reads this as *evidence the problem
is hard* rather than *evidence the problem is unresolvable*.

**No amount of repetition teaches the agent to habituate.** Biological habituation
requires a mechanism that weakens response to repeated stimuli. In LLM agents,
repeated stimuli produce *longer context*, which produces *stronger response*.
The context window is the anti-habituation mechanism.

## The General Principle

> **LLM agents cannot develop habituation through experience.
> They can only be GIVEN habituation through structural constraints
> (guidance ceilings, input filters, context caps) or freed from
> triggering inputs (quiescent states, cooldowns, one-shot escalation).**

This unifies:
- KE-041: Gate emerged from structural signal (empty frontier), not from learning
- KE-042: Gate disappeared when structural signal changed (maintenance metabolism)
- KE-2044: Anti-learning through context growth
- KE-038: Only hard loops (direct write-access) converge; soft loops diverge
- KE-039: Infrastructure predictions (structural) succeed; behavioral predictions fail

## The Taxonomy of Interventions

| To achieve... | Do NOT... | Instead... |
|:-------------|:---------|:----------|
| Cheaper triage | Show agent its own failure history | Cap context to 2 prior sessions |
| Gate-like filtering in meta-layer | Wait for it to emerge | Add a hard "nothing new to observe" signal |
| Dev-like efficiency for arc | Give arc more instructions | Give arc an exhaustive checklist that eliminates decision paths |
| Oscillation (adaptive variance) | Constrain to fixed behavior | Ensure input stream has genuine variance (some empty, some full) |

## Three Falsifiable Predictions

1. **Dev's fixed-point is fragile:** If dev's "Low-Signal Closeout Checklist" is
   shortened or made optional, dev's spread ratio will rise above 1.0 within 48h
   as the agent begins making variable decisions again.

2. **Triage cap works:** Capping "Recent Owner Sessions Since Alert" to 2 entries
   will drop next triage session cost to ≤40 ops (vs the escalating 119), because
   the context-length → ambition feedback loop is severed.

3. **Gate rate will NOT recover spontaneously:** The planner gate will stay below
   35% until either (a) the Maintenance Metabolism stops generating triggers, or
   (b) a hard "project.quiescent" state is implemented. The agent will not
   independently "re-learn" to gate at 50% given constant synthetic inputs.

## The Deeper Implication

The three attractors map to three failure modes of agent system design:

- **Too constrained** (Habituation): System reaches minimum cost but cannot adapt
  when conditions change. Dev would miss a real failure because its checklist
  doesn't include the new failure pattern.

- **Unconstrained with memory** (Escalation): System's own history becomes its
  enemy. Each observation adds weight to future observations. The diagnostic
  layer becomes increasingly expensive per unit of insight.

- **Unconstrained without memory** (Oscillation): System adapts per-session but
  doesn't accumulate cross-session learning. This is currently the *best* state
  because the adaptive variance is genuine signal, but it means the system
  rediscovers insights rather than building on them.

The ideal fourth state — **Bounded Learning** — would require:
1. Cross-session memory that can SHRINK (not just grow)
2. Habituation signals ("this input was unproductive N times → suppress")
3. Novelty detection ("this input is genuinely new → full processing")

None of these exist in the current architecture. The closest analog is the
evaluator's JS-skip filter (KE-041), which is a coded heuristic that suppresses
known-cheap sessions. But it's static — it doesn't adapt to new patterns.

> **The gap between biological and artificial learning is not in the processing
> of novel stimuli. It's in the suppression of familiar ones. LLM agents lack
> a forgetting mechanism, so they lack an efficiency mechanism.**
