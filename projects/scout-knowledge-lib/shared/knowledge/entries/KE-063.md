# KE-063: The Instruction-Behavior Decorrelation

**Created:** 2026-08-21 (creative heartbeat)
**Confidence:** High (quantitative, live data + 4 independent external research papers converging)
**Prior KEs:** KE-059 (Guardrail Tax), KE-060 (Observer Inversion), KE-061 (Text-Mutable Ceiling)

## Core Discovery: The System Knows It Should Stop But Cannot

The evaluator's task prompt explicitly states: `⛔ REPEATED ALERT (seen 10x)`. The
context includes three prior KE analyses that document the root cause. The evaluator
reads them, correctly concludes "escalate to human," and... fires again in 10 minutes.

This is **instruction-behavior decorrelation** — the informational content of the
prompt tells the agent "this is known, nothing new to learn" while the behavioral
contract tells the agent "investigate this metric." The contract wins. Every time.

## The Full Triage Loop (Never Terminates)

```
1. Metric fires (aftermath-coverage = 0)        ← external cause, unchanged
2. Alert fires                                    ← threshold breach (correct)
3. Evaluator heartbeat dispatched                 ← clock schedule (correct)
4. Evaluator reads "seen 10x" + 3 KE refs        ← ~10 ops reading context
5. Evaluator concludes "escalate to human"        ← correct judgment
6. Escalation message sent                        ← creates event
7. May receives escalation                        ← message.created
8. May owner-review (53 avg ops)                  ← correct processing
9. May concludes "known, waiting for human"       ← correct judgment
10. GOTO 1 (10 minutes later)
```

**Every component behaves correctly. The composition is pathological.**

This is the Compositional Incoherence paper (2605.30335) in the wild: locally
coherent components composing into a globally incoherent system. Each step is
individually rational; the loop as a whole produces zero information at maximum cost.

## Why It Cannot Self-Correct: The Four Missing Primitives

### 1. No Rejected-Edit Buffer (SkillOpt 2605.23904)

SkillOpt stops proposing edits that have been rejected N times in a row. Our system
has no equivalent: the triage workflow produces the same conclusion ("escalate")
every time without recording that the conclusion is invariant. Each encounter is
treated as novel.

### 2. No Structured Abstention (EARS 2606.16432)

EARS achieves +10.4pp by learning when NOT to answer. Our evaluator has no mechanism
to abstain from investigation when it predicts with certainty that its conclusion
will be identical to the last N conclusions.

### 3. No Bi-Temporal Invalidation (Engram 2606.09900)

Engram marks stale facts as stale in a temporal graph rather than re-reading them.
Our alert injection has no temporal decay — an alert at "seen 10x" is injected with
the same weight and the same "→ Investigate" instruction as an alert at "seen 1x."

### 4. The Text-Mutable Ceiling Is Binding (MOSS 2605.22794)

The alert injection happens in **code** — the heartbeat dispatch logic reads the
metric table, formats the alert context, and injects it into the prompt. This routing
logic is outside the text-mutable scope. No change to `context.md`, `heartbeat.md`,
or any prompt artifact can prevent the dispatch. MOSS's argument is concrete here:
the fix requires modifying the dispatch condition to include a temporal predicate
(e.g., `if alert.consecutive_failures > 5 AND no_state_change → suppress injection`).

## The Novel Concept: Control-Theoretic "Dead Zone"

In industrial control, a **dead zone** is a region where small deviations from
setpoint produce no corrective action. Dead zones exist because:
- The cost of correction exceeds the benefit
- The measurement noise exceeds the signal
- The actuator cannot respond to changes that small

Our system has no dead zone for alerts. Every deviation from target, no matter how
persistent or well-understood, triggers full investigation at full cost. The fix is
not to suppress alerts entirely (they correctly identify real issues) but to introduce
a temporal dead zone: **after N identical triage cycles with no state change, reduce
investigation to a 1-3 op confirmation rather than a 45-op full investigation.**

---

## The Design Principle

> **Information content of an investigation is proportional to the probability that
> the underlying state has changed since the last investigation. When
> P(state_change) ≈ 0, investigation produces ≈ 0 bits. The system should invest
> ops proportional to expected information gain, not proportional to clock ticks.**

This is the same principle as:
- Engram: "less context = better accuracy when context is stale"
- SkillOpt: "stop proposing rejected edits"
- EARS: "abstain when confidence is low"
- Shannon: "channel capacity = function of conditional entropy"

## Structural Fixes (Ordered by Feasibility)

1. **Dispatch-time suppression** (code change, ~20 lines):
   If `alert.consecutive_unchanged_checks > 5` → omit from heartbeat injection.
   Still visible in metrics dashboard. Investigation can be manually triggered.

2. **Graduated cadence** (code change, ~10 lines):
   At 3× consecutive → reduce heartbeat cadence for that agent by 2×.
   At 10× consecutive → reduce by 4×.
   Natural decay: if the metric recovers, cadence restores immediately.

3. **Temporal dead-zone in prompt** (text-mutable workaround):
   Replace "→ Investigate this metric" with "→ This alert has been stable for 10
   checks with documented cause. No investigation needed. Report unchanged and
   proceed to other work."
   Cost: ~5 ops instead of 45.
   Limitation: the agent still fires and reads the full context.

4. **Alert auto-acknowledge** (code change, ~30 lines):
   After 10 unchanged checks with documented KE analysis → auto-move to
   `acknowledged` status. Remove from heartbeat injection. Add to monthly review.
