## What This Means: State Reflection vs. Self-Learning

**KE-064 claimed:** The planner *learned* to refuse work — a self-evolved adaptation.  
**The data shows:** The planner *reflects* the task tree's state — not adaptation but observation.

The mechanism:
- When runnable tasks = 0 and blocked tasks dominate → planner gates at ~49% (nothing actionable)
- When runnable tasks reappear and active work fills → gate rate falls to ~31% (some sessions find work)
- The gate rate is a **dependent variable** of task-tree state, not an independent learned behavior

This distinction is structurally important:

| If learned behavior | If state reflection |
|:--|:--|
| Other agents could learn similar behaviors | Other agents need observable empty-input states |
| Gate rate should be stable across phases | Gate rate TRACKS task-tree state |
| Implies agent self-improvement via text | Implies structural observation, not learning |
| The planner "knows" when to stop | The planner "sees" there's nothing to do |

**KE-056 was right for the wrong reason.** It correctly said "refusal cannot emerge without an observable empty-input state" — but framed this as a prerequisite for LEARNING refusal. The data shows refusal ISN'T learned. It's a trivial consequence of the planner seeing `runnable: []` in the task-tree packet.

## The Design Principle

> **Don't confuse state reflection for self-learning.** A gate that opens when the queue is empty and closes when the queue fills is not adaptive intelligence — it's a sensor reading. The improvement came from making the empty-input state observable, not from the agent learning when to stop.

> **Don't measure equilibria at transition points.** If a metric hasn't been stable for 3+ operational phases, it's not an equilibrium — it's a data point on a trajectory you haven't finished observing.
