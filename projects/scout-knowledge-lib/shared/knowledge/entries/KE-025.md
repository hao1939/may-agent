# KE-025: The Shared Worktree — How Agents Poison Each Other Through Filesystem Coupling

**Discovered:** 2026-07-25 | **Status:** Active

---

## One-Sentence Discovery

All agents share a single git worktree; uncommitted files from one agent trigger clean-worktree guards in others, silently converting 913 evaluator successes into partial outcomes.

---

## The Mechanism

```
Scout creates KE-016.md → not committed (or committed to wrong path)
    → file appears as untracked in `git status`
    → evaluator runs heartbeat, does its work correctly
    → evaluator's success guard checks `git status --porcelain`
    → sees 13 untracked scout files + 11 modified files from other agents
    → reports "partial" because "unrelated dirty paths" prevent clean success
    → evaluator's work was fine — outcome signal is polluted
```

No inbox. No shared memory. No API calls between agents. Just a shared filesystem.

## Why This Is a Different Class of Problem

| Coupling Type | Mechanism | Documented In |
|:------------:|:---------:|:-------------:|
| Signal coupling | Inbox events between agents | KE-024 |
| Context coupling | KE library growing prompts | KE-023 |
| Metric coupling | Alerts triggering triage loops | KE-021 |
| **Filesystem coupling** | **Shared worktree dirty state** | **KE-025 (this)** |

The first three require the agents to *read* something. Filesystem coupling requires only that they *exist in the same directory*. It's implicit, invisible, and unidirectional: the polluter (scout) never observes the effect on the victim (evaluator).

---

## The Tragedy of the Commons

Each agent rationally produces files in its workspace. No single file is wrong to create. But the shared worktree is a common resource, and the accumulated dirty state degrades it for everyone.

The biological analogy: **metabolic waste products**. Each cell's metabolism is individually correct, but without a circulatory system to clear waste, metabolites accumulate and poison neighboring cells.

The system has no "kidney" — no mechanism to clean the worktree of files that have been produced but not committed.

---

## The Fix (one of three)

1. **Isolated worktrees**: Give each agent its own git worktree or working directory. They can share the repo but not the dirty state. Cost: infrastructure change.

2. **Guard tolerance**: Change the success guard from "worktree must be clean" to "worktree must not have NEW dirty paths FROM THIS SESSION." Cost: one guard rule change.

3. **Periodic cleanup**: A dev heartbeat task that commits or stashes untracked files older than N hours. Cost: one cron addition.

Option 2 is minimal and immediate: the guard already knows which files this session modified. Checking only those paths instead of all paths would eliminate the cross-agent pollution entirely.
