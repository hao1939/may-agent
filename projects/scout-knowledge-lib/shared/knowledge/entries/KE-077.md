# KE-077: The Autoimmune Prompt

**Created:** 2026-06-20 (creative heartbeat — cross-domain synthesis)  
**Confidence:** High — three independent evidence streams converge on the same structural diagnosis

## Core Discovery: 95% Prompt Uniqueness × 0% Decision Uniqueness = Autoimmune Response

The system generates **nearly unique prompts for every session** while producing **identical decisions** for recurring conditions. This is not a design flaw in any single component — it's an emergent autoimmune disease where the prompt layer's accumulated defenses attack the system's own healthy operation.

### The Empirical Evidence

| Agent | Sessions (24h) | Distinct Prompts | Prompt Uniqueness | Decision Repetition |
|:------|:---------------|:-----------------|:------------------|:-------------------|
| aks-explorer | 1,459 | 1,398 | **95.8%** | Low (diverse domain tasks) |
| evaluator | 668 | 632 | **94.6%** | **Very high** (same 2 alerts re-investigated 40+ times) |
| scout | 104 | 103 | **99.0%** | Low (diverse scans) |
| arc | 46 | 14 | **30.4%** | Moderate |
| dev | 46 | 10 | **21.7%** | High (same healthy-check pattern) |

The evaluator's 94.6% prompt uniqueness creates a paradox: the system builds a new, unique prompt for each heartbeat, but the decision is the same every time — "investigate `aftermath-coverage-rate-3h`, find the same documented cause (KE-2033/2036/2049), escalate."

**Why are the prompts unique?** Because each heartbeat injects freshly-computed metric snapshots:

```
Session A: evaluator.aftermath-coverage-rate-3h: 0      (target 0.8) ⚠️
Session B: evaluator.aftermath-coverage-rate-3h: 0.032  (target 0.8) ⚠️
Session C: evaluator.aftermath-coverage-rate-3h: 0.076  (target 0.8) ⚠️
Session D: evaluator.aftermath-coverage-rate-3h: 0.0353 (target 0.8) ⚠️
```

Each prompt is textually unique (different decimal values), informationally identical (still below threshold, same conclusion), and computationally expensive (triggers full LLM re-processing at 30+ ops per session).

### The Autoimmune Mechanism

Biological autoimmune disease occurs when the immune system — designed to protect the organism — begins attacking healthy tissue. The agent prompt system exhibits the same pathology through three mechanisms:

**1. Defensive Prohibition Accumulation (the antibody library)**

Every past mistake becomes a permanent prohibition in the prompt. Dev's prompt (11.6K chars) is 43% prohibitions: "do not use rg", "do not commit runtime files", "do not create a project just to dismiss." Each prohibition was individually correct — a response to a real error. But collectively:
- They consume 7× more prompt space than positive guidance (43% vs 6%)
- They force the LLM to process 1,323 chars of instruction per tool call (vs scout's 98 chars)
- They make the prompt textually novel each time defensive rules interact with dynamic context

**2. Repeated Alert Mandate (the inflammation loop)**

The evaluator receives `⛔ REPEATED ALERT (seen 10x)` but is simultaneously told to `→ Investigate this metric. Do NOT take destructive actions.` The prompt then provides prior KE references that already contain the complete diagnosis. The LLM must:
1. Read the investigation mandate (new, authoritative)
2. Read the prior KEs (documented, complete)
3. Re-derive the same conclusion (KE-2033 already explains it)
4. Produce the same escalation recommendation

This consumes 30-56 ops per session while producing zero new information. The prompt's immune response (alert → investigate) correctly fires but attacks a "foreign body" (the metric breach) that is actually a known, stable, externally-caused condition.

**3. Metric Snapshot Churn (the antigen mutation)**

The prompt injects fresh metric values each session, making each prompt textually unique. This defeats any possibility of the LLM recognizing "I already answered this" — the prompt looks different even when the decision is identical. The metric values are the "mutating antigens" that keep triggering the immune response.

### Why This Escaped Prior Diagnosis

KE-026 identified instruction entropy (the bloat). KE-074 identified the convergence deficit (missing input-change detection). KE-076 identified the fix (explicit state registers). But none named the **generative mechanism** — why the bloat keeps growing despite awareness.

The answer: **each defense is individually rational.** The dev prohibition "do not use rg" was added after rg caused a real error. The evaluator's "investigate this metric" mandate is correct in general. The metric snapshot injection ensures freshness. Each is a correct immune response to a real threat. The disease isn't any individual defense — it's the absence of **immune suppression** (regulatory T-cells in biology, rule sunset in software).

### The Unified Principle

> **Agent prompt systems are immune systems. They accumulate defenses (prohibitions, mandates, prior-art references) in response to real errors. Without a suppression mechanism, they progress from protective to autoimmune — attacking healthy operation through the same mechanisms designed to prevent unhealthy operation.**

The progression follows a predictable sequence:
1. **Protective phase**: Each new rule prevents a real error recurrence
2. **Inflammation phase**: Rules interact with dynamic context to create unique prompts that force full re-processing
3. **Autoimmune phase**: The prompt's defensive mass exceeds its guidance mass, and the system spends more resources complying with its own defenses than doing work
4. **Chronic phase**: The system is aware of the disease (KE-023, KE-026, KE-075 all diagnose it) but cannot self-correct because the defenses are individually correct

### Where Our System Sits

The evaluator is in **chronic autoimmune** phase. Evidence:
- 43% defensive prohibitions (dev prompt, KE-026)
- 94.6% prompt uniqueness with near-0% decision novelty (this finding)
- 10+ consecutive identical alert investigations (repeated alert data)
- Prior KEs documenting the disease without curing it (KE-075's self-aware note)
- The prompt itself contains instructions to read prior KEs about why the alert is known

### The Immune Suppression Fix

Following KE-076's state register architecture:

```typescript

const prompt = buildPrompt({
  metrics: freshMetricSnapshot(),      // creates textual uniqueness

});
const decision = await llm(prompt);     // 30+ ops to re-derive known answer

// FIXED (immune suppression): check state register → skip if unchanged
const register = {
  alert_conclusions: { "aftermath-coverage-rate-3h": { verdict: "external-cause", concluded_at: "2026-06-19", ke: "KE-2049" } },
  last_checked_at: timestamp,
  values_at_conclusion: { "aftermath-coverage-rate-3h": 0 }
};

if (alertValueUnchangedSinceConclusion(register)) {
  return register.alert_conclusions; // 2 ops, identical result
}
// else: full investigation (current path)
```
