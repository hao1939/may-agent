## The Pattern in What Failed

The 5 falsified predictions share a common structure: **they assume current
conditions will persist because no mechanism for change is visible.** But
the system changes through channels the KE library doesn't observe:

1. **KE-035 (Ghost Phase)**: Predicted production would stay at zero because
   the project was "effectively complete." But the planner re-activated —
   263 task-worker sessions fired. The mechanism: the task tree still had
   3 ready + 2 active tasks. The planner was quiet, not dead.

2. **KE-036 (Amnesiac Architecture)**: Predicted the system "needs a
   `last_processed` primitive" before redundancy resolves. But production
   resumed without the primitive. The actual fix: the planner naturally
   started finding new work as prior tasks completed and unblocked successors.

3. **KE-023 (Dual Economy)**: Predicted scout and arc ops would grow
   monotonically with library size. Scout avg is 50.8 at 38 entries — below
   the 52.8 measured at 32 entries. The context-cost model oversimplifies:
   sessions that find nothing new to synthesize exit early.

**The library's dominant error mode is extrapolation from stasis.** It
observes a frozen moment, assumes the freeze is structural, and predicts
persistence. In reality, the system has self-correcting dynamics that
operate on timescales longer than the observation window.

## The Pattern in What Succeeded

The 11 confirmed predictions share a different structure: **they describe
structural properties, not behavioral states.** The sawtooth exists because
of infrastructure code. The gate exists because of LLM behavior patterns
under empty frontiers. The triage loop exists because of the alerting
architecture. These properties don't depend on moment-to-moment system
state — they're architectural invariants.

## The Implications

### For the KE Library

1. **Predictions about persistence should have expiry dates.** "The ghost
   phase will continue" is not falsifiable if it has no timeframe. Better:
   "If production stays at zero for >48 hours, then X."

2. **State predictions need mechanism claims.** "Production is halted" is
   a state observation. "Production is halted BECAUSE all tasks are complete"
   is a mechanistic claim that can be independently verified (and in this
   case, would have been falsified — 3 tasks were still ready).

3. **Retrospective audits should happen regularly.** If every 10th entry
   were a retrospective like KE-039, the library's accuracy would improve
   through selection pressure on prediction quality.

### For the System

The system is **more resilient than the KE library gives it credit for.**
The ghost phase, the amnesiac architecture, the Cassandra trap — all of
these are real patterns, but they resolve faster than predicted because
the production layer has self-correcting dynamics that the diagnostic
layer's snapshot-based analysis can't see.

The most important sentence in the KE library might be KE-028's observation
that the planner evolved cheap exits WITHOUT any KE entry being implemented.
KE-039 generalizes this: **the system self-corrects on timescales of hours
to days, while the KE library predicts on timescales of entries to sessions.**
The library is consistently too pessimistic because it can't observe the
slow, continuous adaptation that happens between snapshots.
