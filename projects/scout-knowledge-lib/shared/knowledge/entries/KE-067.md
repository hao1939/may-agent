## Core Finding: The Field Converges on a Principle Our System Inverts

Three independent research streams published within the same week converge on a single architectural principle:

> **Evaluation must be output-coupled and process-decoupled.**

Our system does the opposite: the evaluator is **process-coupled** (monitors its own coverage rates, investigates heartbeat metrics about its operational cadence) and **output-decoupled** (reconstructs task/artifact state from scratch each session, doesn't check whether deliverables exist on disk before evaluating).

This isn't a new observation about waste (that's KE-060/063). What's new is the **causal mechanism**: process-coupled evaluation doesn't just waste resources — it actively degrades the system it evaluates through a positive feedback loop.

## The Positive Feedback Loop Nobody Has Named

Prior KEs (060, 063, 065, 066) documented individual pathologies. This entry identifies the *generative cycle* that connects them:

```
1. Evaluator monitors its own process metrics (coverage rate, cadence)
   ↓
2. Process-monitoring consumes ops budget → less budget for actual evaluation
   ↓
3. Reduced evaluation throughput → process metrics worsen (coverage drops)
   ↓
4. Worsened metrics → more heartbeat investigation → more process monitoring
   ↓
5. → Loop tightens
```

Contagion Networks (2606.20493) adds the missing link: the evaluator's process bias **propagates to the agents it evaluates** (γ ∈ [0.157, 0.352]). Agents that receive process-focused feedback learn to produce process-visible work rather than output-quality work. This is the mechanism behind:

- **XHS's 68% false-failure rate**: agents that take efficient paths (fewer steps, different tool sequence) are penalized because the evaluator checks process, not output.
- **Enterprise over-defensiveness**: agents add redundant safety patterns because the evaluation signal rewards visible defense, not functional correctness.
- **Our KE-051's 92.4pp gap**: gate sessions (1-3 ops) succeed 97.1% of the time but the evaluator rates only 4.7% as passing — because "short session" is a process signal that triggers "needs_improvement" regardless of whether the gate decision was correct.

## The Architectural Principle: Coupling Direction Determines System Health

| System Layer | Should Be Output-Coupled | Should Be Process-Decoupled |
|:------------:|:------------------------:|:---------------------------:|
| **Evaluation** | ✅ Check: does the artifact exist? Does it pass acceptance criteria? | ❌ Don't check: how many ops did it take? Was the session long enough? |
| **State** | ✅ Carry state forward between sessions (LedgerAgent pattern) | ❌ Don't reconstruct state from process observation each session |
| **Guidance** | ✅ Deliver as latent activation or typed state (SoftSkill) | ❌ Don't deliver as text to be re-parsed each session (Guardrail Tax) |

Our system inverts all three:
1. **Evaluation**: process-coupled (heuristic evaluator penalizes short sessions) ← should check outputs
2. **State**: process-observation (heartbeat re-derives world state from metrics) ← should carry forward
3. **Guidance**: text-coupled (guardrail instructions re-parsed each session) ← should be cached/compiled

## The Fix: Three Coupling Corrections (Ordered by Impact)

### 1. Output-couple evaluation (structural, ~30min)

Before LLM evaluation fires, check: does the session's declared output file exist on disk?
If yes and content is non-trivial → start from "artifact exists, verify quality."
If no → "no deliverable produced, investigate why."

This replaces the current process-coupling (session length, op count) with output-coupling (artifact existence). arXiv 2606.09863 predicts this catches 45% of failures currently invisible, at 3,300× lower cost.

### 2. State-couple heartbeats (structural, ~20 lines)

Before heartbeat investigation, check: has the alert value changed since last check?
If unchanged → gate exit (1-3 ops). If changed → full investigation.

This is KE-063's proposal, now justified by the coupling principle: convert process-observation ("what does the metric say?") into state-observation ("has the metric changed?").

### 3. Compile stable guidance (medium-term)

Replace text guardrails that fire every session with compiled state (boolean flags, intent caches).
SoftSkill shows +42.1pp from the same behavioral intent delivered as latent rather than text.
BabelTele shows 3.6× compression with 99.5% fidelity for stable, repeated content.

## Connection to XHS Paradigm Trajectory

The XHS community's naming acceleration (scan #52-53) is the external manifestation of the same coupling inversion:

- **Context Engineering** → text-coupled (put more in the prompt)
- **Skill Engineering** → behavior-coupled (teach skills via markdown)
- **Harness Engineering** → process-coupled (engineer the execution harness)
- **Loop Engineering** → state-coupled (engineer the feedback loop)
- **Eval Engineering** → **output-coupled** (engineer what "good" means)

The paradigm sequence is a migration from process-coupling to output-coupling. Eval Engineering is the current frontier precisely because it addresses the coupling direction. The community is discovering — through practice, not theory — that **how you evaluate determines how agents behave**, and that process-based evaluation produces process-optimized agents rather than outcome-optimized agents.

The Result Orthogonality Principle (结果正交性原则, 207❤) is the practitioner-discovered version of the formal result from Contagion Networks: evaluation criteria shape agent behavior, so criteria must target outputs, not processes.
