# KE-047: Sensory-Dominant Architecture — The System That Detects Everything and Changes Nothing

## The Discovery

Every feedback mechanism in this system follows the same architectural pattern:

```
Sophisticated Detection → Notification → Zero Behavioral Change
```

This is not a bug in any individual component. It's a structural property of how the components compose.

## The Evidence

### Layer 1: Guards (0% Actuation)

| Guard Category | Warnings/24h | Blocks/24h | Actuation Rate |
|:-:|:-:|:-:|:-:|
| File re-read | 429 | 0 | 0% |
| Uncommitted files | 120 | 0 | 0% |
| Deliverable check | 99 | 0 | 0% |
| Knowledge integrity | 39 | 0 | 0% |
| Hallucinated path | 15 | 0 | 0% |
| **Total** | **875** | **0** | **0%** |

The guard fires 875 times per day. It has never blocked an action. Every warning is advisory — the agent receives the text and continues. This is the textbook definition of "alarm flooding": when every signal is a warning and nothing is a block, warnings carry zero decision-influencing information.

### Layer 2: Heuristic Evaluator (Structurally Blind)

- 1,619 sessions evaluated in 48h
- Total wastedCalls found: **42** (0.03 per session)
- The heuristic always sets `productiveCalls = opCount` and `wastedCalls ≈ 0`
- It **cannot** detect waste by construction — it measures activity, not quality

### Layer 3: Deep Evaluator (Acute Vision, 2.9% Coverage)

- 48 sessions deep-evaluated in 48h (vs 1,619 heuristic)
- Average wastedCalls: **25.8** per session (860× the heuristic rate)
- Coverage: 23 of 802 sessions in 24h = **2.9%**
- The only sensor that actually works covers 1-in-35 sessions

### Layer 4: The Verdict Collapse

The deep evaluator measures two orthogonal dimensions — **quality** (was the work good?) and **efficiency** (was the work lean?) — then collapses them into a single verdict:

| Quality | Waste Fraction | Verdict | The Problem |
|:-:|:-:|:-:|:--|
| 0.93 | 40% | acceptable | Good work, catastrophic waste → "acceptable" |
| 0.90 | 62% | acceptable | Excellent work, majority wasted → "acceptable" |
| 0.88 | 61% | acceptable | Strong work, 61% waste → "acceptable" |
| 0.22 | 66% | low_quality | Bad work, high waste → correctly detected |

The verdict only triggers on **quality** failures. A session that wastes 62% of its ops but produces good work in the remaining 38% gets "acceptable." The waste signal is measured, recorded, and then discarded by the verdict function.

## The Unifying Pattern

Every layer exhibits the same architectural shape:

| Layer | Sensing Quality | Actuation Quality | Net Effect |
|:-:|:-:|:-:|:--|
| Guards | Precise detection (path, reread count, uncommitted files) | Zero actuation (warn-only) | No behavior change |
| Heuristic Eval | Cannot detect waste | N/A | False confidence |
| Deep Eval | Detects 25.8 waste calls/session | 2.9% coverage | 97% of waste is unmeasured |
| Verdicts | Measures quality AND efficiency | Collapses to quality-only | Efficiency signal discarded |

The system invested in **sensors** (guard rules, evaluation prompts, metric collection) while the **actuators** (block actions, verdict thresholds, feedback-to-agent pathways) remained at zero. This is the industrial control equivalent of a factory with 400 temperature sensors and no cooling system.

## Connection to Prior KEs

- **KE-038** (convergent vs divergent loops): Guards are a *divergent* loop — they observe but have no write-path to the behavior that triggers them. The file-reread guard fires 429 times because it cannot stop re-reads, only complain about them.
- **KE-031** (evaluator as compliance stamp): The heuristic evaluator is the most visible instance, but KE-047 shows ALL layers are compliance stamps.
- **KE-044** (dark metabolism): The event loop checks 480 times/hour whether to act. The guard checks 875 times/day whether to block. Both produce the same answer: "no."
- **KE-045** (verification budget): Identified over-verification as the problem. KE-047 refines this: the system doesn't over-*verify* — it over-*senses* and under-*acts*. The verification budget isn't misspent on too many checks; it's misspent on checks that can't change anything.

## The Design Principle

> **A feedback system with comprehensive sensors and zero actuators is not a control system — it's a logging system.**

The fix is not more sensors, better prompts, or wider coverage. It's giving existing sensors write-access to behavior:
1. Guards: promote file-reread-5+ and hallucinated-path from `warn` to `block`
2. Verdicts: add a `wasteful` verdict orthogonal to quality (quality=good + efficiency=wasteful = actionable)
3. Coverage: if deep-eval finds waste>40% on 3+ consecutive sessions for an agent, trigger a guidance update

## Falsifiable Predictions

1. **Guard habituation**: If the file-reread guard stays warn-only, the 429/day rate will remain stable (±10%) over the next 7 days. If it's promoted to block, re-read attempts will drop 60%+ within 24h.
2. **Waste persistence**: Without a waste-specific verdict, the deep-eval waste fraction (avg 0.27) will remain stable because no mechanism converts waste detection into behavioral correction.
3. **Coverage ceiling**: Deep-eval coverage will remain at 2-4% because the evaluator's ops budget is fixed and deep-evals cost ~40 ops each vs ~23 for heuristic.
