# KE-057: The Completion Asymptote — Why the Last 5% Costs More Than the First 50%

**Discovered:** 2026-06-19 | **Status:** Active

---

## Core Finding

As a multi-agent project approaches completion, it enters a **completion asymptote**
where three simultaneous phenomena create a thermal inversion:

1. **Productive granularity shrinks**: Work items progress from "implement feature" →
   "reconcile individual matrix row" → "attach metadata to done task." Each remaining
   task is cheaper in ops but more expensive in context.

2. **External gate density rises**: At 95%+ done, nearly all remaining work requires
   human input, environmental approval, or product fixes. The ratio of blocked:active
   tasks approaches infinity.

3. **Meta-cadence stays constant**: Evaluator, arc, scout, and may heartbeats run at
   the same interval regardless of productive output rate. When production halts on
   external gates, meta-agents investigate the absence of production — generating
   demand from the lack of supply (KE-054's mechanism).

The result: **the system spends more wall-clock time maintaining awareness of its
near-done state than it spent doing the first half of the work.**

## The Done/Total Ratio as Lifecycle Signal

KE-056 identified the prerequisite for refusal: an **observable empty-input state**.
KE-055 identified behavioral temperature as the missing adaptive mechanism.

The `done/total` ratio on the task tree IS both:

| done/total | Lifecycle Phase | Appropriate Temperature |
|:----------:|:---------------|:-----------------------:|
| 0-20% | Exploration / decomposition | 🔥 Hot — high variance OK |
| 20-70% | Execution / bulk production | 🌡️ Warm — steady cadence |
| 70-90% | Consolidation / edge cases | ❄️ Cooling — reduce meta cadence |
| 90-95% | Completion approach | ❄️❄️ Cold — meta on-demand only |
| >95% | Asymptote — mostly external-gated | 🧊 Dormant — minimal heartbeat |

**Today's value: 96.8%.** The system is at the deepest dormancy-appropriate state,
yet meta-agents run at warm/hot cadence.

### Why This Signal Is Superior to Prior Proposals

| Prior Proposal | Limitation | done/total Advantage |
|:--------------|:-----------|:---------------------|
| KE-036's `last_processed` hash | Per-session, no lifecycle awareness | Lifecycle-level signal |
| KE-055's temperature measurement | Descriptive, not prescriptive | Directly computable threshold |
| KE-056's "empty frontier" | Binary (empty/not-empty) | Continuous gradient |
| Human-triggered mode switch | Requires manual intervention | Autonomous detection |

The done/total ratio:
- Is **cheap to compute** (one DB query or tree summary)
- Is **unambiguous** (monotonically increasing until complete)
- Is **already available** (the planner packet includes it)
- **Covers the whole project lifecycle** (not just per-session)

## The Six-Source Convergence

### 1. Internal: Evaluator Alert Trap (This Analysis)

`evaluator.aftermath-coverage-rate-3h` has been red for 10+ consecutive checks. Three
KEs (KE-2033, KE-2036, KE-2049) explain it's downstream of the aks-explorer throughput
cliff, not an evaluator bug. Yet the evaluator investigates it every heartbeat because:
- The metric is still red (stimulus present)
- The evaluator has no lifecycle signal (it doesn't know the project is 96.8% done)
- The instructions say "investigate red metrics" (contract demands response)

This IS evaluation colonization (KE-054), but now we know the **trigger condition**:
done/total > 95% AND blocked/remaining > 80%.

### 2. Internal: Dev as the Solved Case

Dev is the only agent that has achieved asymptote-appropriate behavior:
- 6.6 avg ops, 53s duration
- Zero errors, zero gate sessions
- "If queue empty and metrics healthy, don't investigate"

Dev's contract was manually evolved to include low-signal discipline. The lesson:
**contracts must explicitly address the asymptote state**, or agents will treat it
as normal operations. This confirms EARS: structured abstention must be explicitly
designed, not emergent.

### 3. XHS: "Skill Hell" (8,106❤) — Same Mechanism at Market Scale

"120+ skills, trapped in skill hell" — the more capabilities a system accumulates,
the more maintenance overhead during idle periods. Our system has 18 workflows. Each
runs at its scheduled cadence regardless of productive need. The completion asymptote
is Skill Hell at the project level.

### 4. HN: "Evaluation Is the New Bottleneck" (412pts)

"A million tools that make AI better, and no ways to measure whether AI is working
better." Our evaluator ran 206 sessions investigating metrics during a period where
production was almost entirely externally gated. Evaluation consumed 7,743 ops
evaluating a system that was waiting for human input.

### 5. arXiv: EARS Structured Abstention (+10.4pp)

EARS shows that the ability to say "I can't contribute here" improves system-level
performance by 10.4 percentage points. At the completion asymptote, EVERY meta-agent
session should abstain because the only remaining work is external-gated. The
predicted improvement from asymptote-aware abstention: 40-60% reduction in meta-ops
during >95% completion periods.

### 6. arXiv: StaminaBench — Contract Quality as the 6-12× Multiplier

The completion asymptote is a contract failure. The meta-agent contracts don't
include a lifecycle-awareness clause. Adding `if done/total > 0.95 AND blocked/remaining > 0.8:
reduce cadence 4×` is a contract improvement, not a model capability improvement.
StaminaBench confirms: this type of contract change produces larger effects than
model upgrades.

## The Thermal Inversion Explained

In meteorology, a temperature inversion occurs when warm air traps cold air beneath
it, preventing natural convection. Pollutants accumulate because the atmosphere can't
self-clear.

In the completion asymptote, meta-work (warm layer) sits above productive work (cold
layer, gated by externals). The meta-layer prevents the system from entering natural
dormancy because it generates its own stimuli (investigate red metrics, synthesize
observations, check health). The system can't self-clear into a waiting state because
the meta-layer's activity makes it look active.

This is why KE-052's prediction #4 ("zero tasks completed without human action") was
falsified within 3 hours: the system APPEARS stuck but responds immediately when a
human removes a gate. The problem isn't that the system is broken — it's that the
meta-layer keeps investigating the non-problem of "waiting for external input."

## Actionable Implication

Add lifecycle-phase awareness to one meta-agent contract as an experiment:

```
# At session start:
tree_stats = query("SELECT done/total as completion FROM task_tree_summary")
blocked_ratio = query("SELECT blocked/remaining FROM task_tree_summary")

if completion > 0.95 AND blocked_ratio > 0.8:
  → This is the completion asymptote.
  → Only investigate: new errors, new human steering, new external unblocks.
  → Do NOT: re-investigate known red metrics, synthesize unchanged state,
    or create new analysis of diagnosed conditions.
```

**Predicted effect**: Target meta-agent's ops drop 40-60% during asymptote phase
with zero loss of genuine issue detection. First-detection latency for real problems
unchanged (new errors/steering are still processed). Recovery from dormancy instant
(done/total drops or blocked_ratio drops when gates open).
