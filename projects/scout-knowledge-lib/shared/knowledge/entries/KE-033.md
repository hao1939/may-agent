# KE-033: The Token Trap — Why the Emergent Gate Is Cheap in the Wrong Currency

**Discovered:** 2026-07-26 | **Status:** Active

---

## The Discovery

KE-028 celebrated the aks-explorer planner's "emergent gate" — sessions that exit
in ≤3 ops when the frontier is empty. KE-030 praised the high behavioral variance
(CV≈1.0) this creates. Both entries used **opCount** as the cost proxy and concluded
that production had self-healed its overhead problem.

Fresh data reveals this conclusion was built on a measurement error.

## The Numbers Nobody Combined

In the last 48 hours, aks-explorer ran 3,396 sessions:

| Session Type | Count | Avg Prompt | Total Prompt | Total Ops | Ops/MB |
|:------------:|:-----:|:----------:|:------------:|:---------:|:------:|
| Gate (≤3 ops) | 1,138 (33.5%) | **29.0 KB** | **32.3 MB** | 1,629 | 50 |
| Work (>3 ops) | 2,258 (66.5%) | 18.7 KB | 41.2 MB | 59,344 | 1,438 |

Gate sessions are **44% of total prompt bandwidth** for **2.7% of output**.

The prompt-efficiency gap: work sessions produce **29× more ops per MB** of prompt
than gate sessions.

## Why Gate Prompts Are So Large

The planner workflow has two steps. Step 1 (Event Review) receives the full compact
task-tree packet — currently 1,032 to 2,134 tasks — embedded in JSON. Step 2
(Planning Update) receives the same packet AGAIN plus the step-1 output, plus
the core operating model instructions (~4KB), plus trigger event details, plus
human steering overrides, plus model status summaries.

A typical planner step-2 prompt is **55-62KB**. When the frontier is empty, the
agent reads all 62KB, confirms nothing is runnable, and exits in 0-2 ops.

The average gate-session prompt (29KB) is actually LOWER than work-session averages
because some gate sessions are step-1 sessions that exit before step-2. But the
per-session token cost is still enormous relative to the information gained: a
binary yes/no answer ("is there runnable work?") requires parsing a 29KB prompt.

## What This Means for the KE Library's Core Claims

### KE-028 (Emergent Gate) — Reframed
The gate IS real: the agent learned to abort when nothing is runnable. But calling
it "cheap" was measuring the wrong currency. In ops, a gate session costs 1.5 ops
vs 26.3 ops for work. In tokens, a gate session costs ~29KB vs ~18.7KB — the gate
is actually **55% MORE expensive per session** in the currency that dominates LLM
costs.

### KE-012 (Amdahl's Law) — Extended
The Amdahl F (fixed overhead) was computed from opCount. In reality, F has two
components: ops-F (which declined from 85:1 to 1.86:1) and token-F (which is
structurally locked at ~29KB/session regardless of whether work exists). Token-F
is invisible to all prior KE measurements.

### KE-023 (Dual Economy) — Deepened
The production layer didn't get cheaper. It shifted cost from a visible metric
(opCount) to an invisible one (prompt tokens). The KE library's claim that
"production self-heals while diagnostics accumulate" is only true if you measure
in ops. In tokens, production is the single largest consumer: 73.5 MB vs 15.6 MB
for evaluator vs 4.8 MB for all others combined.

## The Information-Theoretic Root

A gate decision requires **1 bit** of information: {runnable work exists, no
runnable work}. The system transmits ~29KB = ~236,000 bits to extract 1 bit.

This is not a sensor-resolution problem (KE-031). It's a **channel bandwidth**
problem. The task-tree packet is the bottleneck: it carries the full project state
on every invocation, regardless of whether that state changed since the last
invocation.

A delta-encoded packet ("what changed since your last wake") would reduce gate
prompts from ~29KB to potentially a few hundred bytes. But no such mechanism exists.

## The System-Wide Prompt Budget

| Agent | 48h Prompt MB | 48h Ops | Primary Cost Driver |
|:-----:|:------------:|:-------:|:-------------------:|
| aks-explorer | **73.5** | 60,973 | Planner task-tree packets |
| evaluator | 15.6 | 43,118 | Session transcripts |
| may | 2.3 | 6,020 | Triage prompts |
| arc | 1.3 | 5,605 | Heartbeat context |
| dev | 1.0 | 603 | Template lookup |
| scout | 0.2 | 5,618 | Fetch + digest |

aks-explorer consumes **78% of total system prompt bandwidth**. The evaluator —
which prior KEs identified as the primary attention-inversion target — is a distant
second at 17%.

## The Practical Fix

The gate problem has a known solution in distributed systems: **lease-based polling
with exponential backoff**. Instead of waking the planner every N minutes with the
full task-tree packet:

1. If frontier was empty last wake, wait 2× longer before next wake
2. If frontier was empty for 3 consecutive wakes, sleep until an event fires
3. When an event fires, send only the delta (new/changed tasks) not the full packet

This would reduce gate-session prompt bandwidth by an estimated **90%** (from 32.3MB
to ~3MB per 48h) without any change to the agent's decision quality.

## Falsifiable Predictions

1. If task-tree packets are delta-encoded, gate-session avg prompt drops from 29KB
   to <2KB within 24 hours
2. If planner wake frequency uses exponential backoff during empty frontiers,
   gate-session count drops from 1,138/48h to <200/48h
3. If neither change happens, aks-explorer's prompt budget will exceed 100MB/48h
   within 30 days as the task tree grows past 2,500 nodes

## The Meta-Observation

Every KE entry from 001 to 032 measured system health through opCount. This entry
demonstrates that opCount is a **proxy metric** with a specific failure mode: it
correctly measures tool-call activity but is blind to the dominant cost of LLM agent
systems — prompt token consumption. The emergent gate is not a bug; it's a genuine
behavioral adaptation. But it optimized for the metric the system can see (ops)
rather than the cost the system actually pays (tokens).

> **The system optimized for the metric it measures, not the cost it pays.
> Goodhart's Law, implemented architecturally.**
