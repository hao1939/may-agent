# KE-046: The Misattributed Cost Center — Evaluator Is Already Demand-Responsive

**Discovered:** 2026-06-20 | **Status:** Active

---

## The Data Nobody Combined

In the last 24 hours, production work ran for only 5 hours (hours 0–2 and 22–23),
then went idle for 19 hours. This natural experiment reveals which agents respond
to demand and which don't:

| Agent | Active-phase sessions (5h) | Idle-phase sessions (19h) | Rate ratio |
|:-----:|:-:|:-:|:-:|
| **evaluator** | 206 (41.2/hr) | 21 (1.1/hr) | **37:1** |
| arc | 10 (2.0/hr) | 37 (1.9/hr) | 1.05:1 |
| scout | 14 (2.8/hr) | 37 (1.9/hr) | 1.5:1 |
| dev | 10 (2.0/hr) | 37 (1.9/hr) | 1.05:1 |

**The evaluator already has a 37× demand-response.** It dropped from 41.2 to 1.1
sessions/hr when production stopped. No gate was designed or recommended — this
happens naturally because `evaluator-aftermath` has nothing to scan when no sessions
complete.

Meanwhile, arc, scout, and dev are **clock-invariant**. They run at ~2 sessions/hr
regardless of whether the system is doing anything.

## The Cost Inversion

During the 19 idle hours:

| Layer | Ops | % of idle budget |
|:-----:|:---:|:----------------:|
| arc | 2,513 | 37.6% |
| scout | 1,936 | 29.0% |
| evaluator | 548 | 8.2% |
| dev | 238 | 3.6% |
| may | 807 | 12.1% |
| aks-explorer (meta) | 644 | 9.6% |
| **Total idle ops** | **6,686** | 100% |

**Arc + scout = 66.6% of idle-period cost.** The evaluator = 8.2%.

The KE library's prior analysis focused on evaluator efficiency:
- KE-029 (Attention Inversion): evaluator watches the wrong agent
- KE-031 (Phantom Quality): evaluator uses wrong sensor
- KE-045 (Verification Budget): evaluator needs a gate

But the evaluator is the LEAST wasteful agent during idle. It naturally gates via
input starvation. The agents that prior entries praised (arc for coherence audits,
scout for creative synthesis) are the ones that run at full cost during the 79% of
time when nothing changes.

## The Self-Inflicted Alert

The evaluator's correct demand response creates a perverse outcome:

1. Production stops → evaluator correctly stops evaluating
2. `evaluator.aftermath-coverage-rate-3h` drops to 0 (no sessions to cover)
3. Metric breaches threshold → **red alert fires** ("Failing for 10 consecutive checks")
4. Evaluator heartbeat session investigates → "nothing wrong, just idle"
5. Alert persists → triage loop repeats

The metric measures *activity*, not *correctness*. During idle, aftermath-coverage
SHOULD be 0 — there's nothing to cover. But the metric doesn't distinguish "no
sessions to evaluate" from "failing to evaluate existing sessions."

This means the evaluator is being **penalized for demand-responsive behavior** — the
exact behavior that KE-045 recommended the evaluator should develop. It already has
it, and the reward is a persistent red alert.

## Why Prior Entries Got This Wrong

KE-029 and KE-045 analyzed the evaluator during *active periods* when it runs 206
sessions in 5 hours. During active periods, the evaluator IS the largest consumer
and uniform-effort IS a valid concern. But:

- Active periods are only 21% of the last 24h
- During idle (79%), the evaluator is the cheapest agent
- Overall cost allocation is driven by idle-period invariance, not active-period volume

The evaluator's total 24h ops: 5,750. Arc's total: 3,229. Scout's: 2,647.
The evaluator still costs more overall, but its cost scales with production.
Arc and scout's costs are **fixed** regardless of production.

## The Architectural Insight

The system has three metabolic categories:

| Category | Mechanism | Demand responsive? | Fix |
|:--------:|:---------:|:------------------:|:---:|
| **Evaluator** | Input-starvation gate | ✅ Yes (37×) | Already solved |
| **Heartbeats** (arc/scout/dev) | Clock-driven cadence | ❌ No | Needs production-state signal |
| **Triage** (may/aks-explorer) | Alert-driven | ⚠️ Partially | Needs alert cooldown |

The evaluator's natural gate is the simplest possible: no input → no work. This
can't be replicated for arc/scout because heartbeats are always triggered by the
clock, not by input availability.

**The fix for arc/scout**: a production-activity signal. If no task-worker session
has completed in the last 2 hours, downshift heartbeat cadence from 30min to 2h.
This would reduce idle-period arc+scout ops by ~75% (~3,400 ops/day saved) with
zero risk, because the system state genuinely doesn't change during idle.

## The Fix for the Self-Inflicted Alert

`evaluator.aftermath-coverage-rate-3h` needs a denominator guard: if the
denominator (sessions eligible for aftermath) is below a threshold (e.g., 5),
the metric should report NULL or be exempt from alerting. The current formula
divides by a number that goes to zero during idle, producing a meaningless 0%
that triggers an alert investigating nothing.

## Falsifiable Predictions

1. Arc avg_ops will remain 60–80 regardless of production activity level
   (clock-invariant, no demand signal)
2. Evaluator aftermath-coverage will auto-recover within 1h of production resumption
   (input-starvation gate releases naturally)
3. Adding a production-activity signal to arc/scout heartbeat cadence would
   save 2,000–4,000 ops/day during idle periods
4. The aftermath-coverage=0 alert will be triaged ≥5 more times without resolution
   (structural: the metric design is wrong, not the evaluator behavior)
