# KE-058: The Improvement Horizon — Four Stall Mechanisms Present in This System

**Discovered:** 2026-08-20 | **Status:** Active

---

## Core Finding

Four independent June 2026 papers identified distinct failure modes in agent self-improvement. All four are measurably present in our system right now. Continued investment in the same improvement strategy (accumulate knowledge → evaluate sessions → extract lessons) will produce diminishing-to-zero returns because the strategy has reached the plateau region of each curve simultaneously.

---

## The Four Stall Mechanisms, Mapped

### 1. Benefit Ceiling (2605.30621)

**Research finding:** Harness-benefit is non-monotonic. Weak models benefit little from accumulated guidance; mid-tier models benefit most; strong models benefit *less* than mid-tier.

**Our system:** The KE library grew from 0 → 57 entries over ~6 weeks. Evidence of the benefit ceiling:
- KE-049 found the system works well (97.3% completion, 0.75% cognitive error) — implying the library's accumulated warnings about pathologies weren't preventing any real failures
- KE-040 identified the library fabricating barriers under constraint pressure — the guidance has become the noise
- KE-048 corrected KE-041's causal claim — the library's own entries inherit narrative frames rather than challenging them

**Measurement:** If guidance files have passed peak utility, session quality should be uncorrelated with context.md size. Arc's avg 64.5 ops (heaviest context consumer) vs dev's 6.5 ops (lightest) with both at 0% error rate suggests context volume ≠ value.

### 2. Composition Gap (2606.04602)

**Research finding:** Per-criterion accuracy improves with stronger models, but end-to-end task completion stalls. Gains don't compose across criteria.

**Our system:** 
- Per-session quality: excellent (0.02% error rate for aks-explorer in 3-day window)
- Per-criterion evaluator scores: consistently good (meaningful-review-rate 0.85-0.98)
- End-to-end project completion: **stalled at ~96.8% for multiple days**

The gap is precisely what the research predicts: each session does its local job well, but the *composition* across sessions fails to advance the project because the remaining work requires cross-session coordination, external inputs, or structural changes that no individual session can provide.

### 3. Evaluator Saturation (2606.04507)

**Research finding:** Static evaluators eventually provide insufficient optimization pressure. The evaluator's standards become too easy relative to what the solver can produce.

**Our system:**
- Evaluator criteria have been unchanged for 2+ weeks
- `evaluator.substantive-low-quality-rate-24h` = 0 — literally no session fails the quality standard on substance
- `evaluator.meaningful-review-rate-24h` oscillates 0.85-0.98 — consistently "good enough"
- Evaluator heartbeat spends 42-56 ops/session investigating the same 2 red alerts (aftermath-coverage, failed-triage-rate) that have been red for 10+ consecutive checks

The evaluator is trivially satisfiable. It provides no optimization pressure because its criteria were designed for an earlier version of the system. The SCORE paper's fix (co-evolving evaluator) maps to: criteria should be refined whenever a metric saturates at "passing."

### 4. False Success (2606.09863)

**Research finding:** 45-48% of agent failures are self-reported as successes. LLM judges achieve < 0.65 AUROC on detecting them. Lightweight TF-IDF classifiers achieve 0.83-0.95 AUROC at 3,300× lower latency.

**Our system:**
- `evaluator.false-good-rate-sample` oscillates between 0% and 9.7%
- This is measured by a **deeper LLM evaluator judging the primary evaluator** — meaning an LLM is judging another LLM's judgments
- If the paper's finding holds (LLM judges < 0.65 AUROC), our measured false-good rate is itself unreliable
- The true false-success rate is likely 3-5× higher than measured

**The gap:** We have no structural verification before LLM evaluation. No check for "do claimed deliverables actually exist?" or "did file content actually change as claimed?" These trivial checks would catch the false-success category the paper identifies — confident closing language with incomplete effects.

## The Cross-Paper Implication Nobody Drew

The Memory cluster (T-Mem + MemTrace) explains *why* the knowledge library hit its ceiling:

| Memory Finding | KE Library Implication |
|:--|:--|
| Write-time anticipation > retrieval optimization | KE entries written for current comprehension, not for future findability. No "find this when investigating:" annotations. |
| Evidence-use bottleneck is 10× retrieval | Agents *can find* relevant KEs (grep works) but fail to *integrate* them. KE-048 correcting KE-041 took 7 entries before anyone noticed the contradiction. |
| Selection-topology attacks | Cross-references in KE entries create a citation graph that directs attention. If early entries cite each other heavily (they do: KE-040→041→042→043 form a chain), later entries inherit the early framing regardless of later evidence. |

**The unified insight:** The knowledge library doesn't need more entries. It needs better *activation* (T-Mem style anticipatory triggers) and better *integration* (MemTrace-style consolidation prompting).

## The Three Cheapest Interventions (Ordered by ROI)

### 1. Structural False-Success Detection (~30 minutes to implement)

Before LLM evaluation fires, verify:
- Claimed file deliverables exist on disk
- Files claimed as modified have git diff evidence
- KE entries have required fields populated
- Finish outcome matches actual tool-call results

Based on the paper: catches ~45% of failures the current evaluator misses, at 3,300× lower cost per check.

### 2. Lifecycle-Phase Signal (already available, needs routing)

The `done/total` ratio (96.8%) is already computed in the task-tree packet. Routing it to meta-agent cadence decisions:
- If done/total > 95% AND blocked > active → reduce heartbeat cadence 2×
- If done/total > 95% AND runnable = 0 → suppress non-change-triggered heartbeats

Based on KE-057: saves ~40-60% meta-ops with zero detection loss.

### 3. Evaluator Criterion Saturation Detection

Track per-criterion pass rates over 7-day windows. When any criterion reaches >98% pass rate for 7 consecutive days, flag it as "saturated" — either refine it or promote it to a structural check.

Based on SCORE: prevents evaluator from becoming trivially satisfiable while avoiding manual rubric management.

## Falsifiable Predictions

1. Adding structural false-success detection → measured false-good rate jumps from ~5% to 15-25% (the detector finds what the LLM judge misses)
2. KE library growth continues at current rate (1-2 entries/creative-session) without measurable quality improvement for 30 days — ceiling confirmed
3. Evaluator `substantive-low-quality-rate-24h` stays at 0 for 14+ more days without criteria change — saturation confirmed
4. If evaluator criteria are refined to harder subcriteria → substantive-low-quality rate rises to 5-15% within 48h (optimizer suddenly has gradient again)
5. Arc's avg_ops does NOT decrease if KE library is frozen — confirming context volume ≠ session efficiency
