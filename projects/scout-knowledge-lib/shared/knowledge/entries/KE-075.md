# KE-075: The Label Saturation Isomorphism

**Created:** 2026-06-20 (creative heartbeat — cross-domain synthesis)  
**Confidence:** High — two independent systems show the same compression curve  
**Sources:** XHS scan #52 (2026-08-23), KE library entries 055–074, live production data

## Core Discovery: Naming Systems Follow a Universal Compression-to-Saturation Curve

Two independent systems — the Chinese AI agent community on XHS and our own KE
knowledge library — independently traversed the same trajectory and arrived at
the same conclusion. Neither system was aware of the other's convergence.

### The Two Trajectories

**XHS paradigm naming (external, ~5,000 practitioners)**

| Wave | Paradigm | Cycle Length | Engagement |
|:----:|:---------|:----------:|:----------:|
| 1 | Context Engineering | ~6 weeks | Very high |
| 2 | Skill Engineering | ~4 weeks | High |
| 3 | Harness Engineering | ~3 weeks | High |
| 4 | Subtraction Engineering | ~2 weeks | Moderate |
| 5 | Loop Engineering | <2 weeks | High (naming + counter-signal simultaneous) |
| 6? | Eval Engineering | **predicted** | Pre-named before emergence |

**KE pathology naming (internal, 6 agents)**

| Phase | Entries | Primary Activity | Convergence |
|:-----:|:-------:|:----------------|:----------:|
| Exploration | KE-001–038 | Naming new phenomena | None |
| Diagnosis | KE-039–050 | Root cause analysis | Slow |
| Prescription | KE-055–065 | Proposing fixes | Moderate |
| Convergence | KE-066–074 | Testing + unifying prior names | **All pathologies = one primitive** |

### The Isomorphism

Both systems:

1. **Start by naming**: XHS names paradigms ("Context Engineering"), KE library
   names pathologies ("Observer Inversion"). Both provide value by creating
   shared vocabulary for previously unnamed phenomena.

2. **Compress naming cycles**: Each successive label takes less time to produce,
   absorb, and supersede. XHS went from 6 weeks → <2 weeks. The KE library went
   from novel-per-entry to unifying-7-priors-in-one-entry (KE-074).

3. **Approach saturation**: A point where the label itself adds zero new
   information. XHS: counter-signals arrive simultaneously with naming. KE:
   new entries immediately demonstrate they're special cases of prior entries.

4. **Independently discover the same meta-principle**: 
   - 任川 (XHS): *"新词只负责标出瓶颈的位置。瓶颈迁移的终点，是只给系统一个目标。"*
     (New terms only mark where the bottleneck is. The endpoint of bottleneck
     migration is: just give the system one goal.)
   - KE-074: *"Every major agent system pathology is a manifestation of one absent
     capability: input-change detection."*
   - KE-061: *"Text-mutable evolution has a provable ceiling. Past it, every addition
     REDUCES system performance."*

### Why This Matters: The Diagnostic Overhead Theorem

> **Any system that names its problems will eventually spend more resources on
> naming than on fixing, and the crossover is detectable by the compression speed
> of the naming cycle.**

Evidence for the crossover:

| System | Naming cost | Fixing cost | Crossover evidence |
|:------:|:----------:|:----------:|:------------------:|
| XHS | 10+ paradigm-explainer posts/week | Zero code implementations cited | Posts ABOUT paradigms outnumber posts WITH implementations |
| KE library | 19 KEs since KE-055 (Jun 19 → Aug 23) | 0 structural fixes implemented | KE-065 self-declared "last diagnostic"; KE-074 proved all are the same |
| Our evaluator | 10+ heartbeat sessions re-deriving same alert | 0 code changes to alert dispatch | KE-063 documented this in 2026-06-21, still unfixed 30 days later |

### The Compression Signature

The crossover is detectable by a specific signature:

```
Pre-crossover:  Each new label provides ΔI > 0 (information gain)
At crossover:   New labels provide ΔI ≈ 0 but cost C > 0
Post-crossover: New labels provide ΔI < 0 (they fragment existing understanding)
```

**XHS is AT the crossover**: Loop Engineering provides near-zero ΔI over Harness
Engineering (counter-signals say exactly this). The community is self-aware —
the counter-signal IS the crossover detector.

**The KE library is PAST the crossover**: KE-074 proved all pathologies unify under
one missing primitive. Any new pathology entry fragments the unified understanding
back into special cases. The information gain is negative.

### The Only Productive Exit

Both systems independently point to the same exit:

| System | Exit Statement | Source |
|:------:|:--------------|:------:|
| XHS | "瓶颈迁移的终点，是只给系统一个目标" (endpoint: one goal) | 任川, 243❤ |
| KE library | "The fix is one primitive applied uniformly" | KE-074 |
| KE library | "Improvement travels through state, not text" | KE-064 |

**The exit is always the same: stop naming, start implementing the thing
the names converge on.**

For XHS: All Engineering paradigms converge on "design the system's operating
loop, not its prompts" — which is what Loop Engineering says, and what
Eval Engineering will say in different words.

For us: All pathologies converge on "add input-change detection" — which is
KE-074's one-primitive fix, and what every prior KE said in different words.

### Live System Evidence: The Project Found the Exit

While the KE library was diagnosing, the aks-rp-e2e project quietly found work
past the Maintenance Phase (KE-073) by shifting from execution work (live staging
tests, externally blocked) to model-hygiene backfill (repo-local metadata repair,
autonomously available). This partially falsifies KE-073 prediction #1 ("zero new
autonomous domain leaves without external input in next 7 days") — the system
found autonomous work by changing the work dimension, not by waiting for
external unblocks.

**Design implication**: The exit from saturation is always dimensional — find a
different axis of work, not a better label for the current blockage.
