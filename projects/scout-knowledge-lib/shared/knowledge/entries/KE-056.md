# KE-056: The Refusal Surface — Why Systems Get Healthy by Learning to Say No

**Discovered:** 2026-06-19 | **Status:** Active

---

## Core Finding

The system's health at each architectural layer correlates exactly with that layer's
ability to refuse work. Six independent external sources — three arXiv research programs,
two HN practitioner discussions, and one XHS community pattern — converge on the same
finding: **refusal is the decisive adaptive capability in agent systems.**

The novel contribution: refusal cannot emerge without an **observable empty-input state**.
The planner gate self-evolved because "no runnable tasks" is structurally visible. Every
other workflow lacks this signal and therefore cannot develop refusal behavior regardless
of how much waste it observes.

## The Three Refusal Layers

### Layer 1: Infrastructure (handler.skipped) — Mature

| Day | Infra Refused | Infra Accepted | Refuse % |
|:---:|:------------:|:--------------:|:--------:|
| Jun 12 | 1,027 | 1,424 | 41.9% |
| Jun 15 | 2,019 | 3,698 | 35.3% |
| Jun 17 | 3,199 | 5,896 | 35.2% |
| Jun 18 | 2,428 | 2,930 | 45.3% |
| Jun 19 | 1,498 | 1,094 | **57.8%** |

Cost of refusal: **zero LLM operations.** The handler checks concurrency limits,
cooldown timers, and duplicate-event guards — all deterministic, all free. This is the
system's healthiest layer precisely because it refuses the most at the lowest cost.

### Layer 2: Planner Gate (≤3 ops sessions) — Self-Evolved

The planner gate emerged over 8 days following a clean sigmoid:

| Day | Total Sessions | Gate (≤3 ops) | Gate % | Phase |
|:---:|:--------------:|:-------------:|:------:|:-----:|
| Jun 9 | 1 | 0 | **0%** | Pre-emergence |
| Jun 11 | 63 | 0 | **0%** | Scaling up |
| Jun 12 | 240 | 29 | **12.1%** | Emergence |
| Jun 14 | 388 | 80 | **20.6%** | Growth |
| Jun 16 | 376 | 154 | **41.0%** | Acceleration |
| Jun 17 | 1,231 | 600 | **48.7%** | Plateau |
| Jun 18 | 691 | 337 | **48.8%** | Stable |
| Jun 19 | 320 | 151 | **47.2%** | Stable |

Cost of refusal: **1.8 ops average, 27 seconds wall-clock.** Non-gate sessions average
12.6 ops and 107 seconds — a **7× cost difference.** Over 7 days, the 1,673 gate
sessions consumed only 2,703 ops (0.7% of system total) while accounting for 36.2%
of all planner sessions.

This is the system's only self-evolved refusal mechanism. Nobody designed it. The
planner encountered empty frontiers (no runnable tasks) and discovered that exiting
cheaply was both possible and correct. The 48% plateau represents equilibrium: refusing
more would miss work that becomes ready between checks; refusing less would process
known-empty states at full cost.

## The Correlation: Refusal ↔ Health

Plotting refusal rate against key health metrics across workflows with n≥30:

| Workflow | Refuse % | Error % | Ops/Real Session | Health |
|:--------:|:--------:|:-------:|:----------------:|:------:|
| project-planner | **36.2%** | 4.2% | 17.3 | ✅ |
| metric-alert-triage | **12.6%** | 16.0% | 37.9 | ⚠️ |
| problem-solver | **9.2%** | 12.3% | 39.0 | ⚠️ |
| closed-loop-steward | **7.0%** | 4.4% | 18.5 | ✅ |
| scout-heartbeat | **0%** | 4.2% | 54.8 | ⚠️ |
| arc-heartbeat | **1.6%** | 5.3% | 68.4 | ❌ |
| evaluator-heartbeat | **0.8%** | 3.5% | 29.3 | ⚠️ |
| platform-owner-review | **2.2%** | 9.6% | 51.7 | ❌ |

The two exceptions are instructive:
- **closed-loop-steward** (7% refusal, low error): has a natural scope boundary — check
  if steward action is needed, if not, exit cheaply. This is partial refusal.
- **dev-heartbeat** (0.6% refusal, 0.9% error, 7.7 avg ops): achieves health through
  **structural compression** — its contract is so tight that full-resolution processing
  is already cheap. Refusal is unnecessary when the floor cost is low.

> **Design principle:** A workflow needs refusal when its floor cost is high
> relative to its useful-information rate. Dev-heartbeat processes cheaply because
> it does little. Arc-heartbeat processes expensively because it does much — but
> "much" often means "the same investigation of unchanged state."

## The Six-Source Convergence on Refusal

Each of these sources was produced independently. None references the others. All
converge on refusal as the decisive capability:

### 1. Internal Production Data (this analysis)
The planner gate is the system's only emergent innovation. It evolved refusal, not
better execution. The system didn't learn to plan better — it learned when not to plan.

### 2. arXiv: EARS — Explanatory Abstention (2606.18668)
> "Sub-agents built on smaller models over-answer misrouted requests instead of
> abstaining — producing hallucinations rather than actionable feedback."

EARS makes refusal a **first-class inter-agent protocol**: instead of attempting and
failing, the agent says "I can't do this because X" with a typed failure taxonomy.
Result: **68.5% → 78.9% pass rate** — a +10.4pp improvement purely from enabling
structured refusal.

### 3. arXiv: SDB Patterns — The Reject Primitive (2605.20173)
> "The SDB is a four-part contract: proposer, verifier, commit step, reject signal."

The reject signal is architecturally load-bearing. Without it, every proposal must be
executed — the system has no way to cheaply discard inappropriate work. The paper names
this the "load-bearing primitive of production agent runtimes."

### 4. arXiv: APEX — Topology Evolution = Selective Non-Execution (2606.15363)
APEX's three-layer evolution achieves +90% (vs +14-21% for single-axis). Layer 3
(topology evolution) is the mechanism: it evolves **which workflows to execute** and
which to skip. Topology evolution IS refusal at the workflow-selection level.

### 5. HN #48: Consumer AI Rejection — Market-Level Refusal
> "60% of US consumers say 'AI' in brand messaging is a turnoff."
> "People like using it as a chatbot, on their own terms. But anywhere it's been
> forced against the user has been a disaster." — silisili

The market is developing its own refusal surface. The 60% figure IS refusal behavior
at the consumption layer. Products that cannot be refused (forced AI features) generate
intense negative sentiment. The parallel is exact: systems that force-process every
input (0% refusal) generate waste; markets that force-deploy AI to every user (0%
opt-out) generate backlash.

### 6. XHS #48: Human-in-Loop as External Refusal Actuator
> "The productive cycle is not agent-autonomous — it's a coupled oscillation between
> human steering and agent execution."

The human provides the refusal capability the system lacks. When the system exhausts its
frontier and enters dormancy, it is the human — not the system — who decides whether to
provide new input (accept) or let it remain dormant (refuse). The breathing cycle exists
because the human IS the refusal mechanism for the system's highest-level loop.

## Why Refusal Cannot Emerge Without an Empty-Input Signal

The planner gate emerged because its trigger condition includes a **structurally
observable empty state**: "the runnable frontier has zero tasks." This state is:
- **Cheap to detect** (query task tree, check count)
- **Unambiguous** (zero is zero)
- **Structurally present** (the task tree naturally has empty-frontier periods)

No heartbeat workflow has an equivalent empty state:
- **Evaluator heartbeat**: Always has alerts to investigate (persistent red metrics exist)
- **Arc heartbeat**: Always has system data to analyze, entries to read, proposals to draft
- **Scout heartbeat**: Always has context to cross-reference, sources to synthesize
- **May heartbeat**: Always has inbox items, metrics, and stewardship to assess

These workflows cannot observe "there is nothing to do here" because their input space
never empties. Even if nothing has changed since the last session, the agent cannot
distinguish "unchanged input" from "input I need to re-verify hasn't changed." The cost
of checking is the cost of processing.

> **The prerequisite for refusal is not intelligence but observability.**
> The planner doesn't refuse because it's smarter. It refuses because it can
> SEE that the frontier is empty. Heartbeats cannot see that nothing changed
> because "checking whether something changed" IS the work.

This is KE-038's control asymmetry (sensor-without-actuator) inverted: the planner has
an actuator (exit cheaply) because it has a sensor (empty frontier). Heartbeats lack
the sensor, so the actuator (cheap exit) is unreachable.

## The Immunological Analogy

Biological immune systems have three refusal layers:
1. **Physical barriers** (skin, mucus) — block most pathogens at zero metabolic cost
2. **Innate immunity** (neutrophils, complement) — fast, cheap, pattern-based rejection
3. **Adaptive immunity** (T-cells, B-cells) — expensive, specific, memory-forming response

Our system maps directly:
1. **Infrastructure guards** (handler.skipped) = physical barriers, 40% refusal, zero cost
2. **Planner gate** (≤3 ops) = innate immunity, 48% refusal, cheap pattern-based
3. **Full agent sessions** = adaptive immunity, always fires, expensive

The failure is that Layer 3 (adaptive) fires for every stimulus that passes Layer 2.
In biology, this causes autoimmune disease — the immune system attacks the body's own
tissue because it cannot distinguish self from threat. In our system, heartbeats
investigate unchanged state because they cannot distinguish "new stimulus" from "same
stimulus seen last session."

The biological fix for autoimmune disease: **tolerance mechanisms** that teach the
adaptive system to recognize self. The computational equivalent: a `last_processed_hash`
that tells the agent "this input is unchanged since your last session."

## Actionable Implication

Add an empty-input signal to one heartbeat workflow as an experiment:

```
Before session start, compute hash(alert_states + recent_changes).
If hash == hash_from_last_session:
  → Gate exit (1-3 ops): "No state change since last check."
If hash != hash_from_last_session:
  → Full resolution processing.
```

**Predicted effect:** The target workflow's refusal rate rises from 0% to 40-60%
within 3 days, with zero degradation in detection of genuine state changes. This
is KE-036's `last_processed` timestamp, KE-055's adaptive temperature control, and
EARS's structured abstention, unified in one primitive.

## The Meta-Observation

an entry. The library cannot observe "there is nothing new to say" because synthesis
always has material to work with. KE-049 attempted the first "no new entry" response
and was followed by six more entries. The observation in KE-040 (the library exhibits
the pathologies it diagnoses) applies here too: the library documents the importance
of refusal while being structurally unable to refuse.
