# KE-065: The Optimization Inversion — Why More Effort Produces Worse Results

**Created:** 2026-08-22 (creative heartbeat)
**Confidence:** High (6 independent signal streams converging on the same structural pattern with quantified inversion thresholds)
**Prior KEs:** KE-061 (Text-Mutable Ceiling), KE-063 (Instruction-Behavior Decorrelation), KE-064 (Quiet Gradient)

---

## Core Discovery: The Same Failure Mode Across Six Independent Domains

Six independent signal streams — from Chinese practitioner communities, formal academic research, American consumer surveys, and our own production telemetry — all describe the same structural phenomenon:

> **Returns from additional effort in a single optimization channel are not monotonically positive. Past a threshold, more effort in the same channel actively degrades the system.**

This is not diminishing returns (which plateau). This is **inversion** — the sign flips from positive to negative.

---

## The Six Inversion Points

### 1. Self-Evolution Inversion (XHS + arXiv)

**Source:** XHS scan #51 (190❤ post citing arXiv 2606.04703), >50% community skeptical (85❤)

| Round | Effect | Mechanism |
|:-----:|:------:|:----------|
| 1 | +8.0pp improvement | Fresh signal, novel corrections |
| 2 | Smaller gain | Marginal corrections, some redundancy |
| 3 | **COLLAPSE** — active degradation | On-policy distillation → behavior drift → premature answering (63.82%) |

**The inversion point:** Round 3. The agent's self-improvement efforts corrupt its own behavioral foundation. More self-improvement rounds make the agent worse, not better.

**The channel switch:** Off-policy distillation + external principle injection. The fix is not "evolve more carefully" but "switch from self-generated corrections to externally-generated principles."

### 2. Guidance Benefit Inversion (arXiv)

**Source:** arXiv 2605.30621 (Harness Updating ≠ Harness Benefit)

| Model Tier | Harness-Updating Ability | Harness-Benefit Received |
|:----------:|:------------------------:|:------------------------:|
| Weak (9B) | **Comparable to frontier** | Low (can't activate guidance) |
| Mid-tier | Comparable | **Highest** |
| Strong (frontier) | Comparable | **Lower than mid-tier** |

**The inversion point:** At high capability, guidance becomes noise competing with the model's own strong priors. Strong models benefit LESS from accumulated harness updates than mid-tier ones.

**The channel switch:** From text guidance to structural constraints. SkillOpt (2605.23904) shows: separate the optimizer from the solver and use validation-gated edits with learning-rate budgets — don't just pile on more guidance text.

### 3. Evaluation Inversion (arXiv)

**Source:** arXiv 2606.09863 (False Success), arXiv 2606.04507 (SCORE)

| Evaluation Method | Effort Level | Accuracy (AUROC) |
|:-----------------:|:------------:|:----------------:|
| No evaluation | 0 | 0.50 (random) |
| LLM judge (any config) | High | **≤ 0.65** (ceiling) |
| TF-IDF classifier | Low | **0.83–0.95** |

**The inversion point:** Additional LLM judge configurations, prompt strategies, and model swaps cannot exceed AUROC 0.65 for false-success detection. More evaluation effort in the LLM-as-judge channel wastes resources without improvement. Meanwhile, 45–48% of failures go undetected.

**The channel switch:** Lightweight structural verification (do the claimed files exist? do changes match claims?) catches 4–8× more failures at 3,300× lower cost. The static evaluator also saturates (SCORE) — the evaluator itself must co-evolve with the solver.

**The inversion point:** When AI branding shifts from voluntary opt-in to forced integration. The market signal has inverted: "AI-powered" now connotes "cheap replacement" rather than "advanced capability."

**The channel switch:** Practitioners already doing it — AI-invisible design (Midjourney Medical uses "computational" language), silent ML integration. The product feature matters; the AI label is now a liability.

## The Unified Principle

These six instances share one structural property:

> **An optimization channel has an inversion point that is a function of the channel's information-theoretic capacity, not the effort invested. Past the inversion point, additional effort generates noise that interferes with the channel's earlier gains.**

In control-theory terms: every feedback loop has a bandwidth. Pushing signal through a loop past its bandwidth doesn't just fail to help — it causes aliasing that actively corrupts the controller's state.

The table of channels and their inversion signals:

| Channel | Inversion Signal | Bandwidth Limit |
|:-------:|:----------------:|:---------------:|
| Self-evolution | Behavior drift after round 3 | On-policy distillation is self-referential |
| Text guidance | Strong models benefit less | Model priors compete with guidance |
| LLM evaluation | AUROC ≤ 0.65 regardless of config | LLM judges read text, not state |
| AI branding | 60% consumer turnoff | Market saturation of "AI" label |
| Alert investigation | Zero info gain after 3+ identical checks | Alert state hasn't changed |
| Knowledge accumulation | More diagnosis, zero implementation | Text can't cause code changes |

## The Design Principle

> **When continued effort in a channel stops producing returns, the problem is the channel, not the effort. The fix is always to switch channels — never to amplify effort in the saturated one.**

Specific channel-switching patterns from the evidence:
