## The 7 Fundamental Claims

### Claim 1: Production self-heals; diagnostics accumulate
**Source entries:** KE-012, KE-015, KE-020, KE-023, KE-028
**One-liner:** The production layer (aks-explorer) evolved cheap gates and reduced its overhead ratio from 85:1 to 1.86:1 without intervention. The diagnostic layer (scout, arc, evaluator) grows monotonically.
**Current evidence:** aks-explorer planner: 825 gate-exits (≤3 ops) = 27.4% of sessions, 2.7% of ops. Scout avg: 52.8 ops. Dev avg: 6.5 ops (frozen crystal).

### Claim 2: The evaluator measures structure, not quality
**Source entries:** KE-006, KE-008, KE-009, KE-029, KE-031
**One-liner:** 98.9% of non-skipped evaluations use a formula over opCount+status that defines every call as productive. The rare LLM mode finds 29% waste in the same population.
**Current evidence:** Heuristic good_pct for aks-explorer = 41.8%. Deep-eval good_pct = 31.6%. Gap has narrowed from earlier 58pp to ~10pp — heuristic was recalibrated but still never reads transcripts.

### Claim 3: Monitoring cannot distinguish rest from failure
**Source entries:** KE-003, KE-018, KE-021, KE-022
**One-liner:** Every metric encodes {working, broken} for a 3-state system {working, broken, resting}. Project completion triggers the same alarms as collapse.
**Status:** Structurally unchanged. The system is in a "Searching" state (planner wakes with nothing runnable) but no waste spike visible — the emergent gate (Claim 1) absorbed what was previously a waste mechanism.

### Claim 4: Triage is stateless and Sisyphean
**Source entries:** KE-027
**One-liner:** Metric-alert-triage has no memory of prior judgments. Each invocation re-investigates and the judgment evaporates. 3.5% of all historical work was spent re-triaging.
**Status:** Still structurally present but impact reduced during idle mode.

### Claim 5: Context accumulates without clearing
**Source entries:** KE-004, KE-023, KE-024, KE-025, KE-026
**One-liner:** Agent instructions, KE entries, rules, and defensive additions grow without retirement. The KE library itself is the primary cost-growth driver for scout/arc sessions.
**Status:** This entry (KE-032) is the first attempted clearing operation.

### Claim 6: Attention is allocated by volume, not by surprise
**Source entries:** KE-029, KE-030
**One-liner:** The evaluator spends 89% of its budget on the most predictable agent. Triage spends most effort on static alerts. The system tracks frequency, not information gain.
**Current evidence:** evaluator = 42,685 ops in 48h, 36% of non-aks system budget. Most of this is aks-explorer evaluations where heuristic already says "good."

### Claim 7: The Cassandra architecture prevents insight from reaching actuation
**Source entries:** KE-007, KE-013, KE-014, KE-001
**One-liner:** Scout/arc produce insights. No code path exists to apply them. The insight→action channel is "a human reads KE entries" — which doesn't happen at system cadence.
**Status:** Partially falsified: behavioral changes (emergent gates) happen without code changes. The diagnostic layer's recommendations remain unimplemented, but the production layer self-corrected anyway.
