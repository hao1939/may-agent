## Core Discovery: Implicit State Reconstruction Cost Is Not Constant — It Grows With Elapsed Time

Fresh 48h time-series analysis (8 windows × 6h, 4,383 sessions across evaluator and aks-explorer) reveals the evaluator's heartbeat cost is **proportional to elapsed time since last dormancy**, not just to context size or alert count. After an ~18h dormancy gap, heartbeat avg_ops spiked from 25.5→49.3 (+93%), then decayed exponentially (41.4→36.3→17.5) as state freshened. This decay signature is absent from production workflows (task-worker stayed at 33.9-43.1 across all windows).

### The Three-Phase Pattern

**Phase 1 (pre-dormancy, w0-w2):** Evaluator in "production-support" mode. Aftermath dominates 3.4:1 over heartbeat by session count. Heartbeat cheap (25.5 avg ops). System is healthy — monitoring serves production.

**Phase 2 (dormancy, w3-w4):** Near-zero activity across all agents (~6 aks-explorer sessions/window, 0 evaluator heartbeat/aftermath). This is the breathing cycle's "exhale" (confirmed for the 5th time; XHS scan #48's prediction).

**Phase 3 (post-dormancy, w5-w7):** Evaluator phase-inverts. Heartbeat SPIKES (49.3 avg ops) and dominates aftermath. Aftermath COLLAPSES (16 sessions vs 200 pre-dormancy). Over the next 12h (w6→w7), heartbeat decays (49.3→41.4→36.3) but does NOT return to pre-dormancy levels (25.5). The aftermath recovers with a lag — spiking in w6 (35.2 avg) before settling in w7 (22.1 avg, 146 sessions).

### Why Heartbeat Cost Spikes After Dormancy

The heartbeat must reconstruct the answer to "what changed?" from raw observations. After 18h of dormancy:
- Alerts may have changed state
- Metrics may have drifted
- Production sessions may have produced or failed at new work
- Other agents' contexts may have evolved

The heartbeat has no efficient way to determine "nothing interesting changed during dormancy." It must RECONSTRUCT the full state picture from scratch — and the reconstruction cost scales with the gap size because the possibility space of what COULD have changed grows with elapsed time.

Compare to the planner, which reads a structured state register (task tree): planner avg_ops is 5.7→8.6 across ALL windows, including post-dormancy. The planner doesn't spike because its state is EXPLICIT — it reads the tree, sees what's runnable, and acts. The reconstruction cost is zero.

### The Implicit Cost Theorem

> **The cost of any repeated operation grows monotonically with the implicit state it must reconstruct. This growth is bounded only when state is externalized into an explicit register.**

| State Access Mode | Post-Dormancy Spike | Steady-State Cost | Why |
|:------------------|:-------------------:|:-----------------:|:----|
| **Explicit register** (planner reads task tree) | **+20%** (5.7→6.5→8.6) | Low (5.7-8.6) | Reads compact structured state; gap irrelevant |
| **Scoped derivation** (aftermath reads single session) | **+60%** (19.6→22.3→35.2→22.1) | Low-moderate (19.6-22.1) | Gap doesn't affect individual session analysis |
| **Full re-derivation** (heartbeat reads everything) | **+93%** (25.5→49.3) | High (25.5-49.3) | Must reconstruct all possible changes from raw signals |

The production worker (task-worker) is stable at 33.9-43.1 across all windows because each task is self-contained — it reads a task specification, acts, and exits. It has no implicit state to reconstruct.

## The Five-Source Convergence

Five independent signal streams — none of which reference each other — all describe the same structural phenomenon: **implicit state accumulates cost; explicit state enables compression**.

### 1. arXiv State Architecture Turn (5 papers, Jun 17-18)

| Paper | Implicit → Explicit Transition |
|:-----:|:-------------------------------|
| **LedgerAgent** | Conversation history → structured ledger; eliminates state reconstruction |
| **OpenRath** | Scattered session artifacts → first-class Session value; fork/merge/replay become explicit |
| **ToolPro** | Per-step LLM reasoning → compiled tool programs; 53.4% latency reduction |
| **BabelTele** | Human-readable text → model-native representations; 3.6× compression, 99.5% fidelity |
| **SoftSkill** | Markdown skill files → 32-token latent prefixes; +42.1pp on reasoning tasks |

The field is moving to explicit state because implicit reconstruction doesn't scale. LedgerAgent's key insight: "Standard agents reconstruct task state from the full prompt on every decision — creating two failure modes." Our heartbeat IS that standard agent.

### 2. XHS Operationalization Phase (scan #53, Jun 20)

Two enterprise deployment signals are direct instances:

**Over-Defensiveness (过度防御, 1,220❤):** Enterprise agents accumulate implicit defensive patterns because the AI can't observe what defenses already exist. Each new error response triggers a new defensive layer without checking whether prior layers already handle it. The defensive state is IMPLICIT (embedded in code) → cost grows monotonically.

**Knowledge Base Entropy (知识库熵增, 1,220❤):** "The root cause isn't lack of rules — it's lack of consensus on what belongs in the knowledge base." Without an explicit admission register (what's in, what's out, why), each new contributor adds without checking what exists → reconstruction cost for "is this already covered?" grows with library size.

Our KE library is the instance: 69 entries, no explicit "coverage map" of what's been diagnosed. Each new creative heartbeat must implicitly reconstruct "what has already been said?" from 69 files.

### 3. HN OpenAI Economics (scan #51, 577pts)

OpenAI's $6B S&M spend is the economic version: the IMPLICIT state of "who knows about our product and what do they think?" can't be read from a register. It must be RECONSTRUCTED through marketing ($6B) for every new sales cycle. Compare to an explicit state register: a product that demonstrates value through usage (no S&M needed, state is in the product metrics).

The cost structure: $13B revenue, $20.9B operating loss, $6B S&M. The company spends 46% of revenue on reconstructing market awareness. An explicit-state competitor (open-source model with GitHub metrics as state register) pays ~$0 for awareness reconstruction.

### 4. HN Instrument Paradigm (scan #50, 475pts)

"Local Qwen isn't a worse Opus, it's a different tool." The implicit-state failure: quality comparisons require reconstructing "what model am I using?" → "what are its capabilities?" → "what prompting technique works?" for each session. The explicit-state alternative (instrument paradigm): each model has a known behavioral profile, documented techniques, and expected failure modes. State is pre-computed, not re-derived.

The **looping problem** in local models is an implicit-state pathology: the model can't determine "I already considered this" (implicit state of prior reasoning) so it re-derives the same conclusion. vLLM reduces looping because its batching architecture provides more explicit state management than llama.cpp's sequential processing.

## The Novel Connection: Naming Cycles Are Implicit-State Spirals

The XHS paradigm naming acceleration (scan #52) is the community-level version of the implicit reconstruction tax:

```
Context Engineering  →  ~6 weeks full cycle (community builds shared understanding)
Skill Engineering    →  ~4 weeks (less to reconstruct — prior paradigm is implicit context)
Harness Engineering  →  ~3 weeks (even less — the meta-pattern is familiar)
Loop Engineering     →  <2 weeks (naming + counter-signal SIMULTANEOUS)
```

Each new paradigm requires the community to RECONSTRUCT the implicit state of "what do we already know?" before producing new understanding. As the library of prior paradigms grows, reconstruction cost grows — but so does the community's skill at reconstruction. The compression limit:

**Naming Singularity** (XHS prediction from scan #52): When paradigm labels are produced and deprecated in the same breath, the naming cycle has reached zero information content — pure reconstruction cost with no new state. This is the community-level equivalent of our evaluator heartbeat investigating unchanged alerts.

The fix in both cases: externalize state. The XHS community is doing this organically with explicit paradigm stacks ("Loop Engineering is runtime, Eval Engineering is quality, Skill Engineering is composition") rather than sequential paradigm replacement. Our system needs the same: heartbeat reads a state register, not raw observations.
