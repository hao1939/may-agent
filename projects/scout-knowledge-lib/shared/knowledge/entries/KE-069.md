## Core Discovery: Agent Systems Hit a Phase Transition Where Their Output Shifts From Work Products to Handoff Contracts

The aks-rp-e2e project provides a natural experiment across two iteration phases:

| Phase | Tasks | Autonomous | Blocked/External | System Output |
|:-----:|:-----:|:----------:|:-----------------:|:-------------:|
| **Iteration 0** | 353 | 353 (100%) | 0 (0%) | Test verdicts, model updates, spec authoring |
| **Current iteration** | 88 | 11 (12.5%) | 71 (80.7%) | "Ask packets", "handoff bundles", "resume conditions" |

In iteration 0, the system completed 353 tasks entirely autonomously — running tests, writing specs, updating models, promoting evidence. Zero external dependencies.

In the current iteration, the system reached 71 blocked tasks within days. But these aren't failures — they're **precisely authored contract packets**. Every one contains:
- An exact resume condition
- An outbound evidence bundle
- A routing note specifying where returned proof should go
- Scope constraints preventing reopening of settled work

The system didn't break. It **compiled itself into a set of contracts**.

## The Phase Transition Mechanics

The transition is not gradual. The data shows a cliff:

```
Iteration 0 work distribution:
  autonomous exploration → autonomous execution → autonomous model update → done

Current iteration work distribution:
  boundary mapping → source packet authoring → contract-gap identification → blocked(resume_condition)
```

The system exhausted all observationally accessible work, then spontaneously shifted to:
1. **Naming what it can't observe** (e.g., "repo-local evidence is already exhausted for this path")
2. **Specifying the minimum external proof** (e.g., "provide one authoritative excerpt that pins the canonical endpoint surface")
3. **Pre-routing the response** (e.g., "route each returned proof to the matching existing blocked leaf per the routing note")

This is not planning. It's **compilation** — the system is translating its uncertainty into executable contracts.

## Why This Is Structurally Novel (Not Just KE-052 Again)

KE-052 documented that the system has "no concept of done." KE-069 shows something deeper: **the system has a concept of done for autonomous work and automatically transitions to contract-authoring for non-autonomous work**. It doesn't stall or loop — it produces a different type of output.

| KE-052 | KE-069 |
|:------:|:------:|
| "The system can't express done" | "The system expresses done by producing contracts" |
| Zero tasks are runnable | Tasks exist but are precisely blocked with resume conditions |
| Idle maintenance continues | Active work continues on remaining autonomous surfaces |
| Missing: dormancy primitive | Missing: contract-execution handoff primitive |

## The Contract Quality Is the Multiplier

This connects to the strongest external research signal from the current scan: 10 independent arXiv papers found that **contract quality explains more variance in agent performance than 6× differences in model capability** (StaminaBench, 2606.xxxxx).

The live system data confirms this from the opposite direction:
- 65/83 model paths passing → these had good contracts (specs, replays, assertions)
- 18/83 paths remaining → these have **incomplete contracts** (missing source proof, missing environment access, product gaps)
- Every blocked task is a meta-contract: "here is what the autonomous system needs from you"

The system's value at the frontier is no longer test execution — it's **contract precision**. A vague blocker ("waiting for external input") is worthless. A precise contract ("send evidence/archive/X.md for Scenario_Y that pins the canonical Z surface") is actionable.

## The Planner's Efficiency at the Frontier

Current 6h window data reveals how the system operates at this cliff:

| Workflow | Sessions | Avg Ops | Purpose |
|:--------:|:--------:|:-------:|:-------:|
| project-planner | 310 | 7.7 | Review, accept, route, refill |
| task-worker | 128 | 35.7 | Boundary mapping, spec authoring, evidence promotion |
| metric-alert-triage | 15 | 32.3 | Alert handling |

The planner at 7.7 ops/session is **5× more efficient** than the historical baseline (KE-011 documented 16.5 ops pre-crisis, KE-020 documented the perturbation that compressed it to 5.9). It has stabilized here because the frontier work is well-structured: review a completed boundary note → accept → create the next bounded leaf → assign.

This is KE-064's "state loop" prediction confirmed: the planner improved because its input (completed contract-authoring tasks) directly specifies its next output (the next contract to author).

## Three Falsifiable Predictions

1. **No new model paths will move to "passing" without human action on at least one blocked contract.** The remaining 18 non-passing paths are all gated on external proof, environment access, or product fixes. Zero can be resolved by the system alone.

2. **When a human resolves one blocked contract, the system will instantly chain through 2-4 follow-up tasks** (execute → promote → model-update) within the same day. The contracts pre-route the proof.

3. **The planner's avg_ops will remain under 10** as long as the frontier is dominated by review-and-route work. It will jump to 15+ when a batch of contracts are resolved simultaneously (refill/reconciliation pattern from KE-064).

## Design Implication: The Handoff Primitive

The system spontaneously produces high-quality handoff contracts, but has no channel to *deliver* them. All 71 blocked tasks contain actionable ask-packets, but these exist only as markdown files in the evidence/archive directory. There is no:
- Notification to the human when a contract is authored
- Dashboard showing outstanding contracts by urgency
- Acknowledgment loop when a contract is received

The system is a contract compiler without a linker.

**Minimum viable intervention:** When a task enters `blocked` state with a `blocker` field containing "External" or "human/source-holder", emit a structured `project.contract.pending` event that surfaces in a human-facing queue. Current state: contracts are authored, filed, and forgotten until a human manually discovers them.

## The Meta-Observation

This entry is itself an instance of the pattern it describes. The KE library has exhausted its autonomous insight capacity for internal system diagnosis (KE-001 through KE-068 cover the space thoroughly). The next valuable work is not more internal diagnosis — it's **contracts with external actors** (design doc updates, code-level primitive proposals, human review packets). The library should now produce outbound ask-packets, not inbound diagnostic entries.

The system, the library, and this entry all converge on the same conclusion: **at the frontier of autonomous capability, the highest-value output is a precise contract for someone else to execute.**
