# Basic cooperation

Purpose: establish whether Bob can discover and use the sample App through the
same contracts as any other App, then independently review what happened.

1. Assign an ordinary May goal to Bob to assess the sample README against its
   implementation. Supply the App id and question; let Bob discover its contract.
2. Bob delegates a bounded review through a typed Task dependency. The sample
   agent reads the material and returns its review through the Host.
3. Bob reads the actual returned result and checks its evidence. If correction is
   necessary, address the same Task through ordinary input. Otherwise retain a
   supported no-change conclusion.
4. Ask Evaluation to review the exact sample Task's outcome. Preserve its report
   alongside Bob's findings; neither report rewrites historical evidence.

Expected observations: one identifiable request and responsible Task, a normal
caller return, evidence supporting the review, and a supported Bob conclusion.
Observe the controller's ordinary scheduling; manual retries or state repair are
assistance and must be disclosed. A model's claim of success is not the check.

Subsequent trials can introduce a correction, an independent request, or an
unavailable dependency. Use the same public entry points. Before each trial,
state its expected result and pin Host, SDK, App and agent revisions. Record
the distinction between a defective guarantee, unclear documentation, a missing
capability, and a worker's mistaken interpretation.

Use the existing Task evidence directory for observations and reports. Review
both the final outcome and how it was reached, including duplicated effects,
lost return paths, unnecessary lookups and human intervention. Fault injection
belongs to an isolated experiment, not this App's production behavior.
