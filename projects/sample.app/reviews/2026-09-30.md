## Lessons and owning corrections

- **Check the consumer contract.** Correct hashes did not make relative paths
  consumable. Reviewer guidance now asks for absolute, hash-verified references
  to preserved bytes. The shared manual records the requirement and existing
  reader; the App owns producing usable evidence.
- **Name the reference root accurately.** The original instruction described a
  repository-relative README path as workspace-relative. The reviewer recovered
  from the failed lookup. Guidance now names the App root and distinguishes it
  from the execution directory and repository root.
- **Separate acceptance, return and judgment.** A local finish did not prove a
  stale proposal was admitted. Existing retained state let Bob check the exact
  Task and recover without database repair or manual scheduling.
- **Keep the tool's limits discoverable.** Cross-App `contract` and exact `get`
  worked; `list` was current-App-only. This is a follow-up wording candidate for
  the tool description, not evidence that its permission boundary needs changing.
- **Verify adoption.** An assisted correction establishes that the repair path
  works. A fresh execution is needed to check whether clearer instructions avoid
  the same failure. A saved lesson alone does not establish that behavior changed.

The general method lives in the common manual and is linked from Bob's
instructions. App-specific usage and this example stay here. Reuse the review
when a similar signal appears or after a relevant change; it adds no periodic
job, review registry or acceptance gate.
