# KE-031: Retry Storm Patterns in Distributed Cache

**Type**: Knowledge Entry
**Created**: 2026-03-20
**Sources**: EXP-119, EXP-121, incident-2026-03-18
**Status**: Active

## Key Findings

When cache nodes become unresponsive, retry storms can amplify latency by 10-40x.
The cache-first architecture (see KE-023) is particularly vulnerable because every
read operation hits the cache layer first — if the cache is down, ALL reads retry.

EXP-119 showed that exponential backoff with jitter reduces retry storm impact by 85%.
EXP-121 confirmed this holds under production-like conditions.

**Relationship to H-042**: If cache-first reduces response times (H-042), retry storms
during cache failures could negate those gains. This is a key risk factor for the
cache-first approach. See also KE-023 for architecture details and H-045 for 
parallel write implications.
