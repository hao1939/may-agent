# Improvement-loop rollout, September 18, 2026

The stage composition is installed: Host `e0e0b846` and App source `425c6c7791`,
with matching binary, SDK, UI and Console. May, Scout, Evaluation and Gym load
successfully. Evaluation's daily review is enabled. Legacy Gym campaigns,

This installs preparation and comparison capabilities. It does not approve any
generated improvement. The exact-packet operator application command verifies
approval and fast-forwards source; deployment remains a separate authorized
operator action. An agent's report or broad shell access is not authentication
of human approval. See the [stage design](evaluation-improvement-loop.md) and
[operator application contract](operator-application.md).

## What was observed

- May independently implemented the App changes in an isolated checkout. Review
  feedback led to further commits, all integrated locally. She resumed the same
  Task after an attempt timeout and retained her work. Her accepted result
  correctly distinguished candidate delivery from reviewer integration and
  deployment.
- A fresh Evaluation review published a real immutable report about that Task.
  May received it automatically, selected the integrity/current-evidence intake,
  and judged the finding recovered/no-op after reading newer reviewer evidence.
  A valid report did not cause an unnecessary improvement candidate.
- That first live run needed two corrections: May initially omitted workflow
  input, then submitted a follow-up without a Topic. Both errors were returned
  and she recovered. She also created an unnecessary Task just to record the
  no-op. The installed guidance now says the current accepted result already
  retains that disposition; new work needs an independently owned outcome.
- A later operator replay mistakenly supplied absolute report paths where the
  publication contract requires the original relative paths. The intake rejected
  it. May independently verified the retained bytes, distinguished this input
  error from an implementation defect, and retained the disposition in the
  current Conversation result without another recording Task. The original
  request and the subsequent path correction are retained separately. The
  corrected replay passed integrity/current-evidence checks; May fulfilled the
  original request and retained recovered/no-op in that same Conversation result.
- The first live Gym request could not attach because its handler named an old
  parent Task. The handler now reads the root from the actual seed. A regression
  admits both ordinary input forms through the production Host and real seed.
  After deployment, the original retained request admitted without resubmission.
  Gym selected `compare-candidate` and passed the exact frozen input once. The
  workflow refused the invalid baseline before launching candidate trials; Gym
  retained that refusal as successful completion of the eligibility review.
  The saved workflow record confirms the installed source, input and rejection.
- A real-model, four-case isolated baseline and unchanged candidate both passed
  the smoke cases. The actual Gym adapter/CLI returned `hold`: unchanged behavior
  and draft truth cannot demonstrate improvement. This used an isolated granted
  project and fixture Task context, so it is not live agent workflow-selection
  proof.
- Real Git tests cover exact operator approval/application and changed or missing
  prerequisites. No generated behavioral candidate was approved or applied in
  these trials.

## Checks and retained failures

The final Host passes its quality checks and full suite: 3,121 pass, 3 explicit
installation-dependent skips, zero failures. App checks pass: May 65 pass and
one skip, Evaluation 125 pass, Gym 11 pass. The common design check passes.
Exact report lookup after more than 100 newer reports, frozen comparison scope,
process-group cancellation, and application against real Git are covered.

trials. Repeating with the installed benchmark removed that setup omission but
still yielded two invalid semantic-judge results and two machine failures. Some
failure checks depend on literal wording or an older delegation contract. These
results require scorer/benchmark review before attributing a behavior defect or
claiming improvement; they were not relabeled as passes.

The first activation hit UI ownership and historical Gym receipt compatibility
problems. Restoration/rollback kept the prior service available. A reviewed
operator cutover used existing migration and cancellation APIs, preserving
history. Later normal Host recovery settled 13 equivalent legacy admission
aliases. One conflicting historical input remains visible and does not block new

## What to refine next

Keep each stage independently testable. Prioritize a small trustworthy behavioral
benchmark with incident, paraphrase, opposite and transfer cases before increasing
autonomous comparison volume. Review no-op handling for duplicate work and human
noise, and inspect exact report/candidate/receipt links before asking for approval.
May repeatedly omitted intake input on the first call and recovered after the
error. Improve workflow input discoverability before adding another runtime rule;
this is avoidable interaction cost, not evidence of a failed final disposition.
The successful control and routing trials establish useful mechanics; a beneficial
end-to-end behavioral improvement remains to be demonstrated.
