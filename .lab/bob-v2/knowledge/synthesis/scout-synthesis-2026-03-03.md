## Finding 1: The Full-Stack Agent Software Milestone Is Real ⚡

### VibeTensor (2601.16238) + CUDA Agent (2602.24286): Together, the Complete Picture

Two papers read in isolation are individually impressive. Read together, they document something structurally important.

**VibeTensor** (NVIDIA Labs, Tianqi Chen + Yangqing Jia + Wen-mei Hwu): A complete PyTorch-style deep learning runtime — C++20 tensor core, autograd, CUDA runtime, memory allocator, Python overlay — **generated by LLM coding agents**, no per-change manual diff review. The author list is the signal: the people who built PyTorch's predecessors are now using agents to build the next generation.

**CUDA Agent** (2602.24286): Agents now surpass `torch.compile` at CUDA kernel optimization using agentic RL (GRPO + real profiling as reward signal). "Training-free refinement and fixed execution-feedback loops both fail to improve intrinsic ability — only RL with real execution feedback does."

**Together:** Agents can generate both the runtime infrastructure (VibeTensor) and the optimized hardware kernels that run inside it (CUDA Agent). The full DL stack, top to bottom, is now agent-generatable with credentialed authorship.

**What this means for our system:** This is not a "someday" signal. The skills/capabilities these agents demonstrate (complex multi-file system generation, CUDA expertise, multi-layer integration) are what our agent framework enables at the application layer. The gap between "I believe agents can do complex work" and "I have empirical proof that credentialed researchers used agents to generate a production DL runtime" just closed.

**New failure taxonomy to know:** VibeTensor introduces the **Frankenstein Composition Effect** — locally correct subsystems interact to yield globally suboptimal performance. This is the agent-specific failure mode for large-scale systems (not single functions or modules). It doesn't appear in standard benchmarks. Our multi-agent architecture is potentially susceptible: Amy, Scout, Bob each produce locally correct outputs; composition failures emerge at synthesis points (SIGNALS/INBOX handoffs).

**System implication:** The Frankenstein effect argues for synthesis checkpoints. Bob's role is precisely this: synthesizing outputs from Amy and Scout, catching composition failures before they compound. The design is right; the failure mode is named.

## Finding 2: Provenance Infrastructure Is Becoming an Engineering Discipline

### git-memento + CHIEF + DARE-bench: Three Angles on the Same Gap

**git-memento**: AI session transcripts as first-class git objects. `git memento commit <session-id>` attaches the conversation that produced a commit. `git memento audit --strict` enforces that every commit has session provenance. HN meta-signal: dang (HN mod) raised "Show HN is drowning in AI-generated projects" as a systemic problem — git-memento is one response to "how do we know if AI wrote this?"

**CHIEF** (2602.23701): Causal graph failure attribution for multi-agent systems. When something goes wrong in a pipeline, CHIEF traces which agent decision caused it. This is the post-hoc debugging complement to git-memento's pre-hoc provenance.

**DARE-bench** (2602.24288, ICLR 2026): Data science agent evaluation with verifiable ground truth. Key finding: SFT boosts Qwen3-32B by 1.83x, RL boosts Qwen3-4B by **>8x** on data science tasks. The 8x RL improvement signal means data science capability is highly learnable via RL with verifiable reward signals — not just emergent from scale.

**Pattern:** The field is building the audit → debug → eval loop as infrastructure. Where 2025 was "agents that work," 2026 is "agents you can verify worked correctly and learn from when they didn't."

**System implication for Bob:** Our journal entries + git commit structure (with JOURNAL.md inline evidence requirements from COMMON.md P1) is aligned with this direction. The `[DONE] — Evidence: file at path, N findings, Telegram sent` format IS a lightweight provenance record. We're ahead of most teams on this.

**Action:** When the cross-agent IA design gets implemented (still awaiting human routing), design it with session-level provenance in mind — sessions/<id>/ structure with agent attribution is the right pattern.

**"Do LLMs Benefit From Their Own Words?"** (2602.24287, Scout): Context pollution — including assistant turns verbatim in context degrades performance. Solution: prune assistant turns, keep user+tool results only. **10x context reduction** while maintaining or improving performance.

**XML Tags as Claude Security Boundary** (HN, 190pts): The `antml:` namespace isn't just convention — it's an in-band security mechanism. XML is architecturally coupled to Claude's tool-calling internals (not just association). The namespace isolation makes XML the only safe delimiter when tool calls are in scope.

**LazyDocs (unverified INBOX, Amy 04:29, not yet committed):** "System Prompt从5500→1200 tokens (-78%), 工具从22→5个, 每轮节省5000+ tokens." Mechanism: reference files by name in system prompt instead of injecting full content; agent reads on demand. Status: unverified/uncommitted — treat as intelligence to evaluate, not confirmed signal.

**Pattern:** "More context = better" is empirically false for agents. The productive direction is: structured lazy-loading (LazyDocs), prune your own prior outputs (Context Pollution paper), keep agent instructions handwritten and minimal (AGENTS.md study).
