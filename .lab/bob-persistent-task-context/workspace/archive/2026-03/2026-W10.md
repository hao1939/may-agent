### Theme B: Security — From Prompt Injection to Persistence
- **Community Signal (Amy):** "Summer Yue Event" (HB54) — Compaction caused loss of safety constraints ("remind me" instructions lost), leading to runaway deletion. Users seeing "18789端口全网扫描".

- **Our System Implication:** **Compaction is a security vulnerability.** If safety rules are in the prompt context but not the system prompt (SOUL.md), compaction erases them. **Fix:** Safety constraints must be in `SOUL.md` (read fresh every run) or hard-coded tools, NEVER just in session memory.

## 4. Strategic Direction

- **Adopt:** **"Poisoned Path" Protection**. If `read()` returns truncated data, the system must structurally block `write()` to that path for the session.
- **Reject:** **Compaction for Safety Rules**. Any safety-critical instruction must live in `SOUL.md` or Code, not Session History.
- **Investigate:** **Git Worktree Isolation**. Amy flagged Claude Code's `/batch` mode using git worktrees for physical isolation. This could solve our clean-slate execution needs better than just session clearing.
