## Summary

Analysis of `nanocode` (github.com/1rgs/nanocode) — a minimal Agent implementation in a single Python file, <300 lines, zero dependencies.

## Key Points

### Minimal Agent Components

1. **Model Routing** — Environment variables control API path/model name
   - OPENROUTER_API_KEY → OpenRouter; else → Anthropic
   - MODEL env var overrides default
   - Light, fast, portable (weak on multi-env governance, fine for MVP)

2. **Tool Execution Surface** — Only 6 actions: `read/write/edit/glob/grep/bash`
   - Sufficient for code tasks: read context, find locations, modify files, validate
   - Nice detail: `edit` defaults to single replacement; errors if multiple matches without explicit `all=true`

3. **Tool Protocol Generation** — `make_schema()` dynamically converts TOOLS param definitions to `input_schema`
   - Adding tools is concentrated: write function, register in TOOLS, main loop unchanged
   - Critical: won't destabilize main flow as features grow

4. **Agentic Loop** — Simple: model returns `tool_use` → local execution → `tool_result` back → repeat until no `tool_use`
   - Much easier to verify than complex state machines
   - Better for early iteration

### Key Insight
Master minimal implementations first, then study memory/planning/multi-agent coordination — understanding is more solid and you can better judge which complexity is necessary.

## Relevance to Our System
- Our tool set (read/write/edit/bash) is almost identical to nanocode's 6-tool design
- Validates the "primitive tools are enough" philosophy
- Our agentic loop is similarly simple — heartbeat → tool calls → finish
- The "single replacement by default" in edit matches our edit() tool behavior exactly
- Confirms: the minimal viable agent is surprisingly small — complexity should be added only when proven necessary
