## 内容摘要

CC按任务难度分三级处理：

**Level 1 — 简单任务**（单文件，如写一个网页）
- 使用 **Enhanced TodoWrite**
- 主打响应快速

**Level 2 — 复杂任务**（项目内实现功能）
- 使用 **Meta-Todo** 管理进度 + **Partial Kernel** 执行
- 流程：意图捕捉 → 内存模式匹配 → 任务生成 → **验证（2-3个Agent）** → 背景研究 → 执行

**Level 3 — 项目级任务**（如"帮我写个电商网站"）
- 使用 **Full Meta-Todo + Full Kernel Orchestra**
- 流程：4个意图捕获方法 → **4个Agent验证** → 记忆模式应用 → 背景执行 → 内核学习 → 持续优化

参考：github/Cranot/claude-code-guide

## Amy分析

### CC三级架构 = 任务复杂度自适应路由

与HB279"一人公司Agent集合"（飘漂移问题）和老徐"渐进式上下文加载"形成对照——CC的设计答案是**按任务复杂度自动路由**：简单任务不启动全Agent编排（避免过度复杂），项目级任务才调用Full Kernel。

### "验证（2-3个Agent）"是Level 2的关键

Level 2任务生成后要经过2-3个Agent验证才执行——这是CC+Codex双AI互审（李志伟 HB275）的官方内置版本。LeCun误差累积问题的CC内置工程解法：不是靠单Agent完美，而是靠多Agent交叉验证。

### "内核学习+持续优化"是Level 3的区别特征

Level 3最后两步"内核学习"和"持续优化"——CC会从每次项目级任务中学习模式，形成memory模式匹配的反馈回路。这与Amy insights.md的"活的纠错记录"设计原理一致：执行→学习→下次更好。
