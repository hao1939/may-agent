## 内容摘要

OC官方已发布iOS App（非第三方），当前处于TestFlight早期阶段。

### 核心功能

**配对机制：**
- 电脑跑 `openclaw qr` 生成二维码，手机扫码配对
- 局域网自动发现，也支持手动填IP
- 配一次自动重连

**语音交互：**
- 可设触发词，喊一声开始对话
- Talk模式：实时语音来回，支持打断，响应较快
- ⚠️ 语音"很机械化"

**系统分享直通：**
- 看到内容直接通过系统分享菜单发给OC，省去复制粘贴

**Apple Watch支持：**
- 手表接收通知、快捷回复（场景有限）

### 踩坑记录（完整）

1. **Swift版本问题：** 项目依赖要求 swift-tools-version 6.2，Xcode 16.3自带6.1 → 编译报错。需升级到 **Xcode 26**（App Store更新）

2. **缺依赖：** `brew install swiftformat swiftlint`

3. **扫码没反应（最隐蔽）：** 默认gateway跑在局域网IP上未开TLS，生成的二维码是`ws://`开头，但iOS出于安全只允许非TLS连接到localhost → 扫码后**静默失败，无任何报错**。  
   解决：`openclaw config set gateway.tls.enabled true`

### 当前状态

- 后台保活还在调（切后台再回来偶尔断）

## Amy分析

### iOS App是OC生态成熟度的重要信号
从 TG/飞书接入 → 官方iOS App，说明OC在积极降低使用门槛，从"极客工具"向"普通用户"迁移。但TestFlight阶段+需要Xcode编译说明仍在早期。

### TLS坑值得写入技术库
`ws://` vs `wss://` 的iOS安全限制是真实的工程陷阱，且**静默失败无报错**是最恶毒的坑。这类信息应该在OC官方文档中出现但往往缺失。

### 安全顾虑的社区分布
评论区有多条安全相关评论。对于中国用户，"数据安全"顾虑比海外用户更强烈——这与NanoClaw的容器隔离哲学形成对应：OC的开放性在中国市场是双刃剑。
