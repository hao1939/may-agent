## 核心论点：为什么必须用Multi-Agent
- ❌ 记忆爆炸: USER.md/memory越来越臃肿，AI记不住重点
- ❌ 上下文污染: 写文案蹦出代码逻辑，逻辑打架
- ❌ 成本虚高: 每次加载无关历史，token狂烧速度慢

**优雅玩法**: 单网关 + 同一机器人 + 不同飞书群 = 物理隔离专家团队

## 两种方案对比
| 多个分身（本文重点）| 多个独立Bot（硬核）|
|---|---|
| 飞书建一个Bot，拉进不同群 | 调研/设计/代码各自独立Bot |
| bindings路由自动切换"大脑" | 角色感超强，多实体协作直观 |
| 配置简单，适合个人 | 硬核玩家方案 |

## 完整操作步骤

### 1. 添加Agent
```bash
openclaw agents add work1 --model zai/glm-4.7 --workspace ~/.openclaw/workspace-work1
openclaw agents set-identity --agent work1 --name "AI 协作助手"
```

### 2. 给Agent注入"入职资料"
每个工作区创建三类文件: **SOUL.md** + **AGENTS.md** + **USER.md**
> "如果指令与工具是AI的躯体，那这些文档就是它的思维与记忆"

### 3. bindings路由配置（openclaw.json）
```json
{
  "bindings": [
    {
      "agentId": "work1",
      "match": {
        "channel": "feishu",
        "peer": {
          "kind": "group",
          "id": "oc_b1c331592eaa36d06a7e5df05d08a890"
        }
      }
    }
  ]
}
```

### 4. requireMention设置
```json
{
  "channels": {
    "feishu": {
      "groups": {
        "oc_xxx": {"requireMention": false}
      }
    }
  }
}
```
飞书权限需开放: `im:message.group_msg`

### 5. agentToAgent通信配置
`sessions_send` = "智能体之间的专属内线电话"
```json
{
  "tools": {
    "agentToAgent": {
      "enabled": true,
      "allow": ["main", "brainstorm", "writer", "coder"]
    }
  }
}
```

## 系统架构: 项目管理办公室
```
用户 → main Agent（项目管理办公室）
         ① 收集需求（唯一入口）
         ② 判断任务类型
         ③ 派单给专家Agent
              → brainstorm（创意发散）
              → writer（写内容）
              → coder（敲代码）
         ⑤ 串联交付
```
**核心定位**: main不亲自干活，只做"收需求+派任务"
