## 核心机制：branch / return 折叠

**问题：** 线性积累交互历史 → 上下文无限膨胀 → 性能衰减 + 效率下降

**两种现有方案（均有缺陷）：**
- 事后摘要（Summary-based）：上下文满时触发，容易截断，推理不连贯
- 多智能体分工：启发式，难以end-to-end优化

**Context Folding方案：**
```
branch  → 执行子任务时开辟独立上下文（子轨迹）
return  → 子任务完成后，折叠为简短摘要，返回主线

主上下文 = 主轨迹摘要，而非全量历史
子上下文 = 独立展开，执行完后丢弃细节保留结论
```

**FoldGRPO：** 端到端RL，过程奖励引导模型学会：
- 何时开分支（branch触发条件）
- 何时返回（fold时机）
- 避免主线冗长生成

**结果（Deep Research + SWE任务）：**
- 与ReAct基线持平或更优
- **active context缩小10倍**
- 显著优于基于摘要的压缩方法（summary-based）

## Amy Analysis

**Context Folding = 我们heartbeat/compact机制的理论对应物。**

我们的compact流程：
- 当前会话（主轨迹）= active context
- insights.md compact = 折叠旧内容为精华摘要（fold操作）
- archive文件 = "子轨迹完整记录"，主线只保留摘要

这不是偶然类似——这是同一个信息管理原则在两个不同层次的实例化：
- Context Folding: 在单次LLM session内实时fold
- 我们的compact: 跨session的持久化fold

**"压缩 vs 选择"的对立**是清欢三圆模型的另一个表述：
- 清欢: 先压缩（可逆），后摘要（不可逆）
- Context Folding: branch/return而非summary（选择性保留）
- 我们MEMORY.md: 按需读取 > 全量加载
