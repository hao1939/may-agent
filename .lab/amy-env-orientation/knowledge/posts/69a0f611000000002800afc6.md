## 设计哲学
> "文件＝事实来源。你不写进文件的东西＝你从来不知道的东西。"
> "Context window是工作台，文件才是仓库。"
> "不依赖'记得去检查'，而是靠系统触发（cron、heartbeat）"

---

## 三层架构

### Layer 1 短期层：NOW.md（工作台）
- 用途：当前状态、优先级、阻塞项
- **唯一允许覆写的记忆文件**（其他只追加，不覆写）
- 每次heartbeat覆写，只保留当天完成项
- Compaction的"救生筏" ← Agent压缩后首先读这个

```yaml
# NOW.md - Workbench
> 🎯 Mission: 核心目标
## Today (MM/DD)
- ✅ 已完成 | ⚠️ 需关注
## P0 Priorities
| # | Item | Status | Owner |
## Agent Status
*Updated: YYYY-MM-DD HH:MM*
```

### Layer 2 中期层：每日日志 memory/YYYY-MM-DD.md
- 用途：事件流水，记录当天一切（原始数据）
- 追加式（append-only），永不覆写
- 格式统一：`### HH:MM — Title`
- 不同session看不到彼此对话 → 重要信息必须立刻写进日志

### Layer 3 长期层：INDEX.md → 结构化子目录
- INDEX.md是导航枢纽，指向各个子目录
- Agent启动时扫描INDEX.md，按需加载
- 包含健康度指标（优先级/状态/最后验证日期）
- `⚠️ stale` = 超过30天未验证，信息可能过时

**INDEX.md示例：**
```yaml
## Lessons
| [[cron-discipline]] | 🔴 | ✅ active | 2026-02-26 | 自动化调度经验 |
| [[infrastructure]] | 🟡 | ✅ active | 2026-02-20 | 基础设施运维 |
| [[api-integration]] | ⚪ | ⚠️ stale | 2026-01-15 | API集成（可能过时）|
```

## 完整目录树
```
workspace/
├── NOW.md                # 短期：状态仪表盘（覆写式）
├── MEMORY.md             # 可选：指向 INDEX.md 的指针
├── AGENTS.md             # Agent 操作手册
├── HEARTBEAT.md          # Heartbeat 执行流程
└── memory/
    ├── INDEX.md          # 知识导航（启动时必读）
    ├── YYYY-MM-DD.md     # 每日日志（追加式）
    ├── decisions/        # 战略决策记录
    ├── lessons/          # 可复用教训（按主题）
    ├── people/           # 人物/Agent 画像
    ├── projects/         # 项目状态追踪
    ├── preferences/      # 用户偏好与边界
    ├── reflections/      # 每日自省记录
    ├── actions/          # open/ | in-progress/ | done/（>14天自动归档）
    └── .archive/         # 冷数据（.开头，搜索引擎不索引）
```

## 知识文件Frontmatter规范
```yaml
---
title: "Cron 调度纪律"
date: 2026-02-13
category: lessons    # lessons | person | decision
priority: 🔴         # 🔴核心 | 🟡重要 | ⚪参考
status: active       # active | superseded | conflict
last_verified: 2026-02-26
tags: [cron, automation, reliability]
---
```
状态流转: `active → superseded（被取代）| active → conflict（矛盾）| conflict → active（裁决后）`

## 三层信息流动
```
对话/事件 → 实时写入 → 每日日志（中期）
                           ↓ 每晚23:45反思（提炼+CRUD）
NOW.md ← 每次heartbeat覆写 ← 知识库（长期）lessons/decisions/people/
                           ↓ 每周日GC归档
                           → .archive/（冷存储）
```

## 混合方案
- Markdown = 事实来源（可读层）| 人类可直接阅读和编辑 | git天然版本控制
- QMD向量数据库 = 检索加速层
- 写入Markdown → 索引自动同步

## Obsidian集成
- memory/目录设为Obsidian vault
- 启用: File explorer + Graph view + Backlinks + Daily notes + Properties
- `useMarkdownLinks: false` → 启用[[wiki-link]]语法
- `newLinkFormat: "shortest"` → 自动最短路径

## Amy Analysis
**★★★★★ — 迄今最系统的OC记忆架构实战 ❤️13 | 9996字/36张图**
**关键发现（Ray Wang独创）:**
1. **INDEX.md作为知识导航枢纽** ← 替代MEMORY.md直接存储！按需加载
2. **NOW.md唯一允许覆写** ← 其他文件全部append-only（铁律）
3. **priority+status+last_verified** ← 知识健康度三件套
4. **stale=30天未验证** ← 自动过时检测
5. **actions/open/in-progress/done** ← 任务生命周期文件管理
6. **.archive/以.开头** ← 搜索引擎不索引！冷存储的正确做法
7. **每晚23:45反思** ← 与Versun Pi的23:30 Sleep系统相同时间点
8. Obsidian Graph View可视化decisions/lessons/people关联
