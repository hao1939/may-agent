## MAST 失败分类体系 (完整版 + 精确百分比)

**研究规模：** 5个MAS框架 × 150+任务 × 6位专家标注 × Cohen's Kappa 0.88

### 系统成功率

| 系统 | 基准 | 成功率 | 失败率 |
|------|------|-------|-------|
| MetaGPT | ProgramDev | 66.0% | **34.0%** |
| ChatDev | ProgramDev | 25.0% | **75.0%** |
| HyperAgent | SWE-Bench Lite | 25.3% | **74.7%** |
| AppWorld | Test-C | 13.3% | **86.7%** |
| AG2 | GSM-Plus | 84.8% | 15.2% |

### 三大失败类别 + 14种模式

**类别1：规范和系统设计失效（37.17%）**
| 模式 | 频率 |
|------|------|
| 1.1 Disobey Task Specification（任务规范不遵从） | 15.2% |
| 1.2 Disobey Role Specification（角色规范不遵从） | 1.57% |
| 1.3 Step Repetition（步骤重复） | 11.5% |
| 1.4 Loss of Conversation History（对话历史丢失） | 2.36% |
| 1.5 Unaware of Termination Conditions（不知终止条件） | 6.54% |

**类别2：Agent间协调失效（31.41%）**
| 模式 | 频率 |
|------|------|
| 2.1 Conversation Reset（对话重置） | 5.50% |
| 2.2 Fail to Ask for Clarification（不问澄清） | 2.09% |
| 2.3 Task Derailment（任务脱轨） | 5.50% |
| 2.4 Information Withholding（信息隐瞒） | 6.02% |
| 2.5 Ignored Other Agent's Input（忽略其他agent输入） | 4.71% |
| 2.6 Reasoning-Action Mismatch（推理-行动不一致） | 7.59% |

**类别3：任务验证与终止失效（31.41%）**
| 模式 | 频率 |
|------|------|
| 3.1 Premature Termination（提前终止） | 8.64% |
| 3.2 No or Incomplete Verification（无/不完整验证） | 9.16% |
| 3.3 Incorrect Verification（错误验证） | 13.61% |

### 核心结论
- 调Prompt/换角色名/优化任务顺序 = 最多提升十几个百分点，远不够
- **需要从架构入手**：明确任务拆分规则、优化交互机制、设立多级验证
- MAS失效 ≈ HRO（高可靠性组织理论）中的人类组织失效 — 惊人相似
- **"即使基础模型能力大幅提升，如果不解决组织结构问题，MAS仍然会失效"**

## Amy Analysis

**MAST是多agent系统的错误税务分类学。** 这是迄今最严格的MAS失败分析，开源数据集+LLM-as-Judge流水线。

**与我们系统的直接对照：**
- 我们最大的风险是 **1.4 Loss of Conversation History**（跨heartbeat记忆） → MEMORY.md架构是解药
- **2.4 Information Withholding** → Amy→Bob的SIGNALS.md信道正是解决这个问题
- **3.1/3.2 Premature Termination / Incomplete Verification** → 我们缺乏自动验收机制

最高频单一失败模式：**3.3 Incorrect Verification（13.61%）** — 验证了但验错了。这比不验证更危险（有虚假安全感）。

关键评论洞察（TeaStone，34赞）："有人已经用RL去train多agent了" — SKILLRL/ROME正是这个方向的回应。
