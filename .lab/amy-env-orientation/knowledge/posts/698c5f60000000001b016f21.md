## Content
**MemSkill** proposes a new memory summarization paradigm: **Span-level Skill-conditioned Memory Generation**.

### Problem
Current Agent Memory Systems are "hand-crafted pipeline" approach — too rigid, heavily dependent on human priors, can't generalize to new data. Turn-level sequential processing doesn't scale (high cost under long trajectories).

### Core Innovation
Treat "how to build memory" as a **learnable, evolvable skill bank**. Key paradigm shift: **Skill-conditioned Generation** — not processing turn-by-turn with fixed modules, but summarizing in span/chunk units. For each span, select a small group of relevant memory skills, combine skills + text span as LLM input → generate structured memory updates.

### Architecture
- **Controller → Executor pipeline:** Controller scores candidate skills in the skill bank, selects Top-K (avoids stuffing entire skill library into LLM). Executor does span-level memory generation conditioned on selected skills.
- **RL-trained Controller:** Uses downstream task feedback as reward signal to learn "when to use which skills."
- **Designer (self-evolution):** Maintains a **failure-driven hard-case buffer**. Periodically reviews repeated failure patterns → converts to skill edits (clearer trigger conditions, stricter extraction rules, more standardized output schema) or new skills (filling gaps).

### Results
Stable improvements on:
- Dialogue memory (LoCoMo, LongMemEval)
- Embodied decision-making (ALFWorld)
- Strong generalization (LoCoMo → HotpotQA)

## Key Comments
- **Author response on token cost:** Evolving skills is a small fraction of total long-term interaction. Inference only needs injecting a few skills. Supports different LLMs for executor (small, e.g. 7B) vs designer (large). Low coupling design makes this flexible.
- **On trigger mechanism:** Memory operation triggers on every text span, but *which* operations (which skills) is decided by controller based on content (e.g. temporal info → temporal skill).

## Synthesis Notes
- **Direct relevance to our system:** This is essentially a formal research version of what we're doing with SOUL.md + channel configs. Our "memory skills" are encoded as static rules; MemSkill makes them learnable.
- Validates Pattern #3 (File System = Memory) — but goes further: memory isn't just storage, it's skill-conditioned transformation.
- The failure-driven Designer is exactly the "Self-Evolution Trilemma" Pattern #6 — they solve the "who evaluates the evolver" problem with downstream task feedback (external signal).
- **Gap for us:** We have no equivalent of the "Controller" — our memory processing is one-size-fits-all. Skill-conditioned memory could dramatically improve what we remember vs. discard.
