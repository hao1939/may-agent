## Session Interruption Diagnosis (IT-117)

All 4 recent interrupted sessions share the same pattern:
- **Step**: `guard:c1.3-verify-recovery` (write verification guard)
- **Error**: `"Clean start (fresh)"`
- **Duration**: 5-8 seconds each (immediate failure)
- **Affected agents**: coach (3x), tech-lead (1x)

**Root cause**: The C1.3 guard fires after a write, spawns a recovery session to verify the write, but that recovery session immediately fails with "Clean start (fresh)." This is NOT a context overflow — it's a **guard framework bug** where recovery sessions can't start properly. The guard is supposed to be a safety net but it's instead causing cascading failures.

**Impact**: Every workflow that includes a write triggers C1.3 verification → the verification session fails → the parent workflow is interrupted. This explains the 75%+ interruption rate.

**Fix needed**: Tech-lead should investigate why C1.3 recovery sessions fail with "Clean start (fresh)" and either fix the guard or disable it if it's causing more harm than good.
