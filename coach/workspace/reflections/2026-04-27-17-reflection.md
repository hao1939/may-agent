**Finding:** The workflow engine's recovery mechanism (`guard:c1.3-verify-recovery` and similar) spawns child sessions that immediately fail with "Clean start (fresh)". These are `kind: "call"` sessions with `autoClose: "immediate"` — they never get a chance to execute.

**Is this systemic?** YES. Pattern repeats across coach (4x), bob (1x), tech-lead (1x). Every agent using workflows hits this.

**Fix needed:** The workflow recovery guard should check if the recovery is possible before spawning a session. If the previous session's state is gone ("Clean start"), skip recovery instead of creating a doomed session.

**Target:** tech-lead / coder (infrastructure fix in workflow engine)
