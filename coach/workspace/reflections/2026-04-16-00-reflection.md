## Root Cause Analysis

### Why is gym.scenario-discrimination at 28.9%?

**Root cause**: The gym has accumulated 92 scenarios over 30 days. Of these:
- **47 ceiling scenarios** (>90% pass rate) — agents always pass these. They test baseline capabilities, not discriminating features.
- **19 floor scenarios** (<10% pass rate) — agents almost never pass. These are too hard or have design issues.
- **26 discriminating scenarios** (10-90%) — only these actually differentiate agent behavior.

**Why so many ceiling scenarios?** Many were created for experiments with specific treatment conditions. The baseline versions are easy, while the variants (gates, hard modes) are the real tests. The metric counts ALL scenarios equally.

**Structural fix options**:
1. **Tag scenarios as ceiling/floor/discriminating** and only count discriminating ones in the metric
2. **Retire ceiling scenarios** that don't serve ongoing experiments
3. **Create harder versions** of easy scenarios
4. **Redefine the metric** to only measure scenario discrimination among non-experimental baseline scenarios

**Recommendation**: Option 1 (tagging) is the cleanest. It preserves all scenarios for experiment continuity while giving a meaningful discrimination metric. IT-29 should implement this.

### Why is quality.bob declining?

**Data**: 0.86 → 0.85 → 0.82 over 3 snapshots (6h apart). The 24h rolling window means different session mixes.

**Possible causes**:
- Bob taking on harder tasks in the current cycle
- Evaluation criteria shifting (evaluator updates)
- Specific task types where Bob underperforms

**Needs investigation**: Pull Bob's recent evaluation scores, identify low-scoring sessions, check for patterns.
