## Root Cause Analysis

### RCA-1: Guard Approach Definitively Proven Ineffective
**What happened?** Three independent evidence streams converge:
1. Hao's directive: guards reverted, hierarchy defined (context.md > workflows > guards)
2. Coach's own Gate 3 validation: 0/6 effectiveness on missing-prerequisite-detection
3. Historical data: 0/18 SOUL.md text changes effective, 0/6 guard tests effective

**Root cause**: Guards and text additions are "push" interventions — they add constraints the agent must remember to follow. But LLMs are poor at following negative constraints under cognitive load. Context.md facts work because they're "pull" — the agent sees relevant context AT DECISION TIME. Workflows work because they restructure the task to prevent the error path entirely.

**Coach action**: Update method-catalog.md to:
- Mark all guard-based methods as DEPRECATED
- Add "context.md fact" as a new validated method (evidence: npx A/B test)
- Ensure the enforcement hierarchy is documented as preamble

### RCA-2: Reflection→Action Pipeline Still Broken
**What happened?** 7th consecutive reflection with <50% IT completion.
**Why?** The fundamental problem is unchanged: reflection generates ITs in a markdown file. Heartbeats don't read reflection files. `finish(new_items)` bridges this gap in theory, but:
- ITs are written as prose, not tracked requests
- Even when registered via finish(), they compete with higher-priority error-driven work in heartbeats
- Coach prioritizes experiments (which have immediate feedback) over knowledge maintenance (which has deferred feedback)

**Structural fix**: This reflection will use `finish(new_items)` to register exactly 2 concrete, small ITs. Keep them tiny enough to complete in a single heartbeat's idle time.

### RCA-3: Scenario Infrastructure Absorbs Most Coach Effort
**What happened?** Of 7 experiments run since last reflection, 4 were "ceiling effect" due to infra bugs in scenarios (npm missing, scorer bugs, environment already fixed). Coach spent more time fixing scenario infrastructure than coaching agents.
**Why?** The gym scenarios were written quickly and never tested against the actual runtime constraints (e.g., npm not available, argv ordering). Each experiment that hits an infra bug wastes ~4 LLM sessions.
**Structural fix**: Before creating new scenarios, run a quick `node success_criteria.js` in a test harness to verify the scorer actually works. Also: maintain a "known infra issues" list in workspace.
