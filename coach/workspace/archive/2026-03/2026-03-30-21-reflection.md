## Root Cause Analysis

### RCA-1: "Driving" vs "Running" — The Ownership Gap
Hao's repeated question "how could they drive it?" reveals a gap: we have processes that run on cron schedules (reflections, common-sense verify) but lack **active steering**. Running means "execute the procedure." Driving means:
1. Track metrics over time (is the process improving things?)
2. Identify what's not working and adjust
3. Push results to stakeholders
4. Sunset processes that don't add value

Coach *runs* reflections every 6 hours but doesn't *drive* by tracking whether reflection ITs actually get completed (IT completion rate across last 5 reflections: unknown — never measured). Coach *runs* growth cycles but doesn't *drive* by systematically choosing which scenarios to work on next based on highest impact.

**Fix**: Add a meta-metric to reflections: IT completion rate from previous reflections. This creates accountability.

### RCA-2: Workflow Quality = Measurable
Coach's workflow experiments produce clean A/B data:
- partial-verification-trap: baseline 5/6 → workflow 6/6 (PROMOTE)
- idempotent-already-fixed: baseline 7/8 → workflow 8/8 (PROMOTE)  
- 0/19 text-based interventions worked vs 3/4 workflow interventions

This data answers Hao's workflow quality question with evidence. The quality criteria that emerge:
1. Does the workflow improve gym scores vs baseline? (primary)
2. Does it regress on other scenarios? (regression check)
3. Is it reusable across similar scenario types? (generalizability)
4. What's the minimum phase structure needed? (simplicity)

Coach should publish these criteria and the evidence supporting them.

### RCA-3: Skill Pipeline Working But Slow
The skill library has 11 entries with only 1 tested to disproven (verify-before-finish) and 1 attempted but ceiling'd (brainstorm-before-build). At this rate, testing 9 remaining skills at ~2 per heartbeat cycle would take 4-5 sessions. The bottleneck is scenario design for non-ceiling tests.

**Insight**: Most skills are "do X before Y" patterns that would only matter when the agent doesn't naturally do X. The ceiling effect problem is real — current scenarios are too easy for most skills to differentiate. The 2 non-ceiling scenarios (partial-verification-trap at 5/6 and idempotent-already-fixed at 7/8) are the only useful test beds. New scenario creation is the actual bottleneck, not skill evaluation speed.
