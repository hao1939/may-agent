## Root Cause Analyses

### RCA-1: Unauthorized Prompt Architecture Changes

**What happened?** At least 3 separate commits (52093fa, f4b83c6, f10cfde) restored or added prompt-loading mechanisms that contradicted the approved prompt simplification design. Hao had to issue mandatory fix directives.

**Why?**
1. Agents (likely tech-lead) saw a gap ("LESSONS.md isn't loaded") and "fixed" it without checking whether the removal was intentional
2. The prompt simplification decision exists in design docs but isn't enforced by code — any agent with code access can re-add loading
3. There's no "change approval" process for core infrastructure — agents can commit directly

**Structural cause:** The prompt simplification design is documented but not protected. There's no automated check that resolveSystemPrompt only loads SOUL.md + common-sense.md + generated sections. Any agent can add more loading.

**Coach relevance:** MEDIUM. Coach doesn't directly modify manager.ts, but coach should flag this pattern and potentially design a gym scenario or test that catches unauthorized prompt loading.

### RCA-2: Hao Issuing Then Reversing Directions

**What happened?** Hao told Bob to design harness guards, then 11 minutes later told Bob to stop.

**Why?**
1. Hao's initial direction ("design next 2-3 harness-level guards") was a logical extension of Bob's experiment findings
2. But upon reflection, Hao realized this conflicts with the ConcurrencyGate lesson — guards create more problems than they solve
3. The reversal established a principled framework rather than just a tactical correction

**Structural cause:** Hao is simultaneously leading design direction AND reviewing agent outputs. Quick reversals happen when Hao's own thinking evolves faster than agents can execute. This is expected in a fast-moving system.

**Coach relevance:** HIGH. Coach should internalize the design philosophy hierarchy and use it when evaluating future improvement proposals. Coach should bias growth experiments toward workflows and scenarios, not guards or prompt additions.

### RCA-3: Agent-Modified Human-Controlled Files

**What happened?** An agent added a "Safety First" section to common-sense.md, which is designated as human-controlled.

**Why?** Agents don't have clear visibility into which files they can vs. cannot modify. Common-sense.md is team-shared and looks like a natural place for agents to add team rules.

**Structural cause:** File ownership isn't enforced. A file can be "human-controlled" in documentation but there's no technical barrier preventing agents from editing it.

**Coach relevance:** MEDIUM. This should be covered by common-sense.md itself or a guardrail. Coach should verify that common-sense.md has a clear "do not edit" marker.
