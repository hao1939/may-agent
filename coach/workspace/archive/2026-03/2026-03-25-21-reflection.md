## Root Cause Analyses

### RCA-1: Discussion vs. Action Gap

**What happened?** Hao initially sent autoresearch-pattern.md as a discussion prompt to all agents. Within 12 minutes, pivoted to demanding concrete experiments.

**Why?** 
1. Agents have been producing discussion documents (reviews, plans, responses) but not running actual experiments
2. The autoresearch-pattern itself is about running experiments at scale — sending it as a "discussion" is meta-ironic
3. Hao realized discussion docs won't advance the system; only empirical data from actual gym runs will

**Structural cause:** Agent heartbeat loops default to "read → think → write document" workflows. Running experiments requires bash execution, iteration, and handling failures — this is harder and less predictable. Agents naturally drift toward the easier path (writing about experiments instead of running them).

**Coach relevance:** CRITICAL. Coach ran the auto-evolve experiment successfully (5 variations, all tested, results documented). But coach also wrote an autoresearch-pattern response that was... another discussion document. The experiment is the valuable output, not the response doc.

### RCA-2: Multi-Agent Coordination Tax

**What happened?** Hao assigned auto-evolve to 4 agents with role-specific responsibilities, then immediately canceled and reassigned to coach alone.

**Why?**
1. The coordination overhead of 4 agents for a single experiment exceeds the experiment's complexity
2. Agents can't synchronize within a single experiment session — they operate on separate heartbeat cycles
3. The bash loop for gym runs is simple enough for one agent to own

**Structural cause:** The system's coordination model is async (send message → wait for next heartbeat → receive response). This works for parallel independent tasks but fails for sequential multi-step experiments where agent B needs agent A's output. Single-owner experiments are more reliable.

### RCA-3: Proactive Result Reporting Missing

**What happened?** Hao asked "what's the output" about a research task — meaning results weren't delivered.

**Why?** When a task completes, the result lives in an agent's workspace file. Hao has to know to look for it. There's no notification mechanism that says "Task X is complete, here's the result."

**Structural cause:** Agents don't have a "report to human" channel. They write files and move on. The missing link: when a Hao-assigned task completes, the result should be summarized and delivered, not just filed.
