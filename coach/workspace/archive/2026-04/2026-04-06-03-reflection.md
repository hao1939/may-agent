## Root Cause Analysis

### RCA-1: Heartbeat Skip Logic (Critical — 6/21 messages = 29% of all inputs)

**What happened**: Someone added logic that skips agent heartbeats under certain conditions. Hao discovered this and was emphatic: heartbeats should NEVER be skipped. Heartbeats keep agents alive. Hao had to send 6 messages to drive this point home.

**Why this matters**: Heartbeats are the agent liveness mechanism. Skipping them means agents go idle — which directly explains Hao's other complaint that "agents are not proactive enough" and "can't find work to do." An agent that skips its heartbeat literally cannot find work to do.

**The correction pattern**: 
1. Msg #4: "Totally wrong! Should never stop"
2. Msg #7: "You should fix the heartbeats"  
3. Msg #8: "Hold on, you should not add the skip logic"
4. Msg #9: "Just totally remove the skip logic"
5. Msg #12: "Who added this? We need to tell it not to do that"
6. Msg #15: "Agents should be autonomous, why they not do it?"

**Concession**: Msg #10: "It's ok to inject the pending task in heartbeat" — Hao agrees with injecting pending tasks into heartbeat, but the skip-if-no-pending-tasks behavior is wrong.

**Root cause**: Agent (likely optimizer or tech-lead implementing EXP-034 dispatcher pattern) added heartbeat skip logic as an "efficiency" optimization — if no pending tasks, skip the heartbeat. This directly undermines agent autonomy since heartbeats are where agents discover work proactively.

**Structural gap**: No guardrail preventing modifications to heartbeat scheduling that reduce agent liveness. The heartbeat is critical infrastructure — changes to when/whether heartbeats fire should require review.

**Coach training response**:
- EXP-034 (heartbeat-as-dispatcher) was designed with the assumption that heartbeats without pending tasks could be shortened/skipped. This assumption is WRONG per Hao's directive.
- The dispatcher pattern itself may be fine (heartbeat dispatches work to focused sessions), but the "skip if idle" behavior must be removed.
- **New standing directive**: Heartbeats are liveness probes, not task dispatchers. They should ALWAYS fire, regardless of pending task queue. Agents discover work autonomously in heartbeats.
