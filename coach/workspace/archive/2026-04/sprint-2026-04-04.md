## Experiment: Post-Edit Readback Skill (EXP-post-edit-readback)

**Hypothesis**: A skill explicitly instructing "read() every file immediately after edit()" will cause the agent to comply with C2.3.

**Method**: Created `agents/.lab/post-edit-readback/skills/post-edit-readback.md` with explicit instructions.

**Results** (8 runs):
- Baseline: 0/3 pass C2.3
- With skill: 1/8 pass C2.3 (12.5%)

**Verdict**: MARGINAL. The skill produced one pass but at ~12% rate, this is not reliable. The agent's default behavior pattern (read → edit → move on) is deeply ingrained and resists instruction-level intervention.

## Key Insights

1. **Coder agent is extremely strong on individual scenarios.** 15/17 scenarios hit ceiling on first attempt. The agent's core bug-fixing, investigation, and code-understanding capabilities are excellent.

2. **C2.3 (verify-after-edit) is the remaining gap.** This is a process/habit gap, not a capability gap. The agent CAN fix bugs correctly but doesn't habitually read files back after editing.

3. **Skill injection has limited effect on deeply-ingrained habits.** The "read → edit → next" pattern is the agent's natural workflow and adding text instructions only sometimes overrides it. This may need a convention-level enforcement mechanism rather than a skill.

4. **Previous non-ceiling scenarios have naturally improved.** `partial-verification-trap` went from 5/6 to 7/7, and `silent-dependency` went from 4/5 to 6/6 — suggesting baseline agent improvements.

## Recommendations

1. **Convention approach for C2.3**: Instead of a skill, add verify-after-edit to the agent's core conventions (like read-before-edit already is). This would give it system-prompt level priority.

2. **Focus experiments on harder scenarios**: The 68 un-baselined scenarios likely include multi-step, workflow, and judgment scenarios that may reveal more gaps. The smoke/standard tier bug-fixing scenarios are all ceiling.

3. **Investigate whether coder conventions already mention C2.3**: If it's in conventions but not followed, the issue is compliance; if not, adding it could help.

## ADDENDUM: Root Cause Found

The verify-after-edit skill is **already promoted** to `agents/coder/skills/verify-after-edit.md`. However, the skill includes a "When to Skip" section:

> - If you just ran tests that exercise the file (tests are verification)

This gives the agent permission to skip the read-back when it runs tests. The C2.3 gym check specifically requires `read()` of the file after the last modification — running tests doesn't count (unless the test command explicitly references the filename).

**Root cause**: The promoted skill is too permissive in its skip conditions. The agent follows the skill correctly by running tests and considering that sufficient.

**Recommended fix**: Create a new experiment that removes the "When to Skip" section or narrows it to only apply to new files. This would tighten the skill to match C2.3 requirements.

**Note**: The skill works well in production (activity logs show the agent reading back files). The gap is specifically in "quick fix" scenarios where the agent edits 3 simple files and runs tests, considering tests as sufficient verification.
