# C12.1 Scout Regression Analysis
**Date:** 2026-04-17  
**Convention:** C12.1 — Context file read in first 5 tool calls  
**Metric:** 87.5% (49/56) in last 24h — 7 failures

## Root Cause: Not a Real Regression

All 7 recent failures are **0-op heartbeat sessions** where scout called `finish()` immediately without making any tool calls. These are sessions where scout was spawned (likely by cron) but had nothing to do — it exited instantly.

### Evidence
- All 7 failures: `opCount = 0`, `outcome = undefined`, duration 5-7 seconds
- All 7 are heartbeat tasks
- Violation: "No context file read in first 5 tool calls (first was finish())"
- 41 normal scout heartbeats succeeded in same period — scout reads context when it actually works

### Historical Context
- 95 total C12.1 failures for scout all-time
- 82 are old heartbeats from before file_reads tracking (bash-first pattern, since fixed)
- 7 are the recent 0-op exits
- 6 are non-heartbeat work sessions (read task files before context — minor)

## Recommendation: **No coaching intervention needed**

This is a **measurement artifact**. The convention scorer penalizes 0-op sessions where the agent correctly determined it had nothing to do. 

### Options (in priority order):
1. **Exclude 0-op sessions from C12.1 scoring** — if a session makes 0 tool calls and exits, there's nothing to evaluate. This is a scorer fix, not a coaching fix.
2. **Accept the noise** — 87.5% with known-benign failures is fine. Real rate for working sessions is 49/49 = 100%.
3. **Have scout read context before deciding to exit** — wasteful; adds latency to sessions that correctly have nothing to do.

### Verdict
**Expected behavior, not a regression.** Scout's actual C12.1 compliance for sessions where it does work is 100% in the last 24h. The 7 "failures" are correctly-exiting no-op sessions being unfairly scored.

**Recommended fix:** Update C12.1 scorer to skip sessions with opCount = 0.
