## 两种多Agent模式对比

### 模式A: 飞书"分身术"（单渠道单账户）
```
用户→Bot分身→binding规则按群ID路由
→飞书群A(灵统) / 飞书群B(灵谋) / 飞书群C(灵工)
```
特点: 一个Bot走天下 | 配置极简 | 适合个人轻量办公 | 用户无感切换

### 模式B: Discord"独立团"（单渠道多账户）⭐ 本帖主题
```
用户 → Discord频道 → 广播
灵总/灵策/灵工/灵文/灵核 全员监听→响应
```
架构: 1个Gateway统筹 + 4个专家Bot协作

## 关键配置

### 关键OC设置
```yaml
sessions.visibility: "all"  # 打破会话隔离，实现上下文穿透
```

### Discord Bot关键设置
- **务必勾选 Privileged Gateway Intents** （否则机器人变"聋子和瞎子"）
- 精准唤醒: `<@BotID>` ← Discord原生@提及

### 建立步骤
1. 访问 discord.com/developers/applications → New Application
2. 统一命名前缀（如：灵统、灵策）
3. 开启Bot感知能力（Privileged Gateway Intents）
4. bindings路由配置

## Sub-agent vs 多账户军团的核心区别

| 维度 | Sub-agent | 多账户军团 |
|------|-----------|-----------|
| 执行方式 | 后台静默 | 全透明同频 |
| 用户体验 | 只拿结果 | 实时看过程 |
| Token消耗 | 省 | 多 |
| 适用场景 | 极简高效 | 演示/干预/透明协作 |

**"两种模式没有对错，只有场景不同"**
