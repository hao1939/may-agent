## 核心内容：Codex 0.102.0 自定义 Multi-Agent 角色

### 三个内置角色（之前）
- **Default：** 无特定角色，继承父 agent
- **Explorer：** 运行 5.1-Codex-Mini，专职探索代码库
- **Worker：** 继承父级 model，实现/修复/测试/重构

### 现在（0.102.0 更新后）：无限自定义角色

**配置结构（双层）：**
1. `config.toml` 注册角色 → `description`（何时调用） + `config_file`（详细配置路径）
2. `.codex/agents/<role>.toml` → 每角色独立配置

**关键：角色配置只有被调用时才加载，不浪费父 session token**

### 9大配置项
| 配置 | 说明 |
|------|------|
| Model + Reasoning Level | 如 5.3 Codex High / 5.1 Mini Medium |
| developer_instructions | 角色专属 system prompt |
| description | 控制何时被调用（影响自动分派） |
| Permissions | read-only / read-write 沙盒权限 |
| MCP Servers | 每角色独立配（Linear, GitHub 等）|
| ChatGPT Apps | Notion/Monday 等按角色开关 |
| Features | memory_tool / shell_tool 按需开关 |
| Scope | 全局 / 项目级 / 子目录级 |
| Personality | verbosity / pragmatic / detailed |

**未定义选项 → 自动继承父 Agent 配置**

### 隐藏技巧
- 默认最多 6 个并行 agent；`[agents] max_threads = 12` 可突破（多了会 429）
- Skills 和 Subagents 可互相调用（`"Use the $frontend-design skill"`）
- developer_instructions 加输出模板 → agent 可靠输出结构化结果

### 作者推荐组合
- **主编排：** 5.3 Codex High（规划 + 全局理解）
- **执行：** Spark subagent（快速实现）

### 25 个预置角色（开源）

## Amy Analysis
Codex 的 multi-agent 架构比 OC 更结构化（TOML 配置文件）但也更繁琐。

**对我们系统的比较价值：**
1. **description 字段控制路由** — Codex 用自然语言描述"何时调用此角色"来实现路由。我们 OC 的 L1/L2/L3 技能加载用的是 SKILL.md 的触发词，原理类似。
2. **按需加载配置** — "角色配置只有被调用时才加载" = 我们的 Skills 三层加载哲学（L1 名称→L2 全文→L3 执行）完全一致。
3. **MCP per-role** — 每个角色独立配 MCP Server 是 OC 目前没有的细粒度控制。可以给 Bob（synthesis）配写权限，给 Amy（exploration）配只读权限。
4. **max_threads** — OC 的并发 subagent 控制是否类似？值得查。

**Cross-platform pattern：** Codex 和 OC 独立演进到相似的"角色化 multi-agent + 按需配置加载"架构，说明这是这个设计空间的自然收敛点。
