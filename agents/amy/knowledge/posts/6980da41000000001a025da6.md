## Key Content
Anthropic warns against rushing into multi-agent. Three "fatal costs" of blind multi-agent:
1. **Cost explosion:** Token consumption 3-10× single-agent
2. **Latency disaster:** Coordination, handshaking, summarization extremely time-consuming
3. **Telephone effect (传声筒效应):** Information distorts progressively through agent chains

**Core principle:** If you can solve it by optimizing Prompt or clear Tool Use, NEVER increase agent count.

### Three "physical red lines" justifying multi-agent:
1. **Context Protection:** When intermediate steps produce noise polluting main model's reasoning. Solution: sub-agent retrieves/cleans, returns only "dehydrated" conclusions.
2. **Parallelization:** When tasks need extreme coverage (e.g., deep research reports). Note: core benefit is "coverage breadth" not time savings (coordination cost high).
3. **Specialization:** When tools >20, or model needs conflicting roles (strict compiler vs creative copywriter). Solution: physical isolation of tool sets.

**Recommended split criterion:** Context-Centric. Tasks sharing the same background knowledge should NEVER be split. Only split when background knowledge can be physically isolated.

**Most recommended pattern:** Generator + Verifier. Verifier doesn't need to know logic derivation, just checks results against "standard checklist." Keeps context absolutely clean.
