## TL;DR（作者原文）
> OpenClaw的记忆系统基于纯Markdown文件，分为每日笔记和长期记忆两层架构。智能体每次会话加载上下文文件，通过压缩前刷新机制保证记忆不丢失。搜索层可选内置向量搜索或本地QMD。
> **核心思路：文件即真相，确定性注入优于概率检索。**

## 1. 内存机制

**内存就是workspace里的Markdown文件。** 没有隐藏状态，没有黑盒数据库。

### 默认Workspace结构
```
~/.openclaw/workspace/
├── AGENTS.md          # Operating rules (loaded every session)
├── SOUL.md            # Identity / persona (loaded every session)
├── USER.md            # User info (loaded every session)
├── MEMORY.md          # Long-term memory (private chat ONLY)
├── TOOLS.md           # Tool notes
└── memory/
    ├── 2026-02-13.md  # Daily log
    ├── 2026-02-14.md  # Daily log
    └── ...
```

### 会话启动加载规则
- 每次启动：读取 AGENTS.md + SOUL.md + USER.md + 今天+昨天日志
- **MEMORY.md 只在私聊中加载** ← 群聊不加载，防隐私泄露 ⚠️
- 直接读取注入（无检索/排序/向量化）← 快速、可预测

### 核心洞察
> "对于会话间真正重要的20-30个要点，结构良好的Markdown文件比任何向量数据库都好用。始终加载，始终完整，永不检索失败。"

## 2. 记忆构建

### AGENTS.md中的记忆指令
```markdown
## Memory
- Logs: memory/YYYY-MM-DD.md — raw notes
- Long-term: MEMORY.md — curated memory
- If you want to remember something, write it to a file
- "Mental notes" won't survive to the next session. Files will.
```

### 双层架构
| 层 | 文件 | 特点 |
|---|------|------|
| 日志 | `memory/YYYY-MM-DD.md` | 原始、仅追加、意识流、写入成本低 |
| 长期记忆 | `MEMORY.md` | 精选、按主题组织、定期修剪 |

### MEMORY.md示例片段（Dissao实际内容）
```markdown
## Key decisions & patterns
- Security is rule #0. Show diffs before editing config.
- Use a dedicated agent account to separate human vs. agent security domains
- trash > rm — recoverable beats gone forever

## Lessons learned
- Config patches containing bot tokens are dangerous
- macOS Keychain prompts can hang headless processes
- os.tmpdir() on macOS is /var/folders/.../T, not /tmp/
```

### 压缩前记忆刷新（memoryFlush）— Dissao评价"巧妙安全网"
```json
{
  "compaction": {
    "memoryFlush": {
      "enabled": true,
      "softThresholdTokens": 4000,
      "prompt": "Write persistent notes to memory/YYYY-MM-DD.md; if there's nothing to store, reply NO_REPLY"
    }
  }
}
```
> "第3天这救了我——长会话中有重要决策，没有刷新压缩就会丢失上下文。"

## 3. 记忆搜索

### 内置：Markdown向量搜索（memory-core插件）
- 分块：约400token，80token重叠
- 存储：Agent专用SQLite数据库
- 默认**混合搜索** = BM25关键词 + 向量相似性
```json
{
  "memorySearch": {
    "query": {
      "hybrid": {
        "enabled": true,
        "vectorWeight": 0.7,
        "textWeight": 0.3
      }
    }
  }
}
```
混合原因：向量搜索擅长"意思相同"；BM25擅长精确token（错误字符串、配置键）

### QMD（本地优先备选）
- BM25+向量搜索+**重排序**
- 通过Bun+`node-llama-cpp` 完全本地运行，首次自动下载GGUF模型
- Gateway管理QMD进程：每5分钟 `qmd update` + `qmd embed`
- 搜索：`qmd query`

## 4. 推荐方案（运行1周建议）

1. **第1天别设置QMD或向量搜索** ← 从基础文件布局开始
2. 按主题而非时间组织MEMORY.md（Infrastructure/Key decisions/Lessons learned/Open TODOs）
3. **启用memoryFlush** ← 免费保险
4. **日志超过30个文件后再加向量搜索** ← memory/目录超1个月才有必要
5. **MEMORY.md保持私密** ← 只在私聊加载，群聊/Discord不暴露

## 三层心智模型
```
Layer 1: Context files (AGENTS.md, SOUL.md, USER.md, MEMORY.md)
  → Always loaded, deterministic, "working memory"
  → ~20-30 key facts

Layer 2: Logs (memory/YYYY-MM-DD.md)
  → Recent days loaded at startup; older logs searchable
  → Append-only, cheap to write

Layer 3: Vector search (memory_search)
  → Semantic retrieval across all memory files
  → For finding specific items in a growing corpus
```
> "整个系统可检查、可编辑、可版本控制。无黑盒。workspace的git log就是记忆形成的历史。"
