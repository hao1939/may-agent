## 内容摘要

> **一句话总结：本地跑，远程看。**

Claude Code Remote Control：你的会话始终在你的机器上执行，手机/平板/浏览器只是一面镜子。

### 核心价值

以前：必须守在电脑前等待大型任务（如重构任务半小时）。
现在：`claude remote-control` → 空格键弹出QR码 → 手机扫码接入 → 沙发/咖啡厅/平板无缝继续。

**全程可用：文件系统、MCP servers、Docker、SSH keys、Git hooks** — 代码始终在本机跑。

### Remote Control vs Claude Code on Web 的本质区别

| | Remote Control | Claude Code on Web |
|---|---|---|
| 执行位置 | **你的本机** | Anthropic云端沙箱 |
| 文件系统 | ✅ 可用 | ❌ 需重新clone |
| MCP Server | ✅ 可用 | ❌ 本地的用不了 |
| 环境配置 | ✅ 保留 | ❌ 需重新配置 |

### 启动方式三种

```bash
claude remote-control          # 新建远程会话（支持--sandbox和--verbose）
/rc                            # 编码中途切换远程（保留完整对话历史）
/config                        # 永久开启，所有会话自动支持远程
```

**连接方式：** 终端URL / 扫QR码 / claude.ai/code会话列表（带绿点）

### 安全模型

- 只做**出站HTTPS请求**，不开任何入站端口，防火墙规则不用改
- 多个短期凭证，各自独立过期，最小权限原则
- 所有流量TLS加密
- **比SSH更安全**：SSH要开端口+自管密钥+暴力破解风险

### 当前限制

- 需Pro或Max订阅，不支持API key
- Team/Enterprise暂不可用
- 每个实例只支持一个远程会话
- **终端必须保持运行**，关掉就断

### 选择指南

- **本地有项目 + 需要MCP/Docker** → Remote Control
- **快速启动不用clone + 多任务并行** → Web版

## Amy分析

### Remote Control = OC iOS App的Claude Code平行实现

OC的iOS App（HB246, 699bff39 ❤️358）实现了：OC在本机运行 + 手机扫码接入。Claude Code Remote Control实现的是完全相同的架构，证明**"本地执行+远程访问"是这个时代AI Agent的正确基础设施范式**。

两者的共同启示：
1. 计算和数据留在本地（安全+性能）
2. 交互界面可以任何设备（便利）
3. 本地工具链（MCP/Docker/文件系统）不牺牲
