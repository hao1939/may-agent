## 7个多租户隔离机制

### 1. IdentityLinks（跨平台身份统一）
```yaml
identityLinks:
  'alice@work.com':
    - 'telegram:123456789'
    - 'discord:987654321'
```
**效果**: 同一个人在多平台=同一个助理

### 2. SessionKey（唯一门牌号）
```
格式: agent:${agentId}:${channel}:dm:${peerId}
示例: agent:main:telegram:dm:alice@work.com
```
- `dmScope=per-peer`: agent:main:dm:alice
- `dmScope=per-channel-peer`: agent:main:telegram:dm:alice
- `dmScope=per-account-channel-peer`: 最细粒度

### 3. 6级路由优先级
```
用户ID > 群组 > 团队 > 账户 > ... > default
"6级匹配，首中即停"
```
VIP用户→专属高智商Agent | 普通群友→通用Agent

### 4. 物理级文件隔离（关键）
```
~/.openclaw/agents/
├── main/
└── sales-bot/
    ├── sessions/
    │   ├── sessions.json
    │   └── <uuid>.jsonl ← 会话文件
    ├── memory/
    │   └── sales-bot.sqlite
    └── workspace-sales-bot/
```
**完全隔离，零文件共享** — "女朋友Agent的数据别的Bot绝对读不到"

### 5. SessionId + JSONL
- 对话历史不存数据库，直接存`.jsonl`文件
- 一行一条消息，追加写入
- 易备份、易审计，速度极快

### 6. 双层记忆（JSONL + Markdown）
```
短期: <uuid>.jsonl — 完整流水账
长期: memory/2024-01-28.md — 系统自动触发内存刷新
       例:"Alice负责数据库迁移" "AWS月省$450"
```

### 7. 并发安全：文件锁
```
sessions.json.lock { pid: 12345, startedAt: ... }
轮询间隔: 25ms | 最长等待: 10秒
死锁检测: 30秒 → process.kill(pid, 0) 检查PID存活
锁TTL: 45秒 | 缓存TTL: 45s(命中~0.5ms vs 磁盘~5-10ms)
```
