## 日记系统架构（Slide 1 OCR完整）

### 触发机制
```
Cron: nightly-journal-generate
时间: 每天 02:00 自动跑
模型: Opus
```

### 三个数据源（交叉验证）
1. **`memory/YYYY-MM-DD.md`** — 主数据源（用户白天手动写入的事件记录）
2. **Session logs** — 补充（当天所有对话的用户消息，过滤cron/heartbeat噪音）
3. **Git commits** — 补充（当天所有repo的提交记录）

### 生成流程
```
1. journal_generate.sh 收集三个数据源
2. memory文件为主干，session logs和git commits补漏
3. 按 Journal/CLAUDE.md 格式整理:
   ## 随记: 按主题分###小节，保留具体细节(IP/命令/价格等)
   ## 账单: 消费/收入表格 + 汇总
4. 写入 ~/Documents/dec/notebook/Journal/Daily/YYYY/MM/YYYY-MM-DD.md
5. Git commit + push
6. 发Telegram摘要（3-5句话）
```

### 关键规则
- **memory文件是唯一可靠数据源**（session logs会被compaction压缩丢失!）
- 禁止抽象概括，必须保留具体细节
- **300行memory → 目标100-150行日记**

### 硬件+工具链
- **DJI MIC3** 录制语音日志（非电脑时段）
- **Git** 版本管理 | **Obsidian** 查看
- Telegram发摘要
