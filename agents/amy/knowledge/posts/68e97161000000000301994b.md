## Full Text
👀 这篇工作在解决什么？
现在很多应用不改模型参数，而是靠“上下文”来适配任务（系统提示、工作流记忆、证据检索）。但老套路容易出现两大坑： Brevity Bias（越写越短，丢细节）和 Context Collapse（多轮改写后信息被“磨损”）。作者提出 ACE（Agentic Context Engineering）：把上下文当成可进化的“作战手册”，通过“生成 → 反思 → 策展”的模块化流程，增量式加入“有效战术”，避免信息坍缩。
—
🧩 核心创新点
进化式上下文：不是一次性“Prompt”，而是持续积累的策略库（playbook）。
结构化更新：小步增量（delta）与Grow-and-Refine，保留细节、避免反复改写带来的退化。
在线 + 离线都能用：既能优化系统提示等离线上下文，也能优化 Agent 的在线记忆与流程。
自举式提升：能利用执行反馈（如代码是否跑通、答案校验）在无标注监督下也能变强。
	
📈 效果怎样？
综合提升：在 Agent 与金融推理两类任务上，ACE 平均 +10.6%（Agent）、+8.6%（Finance），同时降低适配时延与推理成本。
真实榜单对比：在 AppWorld 榜单上，ACE + 小型开源模型的组合在总体均分上追平顶级生产级 Agent，并在更难的挑战集上反超；还报告了 ReAct + ACE 在无标注设置下 +14.8% 的提升。
	
🔥 为什么重要？
换条赛道：把“调权重”转为“调上下文”，部署更快、可解释更强，适合企业落地与合规审查。
长上下文时代的正确打开方式：结合长上下文与 KV-cache 等推理优化，不必等训练也能持续进化。
	
✅ 一句话总结
ACE = 把 Prompt 变成会长大的“作战手册”。不用改参数，也能让 LLM/Agent 越用越聪明，在真实榜单和垂直任务上都给出了有说服力的提升。
