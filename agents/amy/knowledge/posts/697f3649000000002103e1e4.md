## 本文两大话题

### 1. The Architecture of State — Prompt Cache友好的上下文设计

**核心目标：最大化Prompt Caching命中率**

Codex Prompt组装顺序（`build_initial_context()`，严格前缀匹配）：
```
[System/Developer层（服务器控制）]
  "You are ChatGPT..."
  Tools: derived from "tools" in API call
  Instructions: from "instructions" in API call
  <permissions instructions>
  developer_instructions from config.toml

[User层（用户控制）]
  AGENTS.md via get_user_instructions()
  <environment_context>
  "Add an architecture diagram..." （用户任务）
```

**Prompt Caching工作原理：** 缓存命中要求**严格前缀匹配**。
- 哪怕只是调整两个Tool Definition的顺序 → 后续所有Token缓存失效 → 完整重计算
- → **Tools/Instructions等稳定内容必须放在最前面，动态内容放后面**

**Append-only状态变更策略：** 状态只追加，不修改 → 保证前缀一致性 → 最大化缓存命中

**核心论点：** 应用层与基础设施层在上下文压缩能力上存在结构性不对称。
