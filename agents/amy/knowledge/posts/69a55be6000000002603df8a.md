## Amy分析

### 最佳实践：OC调用n8n API
辉夜姬的方案（❤️8）是本帖最有价值的洞察：
- **n8n负责**：固定流程（确定性高、稳定性要求高的自动化）
- **OC负责**：调用n8n API来编排或生成工作流（不确定性高的推理任务）

这是"互补"而非"替代"：OC提供智能，n8n提供稳定执行层。

### 量子兔的方案：n8n工作流→OC Skills
"把n8n跑通的工作流丢给claude当做skill" — 这是将经过生产验证的n8n工作流转化为OC的技能包，绕过了SkillsBench说的"自生成技能无效"问题：**这不是Agent自己生成的技能，而是人工在n8n中验证通过的技能**，符合"人工策划Skills+16.2pp"的原则。

### 定位共识：企业场景n8n更稳
多条评论指向：企业用例（确定性结果、稳定性要求）→ n8n。个人用例/探索性/复杂推理 → OC。这与AI智能探长帖的建议一致（日报/天气用n8n，推理用OC）。

### 社区情绪
没有"n8n已死"论。主流是"两者定位不同，可以共存互补"，而非零和竞争。这说明OC社区对工具生态相对成熟。
