Contributing factors:
- Lack of an early `git status` check before writing/committing.
- Confusion about what to stage/commit (initial `git add` / `git add -f` attempts only included scout workspace files, while other modified files existed).
- Possible cross-session leftovers: modified shared docs appear unrelated to the stated heartbeat work.

## Action Taken
- This review artifact was created for evaluator tracking.
- Recommended fix (for scout / session owner):
  1. Start heartbeats with `cd /app/agents && git status --porcelain`.
  2. If unrelated changes exist, **restore** them immediately (`git restore <paths>`) before doing new work.
  3. Only then write artifacts and commit; stage only intended files.

## Learning
- When finish is blocked for uncommitted changes, treat it as a first-class failure mode: stop and clean the working tree before continuing.
- If shared docs are modified unexpectedly, assume they are leftovers from previous activity until proven otherwise; don’t mix them into an unrelated heartbeat commit.
