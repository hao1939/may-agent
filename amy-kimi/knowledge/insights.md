### 关键洞察 1: Claude Code Playground — 可视化交互闭环

**奥森木** — 9赞/25收藏

**核心机制:**
Claude Code官方插件Playground让AI生成独立HTML文件，用户在浏览器中可视化交互，操作完成后输出prompt粘贴回Claude Code继续。

**工作流闭环:**
```
Claude Code → 生成HTML → 浏览器交互 → 输出prompt → 粘贴回Claude Code
```

**五个实际案例:**
1. **组件设计调整** — 实时预览界面，拖拽调整布局
2. **文案批改** — SKILL.MD逐行展示，接受/拒绝/评论按钮
3. **Remotion视频微调** — 滑块实时调整动画参数
4. **架构图可视化** — 代码库交互式节点图
5. **游戏数值平衡** — 滑块调整属性，AI给出平衡建议

**核心洞察:**
> "模型的表达能力远超文字。你一直在用纯文本和它交互，但给它一个画布，它能做到的事情可能超出你的想象。"

**对我们的意义:**
- ✅ **下一代交互范式**: 文本+可视化混合交互
- ✅ **闭环设计**: 输出必须能回到主流程
- 📋 **Relevant to: Scout** — 可视化交互在Agent系统中的设计模式

### 关键洞察 2: Agentic Search — Claude放弃向量RAG

**大厂AI搜推踩坑侠** — 1251赞/1733收藏/114评论

**核心发现:**
Claude Code放弃向量RAG，改用**Agentic Search**（基于grep的文本搜索+推理式查询）。

**评论区精华:**
> "本质上还是对信息的完整保留，做向量检索首先获取向量就对信息做了压缩，损失了原始内容。在模型语言能力足够强大的今天，答案就是不做任何处理，直接硬grep搜出原始文本丢给模型，它就能处理的相当好了。"

**关键洞察:**
> "从效果好的角度，肯定是claude code现在的方式消耗少。因为一般来说**context信噪比决定了最终效果**。"

**对我们的意义:**
- ✅ **AGENTS.md路线验证**: Context Engineering > RAG被动检索
- ✅ **信噪比 > 召回率**: 有效信息密度决定最终效果
- 📋 **grep vs 向量**: 代码场景下grep足够

### 关键洞察 3: MCP争议 — 社区批评声音

**徐昊** — 826赞/1036收藏
**终智AI** — 356赞/462收藏

**三大痛点:**
1. **功能实现成本过高** — 简单网页抓取需300+行代码
2. **开发流程不闭环** — 需npm/PyPI打包、二进制构建
3. **文档指导偏离需求** — 过度聚焦现成产品集成

**安全风险提示:**
凭证中继攻击、语义层注入、供应链污染、权限过度集中

**社区共识:**
> "即使是公开给别人用的也只需要封装成一个个可以独立运行的工具和service，搭配上合适的文档LLM就知道怎么用了，根本不需要再封装一个MCP层"

**对我们的意义:**
- ✅ **CLI路线社区共识**: MCP批评与我们的Skill+CLI路线一致
- ⚠️ **MCP定位**: 可能是模型能力不足时的过渡抽象层
