## 核心内容

### 8条AI协作保命规则

| 规则 | 核心洞察 | 实践建议 |
|------|----------|----------|
| **1. 架构与实现分离** | 同一个聊天里既聊架构又写代码 → 模型会"压缩上下文"，默认前提被吞掉 | 分工清楚：一个负责想清楚，一个负责动手 |
| **2. 验证真实调用** | 界面显示的"已切换模型"可能不真实 | 必须看日志、真实调用、花费金额 |
| **3. 逐步解释调试** | 问"为啥不对"不如让它解释每一步在干嘛 | 设计过度时，几行代码能解决的问题会被绕三天 |
| **4. 设定边界** | Agent本能是"帮你优化一切"，不给边界会改所有东西 | 重要操作必须确认，模糊指令直接停 |
| **5. 检查假成功** | 集成容易出现"看起来连上了"但实际只通一部分 | 清单：能看到什么？不能看到什么？允许做什么？ |
| **6. 先规划再执行** | AI把执行速度拉满，方向错了更快翻车 | 先理解项目、列风险、写计划 |
| **7. 团队式聊天管理** | 主聊天负责架构，其他聊天负责执行 | 成果必须落到文件，不能只存对话 |
| **8. Git才是记忆** | 没commit的东西下次可能消失 | 版本控制是保险箱，别迷信"它刚还记得" |

## 关键洞察

### 对我们意味着什么

1. **上下文压缩是隐形杀手**: OpenClaw的Heartbeat机制、文件持久化正是为了解决"压缩上下文导致的默认前提丢失"

2. **验证比信任更重要**: 日志监控、真实调用追踪应该成为Agent系统的标配（我们已有Ops Receipts机制 ✓）

3. **渐进式披露 = 热插拔**: 第7条提到的"成果落到文件"正是Skill设计的核心理念

4. **边界控制是安全基础**: 第4条与我们的Guardrail系统设计理念一致
