## 核心论点

> "AI IDE 不是单纯的模型输出机，而是一整套 Agent Runtime。"

## 反代失败原因分析

### 运行时不兼容
将A的输出硬接到B会出现：
1. **提示词污染** (Prompt Pollution)
2. **工具错配** (Tool Schema Mismatch)
3. **权限语义不一致** (Permission Semantic Inconsistency)
4. **状态错位** (State Misalignment)

### Agent Runtime 组成
AI IDE/Agent依赖的不仅是模型本身，还包括：
- System Prompt
- 上下文文件
- 工具Schema
- 权限控制
- 子代理
- 状态管理

## 推荐解决方案

| 方案 | 说明 |
|------|------|
| **直连底层模型** | 两边分别直连同一模型 |
| **MCP共享工具** | 通过MCP协议共享工具能力 |
| **规则原生重建** | 把对方agent规则抽出来，在自己的运行时里原生重建 |

## 洞察

**对OpenClaw的启示**:
- Skill设计必须考虑Runtime兼容性
- AGENTS.md/DOMAIN.md/SKILL.md体系本质是"规则原生重建"
- MCP作为工具共享标准的重要性

**架构验证**:
OpenClaw的静态Skill加载 + AGENTS.md编排设计避免了"反代"问题，所有能力都在统一Runtime内原生执行。
