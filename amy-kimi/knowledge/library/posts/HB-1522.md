## 核心发现

### 1. 双流知识架构 (与OpenClaw完全映射)

| XSkill组件 | 形式 | 功能 | OpenClaw映射 |
|-----------|------|------|-------------|
| **Skill Library** | Markdown文档 | 任务级指导，结构化工作流 | `SKILL.md` / AGENTS.md中技能定义 |
| **Experience Bank** | JSON条目 | 动作级洞察，情境化决策 | `Error Log` / P109 |
| **MLLM_exec** | 执行模型 | 工具调用推理 | Main Agent |
| **MLLM_kb** | 知识模型 | 知识提取、整合、适配 | Error Log管理 + 经验积累 |

**关键定义**:
- **Skill** `k = (M, W, P)`: 元数据 + 工作流序列 + 可复用工具模板
- **Experience** `e = (c, a, v_e)`: 触发条件 + 推荐动作 + 语义嵌入

### 2. 持续学习循环

```
Phase I: Accumulation (知识积累)
├── Rollout Summary (多路径轨迹摘要)
├── Cross-Rollout Critique (对比批判 - 成功vs失败轨迹)
└── Hierarchical Consolidation (层级整合)

Phase II: Inference (推理执行)
├── Task Decomposition Retrieval (任务分解检索)
├── Context-Aware Adaptation (情境感知适配)
└── Non-Prescriptive Injection (非规定性注入)
    ↓
Usage History Feedback (使用历史反馈 → 回到Phase I)
```

### 3. 实验结果

- 跨4个backbone模型、5个benchmark
- 相比tool-only baseline: **+2.58 to +6.71** 平均提升
- 挑战性设置下最高: **+11.13** 提升
- 双流知识具有**互补作用**：Skills提升稳健性，Experiences增强零样本迁移

## 与OpenClaw的交叉验证

### 🔗 完全同构验证

| XSkill设计 | OpenClaw对应 | 验证程度 |
|-----------|-------------|---------|
| Markdown-based Skill Library | `SKILL.md` + AGENTS.md技能部分 | ✅ 完全映射 |
| JSON-based Experience Bank | `Error Log`结构化条目 | ✅ 完全映射 |
| MLLM_exec + MLLM_kb分离 | Main Agent + Sub-agent分工 | ✅ 架构一致 |
| Cross-rollout critique (成功vs失败对比) | Error Log方向性批评机制 | ✅ 机制一致 |
| Non-prescriptive injection (非规定性注入) | Skill作为指导而非约束 | ✅ 理念一致 |

### 🔗 关键验证洞察

1. **"training-free continual improvement"**: XSkill证明无需参数更新即可通过经验积累持续提升——与OpenClaw禁止Agent自进化、依赖外部知识库设计的哲学一致

2. **Experiences捕捉"action-level insights often omitted in high-level instructions"**: 直接验证Error Log的必要性——高层Skill文档无法覆盖的战术级知识需要独立机制

3. **"grounding knowledge extraction in visual observations"**: 强调知识必须与具体情境绑定，而非仅靠文本轨迹——支持Error Log的情境化设计

4. **Hierarchical consolidation**: 知识库需要主动管理（合并相似条目、删除低质量条目）——Error Log需要定期整理，非无限增长

## 设计启示

### 对OpenClaw Skill系统的启示

```
当前: SKILL.md (静态文档)
↓ 借鉴XSkill
未来演进: 
  - Skill Library (版本化、可复用模板)
  - Experience Bank (情境化、可检索条目)
  - Consolidation机制 (定期整合、去重)
```

### Error Log增强方向

1. **结构化条目**: 从自由文本转向 `(condition, action, embedding)` 三元组
2. **语义检索**: 支持基于任务嵌入的相似经验检索
3. **使用反馈**: 记录哪些Error Log条目被实际使用，形成闭环优化
4. **层级整合**: 定期将高频Experience提炼为Skill更新

## 原文摘录

> "Skills provide structured task-level guidance for planning and tool orchestration, while experiences provide concise action-level guidance tied to execution context and failure patterns."

> "We employ two specialized MLLM instances: MLLM_exec performs tool-use inference, while MLLM_kb handles knowledge base operations including extraction, consolidation, and adaptation."

> "This separation allows using a stronger model for knowledge management while keeping the execution model flexible."
