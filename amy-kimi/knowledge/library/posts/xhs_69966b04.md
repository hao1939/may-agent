## Summary

Codex 0.102.0更新后支持自定义Multi-Agent角色。以前是三个内置角色，现在可创建任意数量的自定义角色，每个都能独立配置model、reasoning、system prompt、权限、MCP和Apps。

---

## Key Content

### 配置结构

**双层配置体系:**

第一层 — config.toml里注册角色:
- `description`: 告诉Codex什么时候该调这个角色
- `config_file`: 指向详细配置

第二层 — `.codex/agents/`目录:
- 每个角色一个toml文件
- 定义model、reasoning level、developer_instructions等
- 角色配置**只有被实际调用时才加载，不浪费父session的token**

### 配置文件层级化加载

加载优先级：全局`~/.codex/` → 项目根目录 → 子目录（越深优先级越高）

可在monorepo里给不同子项目定义专属角色，比如mobile-app目录下放一个专门的移动端reviewer。

### 9大配置项

| 配置项 | 说明 |
|--------|------|
| Model & Reasoning Level | 如5.3 Codex High |
| developer_instructions | 角色专属system prompt |
| description | 控制何时被调用 |
| 权限 | read-only或read-write沙盒 |
| MCP Servers | 每个角色独立配，如Linear、GitHub |
| ChatGPT Apps | Notion、Monday等按角色开关 |
| Features | memory和shell开关 |
| Scope | 全局或项目级 |
| Personality | verbosity和风格 |

**注意:** 大多数情况只需设model+reasoning+developer_instructions，其他省略自动继承父级。

### 隐藏技巧

1. **突破并行限制**: 默认最多6个并行agent，config.toml里加`[agents] max_threads = 12`就能突破（太多会429限流）

2. **Skill+Subagent互调**: Skills和Subagents可以互相调用，比如frontend_arch角色里写"Use the $frontend-design skill"

3. **输出模板**: developer_instructions里加输出模板，agent会可靠遵循格式输出结构化结果

### 推荐组合

**主编排agent + 执行subagent:**
- 5.3 Codex High做主编排agent：负责规划和全局理解
- Spark作为subagent：负责快速执行实现任务

### 开源资源

25个预置角色已开源在GitHub（am-will/codex-skills/agents），包括:
- security_auditor
- performance
- backend_arch
- product_analyst
- frontend_arch

直接下载放进`.codex/agents/`就能用。

## Amy-Kimi Analysis

**Significance:** L3 — 架构设计参考

**Key Insights:**

1. **Lazy Loading Pattern**: 角色配置延迟加载，不浪费父session token —— 与我们Channel的按需激活理念一致

2. **Hierarchical Config**: 三层配置层级（global→project→subdir）—— 验证了我们Context分层设计的正确性

3. **Role-as-Tool**: Subagent本质是配置化的工具，通过description控制何时调用 —— 与我们的Skill+Gateway设计异曲同工

4. **用户反馈印证**: "配置太麻烦"、"不像Claude code自动" —— 说明易用性是关键差异化因素

**Connection to Our System:**
- Codex的Subagent ≈ 我们的Sub-agent
- 但Codex需要手动配置toml，我们的Gateway可以自动路由
- 这是一个产品化机会：比Codex更智能的Agent调度

**Actionable:** 参考Codex的25个预置角色，考虑为我们的系统设计类似的默认Skill集合。
