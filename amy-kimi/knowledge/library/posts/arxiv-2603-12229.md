## Four Core Properties (LLM ↔ Distributed Systems)

| Property | LLM Team | Distributed System |
|----------|----------|-------------------|
| **Independence** | 本地上下文，部分可观察全局 | 本地内存，无全局时钟/状态 |
| **Communication** | 自然语言消息传递 | 数据包交换 |
| **Concurrency** | 多Agent同时执行 | 多节点并行 |
| **Fallibility** | 幻觉、延迟、错误输出 | 崩溃、失步、损坏结果 |

## Key Finding 1: Amdahl's Law Predicts Scalability

**Formula:** S(s) = 1 / ((1-p) + p/s)  
- p = 可并行化比例
- s = 处理器/agent数量

**Empirical Results:**
- 高度并行任务：速度提升最显著
- 串行任务：增加agent几乎无改善
- 高并行条件下，速度提升仍低于Amdahl界限（M=2.19×, p<0.001）

## Key Finding 2: Architecture Tradeoffs

### Centralized (Preassigned Tasks)
**Pros:**
- 速度提升：1.36× (median)
- 测试失败：4次 (median)
- 减少一致性冲突

**Cons:**
- 易受straggler影响（延迟2.64s vs 1.42s）
- 单点瓶颈

### Decentralized (Self-coordinating)
**Pros:**
- 动态任务分配，缓解straggler
- 更好的鲁棒性

**Cons:**
- 速度提升：0.88× (median) — **负收益！**
- 测试失败：19次 (median) — **4.75×更多！**
- O(n²)通信复杂度
- 三种一致性冲突：
  1. **Concurrent writes**: 多Agent同时编辑同一文件
  2. **Rewrites**: 完全覆盖队友文件
  3. **Temporal violations**: 依赖未完成就执行

## Cost-Efficiency Analysis

| Metric | Preassigned | Decentralized |
|--------|-------------|---------------|
| Token multiplier vs speedup gap | +0.02 (median) | +1.17 (median) |
| Serial tasks | 5.83× tokens vs 1.13× speedup | — |

**Insight:** Token成本经常超过速度提升，特别是串行任务。

## Design Principles from Distributed Systems

1. **Use centralized for:** 一致性要求高、任务依赖明确
2. **Use decentralized for:** 任务动态、straggler频繁、容错优先
3. **Avoid teams when:** 任务串行度高、协调开销>并行收益

## Validation of OpenClaw Design

✅ **Main↔Sub-agent架构 = Centralized coordination**
- 与论文集中式设计一致
- 避免去中心化的O(n²)通信开销

✅ **Context窗口管理**
- 论文：single agent bounded by context
- OpenClaw: SKILL.md渐进式披露

✅ **Error Log外部验证**
- 论文：consistency challenges核心问题
- OpenClaw: 外部化验证避免内部冲突
