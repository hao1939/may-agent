## Key Content

### The 5-Part Structure

**1️⃣ CLAUDE.md = "North Star" Memory 🌟**
- Keep it short! Don't stuff everything
- Contains only: WHY (project purpose), WHAT (repo map), HOW (rules & instructions)
- If too long, Claude will miss important information

**2️⃣ .claude/skills/ = Reusable "Expert Modes" 🛠️**
- Don't rewrite same instructions — turn them into "skills"
- Examples: code review checklist, refactoring manual, release process, debugging flow
- Key for consistency across sessions and team members
- Enables workflow automation

**3️⃣ .claude/hooks/ = Mandatory Guardrails 🚧**
- AI models forget, but Hooks don't
- For must-execute actions: formatting after edits, tests after core changes
- Block modifications to unsafe directories (migrations, auth, billing)
- Critical for automated checks

**4️⃣ docs/ = Progressive Disclosure 📚**
- Don't bloat prompts — Claude doesn't need everything in main context
- Just needs to know where to find truth:
  - Architecture overviews
  - Architecture Decision Records (ADRs)
  - Operating manuals

**5️⃣ Local CLAUDE.md = Dangerous Module Guides ⚠️**
- Small CLAUDE.md files in "sharp" or high-risk modules
- Examples: src/auth/CLAUDE.md, src/persistence/CLAUDE.md, infra/CLAUDE.md
- Provides specific "cautions" when Claude works in those folders

### Core Philosophy
> "Prompts are temporary, structure is permanent."

When organized this way, Claude becomes a native project engineer, not just a chatbot.
