## Key Insights

### 1. Agent三核心特征
- 用LLM驱动决策和工作流执行
- 能调用工具与外部系统交互
- 端到端完成任务而不只是回答问题

### 2. 什么时候该建Agent（三信号）
- 工作流涉及复杂决策（如退款审批需综合判断而非简单阈值）
- 规则集太庞大维护不动（每次改动都可能引发连锁反应）
- 需要处理大量非结构化数据（如理解保险理赔文档）

**如果不满足这三个信号，传统确定性方案可能更简单更可靠。**

### 3. Agent三大基石
**Model + Tools + Instructions**

**模型选型原则:**
- 先用最强模型建基线
- 用eval评估
- 再尝试换小模型优化成本
- 同一个系统里不同任务可以用不同模型

**工具分类:**
- **Data工具:** 获取信息（查数据库、读PDF、搜网页）
- **Action工具:** 执行操作（发邮件、更新CRM）
- **Orchestration工具:** Agent本身作为其他Agent的工具

**指令配置四原则:**
1. 用现有文档转化
2. 拆分复杂任务
3. 明确每步动作
4. 覆盖边界情况

### 4. 编排模式（重头戏）

| 模式 | 描述 | OpenAI建议 |
|------|------|------------|
| 单Agent | 一个Agent带工具在循环里执行直到退出条件 | **先最大化单Agent能力** |
| Manager | 中央协调者分派任务给专业Agent再整合结果 | 需要时再使用 |
| Handoff | 平等的Agent之间互相移交控制权 | 复杂场景 |

**关键建议:**
> "多Agent看起来优雅但也带来额外复杂度。拆分的信号：指令里太多if-then-else分支、工具之间定义重叠模型经常选错、Prompt模板难以扩展。"

### 5. 护栏系统（七层防御）
1. **相关性分类器** — 确保不跑题
2. **安全分类器** — 检测越狱和注入
3. **PII过滤器** — 防止泄露个人信息
4. **内容审核** — 标记有害内容
5. **工具风险分级** — 按低中高评估每个工具
6. **规则防护** — 黑名单和正则过滤
7. **输出验证** — 确保符合品牌价值观

**原则:** 单一护栏不够，要多层组合。

**人工介入触发条件:**
- 超过失败阈值自动升级
- 高风险不可逆操作必须人工确认

### 6. 部署路线四阶段
1. **原型阶段** — 用最强模型证明可行性
2. **优化阶段** — 用eval评估尝试小模型替代
3. **扩展阶段** — 根据需要拆分多Agent完善护栏
4. **生产阶段** — 渐进上线持续迭代

**核心原则:**
> "不要一步到位，从小验证逐步扩展，投入生产后才是开始。"
