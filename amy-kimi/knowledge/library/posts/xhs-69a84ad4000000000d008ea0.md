## 核心内容

作者分享学习Anthropic官方Agent评估文章的心得，原文标题"Demystifying evals for AI agents"。

### 关键洞察

**评估是Agent开发的生命线**
- 没有评估，团队会陷入被动循环——只在生产环境发现问题
- 评估使问题和行为变化在影响用户前可见
- 评估价值随Agent生命周期复合增长

### 评估结构定义

| 组件 | 定义 |
|------|------|
| **Task** | 单次测试，定义输入和成功标准 |
| **Trial** | 单次任务尝试（因模型输出变化需多次运行） |
| **Grader** | 评分逻辑，可包含多个assertions |
| **Transcript/Trace** | 完整执行记录（输出、工具调用、推理、中间结果） |
| **Outcome** | 试验结束时的环境最终状态 |
| **Evaluation Harness** | 端到端运行评估的基础设施 |
| **Agent Harness/Scaffold** | 使模型作为Agent运行的系统 |

### 三种评分器类型

| 类型 | 方法 | 优势 | 劣势 |
|------|------|------|------|
| **Code-based** | 字符串匹配、单元测试、静态分析、状态检查 | 快速、廉价、客观、可复现 | 对有效变体脆弱、缺乏细微差别 |
| **Model-based** | Rubric评分、自然语言断言、成对比较 | 灵活、可扩展、捕捉细微差别 | 非确定性、更昂贵、需人工校准 |
| **Human** | 专家评审、众包判断、A/B测试 | 金标准质量、匹配专家判断 | 昂贵、慢、需规模化专家访问 |

### 两类评估

**Capability (能力) 评估**
- 问题："Agent擅长什么？"
- 起始通过率应低，给团队爬坡空间

**Regression (回归) 评估**
- 问题："Agent还能处理以前能做的事吗？"
- 通过率应接近100%，保护不 regress

### 不同Agent类型的评估策略

**Coding Agent**
- 依赖确定性评分器：代码运行吗？测试通过吗？
- SWE-bench Verified: 给Agent GitHub issues，用测试套件评分
- Terminal-Bench: 端到端技术任务（如从源码构建Linux内核）

**Conversational Agent**
- 评估交互质量本身
- 通常需要第二个LLM模拟用户
- τ-Bench/τ2-Bench: 多轮交互基准
- 多维度评估：票据解决(状态检查)、轮数约束、语气适当(LLM rubric)

**Research Agent**
- 难以二元评分，质量需相对任务判断
- 挑战：专家可能对综合是否全面意见不一
- BrowseComp: 测试Agent能否在开放网页中找到"针"
- 策略：Groundedness检查、Coverage检查、Source质量检查

**Computer Use Agent**
- 在真实或沙箱环境中运行
- WebArena: 浏览器任务，用URL和页面状态验证
- OSWorld: 完整操作系统控制，检查文件系统/应用配置/数据库

### 对OpenClaw的启示

1. **评估基础设施**: 需要系统化构建Evaluation Harness
2. **Grader组合**: Code-based + Model-based + Human 三层评分
3. **Capability vs Regression**: 区分"爬坡评估"和"回归防护"
4. **Agent Harness评估**: 评估的是Harness+Model组合，非仅模型
5. **Transcript价值**: 完整执行记录对调试和改进至关重要
