## Three-Tier Progressive Disclosure Architecture

| Level | Component | Token Usage | OpenClaw Equivalent |
|-------|-----------|-------------|---------------------|
| **Level 1** | Metadata (YAML frontmatter) | 30-100 | Skill header (name/description/trigger) |
| **Level 2** | Instructions (Procedural knowledge) | 200-5,000 | Skill body (workflows/best practices) |
| **Level 3** | Resources (Auxiliary assets) | Unbounded | scripts/, references/, templates/ |

**关键洞察**: Level 1作为"目录"让Agent感知数千Skill而不退化上下文窗口；Level 2作为隐藏元消息修改推理过程；Level 3按需加载。

## Skill Formal Definition (四元组)

论文形式化定义Skill为:
```
S = (𝒞, π, 𝒯, ℛ)
```

| Component | 含义 | OpenClaw映射 |
|-----------|------|--------------|
| **𝒞** (Applicability Conditions) | 触发条件/上下文前提 | `trigger` + `when_to_use` |
| **π** (Policy) | 核心程序知识/执行步骤 | Skill instructions |
| **𝒯** (Termination Criteria) | 完成验证条件 | `success_criteria` |
| **ℛ** (Interface) | 标准化调用边界 | `inputs`/`outputs` schema |

## Four-Stage Security Verification (G1-G4)

| Stage | Name | Mechanism | OpenClaw映射 |
|-------|------|-----------|--------------|
| **G1** | Static Analysis | 可疑模式扫描(eval/exec/网络调用) | 静态代码审查 |
| **G2** | Semantic Classification | LLM验证指令-目的对齐 | AGENTS.md约束验证 |
| **G3** | Behavioral Sandboxing | 隔离容器执行 + 资源监控 | Skill测试环境 |
| **G4** | Permission Validation | allowed-tools清单校验 | `read_by`权限系统 |

**关键数据**: 社区Skill分析显示**26.1%存在漏洞**（数据泄露、权限提升）

## Skill Acquisition Pipeline

### 3.1 Repository Structural Analysis
- 使用repo2AI生成仓库Markdown表示
- 识别核心执行脚本、配置、辅助模块
- 区分可重用模式与项目特定实现

### 3.2 Semantic Skill Identification
**两阶段排序**:
1. **Dense Retrieval**: Bi-encoder编码任务描述与代码模块，余弦相似度筛选
2. **Binary Ranking**: Cross-encoder精细评估，仅超过阈值τ的模块进入提取

**提取标准**:
- Recurrence: 多上下文出现的程序模式
- Verification: 功能完整、文档齐全、无严重bug
- Non-obviousness: 需要领域 expertise 或调试才能发现的逻辑
- Generalizability: 可参数化适应不同上下文

### 3.3 Translation to SKILL.md
- **Frontmatter**: YAML元数据(name/description/version/trigger/dependencies)
- **Instructions**: LLM可消费的程序指导（步骤分解、错误处理、最佳实践）
- **Assets**: 重构脚本消除硬编码路径/API密钥

## Case Study: TheoremExplainAgent & Code2Video

### TheoremExplainAgent (TEA)
- **架构**: Planner + Coding Agent双Agent设计
- **Planner**: 教学设计者，将定理转化为故事板
- **Coder**: 故事板→Manim Python脚本，带多轮错误修正
- **RAG**: 集成Manim文档防止API幻觉

### Code2Video
- **三Agent架构**: Planner + Coder + Critic
- **Visual Anchor Prompting**: 10×10网格将连续视觉转为离散坐标
- **TeachQuiz指标**: 相比基线代码生成模型，**知识传递效率+40%**

## SkillNet: 本体论Skill整合

当Skill库扩展到数十万时，需要统一整合机制:
- **本体关系**: "is-a-subset-of", "requires-output-from"
- **效果**: 30%执行步骤减少，40%平均任务奖励提升
- **功能**: 自动检测冗余/重叠Skill

## The Agentic Stack: Skills vs MCP

| 维度 | Agent Skills | Model Context Protocol |
|------|--------------|------------------------|
| **核心角色** | 程序知识 ("What to do") | 工具连接 ("How to connect") |
| **存储单元** | SKILL.md目录 | JSON-RPC端点Server |
| **状态修改** | 上下文 + 系统权限 | 可用工具 + 外部数据 |
| **持久性** | 文件系统(持久) | 会话级(运行时) |
| **操作本质** | 知识/程序 | 连接/动作 |

**关键洞察**: Skills提供领域智能，MCP提供系统连接，两者正交互补。

## Design Implications for OpenClaw

1. **Skill标准验证**: OpenClaw SKILL.md与Anthropic开放标准完全一致
2. **安全治理**: 需建立G1-G4四级验证流程，当前26.1%漏洞率警告
3. **渐进披露**: 当前设计正确，Level 1元数据让Agent感知全部Skill
4. **Skill挖掘**: 可从GitHub开源Agent仓库自动提取Skill
5. **MCP关系**: Skills层与MCP层正交，需明确两者边界
