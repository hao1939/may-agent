### 产品视角

**小柒:**

### 工程实践洞察

**PigBun-AI:**
> "设计模式总结得不错，但实际落地的时候会发现，选哪种模式不是关键，关键是知道什么时候该从简单模式切换到复杂模式。很多人一上来就搞 multi-agent 协作，结果发现单个 ReAct agent 加几个好用的 tool 就够了。**复杂度是有成本的，调试多 agent 系统的痛苦程度是指数级增长的**。建议先从最简单的模式跑通，遇到瓶颈再升级。"

## L3 Flag

- **L3#351**: 复杂度成本 - 多Agent调试痛苦指数级增长，应先从简单模式开始
- **L3#352**: ReAct看似简单实则调试成本高 - 社区共识的实践经验
- **L3#353**: 模式切换策略 - 知道何时从简单升级到复杂是关键工程能力
