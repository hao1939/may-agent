## 造假实锤要点

▶️ **任务不匹配**
Devin 号称可以解决任意的 Upwork 任务。在视频演示中，要求它解决的问题与客户提出的要求不符（客户要求的是设置说明，而不是代码）。

▶️ **编辑不存在的文件**
画面中，Devin 正在修复 GitHub 仓库源代码中的错误，但它所编辑的文件实际上并不存在于该仓库中，而且它所修复的一些错误毫无道理，属于人类绝不会犯的错误。推论Devin 一定是在修复它自己创建的文件中的错误，但这一点没有明确说明。

▶️ **忽视README**
首先不需要进行任何编码，因为版本库中的 README 已经提供了完成任务所需的所有说明，即使版本库已经过时，只需进行一行调整即可正常运行。这就是为什么客户要求的是如何在 EC2 上运行的说明，而不是一些编码。

▶️ **无意义工作**
Devin 似乎没有阅读 README，也不明白只需执行几个预先存在的 Python 脚本即可。视频中的输出结果让人觉得任务复杂而精密，有一个长长的计划和许多复选框显示已完成的工作，但实际上这些工作毫无意义且多余。

▶️ **代码质量差**
Devin 的代码改动很糟糕，例如自己编写低级文件读取循环，而不是正确使用标准库。

▶️ **时间造假**
虽然视频看起来像是 Devin 很快就完成了任务，视频创建者也能在大约 30 分钟内完成要求的任务，但聊天记录中的时间戳显示任务持续了好几个小时，甚至到了第二天。

▶️ **无意义命令**
Devin 会执行一些无意义的 shell 命令，如 `head -n 5 foo | tail -n 5` 等。

## 争议
PS：有人觉得这样的"造假"可以接受，因为是为了推动自己知名度，从而引发技术爆发。
