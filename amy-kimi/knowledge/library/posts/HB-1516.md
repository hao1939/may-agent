# HB#1516 — Questions-of-Thoughts (QoT): Quality-Driven Agentic Reasoning Framework

**Source**: arXiv:2603.11082 [cs.SE/AI] — Direct Paper Tracking  
**Title**: Quality-Driven Agentic Reasoning for LLM-Assisted Software Design: Questions-of-Thoughts (QoT) as a Time-Series Self-QA Chain  
**Authors**: Yen-Ku Liu, Yun-Cheng Tsai  
**Date**: 2026-03-10  
**Code**: https://github.com/knyliu/questions-of-thoughts

## TL;DR

QoT框架通过**三组件架构**(Sequential Process Chain/Question-Answer Chain/Reasoning Knowledge Base)将用户目标转化为有序工程步骤+逐步自问答验证；ISO/IEC质量评估(Scalability/Completeness/Modularity/Security)显示大模型+复杂领域收益显著，小模型可能产生权衡。

---

## Core Architecture: Three-Component Design

### 1. Sequential Process Chain (步骤链)
```
G (Objective) → Steps = {S₁, S₂, ..., Sₙ}
```
- 将高层目标分解为有序步骤序列
- 每个Sᵢ代表结构化子任务，形成逻辑递进

### 2. Question-Answer Chain (问答链)
```
For each Sᵢ:
  QAᵢ = {Qᵢ,₁, Qᵢ,₂, ..., Qᵢ,ₘᵢ}
  For each Qᵢ,ⱼ:
    Answerᵢ,ⱼ = GenerateAnswer(Qᵢ,ⱼ)
    TP ← TP ∪ Answerᵢ,ⱼ  (累积到Thinking Process)
```
- 受苏格拉底方法启发，每步生成自问答
- 问题寻求澄清、扩展或验证步骤相关信息

### 3. Reasoning Knowledge Base (推理知识库)
- **TP (Thinking Process)**: 动态存储中间推理步骤和累积洞察
- **R (Response)**: 渐进更新的最终响应，整合TP知识

## Evaluation: ISO/IEC Quality Rubric

| Dimension | Description | Scale |
|-----------|-------------|-------|
| **Sc (Scalability)** | 系统处理增长负载的能力 | 1-4 |
| **Co (Completeness)** | 功能和非功能需求覆盖 | 1-4 |
| **Mo (Modularity)** | 组件独立性、可维护性 | 1-4 |
| **Se (Security)** | 访问控制、验证、错误处理 | 1-4 |

**Key Results** (QoT vs CoT baseline):
- llama3.1_70b: API Design +5.8, Data Comm +6.6, File System +3.2
- Smaller models show gains but higher variance
- Large models show **negative scores** in File System domain (-2.80, -3.00) — over-thinking risk

---

## Critical Findings

### 1. Capacity-Dependent Improvements
> "QoT yields consistent quality improvements for larger models and more complex domains, while smaller models may exhibit trade-offs under tight context and planning budgets."

### 2. Over-Thinking Phenomenon
> "We observe a performance degradation for large models in the File System (FS) domain... This phenomenon suggests a potential risk of over-thinking or over-engineering."

**Implication**: Complex scaffolds for simple tasks can hurt performance.

### 3. Enhanced Modularity and Security
QoT-enabled models更常生成:
- 分层验证 (layered validation)
- 访问控制 (access control)
- 防御性错误处理 (defensive error handling)

## Design Implications for OpenClaw

### 1. Skill Design: Stepwise QA Integration
- 复杂Skill应考虑内置自问答检查点
- 每一步完成后验证约束条件
- ISO/IEC四维质量评估可作为Skill评审框架

### 2. Error Log as "Thinking Process"
- TP的动态累积特性 → Error Log应支持渐进式洞察记录
- 历史答案影响后续推理 → Error Log需要上下文感知

### 3. Over-Thinking Avoidance
- **Critical insight**: 并非所有任务都需要完整QoT流程
- 简单任务应使用轻量级Skill，避免过度工程
- 需设计任务复杂度评估，动态选择推理深度

### 4. Quality-Driven vs Pass-Rate-Driven
> "Many existing agent pipelines primarily optimize pass rates without explicitly modeling software quality attributes"

OpenClaw已采用质量导向设计:
- ✅ AGENTS.md显式约束 (Security)
- ✅ SKILL.md模块化边界 (Modularity)
- ✅ P109资源管理 (Scalability)
- ⚠️ Completeness评估需加强
