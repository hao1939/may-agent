## 运作机制对比

### 📌 RAG（检索增强生成）
1. **查询与向量化**（检索阶段）: 从数据源检索，向量数据库提取数据
2. **提示词增强**（增强阶段）: 检索结果与用户查询及系统提示词融合
3. **大模型输出**（生成阶段）: LLM基于整合信息生成响应

### 📌 AI智能体（Agent）
1. **查询处理**: 接收并分析用户请求
2. **记忆与规划**: 利用记忆框架（ReACT、Reflexion）制定策略
3. **工具调用**: 通过外部工具获取实时数据
4. **输出生成**: 结合工具信息与记忆库推理优化

### 📌 协同运作
- 智能体**动态管理**RAG的向量检索，根据查询需求选择数据源
- 智能体在RAG增强提示词基础上，加入**规划能力**与**实时工具数据**

---

## 完整工作流示例

```
1. 查询路由 → 智能体协调处理用户请求
2. 上下文保留 → 短期/长期记忆跟踪对话状态
3. 任务规划 → 制定检索策略并选择工具
4. 数据获取 → 从知识库抓取实时信息
5. 提示词优化 → 融合检索数据、查询与系统提示
6. 响应生成 → LLM输出最终结果
```

## 评论区关键洞察

### 工程本质论 (林海)
> "Agentic RAG本质上也是一个工程系统方法论的产物，本身并没有什么创新，在特定的系统中是比较容易实现的...所以并不能做通用的产品"

作者@米小卷回应："没错，也是一套架构设计"

**核心启示**: 
- Agentic RAG的价值在于**架构设计**而非概念创新
- 需要**场景定制**，非通用方案
- 验证了我们**场景化设计**的重要性

## 与OpenClaw的关联

### 🔗 工作流映射
| Agentic RAG步骤 | OpenClaw对应 |
|----------------|-------------|
| 查询路由 | Main Agent决策层 |
| 上下文保留 | AGENTS.md + SESSION.md |
| 任务规划 | Skill选择逻辑 |

- **AGENTS.md的被动注入**对应RAG的"提示词增强"阶段
- **Skill的动态选择**对应Agent的"记忆与规划"
