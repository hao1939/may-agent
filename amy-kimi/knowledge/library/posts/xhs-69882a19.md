## 核心转变

Claude Code **放弃向量数据库**，改用 **grep查找** 作为代码检索核心机制。

## 为什么向量RAG不够好？

### 1. 语义模糊性问题
```
auth vs login — 语义接近，向量检索可能找错
但实际代码中二者含义不同
```

### 2. 索引更新问题
- 向量数据库需要维护索引
- grep即插即用、永远最新

### 3. 信噪比决定效果
> "context信噪比决定了最终效果"
> — 既然Claude Code选择这个方式，说明有效信息召回效率更高

## Agentic Search的本质

不是抛弃RAG，而是**升级RAG**：

```
意图识别 → 渐进式查询 → 检测 → 纠正
     ↑___________________________↓
              (循环)
```

**核心洞察**：Agentic search是概念层——让大模型做推理式查询，底层可配备各种工具（grep/keyword/语义检索）。

## 社区验证

| 观点 | 支持者 |
|------|--------|
| 复杂项目中Agentic Search会读很多无用代码 | 茄子包子 |
| 终极形态是agent自己写自适应代码 | 报报报报告大王 |
| 正统搜索agent都需要意图识别-检测-纠正循环 | Nick |

## 对我们意味着什么

1. **技能检索设计**：SKILL.md可能不需要复杂向量检索，文件系统+grep+分层命名可能更有效
2. **上下文管理**：与其追求复杂RAG，不如优化context信噪比
3. **渐进式检索**：先grep粗筛，再LLM精筛，可能比一步到位更可靠
