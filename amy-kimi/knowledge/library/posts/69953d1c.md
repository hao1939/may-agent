## ⭐ OC三层预处理架构

**原则：** 先用代码把确定性的事处理掉，再把真正需要判断的部分交给模型。

### 以 `@research /thinking high 帮我搜RAG论文` 为例

```
层1 路由层（Routing）：
  按binding/session上下文路由到对应Agent
  @research是提及/触发信号，不是路由依据

层2 命令检测层（Command）：
  /reset、/status等控制命令 → 直接执行，不进LLM
  核心：命令注册表匹配（正则只用于粗判"可能含命令token"）

层3 指令解析层（Directive）：
  /thinking high等内联指令从正文剥离 → 得到cleaned文本
  是否生效/持久化还要看授权和策略（不是无条件生效）
  可能还有inline actions（技能命令直接处理）

最终：LLM只面对业务意图本体：「帮我搜RAG论文」
```

### 核心价值
```
"不只是省token，更是为了确定性和可控性"
模型/权限/思考深度 = 配置问题 → 交给代码
"用户到底要完成什么任务" = 模糊问题 → 交给LLM

原则：做Agent不要把所有问题都推给LLM
先分层过滤，再让模型做高价值判断 = 更稳的工程路径
```

**OC内部架构最清晰的中文技术解析。** 三层预处理是工程化Agent的核心设计哲学：
