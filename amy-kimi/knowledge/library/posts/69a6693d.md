## 正文
你以为 AI Agent 的核心竞争力是模型？错了。

同一个 Claude Opus 4.5，换一套编排框架（Harness），CORE-Bench 得分直接从 **42% 飙到 78%**。模型一行代码没改，性能翻了将近一倍。

Cursor 做了个实验：把工具定义从"全量加载"改成"按需懒加载"，Token 消耗直降 **46.9%**。Vercel 更狠——**删掉 80% 的工具**，Agent 反而从"完不成任务"变成了"轻松搞定"。

所以到底什么是 **Harness**？

打个比方：AI 模型是 F1 赛车手，Harness 就是整辆赛车。同一个车手，开破车还是开红牛 RB20，成绩天差地别。Harness 包括执行循环、工具定义、信息管理、错误恢复、状态追踪——**模型之外的一切**。

## 5家顶级公司的Harness架构拆解

### Claude Code — Anthropic的极简哲学
- 只给模型 **18个原语工具**
- 用 bash 和 grep 替代复杂集成
- **TodoWrite**: 一个什么都不做的"空操作"工具，但能迫使 Agent 把计划说出来，保持长任务不跑偏

### Cursor — 按模型定制Harness
- 不同模型拿到不同的工具名、提示词和行为指导
- 自己训练语义搜索模型，搜索准确率提升 **12.5%**

### Manus — KV-Cache至上
- 框架重写了 **5次**
- 用 **logit masking** 控制工具可用性，而不是动态增删工具定义（会导致缓存失效）
- **核心哲学：最大的性能提升来自删东西**

### SWE-Agent — Agent-Computer Interface
- 所有代码编辑必须过 **linter 检查**，没通过就打回重试
- 去掉这道关卡，性能下降 **3%**

### Devin/Windsurf/Aider/Replit
- **Devin**: Playbook 系统把 PR 合并率从 34% 拉到 **67%**
- **Aider**: 用 PageRank 给代码仓库画地图
- **Replit**: 三个 Agent 组成自愈循环

## 行业共识与黄金法则

**最有意思的发现**：所有公司都收敛到了同一个核心模式——

### Progressive Disclosure（渐进式披露）
不是把所有信息一股脑塞给模型，而是只展示当前需要的，复杂度按需揭示。

> 这个来自 **1980 年代 IBM UI 设计** 的理念，如今成了 Agent 架构的黄金法则。

**行业共识：**
- ✅ 单一扁平循环优于复杂 DAG
- ✅ 文件系统就是最好的扩展记忆
- ✅ 原语工具胜过定制集成

**仍在争论：**
- ❓ 工具太多了怎么办？全加载还是按需加载？
- ❓ Harness 该管多少，还是直接把 2M 上下文窗口全给模型？
