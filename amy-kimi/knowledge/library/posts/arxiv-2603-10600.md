## 核心贡献

提出从Agent执行轨迹自动提取可行动学习并通过上下文记忆检索提升未来性能的框架。

### 四组件架构

| 组件 | 功能 |
|------|------|
| **Trajectory Intelligence Extractor** | 对Agent推理模式进行语义分析 |
| **Decision Attribution Analyzer** | 识别导致失败/恢复/低效的具体决策 |
| **Contextual Learning Generator** | 生成三类指导：Strategy/Recovery/Optimization Tips |
| **Adaptive Memory Retrieval System** | 基于多维度相似性注入相关学习 |

### 三类Tips

```
Strategy Tips    → 从Clean Success提取的有效模式
Recovery Tips    → 从Failure→Recovery提取的错误处理
Optimization Tips → 从Inefficient Success提取的效率改进
```

## 关键洞察

### 现有记忆系统的四大局限

论文批评Mem0、Letta等通用记忆系统：

1. **缺乏执行模式理解** — 统一处理所有记忆，不区分策略/恢复/优化
2. **无法因果分析** — 存储结果但不存储产生结果的决策链
3. **缺乏结构化学习提取** — 自由文本，无指导Agent所需的结构
4. **无溯源追踪** — 无法验证学习是否有效或调查指导生成原因

> "naive experience accumulation leads to error propagation and misaligned replay"

### 因果归因的三层分析

| 层级 | 定义 | 用途 |
|------|------|------|
| Immediate Cause | 直接触发失败的因素 | 快速定位 |
| Proximate Cause | 导致直接因素的近期决策 | 中期分析 |
| Root Cause | 链式反应的原始问题 | 深度修复 |

## 实验结果 (AppWorld Benchmark)

| 指标 | 提升 |
|------|------|
| 整体Scenario Goal完成率 | **+14.3 percentage points** |
| 复杂任务Scenario Goal | **+28.5 pp (149%相对提升)** |

复杂任务收益最大 — 学习经验在高复杂度场景最有价值。

## 对OpenClaw的关键验证

### 1. Error Log设计的理论支撑 ✅

论文的框架与OpenClaw的Error Log设计**高度一致**：

| 论文组件 | OpenClaw对应 |
|----------|-------------|
| Trajectory Intelligence Extractor | Error Log收集 + 模式识别 |
| Decision Attribution Analyzer | 执行验证(Execution Verification) |
| Contextual Learning Generator | Error Log → Skill改进 |
| Adaptive Memory Retrieval | AGENTS.md中的Error Log引用 |

### 2. 三类Tips与L0-L3约束层映射

| Tips类型 | 约束层 | 语义 |
|----------|--------|------|
| Strategy Tips | L1-L2 | 最佳实践指导 |
| Recovery Tips | L2-L3 | 错误恢复机制 |
| Optimization Tips | L3 | 效率优化建议 |

### 3. 禁止运行时自进化的验证

论文强调：
- 学习发生在**编译期**（轨迹分析→记忆生成）
- 运行时仅进行**检索和注入**，不进行自我修改
- 与OpenClaw"训练时进化，禁止运行时自修改"立场**完全一致**
