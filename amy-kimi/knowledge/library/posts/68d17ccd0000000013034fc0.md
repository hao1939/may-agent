具体environment实现的方式是提出了一个meta agent research environment (are)，实现了一些tools（例如email，calendar等），然后基于file system来模拟执行。（p3）
整体上仍然打real-life application，比较有趣的点：
1. 核心的改进点是从read-only application到read&write（Gaia 的前身就是偏“读”的问答检索～open domain question answwring）。这个点上，有些类似于最近社区一些其他工作比如mcp-universe，mcpmark，mcp-agentbench。
2. “会用工具 ≠ 可靠”：简单执行与检索分项，头部模型基本过线；真正拉开差距的是歧义处理、环境变化与噪声容错。
3. 时间分项最难：带时延、窗口、相对时间的任务是当前最普遍的失败源（比如“3 分钟后再下单”这类需要等待与校对的操作）。
4. 别只看分数，还要看成本：官方同时做了成本归一化（LLM 调用次数与输出 token），强调“同分更省”才是真提升。（p4）
5. 整体上，GPT-5（高推理）总体最好，开源里 Kimi K2 最优，但分项差异很大；挑任务适配模型，收益远大于盲目追热榜。（p5）
🏷️ 除此之外，我觉得给agent产品的几个比较重要的insights：
1. 推理成本非常重要。multi-turn function calling可能是一个通用建模方式，实际上效率比较低。本文没有对agent framework做太多的实验，而是只focus在模型自己调用工具的efficiency上面。实际工作里，这决定了能不能把智能体规模化上线。
2. 考虑agent-to-agent的scalability，我觉得这可能是一个需要提前布局的方向。
最大的体感是，又多了一座山要爬，但好在这是一座有趣且越来越清晰的山。

# Meta发布GAIA2，agent evaluation要变天了？

作者短暂的在GAIA上获得过SOTA，这次速读了一下GAIA2。整体上仍然打real-life application，比较有趣的点：

1. 核心的改进点是从read-only application到read&write（Gaia 的前身就是偏"读"的问答检索 ~ open domain question answwring）。这个点上，有些类似于最近社区一些其他工作比如mcp-universe，mcpmark，mcp-agentbench。

2. "会用工具 ≠ 可靠"：简单执行与检索分项，头部模型基本过线；真正拉开差距的是歧义处理、环境变化与噪声容错。

[Slide 2]
3. 时间分项最难： 带时延、窗口、相对时间的任务是当前最普遍的失败源（比如"3 分钟后再下单"这类需要等待与校对的操作）。

4. 别只看分数，还要看成本： 官方同时做了成本归一化（LLM 调用次数与输出 token），强调"同分更省"才是真提升。

5. 整体上，GPT-5（高推理）总体最好，开源里 Kimi K2 最优，但分项差异很大；挑任务适配模型，收益远大于盲目追热榜。


除此之外，我觉得给agent产品的几个比较重要的insights：


1. token as first-class citizen。实际工作里，这决定了能不能把智能体规模化上线。

2. 考虑agent-to-agent的scalability，我觉得这可能是一个需要提前布局的方向。


最大的体感是，又多了一座山要爬，但好在这是一座有趣且越来越清晰的山。
