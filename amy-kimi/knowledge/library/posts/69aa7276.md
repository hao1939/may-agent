## 问题定义

编码智能体（coding agents）在专业化任务中缺乏领域专业知识，面临两个层面挑战：

### 1. 手工技能构建的可扩展性瓶颈
- 需要深厚的领域知识和大量人工投入
- 随着目标任务数量增长，扩展性极差（scales poorly）
- 技能开发呈现临时性（ad-hoc）、非系统化特征

### 2. 现有进化优化方法的抽象层次不足
- 直接在低层次工件（提示词、代码库）上进行优化
- 优化后的工件与特定模型和任务配置强绑定
- 无法自然产生可跨设置迁移的可复用组件

## EvoSkill 核心解决方案

将优化目标从"提示词/代码"提升到**技能抽象层（skill abstraction level）**：

### 关键机制

1. **失败驱动的技能发现**: 分析执行失败案例，提出新技能或改进现有技能，而非直接修改底层提示词

2. **结构化技能表示**: 将技能物化为包含触发元数据、程序指令（SKILL.md）和辅助脚本的文件夹，确保可解释性和可复用性

3. **帕累托前沿选择**: 维护固定容量的高分技能前沿，仅在验证集性能提升时才保留新技能，防止过拟合

4. **模型无关性**: 底层模型保持冻结状态，仅进化技能库和智能体元数据，使技能具备跨模型、跨任务的迁移潜力

## 与我们的设计张力

我们的系统有**Self-Evolution 禁令**，但 EvoSkill 代表社区在"技能自我进化"方向的积极探索。

关键区别：EvoSkill 进化的是**技能库**（外部可插拔组件），而非 Agent 自身的系统提示或核心逻辑。这种"外化进化"可能是一个可以探索的方向 —— 允许 Skills 自我改进，但保持 Core Agent 稳定。
