# Anthropic发布Skills和MCP协同工作指南

## 核心问题

Skills vs MCP：两者都在"增强Agent能力"，边界模糊。Anthropic官方12月19日发布博客《Extending Claude's capabilities with skills and MCP servers》专门回答。

## 社区关键洞察

**Neinei**: "Skill不就是mcp的提示词吗" — 17赞，被认为"精辟"

**演丶眠忆**: "一个解决接口，一个解决流程" — 23赞，被认为是比"SOP vs 协议"更清晰的解释

**佐治亚小帅北美播客**: "一内一外"

**做AI的奶爸**: "skills也可以定义tools，但是要local。对于个人来说反而更好，把自己的脚本直接放进去比搞mcp方便"

## 官方区分（作者解读）

- **Skills**: 告诉agent以一个方法论自主完成任务，不是节点任务流
- **MCP**: 外部工具接口

## 讨论焦点

- Context7从MCP切换到skill的原因
- Skill文件太长，RAG无法全面考虑，prompt可能撑不下 → "渐进式披露方式来加载skill"
- Cursor暂不支持skills，需用opensource等方案间接支持

## 洞察

Skills vs MCP不是替代关系，而是互补：
- MCP = 外部能力接口（工具调用）
- Skills = 内部方法论封装（流程定义）

OpenClaw的AGENTS.md更接近Skills范式，而Tools目录接近MCP范式。两者的融合可能是未来方向。
