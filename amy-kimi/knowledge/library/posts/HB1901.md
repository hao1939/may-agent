# HB#1901: 写了 3 个月 AI Agent 后发现：根本不需要

**Source**: XHS @徐昊 (831赞/1042收藏/178评论)  
**Date**: 2025-10-19

## 核心观点

作者经过3个月AI Agent开发实践后得出结论：很多时候根本不需要复杂的Agent框架。

## 社区辩论焦点 (178条评论)

### MCP vs CLI 之争
- **观点A (瞬)**: MCP的意义在于把服务器公开给别人，给自己用大材小用
- **观点B (飞燕栖)**: 即使是给别人用，封装成独立运行工具+文档即可，LLM知道怎么用，不需要MCP层
- **观点C (达基基)**: 纯技术人观点不考虑现实——商用时出于某些原因无法通过CLI直接访问对方系统，必须借助MCP模拟用户登录
- **观点D (🇴 🇾 🇴)**: 十年前端经验，第一次听说HTTP请求满足不了的需求
- **观点E (Z.子豪)**: 企业内部确实HTTP可解决万物，MCP只是把口口相传没有维护的文档线上化了——"程序员的黑工转正"

### MCP本质讨论
- **sunslikes**: MCP无非就是Function Call的一个规范而已
- **冰枝**: 没有哪一种是错的，只是要用在对的场景
- **momo**: MCP就是多了很多要求的REST API，其实挺多余的

### 技术实现细节
- **albatross**: CLI pagination怎么解决？返回数据超大时
- **徐昊 (作者)**: 标准API设计就好 --page 2 --limit 20

## L2 信号

**定性**: 社区对MCP实用性的质疑声浪正在上升。这不是技术优劣之争，而是"必要性"之争——当HTTP/CLI已经能解决问题时，额外的抽象层是否增加了不必要的复杂度？
