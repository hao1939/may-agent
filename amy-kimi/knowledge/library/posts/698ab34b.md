## 正文
最近 Claude Code 更新到 Opus 4.6 之后，我明显感觉整体跑得慢了一些 😅 不过新出的 Agent Team 模式能追回一部分速度 💨

它的核心体验是：能**多agent并行协调任务**

下面是懒人版教程，详细用法可以参考官方文档搜 **Orchestrate teams of Claude Code sessions**，图二图三是基于文档总结的速查表。

### ⚙️ Agent Team 怎么开？
配置环境变量 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` 为 `1`

懒得配置环境变量的朋友 🫠 直接告诉 Claude Code 让它帮你配也行～

### 📋 Agent Team 模式流程
1️⃣ **先进入 plan mode**，讨论出具体需要解决的问题

2️⃣ **告诉 Claude Code**: 「Create an agent team 并行执行计划」

然后你就会看到它开始自动化操作 👇

- 🔧 **自己拆分 Phase**（基础层先做、UI 并行、最后收尾）
- 🤖 **自己分配 agent**（谁负责 engine / challenge-ui / presentation-ui）
- ⏳ **自己控制并发和等待**（依赖没满足就先挂起，满足后自动接手）

整个过程你只需要坐着看它协调就行 🍿 体验很丝滑～

## Amy 的分析

**核心洞察：Claude Code 正式进入多Agent协调领域**

Claude Code Opus 4.6 的 Agent Team 模式标志着 Anthropic 官方开始支持多Agent并行协调，这与 OpenClaw 的多Agent设计方向一致。

**技术细节：**
```
开启方式: CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1

工作流程:
Plan Mode → Create Agent Team → Auto Orchestration
                ↓
    ┌───────────┼───────────┐
    ↓           ↓           ↓
 Phase拆分   Agent分配    并发控制
(基础→UI→收尾) (engine/UI) (依赖等待)
```

**关键特性：**
1. **自动Phase拆分** — 识别任务依赖关系，基础层先做，UI层可并行
2. **角色化Agent分配** — engine / challenge-ui / presentation-ui 等角色
3. **智能并发控制** — 依赖未满足时自动挂起，满足后自动恢复

**对我们系统的意义：**
🔴 **竞争信号** — Claude Code 原生的多Agent协调能力将直接与 OpenClaw 的 Agent Team 形成竞争
★ **验证方向** — 多Agent并行是行业共识，我们的设计方向正确
⚠️ **差异化机会** — Claude Code 的 Agent Team 是实验性功能(EXPERIMENTAL)，且局限于Claude Code生态；OpenClaw 的跨模型、跨工具Agent协调仍有优势
★ **架构参考** — 其"Plan → Team → Orchestrate"流程与我们的设计哲学中 "Explore → Delegate → Synthesize" 相似
