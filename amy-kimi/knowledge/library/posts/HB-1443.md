# 让 Claude Code 帮我写代码，结果动了40个我不知道的文件

## 核心内容

用户让 Claude Code 添加一个登录功能，两小时后：
- **改了40个文件**
- **其中2个已经坏了**

作者反思："不是 AI 的问题——是我没有工作流。"

## 关键洞察

### 1. 工作流缺失 = AI失控
这是社区首次明确将 AI 代码修改失控归因于"工作流"缺失，而非模型能力不足。

### 2. 与我们设计的对应
- **Error Log审计**: 40个文件修改中，2个损坏但用户事后才发现 → 需要实时审计
- **read_by追踪**: 用户"不知道"改了哪些文件 → 需要显式确认机制
- **L2/L3分层**: 简单功能(登录)不应触发大规模文件修改 → 需要影响范围评估

### 3. 社区痛点验证
- 这是高频痛点：Claude Code/Cursor 等工具"静默修改"引发的问题
- 用户核心诉求：可控性 > 自动化程度
