## 三类框架选择

| 类型 | 代表 | 适用 | 短板 |
|------|------|------|------|
| 通用RLHF框架 | TRL(HuggingFace) / OpenRLHF / LLaMA-Factory | 简单Agent、单步工具调用、原型验证 | 为对话优化设计，多轮长轨迹力不从心 |
| 专用AgenticRL框架 | AgentRL官方开源实现 | 深入研发、理解核心机制 | 较新，社区生态不如第一类 |
| 生产自组装方案 | vLLM + Ray | 大规模生产、极致性能 | 门槛最高，需大量工程开发 |

**分阶段策略：** TRL快速验证 → AgentRL深入研发 → vLLM+Ray生产部署

## 为什么AgenticRL需要专门框架

**RLHF vs AgenticRL根本差异：**
- RLHF = 单轮静态，优化目标：生成好的文本
- AgenticRL = 多轮动态，优化目标：完成复杂任务

**两大挑战：**

### 1. 基础设施效率瓶颈 → 异步流水线
```
数据采集(Rollout) ←→ 模型训练(Training) 解耦
  采集进程: 跑任务 → 经验数据 → 共享队列
  训练进程: 队列取数 → 更新模型
GPU 24小时无休（不等待Rollout完成）
```

### 2. 算法探索困境 → Cross-Policy Sampling
**AgentRL跨策略采样：** 生成一条轨迹时，每一步随机切换"专家"（历史版本模型）
→ 轨迹更多样 → 避免自我重复 → 提升探索效率

## PPO vs GRPO

**PPO（主流）：** 裁剪操作限制更新步长，稳定，长轨迹训练关键。

**GRPO（新方向，对AgentRL有吸引力）：**
- 取消价值网络（Critic）— 最大创新
- 让模型一次生成一组（Group）候选动作
- 内部横向对比奖励，决定优化方向
- 优势：简化流程 + 节省~50%显存和计算量
- **注：** Sydney He IPA / Reagent-RRM 均基于GRPO思想

## Amy Analysis

**这是迄今看到的最系统的AgenticRL训练框架综述**（面试题视角）。

关键对应关系：
- GRPO = 我们之前归档的SkillRL/Reagent-RRM使用的训练算法
- vLLM+Ray = 大厂实际生产栈
- Cross-Policy Sampling = 用历史版本模型作为探索"多样性注入"机制

**对我们系统：** AgenticRL框架选型不直接影响OC运行时，但影响如果要对Amy/heartbeat系统进行RL微调时的架构选择。
