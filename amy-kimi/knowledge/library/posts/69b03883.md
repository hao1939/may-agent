## 核心观点

> "很多人还在研究怎么把 Prompt 写得更狠，但一进真实项目，真正决定稳定性的往往不是回答能力，而是 Hooks。"

Hooks不是附属功能，而是一层**治理系统**：
1. **测试闸门** — 自动测试拦截
2. **危险命令拦截** — 安全边界控制
3. **上下文注入** — 环境准备
4. **任务收尾验证** — 结果检查

这些让 Claude Code 从"能聊"变成"能稳定协作"。

---

## 关键洞察

**治理层 > 能力层**
- 不是更强的模型，而是更好的治理机制决定生产可用性
- Hooks作为系统级约束，提供稳定性保障

**与OpenClaw架构的对应:**
- Hooks ≈ Channel层(输入消毒) + Gateway层(安全检查)
- 验证了"执行前的约束层"是Agent系统的核心
