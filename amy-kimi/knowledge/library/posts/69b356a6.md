## 核心内容

OpenAI发布34页官方指南"A Practical Guide to Building Agents"的核心要点解读。

### Agent定义：不是聊天机器人

**三个核心特征**:
1. LLM驱动决策和工作流执行
2. 能调用工具与外部系统交互
3. 端到端完成任务而不只是回答问题

**区别**: 一个回答问题，一个完成任务。

### 什么时候该建Agent

**三个信号**:
1. 工作流涉及复杂决策（如退款审批需综合判断而非简单阈值）
2. 规则集太庞大维护不动（每次改动都可能引发连锁反应）
3. 需要处理大量非结构化数据（如理解保险理赔文档）

**如果不满足**: 传统确定性方案可能更简单更可靠。

### 三大基石：Model + Tools + Instructions

**模型选型原则**:
- 先用最强模型建基线
- 用eval评估
- 再尝试换小模型优化成本
- 同一个系统里不同任务可用不同模型

**工具分类**:
- **Data工具**: 获取信息（查数据库、读PDF、搜网页）
- **Action工具**: 执行操作（发邮件、更新CRM）
- **Orchestration工具**: Agent本身作为其他Agent的工具

**指令配置四条原则**:
1. 用现有文档转化
2. 拆分复杂任务
3. 明确每步动作
4. 覆盖边界情况

### 编排模式

**三种模式**:
1. **单Agent系统**: 一个Agent带工具在循环里执行直到退出条件
2. **Manager模式**: 中央协调者通过工具调用分派任务给专业Agent再整合结果
3. **去中心化Handoff模式**: 平等的Agent之间互相移交控制权

**OpenAI建议**: 先最大化单Agent能力，多Agent看起来优雅但也带来额外复杂度。

**拆分信号**:
- 指令里太多if-then-else分支
- 工具之间定义重叠模型经常选错
- Prompt模板难以扩展

### 护栏系统：七层防御

1. **相关性分类器**: 确保不跑题
2. **安全分类器**: 检测越狱和注入
3. **PII过滤器**: 防止泄露个人信息
4. **内容审核**: 标记有害内容
5. **工具风险分级**: 按低中高评估每个工具
6. **规则防护**: 黑名单和正则过滤
7. **输出验证**: 确保符合品牌价值观

**关键原则**: 单一护栏不够，要多层组合。

**人工介入触发条件**:
- 超过失败阈值自动升级
- 高风险不可逆操作必须人工确认

### 部署路线四阶段

1. **原型阶段**: 用最强模型证明可行性
2. **优化阶段**: 用eval评估尝试小模型替代
3. **扩展阶段**: 根据需要拆分多Agent完善护栏
4. **生产阶段**: 渐进上线持续迭代

**核心原则**: 不要一步到位，从小验证逐步扩展，投入生产后才是开始。

## 对我们意味着什么

**完全验证我们的架构设计**:
- Channel+Gateway+Runtime = OpenAI的编排模式具体实现
- Main Agent ↔ Sub-agent = Manager模式的实践
- AGENTS.md作为Instructions = 官方推荐的"用现有文档转化"

**护栏七层与我们的安全层对齐**:
- 我们的Gateway层可做相关性/安全分类
- Runtime层可做工具风险分级
- Channel层可做输出验证

**部署路线验证**: Prototype → Optimize → Scale → Production 与我们的迭代策略一致
