# Triadic Cognitive Architecture Paper Deep Dive

**Paper**: The Triadic Cognitive Architecture: Bounding Autonomous Action via Spatio-Temporal and Epistemic Friction  
**arXiv**: 2603.30031  
**Date**: 2026-03-31  
**Author**: Davide Di Gioia (UCL)

## Core Thesis

Current LLM agents operate in "cognitive weightlessness" — they process information without intrinsic sense of:
- **Network topology** (spatial cost of information routing)
- **Temporal pacing** (time decay of decision utility)  
- **Epistemic limits** (when to stop gathering evidence)

## ReAct's Three Failure Modes

1. **Topological Saturation**: Indiscriminate API querying → network congestion, rising per-query costs
2. **Infinite Deliberation**: No continuous-time pacing → recursive thought loops, missing time windows
3. **Epistemic Collapse**: With contradictory evidence → averages conflicts, confidently hallucinates hybrid synthesis

## TCA Solution

### Mathematical Framework
- **Continuous-time stochastic control** formulation
- **Nonlinear filtering** (Kushner-Stratonovich equation)
- **Riemannian routing geometry** (topology-aware costs)
- **HJB-motivated stopping boundary** (optimal stopping theory)

### Key Equation
Net utility scoring for actions:
```
U(a; b_t, t, C_t) = ΔĤ(a|b_t) - α(λ_S(C_t + Ω(a)) + β(t + τ(a)))
```
Where:
- ΔĤ = Value-of-Information (expected entropy reduction via rollouts)
- Ω(a) = Action load (spatial cost)
- τ(a) = Latency (temporal cost)
- C_t = Current congestion
- α, β, λ_S = Scaling parameters

### Stopping Condition
```
STOP ⟺ max_{a∈A} U(a; b_t, t, C_t) ≤ 0
```
Stop when even the best query has non-positive net value.

## EMDG Validation

**Emergency Medical Diagnostic Grid** simulation:
- 5 fatal pathologies, uniform prior
- Distributed hospital sub-systems with distinct load costs
- Patient survivability decays exponentially with time

**Results**: TCA reduces time-to-action while maintaining diagnostic accuracy vs greedy ReAct baselines.

## Key Insight for OpenClaw

> "True autonomous control cannot emerge from unstructured prompt-reflection; it requires a formal, decision-theoretic optimization layer."

This validates our L4 Controller design philosophy — but suggests we should:
1. Add explicit **cost pricing** to tool calls
2. Replace fixed token limits with **utility-driven stopping**
3. Consider **belief-dependent VOI** for planning decisions
