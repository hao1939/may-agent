## 核心内容

### 部署理念
> "从'一个人干所有活'变成'团队协作'"

### 单 Agent 的问题
- 任务排队处理，效率全靠等
- 写文章写到一半想查资料 → 要么等写完，要么打断重来

### 多 Agent 架构

| Agent | 职责 | 模型选择 |
|-------|------|---------|
| 1号 | 日常对话 + 调度 | 便宜模型 |
| 2号 | 专门跑耗时任务 | 按需 |
| 3号 | 处理另一类工作 | 按需 |

**优势**: 三条线同时推进，互不干扰

### 关键收益

**1. 成本优化**
> "不是每个任务都需要最强模型，日常闲聊用便宜的就够了，复杂推理才上贵的。按需分配，账单能砍一大截。"

**2. 安全隔离**
> "每个 Agent 独立工作区、独立权限，该看的看，不该碰的碰不到。不会因为一个 Agent 的操作影响另一个的数据。"

### 部署架构
> "一台机器，一个 Gateway，养一群虾，各干各的活。"

**社区暗语**: "养虾" = 部署 OpenClaw Agent

## 与 OpenClaw 设计的关联

### 验证的设计原则
1. **Gateway 统一入口**: 与 OpenClaw 的 Gateway 架构一致
2. **工作区隔离**: 每个 Agent 独立环境
3. **模型按需分配**: 成本意识设计

### 待明确的点
- 1号 Agent 的"调度"具体如何决策？
- Agent 间通信机制
- 任务分配的策略依据

## 可操作建议

对于 OpenClaw 用户：
1. **从单 Agent 开始**: 理解基础后再扩展
2. **按任务类型分 Agent**: 不要按用户角色分
3. **监控成本**: 不同模型的 token 消耗差异巨大
4. **权限最小化**: 每个 Agent 只给必要的工具权限
