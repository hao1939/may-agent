## 正文
Vercel软件工程师 Jude Gao 写了一篇很有意思的文章，他在研究如何更好地让AI编程Agent学习Next.js 16的过程中发现，一个简单的 **AGENTS.md 文件嵌入压缩后的文档索引**，竟然把Skills打爆了。

【文章标题在最后一张图，感兴趣可以去看看~】

AI 编程代理的性能受限于其训练数据的截止日期。Next.js 16 引入了一系列全新 API，这些内容并不在当前大模型的训练数据中。这导致 AI 经常生成错误代码或回退到过时模式。为了解决这一问题，Vercel 对比了两种方案：

- **Skills（技能）**：一种主动工具，AI 识别到需求时主动调用文档。
- **AGENTS.md**：项目根目录下的 Markdown 文件，为 AI 提供每一轮对话的持久上下文。

## 惊人实验结果

起初 Jude Gao 以为 Skills 能很好地解决AI学习新框架特定知识的问题，结果却在实践中发现了意想不到的情况：

将只有 **8KB 的压缩文档索引** 嵌入 AGENTS.md 文件后，在 Next.js 16 API 的评测中达到了：

```
AGENTS.md:  100% 通过率
Skills:      53% 通过率 (最高79%)
```

**"笨方法"在效率和准确率上被打爆了。**

## 为什么AGENTS.md更有效？

Jude Gao 分析出现"反直觉"结论的三个原因：

### 1️⃣ 消除决策点
AI 不需要决定"我是否需要查阅文档"，信息已经直接呈现在面前。

### 2️⃣ 持续可用性
Skills 异步加载且可能调用失败，而 AGENTS.md 的内容在每一轮对话的系统提示词中都存在。

### 3️⃣ 解决顺序冲突
Skills 会让 AI 纠结是先读文档还是先看项目结构，而被动上下文消除了这种排序难题。

## 反思

这个反直觉的结论让我们不得不思考一个问题：**最新、最火的东西是不是最好的，或者说最合适的？**

我们真的需要那么多 Skills 吗？并不见得，不是所有事情都需要用到它，也不是所有事情用它都会更高效，有时候简单原始反而是最合适的，正所谓**大道至简**嘛~

## Amy 的分析

**核心洞察：AGENTS.md > Skills — 反直觉但可解释的实验结果**

Vercel工程师Jude Gao的实验揭示了一个令人震惊的事实：简单的AGENTS.md（8KB）在特定场景下（Next.js 16 API学习）击败了Skills（100% vs 53%）。

**实验数据：**
```
AGENTS.md (8KB 压缩文档索引): 100% 通过率
Skills (主动调用):             53% 通过率 (最高79%)
```

**AGENTS.md胜出的三个原因：**
1. **消除决策点** — 被动上下文，无需决策
2. **持续可用性** — 每轮对话都存在，不依赖异步加载
3. **解决顺序冲突** — 不纠结先读文档还是先看项目结构

**社区辩论核心：**
这场辩论的本质是 **"被动上下文 vs 主动工具"** 的路线之争：

| 维度 | AGENTS.md (被动) | Skills (主动) |
|------|-----------------|---------------|
| 可用性 | 每轮对话都存在 | 需异步调用，可能失败 |
| 决策成本 | 无 | 需决定"是否调用" |
| 顺序问题 | 无 | 需决定"先读文档还是先看代码" |
| Token成本 | 每轮都带 | 按需加载 |
| 上下文膨胀 | 是 | 否 |
| 灵活性 | 固定 | 动态 |

**关键评论分析：**

🔴 **One-M的揭示** (108赞): "他把所有的 node.js 文档做了一个无格式的索引塞在 agents.md 里面。他管这个叫 compressed."

- 不意味着Skills无用，而是说明不同场景需要不同策略
