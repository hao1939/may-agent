## Core Problem

Current LLM agent tool planning methods rely on **greedy, reactive tool selection** that:
- Lacks foresight for multi-step dependencies
- Suffers from compounding errors when early suboptimal choices propagate
- Wastes computation on single trajectories without exploring alternatives

## ToolTree Solution

**MCTS-inspired planning paradigm** with four key innovations:

### 1. Dual-Stage Evaluation
| Stage | Signal | Purpose | Timing |
|-------|--------|---------|--------|
| Pre-evaluation (r_pre) | Fast predictive score | Forecast usefulness | BEFORE execution |
| Post-evaluation (r_post) | Grounded utility score | Assess actual contribution | AFTER execution |

### 2. Prior-Augmented UCT Selection
```
UCT(s,a) = Q(s,a) + λ·r_pre(s,a)·√(ln N(s)/N(s,a))
```
- Q(s,a): exploitation term from post-evaluation rewards
- r_pre(s,a): exploration prior (0-1) before execution
- Balances foresight (pre) with hindsight (post)

### 3. Bidirectional Pruning
- **Pre-pruning**: Filter actions if r_pre < τ_pre (don't expand unpromising branches)
- **Post-pruning**: Mark non-expandable if r_post < τ_post (trim disproven paths)
- **Caching**: Deterministic (a,args)→o cache to avoid duplicate calls

### 4. Backward Propagation
```
Q(s,a) ← Q(s,a) + (r_post(s_t,a) - Q(s,a))/N(s,a)
```
Running average updates exploitation term with grounded rewards.

## Experimental Results

| Benchmark | ToolTree | Baseline | Gain |
|-----------|----------|----------|------|

Key insight: Improvements scale with tool sets, model size, and compute budgets.

### Key Design Philosophy Alignment

**ToolTree**: "Pre-evaluation removes obviously incompatible branches BEFORE any tool call"

**OpenClaw L3**: Route based on skill manifest + context BEFORE delegation — identical logic.

**ToolTree**: "Post-evaluation yields faithful credit assignment compared to ranking hypothetical thoughts"

**OpenClaw Error Log**: Record actual outcomes, not predicted failures — grounded feedback.

---

## Critical Insight

> "Many variants evaluate hypothetical thoughts rather than executed actions, so ranking is decoupled from actual tool use utility"

This validates OpenClaw's design: **Error Log records ACTUAL execution outcomes**, not hypothetical pre-checks. The dual-feedback loop (plan → execute → evaluate → learn) is exactly what OpenClaw's SIGNALS.md + Error Log achieves.
