## 核心论点

从 Prompt Engineering 到 Context Engineering，再到 Harness Engineering。Agent 时代的工程方法论正在经历第三次范式跃迁。

### Harness Engineering 定义

Harness engineering = 为 Agent 设计的结构化（被约束的）运行环境，包含：
- 🔧 **工具接口**: Agent 能调用的 MCP/skills/白名单
- 🚧 **执行边界**: 哪些操作需要审批/确认
- 📋 **状态管理**: 持久化记忆和检查点
- 🔍 **审计追踪**: 完整的行为日志

### 为什么重要

多组实验表明：**在 Agent 系统中，系统设计（Harness）对性能的影响甚至超过了模型本身的能力。**

### L0-L5 成熟度阶梯

笔记提供了从 L0 到 L5 的成熟度阶梯：
1. 写好 CLAUDE.md 指令文档
2. 引入 Hooks（钩子）进行约束
3. 将重复流程封装成 Skills（技能）
4. 实现复杂的多 Agent 协作

### 精彩评论

**小跃要努力**给出简洁takeaway:
> "Harness engineering，可以理解为 一个agent的约束框架，（harness 单词本身就是被驾驭控制的意思）"

**苟钩摄影**提出三个关键问题:
1. harness跟SDD(Spec-Driven Development)的区别联系
2. 在技术迭代非常快的背景下，应该关注哪一层不变的东西？
3. harness最重要的是自我验证自我优化吗？企业中如何落地？

作者回复：
1. Harness是**运行时**的工程框架（Agent 怎么跑），SDD是**开发时**的协作范式（人怎么告诉Agent该做什么）
2. **不变的是工程范式层**：工具层一直在变，但Harness Engineering的五个维度是稳定的
3. 分阶段逐步落地

**智能体前沿研究**质疑:
> "去年就在搞了，没什么新东西了。架构已经到顶了。"

作者回应:
> "随着AI逐步进化演进，每年都会有新概念涌现"

## 设计哲学

"愚蠢的管道、聪明的端点" —— Harness是基础设施，Agent是智能端点。
