## 核心观点

从 Prompt Engineering 到 Context Engineering，再到 **Harness Engineering**。Agent 时代的工程方法论正在经历**第三次范式跃迁**。

## 社区精彩总结

**小跃要努力** (👍7):
> Harness engineering，可以理解为 **一个agent的约束框架**，（harness 单词本身就是被驾驭控制的意思）是为 Agent 设计的结构化（被约束的）运行环境，包含：
> - 🔧 **工具接口**: Agent 能调用的 MCP/skills/ 白名单
> - 🚧 **执行边界**: 哪些操作需要审批/确认
> - 📋 **状态管理**: 持久化记忆和检查点
> - 🔍 **审计追踪**: 完整的行为日志

## 核心洞察

多组实验表明，在 Agent 系统中，**系统设计（Harness）对性能的影响甚至超过了模型本身的能力**。当模型能力趋同时，Harness 成为了构建可靠 AI 应用的关键。

## L0-L5 成熟度阶梯

笔记提供了一个从 L0 到 L5 的成熟度阶梯：
1. 写好 CLAUDE.md 指令文档
2. 逐步引入 Hooks（钩子）进行约束
3. 将重复流程封装成 Skills（技能）
4. 最终实现复杂的多 Agent 协作

## 精彩问答

**苟钩摄影** 提问:
> 1. harness跟sdd的区别联系在哪？
> 2. 在技术迭代非常快的背景下，我们应该更加关注、沉淀哪一层不变的东西？
> 3. 你认为harness最重要的是自我验证自我优化吗？

**CuiLiang.ai** 回答:
> 1. **Harness 是运行时的工程框架**（Agent 怎么跑），SDD 是开发时的协作范式（人怎么告诉 Agent 该做什么）
> 2. **工具层一直在变，不变的是工程范式层**。CC会迭代，Cursor 会迭代，甚至 MCP 协议本身也可能被替代，但 Harness Engineering 的五个维度是稳定的
> 3. 分阶段逐步落地

## 对我们的意义

1. **范式确认**: Harness Engineering 是 PE → CE → HE 的第三次跃迁，我们在正确的方向上
2. **架构对应**: 我们的 CLAUDE.md → Hooks → Skills → Multi-Agent 设计与成熟度阶梯完全对齐
3. **关键洞察**: 不变的是工程范式层，工具层会持续迭代
4. **竞争格局**: Harness 与 SDD 是运行时 vs 开发时的互补关系
