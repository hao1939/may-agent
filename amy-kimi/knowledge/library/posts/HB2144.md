## 三种Agent模式详解

### ① 单一代理 — ReAct 循环

**核心机制**: 思考 → 行动 → 观察，不断循环，直到任务完成。

没有预设脚本，靠上下文驱动推理。每一轮循环，模型能看到完整的历史记录（任务 + 所有历史思考 + 工具调用结果），然后自主决定下一步。

**示例** — 「订一家今晚最高分日料」:
→ 思考：需要位置 → 调用定位 → 返回「上海·静安区」
→ 思考：搜附近日料 → 调用搜索 → 返回5家餐厅
→ 思考：比较评分 → 查询 → A餐厅 4.9分最高
→ 任务完成，输出结果

**⚠️ 弱点**: 步骤越多，上下文越长，越容易「推理偏轨」，整个任务直接崩。

---

### ② 顺序代理 — 共享记忆白板

把任务拆给多个代理，一个一个按顺序跑，通过「共享状态」传递信息。

**白板机制**: 
代理完成任务 → 写入结果 → 下一个代理读取 → 继续工作
代理之间从不直接对话，白板是唯一沟通渠道。

**关键特点**:
- 信息只增不减，每个代理追加内容，不会删前面的
- 顺序硬编码，代理一跑完才能启动代理二
- **可靠性高，但不灵活** — 中途需求变了，整条流水线重跑

---

### ③ 并行代理 — 汇总代理的价值

多个代理同时跑，最后交给「汇总代理」整合结果。

**汇总代理**做的不是简单拼接，而是真正的二次推理：
1. **去重过滤** → 剔除重叠和低质信息
2. **关联分析** → 横向对比时间、距离、偏好，找最优组合
3. **生成叙述** → 输出用户可直接行动的完整方案

**类比**: 三个并行代理是调研员，各自打探情报；汇总代理是项目负责人，拍板出完整方案。

**⚠️ 难点**: 汇总代理的 prompt 设计难度远高于普通代理。

---

## 三种模式选择指南

| 场景 | 推荐模式 | 原因 |
|------|---------|------|
| 简单单步任务 | 单一代理 | 够用 |
| 结构固定、可预测的流程 | 顺序代理 | 可靠 |
| 速度敏感、多维度并行 | 并行代理 | 快但贵 |

---

## 关键洞察

1. **ReAct的上下文膨胀问题** — 步骤越多越容易偏轨
2. **顺序代理的刚性问题** — 需求变化需重跑整条链
3. **汇总代理的设计难点** — 二次推理能力要求远高于普通代理
4. **模式选择是权衡** — 可靠性 vs 灵活性 vs 成本
