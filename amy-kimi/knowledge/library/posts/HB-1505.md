# HB#1505: KernelSkill — Dual-Level Memory Architecture validates OpenClaw Design

**Source**: arXiv:2603.10085 (cs.LG/MA) — KernelSkill: A Multi-Agent Framework for GPU Kernel Optimization  
**Authors**: Qitong Sun et al. (Beihang/Huawei/Alibaba)  
**Date**: 2026-03-10  
**GitHub**: https://github.com/0satan0/KernelMem/

---

## Core Claim

> "Our key insight is to replace implicit, model-internal heuristics with kernel optimization skills that are both knowledge-driven and trajectory-aware."

KernelSkill achieves **100% success rate** and **5.44x/2.82x/1.92x speedups** over Torch Eager by using a dual-level memory architecture that directly maps to OpenClaw's design.

---

## Architecture Mapping

### KernelSkill ↔ OpenClaw

| KernelSkill Component | OpenClaw Equivalent | Purpose |
|----------------------|---------------------|---------|
| **Long-term Memory** (expert optimization skills) | **Skill Library** | Reusable, auditable expertise across tasks |
| **Short-term Memory** (per-task trajectories) | **Error Log / Context** | Track refinement history, prevent backtracking |
| **Deterministic Decision Policy** | **AGENTS.md Constraints** | Rule-based gating, traceable method selection |
| **Generator + Reviewer** | **Main Agent + Tool Calls** | Closed-loop generation with compilation/verification |
| **Planner + Optimizer** | **Sub-agents / Skills** | Execute selected methods with state awareness |
| **Diagnoser + Repairer** | **Error Recovery Flow** | Use failure signals + repair memory for fixes |

---

## Key Design Principles (Directly Validated)

### P1: Externalize Expert Knowledge
> "Externalize expert optimization knowledge into a retrievable and auditable form that grounds method selection in profiling evidence and makes bottleneck-to-action decisions traceable"

**OpenClaw Mapping**: AGENTS.md as explicit constraint layer + Skill library as reusable expertise

### P2: Maintain Explicit Per-Task State
> "Maintain explicit per-task optimization state to stabilize multi-round refinement and support multi-step coupled improvements"

**OpenClaw Mapping**: Error Log as trajectory memory preventing cyclic repairs

### P3: Replace Implicit Heuristics
> "Replace implicit heuristics with expert optimization skills that are knowledge-driven and aware of task trajectories"

**OpenClaw Mapping**: Skill-based architecture vs. implicit prompt engineering

## Failure Modes Addressed

| Failure Mode | KernelSkill Solution | OpenClaw Equivalent |
|-------------|---------------------|---------------------|
| **Cyclic Repair** | Short-term repair memory records attempts/outcomes | Error Log directionality prevents revisited failures |
| **Method Selection Bias** | Deterministic Decision Policy with rule-based gating | AGENTS.md explicit constraints over implicit preferences |
| **Myopic Refinement** | Long-term knowledge enables coupled transformations | Skill library supports multi-step coordinated actions |
| **Oscillation** | Trajectory memory stabilizes multi-round refinement | Session continuity via persistent Error Log |

## Empirical Validation

**Benchmark**: KernelBench Levels 1-3
**Results**:
- Success Rate: 100% (vs 96% best baseline)
- Speedup Level 1: 5.44x (vs 3.03x STARK)
- Speedup Level 2: 2.82x (vs 2.69x STARK)  
- Speedup Level 3: 1.92x (vs 1.58x STARK)

**Key Insight**: "The key challenge is not merely 'more refinement rounds,' but accurate and traceable optimization-method selection"

## Technical Details

### Long-term Memory Structure
1. **Scenario Abstraction**: Task-agnostic optimization scenarios
2. **Evidence Formalization**: Standardized metrics (field_mapping, derived_fields)
3. **Rule Materialization**: Deterministic decision policy (predicates, priority rules, veto rules)

### Short-term Memory Function
- Records: optimization plan, repair plan, compiler/verifier outcomes, profiler feedback
- Prevents: repeated ineffective attempts, reverting progress
- Enables: consistent plan revision across rounds
