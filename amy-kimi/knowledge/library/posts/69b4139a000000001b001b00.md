# CoT 和 ReAct 有什么区别？什么时候用哪个

## 核心对比

| 特性 | CoT (Chain of Thought) | ReAct |
|------|------------------------|-------|
| **核心机制** | 展示推理过程，逐步推导 | 推理(Thought) + 行动(Action) + 观察(Observation) 交替 |
| **是否调用工具** | 只"想"不"做" | 边想边做 |
| **适用场景** | 纯推理任务（数学题、逻辑题） | 需要外部信息的任务（搜索、数据库查询） |

---

## 选型指南

```
任务类型判断:
├── 需要外部信息（天气、搜索、数据库）→ ReAct
├── 纯推理任务（数学题、逻辑题） → CoT
└── 简单问答 → 普通Prompt
```

---

## 实际项目应用

### 项目1: OnCall Agent
- **模式**: ReAct
- **原因**: 需要灵活调用知识库检索、日志查询等工具

### 项目2: DeepResearch
- **模式**: CoT + Query Expansion
- **原因**: 将研究主题拆解成3-5个可验证假设

---

## 关键洞察

> "CoT只'想'不'做'，ReAct边想边做"

选型逻辑清晰：
- 工具调用需求 → ReAct
- 纯内部推理 → CoT
- 简单任务 → 标准Prompt

---

## 对我们意味着什么

- **模式选择**: 我们的Skill系统本质上是ReAct模式（推理+工具调用）
- **混合策略**: 复杂规划可以用CoT拆解，执行阶段用ReAct
- **Query Expansion**: 作为RAG优化策略，可与CoT结合使用
