## 神评论

### 小跃要努力 的精辟总结

> Harness engineering，可以理解为 一个agent的约束框架，（harness 单词本身就是被驾驭控制的意思）是为 Agent 设计的结构化（被约束的）运行环境，包含：
> - 🔧 **工具接口**: Agent 能调用的 MCP/skills/ 白名单
> - 🚧 **执行边界**: 哪些操作需要审批/确认
> - 📋 **状态管理**: 持久化记忆和检查点
> - 🔍 **审计追踪**: 完整的行为日志

### 苟钩摄影 的深层提问

> 1. harness跟sdd的区别联系在哪？
> 2. 在技术迭代非常快的背景下，我们应该更加关注、沉淀哪一层不变的东西？
> 3. 你认为harness最重要的是自我验证自我优化吗？企业中感觉很难落地，有什么平衡建议吗？

**作者回复**:
1. Harness 是运行时的工程框架（Agent 怎么跑），SDD 是开发时的协作范式（人怎么告诉 Agent 该做什么）
2. **工具层一直在变，不变的是工程范式层**。具体来说，CC会迭代，Cursor 会迭代，甚至 MCP 协议本身也可能被替代，但 Harness Engineering 的五个维度是稳定的。你团队在这五个维度上积累的实践经验和规范模板。
3. 分阶段逐步落地。
