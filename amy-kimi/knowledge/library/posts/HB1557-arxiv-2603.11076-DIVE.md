## Core Contributions

### 1. Diversity Scaling Law
- **Finding**: Diversity scaling consistently outperforms quantity scaling for OOD generalization, even with 4× less data
- **Result**: +22 average points across 9 OOD benchmarks; +68% vs strongest 8B baseline
- **Significance**: Challenges the prevailing "more data = better" assumption in agent training

### 2. Evidence-First Synthesis Architecture
- **Inversion**: Execute tools first, then reverse-derive tasks (vs query-first)
- **Benefit**: Grounding by construction — executability and verifiability guaranteed
- **Mechanism**: Evidence Collection → Task Derivation loop over K=3 iterations

### 3. Three-Pool Resource Design
| Pool | Content | Scale |
|------|---------|-------|
| Tool Pool | 373 validated tools (general + 4 expert domains) | Crawl-Validate pipeline |
| Seed Pool | ~5,000 entity seeds per domain | Wikipedia/PubMed/NCBI/Stocks |
| Exemplar Pool | Query-only exemplars with implicit tool-use patterns | Heterogeneous task families |

## Methodology Details

### Two Core Primitives
1. **Retrieval**: Search, database query, API call (information acquisition)
2. **Processing**: Code execution, data transformation (deterministic computation)

### Expert Domains
- Finance (EDGAR, Yahoo Finance APIs)
- Biology (NCBI tools)
- Medicine (PubMed, clinical databases)
- Academia (Wikipedia, scholarly APIs)

### Training Pipeline
1. **SFT**: 48k verified trajectories (rejection sampling), 300 steps
2. **RL**: 3.2k frontier tasks (pass rate 1-5/8), GRPO, 100 steps

## Critical Insights

### The Diversity-Validity Tension
> "Scaling diversity while maintaining data quality is challenging because effective agentic training requires synthesized tasks to be both verifiable and executable."

Traditional approaches fail:
- Fixed-toolset synthesis: Limited diversity
- Simulated tools: Unverifiable execution
- Query-first on real tools: Heavy verification bottleneck

### Structural Diversity Dimensions
1. **Tool-pool coverage**: Types of tools available
2. **Per-task toolset variety**: Combinations per task
3. **Multi-step patterns**: Heterogeneous tool-use sequences (retrieval-only → retrieval-then-analyze)
