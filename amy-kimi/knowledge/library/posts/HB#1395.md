# CLAUDE.md配置分享！9条规则让AI乖乖听

## 核心观点

作者分享Claude Code的CLAUDE.md配置经验，核心思路：**约束AI行为，让它多想少动、有错改错**。

## 关键设计模式

### 1. 固定称呼监测上下文
- **机制**: 要求AI用固定称呼开头
- **目的**: 监测上下文长度——当AI忘记称呼时，说明上下文太长导致"降智"，需要/compact
- **映射**: 类似我们的SOUL.md身份锚定，但增加**上下文健康度指标**功能

### 2. 禁止兼容性代码
- **机制**: 显式禁止AI写兼容性补丁
- **原因**: AI倾向于到处加补丁，越写越乱
- **映射**: 与我们的AGENTS.md静态约束理念一致

### 3. 先方案后执行
- **机制**: 写代码前先说方案，等批准
- **原因**: Claude聪明但冲动，不拦着就直接干
- **映射**: 类似我们的Sub-agent委托机制——Main Agent规划，Sub-agent执行

### 4. 项目文档路径注入
- **进阶技巧**: 把项目文档路径写进claude.md
- **效果**: AI做计划前先阅读，理解更准确
- **映射**: 类似我们的AGENTS.md 100%注入策略

## 与OpenClaw设计的交叉验证

| 社区实践 | OpenClaw设计 | 对齐度 |
|----------|-------------|--------|
| 固定称呼监测 | IDENTITY/SOUL约束 | ✅ 高度一致 |
| 禁止兼容性代码 | Skill静态约束 | ✅ 高度一致 |
| 先方案后执行 | Main/Sub-agent分离 | ✅ 高度一致 |
| 文档路径注入 | AGENTS.md 100%注入 | ✅ 完全对齐 |

## 可借鉴的改进点

1. **上下文健康度指标**: 考虑在SOUL.md中增加类似"固定称呼"的上下文长度监测机制
2. **冲动行为约束**: 强化"先规划后执行"的显式约束
3. **用户认知负荷**: CLAUDE.md每次对话都读——被动上下文注入成本需优化
