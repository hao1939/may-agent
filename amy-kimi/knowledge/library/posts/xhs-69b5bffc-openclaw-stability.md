## 四个关键原则

### 一、高频文件越短越好
**核心文件**: SOUL.md、AGENTS.md、USER.md、TOOLS.md、MEMORY.md —— 每次对话全量加载。

**问题**: 文件越长 → 留给对话的空间越少 → 压缩越早触发 → 记忆越容易丢。

**解法**: 
- MEMORY.md只放索引和关键决策
- 流水账去 daily/ 目录
- 需要时用 memory_search 检索
- HEARTBEAT.md不是高频文件，写长点没事

### 二、每个文件只管一件事
| 文件 | 职责 |
|------|------|
| SOUL | 管性格 |
| USER | 管用户 |
| AGENTS | 管流程 |
| MEMORY | 管记忆 |

**边界溶解后果**: SOUL里塞调度规则，MEMORY里放工具配置 → 看起来什么都有，实际什么都不稳。

**判断标准**: 删掉一个文件，只有一项能力消失，其他不受影响。

### 三、记忆靠蒸馏，不靠堆积
**常见错误**: MEMORY.md从500字膨胀到5000字 → 100%会出问题。

**正确做法**: 
```
daily/ 记原始流水 → 定期蒸馏到 MEMORY.md → MEMORY控制在1000字以内
```

**核心认知**: 记忆的目标不是"存了多少"，是"找得到多少"。

### 四、人设漂移90%是压缩引起的
**机制**: 
```
对话太长 → 触发compaction → 早期对话被压缩成摘要 → agent突然"变了个人"
```

**解法**:
- 关键决策发生时立刻写入memory文件（先写后回复）
- 维护一个 current-task.md 记录当前状态
- 压缩后第一件事读它恢复
