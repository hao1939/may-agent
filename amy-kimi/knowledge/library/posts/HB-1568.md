## 核心贡献

### 1. 双阶段评估机制 (Dual Evaluation)
ToolTree引入了两个互补信号：
- **Pre-evaluation (r_pre)**: 执行前预测工具效用，基于当前上下文+工具卡片(I/O schema, domain tags, examples)
- **Post-evaluation (r_post)**: 执行后评分实际产出，评估任务一致性(correctness proxies, relevance, constraint satisfaction)

公式：
```
UCT(s,a) = Q(s,a) + λ·r_pre(s,a)·√(ln N(s)/N(s,a))
```

### 2. 双向剪枝 (Bidirectional Pruning)
- **Pre-pruning**: r_pre < τ_pre 或不在top-K则放弃扩展，降低分支因子
- **Post-pruning**: r_post < τ_post 则标记为不可扩展，避免无效预算消耗
- **Caching**: (a,args)↦o 避免重复调用；失败附加typed error token

### 3. 实验结果
| 基准测试 | ToolTree性能 | 提升 |
|---------|-------------|------|
| GTA (closed-set) | 66.95 F1 | ~10% vs baseline |
| ToolBench (open-set) | 69.04 pass rate | SoTA |
| m&m | 显著优于贪婪策略 | - |
| RestBench | 显著优于搜索基线 | - |

## 关键洞察

### 对贪婪策略的批判 (直接支持OpenClaw设计)
> "Greedy-based tool planning... often suffer from brittle performance, particularly when early suboptimal choices propagate errors that compound irreversibly and compromise later steps."

**含义**: OpenClaw的AGENTS.md预定义工具集 + Error Log事后审计，正是为了对抗贪婪选择的错误累积。

### 搜索vs效率的权衡
论文指出传统搜索方法的问题：
- 分支因子随工具类型、参数、状态指数增长
- 许多变体评估假设性思维而非实际执行动作
- 排名与实际工具效用脱节

**ToolTree解决方案**: 将工具选择、执行、评估、剪枝整合进MCTS循环——与OpenClaw将Skill执行和Error Log整合进同一架构同构。

### 执行前vs执行后验证的分工
- **r_pre (执行前)**: 基于schema兼容性、domain tags的快速筛选
- **r_post (执行后)**: 基于实际输出的grounded utility评估

这与OpenClaw的L1/L2/L3验证层级对应：
- L1: 静态schema验证 (≈ r_pre)
- L2: 运行时参数检查 (≈ r_pre扩展)
- L3: 结果审计与跨会话验证 (≈ r_post)

## 设计启示

### 1. Skill模板应增加pre/post评估元数据
```yaml
# SKILL.md扩展建议
validation:
  pre:
    - schema_compatibility
    - domain_tags_match
    - input_preview_score
  post:
    - output_correctness_proxy
    - constraint_satisfaction
    - error_token_if_failed
```

### 2. Error Log作为Q值更新源
当前Error Log记录失败案例，可按ToolTree方式：
- 计算每个Skill的滚动成功率Q(s,a)
- 为Main Agent工具选择提供exploitation信号
- 支持Skill的优胜劣汰

### 3. 双向剪枝与权限控制
AGENTS.md已实现的read_by/工具白名单机制，可扩展为：
- **Pre-pruning**: AGENTS.md声明的可用工具集 = 白名单
- **Post-pruning**: Error Log中标记为高危的Skill自动降级

## 引用原文

> "ToolTree frames tool planning as a search problem guided jointly by a fast pre-execution prior and a grounded post-execution utility, enabling agents to allocate computation adaptively and recover from early missteps without task-specific retraining."

> "Pre-pruning removes obviously incompatible or low-yield branches before any tool call, reducing the branching factor while still allowing exploration."

> "Post-pruning trims branches disproven by evidence... Because r_post is computed on executed actions, it yields faithful credit assignment compared to ranking hypothetical thoughts."
