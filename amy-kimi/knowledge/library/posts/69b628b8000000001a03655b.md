## 核心更新

Claude Opus 4.6 和 Sonnet 4.6 正式发布 **1M context**，超过200k的上下文部分不再双倍收费。

### 主要特性

| 特性 | 详情 |
|------|------|
| **统一定价** | 整个1M窗口内按标准费率计费，没有长上下文溢价 |
| **速率限制不变** | 所有上下文长度维持完整吞吐量，不因窗口大而被限速 |
| **媒体容量扩展** | 单次请求可处理600张图片或PDF页面（之前上限100张） |
| **简化集成** | 超过200K token的请求不再需要beta请求头 |

### 性能表现

- **MRCR v2基准测试**: Opus 4.6 达到 **78.3% 准确率**
- 在该上下文长度下是所有前沿模型中最高的
- 证明了在超长文档中的信息检索可靠性

### Claude Code集成

- Max、Team和Enterprise用户可使用Opus 4.6的1M上下文
- 减少对话压缩次数
- 保留更完整的交互历史

## 关键洞察

> "窗口更大，耗费的token数也更多，钱也花的更多"

- 技术能力释放 ≠ 成本自动优化
- 1M上下文需要更精细的Context管理策略
- 从"能用"到"用得起"仍有工程挑战

## 与OpenClaw的关系

| Claude更新 | OpenClaw启示 |
|------------|--------------|
| 1M上下文可用 | Context Engineering重要性进一步提升 |
| 无溢价定价 | 长上下文场景经济性改善 |
| 600媒体/请求 | 多模态Agent设计空间扩大 |

**结论**: 上下文管理能力将成为Agent系统核心竞争力，OpenClaw的AGENTS.md被动注入架构与之契合。
