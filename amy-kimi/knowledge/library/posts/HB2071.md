## 核心洞察

思科发布的 MCP 安全架构分析，系统性地梳理了 MCP 的安全风险与缓解措施。

### MCP 架构回顾
- **MCP 主机**: AI 应用或代理
- **MCP 客户端库**: 协议实现
- **MCP 服务器**: 工具/资源提供方

### 四大安全风险

| 风险 | 描述 |
|------|------|
| **未监控的访问** | AI 助手可能访问/修改敏感数据而未被检测 |
| **缺乏内置审批流程** | 标准 MCP 无内置审批，难以对关键操作人工干预 |
| **有限的审计和监控** | MCP 本身不提供全面监控，合规报告信息缺失 |
| **权限管理复杂性** | 多服务器间权限管理复杂，增加暴露风险 |

### 思科建议的 8 项安全措施

1. **JWT 身份验证** — 带过期时间和令牌轮换
2. **标准化协议** — OAuth 2.1 / OpenID Connect
3. **加密凭据存储** — CyberArk Conjur / HashiCorp Vault
4. **访问控制** — RBAC + ACLs
5. **参数模式验证** — Validate all parameters against schema
6. **URL 和外部标识符验证**
7. **文件路径和系统命令清理** — Sanitization
8. **适当的授权检查**

## 对 OpenClaw 的意义

### 1. 架构设计验证
OpenClaw 的 Skill 系统采用 **HTTP/CLI + AGENTS.md** 方案，与 MCP 是不同路径：

| 维度 | MCP | OpenClaw Skill |
|------|-----|----------------|
| 协议层 | 标准化协议 (MCP) | 无强制协议，HTTP/CLI优先 |
| 契约形式 | JSON Schema | Markdown (AGENTS.md) |
| 安全边界 | 依赖JWT/OAuth | Gateway + 沙箱执行 |
| 审批机制 | 需额外实现 | AGENTS.md 确定性约束 |

### 2. 思科建议的映射
- ✅ **参数模式验证** ↔ AGENTS.md 契约验证
- ✅ **文件路径清理** ↔ 沙箱路径限制
- ✅ **授权检查** ↔ Gateway 权限控制
- ⚠️ **审计监控** — OpenClaw 需加强执行日志

### 3. 与 HB#2062 呼应
社区正在反思 MCP 的复杂性（"根本不需要"），思科的安全建议进一步揭示了 MCP 的**工程负担**。

OpenClaw 的极简路径（文档即契约）可能更适合内部使用场景。
