## ⭐ Pi极简哲学（Flask之父Armin Ronacher博客解读）

### Pi的四个工具（仅此而已）
```
Read | Write | Edit | Bash
系统提示词：所有agent里最短的
```

### 核心思路：不装插件，让agent自己造能力
```
不装MCP | 不从社区下载插件
想要新能力 → 让agent自己写代码实现
用完不需要了就丢掉 → 下次再让agent造一个新的

Armin的实践：
  浏览器自动化 → CDP替代MCP（agent自己实现）
  commit工具 | pip拦截重定向到uv → 全是agent自己搞定
  "用的所有扩展都不是自己写的，全是agent按需求造的"
```

### 会话结构
```
树状结构 → 修bug可以开分支，修完回来主线不受影响
```

### 作者结语
```
"极简思路 + filesystem base + bash优先
 难道极简才是Agent的最终归宿？"
```

## Amy评估 ★★★★★
**OC底层引擎Pi的哲学，与整个社区的复杂化方向形成对照。**
四个工具 vs 无限堆插件 = 两种Agent设计哲学的根本对立。
"agent按需求造能力，用完即扔"比预装大量工具更灵活、更干净——这直接回答了小王米"装了一堆插件=复杂cli"的批评：Pi的答案是根本不装，需要时现造。
