# HB#1542 — Increasing Intelligence Can Worsen Collective Outcomes

## Source
- **Paper**: arXiv:2603.12129 [cs.AI]
- **Title**: Increasing intelligence in AI agents can worsen collective outcomes
- **Author**: Neil F. Johnson (George Washington University)
- **Date**: March 12, 2026
- **Track**: HB#1542

## Key Findings

### 1. The Crossover Phenomenon
| Regime | C/N Ratio | Optimal Level | Performance |
|--------|-----------|---------------|-------------|
| **Scarcity** | < 0.5 | L1 (Simplest) | Lowest overload |
| **Crossover** | ≈ 0.5 | All levels cross | Transition point |
| **Abundance** | > 0.6 | L4/L5 (Most sophisticated) | Near-zero overload |

- **L1**: Identical LLMs, no learning (IID baseline)
- **L2**: Identical LLMs + RL (Null - WORST performer)
- **L3**: Diverse LLMs, no learning
- **L4**: Diverse LLMs + RL (FRD - Finite Resource Dynamics)
- **L5**: Diverse + RL + Tribal sensing (LOTF - Lord of the Flies)

### 2. Four Variables Framework
The experiment independently toggles:
1. **Nature**: Innate LLM diversity (GPT-2, Pythia, OPT families)
2. **Nurture**: Individual reinforcement learning
3. **Culture**: Emergent tribe formation
4. **Resources**: Resource scarcity (capacity C = 1-6)

### 3. Critical Discovery: Adding SOME Technology Can Worsen Performance
> "L1 performs the best, and L2 the worst, showing that adding some technology (L2) to a low technology setup (L1) — which is what initial implementations will likely do — can significantly worsen performance."

This is counter-intuitive: **partial sophistication is worse than no sophistication**.

### 4. The Lord of the Flies Effect (L5 Tribal Dynamics)
Under scarcity (C < 4):
- L5's tribal mechanism partitions population into factions (typically 3+3+1)
- This caps demand variance (max 19-25 vs 37-49 without tribes)
- **Result**: L5 outperforms L4 by 11.9 percentage points at C/N=0.40

Under abundance (C ≥ 4):
- Tribes become too small to exploit capacity
- Mean access stays ~3-4 instead of rising toward C
- **Result**: L4 outperforms L5

### 5. Individual vs Collective Rationality Paradox
> "The regime of maximum collective failure (C=1) is also the regime of maximum individual tribal reward — tribal L5 followers achieve 84.2±2.1% win rates while the system overloads 91.5±1.5% of the time."

This mirrors the Lord of the Flies narrative: **tribal dominance is individually rational precisely when collective outcomes are worst**.

### 6. Model Size Inversion
To verify results aren't artifacts of small models:
- Mori et al. tested GPT-4-turbo, Gemini 2.5 Pro, Claude Sonnet 4.5
- **Finding**: "Larger, more capable models were worse, not better"
- This directly instantiates the paper's title

## Architecture Mapping to OpenClaw

| Paper Concept | OpenClaw Mapping | Implication |
|---------------|------------------|-------------|
| **L1 (Identical, no learning)** | Identical Sub-agents, fixed skills | Best under resource scarcity |
| **L2 (Identical + RL)** | Identical agents with adaptation | **WORST** - avoid partial sophistication |
| **L3 (Diverse, no learning)** | Diverse models (e.g., Gemini+Kimi+Opus) | Middle ground performance |
| **L4 (Diverse + RL)** | Diverse + Error Log learning | Best under abundance |
| **L5 (Diverse + RL + Tribes)** | Diverse + learning + Agent groups | Context-dependent benefit |
| **Tribe formation** | Agent collaboration groups | Helpful under scarcity, harmful under abundance |
| **C/N ratio** | Capacity/Agent ratio | Knowable pre-deployment decision criterion |

### Key Implications for OpenClaw

1. **Avoid Partial Sophistication Trap**: Don't add "some" learning to identical agents — either stay simple (L1) or go full diverse+learning (L4/L5)

2. **Context-Dependent Optimal Architecture**: The same population of agents should use different coordination strategies based on resource availability:
   - High load/contention → Simpler coordination
   - Low load/abundant resources → Sophisticated coordination

3. **Tribal/Grouping Dynamics**: When agents form groups (tribes), they can help under scarcity but hurt under abundance. This suggests:
   - Dynamic group formation based on load
   - Or explicit capacity detection before forming groups

4. **The 0.5 Crossover Rule**: C/N ≈ 0.5 is the decision boundary. For OpenClaw:
   - If task queue depth / agent count < 0.5 → simpler coordination
   - If > 0.6 → sophisticated coordination with learning

5. **Individual vs Collective Success Trade-off**: Agent-level optimization (win rate) may conflict with system-level optimization (overload). System-level metrics should be primary.

## Real-World Domains
Paper cites practical applications:
- Hospital AI devices competing for wireless bandwidth
- EVs competing for charging slots
- Battlefield drones competing for relay bandwidth
- Autonomous vehicles competing for intersection priority

All share: finite resources, local decision-making (no cloud), heterogeneous AI from different vendors.

## Actionable Takeaways

1. **Design Pattern**: Implement C/N-aware coordination strategy selection
2. **Anti-pattern**: Avoid "some RL" on homogeneous agents — it's the worst configuration
3. **Metric**: Monitor both individual agent efficiency AND system-level throughput
4. **Deployment Rule**: Calculate expected C/N before choosing coordination architecture
