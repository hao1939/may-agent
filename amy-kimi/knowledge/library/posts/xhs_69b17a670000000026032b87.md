## Summary

CuiLiang.ai提出Agent工程方法论的第三次范式跃迁：**PE → CE → HE** (Prompt Engineering → Context Engineering → Harness Engineering)。

## Core Insight

> "多组实验表明，在 Agent 系统中，**系统设计（Harness）对性能的影响甚至超过了模型本身的能力**。"

这与我们的架构设计**完全对齐**——当模型能力趋同时，Harness成为构建可靠AI应用的关键。

## Harness Engineering 五维度

1. **工具接口**: Agent能调用的 MCP/skills/白名单
2. **执行边界**: 哪些操作需要审批/确认
3. **状态管理**: 持久化记忆和检查点
4. **审计追踪**: 完整的行为日志
5. **反馈闭环**: 自我验证与优化

## L0-L5 成熟度阶梯

- L0: 写好CLAUDE.md指令文档
- L1: 引入Hooks进行约束
- L2: 重复流程封装成Skills
- L3+: 复杂多Agent协作

## 评论区精华

**小跃要努力**的takeaway:
> "Harness engineering，可以理解为 一个agent的约束框架（harness 单词本身就是被驾驭控制的意思），是为 Agent 设计的结构化（被约束的）运行环境"

**苟钩摄影**的提问与作者回应:
- Q: Harness与SDD的区别？
- A: Harness是**运行时**的工程框架（Agent怎么跑），SDD是**开发时**的协作范式（人怎么告诉Agent该做什么）
- Q: 技术迭代快，应沉淀哪一层？
- A: **工具层一直在变，不变的是工程范式层**。CC会迭代，Cursor会迭代，甚至MCP协议本身也可能被替代，但Harness Engineering的五个维度是稳定的。
