### 核心机制

1. **Next-State Signal**: 每次交互产生next-state信号（用户回复、工具输出、终端/GUI状态变化），这些信号是普适的、可作为在线学习源

2. **双重信号编码**:
   - **Evaluative Signals** (评估信号): 通过PRM judge提取标量奖励
   - **Directive Signals** (指令信号): 通过Hindsight-Guided On-Policy Distillation (OPD)提取"动作应如何不同"

3. **统一训练**: 个人对话、终端执行、GUI交互、SWE任务、工具调用追踪——全部可在同一循环中训练同一策略

4. **异步架构**: 模型服务实时请求、PRM评判进行中交互、Trainer更新策略——三者同时运行，零协调开销

### 技术特色

- ⚡ Fully Async
- 💰 Zero API or Zero GPU
- 🤖 Personalized
- 🛠️ Auto Optimization
- 💬 Language Feedback

## 对OpenClaw项目的意义

### 1. 命名巧合的信号价值
独立团队选择"OpenClaw"命名，验证"Claw"隐喻在Agent领域的直觉共鸣——抓取、控制、精准。

### 2. 技术方向验证
- **Next-State Signal** ↔ 我们的Error Log审计设计
- **异步训练** ↔ 我们的Main/Sub-agent分离架构
- **Language Feedback** ↔ 我们的SOUL.md/AGENTS.md约束语言
- **Multi-domain统一** ↔ 我们的Skill通用架构

### 3. 关键差异
| 维度 | OpenClaw-RL (论文) | OpenClaw (我们) |
|------|-------------------|----------------|
| 核心 | RL训练框架 | Agent操作系统 |
| 学习 | 运行时在线学习 | 编译期静态约束 |
| 进化 | 允许策略自改进 | 禁止Self-Evolution |
| 反馈 | PRM Judge自动评估 | Error Log人工审计 |

### 4. 需关注的风险
论文的"Auto Optimization"和"Personalized"特性可能触及**Self-Evolution边界**——需深入分析其技术实现是否涉及运行时自修改。
