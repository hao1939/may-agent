### 概念定位

由于上下文工程的内涵仍在快速演进，其概念边界较为开放。本文聚焦于其最有价值的核心，为读者构建一个清晰、稳固的认知框架。

### Context Engineering vs 其他概念

| 概念 | 关注点 | 区别 |
|------|--------|------|
| Prompt Engineering | 提示词设计 | 单次交互优化 |
| RAG | 检索增强 | 外部知识引入 |
| MCP | 模型上下文协议 | 工具标准化接口 |
| **Context Engineering** | **上下文管理** | **系统性上下文构建与维护** |

## Amy 的分析

**核心洞察：Context Engineering — 从Prompt Engineering到系统性上下文管理**

这篇帖子提出了一个关键认知转变：AI Agent失败的主要原因不是模型能力不足，而是上下文工程（Context Engineering）做得不好。

**概念演进路径：**
```
Prompt Engineering → RAG → MCP → Context Engineering
单次提示词优化    → 外部知识 → 工具协议 → 系统性上下文管理
```

**context-kit工具包的价值：**

作者不仅提出概念，还实现了开源工具包（github.com/keli-wen/context-kit），包含三个核心模块：

| 模块 | 功能 | 对应我们的系统 |
|------|------|---------------|
| **Select** | 上下文选择 | insights-index.json, 关键词筛选 |
| **Compress** | 上下文压缩 | compact策略, insights分层 |
| **Memory** | 记忆管理 | AGENTS.md, MEMORY.md, 知识分层 |

**对我们系统的意义：**

🔴 **直接相关** — 我们的整个知识管理系统（insights/posts分层、compact策略、AGENTS.md加载机制）本质上就是Context Engineering的实践

★ **验证方向** — 从Prompt Engineering升级到Context Engineering是行业趋势
★ **工具参考** — context-kit的Select/Compress/Memory模块可以作为我们系统的技术参考
★ **概念对齐** — 我们的工作可以明确归类为"Context Engineering"领域
