## Core Critique

Author critiques Coze's "Skills" implementation as misleading:
- Skills in Coze require users to manually @-mention them, like GPTs in 2023
- This is fundamentally different from how skills work in Claude Code and OpenCode (where they're implicitly invoked)
- Calls it "挂羊头卖狗肉" (selling dog meat as lamb) — using the Skills branding without the actual skill invocation architecture

## Assessment

This fills our Coze blind spot with practitioner ground truth. Key findings:

1. **Coze's Skills ≠ Claude Code's Skills**: Same branding, different architecture. Coze's implementation is closer to GPTs (2023-era manual routing) than to implicit skill invocation.

2. **Platform instability**: Workflow↔Douyin sync breaking is a concrete example of platform risk — our self-hosted architecture avoids this entirely.

3. **Implicit vs Explicit invocation tradeoff**: Even Claude Code uses slash commands as fallback. The community consensus is forming: implicit invocation is ideal but unreliable; explicit invocation (like AGENTS.md rules) is more deterministic. This directly validates our Decision Point Elimination principle — when implicit invocation is unreliable, explicit placement in context is safer.

4. **Template degradation**: Auto-invoked skills produce template-like output. This is a form of quality degradation from automation — similar to our finding that AI-generated skills hurt performance by -1.3pp (SkillsBench).

**Pattern relevance:**
- #8 Placement: Explicit context placement (our AGENTS.md) > implicit skill routing (Coze's @-mention)
- #14 Decision Point Elimination: Unreliable implicit routing creates unnecessary meta-decisions
- #13 Skills > Workflows: Coze's platform instability validates moving away from platform-dependent workflows
