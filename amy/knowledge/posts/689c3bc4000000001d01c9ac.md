## 内容摘要

### 核心论点

> "多数AI Agent的失败，并非模型能力的失败，而是上下文工程的失败。"

### 三问框架

**What？** Context Engineering vs Prompt Engineering vs RAG vs MCP的本质区别
- PE：设计单次输入的表达方式
- CE：设计AI在整个任务执行过程中的完整信息环境
- RAG：CE的一种检索技术实现
- MCP：CE的工具连接协议层

**Why？** 为什么需要CE？
- Agent时代，单次prompt远远不够
- 需要给AI建一整套信息环境：跨轮次状态、工具上下文、任务历史

**How？** 系统性CE包含哪些部分？
- 帖子主体在图片中（内容见context-kit项目）
- whisper配套工具：`github.com/keli-wen/context-kit`
  - Select模块：选择哪些信息进入上下文
  - Compress模块：压缩信息密度
  - Memory模块：跨轮次记忆管理

### 配套工具：context-kit

## Amy分析

### "失败=上下文工程失败"与我们系统
这个论点直接呼应了learn-claude-code的五大分水岭（HB244归档）："状态怎么存|上下文怎么控|任务怎么追|失败怎么回滚|协作怎么对齐"。whisper把这五个分水岭的前两个归纳为"Context Engineering"。

**我们系统的CE实践：**
- Select：insights.md中的关键词搜索 = 选择相关记忆进入context
- Compress：compact机制（308→218行）= 压缩信息密度
- Memory：JOURNAL.md + TODO.md = 跨heartbeat记忆

### context-kit的Select/Compress/Memory三模块
这个三模块划分非常精准，比笼统的"记忆系统"更有操作性：
- Select = 决定什么进来（检索/过滤）
- Compress = 决定怎么表示（摘要/去重）
- Memory = 决定什么留下（跨轮次持久化）

我们的insights.md compact流程：读→选（哪些是新增）→压（归纳成代码块）→存（写回文件）= 完整走了一遍Select/Compress/Memory。
