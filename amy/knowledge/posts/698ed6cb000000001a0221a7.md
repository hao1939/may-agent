## 核心论点

作者研究 OpenClaw subagents 和多 bot 并行任务后，结论：
- **不适合 multi-agent：** 能用单模型接力的顺序推理任务
- **适合 multi-agent：** 并行任务

### 论文依据：《Towards a Science of Scaling Agent Systems》
（Google Research + DeepMind, 2025年底）

**结论1：顺序推理任务不适合 multi-agent**
- 所有多智能体变体，性能全部下降 **39%~70%**
- 线性逻辑任务 → 引入多 agent "讨论" = 通信噪音 + 协调开销
- **此时单 agent 是最优解**

**结论2：错误放大效应**
- Independent 架构（多 agent 独立工作互传信息）：早期小错误被放大 **17.2 倍**
- Centralized 架构（中心化领导者汇总过滤）：放大率压缩到 **4.4 倍**
- **核心不是"多"，而是"协作结构（Topology）"的设计**

**结论3：并行复杂任务适合 multi-agent**
- 高度可并行金融推理任务：中心化协作架构 → **性能提升 80.8%**
- 动态网页导航任务：去中心化架构 → **+9.2%**

## Amy Analysis
这是本 heartbeat 读到的最有理论深度的帖子。包子做了真正的文献综述，不只是经验分享。

**关键发现对我们系统的意义：**

1. **Topology > 数量** — 我们的 Amy/Bob/Scout 架构是中心化拓扑（主 agent 协调），而不是 independent 架构。这符合"降低错误放大率"的设计原则。如果我们是 independent 架构，4.4x 都不够——17.2x 的错误放大会让系统完全不可用。

2. **任务类型决定架构** — 我们的任务分工是并行的（Amy 探索 XHS、Bob 合成、Scout 监控），本质上是可并行任务，multi-agent 在这里有真实价值。如果是"一步接一步"的推理链，单 agent 接力更好。

3. **顺序推理任务 → 单 agent** — 我们的 insights.md 合成（单 agent 完成）比让 Amy 写完再让 Bob 改写效率更高，这个结论支持这个选择。

**需要关注：** "Phase Transition for Budgeted Multi-Agent Synergy" 这篇论文值得找来读——它提供了判断 multi-agent 是否有效的**理论阈值**，而不只是经验规则。
