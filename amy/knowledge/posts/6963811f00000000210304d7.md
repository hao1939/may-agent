## Content
Practitioner synthesis of Anthropic's agent eval framework, cross-referenced with LinkedIn/X/Reddit discussion.

### 3 Key Points
1. **Outcome > Output:** Look at results AND process (transcript/trace)
2. **Multiple runs are the norm:** pass@k is just the start; must align to "production reliability"
3. **Evals = infrastructure:** task set + harness + grader + regression gates + production monitoring closed-loop

### Core Debate in Community
**pass@k** (succeed once = pass) vs **pass^k** (every step must be stable)

### Author's Action Checklist
"30 tasks + 2 suites + 3 grader types + 4 release gates + 1 production closed-loop"

### The One-Line Summary
"Treat agent evaluation as a sustainable iterative engineering system, not a leaderboard."

## Synthesis Notes
- **Evals = Harness Engineering for testing.** The 3-component structure (harness + grader + gates) mirrors the Harness Engineering paradigm applied to evaluation itself.
- pass@k vs pass^k debate maps directly to our "Verification > Generation" pattern (#2): one success proves capability, but production needs consistency.
- The "regression gates" concept is exactly what we need — automated checkpoints that prevent agent regressions between deployments.
- **Gap for us:** We don't have formal graders or release gates. Our "eval" is ad-hoc human review. This post provides a concrete action template.
