## Full Text
大模型推理能力的主流提升路径依赖强化学习与外部可验证奖励，但这带来训练成本高、奖励设计复杂等问题。本文提出 Test-time Recursive Thinking（TRT），回答一个关键问题：LLM 能否在不训练、不接收外部反馈的前提下，在“测试时”持续自我改进推理能力？结论是肯定的，而且效果显著：在数学推理与代码生成两大高难任务上，TRT 实现了前所未有的测试时自进化性能。
核心亮点：
测试时递归自改进机制： TRT 不依赖梯度更新或奖励模型，而是在单个问题内，通过“生成—自评—反思—积累知识”的递归闭环，实现持续性能提升。
知识显式积累而非思维链堆叠： 与直接追加历史 CoT 不同，TRT 将失败原因压缩为“不要做什么（Don’ts）”形式的高层知识，避免上下文污染与退化。
策略驱动的探索，而非随机采样： 每一轮为不同 rollout 自动生成互补策略（算法范式、推理路径、实现侧重点），显著提升解空间覆盖效率。
无真值条件下的自验证选择：
数学任务：利用答案互斥性，追踪自否定答案
代码任务：模型自生成测试用例并执行，作为选择信号
深度优于宽度的推理计算规律： 实验表明，多轮递归改进（depth）比单轮并行采样（breadth）更关键，K=2 即可逼近性能上限。
可解释、可复用的失败知识库： 在代码任务中，模型主要学习到性能瓶颈、边界条件、索引错误等“工程级”知识，而非表层语法修补。

**Algorithm 1** Test-time Recursive Thinking

**Require:** Problem P, rounds T, rollouts per round K
**Ensure:** Selected solution r*

```
1:  Initialize knowledge list K ← ∅
2:  Initialize solution pool S ← ∅
3:  for t = 1 to T do
4:      // Generate
5:      for k = 1 to K do
6:          Design strategy s_k based on K
7:          r_k ← LLM(P, K, s_k)
8:          S ← S ∪ {r_k}
9:      end for
10:     // Select
11:     r* ← SELECT(S)
12:     // Reflect
13:     for each r in current round where r ≠ r* do
14:         Extract insights by comparing r to r*
15:         K ← K ∪ {insights}
16:     end for
17: end for
18: return r*
```
