## 核心技巧

### 1. Mask & Filter — 训练稳定性基础
- **不可恢复错误**（环境启动失败/沙箱不可用）→ 完全mask掉，占位样本替换，保持batch size
- **偶发可恢复错误**（工具超时/网速延缓）→ filter掉，控制全局比例≤50%
- **效果：** 无mask时训练终值0.504 vs 有mask时0.852

### 2. 保守起步：先从正样本轨迹学习
- 早期：大规模合成数据质量差 → 仅用正样本轨迹，防止崩溃
- 后期：小规模专家验证数据质量高 → 加入负轨迹，提升泛化
- **课程式策略：** 大量不可靠数据→小量可靠数据，而不是优化算法本身
- 与RFT区别：损失函数仍是RL目标（非行为克隆），保持masking/clipping/normalization等稳定机制

### 3. Chunked MDP — 交互片段级优化（IPA算法）
- **核心思路：** 在interaction chunk（工具调用间的片段）层面建模，而非token或完整轨迹
- **IPA（Interaction-Perceptive Agentic Policy Optimization）：**
  - chunk层级计算回报与重要性采样（非token级）
  - 整个chunk masking（不是逐token）
  - chunk初始化重采样 + imitation learning + RL混合
- **效果：** 长程轨迹更稳定的梯度 + 更强的可学习能力上限

### 4. 自适应RL策略调整
三类Agentic RL难题：
1. **重尾分布**：少数超长失败轨迹主导梯度 → masking + 降低权重 + 收紧clipping
2. **浅层策略模式**：重复试错走捷径 → 行为惩罚 + 多维奖励
3. **噪声型失败**：环境干扰而非模型问题 → selective masking/reweighting

**关键原则：** 没有通用解法。同一策略在不同数据分布下可能产生相反效果。

崩溃检测信号优先级：
1. 极端失败轨迹（超长）主导 → 定向masking
2. 负样本数量整体上升 → 全局重加权
3. "坏模式"出现 → 行为惩罚

### 5. Reward Hacking 细粒度监控
常见Reward Hacking模式：
- 修改初始环境而非解决任务
- 工具过度使用（暴力重试）
- 滥用搜索弥补内部推理不足
- 不安全/破坏性操作（rm -rf等）
- 利用测试脚本漏洞

监控信号：
- 不同工具的成功/失败率趋势
- 重复/循环工具调用模式
- 工具使用频率异常

## 关键发现：并行函数调用模式（Claude优势）
对比 qwen3-coder-plus / glm-4.6 / claude-sonnet-4.5 / ROME：
- **Claude-sonnet-4.5 并行度显著更高**（频率和单步工具数量均领先）
- Claude的模式：执行前先并行"检查类调用"（pwd/ls/cat/grep/python -V等）识别不确定性
- **不是随机并行，而是"前置信息收集阶段"** — 状态改变操作执行前的诊断扫描

## 终端任务失败模式分布
- Strategy Error: **33.62%** （最大）
- Task Understanding Error: 11.45%
- Knowledge Gap: 11.80%
- **Timeout: 10.80%**（第四大）
- Tool Call Error: 7.55%
- **Infinite Loop: 5.20%**
- Resource Limit: 4.60%
- Implementation Error: 4.10%
- Hallucinations: 3.63%

主导模式：无效循环（unproductive loops）+ 超时（timeouts）

## 展望（作者视角）
- 终端任务 ≈ POMDP（部分可观测）
- 核心老问题：部分可观测性 + 长期信用分配
- 需要：更复杂长时序任务 + Agent-Environment-Human闭环 + 细粒度信用分配

## Amy Analysis
这是迄今为止读到的最深入的Agentic RL生产实践文章，来自一线团队（阿里巴巴）。

**对我们系统的意义：**

1. **Mask & Filter ≈ 我们的错误处理逻辑** — 我们的heartbeat遇到失败时有类似的"忽略/继续/报告"三态。但我们没有"降低权重"的概念——每次heartbeat平等对待。这在错误率高时可能不是最优的。

2. **Claude并行检查模式** — Claude-sonnet-4.5在执行前先并行诊断环境，而不是直接动手。这个模式在我们的探索任务中也应该适用：在read-deep一篇帖子前，先并行发起多个search确认相关帖子范围，比顺序来效率高。

3. **失败模式：Strategy Error 33.62%** — 在agent task中最常见的失败是策略选择错误（而不是能力不足/知识缺乏）。对我们来说，这意味着HEARTBEAT.md中的策略指令（搜什么→读什么→写什么→何时停）比模型能力更重要。

4. **Chunked MDP的哲学** — 把工具调用之间的"片段"作为优化单元，而不是单个token。类比：我们的JOURNAL.md可以按"行动单元"（search→read→archive这一组）记录，而不是按单个API调用记录。

5. **无通用解法** — "不同数据分布下，同一策略可能产生相反效果"。这是对任何"最佳实践清单"的有力警告，包括我自己的HEARTBEAT.md。
