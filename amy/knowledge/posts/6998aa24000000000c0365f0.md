## 架构概述

**1个Gateway进程 + 8个AI大脑（小王+王一到王七）**
- 小王（main，管理者）→ 调度分配监控
- 王一到王七（执行者）→ 各司其职

每个Agent完全隔离：
- 独立workspace（文件/笔记/代码互不干扰）
- 独立人格（SOUL.md）
- 独立记忆（MEMORY.md）
- 独立Telegram Bot

**共享同一个Gateway进程（资源高效）**

## 四步配置

### Step 1：定义Agent列表（agents.list）
```json
{
  "agents": {
    "list": [
      {"id": "main", "default": true, "name": "小王", "workspace": "~/.openclaw/workspace"},
      {"id": "wang1", "name": "王一", "workspace": "~/.openclaw/workspace-wang1"},
      // ... 王二到王七
    ]
  }
}
```
**关键：** workspace必须独立，否则记忆和人格会串。

**每个workspace必备文件：**
```
~/.openclaw/workspace-wang1/
├── AGENTS.md    # 行为规则
├── SOUL.md      # 人格定义
├── IDENTITY.md  # 身份信息
├── USER.md      # 用户信息
├── MEMORY.md    # 长期记忆
└── memory/      # 日志目录
```

### Step 2：配置Telegram多账户
```json
"channels": {
  "telegram": {
    "accounts": {
      "xiaowang": {"name":"小王", "botToken":"...", "dmPolicy":"allowlist"},
      "wang1": {"name":"王一", "botToken":"...", "dmPolicy":"allowlist"}
    }
  }
}
```
**路由绑定（bindings）：**
```json
"bindings": [
  {"agentId": "main", "match": {"channel": "telegram", "accountId": "xiaowang"}},
  {"agentId": "wang1", "match": {"channel": "telegram", "accountId": "wang1"}}
]
```

### Step 3：群组配置 + 提及触发
- `requireMention: true` — 避免8个Bot同时抢答
- 给每个Agent配`mentionPatterns`: `["@王一", "王一"]`
- **BotFather必须关闭隐私模式** (`/setprivacy → Disable`)，否则Bot在群里看不到非@消息

### Step 4：开启Agent间通信
```json
"tools": {
  "agentToAgent": {
    "enabled": true,
    "allow": ["main", "wang1", "wang2", ...]
  }
}
```
主Agent可跨Agent发消息/分配任务。

## Amy Analysis

**这是目前档案中最完整的OC多Agent配置教程**，含完整JSON代码示例。

**架构与我们系统的对应：**
- 小王(main) = Bob（调度层）
- 王一到王七 = Amy/Scout等专业子Agent
- agents.list声明方式 = 我们的AGENTS.md设计
- workspace隔离 = 已确认的核心设计原则

**关键技术细节（新信息）：**
- `mentionPatterns` 字段 — 允许自然语言触发（"王一帮我查"而非"@王一"）
- BotFather必须关闭隐私模式 — 群内可见性的常见漏报坑
- `tools.agentToAgent.allow` 白名单 — 细粒度控制哪些Agent可互通
- `bindings` 字段 — accountId到agentId的显式映射
