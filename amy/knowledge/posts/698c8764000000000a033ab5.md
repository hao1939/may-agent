## 内容摘要

### 1. 团队共识：Vibe宣言（4条）

1. **AI是手，人是脑**：AI负责实现细节，人负责定义验收标准和边界
2. **无验证，不提交**：未经测试或人工Review的代码，禁止合入主干
3. **回滚 > 修补**：AI陷入混乱时，立即回滚重来，别通过对话"打补丁"
4. **意图显性化**：Prompt必须包含工程约束（不增依赖、不改公开API）

### 2. 核心心法：双模驱动（Thinker + Doer）

| 角色 | 模型 | 职责 |
|---|---|---|
| **Thinker（思考者）** | DeepSeek-R1 / o1 | 慢思考：设计接口、拆解任务、排查复杂Bug、补齐测试用例 |
| **Doer（执行者）** | Claude Sonnet / GPT-4o | 快执行：拿Thinker拆好的Step，补全代码、写CRUD |

### 3. 6步闭环（拒绝"凭感觉"）

1. **明确验收** — 先定"怎么测才算过"
2. **提供上下文** — 给入口文件和约束条件
3. **AI出计划** — AI先列改动计划+风险点，人确认后再动手
4. **小步切片** — 一次只改一个可回滚的切片
5. **强制验证** — Lint/Test/Typecheck通不过？重来！
6. **人类把关** — 最后审查接口契约和安全性

### 4. 标准"任务卡"模板

```
目标：一句话说明要做什么
现状入口：文件路径#关键符号
约束：不新增依赖；不改公开API；遵循现有分层
验收标准：必须通过哪些测试命令；给出2-3个边界用例
输出要求：先给计划 → 再实现 → 最后给验证步骤
```

## Amy分析

### 四大原则与HB258 CLAUDE.md五部件的映射

| Vibe宣言 | CLAUDE.md五部件对应 |
|---|---|
| AI是手，人是脑 | SOUL.md（身份定义） |
| 无验证不提交 | .claude/hooks/（PostToolUse验证） |
| 回滚>修补 | docs/（spec规范，不让AI凭感觉改） |
| 意图显性化 | CLAUDE.md（约束显式声明） |

这四条宣言本质上是CLAUDE.md工程化的"团队文化版"——将个人工程约束翻译成团队共识。

### 双模驱动 = 专业化分工

Thinker(慢思考/设计) + Doer(快执行/实现)——这与HB244/245的多Agent架构完全吻合：集中式架构中Chief做Thinker，Worker做Doer。不同的是，双模驱动用两个不同模型而非两个Agent实例。

### 6步闭环 vs Ralph Loop (HB255)

Ralph Loop：prompt→Claude Code执行→自动测试→失败回滚→下一轮。
6步闭环：人工确认计划在步骤3，AI执行在4-5，人工审查在6。
**区别在于"人在回路"的位置**：Ralph Loop自动循环，6步闭环在关键节点保留人工控制点。两者并不互斥，可以嵌套：Ralph Loop跑在步骤4-5内部，人工把关在步骤3和6。

### 任务卡模板 = Prompt工程的结构化落地

"验收标准+边界用例"是任务卡最关键的部分——这直接对应SkillsBench(HB247)的核心发现：人工策划的结构化知识（包括验收标准）才是+16.2pp的来源。
