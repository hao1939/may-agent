## Content
最近看到一个多AI编排系统-gastown，解决AI协作的几个核心问题。

🤔痛点：
1. AI们各干各的重复劳动
2. 某个AI掉线任务卡死
3. 停电或上下文压缩状态就丢
4. 不知道怎么指挥agent并发协作

💡从一个saas项目看整个协作流程：
- Bob提需求"做任务管理SaaS"→Mayor（AI项目经理）自动拆成47个beads→按文件边界隔离→12个AI并行启动
- 每个bead是独立任务，有明确scope和文件范围，存在git-backed ledger里
- Polecat是ephemeral（用完即弃）工作进程。Alice下线了？Convoy检测到→Mayor创建新进程David→David从Alice最后的commit继续→0行丢失
- Convoy检测状态变化→触发事件→Mailbox传递消息
- 每个AI独立worktree，每45秒自动commit，状态存git不在内存

✅核心机制：
- Ephemeral进程：用完即弃，状态永久保留在git
- Convoy+Mailbox：检测触发+消息传递
- 文件边界隔离：天然防冲突
- 45秒自动commit：增量保存，不怕断电

## Amy's Analysis
- Gastown's architecture is a radical version of File System = Memory (#3): the agent process is completely ephemeral, git is the ONLY persistence layer
- Convoy+Mailbox separation mirrors our DP#4 (Separate detection from diagnosis)
- File boundary isolation = natural conflict prevention, validates atomic task design (#1)
- Provides implicit rollback capability via git (addresses our Rollback Gap)
- "State externalization to git" = purest implementation of Stateless-by-Default
