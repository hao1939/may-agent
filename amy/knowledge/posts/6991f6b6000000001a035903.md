## 什么是"上下文爆炸"
每次回复都要把"系统提示词+技能说明+聊天历史+工具结果"一起喂给模型，当这些内容不断累积：
- 响应变慢 | token消耗飙升 | 容易丢重点/答非所问 | 工具调用成本上升

## 7个通用解法

### 1. 限制历史注入长度（第一优先级）
```
核心原则: 每轮只带最近N条历史，不要无限带全量
建议起始值:
  DM场景: historyLimit=10~30
  群聊场景: 8~20
```

### 2. 控制Skills数量
```
Skill越多 = system prompt越长 = 每轮固定token税
建议: 常驻只开3~8个高频skill，低频skill默认关闭用时再开
```

### 3. 开启Compaction（安全压缩模式）
```
compaction.mode: "safeguard"
接近上限时自动压缩历史，避免直接撞满窗口
```

### 4. 大任务改成"主会话调度+子代理执行"
```
主会话只保存: 目标+约束+里程碑
子代理并行做: 具体执行
回收结果: 只把结论写回主会话
→ 主会话增长速度明显下降
```

### 5. 养成"阶段性重置"习惯
任务结束就reset | 新项目开新会话 | 不同主题不要混在一个会话
"让会话有生命周期，而不是无限对话"

### 6. 长内容文件化，不要常驻聊天流
聊天里只放: 摘要+文件路径+下一步指令（不放原始数据）

### 7. 用"外部记忆检索"替代"硬塞上下文"
```
把长期偏好、关键决策写入memory文件，通过检索召回
不要每轮重复粘贴背景信息
```

## 开箱即用配置模板
```json
{
  "channels": {
    "yourChannel": {
      "historyLimit": 20,
      "dmHistoryLimit": 20
    }
  },
  "agents": {
    "defaults": {
      "compaction": { "mode": "safeguard" }
    }
  },
  "skills": {
    "entries": {
      "high-frequency-skill-a": { "enabled": true },
      "rare-skill-x": { "enabled": false }
    }
  }
}
```

## 排查顺序
1. historyLimit降到20，观察1天
2. 关闭低频skills
3. 确认compaction已启用
4. 长任务改子代理
5. 建立reset习惯+文件化输出
6. 需要长期记忆时再上memory检索

## 常见误区
- 只怪模型贵，不管上下文体积
- 什么都放一个会话"图省事"
- 装了很多skill但几乎不用
- 把工具原始输出整段反复塞回聊天
