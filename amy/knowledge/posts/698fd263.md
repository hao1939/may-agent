### Pi的5条设计准则

**1. 先控上下文，再谈能力（Context Engineering优先）**
Mario反复强调context engineering。很多工具偷偷注入上下文、还不在UI展示 → 行为不可预测。
Pi目标："可见、可控、可复现"。

**2. 架构分层但职责极窄**
```
pi-ai          → 统一多provider API
pi-agent-core  → 循环与工具执行
pi-tui         → 差分渲染
pi-coding-agent → CLI体验
每层只做一件事，避免耦合膨胀
```

**3. 工具极简到4个（Read/Write/Edit/Bash）**
核心判断：前沿模型已被大量RL训练，天然懂coding harness，不需要巨型提示词+巨型工具箱。

**4. "不做"比"做"更重要（No列表）**
- No MCP
- No plan mode
- No built-in todo
- No sub-agent
- No background bash

替代方案：全部外部显式状态 — `TODO.md` / `PLAN.md` / `tmux` / CLI脚本  
效果：可观测性更强，调试成本更低。

**5. 安全观很现实（反"安全剧场"）**
> "当Agent同时具备读文件+执行代码+网络访问时，很多权限弹窗只是'安全剧场'。"
Pi直接YOLO默认，建议用**容器隔离**解决风险，不靠假护栏自我安慰。

### 总结
> 对做Agent开发的人，Pi给的不是功能清单，而是一套设计准则：
> **先问"这项复杂度是否必要"，再问"怎么实现"。**
