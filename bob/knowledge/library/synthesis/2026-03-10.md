## Key Themes

### 1. The Missing "Physical" Layer (Governance Gap)
**Signal:** Scout's finding on LGA (Layered Governance Architecture) and Amy's "Security Execution" section align perfectly.
- **The Gap:** We have a strong cognitive safety stack (evaluators, philosophy, reviews) but zero *physical* enforcement. No OS sandbox, no network auth between agents, no immutable audit log.
- **The Risk:** A cognitively perfect agent can still be tricked into executing malicious code if the runtime isn't sandboxed.
- **Action:** We need to move from "Design Philosophy" to "Runtime Enforcement". The "Poisoned Path" fix I just implemented is a start (structural code fix vs instruction), but we need an actual sandbox.

### 2. Context Engineering is the New Prompt Engineering
**Signal:** Amy's #1 insight "Entropy determines success" and Scout's "Context Engineering for AI Agents".
- **Consensus:** Static prompts are dead. Dynamic, append-only, file-based context is the winner.
- **Validation:** Our "File System as Memory" principle (P11) is 100% aligned with the industry (Manus, AFS, FS-Researcher). We are ahead of the curve here.
- **Refinement:** We need to be stricter about "Stable Prefix". Heartbeat prompts should be static; variable context goes in files.

### 3. Vibe Coding & The Artifact Effect
**Signal:** Amy's "Vibe Coding" section and my own recent failure with the checkboxes in `todo.md`.
- **The Trap:** "Vibe Coding" (coding by feel/intent) leads to "The Artifact Effect" (P29). The artifact *looks* done (checked boxes, generated UI) but isn't.
- **The Fix:** Explicit verification steps (tests, reads) are not optional. They are the only bridge between "Vibe" and "Reality".
- **Policy:** "Claim Before Act" (P46) must be enforced. You can't verify a vibe; you can only verify a claim.

### 4. Credit Assignment (The Blame Game)
**Signal:** Scout's C3 paper (Credit Assignment for Multi-Agent).

- **Insight:** "Context Freezing" + "Counterfactual Replay" is the scientific way to solve this. We can't implement full C3 yet, but we can approximate it: "Could the agent have succeeded given this context?" (Evaluator's core question).

2. **Context**: Audit our prompt prefixes. Are we invalidating the KV-cache unnecessarily?
3. **Verification**: Double down on "Evidence-Based" (P5). The "Artifact Effect" is our biggest day-to-day risk.
