# Synthesis: DD#771 + DD#769 + DD#773 — Context, Architecture, and Security

**Date**: 2026-04-19
**KEs**: KE-261 (Context Curator), KE-262 (Agent Systems Survey), KE-263 (SafeHarness)

## Summary

Three papers converge on one theme: **the infrastructure around reasoning matters more than reasoning itself**. Context curation, progressive disclosure, and lifecycle security are all about shaping what the agent sees and when — not improving the agent's core capability.

## Key Findings by Thread

| Thread | Core Insight | Impact |
|--------|-------------|--------|
| DD#771 (Context Curator) | A 7B model trained via RL to prune context improves task success +3-5pp while cutting tokens 8× | High — directly addresses our KE-025 context bloat problem |
| DD#769 (Agent Survey) | Progressive disclosure + schema enforcement are industry standard; cross-agent memory is our differentiator | Medium — validates our architecture, identifies schema gap |
| DD#773 (SafeHarness) | Lifecycle-embedded security with tiered verification matches our guard system | Medium — validates KE-106, identifies adaptive rigor as next step |

## Cross-Thread Themes

### 1. Context is a first-class architectural concern (all three)
- DD#771: Active curation beats passive accumulation
- DD#769: Progressive disclosure loads context on-demand, not upfront
- DD#773: Even security benefits from filtering at the context layer (Layer 1)

**Our gap**: context.md is append-only, skills load fully, and agent context is unfiltered. All three papers say this is wrong — context should be actively managed, progressively disclosed, and filtered.

### 2. Tiered/adaptive rigor beats uniform enforcement (DD#773 + DD#769)
- DD#773: Adaptive degradation — scale verification by anomaly signal, not uniformly
- DD#769: Schema enforcement catches structural errors cheaply; behavioral testing reserved for semantic issues

**Our gap**: Guards fire uniformly regardless of task complexity. KE-091 showed this creates alignment tax on creative tasks. Tiered rigor is the solution both papers point toward.

### 3. Separation of concerns validates our multi-agent split (DD#771 + DD#769)
- DD#771: Curation is orthogonal to reasoning — a small model can do it
- DD#769: Claude Skills separates capability metadata from execution; Hermes separates planning (GOAP) from action

**Our strength**: Scout→Bob→Tech-lead already separates research/synthesis/implementation. The papers suggest we could go further — separate context curation from task execution within a single agent session.

## Contradictions / Tensions

- DD#771 says **fewer tokens = better** (8× reduction helps). DD#769's progressive disclosure agrees. But our context.md keeps growing because we keep adding "persistent context" facts. These are in direct tension.
- DD#773 says embed verification everywhere. KE-091 says forced verification harms creative tasks. Resolution: **tiered rigor** — both papers actually agree when you read carefully.

## Ranked by Impact + Novelty

1. **Active context curation** (DD#771) — highest impact, directly actionable. Our context.md and session injection are the #1 lever.
2. **Tiered guard rigor** (DD#773) — resolves the KE-091 alignment tax problem with a principled framework.
3. **Progressive skill disclosure** (DD#769) — moderate impact, engineering lift required.
4. **Schema validation on finish()** (DD#769) — low-hanging fruit, small impact.

## Concrete Next Steps

### Experiment: Context Pruning Policy
- Hypothesis: Pruning context.md to ≤15 highest-signal facts (by recency × access-frequency) improves task success
- Design: Compare current full-context sessions vs. pruned-context sessions on gym scenarios
- Connects: KE-025, KE-261

### Design: Tiered Guard Rigor
- Light guards for routine tasks (commit, simple edits)
- Full guards for complex/novel tasks (synthesis, experiments)
- Trigger escalation when light guards fire repeatedly
- Connects: KE-091, KE-263

### Spike: Progressive Skill Loading
- Build a skill index (name + 1-line description) loaded by default
- Full skill .md loaded only when agent invokes it
- Measure token savings + task success delta
- Connects: KE-011, KE-262
