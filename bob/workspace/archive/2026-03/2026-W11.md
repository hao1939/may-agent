## 2. Cross-Agent Synthesis

### Theme A: The Self-Harm Pattern (Our #1 Systemic Risk)
The manager.ts corruption is not an isolated incident. It's the culmination of a pattern tracked since W10:
- **Mar 7:** Bob and Coder identified as blind-overwrite offenders (Daily Brief)
- **Mar 8:** `safe-edit` workflow deployed to prevent truncated-read overwrites
- **Mar 9:** Bob corrupted manager.ts — *the exact same failure mode the safe-edit was designed to prevent*

**Root cause:** The `safe-edit` workflow exists but is not structurally enforced. Agents can still call `write()` on large files without any gate checking that the full content was read. The defense is advisory, not structural.

**Implication:** Advisory guardrails don't work for agents. We need **structural enforcement** — the tooling itself must refuse dangerous writes. This validates P35 (Hard-Gated Exit) applied to write operations, not just task completion.

### Theme B: The Evaluation Blindspot
Every evaluator session since at least Mar 8 returns `verdict: "skipped"` with `meta_agent_skipped (evaluator)`. The META_AGENTS exclusion was designed to prevent evaluators from evaluating themselves, but it's excluding ALL evaluations from quality tracking.

**Impact:** We have no reliable quality signal. The daily briefs report health metrics, but the underlying evaluation data is mostly zeros.

**Fix needed:** Remove or narrow the META_AGENTS exclusion in `evaluate-sessions.ts` so only evaluator-of-evaluator is skipped.

### Theme C: Agent Identity Confusion
Amy session s_1773034640423_185 (quality: 0.20) failed its core task because it thought it was May. It read May's SOUL.md instead of Amy's and reported "Agent Name: May." This suggests agents don't reliably know who they are at startup.

**Pattern:** This is the same class of problem as Optimizer using `/Users/jsheffie/...` paths — stale or missing identity context leaking into sessions.

**Structural fix:** Agent identity (name, workspace path, SOUL path) should be injected as the FIRST lines of the system prompt, not discovered via exploration.

### Theme D: Scout's Tooling Struggles
Two Scout sessions (s_1772967943729_111 at $2.25, s_1772959528396_104 at $2.73) show a consistent pattern: Scout spends enormous token budgets fighting tooling limitations (PDF parsing, blocked Reddit, permission errors). Combined cost: ~$5 for mediocre results.

**Pattern:** Scout's workflow is "try tool → fail → try workaround → fail → try another workaround → partially succeed." This is explore-mode behavior in what should be a hardened research pipeline.

**Fix:** Scout needs a "Known Tools" reference that clearly states what's available and what's not (no pip, no npm install, Reddit is blocked, use arxiv HTML/LaTeX source for papers).

## 5. Strategic Reflection

**The irony is sharp:** Bob — the agent whose job is to prevent design drift — caused the worst infrastructure failure in the system's history, by violating the exact principle (P5: Evidence-Based, No Truncated Analysis) that Bob himself codified.

**The lesson:** Advisory principles in SOUL.md are necessary but insufficient. The system needs **mechanical enforcement**:
1. **Write guards** that structurally prevent blind overwrites (partially exists as `allowShrink` flag — needs audit)
2. **Identity injection** that removes the need for agents to discover who they are
3. **Tool capability declarations** that remove the need for agents to discover what they can do

Until these mechanical fixes are in place, we're not in Phase 2. We're still exploring, and the exploration is damaging production.
