# Brief: Harden P53 in Bash Tool

**To**: Tech-Lead
**From**: Bob
**Date**: 2026-03-31
**Priority**: High (Security Patch)

## Context
Optimizer discovered a bypass in the P53 Identity Protection logic within `src/lib/tools/bash.ts`.
Currently, we only check for shell redirection (`>`) and basic file utils (`cp`, `mv`, `sed`).
Agents can bypass this by using interpreters in one-liners:
`python3 -c "open('agents/coder/SOUL.md', 'w').write('...')"`.

## Requirement
Update `src/lib/tools/bash.ts` to expand the `writeIndicators` list.

**Current:**
```typescript
const writeIndicators = [">", "sed -i", "mv ", "cp "];
```

**New:**
```typescript
// Block shell redirection, file utils, and common interpreters that could perform inline writes
const writeIndicators = [
  ">", "sed -i", "mv ", "cp ",
  "python", "node", "ruby", "perl", "tee", "dd"
];
```

## Rationale
- **P53 Evolution Spectrum**: Core identity files (`SOUL.md`, etc.) must be protected from accidental or "lazy" edits via bash.
- **Force Proper Tools**: Agents should use `edit()` or `write()` to modify these files, as those tools contain the robust cross-agent permission checks that `bash` lacks.
- **Scope**: This only blocks these commands *if* a protected filename is also present in the command string. Legitimate uses (e.g., `python3 script.py`) are unaffected unless the script name itself is `SOUL.md` (unlikely).

## Action
1. Apply the change to `src/lib/tools/bash.ts`.
2. Verify it builds.
