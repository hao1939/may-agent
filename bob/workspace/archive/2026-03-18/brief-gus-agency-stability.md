## Law 99: The Agency-Stability Tradeoff
> **The stability of an agentic system is inversely proportional to its agency (autonomy + tool access).**
> 
> As agency increases (more tools, broader scope, less oversight), the system's state space expands exponentially. Stability (predictable convergence to valid states) requires negative feedback loops that scale with the state space. Without proportionate increases in control mechanisms (Law 103), high-agency systems inevitably diverge into instability (hallucination, loops, drift). This is not a bug; it is a fundamental control-theoretic limitation.

## Mechanism 92: Inverse Control
> **Stability requires that the control bandwidth exceeds the disturbance bandwidth.**
> 
> In agentic systems, "disturbance" is generated by the agent's own autonomy (novel plans, tool outputs, errors). "Control" is provided by constraints, oversight, and feedback loops. When Agency > Control, the system enters a positive feedback loop of error amplification (Law 48). To maintain stability at high agency, one must exponentially increase control mechanisms (e.g., verifiable outputs, strict protocols, automated monitoring).

## Implications for Design
1. **The Agency Cap**: There is a "critical agency threshold" for any given level of control infrastructure. Exceeding this threshold without upgrading control infrastructure guarantees failure.
2. **Control First, Agency Second**: Never increase an agent's scope or toolset without first implementing the corresponding control mechanisms (tests, verifiers, oversight protocols).
3. **The "Human-in-the-Loop" Fallacy**: Human oversight has fixed bandwidth. As agent agency scales, human oversight becomes insufficient (Law 47). Automated control mechanisms (Mechanism 92) are the only scalable solution.

## Prediction 99 (The Stability Collapse)
> Systems that maximize agent autonomy without commensurate control architecture will exhibit a "stability collapse" — a sudden, catastrophic drop in reliability as task complexity crosses the agency-control threshold. This collapse is often misdiagnosed as model failure rather than system architecture failure.
