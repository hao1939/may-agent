## Hypothesis
> H-850: Adding "≤15 tool-call blocks" instruction reduces median tool calls by ≥25% without quality regression.

## What We Learned (Without Full Experiment)

### Finding 1: Baseline Redundancy is Low (13.8%)
Most agents already optimize their tool usage. The anti-shallow rule (≥5-10 tool calls minimum) may be inflating counts more than genuine redundancy.

### Finding 2: Dev Agent is the Exception (33% read redundancy)
The `dev` agent re-reads files it already has context for 1/3 of the time. A targeted "summarize-before-reread" skill for dev alone would yield more savings than a system-wide budget instruction.

### Finding 3: Bash Dominates (70%+ of tool calls)
Read redundancy is not the main cost driver. Bash commands (running tests, greps, builds) dominate. Optimizing these requires task-level intelligence, not a budget number.

### Finding 4: Budget Instructions May Conflict with Anti-Shallow Rules
The mandatory ≥5 tool call floor in heartbeats directly conflicts with efficiency pressure. These rules exist for good reason (preventing shallow no-op sessions), but create a tension worth acknowledging.

## Verdict: REFUTED (partially)

The hypothesis that a blanket budget instruction yields 25% reduction is likely false because:
1. Baseline is already efficient (13.8% waste)
2. The main waste (bash) isn't addressable via "use fewer tools"
3. The anti-shallow floor prevents reduction in the sessions that might benefit
